# R² Flow: Recursive Self-Improvement via Recursive Skill Evolution

Mingda Zhang    Qiang Huang Affiliation: The Chinese University of Hong
Kong, Shenzhen Fudan University    Yanjin Li    Zijia Wang    Qika Lin
Affiliation: University of Illinois at Urbana-Champaign University of
Oxford National University of Singapore    Xiaoying Tang    Tiesunlong
Shen Affiliation: University of Illinois at Urbana-Champaign University
of Oxford National University of Singapore

###### Abstract

LLM-based agents can improve themselves across tasks by reusing and
revising the skills they orchestrate into executable procedures.
Flow-based training fits this loop: it samples procedures in proportion
to reward, and the flow through each skill credits it for the next
library revision. Three obstacles stand in the way of making this
self-improvement reliable: flow training suffers strategy collapse over
tree-structured histories; nonnegative flow-based credit rewards
frequent use as if it were benefit; and library edits rest on the task
reward the policy optimizes. We introduce R² Flow, a recursive
self-improvement framework that alternates policy learning, independent
verification, and versioned skill-library updates on a shared-state
orchestration graph. The graph merges histories that differ only in the
order of independent steps, allowing flow training to pool evidence
across equivalent executions. A flow-share readout of the trained flow,
invariant to the backward policy, and a separate signed utility rank
which skills to change, verifier evidence decides whether an edit is
warranted, and a residual-variance plateau sets when to update.
Committed edits reshape the graph the next policy learns on, realizing
recursive skill evolution. Across question answering, mathematical
reasoning, interactive decision making, and code generation, R² Flow
improves task accuracy and library-edit precision over heuristic
orchestration, reinforcement learning, and skill-evolution baselines,
and transfers across executors. Code is available at
[https://github.com/beita6969/r2flow](https://github.com/beita6969/r2flow).

## 1 Introduction

Figure 1: R² Flow trains a flow on shared states (inner loop), reads
share and signed utility separately, and gates library edits on verified
evidence (outer loop).

In recent years, LLM-based agentic systems have come to orchestrate
reusable skills into executable procedures ([Yao et al.,
2022b](#bib.bib53); [Wang et al., 2023](#bib.bib44); [Yue et al.,
2026](#bib.bib56)), shifting the unit of automation from a single answer
to an entire procedure. A central goal is therefore not only to complete
a task but to improve the procedure used later ([Fang et al.,
2025](#bib.bib9); [Ren et al., 2026](#bib.bib32); [Chen et al.,
2026b](#bib.bib8)). This makes self-improvement a recursive loop: each
phase trains the policy on a versioned library and updates that library
from what it learned, and the next phase repeats this on the new
library. Without human review, such a loop must admit each update on
evidence outside the training reward.

Task orchestration organizes primitive actions and reusable skills into
structured trajectories on an orchestration graph
([Figure 1](#S1.F1 "In 1 Introduction ‣ R2 Flow: Recursive Self-Improvement viaRecursive Skill Evolution"),
panel 1), where each node is an execution state and each edge is one
orchestration event, which makes complex tasks more controllable and
composable ([Zhuge et al., 2024](#bib.bib70); [Zhang et al.,
2025](#bib.bib66); [Yun et al., 2026](#bib.bib57); [Tieu et al.,
2026](#bib.bib42)). Orchestration has accordingly evolved from static
human-authored pipelines to graphs generated or edited at run time
([Zhang et al., 2025](#bib.bib66); [Zhang et al., 2026d](#bib.bib67);
[Yue et al., 2026](#bib.bib56)), and further to policies trained
directly from execution feedback ([Zhang et al., 2026e](#bib.bib68);
[Zhang, 2026b](#bib.bib60)). However, these policies are still trained
on tree-structured histories, where the same steps taken in a different
order are never recognised as one procedure.

Figure 2: Four orchestration paradigms. (a) Workflow graph optimization
hides a harmful skill in the return. (b) Flow-driven orchestration
learns $`AB`$ and $`BA`$ twice on a history tree, so evidence never
pools. (c) Posterior-guided evolution scores reliability, not signed
utility, so success reads as benefit. (d) R² Flow pools evidence on
shared states, separates share from utility, and commits verified edits.

To address these issues, _graph-based orchestration_
([Figure 2](#S1.F2 "In 1 Introduction ‣ R2 Flow: Recursive Self-Improvement viaRecursive Skill Evolution")a)
retrieves prebuilt skills or searches and edits workflow graphs at run
time ([Zhang et al., 2025](#bib.bib66); [Zhuge et al.,
2024](#bib.bib70); [Yun et al., 2026](#bib.bib57); [Li et al.,
2026a](#bib.bib19); [Tieu et al., 2026](#bib.bib42)). _Step-level credit
assignment_
([Figure 2](#S1.F2 "In 1 Introduction ‣ R2 Flow: Recursive Self-Improvement viaRecursive Skill Evolution")b)
converts a terminal reward into finer-grained signals through process
reward models, hindsight advantage estimation, and GFlowNet balance
objectives that sample in proportion to reward ([Bengio et al.,
2021](#bib.bib4); [Malkin et al., 2022](#bib.bib27); [Zhang et al.,
2026e](#bib.bib68); [Tao et al., 2026](#bib.bib39); [Tan et al.,
2026](#bib.bib37)). _Dynamic skill libraries_
([Figure 2](#S1.F2 "In 1 Introduction ‣ R2 Flow: Recursive Self-Improvement viaRecursive Skill Evolution")c)
grow capability by curating skills with LLM-as-judge prompting,
execution feedback, or posterior beliefs over skill reliability ([Wang
et al., 2023](#bib.bib44); [Wu et al., 2026](#bib.bib46); [Tang et al.,
2026](#bib.bib38); [Ouyang et al., 2026](#bib.bib30)).

However, joining these lines of work into one loop faces three
challenges. (i) Strategy collapse. When a state is the full interaction
history, every state has exactly one parent, so the orchestration graph
is a tree and the backward policy is trivially one ([Malkin et al.,
2022](#bib.bib27); [Fawkes & Hartford, 2026](#bib.bib10); [Wang et al.,
2026](#bib.bib45)). Executions that differ only in the order of
independent steps sit on different branches and never share evidence;
the flow then spreads probability over reorderings of one procedure
rather than across genuinely different strategies, so a procedure with
more admissible orderings receives proportionally more sampling mass,
and more weight in the next library edit ([Bengio et al.,
2021](#bib.bib4); [Zhang et al., 2026e](#bib.bib68)).
(ii) Indiscriminate credit assignment. Flow shares and usage counts are
non-negative by construction and reliability posteriors score whether a
call succeeds, so none says whether a skill helps, and a frequently
invoked harmful skill looks critical and survives into the next library
([Zhang et al., 2026e](#bib.bib68); [Wu et al., 2026](#bib.bib46); [Li,
2026](#bib.bib21)). (iii) Unverified skill evolution. Edits are admitted
on the same task reward whose attribution is in question, and on point
estimates that cannot separate insufficient evidence from confirmed
failure, so a skill can be pruned before its evidence accumulates
([Zhang et al., 2025](#bib.bib66); [Wu et al., 2026](#bib.bib46); [Zhang
et al., 2026f](#bib.bib69); [Zhang, 2026c](#bib.bib62); [Zhang,
2026a](#bib.bib59)).

We introduce R² Flow
([Figure 2](#S1.F2 "In 1 Introduction ‣ R2 Flow: Recursive Self-Improvement viaRecursive Skill Evolution")d),
running this loop through three designs, each serving the library
update. The first, the Orchestration Graph, replaces the history tree of
trained orchestration policies: it merges histories differing only in
the order of independent steps into one state, so their evidence pools
at that state; when a merged state has several legal predecessors, the
backward policy is a genuine choice among them. Built on the graph, we
further propose flow share: a flow network is trained on the shared
states with the balance objective R²TB, and each skill’s share of the
flow is read from the trained policy’s rollouts weighted by their
residuals, a readout invariant to the backward policy. In contrast to
credit that reads use as benefit, it is kept separate from a signed
utility that says whether the skill helps. R² Flow then performs
verifier-gated skill-library updates, replacing admission on the task
reward: independent verifiers label skill invocations, edge flow picks
which ones to verify, and an edit refines or prunes a skill only when
verified evidence supports it, waiting otherwise. The R²TB residual also
times the loop: a plateau in its variance ends a phase and triggers the
next library update. Together the designs close one recursive loop: each
phase trains on the library the previous phase committed, and its
readouts, posterior and residual decide the next commit.

We evaluate on twelve datasets across four task domains, six held out,
reporting task accuracy, executor transfer, and library-edit precision
against heuristic orchestration, reinforcement learning ([Zhang et al.,
2026d](#bib.bib67)), and skill-evolution baselines ([Ni et al.,
2026](#bib.bib29); [Yang et al., 2026](#bib.bib50)).

## 2 Related Work

#### Self-Improving Agents.

Self-improving agents rewrite scaffolding, meta-agent designs, or their
own logic and code ([Zelikman et al., 2023](#bib.bib58); [Hu et al.,
2025](#bib.bib13); [Yin et al., 2025](#bib.bib54); [Zhang et al.,
2026c](#bib.bib65)), in loops framed as bounded or open-ended
self-modification ([Chen et al., 2026b](#bib.bib8)). Skill evolution
co-trains the library with the policy ([Xia et al., 2026](#bib.bib47);
[Zhang et al., 2026e](#bib.bib68)), Bayesian curation adds finite-sample
uncertainty, and verification screens edits ([Guo et al.,
2026](#bib.bib11); [Wu et al., 2026](#bib.bib46); [Chen et al.,
2026a](#bib.bib7); [Zhang et al., 2026a](#bib.bib63)). Most admit an
edit on task-level outcomes, so the edit is judged by the signal whose
attribution is in question, where an optimiser exploits its evaluator
([Thaman, 2026](#bib.bib41)). R² Flow instead admits library edits on
verifier labels outside the reward.

#### Agent Task Orchestration.

LLM agents orchestrate tasks in loops that plan, act, and revise on
execution feedback ([Yao et al., 2022b](#bib.bib53); [Yue et al.,
2026](#bib.bib56)). Existing work spans operator graphs generated by
search or edited under structured feedback ([Zhang et al.,
2025](#bib.bib66); [Zhuge et al., 2024](#bib.bib70); [Zhang et al.,
2026d](#bib.bib67); [Li et al., 2026a](#bib.bib19); [Tieu et al.,
2026](#bib.bib42)), reusable skill memory, and self-evolving
architectures ([Wang et al., 2023](#bib.bib44); [Tang et al.,
2026](#bib.bib38); [Xu et al., 2026b](#bib.bib49); [Bai et al.,
2026](#bib.bib3); [Lin et al., 2026](#bib.bib23)). Trained orchestration
policies define states over raw histories, so a procedure and its
reorderings never share statistics. R² Flow instead trains its flow on a
dependency-aware shared-state graph of executable histories, where
reorderings meet at one state ([Yu et al., 2024](#bib.bib55), as in
reasoning DAGs;).

## 3 Preliminaries

Definition 1: Orchestration State Graph. Task orchestration is a
directed graph $`\mathcal{G}`$ whose vertices are interaction histories
$`H_{t}`$ and whose edges are orchestration events. The update
$`H_{t}=H_{t-1}\oplus(r_{t},e_{t},o_{t}^{\mathrm{exec}})`$ appends one
record, so $`\mathcal{G}`$ is acyclic and every non-root history has one
parent.

Definition 2: Orchestration Trajectory. A complete path from the initial
history $`H_{0}`$ to a terminal state defines an orchestration
trajectory:

|     |     |     |     |
| --- | --- | --- | --- |
|     |

````math
\tau=\bigl\{(r_{t},\ e_{t},\ o_{t}^{\mathrm{exec}})\bigr\}_{t=1}^{T}\ \Rightarrow\ y_{q},
``` |  | (1) |

where $`r_{t}`$ is the reasoning text,
$`e_{t}=(u_{t},\mathrm{args}_{t})`$ the event, and
$`o_{t}^{\mathrm{exec}}`$ the execution feedback. It ends on acceptance
or budget exhaustion; its terminal outcome $`x`$ earns a reward
$`R(x)\in[0,1]`$.

Problem Statement. Given a task $`q`$ and an environment $`\mathcal{E}`$
with a frozen executor $`\mathcal{M}_{\mathrm{exec}}`$, we augment the
graph with a non-negative edge flow ([Bengio et al., 2021](#bib.bib4);
[Bengio et al., 2023](#bib.bib5)) that is conserved at every
non-terminal state, with terminal condition $`F(x)=R_{\eta}(x)`$ for the
tempered reward $`R_{\eta}(x)=(R(x)+\epsilon)^{\eta}`$. The forward and
backward policies are the normalised edge flows,
$`P_{F}(e\mid s)=F(s\!\to\!e)/F(s)`$ and
$`P_{B}((s,e)\mid s^{\prime})=F(s\!\to\!e)/F(s^{\prime})`$, and a flow
meeting the terminal condition is called *reward-matching*. We seek a
state map $`\sigma`$ that merges reorderings of independent steps,
preserves legal events, successors and terminal reward, and induces a
graph admitting a reward-matching flow with terminal marginal
proportional to the tempered reward:

|  |  |  |  |
|----|----|----|----|
|  |
``` math
P_{F}(x\mid q)\;=\;\frac{R_{\eta}(x)}{Z^{\star}(q)},\qquad Z^{\star}(q)=\sum_{x\in\mathcal{X}}R_{\eta}(x),
``` |  | (2) |

where $`Z^{\star}(q)`$ is the true partition function. The flow must
also give a per-skill attribution well defined on that graph, to rank
the edits turning the phase-$`k`$ library $`\mathcal{S}^{(k)}`$ into
$`\mathcal{S}^{(k+1)}`$ (Appendices A and D).

## 4 Methodology: R² Flow

![Refer to caption](2609.33867v1/fig3.png)

Figure 3: The R² Flow framework. (1) The Supervisor $`\pi_{\theta}`$
acts in a structured environment where histories differing only in the
order of independent steps share one state. (2) $`P_{F}`$, $`P_{B}`$ and
$`F_{\psi}`$ are trained with R²TB; flow share $`\Psi^{0}(u)`$ and
signed utility $`\widetilde{A}_{e}`$ are read separately. (3) Verifier
evidence, the two readouts and the variance plateau decide whether,
which and when to edit.

In
[Figure 3](#S4.F3 "In 4 Methodology: R2 Flow ‣ R2 Flow: Recursive Self-Improvement viaRecursive Skill Evolution"),
R² Flow nests two self-improvement loops: within a phase (inner loop),
the policy improves on its own rollouts with R²TB until the residual
variance plateaus; across phases (outer loop), verified edits update the
library, and with it the next phase’s graph. The graph (Section 4.1)
carries a flow trained with R²TB (Section 4.2) whose readouts and
residual steer the edits (Section 4.3).

### 4.1 Orchestration Graph and Task Modeling

R² Flow follows a Supervisor–Executor paradigm ([Yao et al.,
2022b](#bib.bib53)): a trainable Supervisor $`\pi_{\theta}`$ interacts
with a structured environment $`\mathcal{E}`$ whose states are shared
states rather than raw histories.

Structured Environment $`\mathcal{E}`$. It holds the skill library, a
verifier suite, and the executor:

|  |  |  |  |
|----|----|----|----|
|  |
``` math
\mathcal{E}=(\mathcal{S},\ \mathcal{Y},\ \mathcal{M}_{\mathrm{exec}}),
``` |  | (3) |

where $`\mathcal{S}`$ is the dynamic skill library, $`\mathcal{Y}`$ a
suite of independent verifiers labelling single skill invocations, and
$`\mathcal{M}_{\mathrm{exec}}`$ the pluggable executor. The library
changes at phase boundaries, so the action space is fixed within a phase
and every trajectory in that phase is sampled against one library
version.

Shared States and the Merge Rule. A raw history $`H_{t}`$ (Definition 1)
maps to its shared state by $`\sigma`$:

|  |  |  |  |
|----|----|----|----|
|  |
``` math
s_{t}=\sigma(H_{t})=\bigl(E_{t},\ \prec_{t},\ \mathcal{A}_{t},\ \mathcal{V}_{t},\ \Omega_{t}\bigr),
``` |  | (4) |

where $`E_{t}`$ is the set of committed events, $`\prec_{t}`$ their
dependency order, $`\mathcal{A}_{t}`$ the canonicalised artifacts,
$`\mathcal{V}_{t}`$ the verified facts, and $`\Omega_{t}`$ the
environment observables. For example, independent checks $`A`$ and $`B`$
can run in either order, so $`A\!\rightarrow\!B`$ and
$`B\!\rightarrow\!A`$ map to one state; if $`B`$ consumes $`A`$’s
output, the dependency $`A\prec B`$ is retained and the orders stay
distinct (legality conditions on $`\sigma`$ in Appendix A).

In-Edges and Rank. A merged state has several in-edges, each from
removing a $`\prec`$-maximal event:

|  |  |  |  |
|----|----|----|----|
|  |
``` math
\Inn(s^{\prime})=\bigl\{(s,e):s^{\prime}=s\oplus e\bigr\},\qquad\rho(s)=|E_{s}|,
``` |  | (5) |

where $`\rho`$ is a state’s rank; each edge commits an event, so
$`\rho`$ increases along paths and, with the step budget, the graph is a
finite DAG. Each predecessor of $`s^{\prime}`$ is an in-edge for the
backward policy.

Terminal States and Tempered Reward. The terminal state $`x`$ carries
the tempered reward $`R_{\eta}(x)`$ of Section 3, whose exponent
$`\eta`$ sets how sharply sampling favours high reward and whose
$`\epsilon>0`$ keeps it positive; $`R`$ is a function of the terminal
state, so histories merged into one state share one reward.

Proposition 1. *Merging reorderings yields a shared-state DAG; whenever
a reachable state has multiple legal predecessors, the backward policy
is a genuine choice among them.* (Empirically, the shared-states and
backward-policy ablations and strategy counts, RQ4 in
§[5](#S5 "5 Experiments ‣ R2 Flow: Recursive Self-Improvement viaRecursive Skill Evolution");
formally, Appendix A.)

### 4.2 Flow Training and Flow Share

As shown in
[Figure 3](#S4.F3 "In 4 Methodology: R2 Flow ‣ R2 Flow: Recursive Self-Improvement viaRecursive Skill Evolution"),
panel 2, over the shared-state graph from Section 4.1, R² Flow trains a
flow network $`(P_{F,\theta},P_{B,\phi},F_{\psi})`$ targeting the
reward-matching flow of Section 3, whose forward policy $`P_{F,\theta}`$
is the Supervisor $`\pi_{\theta}`$; throughout, $`P_{F}(e\mid s)`$
denotes the one-step edge policy. Beyond mode coverage, the flow serves
the edit step: $`F(s)`$ is shared by every path through $`s`$, so where
paths merge, the reference flow $`F^{0}`$ gives the readout of
Section 4.3, alongside the signed utility below.

Forward Policy $`P_{F}`$ and Backward Policy $`P_{B}`$. An event is a
skill identifier with structured arguments, so the forward policy
factorises, while the backward policy is normalised over in-edges:

|  |  |  |  |
|----|----|----|----|
|  |
``` math
P_{F}(e\mid s)=P_{F}(u\mid s)\,P_{F}(\mathrm{args}\mid u,s),\qquad P_{B}\bigl((s,e)\mid s^{\prime}\bigr)=\frac{\exp f_{\phi}(s,e,s^{\prime})}{\sum_{(\bar{s},\bar{e})\in\Inn(s^{\prime})}\exp f_{\phi}(\bar{s},\bar{e},s^{\prime})},
``` |  | (6) |

where $`f_{\phi}`$ scores an in-edge from the hindsight state. Each
in-edge removes a different $`\prec`$-maximal event, so $`P_{B}`$
spreads training credit over the skills that reach $`s^{\prime}`$. On a
history tree every state has one in-edge, so $`P_{B}\equiv 1`$ and this
credit is never split (Appendix A).

Recursive-Residual Trajectory Balance (R²TB). Given $`P_{F}`$,
$`P_{B}`$, a log-flow head $`\log F_{\psi}`$ and the reasoning text
$`r_{t}`$, a sub-trajectory from $`s_{i}`$ to $`s_{j}`$ has the balance
residual (SubTB; [Madan et al., 2023](#bib.bib26)):

|  |  |  |  |
|----|----|----|----|
|  |
``` math
\delta_{i:j}=\ell(s_{i})+\sum_{t=i+1}^{j}\log P_{F}(e_{t}\mid s_{t-1},r_{t})-\ell(s_{j})-\sum_{t=i+1}^{j}\log P_{B}\bigl((s_{t-1},e_{t})\mid s_{t}\bigr).
``` |  | (7) |

The training objective is the weighted squared residual, with the
terminal flow anchored to the reward:

|  |  |  |  |
|----|----|----|----|
|  |
``` math
\mathcal{L}_{\mathrm{flow}}=\sum_{0\leq i<j\leq T}\omega_{j-i}\,\delta_{i:j}^{2},\qquad\ell(s)=\log F_{\psi}(s)+b_{d}\;\,(s\notin\mathcal{X}),\quad\ell(x)=\log R_{\eta}(x),
``` |  | (8) |

where $`F_{\psi}(s_{0})=Z_{\theta}(q)`$ is the learned partition
function, $`\omega_{j-i}`$ decays geometrically in $`j-i`$ (as in SubTB)
and is normalised per trajectory, and the per-domain bias $`b_{d}`$
absorbs a shared offset of the terminal residuals (Appendix B). Here
$`j=i+1`$ recovers detailed balance and $`(i,j)=(0,T)`$ trajectory
balance, so one loss interpolates between local bootstrapping and
trajectory variance, and the target terminal law holds at zero loss
([propositions D.3](#A4.Thmproposition3 "Proposition D.3 (Sub-trajectory objective and exact balance). ‣ D.1 Path factorisation and balance identities ‣ Appendix D Proof Details ‣ R2 Flow: Recursive Self-Improvement viaRecursive Skill Evolution")
and [D.5](#A4.Thmproposition5 "Corollary D.5 (Terminal law under an exact compatible triple). ‣ D.2 Compatible reference flows ‣ Appendix D Proof Details ‣ R2 Flow: Recursive Self-Improvement viaRecursive Skill Evolution")).
R²TB is sub-trajectory balance on the shared-state graph with the
per-domain bias $`b_{d}`$ and the reasoning-conditioned forward term,
and its residual variance sets the phase boundary of Section 4.3.

Flow Share and Signed Utility. Flow share measures how much of the
reward-matching flow passes through each skill: at exact balance, a
compatible reference triple $`(F^{0},P_{F}^{0},P_{B}^{0})`$ makes the
normalised edge flow the probability of traversing that edge, and a
skill’s share sums them over its edges:

|  |  |  |  |
|----|----|----|----|
|  |
``` math
\varphi^{0}(e)=\frac{F^{0}(s)\,P_{F}^{0}(e\mid s)}{Z^{\star}(q)},\qquad\Psi^{0}(u)=\frac{\sum_{e\ \text{invokes}\ u}\varphi^{0}(e)}{\sum_{e\in\mathcal{E}_{\mathrm{skill}}}\varphi^{0}(e)},
``` |  | (9) |

where $`F^{0}`$ and $`P_{F}^{0}`$ are defined by the uniform reference
backward policy $`P_{B}^{0}`$ (Appendix D), which also fixes the edge
share $`\varphi^{0}(e)`$ used to allocate verification. The denominator
sums over skill edges, so the shares of all skills sum to one. Every
path to a terminal commits the same events, so $`\Psi^{0}(u)`$ is the
share of $`u`$ among skill calls at terminals drawn in proportion to
$`R_{\eta}`$, for any backward policy
([Corollary D.9](#A4.Thmproposition9 "Corollary D.9 (Skill share on the shared-state graph and its estimator). ‣ D.2 Compatible reference flows ‣ Appendix D Proof Details ‣ R2 Flow: Recursive Self-Improvement viaRecursive Skill Evolution")).
It is estimated per query from trained-policy rollouts, each weighted by
$`e^{-\delta_{0:T}}`$ normalised within the query, and averaged over
queries; the normalisation cancels $`\log Z_{\theta}(q)`$ and $`b_{d}`$.
Flow share is non-negative by construction and measures how much flow a
skill carries; to measure whether it helps, following step-level and
counterfactual credit ([Zhang et al., 2026b](#bib.bib64); [Lu et al.,
2026](#bib.bib25); [Li et al., 2026b](#bib.bib22)), we add a signed
utility $`\widetilde{A}_{e}`$ contrasted with a fixed reference policy
$`\nu`$:

|  |  |  |  |
|----|----|----|----|
|  |
``` math
\widetilde{A}_{e}=\Bigl(\widehat{\mathbb{E}}[R_{\eta}\mid s,e]-\mathbb{E}_{e^{\prime}\sim\nu}\bigl[\widehat{\mathbb{E}}[R_{\eta}\mid s,e^{\prime}]\bigr]\Bigr)\exp\!\bigl(-|\delta_{e}|/\tau_{c}\bigr),
``` |  | (10) |

where $`\widehat{\mathbb{E}}[R_{\eta}\mid s,e]`$ estimates the expected
tempered reward after taking $`e`$ at $`s`$ under a fixed continuation
policy
([eq. B.7](#A2.E7 "In Utility: a separate, signed quantity. ‣ B.2 Flow Diagnostics ‣ Appendix B Balance Objectives and Flow Diagnostics ‣ R2 Flow: Recursive Self-Improvement viaRecursive Skill Evolution")),
$`\nu(\cdot\mid s)`$ is uniform over the legal events at $`s`$,
$`\delta_{e}=\delta_{t-1:t}`$ is the single-edge balance violation, and
$`\tau_{c}>0`$ scales a discount that weights each estimate by how well
the flow balances on that edge. A positive $`\widetilde{A}_{e}`$ means
the event beats an average legal alternative at $`s`$. In
[Figure 3](#S4.F3 "In 4 Methodology: R2 Flow ‣ R2 Flow: Recursive Self-Improvement viaRecursive Skill Evolution"),
skill $`u_{1}`$ carries the most flow while its edge $`e_{1}`$ has
negative signed utility.

Proposition 2. *At zero R²TB loss the Supervisor samples terminals in
proportion to the tempered reward, and flow share is conserved,
independent of the backward policy, consistently estimated from the
rollouts of any trained flow, and separate from whether a skill helps.*
(Empirically, the reference-readout and utility ablations, RQ4 in
§[5](#S5 "5 Experiments ‣ R2 Flow: Recursive Self-Improvement viaRecursive Skill Evolution");
formally, Appendices A, B and D.)

### 4.3 Recursive Skill Evolution with Verifier-Gated Updates

Section 4.2 provides two readouts, the share $`\Psi^{0}(u)`$ and the
signed utility $`\widetilde{A}_{e}`$; both are functions of the reward
the library is judged by, so an edit’s evidence must come from the
verifiers of Section 4.1 rather than that reward. This section
([Figure 3](#S4.F3 "In 4 Methodology: R2 Flow ‣ R2 Flow: Recursive Self-Improvement viaRecursive Skill Evolution"),
panel 3) combines them with verifier evidence once per phase: verifier
labels answer *whether*, the readouts answer *which*, and the residual
answers *when*.

Each phase applies one fixed update, repeated until the compute budget
is spent. The phase state $`X_{k}`$ holds the library, graph, policy and
flow parameters and verifier posterior counts, and a log
$`\mathcal{H}^{\mathrm{imp}}_{k}`$ records each phase’s edit decisions
and validation outcomes. Under fixed configuration $`\lambda`$, the loop
is the recursion $`\Xi_{k+1}=\mathfrak{R}_{\lambda}(\Xi_{k};\zeta_{k})`$
on $`\Xi_{k}=(X_{k},\mathcal{H}^{\mathrm{imp}}_{k})`$, where
$`\mathfrak{R}_{\lambda}`$ runs training, diagnostics, verification and
the library operator $`\Phi`$, and $`\zeta_{k}`$ is the phase randomness
([Proposition C.2](#A3.Thmproposition2 "Proposition C.2 (Phase-state recursion). ‣ Versioning, rollback, hysteresis. ‣ C.2 Phase Transition and Skill Evolution ‣ Appendix C Evidence, Gating, and Skill Evolution ‣ R2 Flow: Recursive Self-Improvement viaRecursive Skill Evolution")).

Whether: Verified Evidence and Credible Bounds. Each invocation carries
a context $`z`$, and each verified one an independent-verifier outcome
$`y_{e}`$ with confidence $`c_{e}`$. The verified invocations of skill
$`u`$ in context $`z`$, $`\mathcal{E}^{\mathrm{ver}}_{u,z}`$, update a
hierarchical Beta posterior over its reliability in $`z`$:

|  |  |  |  |
|----|----|----|----|
|  |
``` math
\alpha^{\mathrm{ver}}_{u,z}=\kappa_{u}\mu_{u}+\sum_{e\in\mathcal{E}^{\mathrm{ver}}_{u,z}}c_{e}y_{e},\qquad\beta^{\mathrm{ver}}_{u,z}=\kappa_{u}(1-\mu_{u})+\sum_{e\in\mathcal{E}^{\mathrm{ver}}_{u,z}}c_{e}(1-y_{e}),
``` |  | (11) |

where $`\mu_{u}`$ is the skill-level reliability and $`\kappa_{u}`$ the
shrinkage strength, pooling sparse contexts toward the skill. Verifier
calls are budgeted and go to the invocations with the largest reference
edge flow $`\varphi^{0}(e)`$
([Remark C.1](#A3.Thmremark1 "Remark C.1 (Flow allocates the verification budget). ‣ Evidence. ‣ C.1 Verifier-Gated Bayesian Calibration ‣ Appendix C Evidence, Gating, and Skill Evolution ‣ R2 Flow: Recursive Self-Improvement viaRecursive Skill Evolution")).
Decisions then act on the posterior’s lower and upper credible bounds,
$`\mathrm{LCB}_{u,z}`$ and $`\mathrm{UCB}_{u,z}`$, rather than point
estimates. The interval separates thin evidence from confirmed weakness:
a wide interval from too few verified records triggers *defer* to
collect more observations, whereas $`\mathrm{UCB}_{u,z}`$ below a
quality threshold triggers *refine* or *prune*.

Which: Flow Share and Signed Utility. Both readouts of Section 4.2 enter
the library operator together with the credible bounds and the
invocation counts:

|  |  |  |  |
|----|----|----|----|
|  |
``` math
\mathcal{S}^{(k+1)}=\Phi\bigl(\mathcal{S}^{(k)};\ \{\Psi^{0}(u),n_{u}^{\mathrm{call}},\mathrm{LCB}_{u,z},\mathrm{UCB}_{u,z}\}_{u\in\mathcal{S}^{(k)}},\ \{\widetilde{A}_{e}\}_{e}\bigr),
``` |  | (12) |

where $`n_{u}^{\mathrm{call}}`$ is the empirical invocation count of
skill $`u`$. The operator applies *defer*, *split*, *refine*, *retain*
and *prune* to single skills, *consolidate* to skill pairs, and
*generate* to context clusters, in that order (rules in Appendix C).
Flow share and signed utility rank the candidate edits. A skill is
refined when it is sound overall and confirmed weak in some context,
split when its contexts diverge, and pruned when it is confirmed weak in
every context, has non-positive signed utility, and every context it
covers is covered by another skill. Every edit is versioned and is
accepted once paired rollouts are non-inferior on success, tempered
reward, token cost, and latency. $`\mathcal{S}^{(k+1)}`$ changes the
graph’s edge set (Section 4.1), so the next phase retrains the flow on
it and recomputes the readouts and $`V_{q}`$.

When: Residual Variance Plateau. For a fixed query,
$`\log Z_{\theta}(q)`$ shifts every full-trajectory residual
$`\delta_{0:T}`$ by the same constant, so their variance is free of it
([Zhang et al., 2023](#bib.bib61), log-partition variance;):

|  |  |  |  |
|----|----|----|----|
|  |
``` math
V_{q}=\operatorname{Var}_{\tau\mid q}\bigl[\delta_{0:T}(\tau)\bigr].
``` |  | (13) |

$`V_{q}`$ is therefore comparable across training steps on one library
version: it falls while the policy learns on the current library, and
when it levels off the phase ends and the next verifier-gated proposals
are made. Writing $`\bar{V}_{w}`$ for $`V_{q}`$ aggregated over held-out
queries at step $`w`$, a phase boundary is declared when the fitted
slope of $`\bar{V}_{w}`$ is flat within a tolerance, its relative
decrease over a recent window is non-negative but small, and the
normalised skill entropy has fallen
([eq. C.9](#A3.E9 "In Trigger. ‣ C.2 Phase Transition and Skill Evolution ‣ Appendix C Evidence, Gating, and Skill Evolution ‣ R2 Flow: Recursive Self-Improvement viaRecursive Skill Evolution")).

Proposition 3. *Every committed skill-library edit is backed by
independent verifier evidence and passes paired validation, the readouts
of Section 4.2 rank the candidates, and one fixed update maps each phase
state to the next.* (Empirically, RQ4 and RQ6 in
§[5](#S5 "5 Experiments ‣ R2 Flow: Recursive Self-Improvement viaRecursive Skill Evolution");
formally, Appendix C.)

#### In distribution (RQ1).

R² Flow leads every IID dataset and metric
([Table 1](#S4.T1 "In 4.3 Recursive Skill Evolution with Verifier-Gated Updates ‣ 4 Methodology: R2 Flow ‣ R2 Flow: Recursive Self-Improvement viaRecursive Skill Evolution")),
2.03 EM and 5.57 accuracy points above SkillOpt, the strongest baseline,
with every average gain significant at $`p<10^{-3}`$
([Figure 4](#S5.F4 "In Setup. ‣ 5 Experiments ‣ R2 Flow: Recursive Self-Improvement viaRecursive Skill Evolution")b).
SFT and GRPO^(†) on the backbone fall below Qwen3.5 in accuracy, whereas
the R² Flow architecture adds 13.71 IID points and training 18.07 more
([Table 2](#S5.T2 "In Setup. ‣ 5 Experiments ‣ R2 Flow: Recursive Self-Improvement viaRecursive Skill Evolution")).
Tuning the backbone on task reward also trades one task for another:
GRPO^(†) raises the IID exact-match average by 7.26 points but lowers
AIME 2026 from 51.33 to 36.00, while R² Flow raises both.

#### Out of distribution (RQ2).

R² Flow again leads every OOD row, 3.83 EM and 2.85 accuracy points
above the strongest baselines, with larger gains over Qwen3.5 than in
distribution and its narrowest margins, about one point, on GPQA and
MATH-Hard. Verification matters more here: edits admitted on
reward-derived labels cost 5.00 OOD points against 3.34 IID
([Table 2](#S5.T2 "In Setup. ‣ 5 Experiments ‣ R2 Flow: Recursive Self-Improvement viaRecursive Skill Evolution")),
as most of them raise the training reward while lowering the held-out
verified score (RQ6). With a 9B Supervisor and executor, R² Flow also
beats DeepSeek-V4-Flash answering directly on all twelve datasets.

#### Across executors (RQ3).

With the trained Supervisor fixed and six other frozen executors
([Figure 4](#S5.F4 "In Setup. ‣ 5 Experiments ‣ R2 Flow: Recursive Self-Improvement viaRecursive Skill Evolution")a,d),
R² Flow raises every backbone on every IID dataset and OOD domain, by
15.70 to 24.64 points on average, and narrows the IID spread across
executors from 14.5 to 6.9 points. Weaker executors gain more (Pearson
$`r=-0.97`$) and all gain more out of distribution, consistent with the
orchestration and verified skills compensating for the weaker executors.

#### Component ablations (RQ4).

All 108 ablated cells of
[Table 2](#S5.T2 "In Setup. ‣ 5 Experiments ‣ R2 Flow: Recursive Self-Improvement viaRecursive Skill Evolution")
fall below the full model. Shared states matter most, 7.31 IID and 5.99
OOD points: on a history tree, reorderings of one procedure no longer
pool evidence, so the flow spreads over them and distinct strategies per
domain fall from 9.6–14.9 to 5.2–8.0, near the baselines
([Figure 5](#S5.F5 "In Setup. ‣ 5 Experiments ‣ R2 Flow: Recursive Self-Improvement viaRecursive Skill Evolution")f),
and training accuracy falls behind
([Figure 4](#S5.F4 "In Setup. ‣ 5 Experiments ‣ R2 Flow: Recursive Self-Improvement viaRecursive Skill Evolution")c).
For credit, a uniform $`P_{B}`$, which splits credit evenly over the
skills reaching a merged state, costs 4.52 IID points, and ranking by
share alone, which reads frequent use as benefit, 3.61. Replacing
credible bounds by posterior means, which cannot tell thin evidence from
confirmed weakness, costs 2.23 IID and 2.97 OOD points, and resetting
the phase state, which discards the flow and verifier posterior carried
across phases, about five points on both splits. Reading the shares off
the learned flow, whose internal flows depend on $`P_{B}`$, costs 2.63
IID and 1.61 OOD points.

#### Training objectives (RQ5).

R²TB leads every IID dataset
([Figure 5](#S5.F5 "In Setup. ‣ 5 Experiments ‣ R2 Flow: Recursive Self-Improvement viaRecursive Skill Evolution")a)
and beats every other objective on OOD by 1.69–6.17 points
([Figure 5](#S5.F5 "In Setup. ‣ 5 Experiments ‣ R2 Flow: Recursive Self-Improvement viaRecursive Skill Evolution")b),
for 7.5% more GPU time than GRPO. SubTB, which balances the same
sub-trajectories without the per-domain bias $`b_{d}`$ that absorbs a
shared offset of each domain’s terminal residuals, comes closest. TB and
DB, which balance only whole trajectories or single edges, trail it, and
GRPO, without a balance residual, is lowest.

#### Phase-to-phase improvement (RQ6).

The mean OOD score rises from 71.2 to 81.02 over eight phases and dips
only once
([Figure 5](#S5.F5 "In Setup. ‣ 5 Experiments ‣ R2 Flow: Recursive Self-Improvement viaRecursive Skill Evolution")c),
as each phase trains on the library the previous one committed and 33 of
the 37 committed edits raise the held-out verified score (precision
0.89,
[Figure 5](#S5.F5 "In Setup. ‣ 5 Experiments ‣ R2 Flow: Recursive Self-Improvement viaRecursive Skill Evolution")d).
With reward-derived labels, 25 of 44 edits raise the training reward but
lower the verified score, so accuracy peaks at phase 3 and then
declines; a frozen library stalls below 75, and fixed-length phases end
at 78.99. Signed utility lets R² Flow prune eleven of twelve injected
harmful skills
([Figure 5](#S5.F5 "In Setup. ‣ 5 Experiments ‣ R2 Flow: Recursive Self-Improvement viaRecursive Skill Evolution")e),
six by phase 2 and the rest as evidence accumulates, whereas share-only
ranking keeps eight, Bayesian-Agent ([Wu et al., 2026](#bib.bib46)) six
and SkillFlow ([Zhang et al., 2026e](#bib.bib68)) seven.

## 6 Conclusion

We presented R² Flow, a recursive self-improvement framework that admits
library edits on verifier evidence outside the task reward. On twelve
datasets it beats every baseline in and out of distribution and improves
over eight phases without human intervention, at 0.89 held-out edit
precision.

## Appendix A Formal Foundations of the Orchestration Graph

### A.1 Quotient Orchestration Graph

#### Raw histories.

An execution history evolves by appending atomic records,

|     |                                                             |     |       |
|-----|-------------------------------------------------------------|-----|-------|
|     |
       ``` math
       H_{t}\;=\;H_{t-1}\oplus(r_{t},e_{t},o_{t}^{\mathrm{exec}}),
       ```                                                          |     | (A.1) |

where $`r_{t}`$ is internal reasoning text, $`e_{t}`$ the executed
orchestration event (a skill or tool invocation with structured
arguments), and $`o_{t}^{\mathrm{exec}}`$ the environment feedback.
Given a query $`q`$ and a retrieved skill subset
$`\mathcal{S}_{\mathrm{ret}}\subseteq\mathcal{S}^{(k)}`$ together with a
task-conditioned prompt state $`\omega_{q}`$, the root history is
$`H_{0}=q\oplus\mathcal{S}_{\mathrm{ret}}\oplus\omega_{q}`$, to which
[eq. A.1](#A1.E1 "In Raw histories. ‣ A.1 Quotient Orchestration Graph ‣ Appendix A Formal Foundations of the Orchestration Graph ‣ R2 Flow: Recursive Self-Improvement viaRecursive Skill Evolution")
appends the first atomic record.

###### Remark A.1 (Canonicalisation creates informative backward structure).

If nodes are identified with histories, every node except the root has
exactly one parent, namely $`H_{t}`$ with its last record deleted. The
resulting object is a prefix tree, not a confluent DAG, and the backward
transition probability is degenerate,
$`P_{B}(H_{t-1}\mid H_{t})\equiv 1`$. Canonicalisation merges
reorderings of independent events into shared states, turning the prefix
tree of raw histories into a DAG with multiple valid incoming edges; the
resulting backward transition therefore carries information about how a
state was reached.

###### Definition A.1 (Execution trace and dependency order).

Let $`E_{t}`$ be the set of atomic event instances committed after $`t`$
steps. The direct dependency relation records when an event consumes an
artifact, fact, or environment change produced by another event;
$`\prec_{t}`$ denotes its transitive closure, so it is a partial order.
Repeated calls with the same skill and arguments are distinct event
instances, while their provenance is retained in the canonical state.
Let $`\mathcal{A}_{t}`$ be the canonicalised artifacts with provenance,
$`\mathcal{V}_{t}`$ the verified facts, and $`\Omega_{t}`$ the
environment observables required for future decisions. The abstraction
map, whose values are the shared states of Section 4.1, is

|  |  |  |  |
|----|----|----|----|
|  |
``` math
s_{t}\;=\;\sigma(H_{t})\;=\;\bigl(E_{t},\ \prec_{t},\ \mathcal{A}_{t},\ \mathcal{V}_{t},\ \Omega_{t}\bigr).
``` |  | (A.2) |

Two histories are identified iff they are distinct linear extensions of
the same dependency order with identical artifacts, facts, and
observables; this is the Mazurkiewicz trace equivalence of concurrency
theory ([Mazurkiewicz, 1986](#bib.bib28)) (trace in the sense of a
partial-order equivalence class of executions, not an orchestration
trace in the sense used by [Zhang (2026b)](#bib.bib60)).

###### Assumption A.1 (Quotient validity).

For all $`H,H^{\prime}`$ with $`\sigma(H)=\sigma(H^{\prime})=s`$:

1.  (a)
    *action-mask consistency*:
    $`\mathcal{E}(H)=\mathcal{E}(H^{\prime})`$, the legal event sets
    coincide;
2.  (b)
    *successor consistency*:
    $`\mathbb{P}\bigl(\sigma(H\oplus e)=s^{\prime}\mid H,e\bigr)=\mathbb{P}\bigl(\sigma(H^{\prime}\oplus e)=s^{\prime}\mid H^{\prime},e\bigr)`$
    for all legal $`e`$;
3.  (c)
    *terminal-reward consistency*: if $`s`$ is terminal then
    $`R(H)=R(H^{\prime})`$, i.e. the reward is measurable with respect
    to the terminal *node* $`s`$ shared by $`H`$ and $`H^{\prime}`$.

###### Assumption A.2 (Markov policy and flow).

The backward policy and state flow read only the abstract state, and the
forward policy reads it together with the current reasoning text
$`r_{t}`$: the first two are functions of $`(s,q,k)`$ and the forward
policy of $`(s,q,k,r_{t})`$, none of the discarded history
([section C.3](#A3.SS3 "C.3 Approximate Balance and Abstraction Error ‣ Appendix C Evidence, Gating, and Skill Evolution ‣ R2 Flow: Recursive Self-Improvement viaRecursive Skill Evolution")).
Reasoning text $`r_{t}`$ influences future behaviour only through the
canonicalised content it commits to the artifacts $`\mathcal{A}_{t}`$ or
the verified facts $`\mathcal{V}_{t}`$.

###### Assumption A.3 (Finite event horizon and branching).

There is a finite horizon $`T<\infty`$, and every nonterminal abstract
state has a finite nonempty set of legal events. Terminal states have no
outgoing events. The horizon and event set are fixed within a library
version; a phase update may change them only at a phase boundary
declared by the trigger of
[eq. C.9](#A3.E9 "In Trigger. ‣ C.2 Phase Transition and Skill Evolution ‣ Appendix C Evidence, Gating, and Skill Evolution ‣ R2 Flow: Recursive Self-Improvement viaRecursive Skill Evolution").

###### Assumption A.4 (Canonicalised transitions).

After canonicalisation, the successor state is a deterministic function
of $`(s,e)`$. Tools with stochastic canonicalised output are modelled by
the event/environment split $`s\to(s,e)\to s^{\prime}`$ into an event
step and an environment step.

###### Definition A.2 (Edges, in-edges, rank).

An edge $`s\xrightarrow{e}s^{\prime}`$ exists iff $`e`$ is legal at
$`s`$ and $`\sigma`$-appending $`e`$ yields $`s^{\prime}`$. The in-edge
set is $`\Inn(s^{\prime})=\{(s,e):s\xrightarrow{e}s^{\prime}\}`$, and
its predecessor-state projection is:

|  |  |  |  |
|----|----|----|----|
|  |
``` math
\Pa(s^{\prime})\;=\;\bigl\{\,s:\exists e\text{ with }s\xrightarrow{e}s^{\prime}\,\bigr\}.
``` |  | (A.3) |

Each edge commits one atomic event, so each in-edge deletes one
$`\prec`$-maximal event whose removal leaves a legal predecessor. The
rank is $`\rho(s)=|E_{s}|`$, the number of committed atomic events.

###### Proposition A.1 (Well-posedness).

Every edge strictly increases $`\rho`$; hence the quotient graph is a
finite DAG with a single source $`s_{0}=\sigma(H_{0})`$, and every
complete trajectory visits states of strictly increasing rank $`\rho`$,
the number of committed atomic events.

###### Proof.

Each edge commits at least one atomic event, so
$`\rho(s^{\prime})\geq\rho(s)+1>\rho(s)`$. A strictly monotone integer
potential forbids cycles. By
[Assumption A.3](#A1.Thmassumption3 "Assumption A.3 (Finite event horizon and branching). ‣ Raw histories. ‣ A.1 Quotient Orchestration Graph ‣ Appendix A Formal Foundations of the Orchestration Graph ‣ R2 Flow: Recursive Self-Improvement viaRecursive Skill Evolution"),
every path has at most $`T`$ events and every node has finite branching,
so the reachable quotient graph is finite. ∎

#### Terminal states and tempered reward.

Let $`\mathcal{X}`$ be the set of terminal nodes. By
[Assumption A.1](#A1.Thmassumption1 "Assumption A.1 (Quotient validity). ‣ Raw histories. ‣ A.1 Quotient Orchestration Graph ‣ Appendix A Formal Foundations of the Orchestration Graph ‣ R2 Flow: Recursive Self-Improvement viaRecursive Skill Evolution")(c)
the reward is a function of the terminal node, and we temper and shift
it as

|  |  |  |  |
|----|----|----|----|
|  |
``` math
R_{\eta}(x)\;=\;\bigl(R(x)+\epsilon\bigr)^{\eta},\qquad R(x)\in[0,1],\ \epsilon>0,\ \eta>0.
``` |  | (A.4) |

###### Proposition A.2 (Representation multiplicity).

Suppose an observable outcome $`o`$ is represented by $`k(o)`$ distinct
terminal nodes, each anchored to $`R_{\eta}(o)`$. Then at any exact
balance solution

|  |  |  |  |
|----|----|----|----|
|  |
``` math
P_{F}^{\mathrm{term}}(o\mid q)\;=\;\frac{k(o)\,R_{\eta}(o)}{Z^{\star}(q)},
``` |  | (A.5) |

i.e. outcomes are over-sampled in proportion to how many ways they can
be represented.

###### Proof.

At the exact solution
$`P_{F}^{\mathrm{term}}(x\mid q)=R_{\eta}(x)/Z^{\star}(q)`$ for each
terminal node $`x`$
([proposition A.3](#A1.Thmproposition3 "Proposition A.3 (Two faces of 𝑃_𝐵). ‣ Backward policy. ‣ A.2 Forward and Backward Policies ‣ Appendix A Formal Foundations of the Orchestration Graph ‣ R2 Flow: Recursive Self-Improvement viaRecursive Skill Evolution")).
Summing over the $`k(o)`$ nodes representing $`o`$ gives
[eq. A.5](#A1.E5 "In Proposition A.2 (Representation multiplicity). ‣ Terminal states and tempered reward. ‣ A.1 Quotient Orchestration Graph ‣ Appendix A Formal Foundations of the Orchestration Graph ‣ R2 Flow: Recursive Self-Improvement viaRecursive Skill Evolution").
∎

#### Library versioning.

A skill-library update changes the legal event set and therefore the
graph itself. We write $`\mathcal{G}^{(k)}`$ for the graph of library
version $`k`$ and condition all learned objects on the version index,
the policies $`P_{F}(\cdot\mid s,q,k)`$ and
$`P_{B}(\cdot\mid s^{\prime},q,k)`$, and the flow $`F_{\psi}(s,q,k)`$.

### A.2 Forward and Backward Policies

#### Semantic action factorisation.

An event is a pair $`e=(u,\mathrm{args})`$ of a skill/tool identifier
$`u\in\mathcal{S}^{(k)}`$ and structured arguments, so that

|  |  |  |  |
|----|----|----|----|
|  |
``` math
P_{F}(e\mid s,q,k)\;=\;P_{F}(u\mid s,q,k)\,P_{F}(\mathrm{args}\mid u,s,q,k).
``` |  | (A.6) |

###### Remark A.2 (Token-length normalisation).

Because each event is modelled directly as a skill identifier and
structured arguments,
[eq. A.6](#A1.E6 "In Semantic action factorisation. ‣ A.2 Forward and Backward Policies ‣ Appendix A Formal Foundations of the Orchestration Graph ‣ R2 Flow: Recursive Self-Improvement viaRecursive Skill Evolution")
defines a normalised probability over executable events without
token-length correction, and a policy used consistently for sampling and
for balance evaluation satisfies the balance identities encoded by the
residual in
[eq. B.1](#A2.E1 "In B.1 The R2TB Objective ‣ Appendix B Balance Objectives and Flow Diagnostics ‣ R2 Flow: Recursive Self-Improvement viaRecursive Skill Evolution").

#### Backward policy.

The backward policy is a distribution over *in-edges*, parameterised
with hindsight features and normalised explicitly:

|  |  |  |  |
|----|----|----|----|
|  |
``` math
P_{B}\bigl((s,e)\mid s^{\prime}\bigr)\;=\;\frac{\exp f_{\phi}(s,e,s^{\prime})}{\displaystyle\sum_{(\bar{s},\bar{e})\in\Inn(s^{\prime})}\exp f_{\phi}(\bar{s},\bar{e},s^{\prime})}.
``` |  | (A.7) |

###### Definition A.3 (Canonical backward policy).

$`P_{B}^{0}\bigl((s,e)\mid s^{\prime}\bigr)=1/|\Inn(s^{\prime})|`$: the
valid in-edges are weighted uniformly *locally*. This uniform weighting
is local, so complete linearisations of a trace can have different
probabilities under the canonical backward policy $`P_{B}^{0}`$.

###### Proposition A.3 (Two faces of $`P_{B}`$).

Let $`Z^{\star}(q)=\sum_{x\in\mathcal{X}}R_{\eta}(x)`$ and suppose
balance holds exactly.

1.  (i)
    *(Invariance.)* The terminal marginal satisfies
    $`P_{F}^{\mathrm{term}}(x\mid q)=R_{\eta}(x)/Z^{\star}(q)`$ for
    every choice of normalised backward policy $`P_{B}`$ with full
    support.
2.  (ii)
    *(Dependence.)* The internal state flows $`F(s)`$ do depend on
    $`P_{B}`$.

###### Proof.

(i) Exact balance gives
$`P_{F}(\tau)=R_{\eta}(x_{\tau})P_{B}(\tau\mid x_{\tau})/Z^{\star}(q)`$.
Summing over trajectories reaching a fixed $`x`$ and using
$`\sum_{\tau\to x}P_{B}(\tau\mid x)=1`$ yields
$`P_{F}^{\mathrm{term}}(x\mid q)=R_{\eta}(x)/Z^{\star}(q)`$. (ii) Take a
single terminal $`x`$ reached by two length-two paths through distinct
states $`\hat{u}`$ and $`\hat{v}`$. Then
$`F(\hat{u})/F(\hat{v})=P_{B}(\hat{u}\text{-path}\mid x)/P_{B}(\hat{v}\text{-path}\mid x)`$,
which equals $`9`$ for $`P_{B}=(0.9,0.1)`$ and $`1`$ for $`P_{B}^{0}`$,
while the terminal marginal is identical in both cases. ∎

###### Remark A.3 (Consequence for credit).

Terminal reward matching does not pin down internal flow: edge and state
flows read off $`F`$ depend on the backward policy, whereas the skill
share $`\Psi^{0}`$ does not
([corollary D.9](#A4.Thmproposition9 "Corollary D.9 (Skill share on the shared-state graph and its estimator). ‣ D.2 Compatible reference flows ‣ Appendix D Proof Details ‣ R2 Flow: Recursive Self-Improvement viaRecursive Skill Evolution")).
We keep training and readout separate: the flow is trained with the
learned $`P_{B,\phi}`$, and the reference readout is defined by a
compatible triple $`(F^{0},P_{F}^{0},P_{B}^{0})`$ and estimated from the
trained policy’s rollouts with the residual weights of
[corollary D.9](#A4.Thmproposition9 "Corollary D.9 (Skill share on the shared-state graph and its estimator). ‣ D.2 Compatible reference flows ‣ Appendix D Proof Details ‣ R2 Flow: Recursive Self-Improvement viaRecursive Skill Evolution").

## Appendix B Balance Objectives and Flow Diagnostics

### B.1 The R²TB Objective

We learn a forward policy $`P_{F}`$, a backward policy $`P_{B}`$, and an
explicit log-flow head $`\log F_{\psi}(s)`$. For $`0\leq i<j\leq T`$
define the residual

|  |  |  |  |
|----|----|----|----|
|  |
``` math
\delta_{i:j}\;=\;\log F_{\psi}(s_{i})+\sum_{t=i+1}^{j}\log P_{F}(e_{t}\mid s_{t-1})-\log F_{\psi}(s_{j})-\sum_{t=i+1}^{j}\log P_{B}\bigl((s_{t-1},e_{t})\mid s_{t}\bigr),
``` |  | (B.1) |

with the terminal anchor and source identification

|  |  |  |  |
|----|----|----|----|
|  |
``` math
\log F_{\psi}(x)\;=\;\log R_{\eta}(x)\quad\forall x\in\mathcal{X},\qquad F_{\psi}(s_{0})\;=\;Z_{\theta}(q).
``` |  | (B.2) |

The objective is

|  |  |  |  |
|----|----|----|----|
|  |
``` math
\mathcal{L}_{\mathrm{flow}}\;=\;\sum_{0\leq i<j\leq T}\omega_{j-i}\,\delta_{i:j}^{2},
``` |  | (B.3) |

where $`j=i+1`$ recovers detailed balance, $`(i,j)=(0,T)`$ recovers
trajectory balance, and intermediate lengths interpolate between local
bootstrapping and whole-trajectory variance. R²TB is this objective with
the domain offset of
[remark B.1](#A2.Thmremark1 "Remark B.1 (Domain bias). ‣ B.1 The R2TB Objective ‣ Appendix B Balance Objectives and Flow Diagnostics ‣ R2 Flow: Recursive Self-Improvement viaRecursive Skill Evolution")
and the $`r_{t}`$-conditioned $`P_{F}`$ of
[section C.3](#A3.SS3 "C.3 Approximate Balance and Abstraction Error ‣ Appendix C Evidence, Gating, and Skill Evolution ‣ R2 Flow: Recursive Self-Improvement viaRecursive Skill Evolution").

###### Remark B.1 (Domain bias).

For a query of domain $`d`$ the implementation adds one scalar $`b_{d}`$
to $`\log Z_{\theta}(q)`$ and to every intermediate
$`\log F_{\psi}(s)`$, and keeps the terminal anchor at
$`\log R_{\eta}(x)`$. The offset cancels in every residual whose
endpoints are both nonterminal and shifts every residual that ends at a
terminal by $`b_{d}`$. Since the flow head is conditioned on $`q`$,
$`b_{d}`$ keeps the zero-loss solutions of
[proposition D.3](#A4.Thmproposition3 "Proposition D.3 (Sub-trajectory objective and exact balance). ‣ D.1 Path factorisation and balance identities ‣ Appendix D Proof Details ‣ R2 Flow: Recursive Self-Improvement viaRecursive Skill Evolution")
and absorbs the shared domain offset during training. It is updated
toward a closed-form target: after each step it moves by $`0.3`$ times
the median, over the domain’s trajectories, of the shift
$`c^{\star}=-\sum_{i}\omega_{T-i}\delta_{i:T}/\sum_{i}\omega_{T-i}`$
that minimises each trajectory’s loss, and it is carried to the next
phase together with $`\psi`$. At zero loss every $`c^{\star}`$ vanishes,
so $`b_{d}`$ is stationary. The within-query variance $`V_{q}`$ and the
reference share $`\Psi^{0}(u)`$ do not depend on $`b_{d}`$. The
implementation uses $`\omega_{j-i}\propto 0.9^{\,j-i}`$ normalised per
trajectory, $`\eta=4`$, and $`\epsilon=0.1`$.

###### Remark B.2 (Which residual to report).

$`\log Z_{\theta}(q)`$ enters $`\delta_{0:T}`$ as a constant shift for a
fixed $`q`$, but $`\log Z_{\theta}(q)/T`$ does not when trajectory
lengths vary. All diagnostics in
[section C.2](#A3.SS2 "C.2 Phase Transition and Skill Evolution ‣ Appendix C Evidence, Gating, and Skill Evolution ‣ R2 Flow: Recursive Self-Improvement viaRecursive Skill Evolution")
therefore use the raw residual $`\delta_{0:T}`$ of
[eq. B.1](#A2.E1 "In B.1 The R2TB Objective ‣ Appendix B Balance Objectives and Flow Diagnostics ‣ R2 Flow: Recursive Self-Improvement viaRecursive Skill Evolution"),
never a length-normalised variant.

### B.2 Flow Diagnostics

###### Proposition B.1 (What the state flow is).

Let $`h_{B}(s\mid x)`$ be the probability that backward sampling from
terminal $`x`$ under $`P_{B}`$ passes through $`s`$. At exact balance,

|  |  |  |  |
|----|----|----|----|
|  |
``` math
F(s)\;=\;\sum_{x\in\mathcal{X}}R_{\eta}(x)\,h_{B}(s\mid x),\qquad F(s_{0})=Z^{\star}(q),\qquad F(x)=R_{\eta}(x).
``` |  | (B.4) |

###### Proof.

Trajectory flow at the optimum is
$`F(\tau)=Z^{\star}P_{F}(\tau)=R_{\eta}(x_{\tau})P_{B}(\tau\mid x_{\tau})`$.
Summing over trajectories through $`s`$ and grouping by terminal state
gives
[eq. B.4](#A2.E4 "In Proposition B.1 (What the state flow is). ‣ B.2 Flow Diagnostics ‣ Appendix B Balance Objectives and Flow Diagnostics ‣ R2 Flow: Recursive Self-Improvement viaRecursive Skill Evolution").
∎

###### Remark B.3 (The state flow as downstream reward mass).

The flow through $`s`$ that terminates at $`x`$ equals both
$`F(s)P_{F}(x\mid s)`$ and $`R_{\eta}(x)h_{B}(s\mid x)`$, so
$`P_{F}(x\mid s)=R_{\eta}(x)h_{B}(s\mid x)/F(s)`$ and

|  |  |  |  |
|----|----|----|----|
|  |
``` math
\mathbb{E}_{P_{F}}\bigl[R_{\eta}\mid s\bigr]\;=\;\frac{1}{F(s)}\sum_{x}R_{\eta}(x)^{2}\,h_{B}(s\mid x).
``` |  | (B.5) |

The second moment appears, so
$`F(s)\not\propto\mathbb{E}[R_{\eta}\mid s]`$ in general. $`F`$ is a
partition function over the downstream reward mass of $`s`$ and
$`\log F`$ a free energy.

#### Importance: normalised flow share.

Define the normalized expected invocation mass routed through an edge
and through a skill under the reward-matching reference law,

|  |  |  |  |
|----|----|----|----|
|  |
``` math
\varphi^{0}(e)\;=\;\frac{F^{0}(s)\,P_{F}^{0}(e\mid s)}{Z^{\star}(q)},\qquad\Psi^{0}(u)\;=\;\frac{\sum_{e\,\text{invoking}\,u}\varphi^{0}(e)}{\sum_{e\in\mathcal{E}_{\mathrm{skill}}}\varphi^{0}(e)}.
``` |  | (B.6) |

###### Proposition B.2 (Conservation).

If $`\mathcal{C}`$ is a cut, i.e. every complete trajectory visits
exactly one state of $`\mathcal{C}`$, then
$`\sum_{s\in\mathcal{C}}F^{0}(s)=Z^{\star}(q)`$. For every nonterminal
state $`s`$, $`\sum_{e\in\Out(s)}\varphi^{0}(e)=F^{0}(s)/Z^{\star}(q)`$.
If $`\mathcal{E}_{\mathrm{skill}}`$ is the set of counted edges and
every such edge invokes exactly one skill, then
$`\sum_{u}\Psi^{0}(u)=1`$ when the denominator of $`\Psi^{0}`$ is
restricted to $`\mathcal{E}_{\mathrm{skill}}`$.

###### Proof.

For each terminal-directed trajectory $`\tau`$, let its reference
trajectory mass be $`m^{0}(\tau)=F^{0}(s_{0})P_{F}^{0}(\tau)`$. Exact
balance and the terminal anchor give
$`\sum_{\tau}m^{0}(\tau)=Z^{\star}(q)`$. Since the cut is visited
exactly once, partitioning the trajectories by their unique cut state
yields
$`\sum_{s\in\mathcal{C}}F^{0}(s)=\sum_{\tau}m^{0}(\tau)=Z^{\star}(q)`$.
For a fixed state,
$`F^{0}(s)=\sum_{e\in\Out(s)}F^{0}(s)P_{F}^{0}(e\mid s)`$, so dividing
by $`Z^{\star}(q)`$ gives
$`\sum_{e\in\Out(s)}\varphi^{0}(e)=F^{0}(s)/Z^{\star}(q)`$. Finally, if
each counted skill edge has one and only one skill label, the skill sums
form a partition of
$`\sum_{e\in\mathcal{E}_{\mathrm{skill}}}\varphi^{0}(e)`$; after
dividing by this same positive denominator, $`\sum_{u}\Psi^{0}(u)=1`$,
the normalisation of the skill share in
[eq. B.6](#A2.E6 "In Importance: normalised flow share. ‣ B.2 Flow Diagnostics ‣ Appendix B Balance Objectives and Flow Diagnostics ‣ R2 Flow: Recursive Self-Improvement viaRecursive Skill Evolution").
∎

#### Utility: a separate, signed quantity.

For utility we compare an event against a *fixed* reference distribution
$`\nu`$, uniform over the legal events at $`s`$,

|  |  |  |  |
|----|----|----|----|
|  |
``` math
A^{\mathrm{util}}_{e}\;=\;\widehat{\mathbb{E}}\bigl[R_{\eta}\mid s,e\bigr]-\mathbb{E}_{e^{\prime}\sim\nu(\cdot\mid s)}\bigl[\widehat{\mathbb{E}}[R_{\eta}\mid s,e^{\prime}]\bigr],
``` |  | (B.7) |

and discount it by the edge-level balance violation
$`\delta_{e}=\delta_{t-1:t}`$,

|  |  |  |  |
|----|----|----|----|
|  |
``` math
\widetilde{A}_{e}\;=\;A^{\mathrm{util}}_{e}\,\exp\!\bigl(-|\delta_{e}|/\tau_{c}\bigr).
``` |  | (B.8) |

Here $`\widehat{\mathbb{E}}[R_{\eta}\mid s,e]`$ estimates
$`Q^{\pi_{\mathrm{eval}}}(s,e)`$ under a fixed continuation policy
$`\pi_{\mathrm{eval}}`$.

## Appendix C Evidence, Gating, and Skill Evolution

### C.1 Verifier-Gated Bayesian Calibration

Each invocation carries a context feature vector

|  |  |  |  |
|----|----|----|----|
|  |
``` math
z=\bigl[\text{context class},\ \text{failure mode},\ \text{token bucket},\ \text{horizon bucket}\bigr].
``` |  | (C.1) |

Context features use only information available before the invocation; a
failure mode observed afterwards enters later invocations as a lagged
feature.

#### Evidence.

Labels come from independent verifiers (unit tests, schema validation,
assertions, execution status) with confidence
$`c^{\mathrm{ver}}_{e}\in[0,1]`$. For each skill/context cell define the
verifier-record index set, which collects the verifier records of skill
$`u`$ observed in context $`z`$,

|  |  |  |  |
|----|----|----|----|
|  |
``` math
\mathcal{E}^{\mathrm{ver}}_{u,z}=\{e\in\mathcal{E}^{\mathrm{ver}}:\ u(e)=u,\ z(e)=z\}.
``` |  | (C.2) |

Only these verifier records enter the gate posterior:

|  |  |  |  |  |
|----|----|----|----|----|
|  | $`\displaystyle\alpha^{\mathrm{ver}}_{u,z}`$ | $`\displaystyle=\alpha_{0,u}+\sum_{e\in\mathcal{E}^{\mathrm{ver}}_{u,z}}c^{\mathrm{ver}}_{e}y_{e},`$ |  | (C.3) |
|  | $`\displaystyle\beta^{\mathrm{ver}}_{u,z}`$ | $`\displaystyle=\beta_{0,u}+\sum_{e\in\mathcal{E}^{\mathrm{ver}}_{u,z}}c^{\mathrm{ver}}_{e}(1-y_{e}).`$ |  | (C.4) |

A soft label $`\widetilde{y}_{e}\in[0,1]`$ derived from
$`\widetilde{A}_{e}`$ enters a separate proposal score
$`q^{\mathrm{soft}}_{u,z}`$ that orders candidates and stays outside the
gate posterior $`(\alpha^{\mathrm{ver}},\beta^{\mathrm{ver}})`$ of
[eqs. C.3](#A3.E3 "In Evidence. ‣ C.1 Verifier-Gated Bayesian Calibration ‣ Appendix C Evidence, Gating, and Skill Evolution ‣ R2 Flow: Recursive Self-Improvement viaRecursive Skill Evolution")
and [C.4](#A3.E4 "Equation C.4 ‣ Evidence. ‣ C.1 Verifier-Gated Bayesian Calibration ‣ Appendix C Evidence, Gating, and Skill Evolution ‣ R2 Flow: Recursive Self-Improvement viaRecursive Skill Evolution").

###### Remark C.1 (Flow allocates the verification budget).

$`\varphi^{0}(e)`$ decides *which* invocations are worth verifying;
verifier confidence decides *how much* an observation counts as
evidence. Keeping the two roles separate is what makes the posterior
interpretable.

###### Remark C.2 (Effective sample size).

With fractional weights, the quantity that behaves like a sample count
is Kish’s effective sample size ([Kish, 1965](#bib.bib16)),

|  |  |  |  |
|----|----|----|----|
|  |
``` math
N_{\mathrm{eff}}=\frac{\bigl(\sum_{e}w_{e}\bigr)^{2}}{\sum_{e}w_{e}^{2}}\quad(\text{zero without records}),
``` |  | (C.5) |

not $`\sum_{e}w_{e}`$: one weight of size $`N`$ with the rest near zero
has $`\sum_{e}w_{e}=N`$ but $`N_{\mathrm{eff}}\approx 1`$.

#### Hierarchical prior and credible bounds.

Contexts are pooled towards the skill-level reliability $`\mu_{u}`$ with
strength $`\kappa_{u}`$, using the same prior parameters as the verifier
gate, $`\alpha_{0,u}=\kappa_{u}\mu_{u}`$ and
$`\beta_{0,u}=\kappa_{u}(1-\mu_{u})`$:

|  |  |  |  |
|----|----|----|----|
|  |
``` math
p_{u,z}\ \sim\ \mathrm{Beta}\bigl(\kappa_{u}\mu_{u},\ \kappa_{u}(1-\mu_{u})\bigr),
``` |  | (C.6) |

and decisions use Beta quantiles rather than a normal approximation:

|  |  |  |  |
|----|----|----|----|
|  |
``` math
\mathrm{LCB}_{u,z}=Q_{a}(\alpha^{\mathrm{ver}}_{u,z},\beta^{\mathrm{ver}}_{u,z}),\qquad\mathrm{UCB}_{u,z}=Q_{1-a}(\alpha^{\mathrm{ver}}_{u,z},\beta^{\mathrm{ver}}_{u,z}).
``` |  | (C.7) |

With fractional confidences these bounds are credible quantiles of a
power posterior
([proposition D.10](#A4.Thmproposition10 "Proposition D.10 (Fractional verifier evidence as a power posterior). ‣ D.3 Verifier posteriors and decision invariants ‣ Appendix D Proof Details ‣ R2 Flow: Recursive Self-Improvement viaRecursive Skill Evolution")).

### C.2 Phase Transition and Skill Evolution

#### A partition-function-free stagnation statistic.

For a fixed query $`q`$, fixed graph, policy, and trajectory law, the
source log-flow $`\log Z_{\theta}(q)`$ shifts every complete-trajectory
residual $`\delta_{0:T}(\tau)`$ by the same constant, hence the residual
variance

|  |  |  |  |
|----|----|----|----|
|  |
``` math
V_{q}\;=\;\operatorname{Var}_{\tau\mid q}\bigl[\delta_{0:T}(\tau)\bigr]
``` |  | (C.8) |

is invariant to that source-log-flow shift. It is estimated from
independent rollouts of each query, and queries are aggregated with a
random-effects model.

#### Trigger.

Let $`\bar{V}_{w}`$ be $`V_{q}`$ aggregated over the held-out validation
query set
([Appendix E](#A5 "Appendix E Full experimental results ‣ R2 Flow: Recursive Self-Improvement viaRecursive Skill Evolution"))
at training step $`w`$, $`b`$ the slope of a linear fit to
$`\bar{V}_{w}`$ over a window $`W`$, and $`\mathrm{CI}(b)`$ its
confidence interval at a fixed level. A phase boundary is declared iff
all three hold:

|  |  |  |  |
|----|----|----|----|
|  |
``` math
\mathrm{CI}(b)\subseteq[-\epsilon_{b},\,\epsilon_{b}],\qquad\frac{\bar{V}_{w-W}-\bar{V}_{w}}{\max\{\bar{V}_{w-W},\,v_{\min}\}}\in[0,\gamma_{\mathrm{var}}),\qquad\Delta H_{\mathrm{norm}}<-h_{0},
``` |  | (C.9) |

where $`\epsilon_{b}>0`$ is the slope tolerance, $`v_{\min}>0`$ a
numerical floor, $`\gamma_{\mathrm{var}}>0`$ the plateau tolerance,
$`h_{0}>0`$ a margin, and $`\Delta H_{\mathrm{norm}}`$ the change over
the window of the normalised skill entropy
$`H_{\mathrm{norm}}=H(\mathcal{S}\mid q,z)/\log|\mathcal{S}_{\mathrm{active}}|`$,
with $`H(\mathcal{S}\mid q,z)=-\sum_{u}p_{u\mid q,z}\log p_{u\mid q,z}`$
and $`p_{u\mid q,z}\propto n_{u,q,z}^{\mathrm{call}}`$ computed from the
held-out rollouts in that query/context cell. The first condition is an
equivalence test that places the whole interval inside a tolerance band,
the lower bound of zero in the second excludes divergence, and the
normalised entropy keeps changes in library size from masquerading as
saturation.

#### Evolution operator.

The library is refined by

|  |  |  |  |
|----|----|----|----|
|  |
``` math
\mathcal{S}^{(k+1)}\;=\;\Phi\bigl(\mathcal{S}^{(k)};\ \Psi^{0}(u),\ n_{u}^{\mathrm{call}},\ \mathrm{LCB}_{u,z},\ \mathrm{UCB}_{u,z},\ \widetilde{A}_{e}\bigr),
``` |  | (C.10) |

whose actions live at three levels: single skills, skill pairs and
context clusters.

*Single-skill decisions*, evaluated in this order for each skill $`u`$:

1.  (1)
    Defer / Explore: $`N_{\mathrm{eff},u}<n_{\min}`$. No structural
    change; allocate verification and exploration budget instead, since
    the effective sample size of $`u`$ is below $`n_{\min}`$.
2.  (2)
    Split: with sufficient support in each context,
    $`\mathbb{P}\bigl(\max_{z}p_{u,z}-\min_{z}p_{u,z}>\theta_{h}\mid\mathcal{D}\bigr)>1-a`$.
3.  (3)
    Refine: globally sound but locally confirmed weak,
    $`\mathrm{LCB}^{\mathrm{glob}}_{u}\geq\theta_{\mathrm{mid}}`$ and
    $`\exists z:\ \mathrm{UCB}_{u,z}<\theta_{\mathrm{low}}`$.
4.  (4)
    Retain: confirmed reliable at the skill level,
    $`\mathrm{LCB}^{\mathrm{glob}}_{u}\geq\theta_{\mathrm{high}}`$.
5.  (5)
    Prune: $`\max_{z}\mathrm{UCB}_{u,z}<\theta_{\mathrm{low}}`$ and
    $`\overline{\widetilde{A}}(u)\leq 0`$ and $`u`$ provides no unique
    coverage.

*Pairwise*: Consolidate is a redundancy test on a skill pair: near
equivalence of invocation contexts, outputs and verifier outcomes, with
no coverage loss on removal; downstream reward and cost are checked by
the paired validation below. *Cluster-level*: Generate requires a
context cluster with sufficient support, concentrated failure mass and
no existing skill whose $`\mathrm{UCB}`$ is adequate there, and the new
skill must be checkable by the verifiers. Here $`N_{\mathrm{eff},u}`$ is
the Kish effective sample size
([C.5](#A3.E5 "Equation C.5 ‣ Remark C.2 (Effective sample size). ‣ Evidence. ‣ C.1 Verifier-Gated Bayesian Calibration ‣ Appendix C Evidence, Gating, and Skill Evolution ‣ R2 Flow: Recursive Self-Improvement viaRecursive Skill Evolution"))
over the verifier records of skill $`u`$, and sufficient support means
an effective sample size of at least $`n_{\min}`$ for the skill, context
or cluster concerned; $`\mathrm{LCB}^{\mathrm{glob}}_{u}`$ is the lower
credible bound of the skill-level posterior pooled over contexts; $`u`$
provides unique coverage when some context it serves is served by no
other skill; and $`\overline{\widetilde{A}}(u)`$ aggregates
$`\widetilde{A}_{e}`$ over the invocations of $`u`$ and serves for
proposal ordering and as the utility veto of Prune. The thresholds
satisfy
$`0\leq\theta_{\mathrm{low}}<\theta_{\mathrm{mid}}<\theta_{\mathrm{high}}\leq 1`$.

#### Versioning, rollback, hysteresis.

Each application of $`\Phi`$ yields $`\mathcal{G}^{(k+1)}`$ and is
accepted only after paired rollouts on the held-out validation query set
with a non-inferiority margin on success, tempered terminal reward,
token cost and latency, assessed by a one-sided test per metric against
that margin ([Schuirmann, 1987](#bib.bib33)); otherwise it is rolled
back. A cooldown prevents a skill from being re-edited within the
cooldown window through Split–Refine–Prune.

###### Definition C.1 (Verifier-only acceptance gate).

Let $`\mathcal{C}_{k}`$ be the candidate edits proposed or ranked from
flow diagnostics, signed utility, and retained records at phase $`k`$.
Define $`\operatorname{Acc}_{k}(d)=1`$ only if (i) every structural
predicate for $`d`$ is computed from the verifier posterior
$`(\alpha^{\mathrm{ver}},\beta^{\mathrm{ver}})`$ and its support
threshold $`n_{\min}`$, (ii) the candidate passes the paired held-out
non-inferiority check, and (iii) the version, cooldown and coverage
predicates hold. The soft score $`q^{\mathrm{soft}}`$ and
$`\widetilde{A}_{e}`$ rank $`\mathcal{C}_{k}`$, and Prune additionally
requires the utility veto $`\overline{\widetilde{A}}(u)\leq 0`$ for the
pruned skill $`u`$.

###### Proposition C.1 (Gate and rollback invariants).

If $`\operatorname{Acc}_{k}`$ is applied after candidate generation and
before a library version is committed, then every committed edit has
verifier-only structural eligibility and paired validation, while a
failed validation or failed gate leaves the active library equal to
$`\mathcal{S}^{(k)}`$.

###### Proof.

By definition, a candidate can enter the commit branch only when
$`\operatorname{Acc}_{k}(d)=1`$, which includes the verifier-only
predicate and the paired non-inferiority check. If either check fails,
the transition takes the defer or rollback branch, whose returned
library is defined to be the previous version $`\mathcal{S}^{(k)}`$.
Since $`q^{\mathrm{soft}}`$ and $`\widetilde{A}_{e}`$ cannot supply the
verifier-only eligibility condition, changing them while holding the
verifier posterior and validation outcomes fixed cannot turn an
ineligible candidate into an eligible one. Reward-derived signals can
therefore block an edit through the utility veto of Prune but never make
one eligible for the commit branch. ∎

###### Proposition C.2 (Phase-state recursion).

Let $`X_{k}`$ contain the active library and graph version, trainable
policy and flow parameters, retained verifier statistics, and all
persistent bookkeeping read by the next transition. Under a fixed outer
protocol $`\lambda`$ and phase randomness $`\zeta_{k}`$, the completed
phase transition has the form

|  |  |  |  |
|----|----|----|----|
|  |
``` math
X_{k+1}=\mathcal{U}_{\lambda}(X_{k};\zeta_{k}),\qquad r_{k}=\mathcal{L}_{\lambda}(X_{k},X_{k+1};\zeta_{k}),\qquad\mathcal{H}^{\mathrm{imp}}_{k+1}=\mathcal{H}^{\mathrm{imp}}_{k}\frown[r_{k}].
``` |  | (C.11) |

Consequently $`\Xi_{k}=(X_{k},\mathcal{H}^{\mathrm{imp}}_{k})`$, which
pairs $`X_{k}`$ with the log of edit decisions and validation outcomes,
obeys the well-defined recurrence
$`\Xi_{k+1}=\mathfrak{R}_{\lambda}(\Xi_{k};\zeta_{k})`$.

###### Proof.

The fixed protocol maps a completed phase state and its random input to
the next state. The record map $`\mathcal{L}_{\lambda}`$ is total on
completed transitions, so sequence concatenation defines the next audit
log. Pairing the two updates gives $`\mathfrak{R}_{\lambda}`$. Because
$`X_{k}`$ contains every field the next transition reads, this map is a
function of the phase state $`\Xi_{k}`$ for fixed phase randomness
$`\zeta_{k}`$. ∎

### C.3 Approximate Balance and Abstraction Error

#### Reasoning-conditioned events.

The implemented residual scores $`\log P_{F}(e_{t}\mid s_{t-1},r_{t})`$
with the sampled reasoning text as context; free-text arguments of a
skill call are treated the same way, so $`P_{F}(\mathrm{args}\mid u,s)`$
scores only the structured arguments. Sampling and scoring then use the
same conditional policy, so the balance identities apply to it
([remark A.2](#A1.Thmremark2 "Remark A.2 (Token-length normalisation). ‣ Semantic action factorisation. ‣ A.2 Forward and Backward Policies ‣ Appendix A Formal Foundations of the Orchestration Graph ‣ R2 Flow: Recursive Self-Improvement viaRecursive Skill Evolution")).
When $`|\delta_{0:T}|\leq\varepsilon`$ holds for every sampled reasoning
text, the terminal-distribution bound of
[proposition C.3](#A3.Thmproposition3 "Proposition C.3 (Residual to terminal distribution). ‣ Reasoning-conditioned events. ‣ C.3 Approximate Balance and Abstraction Error ‣ Appendix C Evidence, Gating, and Skill Evolution ‣ R2 Flow: Recursive Self-Improvement viaRecursive Skill Evolution")
applies to the marginal policy as well, because the marginal trajectory
probability averages the conditional trajectory probabilities, each of
which satisfies the residual bound.

###### Proposition C.3 (Residual to terminal distribution).

Let $`\widehat{Z}=F_{\psi}(s_{0})=Z_{\theta}(q)`$ be the learned source
flow and $`Z^{\star}=\sum_{x\in\mathcal{X}}R_{\eta}(x)`$ the true reward
partition function. On the finite reachable DAG, assume that the forward
and backward policies have positive support on every legal edge and that
$`|\delta_{0:T}(\tau)|\leq\varepsilon`$ for every complete legal
trajectory $`\tau`$ (hence for every terminal-support fibre). Then for
every terminal $`x`$,

|  |  |  |  |
|----|----|----|----|
|  |
``` math
e^{-\varepsilon}\;\leq\;\frac{\widehat{Z}\,P_{F}^{\mathrm{term}}(x\mid q)}{R_{\eta}(x)}\;\leq\;e^{\varepsilon},\qquad e^{-\varepsilon}\;\leq\;\frac{\widehat{Z}}{Z^{\star}}\;\leq\;e^{\varepsilon},\qquad e^{-2\varepsilon}\;\leq\;\frac{Z^{\star}P_{F}^{\mathrm{term}}(x\mid q)}{R_{\eta}(x)}\;\leq\;e^{2\varepsilon}.
``` |  | (C.12) |

###### Proof.

$`\delta_{0:T}(\tau)=\log\bigl[\widehat{Z}P_{F}(\tau)/(R_{\eta}(x_{\tau})P_{B}(\tau\mid x_{\tau}))\bigr]`$.
Exponentiating the residual bound and summing over trajectories ending
at $`x`$, while using $`\sum_{\tau\to x}P_{B}(\tau\mid x)=1`$, gives the
first inequality. Summing the first inequality after multiplying by
$`R_{\eta}(x)/\widehat{Z}`$ over all terminal states gives
$`e^{-\varepsilon}\leq\widehat{Z}/Z^{\star}\leq e^{\varepsilon}`$.
Multiplying the first inequality by $`Z^{\star}/\widehat{Z}`$, which the
second inequality bounds, yields the third inequality, with the exponent
$`2\varepsilon`$ in place of $`\varepsilon`$. ∎

###### Proposition C.4 (Abstraction error propagation).

Let $`\sigma`$ be the abstraction map and $`\pi`$ a common abstract
policy. For a concrete history $`H`$ with $`\sigma(H)=s`$, let
$`K_{H,t}^{\sigma,\pi}(\cdot\mid s)`$ be the history-level one-step
terminal-or-successor kernel, and let $`\overline{K}_{t}(\cdot\mid s)`$
be the adopted quotient kernel. Assume a common initial abstract
distribution, terminal space, policy and termination convention, and

|  |  |  |  |
|----|----|----|----|
|  |
``` math
\sup_{H:\,\sigma(H)=s}\operatorname{TV}\!\left(K_{H,t}^{\sigma,\pi}(\cdot\mid s),\overline{K}_{t}(\cdot\mid s)\right)\leq\varepsilon_{t}\quad\text{for every reachable }s\text{ at decision step }t.
``` |  | (C.13) |

If terminated paths are padded by a common absorbing transition and all
paths have at most $`T`$ decision steps, then the terminal marginals of
the history-level and quotient processes differ by at most
$`\min\{1,\sum_{t=0}^{T-1}\varepsilon_{t}\}`$ in total variation. With
$`\varepsilon_{t}=0`$ at every decision step, the kernel bound of
[eq. C.13](#A3.E13 "In Proposition C.4 (Abstraction error propagation). ‣ Reasoning-conditioned events. ‣ C.3 Approximate Balance and Abstraction Error ‣ Appendix C Evidence, Gating, and Skill Evolution ‣ R2 Flow: Recursive Self-Improvement viaRecursive Skill Evolution")
is the model-irrelevance condition of [Li et al. (2006)](#bib.bib20),
and the terminal marginals of the history-level and quotient processes
then coincide.

###### Proof.

Project the history-level process to the abstract state. Conditional on
a projected state, its one-step kernel is the mixture of the
history-level kernels over the conditional distribution of concrete
histories. Convexity of total variation and
[eq. C.13](#A3.E13 "In Proposition C.4 (Abstraction error propagation). ‣ Reasoning-conditioned events. ‣ C.3 Approximate Balance and Abstraction Error ‣ Appendix C Evidence, Gating, and Skill Evolution ‣ R2 Flow: Recursive Self-Improvement viaRecursive Skill Evolution")
bound the distance between this mixture and $`\overline{K}_{t}`$ by
$`\varepsilon_{t}`$. A stepwise hybrid argument, or induction using
contraction of Markov kernels, then gives the sum of the per-step
bounds; the outer minimum uses $`\operatorname{TV}\leq 1`$. ∎

###### Remark C.3 (Reward measurability of merged terminals).

[Assumption A.1](#A1.Thmassumption1 "Assumption A.1 (Quotient validity). ‣ Raw histories. ‣ A.1 Quotient Orchestration Graph ‣ Appendix A Formal Foundations of the Orchestration Graph ‣ R2 Flow: Recursive Self-Improvement viaRecursive Skill Evolution")(c)
makes $`R_{\eta}(x)`$ well defined on every merged terminal, so the
terminal anchor of
[eq. B.2](#A2.E2 "In B.1 The R2TB Objective ‣ Appendix B Balance Objectives and Flow Diagnostics ‣ R2 Flow: Recursive Self-Improvement viaRecursive Skill Evolution")
applies there; the abstraction map $`\sigma`$ meets this terminal-reward
consistency by keeping in $`s`$ every feature of the history that the
reward reads, which makes the reward $`\sigma`$-measurable.

### D.1 Path factorisation and balance identities

###### Lemma D.1 (Path factorisation).

Under
[Assumptions A.1](#A1.Thmassumption1 "Assumption A.1 (Quotient validity). ‣ Raw histories. ‣ A.1 Quotient Orchestration Graph ‣ Appendix A Formal Foundations of the Orchestration Graph ‣ R2 Flow: Recursive Self-Improvement viaRecursive Skill Evolution"),
[A.2](#A1.Thmassumption2 "Assumption A.2 (Markov policy and flow). ‣ Raw histories. ‣ A.1 Quotient Orchestration Graph ‣ Appendix A Formal Foundations of the Orchestration Graph ‣ R2 Flow: Recursive Self-Improvement viaRecursive Skill Evolution"),
[A.3](#A1.Thmassumption3 "Assumption A.3 (Finite event horizon and branching). ‣ Raw histories. ‣ A.1 Quotient Orchestration Graph ‣ Appendix A Formal Foundations of the Orchestration Graph ‣ R2 Flow: Recursive Self-Improvement viaRecursive Skill Evolution")
and [A.4](#A1.Thmassumption4 "Assumption A.4 (Canonicalised transitions). ‣ Raw histories. ‣ A.1 Quotient Orchestration Graph ‣ Appendix A Formal Foundations of the Orchestration Graph ‣ R2 Flow: Recursive Self-Improvement viaRecursive Skill Evolution"),
let $`\tau=(s_{0},e_{1},s_{1},\ldots,e_{T},s_{T})`$ be a legal
trajectory ending at $`x=s_{T}`$. For any normalized forward policy
$`P_{F}`$ and backward policy $`P_{B}`$ with positive support on the
edges of $`\tau`$,

|  |  |  |  |
|----|----|----|----|
|  |
``` math
P_{F}(\tau)=\prod_{t=1}^{T}P_{F}(e_{t}\mid s_{t-1}),\qquad P_{B}(\tau\mid x)=\prod_{t=1}^{T}P_{B}((s_{t-1},e_{t})\mid s_{t}).
``` |  | (D.1) |

###### Proof.

The Markov assumption makes the conditional law of the next event depend
only on $`(s_{t-1},q,k)`$, and
[Assumption A.4](#A1.Thmassumption4 "Assumption A.4 (Canonicalised transitions). ‣ Raw histories. ‣ A.1 Quotient Orchestration Graph ‣ Appendix A Formal Foundations of the Orchestration Graph ‣ R2 Flow: Recursive Self-Improvement viaRecursive Skill Evolution")
makes each successor a function of the current state and event, so the
chain rule reduces to the first product. Running the normalized in-edge
policy backward from the terminal $`x=s_{T}`$ gives the second product
of
[eq. D.1](#A4.E1 "In Lemma D.1 (Path factorisation). ‣ D.1 Path factorisation and balance identities ‣ Appendix D Proof Details ‣ R2 Flow: Recursive Self-Improvement viaRecursive Skill Evolution").
∎

###### Lemma D.2 (Residual additivity).

For $`0\leq i<\ell<j\leq T`$, the residual in
[eq. B.1](#A2.E1 "In B.1 The R2TB Objective ‣ Appendix B Balance Objectives and Flow Diagnostics ‣ R2 Flow: Recursive Self-Improvement viaRecursive Skill Evolution")
satisfies

|     |                                               |     |       |
|-----|-----------------------------------------------|-----|-------|
|     |
       ``` math
       \delta_{i:j}=\delta_{i:\ell}+\delta_{\ell:j}.
       ```                                            |     | (D.2) |

Consequently, zero residual on every sub-trajectory implies both
detailed balance on every edge and trajectory balance on every complete
trajectory of the DAG.

###### Proof.

Expand the two terms on the right of
[eq. D.2](#A4.E2 "In Lemma D.2 (Residual additivity). ‣ D.1 Path factorisation and balance identities ‣ Appendix D Proof Details ‣ R2 Flow: Recursive Self-Improvement viaRecursive Skill Evolution").
The intermediate terms $`\log F_{\psi}(s_{\ell})`$ and
$`-\log F_{\psi}(s_{\ell})`$ cancel, as do no other terms, leaving
exactly the sums from $`i+1`$ through $`j`$. Choosing $`j=i+1`$ gives
detailed balance on every edge, and choosing $`(i,j)=(0,T)`$ gives
trajectory balance on every complete trajectory. The converse does not
hold from trajectory balance alone: internal flows can change while
preserving the endpoint product. ∎

###### Proposition D.3 (Sub-trajectory objective and exact balance).

Let $`\mu`$ be the distribution over complete legal trajectories used
for the population objective and write
$`\mathcal{J}_{\mu}=\mathbb{E}_{\tau\sim\mu}[\mathcal{L}_{\mathrm{flow}}(\tau)]`$.
Assume $`\omega_{j-i}>0`$ for every included pair and
$`\Pr_{\mu}(e\in\tau)>0`$ for every constrained edge. Then
$`\mathcal{J}_{\mu}=0`$ if and only if every included residual is zero
on the support of $`\mu`$. If all contiguous pairs are included and the
support covers every legal edge, this is equivalent to the collection of
detailed-balance identities on the DAG together with the terminal anchor
of
[eq. B.2](#A2.E2 "In B.1 The R2TB Objective ‣ Appendix B Balance Objectives and Flow Diagnostics ‣ R2 Flow: Recursive Self-Improvement viaRecursive Skill Evolution").

###### Proof.

The integrand is a finite sum of nonnegative terms. Its expectation is
zero only if every term is zero $`\mu`$-almost surely. The positive
edge-visitation condition makes each constrained edge occur with
positive probability, so each included residual is zero on that edge’s
support. The first implication of
[lemma D.2](#A4.Thmproposition2 "Lemma D.2 (Residual additivity). ‣ D.1 Path factorisation and balance identities ‣ Appendix D Proof Details ‣ R2 Flow: Recursive Self-Improvement viaRecursive Skill Evolution")
gives detailed balance and trajectory identities. Conversely, those
identities make every included residual $`\delta_{i:j}`$ in the
objective of
[eq. B.3](#A2.E3 "In B.1 The R2TB Objective ‣ Appendix B Balance Objectives and Flow Diagnostics ‣ R2 Flow: Recursive Self-Improvement viaRecursive Skill Evolution")
zero. ∎

###### Remark D.1 (From exact to approximate balance).

A finite-sample optimizer leaves small nonzero residuals; when every

### D.2 Compatible reference flows

###### Proposition D.4 (Backward reconstruction of a compatible triple).

On a finite DAG in which every reachable node lies on a
source-to-terminal path, with positive terminal rewards and a normalized
full-support backward policy $`P_{B}^{0}`$ on every nonempty in-edge
set, define the reference state and edge flows recursively

|  |  |  |  |  |  |  |
|----|----|----|----|----|----|----|
|  | $`\displaystyle F^{0}(x)`$ | $`\displaystyle=R_{\eta}(x)`$ |  | $`\displaystyle(x\in\mathcal{X}),\qquad f^{0}(s,e,s^{\prime})=F^{0}(s^{\prime})P_{B}^{0}((s,e)\mid s^{\prime}),`$ |  | (D.3) |
|  | $`\displaystyle F^{0}(s)`$ | $`\displaystyle=\sum_{(s,e,s^{\prime})\in\Out(s)}f^{0}(s,e,s^{\prime})`$ |  | $`\displaystyle(s\notin\mathcal{X}).`$ |  |  |

Then $`Z^{\star}=F^{0}(s_{0})=\sum_{x}R_{\eta}(x)`$ and
$`P_{F}^{0}(e\mid s)=f^{0}(s,e,s^{\prime})/F^{0}(s)`$ form a compatible
flow triple $`(F^{0},P_{F}^{0},P_{B}^{0})`$. It is unique for the chosen
$`P_{B}^{0}`$ and terminal anchor.

###### Proof.

The recurrence is evaluated in decreasing rank. Terminal values are
fixed by the terminal anchor. Since every reachable node lies on a
terminal path and all terminal rewards and backward probabilities are
positive, induction gives $`F^{0}(s)>0`$ at every reachable node. Once
all children of $`s`$ have been assigned flow values, every outgoing
edge mass is fixed by $`P_{B}^{0}`$, so their sum fixes $`F^{0}(s)`$ and
division by it fixes the normalized forward probabilities. For each
non-root node $`s^{\prime}`$, normalization of the backward policy
$`P_{B}^{0}`$ gives
$`\sum_{(s,e)\in\Inn(s^{\prime})}f^{0}(s,e,s^{\prime})=F^{0}(s^{\prime})`$.
Summing this incoming-flow identity over all non-root states and the
outgoing-flow definition over all nonterminal states cancels the mass of
every internal edge, leaving
$`F^{0}(s_{0})=\sum_{x\in\mathcal{X}}F^{0}(x)=\sum_{x}R_{\eta}(x)`$. The
same induction over decreasing rank shows uniqueness. The construction
also gives
$`F^{0}(s)P_{F}^{0}(e\mid s)=F^{0}(s^{\prime})P_{B}^{0}((s,e)\mid s^{\prime})`$,
which is the required compatibility identity. ∎

###### Corollary D.5 (Terminal law under an exact compatible triple).

If a forward policy is generated by
[proposition D.4](#A4.Thmproposition4 "Proposition D.4 (Backward reconstruction of a compatible triple). ‣ D.2 Compatible reference flows ‣ Appendix D Proof Details ‣ R2 Flow: Recursive Self-Improvement viaRecursive Skill Evolution"),
then its terminal marginal is

|  |  |  |  |
|----|----|----|----|
|  |
``` math
P_{F}^{0,\mathrm{term}}(x\mid q)=\frac{R_{\eta}(x)}{Z^{\star}}.
``` |  | (D.4) |

The terminal law is invariant to the choice of full-support
$`P_{B}^{0}`$, while the internal state and edge flows generally are
not, as in the two-path example of
[proposition A.3](#A1.Thmproposition3 "Proposition A.3 (Two faces of 𝑃_𝐵). ‣ Backward policy. ‣ A.2 Forward and Backward Policies ‣ Appendix A Formal Foundations of the Orchestration Graph ‣ R2 Flow: Recursive Self-Improvement viaRecursive Skill Evolution").

###### Proof.

For every trajectory ending at $`x`$, compatibility gives
$`P_{F}^{0}(\tau)=R_{\eta}(x)P_{B}^{0}(\tau\mid x)/Z^{\star}`$. Summing
over trajectories and using normalization of the backward trajectory
distribution gives
[eq. D.4](#A4.E4 "In Corollary D.5 (Terminal law under an exact compatible triple). ‣ D.2 Compatible reference flows ‣ Appendix D Proof Details ‣ R2 Flow: Recursive Self-Improvement viaRecursive Skill Evolution").
Internal flows contain the factors $`P_{B}^{0}(\tau\mid x)`$ before they
are summed, so two backward policies can induce different internal
allocations while preserving the same terminal marginal. ∎

###### Remark D.2 (Reference readout versus learned training triple).

Equation ([B.6](#A2.E6 "Equation B.6 ‣ Importance: normalised flow share. ‣ B.2 Flow Diagnostics ‣ Appendix B Balance Objectives and Flow Diagnostics ‣ R2 Flow: Recursive Self-Improvement viaRecursive Skill Evolution"))
is a flow diagnostic only when all of its factors come from one
compatible triple; pairing a learned $`P_{F,\theta}`$ with a state flow
built from another $`P_{B}^{0}`$ need not conserve flow. R² Flow
therefore estimates the reference readout from the trained policy’s
rollouts with the residual weights of
[corollary D.9](#A4.Thmproposition9 "Corollary D.9 (Skill share on the shared-state graph and its estimator). ‣ D.2 Compatible reference flows ‣ Appendix D Proof Details ‣ R2 Flow: Recursive Self-Improvement viaRecursive Skill Evolution"),
which needs no reconstruction.

###### Lemma D.6 (Occupancy identity).

For a compatible positive flow on the fixed rooted, terminal-complete
DAG,

|  |  |  |  |
|----|----|----|----|
|  |
``` math
\Pr_{P_{F}^{0}}(s\in\tau)=\frac{F^{0}(s)}{Z^{\star}},\qquad\Pr_{P_{F}^{0}}((s,e,s^{\prime})\in\tau)=\frac{F^{0}(s)P_{F}^{0}(e\mid s)}{Z^{\star}}.
``` |  | (D.5) |

###### Proof.

The source is visited with probability one. In increasing rank,
incoming-edge events to a fixed state are mutually exclusive, so its
visitation probability satisfies

|  |  |  |
|----|----|----|
|  |
``` math
v(s^{\prime})=\sum_{(s,e)\in\Inn(s^{\prime})}v(s)P_{F}^{0}(e\mid s)=\frac{\sum_{(s,e)\in\Inn(s^{\prime})}F^{0}(s)P_{F}^{0}(e\mid s)}{Z^{\star}}=\frac{F^{0}(s^{\prime})}{Z^{\star}},
``` |  |

where the last equality is flow conservation. Multiplying $`v(s)`$ by
the conditional edge probability gives the edge identity. Terminal
completeness makes these visitation probabilities equal to sums over the
complete trajectories containing the state or edge. ∎

###### Proposition D.7 (Flow-share normalization).

Fix a finite compatible reference-flow triple
$`(F^{0},P_{F}^{0},P_{B}^{0})`$ with source flow
$`F^{0}(s_{0})=Z^{\star}>0`$. Let $`\mathcal{E}_{u}`$ be the set of
counted edges labelled by skill $`u`$, assume that the sets
$`\{\mathcal{E}_{u}\}_{u}`$ form a disjoint partition of
$`\mathcal{E}_{\mathrm{skill}}`$, and define

|  |  |  |  |
|----|----|----|----|
|  |
``` math
\varphi^{0}(e)=\frac{F^{0}(s)P_{F}^{0}(e\mid s)}{Z^{\star}}\quad\text{for }e=(s\!\to\!s^{\prime}).
``` |  | (D.6) |

For a complete trajectory $`\tau`$, let

|  |  |  |  |
|----|----|----|----|
|  |
``` math
I_{e}(\tau)=\mathbf{1}\{e\in\tau\},\qquad N_{u}(\tau)=\sum_{e\in\mathcal{E}_{u}}I_{e}(\tau),\qquad T_{\mathrm{skill}}(\tau)=\sum_{e\in\mathcal{E}_{\mathrm{skill}}}I_{e}(\tau).
``` |  | (D.7) |

Then

|  |  |  |  |
|----|----|----|----|
|  |
``` math
\sum_{e\in\mathcal{E}_{u}}\varphi^{0}(e)=\mathbb{E}_{\tau\sim P_{F}^{0}}[N_{u}(\tau)],\qquad M_{\mathrm{skill}}=\sum_{e\in\mathcal{E}_{\mathrm{skill}}}\varphi^{0}(e)=\mathbb{E}_{\tau\sim P_{F}^{0}}[T_{\mathrm{skill}}(\tau)].
``` |  | (D.8) |

If $`M_{\mathrm{skill}}>0`$, the normalized skill share is therefore

|  |  |  |  |
|----|----|----|----|
|  |
``` math
\Psi^{0}(u)=\frac{\mathbb{E}_{P_{F}^{0}}[N_{u}(\tau)]}{\mathbb{E}_{P_{F}^{0}}[T_{\mathrm{skill}}(\tau)]}=\frac{\sum_{e\in\mathcal{E}_{u}}\varphi^{0}(e)}{M_{\mathrm{skill}}},\qquad\sum_{u}\Psi^{0}(u)=1.
``` |  | (D.9) |

In general this is a ratio of expectations, not
$`\mathbb{E}[N_{u}(\tau)/T_{\mathrm{skill}}(\tau)]`$.

###### Proof.

Because the graph is acyclic, a complete trajectory traverses any fixed
edge at most once. Compatible flow balance gives

|  |  |  |  |
|----|----|----|----|
|  |
``` math
F^{0}(s)P_{F}^{0}(e\mid s)=\sum_{\tau:\,e\in\tau}F^{0}(s_{0})P_{F}^{0}(\tau).
``` |  | (D.10) |

By
[lemma D.6](#A4.Thmproposition6 "Lemma D.6 (Occupancy identity). ‣ D.2 Compatible reference flows ‣ Appendix D Proof Details ‣ R2 Flow: Recursive Self-Improvement viaRecursive Skill Evolution"),
dividing by $`F^{0}(s_{0})=Z^{\star}`$ yields

|  |  |  |  |
|----|----|----|----|
|  |
``` math
\varphi^{0}(e)=\sum_{\tau}P_{F}^{0}(\tau)I_{e}(\tau)=\mathbb{E}_{\tau\sim P_{F}^{0}}[I_{e}(\tau)].
``` |  | (D.11) |

All sums are finite, so linearity of expectation permits exchanging the
edge sum and the trajectory expectation. This proves both identities in
[eq. D.8](#A4.E8 "In Proposition D.7 (Flow-share normalization). ‣ D.2 Compatible reference flows ‣ Appendix D Proof Details ‣ R2 Flow: Recursive Self-Improvement viaRecursive Skill Evolution").
Since the skill-labelled edge sets form a partition,
$`T_{\mathrm{skill}}(\tau)=\sum_{u}N_{u}(\tau)`$ pointwise. Taking
expectations and dividing by the common positive denominator
$`M_{\mathrm{skill}}`$ of
[eq. D.8](#A4.E8 "In Proposition D.7 (Flow-share normalization). ‣ D.2 Compatible reference flows ‣ Appendix D Proof Details ‣ R2 Flow: Recursive Self-Improvement viaRecursive Skill Evolution")
proves
[eq. D.9](#A4.E9 "In Proposition D.7 (Flow-share normalization). ‣ D.2 Compatible reference flows ‣ Appendix D Proof Details ‣ R2 Flow: Recursive Self-Improvement viaRecursive Skill Evolution").
∎

###### Corollary D.8 (Backward-policy independence under path-invariant counts).

Suppose that for every terminal node $`x`$ there are deterministic
functions $`n_{u}(x)`$ and $`t_{\mathrm{skill}}(x)`$ such that every
complete trajectory ending at $`x`$ satisfies

|  |  |  |  |
|----|----|----|----|
|  |
``` math
N_{u}(\tau)=n_{u}(x),\qquad T_{\mathrm{skill}}(\tau)=t_{\mathrm{skill}}(x).
``` |  | (D.12) |

Then every full-support compatible backward policy $`P_{B}^{0}`$ induces
the same normalized skill share:

|  |  |  |  |
|----|----|----|----|
|  |
``` math
\Psi^{0}(u)=\frac{\sum_{x}R_{\eta}(x)n_{u}(x)}{\sum_{x}R_{\eta}(x)t_{\mathrm{skill}}(x)},
``` |  | (D.13) |

provided the denominator of
[eq. D.13](#A4.E13 "In Corollary D.8 (Backward-policy independence under path-invariant counts). ‣ D.2 Compatible reference flows ‣ Appendix D Proof Details ‣ R2 Flow: Recursive Self-Improvement viaRecursive Skill Evolution")
is positive.

###### Proof.

Compatibility gives the terminal law
$`P_{F}^{0}(x)=R_{\eta}(x)/Z^{\star}`$, independently of the chosen
full-support backward policy. Under
[eq. D.12](#A4.E12 "In Corollary D.8 (Backward-policy independence under path-invariant counts). ‣ D.2 Compatible reference flows ‣ Appendix D Proof Details ‣ R2 Flow: Recursive Self-Improvement viaRecursive Skill Evolution"),
conditioning on $`x`$ removes all remaining path dependence:

|  |  |  |  |
|----|----|----|----|
|  |
``` math
\mathbb{E}_{P_{F}^{0}}[N_{u}(\tau)]=\sum_{x}\frac{R_{\eta}(x)}{Z^{\star}}n_{u}(x),\qquad\mathbb{E}_{P_{F}^{0}}[T_{\mathrm{skill}}(\tau)]=\sum_{x}\frac{R_{\eta}(x)}{Z^{\star}}t_{\mathrm{skill}}(x).
``` |  | (D.14) |

Substitution into
[eq. D.9](#A4.E9 "In Proposition D.7 (Flow-share normalization). ‣ D.2 Compatible reference flows ‣ Appendix D Proof Details ‣ R2 Flow: Recursive Self-Improvement viaRecursive Skill Evolution")
cancels $`Z^{\star}`$ and yields
[eq. D.13](#A4.E13 "In Corollary D.8 (Backward-policy independence under path-invariant counts). ‣ D.2 Compatible reference flows ‣ Appendix D Proof Details ‣ R2 Flow: Recursive Self-Improvement viaRecursive Skill Evolution").
∎

###### Corollary D.9 (Skill share on the shared-state graph and its estimator).

Let every edge commit one atomic event labelled by one skill
$`u\in\mathcal{S}^{(k)}`$
([definition A.2](#A1.Thmdefinition2 "Definition A.2 (Edges, in-edges, rank). ‣ Raw histories. ‣ A.1 Quotient Orchestration Graph ‣ Appendix A Formal Foundations of the Orchestration Graph ‣ R2 Flow: Recursive Self-Improvement viaRecursive Skill Evolution")).

1.  (i)
    Every complete trajectory ending at $`x`$ satisfies
    [eq. D.12](#A4.E12 "In Corollary D.8 (Backward-policy independence under path-invariant counts). ‣ D.2 Compatible reference flows ‣ Appendix D Proof Details ‣ R2 Flow: Recursive Self-Improvement viaRecursive Skill Evolution"),
    with $`n_{u}(x)`$ the number of events of $`E_{x}`$ that invoke
    $`u`$ and $`t_{\mathrm{skill}}(x)=\sum_{u}n_{u}(x)`$, so
    $`\Psi^{0}(u)`$ is given by
    [eq. D.13](#A4.E13 "In Corollary D.8 (Backward-policy independence under path-invariant counts). ‣ D.2 Compatible reference flows ‣ Appendix D Proof Details ‣ R2 Flow: Recursive Self-Improvement viaRecursive Skill Evolution")
    for every full-support compatible backward policy $`P_{B}^{0}`$, as
    in
    [corollary D.8](#A4.Thmproposition8 "Corollary D.8 (Backward-policy independence under path-invariant counts). ‣ D.2 Compatible reference flows ‣ Appendix D Proof Details ‣ R2 Flow: Recursive Self-Improvement viaRecursive Skill Evolution").
2.  (ii)
    Let $`\tau_{1},\dots,\tau_{N}`$ be rollouts of query $`q`$ drawn
    independently from a forward policy with positive support on every
    legal edge, let $`P_{B}`$ be any normalized full-support backward
    policy, and let $`w_{i}=\exp(-\delta_{0:T}(\tau_{i}))`$ be computed
    from them. Then

    |  |  |  |  |
    |----|----|----|----|
    |  |
    ``` math
    \widehat{\Psi}^{0}_{N}(u)=\frac{\sum_{i}w_{i}\,n_{u}(x_{\tau_{i}})}{\sum_{i}w_{i}\,t_{\mathrm{skill}}(x_{\tau_{i}})}\;\longrightarrow\;\Psi^{0}(u)\quad\text{almost surely as }N\to\infty,
    ``` |  | (D.15) |

    whatever the values of the source flow $`F_{\psi}(s_{0})`$ and the
    domain bias $`b_{d}`$.
3.  (iii)
    With unit weights and $`|\delta_{0:T}|\leq\varepsilon`$ on every
    complete legal trajectory, the limit of
    $`\widehat{\Psi}^{0}_{N}(u)`$ in
    [eq. D.15](#A4.E15 "In Item (ii) ‣ Corollary D.9 (Skill share on the shared-state graph and its estimator). ‣ D.2 Compatible reference flows ‣ Appendix D Proof Details ‣ R2 Flow: Recursive Self-Improvement viaRecursive Skill Evolution")
    lies in $`[e^{-4\varepsilon},e^{4\varepsilon}]\,\Psi^{0}(u)`$.

The same weights estimate the edge share,
$`\widehat{\varphi}^{0}_{N}(e)=\sum_{i}w_{i}\,h_{B^{0}}(e\mid x_{\tau_{i}})/\sum_{i}w_{i}`$,
where $`h_{B^{0}}(e\mid x)`$ is the probability that a backward walk
under $`P_{B}^{0}`$ from $`x`$ traverses $`e`$.

###### Proof.

(i) A state records its committed events, the source has none, and each
edge adds one event, so a complete trajectory ending at $`x`$ adds every
event of $`E_{x}`$ exactly once and its skill counts depend on $`x`$
alone;
[corollary D.8](#A4.Thmproposition8 "Corollary D.8 (Backward-policy independence under path-invariant counts). ‣ D.2 Compatible reference flows ‣ Appendix D Proof Details ‣ R2 Flow: Recursive Self-Improvement viaRecursive Skill Evolution")
then applies. (ii) As in the proof of
[proposition C.3](#A3.Thmproposition3 "Proposition C.3 (Residual to terminal distribution). ‣ Reasoning-conditioned events. ‣ C.3 Approximate Balance and Abstraction Error ‣ Appendix C Evidence, Gating, and Skill Evolution ‣ R2 Flow: Recursive Self-Improvement viaRecursive Skill Evolution"),
$`w_{i}=c_{q}\,R_{\eta}(x)P_{B}(\tau_{i}\mid x)/P_{F}(\tau_{i})`$ with
$`x=x_{\tau_{i}}`$ and a constant $`c_{q}>0`$ that collects
$`F_{\psi}(s_{0})`$ and $`b_{d}`$ for the query. For any function $`g`$
of the terminal,
$`\mathbb{E}_{P_{F}}[w\,g(x_{\tau})]=c_{q}\sum_{\tau}R_{\eta}(x_{\tau})P_{B}(\tau\mid x_{\tau})g(x_{\tau})=c_{q}\sum_{x}R_{\eta}(x)g(x)`$,
because $`\sum_{\tau\to x}P_{B}(\tau\mid x)=1`$. Taking $`g=n_{u}`$ and
$`g=t_{\mathrm{skill}}`$, the strong law of large numbers applies to the
numerator and the denominator, $`c_{q}`$ cancels, and the ratio
converges to
[eq. D.13](#A4.E13 "In Corollary D.8 (Backward-policy independence under path-invariant counts). ‣ D.2 Compatible reference flows ‣ Appendix D Proof Details ‣ R2 Flow: Recursive Self-Improvement viaRecursive Skill Evolution").
When the forward term conditions on sampled reasoning text,
$`P_{F}(\tau_{i})`$ is the event probability given that text; the text
is drawn from its own distribution, so summing over it leaves the same
expectation. (iii) With unit weights the limit is
$`\sum_{x}P_{F}^{\mathrm{term}}(x\mid q)\,n_{u}(x)/\sum_{x}P_{F}^{\mathrm{term}}(x\mid q)\,t_{\mathrm{skill}}(x)`$.
By
[proposition C.3](#A3.Thmproposition3 "Proposition C.3 (Residual to terminal distribution). ‣ Reasoning-conditioned events. ‣ C.3 Approximate Balance and Abstraction Error ‣ Appendix C Evidence, Gating, and Skill Evolution ‣ R2 Flow: Recursive Self-Improvement viaRecursive Skill Evolution"),
$`P_{F}^{\mathrm{term}}(x\mid q)`$ lies within a factor
$`e^{\pm 2\varepsilon}`$ of $`R_{\eta}(x)/Z^{\star}`$, so the numerator
and the denominator each lie within that factor of their targets and the
ratio within $`e^{\pm 4\varepsilon}`$. For the edge share, take
$`g(x)=h_{B^{0}}(e\mid x)`$ and $`g\equiv 1`$; the limit is
$`\sum_{x}R_{\eta}(x)h_{B^{0}}(e\mid x)/Z^{\star}=\varphi^{0}(e)`$ by
[proposition B.1](#A2.Thmproposition1 "Proposition B.1 (What the state flow is). ‣ B.2 Flow Diagnostics ‣ Appendix B Balance Objectives and Flow Diagnostics ‣ R2 Flow: Recursive Self-Improvement viaRecursive Skill Evolution")
applied to the reference triple and the compatibility identity
$`F^{0}(s)P_{F}^{0}(e\mid s)=F^{0}(s^{\prime})P_{B}^{0}((s,e)\mid s^{\prime})`$.
∎

###### Remark D.3 (Precision of the share estimate).

The Kish effective sample size
([C.5](#A3.E5 "Equation C.5 ‣ Remark C.2 (Effective sample size). ‣ Evidence. ‣ C.1 Verifier-Gated Bayesian Calibration ‣ Appendix C Evidence, Gating, and Skill Evolution ‣ R2 Flow: Recursive Self-Improvement viaRecursive Skill Evolution"))

[eq. D.15](#A4.E15 "In Item (ii) ‣ Corollary D.9 (Skill share on the shared-state graph and its estimator). ‣ D.2 Compatible reference flows ‣ Appendix D Proof Details ‣ R2 Flow: Recursive Self-Improvement viaRecursive Skill Evolution").

### D.3 Verifier posteriors and decision invariants

###### Proposition D.10 (Fractional verifier evidence as a power posterior).

Let $`p_{u,z}`$ have prior
$`\operatorname{Beta}(\alpha_{0,u},\beta_{0,u})`$ with
$`\alpha_{0,u},\beta_{0,u}>0`$. For binary verifier records
$`y_{e}\in\{0,1\}`$ with confidence weights $`c_{e}\in[0,1]`$, define
the generalized likelihood

|  |  |  |  |
|----|----|----|----|
|  |
``` math
L(p)=\prod_{e\in\mathcal{E}^{\mathrm{ver}}_{u,z}}[p^{y_{e}}(1-p)^{1-y_{e}}]^{c_{e}}.
``` |  | (D.16) |

Then the generalized posterior ([Bissiri et al., 2016](#bib.bib6)) is
$`\operatorname{Beta}(\alpha^{\mathrm{ver}}_{u,z},\beta^{\mathrm{ver}}_{u,z})`$
with the confidence-weighted update of the gate posterior in
[eqs. C.3](#A3.E3 "In Evidence. ‣ C.1 Verifier-Gated Bayesian Calibration ‣ Appendix C Evidence, Gating, and Skill Evolution ‣ R2 Flow: Recursive Self-Improvement viaRecursive Skill Evolution")
and [C.4](#A3.E4 "Equation C.4 ‣ Evidence. ‣ C.1 Verifier-Gated Bayesian Calibration ‣ Appendix C Evidence, Gating, and Skill Evolution ‣ R2 Flow: Recursive Self-Improvement viaRecursive Skill Evolution").

###### Proof.

Multiplying the Beta prior density by
[eq. D.16](#A4.E16 "In Proposition D.10 (Fractional verifier evidence as a power posterior). ‣ D.3 Verifier posteriors and decision invariants ‣ Appendix D Proof Details ‣ R2 Flow: Recursive Self-Improvement viaRecursive Skill Evolution")
collects the powers of $`p`$ and $`(1-p)`$ as
$`p^{\alpha_{0,u}-1+\sum_{e\in\mathcal{E}^{\mathrm{ver}}_{u,z}}c_{e}y_{e}}`$
and
$`(1-p)^{\beta_{0,u}-1+\sum_{e\in\mathcal{E}^{\mathrm{ver}}_{u,z}}c_{e}(1-y_{e})}`$.
The normalizing constant is the Beta function, giving the stated
generalized posterior. Because fractional powers are used, this is a
power-posterior interpretation of the update in
[eqs. C.3](#A3.E3 "In Evidence. ‣ C.1 Verifier-Gated Bayesian Calibration ‣ Appendix C Evidence, Gating, and Skill Evolution ‣ R2 Flow: Recursive Self-Improvement viaRecursive Skill Evolution")
and [C.4](#A3.E4 "Equation C.4 ‣ Evidence. ‣ C.1 Verifier-Gated Bayesian Calibration ‣ Appendix C Evidence, Gating, and Skill Evolution ‣ R2 Flow: Recursive Self-Improvement viaRecursive Skill Evolution").
∎

###### Lemma D.11 (Beta density-ratio ordering).

Let $`P_{\alpha,\beta}`$ denote a $`\operatorname{Beta}(\alpha,\beta)`$
random variable, where $`\alpha,\beta>0`$. For every $`c\geq 0`$,

|  |  |  |  |
|----|----|----|----|
|  |
``` math
P_{\alpha+c,\beta}\succeq_{\mathrm{FOSD}}P_{\alpha,\beta},\qquad P_{\alpha,\beta+c}\preceq_{\mathrm{FOSD}}P_{\alpha,\beta},
``` |  | (D.17) |

where $`\succeq_{\mathrm{FOSD}}`$ denotes first-order stochastic
dominance ([Shaked & Shanthikumar, 2007](#bib.bib34)). The inequalities
are strict on the interior $`(0,1)`$ when $`c>0`$.

###### Proof.

The case $`c=0`$ is equality, so take $`c>0`$. The two Beta densities
satisfy

|  |  |  |  |
|----|----|----|----|
|  |
``` math
\frac{f_{\alpha+c,\beta}(p)}{f_{\alpha,\beta}(p)}=\frac{B(\alpha,\beta)}{B(\alpha+c,\beta)}p^{c}\eqqcolon r_{\alpha,c}(p).
``` |  | (D.18) |

The ratio is continuous and strictly increasing. Since both densities
integrate to one, it has a unique crossing $`p_{\star}\in(0,1)`$: the
density difference is negative before $`p_{\star}`$ and positive after
it. For $`D(t)=F_{\alpha+c,\beta}(t)-F_{\alpha,\beta}(t)`$, this gives
$`D(t)\leq 0`$ for $`t\leq p_{\star}`$. For $`t>p_{\star}`$, using
$`\int_{0}^{1}(f_{\alpha+c,\beta}-f_{\alpha,\beta})=0`$ gives

|  |  |  |  |
|----|----|----|----|
|  |
``` math
D(t)=-\int_{t}^{1}(f_{\alpha+c,\beta}(p)-f_{\alpha,\beta}(p))\,dp\leq 0.
``` |  | (D.19) |

Thus the first CDF is everywhere no larger, proving the first
stochastic-order relation. Similarly,

|  |  |  |  |
|----|----|----|----|
|  |
``` math
\frac{f_{\alpha,\beta+c}(p)}{f_{\alpha,\beta}(p)}=\frac{B(\alpha,\beta)}{B(\alpha,\beta+c)}(1-p)^{c}
``` |  | (D.20) |

is strictly decreasing; reversing the preceding sign argument proves the
second relation. Positivity of Beta densities on $`(0,1)`$ gives strict
interior inequalities for $`c>0`$. ∎

###### Corollary D.12 (Monotonicity of verifier-posterior quantiles).

For $`a\in(0,1)`$, define

|  |  |  |  |
|----|----|----|----|
|  |
``` math
Q_{a}(\alpha,\beta)=\inf\{p\in[0,1]:F_{\alpha,\beta}(p)\geq a\}.
``` |  | (D.21) |

Then, for every $`c\geq 0`$,

|  |  |  |  |
|----|----|----|----|
|  |
``` math
Q_{a}(\alpha+c,\beta)\geq Q_{a}(\alpha,\beta),\qquad Q_{a}(\alpha,\beta+c)\leq Q_{a}(\alpha,\beta).
``` |  | (D.22) |

Consequently, adding verifier success mass $`c`$ cannot decrease a lower
posterior quantile, and adding verifier failure mass $`c`$ cannot
increase an upper posterior quantile, provided the other shape parameter
and prior hyperparameters are held fixed.

###### Proof.

If $`F_{1}(t)\leq F_{0}(t)`$ for every $`t`$, the level $`a`$ is reached
by $`F_{1}`$ no earlier than by $`F_{0}`$, so
$`Q_{a}(F_{1})\geq Q_{a}(F_{0})`$. Applying this implication to the CDF
orderings in
[lemma D.11](#A4.Thmproposition11 "Lemma D.11 (Beta density-ratio ordering). ‣ D.3 Verifier posteriors and decision invariants ‣ Appendix D Proof Details ‣ R2 Flow: Recursive Self-Improvement viaRecursive Skill Evolution")
proves the inequalities. Under the power-posterior update of
[proposition D.10](#A4.Thmproposition10 "Proposition D.10 (Fractional verifier evidence as a power posterior). ‣ D.3 Verifier posteriors and decision invariants ‣ Appendix D Proof Details ‣ R2 Flow: Recursive Self-Improvement viaRecursive Skill Evolution"),
a verifier success of mass $`c`$ changes $`(\alpha,\beta)`$ to
$`(\alpha+c,\beta)`$ and a verifier failure of mass $`c`$ changes it to
$`(\alpha,\beta+c)`$. ∎

The Supervisor and the frozen executor are both Qwen3.5-9B. The phase
trigger and paired validation of Appendix C use a separate validation
query set, disjoint from the training queries and from every evaluation
record; the six OOD datasets serve only for final evaluation. All
methods share the same executor, tool set, retrieval corpus and
inference budget. Verifier labels come from unit tests, schema
validation, assertions and execution status (Appendix C).

#### Extended analysis.

*Main results.* Training the backbone raises the IID exact-match average
by at most 7.26 points (GRPO^(†)) but lowers AIME 2026 from 51.33 to
````
