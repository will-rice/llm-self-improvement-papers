###### Abstract

Self-improving agents aim to continuously improve their behavior by
learning from experience after deployment. However, accumulating and
reusing more experience does not necessarily lead to better decisions,
particularly when generation, interaction, and memory resources are
jointly constrained. Under such stringent constraints, we find that
several existing lifelong-memory methods provide limited benefits over
simple retrieval or even no-memory agents. This reveals a fundamental
challenge for resource-efficient self-improvement: agents must learn not
only which past experiences are relevant, but which are actually worth
reusing to improve future decisions. When memory capacity and
opportunities for reasoning and recovery are limited, retrieving an
ineffective experience can consume scarce resources and hinder
downstream execution. To address this challenge, we propose TokenWorth,
a lightweight feedback-driven memory adaptation framework that learns
query-dependent memory worth from sparse execution feedback. Without
updating the backbone model, TokenWorth uses the learned worth to guide
both experience retrieval and bounded memory management, enabling the
agent to continually adapt how it reuses accumulated experience. Across
three LifelongAgentBench environments and both local and API-based
deployments, TokenWorth achieves the highest task success rate while
using the fewest output tokens among the evaluated methods under the
specified resource budgets. These results suggest that effective
self-improvement under resource constraints depends not on accumulating
more experience, but on learning what is worth remembering. Our code is
publicly available at
[https://github.com/AIGNLAI/TokenWorth](https://github.com/AIGNLAI/TokenWorth).

## 1 Introduction

Self-improving agents continually accumulate and reuse experience from
evolving task streams to improve their behavior after deployment
\[[35](#bib.bib3)\]. Such experience-driven adaptation is particularly
valuable for long-running agents facing evolving user needs,
environments, and tasks \[[4](#bib.bib7), [6](#bib.bib4),
[16](#bib.bib6)\]. However, accumulating more experience does not
necessarily translate into better decisions. In practice, generation is
constrained by latency, computation, or inference cost; interaction
opportunities are finite; and only a bounded amount of historical
experience can be stored or reused \[[8](#bib.bib22), [11](#bib.bib20),
[29](#bib.bib23)\]. This raises a fundamental question: _how can agents
effectively improve from experience when generation, interaction, and
memory resources are jointly constrained?_

![Refer to caption](2610.26453v2/intro.png)

Figure 1: Left: Representative local results with Qwen2.5-14B-Instruct
under the evaluated stringent joint resource constraints; TokenWorth
remains effective where several memory baselines do not. Right:
Resource-constrained lifelong agents adapt from experience under bounded
generation, interaction, and memory budgets.

Our evaluation reveals that existing memory mechanisms often struggle
under such constraints. As shown in
Figure [1](#S1.F1 "Figure 1 ‣ 1 Introduction ‣ Learning What to Remember: Resource-Efficient Self-Improvement for Lifelong Agents")(a),
several sophisticated lifelong-memory approaches provide limited
improvement over simple retrieval or even no-memory agents, and can
substantially underperform in some environments. These results suggest
that accumulating and reusing experience alone is insufficient for
reliable adaptation under stringent resource constraints. Importantly,
this limitation cannot be attributed simply to insufficient memory
capacity: under the same resource budget, different memory policies can
lead to markedly different downstream task performance.

To study this challenge systematically, we formalize
_resource-constrained lifelong agents_: agents that must continually
adapt from experience while operating under bounded generation,
interaction, and memory budgets. As illustrated in
Figure [1](#S1.F1 "Figure 1 ‣ 1 Introduction ‣ Learning What to Remember: Resource-Efficient Self-Improvement for Lifelong Agents")(b),
we jointly constrain the resources available for task execution and
experience reuse. Specifically, the agent operates with a bounded output
budget and limited interaction rounds, while its external memory is
constrained in capacity, retrieval count, and injection length. The
backbone remains frozen throughout the task stream, allowing us to study
experience-driven adaptation under a controlled, stringent resource
budget.

Why does experience-based adaptation become fragile under such
constraints? When only a small amount of experience can be retained or
reused, and opportunities for reasoning and recovery are limited, each
memory decision becomes more consequential. Semantic relevance alone may
be insufficient: an experience can appear relevant to the current query
yet provide little downstream utility. Conversely, useful experience
that is not retained or selected cannot be recovered by simply injecting
more context or extending the interaction. Resource scarcity therefore
exposes a fundamental distinction between accumulating experience and
effectively learning from it. The central challenge is not merely to
retrieve relevant experience, but to determine which experiences are
actually _worth_ retaining and reusing to improve future decisions.

To address this challenge, we propose TokenWorth, a lightweight
feedback-driven memory adaptation framework that learns query-dependent
memory worth from sparse execution feedback. TokenWorth combines an
interpretable online base scorer with a residual Recursive Feature
Machine (RFM), allowing stable global patterns of memory usefulness to
be complemented by nonlinear, query-specific corrections. The learned
worth guides both memory retrieval and bounded memory-bank management,
enabling the agent to continually adapt its experience-reuse policy
without backbone updates or additional language-model calls.

We evaluate TokenWorth on three LifelongAgentBench environments covering
database interaction, operating-system tasks, and knowledge-graph
reasoning, under both local and API-based deployments. Across all six
environment–deployment combinations, TokenWorth achieves the highest
task success rate among the evaluated methods while using the fewest
output tokens. These results suggest that resource-efficient adaptation
depends not on accumulating more experience, but on learning what is
worth remembering.

Our contributions are threefold:

- •
  We formulate _resource-constrained lifelong agents_ and investigate
  experience-driven adaptation under stringent joint constraints on
  generation, interaction, and memory.
- •
  We propose TokenWorth, a lightweight online framework that learns
  query-dependent memory worth from execution feedback and uses it
  consistently for memory retrieval and bounded memory management.
- •
  We evaluate TokenWorth across three LifelongAgentBench environments
  under both local and API-based deployments, demonstrating improved
  task success and generation efficiency under stringent resource
  constraints.

## 2 Related Work

#### Experience-Driven Self-Improvement in Language Agents.

Self-improving language agents aim to continually improve from
accumulated interaction experience, enabling adaptation after deployment
without necessarily updating backbone parameters \[[6](#bib.bib4),
[35](#bib.bib3)\]. Early agent systems demonstrated that past
trajectories, reflections, or reusable skills can improve future
decisions, including Reflexion \[[19](#bib.bib12)\],
ExpeL \[[33](#bib.bib13)\], Voyager \[[24](#bib.bib14)\], and
SocioDojo \[[4](#bib.bib7)\]. More recent work has developed explicit
memory and skill mechanisms for continual adaptation, such as
MemoryBank \[[37](#bib.bib11)\], Mem0 \[[5](#bib.bib17)\],
MemRL \[[32](#bib.bib18)\], MemSkill \[[30](#bib.bib19)\], and
AutoSkill \[[27](#bib.bib24)\]. Meanwhile,
LifelongAgentBench \[[34](#bib.bib5)\], AgentCL \[[21](#bib.bib9)\],
SkillLearnBench \[[36](#bib.bib15)\], and XSkill \[[10](#bib.bib8)\]
provide systematic evaluations of experience-driven adaptation. While
these studies explore how agents accumulate and exploit experience, we
investigate how agents can learn which experiences are worth reusing to
support effective adaptation under stringent resource constraints.

#### Resource-Constrained Agent Adaptation.

Resource efficiency has been extensively studied for LLM inference and
serving, including memory-efficient execution \[[11](#bib.bib20)\] and
collaborative inference under computation and communication
constraints \[[29](#bib.bib23)\]. Recent work has extended resource
considerations to agent adaptation. [Hajimiri et al. \[9\]](#bib.bib25)
study whether online memory and skill modules remain beneficial under
fixed inference-token budgets, while [Wu et al. \[25\]](#bib.bib26)
investigate continual learning with hard-bounded on-device memory.
BudgetMem \[[31](#bib.bib30)\] considers query-aware routing across
runtime memory budgets, and [Chen and Cheng \[3\]](#bib.bib31) model
agentic memory value using multiple factors for retention and retrieval.
These studies highlight the importance of resource-aware experience
reuse, but primarily focus on individual constraints, runtime budgeting,
or memory valuation in isolation. In contrast, we study
experience-driven self-improvement under stringent joint constraints on
generation, interaction, and memory. We propose TokenWorth, which learns
query-dependent memory worth from online execution feedback to guide
both retrieval and bounded memory management, enabling continual
adaptation without backbone updates.

## 3 Resource-Constrained Lifelong Agents

We consider a lifelong agent that sequentially processes an online task
stream $`\mathcal{Q}=\{q_{1},q_{2},\ldots,q_{T}\}`$. At step $`t`$, the
agent receives task $`q_{t}`$ and may retrieve a set of past experiences
$`\mathcal{R}_{t}`$ from its current memory bank
$`\mathcal{B}_{t}=\{m_{1},\ldots,m_{N_{t}}\}`$. Conditioned on $`q_{t}`$
and $`\mathcal{R}_{t}`$, the backbone model interacts with the
environment for $`J_{t}`$ rounds, producing a trajectory

|     |     |     |
| --- | --- | --- |
|     |

       ``` math
       \tau_{t}=\{(o_{t,j},a_{t,j})\}_{j=1}^{J_{t}},
       ```                                            |     |

where $`o_{t,j}`$ and $`a_{t,j}`$ denote the observation and model
output at interaction round $`j`$, respectively. The environment then
returns a task-level reward $`r_{t}\in\{0,1\}`$. After observing this
outcome, the memory policy may update the bank from $`\mathcal{B}_{t}`$
to $`\mathcal{B}_{t+1}`$. We focus on a frozen-backbone setting, where
experience-driven adaptation occurs through online updates to external
memory and its management policy, rather than model parameters.

We impose resource constraints on both task execution and experience
reuse. For execution, the total amount of model generation associated
with each task, including both environment interaction and any
method-specific auxiliary language-model calls, is bounded by

|     |     |     |
| --- | --- | --- |
|     |

````math
\sum_{j=1}^{J_{t}}|a_{t,j}|_{\mathrm{tok}}+A_{t}^{\mathrm{aux}}\leq O_{\max},\qquad J_{t}\leq J_{\max},
``` |  |

where $`A_{t}^{\mathrm{aux}}`$ denotes the output tokens generated by
auxiliary language-model calls such as memory construction, reflection,
or skill extraction. For memory, the persistent bank is bounded by

|     |                                 |     |
|-----|---------------------------------|-----|
|     |
       ``` math
       |\mathcal{B}_{t}|\leq B_{\max},
       ```                              |     |

while the memories supplied to the agent satisfy

|  |  |  |
|----|----|----|
|  |
``` math
|\mathcal{R}_{t}|\leq K_{\max},\qquad\mathrm{Len}(\mathcal{R}_{t})\leq L_{\max}.
``` |  |

We summarize the overall resource budget as

|     |                                                             |     |
|-----|-------------------------------------------------------------|-----|
|     |
       ``` math
       \mathcal{C}=(O_{\max},J_{\max},B_{\max},K_{\max},L_{\max}),
       ```                                                          |     |

which jointly constrains generation, interaction, memory storage, and
memory usage.

Let $`\pi_{\mathrm{mem}}`$ denote an online memory policy that
determines both which experiences to retrieve for the current task and
how the memory bank is updated after observing the task outcome. Through
execution feedback, this policy can adapt how accumulated experience
influences future decisions without modifying the backbone. For a fixed
resource budget $`\mathcal{C}`$, we define its lifelong task performance
as

|  |  |  |
|----|----|----|
|  |
``` math
S(\pi_{\mathrm{mem}};\mathcal{C})=\frac{1}{T}\sum_{t=1}^{T}\mathbb{E}[r_{t}].
``` |  |

The objective is therefore

|  |  |  |  |
|----|----|----|----|
|  |
``` math
\pi_{\mathrm{mem}}^{\star}=\arg\max_{\pi_{\mathrm{mem}}\in\Pi(\mathcal{C})}S(\pi_{\mathrm{mem}};\mathcal{C}),
``` |  | (1) |

where $`\Pi(\mathcal{C})`$ denotes the class of online memory policies
satisfying the resource constraints above.

Our focus is on experience-driven adaptation under a stringent joint
resource budget, where generation, interaction, and memory resources are
simultaneously limited. Under such constraints, ineffective memory
decisions cannot easily be compensated for by retrieving additional
experience, generating longer reasoning traces, or interacting for more
rounds. Each retrieval and retention decision therefore becomes more
consequential. The central challenge for resource-efficient
self-improvement is not merely to accumulate or retrieve relevant
experience, but to learn which experiences are actually *worth*
retaining and reusing to improve future decisions.

## 4 TokenWorth: Feedback-Driven Memory Adaptation

### 4.1 Overview

Figure [2](#S4.F2 "Figure 2 ‣ 4.1 Overview ‣ 4 TokenWorth: Feedback-Driven Memory Adaptation ‣ Learning What to Remember: Resource-Efficient Self-Improvement for Lifelong Agents")
illustrates the feedback-driven adaptation process of TokenWorth. Given
a query $`q_{t}`$, the agent first recalls a small candidate set from
its bounded memory bank. TokenWorth estimates the query-dependent worth
of each candidate using a learnable linear base scorer and an RFM-based
residual correction, selecting the highest-valued experience for task
execution. After receiving the environment reward, the worth model is
updated online, and the learned worth further guides memory-bank
management. Through this feedback loop, the agent continually adapts how
past experience influences future decisions without updating its
backbone.

TokenWorth consists of three components. First, an interpretable linear
scorer captures stable memory-utility patterns, while a residual
Recursive Feature Machine (RFM) models nonlinear, query-specific
corrections \[[2](#bib.bib10), [18](#bib.bib21)\]. Second, fast value
updates and slower AGOP-based feature adaptation balance stability and
adaptivity under sparse feedback. Third, learned worth guides both
retrieval and bounded memory management.

### 4.2 Learning Query-Dependent Memory Worth

Effective experience-driven adaptation requires identifying which past
experiences are worth reusing for future decisions. Unlike a fixed
memory-utility score, the usefulness of an experience depends on the
current query and must be inferred from sparse execution feedback. Each
task is executed only once, feedback is observed only for the memory
actually used, and execution failure may arise from factors beyond the
selected memory itself.

To balance stability and adaptivity under such feedback, TokenWorth
decomposes memory worth into two complementary components. A lightweight
linear base scorer captures stable and interpretable patterns across the
task stream, while an RFM learns nonlinear residual structure not
captured by the base scorer. The linear component is updated
conservatively around an informative prior, whereas the RFM adapts more
flexibly to local query–memory interactions.

#### Candidate recall and representation.

Each memory $`m_{i}\in\mathcal{B}_{t}`$ contains a compact record of a
previously successful interaction together with lightweight statistics
describing its historical use. Given the current query $`q_{t}`$, we
first recall a small candidate set using a lightweight textual relevance
function:

|  |  |  |
|----|----|----|
|  |
``` math
\mathcal{C}_{t}=\operatorname{TopK}_{K_{c}}\left\{s_{\mathrm{recall}}(q_{t},m):m\in\mathcal{B}_{t}\right\},
``` |  |

where $`K_{c}`$ controls only the internal candidate pool and is
independent of the number of memories ultimately supplied to the agent.

For each candidate $`m_{i}\in\mathcal{C}_{t}`$, we construct four
interpretable features

|  |  |  |
|----|----|----|
|  |
``` math
\bm{\phi}_{t}^{i}=\left[\phi_{\mathrm{sim}}(q_{t},m_{i}),\phi_{\mathrm{util}}(m_{i}),\phi_{\mathrm{rel}}(m_{i}),\phi_{\mathrm{recent}}(m_{i})\right],
``` |  |

capturing lightweight textual similarity, historical utility,
reliability, and recency.

For residual estimation, we additionally construct a richer query–memory
representation

|  |  |  |
|----|----|----|
|  |
``` math
\mathbf{z}_{t}^{i}=\left[|\mathbf{e}_{t}-\mathbf{e}_{i}|,\operatorname{cos}(\mathbf{e}_{t},\mathbf{e}_{i}),u_{i},\operatorname{rel}_{t}(m_{i}),\operatorname{rec}_{t}(m_{i}),\operatorname{freq}_{t}(m_{i})\right].
``` |  |

This representation combines hashed textual similarity features with the
empirical history of each memory. The text representation is
deterministic and lightweight rather than a learned semantic embedding;
detailed definitions are provided in
Appendix [B](#A2 "Appendix B Implementation Details of TokenWorth ‣ Learning What to Remember: Resource-Efficient Self-Improvement for Lifelong Agents").

#### Prior-regularized base scorer.

The base scorer captures stable global relationships between memory
characteristics and downstream usefulness:

|  |  |  |
|----|----|----|
|  |
``` math
s_{\mathrm{base},t}(q_{t},m_{i})=\mathbf{w}_{t}^{\top}\bm{\phi}_{t}^{i}.
``` |  |

Rather than learning $`\mathbf{w}_{t}`$ from scratch, we initialize it
from an informative prior $`\mathbf{w}_{0}`$ and regularize subsequent
online updates toward this prior. Given observed execution feedback
$`\mathcal{D}^{\mathrm{base}}_{t}=\{(\bm{\phi}_{j}^{\star},y_{j})\}`$,
we optimize

|  |  |  |
|----|----|----|
|  |
``` math
\mathcal{L}_{\mathrm{base}}(\mathbf{w})=\sum_{(\bm{\phi}_{j}^{\star},y_{j})\in\mathcal{D}^{\mathrm{base}}_{t}}\log\!\left(1+\exp\!\left(-y_{j}\mathbf{w}^{\top}\bm{\phi}_{j}^{\star}\right)\right)+\lambda_{w}\|\mathbf{w}-\mathbf{w}_{0}\|_{2}^{2}.
``` |  |

The prior anchors the scorer when feedback is scarce, while online
updates allow it to capture evolving patterns of memory usefulness.
Conservative periodic updates, smoothing, and bounded weights further
reduce unstable drift; implementation details are provided in
Appendix [B](#A2 "Appendix B Implementation Details of TokenWorth ‣ Learning What to Remember: Resource-Efficient Self-Improvement for Lifelong Agents").

#### Residual worth estimation.

The linear base scorer captures stable global regularities but cannot
model all nonlinear or query-specific interactions among memory signals.
TokenWorth therefore augments it with an RFM-based residual correction:

|  |  |  |  |
|----|----|----|----|
|  |
``` math
s_{t}(q_{t},m_{i})=s_{\mathrm{base},t}(q_{t},m_{i})+\eta_{t}f_{t}(\mathbf{z}_{t}^{i}),
``` |  | (2) |

where $`f_{t}`$ predicts the residual memory worth not explained by the
base scorer and $`\eta_{t}`$ controls its contribution. The selected
memory is

|  |  |  |
|----|----|----|
|  |
``` math
m_{t}^{\star}=\arg\max_{m_{i}\in\mathcal{C}_{t}}s_{t}(q_{t},m_{i}).
``` |  |

The linear scorer captures stable patterns of memory usefulness, while
the RFM models nonlinear, query-specific deviations.

After task execution, the observed reward provides execution-derived
supervision for the selected query–memory pair:

|     |                             |     |
|-----|-----------------------------|-----|
|     |
       ``` math
       y_{t}=2r_{t}-1\in\{-1,+1\}.
       ```                          |     |

The base scorer is updated directly from
$`(\bm{\phi}_{t}^{\star},y_{t})`$. For the residual learner, we first
compute the prediction implied by the base scorer,

|  |  |  |
|----|----|----|
|  |
``` math
\hat{y}_{t}^{\mathrm{base}}=2\sigma\!\left(s_{\mathrm{base},t}(q_{t},m_{t}^{\star})\right)-1,
``` |  |

and define the residual target

|     |                                               |     |
|-----|-----------------------------------------------|-----|
|     |
       ``` math
       \delta_{t}=y_{t}-\hat{y}_{t}^{\mathrm{base}}.
       ```                                            |     |

The RFM is then updated from $`(\mathbf{z}_{t}^{\star},\delta_{t})`$.
This feedback-driven update allows subsequent memory decisions to
incorporate observed execution outcomes. Importantly, the supervision
reflects downstream task success rather than the counterfactual causal
contribution of $`m_{t}^{\star}`$: TokenWorth does not re-execute the
same task with alternative memories.

### 4.3 Two-Timescale RFM Adaptation

Continual adaptation from sparse feedback requires balancing
responsiveness to recent outcomes with stability across the task stream.
Within the residual learner, prediction and feature geometry need not
adapt at the same rate. Recent outcomes provide immediate evidence about
local residual structure, whereas the geometry governing query–memory
features should evolve more conservatively. TokenWorth therefore
separates *fast residual adaptation* from *slow geometry adaptation*.

#### Fast residual adaptation.

Given a short feedback buffer
$`\mathcal{D}^{\mathrm{fast}}_{t}=\{(\mathbf{z}_{j},\delta_{j})\}_{j=1}^{N_{f}}`$,
we fit a kernel ridge regressor

|  |  |  |  |
|----|----|----|----|
|  |
``` math
f_{t}(\mathbf{z})=\sum_{j=1}^{N_{f}}\alpha_{j}K_{\mathbf{M}_{t}}(\mathbf{z},\mathbf{z}_{j}),\qquad\bm{\alpha}=\left(\mathbf{K}_{\mathbf{M}_{t}}+\lambda\mathbf{I}\right)^{-1}\bm{\delta},
``` |  | (3) |

where $`\mathbf{M}_{t}`$ is an adaptive diagonal feature metric. The KRR
coefficients are updated frequently, allowing the residual learner to
rapidly capture deviations from the global base scorer.

#### Slow geometry adaptation.

A fixed kernel metric would assume that different query–memory features
retain the same relative importance throughout the task stream. Instead,
RFM adapts the feature geometry using the *Average Gradient Outer
Product* (AGOP) \[[18](#bib.bib21), [13](#bib.bib38)\]. Given a longer
feedback window
$`\mathcal{D}^{\mathrm{slow}}_{t}=\{(\mathbf{z}_{j},\delta_{j})\}_{j=1}^{N_{s}}`$,
we compute the diagonal AGOP

|  |  |  |
|----|----|----|
|  |
``` math
\widetilde{\mathbf{G}}_{t}=\operatorname{Diag}\left(\frac{1}{N_{s}}\sum_{j=1}^{N_{s}}\nabla_{\mathbf{z}}f_{t}(\mathbf{z}_{j})\odot\nabla_{\mathbf{z}}f_{t}(\mathbf{z}_{j})\right),
``` |  |

and update the metric as

|  |  |  |  |
|----|----|----|----|
|  |
``` math
\mathbf{M}_{t+1}=\operatorname{NormClip}\left((1-\beta)\mathbf{M}_{t}+\beta\widetilde{\mathbf{G}}_{t}\right).
``` |  | (4) |

After each metric update, the KRR predictor is refitted under the
updated geometry.

These adaptation mechanisms play complementary roles in online
memory-worth learning. The prior-regularized linear scorer captures
slowly evolving global regularities, the fast KRR update tracks recent
residual structure, and the slower AGOP update adapts the feature
geometry more conservatively. Together, they aim to balance stability
and responsiveness when learning from limited execution feedback.

### 4.4 Worth-Guided Memory Lifecycle

Learning which memory to use for the current query addresses only part
of experience-driven adaptation. Under a bounded persistent capacity
$`B_{\max}`$, the agent must also determine which experiences deserve to
remain available for future tasks. TokenWorth therefore extends the same
query-dependent notion of worth from immediate retrieval to long-term
memory management.

Only successful, externally verified interactions are considered as new
memory candidates. For a candidate memory $`m`$, we estimate its broader
worth over a small set of recent probe queries $`\mathcal{P}_{t}`$:

|  |  |  |  |
|----|----|----|----|
|  |
``` math
V_{t}(m)=\frac{1}{|\mathcal{P}_{t}|}\sum_{q\in\mathcal{P}_{t}}s_{t}(q,m).
``` |  | (5) |

While $`s_{t}(q,m)`$ measures the query-dependent worth of $`m`$ for a
particular query, $`V_{t}(m)`$ aggregates this signal over recent
queries to estimate whether the memory deserves persistent capacity
under the current task distribution.

TokenWorth follows a coverage–quality principle for memory admission.
When capacity remains available, successful experiences are admitted to
build initial coverage. Once the bank is full, a candidate is admitted
if it is sufficiently novel, or if its probe-averaged worth exceeds that
of the best existing memory and satisfies a positive-score ratio
criterion. Candidates failing this admission gate may still replace a
low-utility nearest neighbor when they provide a sufficiently large
worth improvement. Detailed admission and replacement criteria are
provided in
Appendix [B](#A2 "Appendix B Implementation Details of TokenWorth ‣ Learning What to Remember: Resource-Efficient Self-Improvement for Lifelong Agents").

For candidates passing the admission gate, TokenWorth enforces the
capacity bound by evicting the memory with the lowest probe-averaged
worth from the enlarged bank:

|  |  |  |
|----|----|----|
|  |
``` math
m_{\mathrm{evict}}=\arg\min_{m\in\mathcal{B}_{t}\cup\{m_{\mathrm{new}}\}}V_{t}(m).
``` |  |

TokenWorth thus applies a unified notion of memory worth at two
complementary timescales: query-dependent worth determines which
experience should be used *now*, while probe-averaged worth determines
which experience should be retained for *later*. This feedback-driven
memory lifecycle continually reallocates limited capacity toward
experiences estimated to be useful for future tasks, allowing the agent
to adapt its experience-reuse policy over time. All adaptation occurs
within the lightweight memory controller; TokenWorth requires no
backbone updates, task replay, counterfactual execution, or additional
language-model calls.

## 5 Experiments

### 5.1 Experimental Setup

Benchmarks. We conduct our main evaluation on three environments from
LifelongAgentBench \[[34](#bib.bib5)\]: database interaction (DB),
operating-system interaction (OS), and knowledge-graph interaction (KG).
These environments cover heterogeneous forms of interactive decision
making under an online lifelong protocol, where agents can continually
adapt their experience-reuse policies based on preceding interactions.
In all environments, the memory bank is initialized empty, each task is
executed once, and memory decisions depend only on experience observed
from previous tasks.

We additionally evaluate generalization beyond LifelongAgentBench using
online lifelong variants of BigCodeBench \[[38](#bib.bib34)\] and
ALFWorld \[[20](#bib.bib35)\]. These results are reported in
Appendix [C](#A3 "Appendix C Generalization Beyond LifelongAgentBench ‣ Learning What to Remember: Resource-Efficient Self-Improvement for Lifelong Agents").

Backbone and deployment. We evaluate TokenWorth under two complementary
deployment settings. In the *local* setting, all methods use
Qwen2.5-14B-Instruct \[[17](#bib.bib37)\] as the frozen backbone, where
generation and interaction are constrained by computation and latency.
In the *API-based* setting, all methods use
DeepSeek-V4-Flash \[[26](#bib.bib36)\] through an external API, where
model generation and repeated interaction directly incur inference cost.
The backbone remains frozen throughout evaluation, so adaptation occurs
solely through external memory mechanisms.

Resource-constrained protocol. Following
Sec. [3](#S3 "3 Resource-Constrained Lifelong Agents ‣ Learning What to Remember: Resource-Efficient Self-Improvement for Lifelong Agents"),
we evaluate all methods under a stringent joint resource budget that
constrains generation, interaction, persistent memory capacity, and
memory injection. Within each environment and deployment setting, all
methods process the same task stream under the same resource budget. All
language-model generation incurred by a method, including auxiliary
calls for memory construction, reflection, or skill extraction, is
counted toward the same per-task generation budget $`O_{\max}`$. This
controlled protocol allows us to examine the effectiveness of
experience-driven adaptation when both task execution and experience
reuse are severely constrained. Across DB, OS, and KG, memory capacity
is 64 and at most one memory is retrieved per task. The respective
output-token budgets are 128, 512, and 128, with interaction limits of
3, 5, and 15 rounds. These results characterize effectiveness under this
fixed stringent budget; we do not claim robustness across a range of
budget levels.

Baselines. We compare TokenWorth with a no-memory agent (Standard),
vanilla retrieval-augmented generation (RAG) \[[15](#bib.bib16)\], and
representative lifelong-memory methods, including
MemRL \[[32](#bib.bib18)\], Mem0 \[[5](#bib.bib17)\],
MemP \[[7](#bib.bib27)\], MemSkill \[[30](#bib.bib19)\],
Reflexion \[[19](#bib.bib12)\], EvoSC \[[28](#bib.bib28)\], and
EvoSkill \[[1](#bib.bib29)\]. All methods share the same frozen
backbone, task stream, and resource budget within each setting.

Metrics. We evaluate task effectiveness using task success rate
($`\mathrm{SR}\uparrow`$). To measure generation efficiency, we report
the average number of output tokens per task (OutputTok $`\downarrow`$),
including all language-model generation incurred during task execution
and method-specific auxiliary operations such as memory construction,
reflection, or skill extraction. We further report the relative change
in output-token usage with respect to the no-memory Standard agent:

|  |  |  |
|----|----|----|
|  |
``` math
\Delta\mathrm{Tok}=\frac{\mathrm{OutputTok}_{\mathrm{method}}-\mathrm{OutputTok}_{\mathrm{Standard}}}{\mathrm{OutputTok}_{\mathrm{Standard}}}\times 100\%,
``` |  |

where a negative value indicates lower generation consumption than the
no-memory baseline.

RQ1: Can TokenWorth support effective experience-driven adaptation under

Under the local deployment, the improvement is particularly pronounced
on DB, where TokenWorth reaches $`65.0\%`$, outperforming the strongest
baseline RAG ($`33.0\%`$) by $`32.0`$ percentage points. It also

memory-based methods provide limited gains over the no-memory Standard
agent and can even substantially underperform it, particularly on KG.

does not guarantee effective adaptation. Learning which experiences are
worth reusing is particularly important when generation, interaction,
and memory resources are jointly constrained.

Under the local Qwen2.5-14B-Instruct deployment, TokenWorth reduces

TokenWorth also uses fewer output tokens than the most
generation-efficient baseline in each setting, with clear margins on DB
and OS. Although the margin over MemRL on API-based KG is smaller,
TokenWorth still improves both success and token usage. These results
suggest that learning to reuse higher-value experience helps the frozen
backbone solve more tasks with less generation, supporting
resource-efficient experience-driven adaptation.

RQ3: How do the adaptation components affect memory-worth learning?
Figure [3](#S5.F3 "Figure 3 ‣ 5.2 Results and Analysis ‣ 5 Experiments ‣ Learning What to Remember: Resource-Efficient Self-Improvement for Lifelong Agents")(b)
reports a core ablation on DB with Qwen2.5-14B-Instruct. We compare the
base scorer alone (Base Only), the base scorer augmented with an RFM
residual learner using a fixed feature metric (Base + RFM), and the full
framework with AGOP-based feature adaptation (Full).

The base scorer achieves $`64.2\%`$, demonstrating the effectiveness of
stable, interpretable memory signals. Adding the RFM residual learner
with a fixed feature metric reduces performance to $`63.0\%`$,
indicating that nonlinear residual modeling alone does not necessarily
improve memory-worth estimation. With AGOP-based feature adaptation, the
full framework reaches $`65.0\%`$, recovering this degradation and
modestly outperforming the base-only variant. These results suggest that
adaptive feature geometry improves residual corrections under sparse
execution feedback, highlighting the importance of balancing stability
and adaptivity in online memory-worth learning.

## 6 Conclusion

We study experience-driven adaptation in lifelong agents under joint
constraints on generation, interaction, and memory. We propose
TokenWorth, a lightweight feedback-driven memory adaptation framework
that learns query-dependent memory worth from online execution feedback
and uses it for retrieval and bounded memory management. Across three
LifelongAgentBench environments and local and API-based backbones,
TokenWorth achieves the highest task success rates among evaluated
methods while using the fewest output tokens. Additional experiments
show competitive performance on coding and embodied-agent tasks. These
results suggest that resource-efficient self-improvement depends not on
accumulating more experience, but on learning what is worth remembering.
Since feedback is observed only for selected memories, their causal
contributions remain unidentified. Developing budget-efficient credit
assignment remains an important direction for future work.

## Appendix A Additional Experimental Details

### A.1 Benchmarks

Our main experiments use three environments from
LifelongAgentBench \[[34](#bib.bib5)\]: database interaction (DB),
operating-system interaction (OS), and knowledge-graph interaction (KG).
Tasks are processed sequentially, and only experience from preceding
tasks may be reused. DB requires structured database operations and
answers grounded in retrieved observations. OS requires multi-step
system management through Bash commands. KG follows an AgentBench-style
protocol in which the agent interacts with a knowledge graph through
structured tool calls, while SPARQL queries are executed by the backend.
The environments thus cover heterogeneous forms of interactive decision
making under a shared online lifelong-learning protocol.

We additionally evaluate online lifelong variants of
BigCodeBench \[[38](#bib.bib34)\] and ALFWorld \[[20](#bib.bib35)\];
their results are reported in
Appendix [C](#A3 "Appendix C Generalization Beyond LifelongAgentBench ‣ Learning What to Remember: Resource-Efficient Self-Improvement for Lifelong Agents").

Beyond language agents, class-incremental learning has examined the
impact of task ordering on continual adaptation \[[12](#bib.bib1)\] and
the variability of performance across evaluation sequences
\[[14](#bib.bib2)\]. These studies highlight the importance of
evaluation protocols in continual learning, while our experiments focus
on online memory adaptation under fixed resource budgets.

### A.2 Baselines

We compare TokenWorth with a no-memory agent (Standard),
retrieval-augmented generation (RAG), and representative memory- and
skill-learning methods.

#### Standard.

The frozen backbone solves every task independently, without persistent
cross-task memory.

#### RAG.

RAG \[[15](#bib.bib16), [22](#bib.bib33), [23](#bib.bib32)\] stores
successful experiences and retrieves them by lightweight textual
relevance, without online value learning.

#### MemRL.

MemRL \[[32](#bib.bib18)\] uses execution feedback to learn utility
signals for episodic memories, serving as a value-aware baseline.

#### Mem0.

Mem0 \[[5](#bib.bib17)\] supports memory extraction, storage, retrieval,
and update in long-running agents.

#### MemP.

MemP \[[7](#bib.bib27)\] retains procedural task experience for later
reuse.

#### MemSkill.

MemSkill \[[30](#bib.bib19)\] converts experience into reusable memory
skills and evolves them online.

#### Reflexion.

Reflexion \[[19](#bib.bib12)\] stores verbal reflections derived from
task feedback for reuse in subsequent tasks.

#### EvoSC.

EvoSC \[[28](#bib.bib28)\] consolidates and evolves agent experience.

#### EvoSkill.

EvoSkill \[[1](#bib.bib29)\] extracts reusable skills from interaction
trajectories and updates its skill repository.

Within each environment and deployment setting, methods share the same
task sequence, backbone, environment interface, and resource budget. We
preserve baseline-specific auxiliary operations such as reflection,
memory construction, and skill extraction; their generated output tokens
are included in both the per-task budget and the reported OutputTok.
Baseline implementations are adapted to satisfy the common resource
limits.

### A.3 Backbones and Deployment Settings

#### Local deployment.

All methods use the frozen Qwen2.5-14B-Instruct \[[17](#bib.bib37)\]
backbone on NVIDIA A800 GPUs.

#### API-based deployment.

All methods use the frozen DeepSeek-V4-Flash \[[26](#bib.bib36)\]
backbone through an external inference API.

In both deployments, the memory bank starts empty, task order is fixed
within an environment, and no backbone parameters are updated.
TokenWorth uses neither offline pretraining nor task replay or
counterfactual re-execution.

### A.4 Evaluation Protocol

We measure task effectiveness with task success rate
($`\mathrm{SR}\uparrow`$). A task succeeds only if the environment
evaluator marks its final answer or state as correct. Generation
efficiency is measured by average output tokens per task (OutputTok
$`\downarrow`$), including tokens from task execution and all
method-specific auxiliary language-model calls. Relative to Standard,

|  |  |  |
|----|----|----|
|  |
``` math
\Delta\mathrm{Tok}=\frac{\mathrm{OutputTok}_{\mathrm{method}}-\mathrm{OutputTok}_{\mathrm{Standard}}}{\mathrm{OutputTok}_{\mathrm{Standard}}}\times 100\%.
``` |  |

Negative values indicate fewer generated tokens. OutputTok does not
include input tokens or controller-side computation and should not be
interpreted as total inference cost.

## Appendix B Implementation Details of TokenWorth

### B.1 Common Online Implementation

#### Online feedback protocol.

At the beginning of task $`t`$, retrieval uses the bank
$`\mathcal{B}_{t}`$ and feedback available through task $`t-1`$. Task
$`t`$ is executed once. Following its completion, the observed reward
updates the worth model and the selected memory’s statistics, and memory
admission or eviction constructs $`\mathcal{B}_{t+1}`$. These updates
may affect task $`t+1`$ and later tasks; there is no same-task
counterfactual execution or backbone fine-tuning.

#### Lightweight text representation.

We construct deterministic $`512`$-dimensional text vectors by token
hashing and character $`3`$–$`5`$-gram hashing, followed by $`\ell_{2}`$
normalization. This representation requires no learned encoder and
captures lightweight textual similarity rather than learned semantic
embeddings. For a query $`q`$ and memory $`m`$, the residual input is

|  |  |  |
|----|----|----|
|  |
``` math
\mathbf{z}(q,m)=\bigl[|\mathbf{e}_{q}-\mathbf{e}_{m}|,\operatorname{cos}(\mathbf{e}_{q},\mathbf{e}_{m}),u_{m},\operatorname{rel}(m),\operatorname{rec}(m),\operatorname{freq}(m)\bigr].
``` |  |

Here $`u_{m}`$ is historical utility. With $`h_{m}`$ and $`d_{m}`$
denoting counts of successful and unsuccessful executions, respectively,
*conditioned on selecting $`m`$*, the other statistics are

|  |  |  |  |
|----|----|----|----|
|  | $`\displaystyle\operatorname{rel}(m)`$ | $`\displaystyle=\frac{h_{m}+1}{h_{m}+d_{m}+2},`$ |  |
|  | $`\displaystyle\operatorname{rec}(m)`$ | $`\displaystyle=\exp(-\kappa\Delta t_{m}),`$ |  |
|  | $`\displaystyle\operatorname{freq}(m)`$ | $`\displaystyle=\frac{c_{m}}{\max(1,t-\tau_{m}+1)}.`$ |  |

Here $`\Delta t_{m}`$ is the number of steps since last access,
$`c_{m}`$ is the access count, and $`\tau_{m}`$ is the creation step. We
set $`\kappa=0.02`$. The success and failure counts are
execution-derived statistics, not causal estimates of a memory’s effect.

#### Candidate recall and base scorer.

The bank is screened by lightweight textual relevance to form

|  |  |  |
|----|----|----|
|  |
``` math
\mathcal{C}_{t}=\operatorname{TopK}_{K_{c}}\{s_{\mathrm{recall}}(q_{t},m):m\in\mathcal{B}_{t}\}.
``` |  |

For each candidate, define
$`\bm{\phi}(q,m)=[\phi_{\mathrm{sim}},\phi_{\mathrm{util}},\phi_{\mathrm{rel}},\phi_{\mathrm{recent}}]`$
and $`s_{\mathrm{base},t}(q,m)=\mathbf{w}_{t}^{\top}\bm{\phi}(q,m)`$. We
initialize $`\mathbf{w}_{0}=[1.0,0.10,0.10,0.02]`$ and fit

|  |  |  |
|----|----|----|
|  |
``` math
\mathcal{L}_{\mathrm{base}}(\mathbf{w})=\sum_{(\bm{\phi}_{j},y_{j})\in\mathcal{D}^{\mathrm{base}}_{t}}\log\!\left(1+\exp(-y_{j}\mathbf{w}^{\top}\bm{\phi}_{j})\right)+\lambda_{w}\|\mathbf{w}-\mathbf{w}_{0}\|_{2}^{2}.
``` |  |

The FIFO training window contains at most $`256`$ selected query–memory
pairs, with $`y_{j}\in\{-1,+1\}`$. We use $`\lambda_{w}=0.1`$ and refit
after every $`50`$ new feedback examples using deterministic Newton
optimization with backtracking line search. Updated weights are smoothed
with coefficient $`\beta_{w}=0.5`$ and clipped coordinate-wise between
$`[0,0,0,0]`$ and $`[2.0,1.0,1.0,1.0]`$.

#### Residual worth estimation.

The combined score and selected memory are

|  |  |  |
|----|----|----|
|  |
``` math
s_{t}(q,m)=s_{\mathrm{base},t}(q,m)+\eta_{t}f_{t}(\mathbf{z}(q,m)),\qquad m_{t}^{\star}=\arg\max_{m\in\mathcal{C}_{t}}s_{t}(q_{t},m).
``` |  |

To avoid abrupt residual corrections during early adaptation, we
linearly increase the residual coefficient over the first three KRR
fits:

|  |  |  |
|----|----|----|
|  |
``` math
\eta_{t}=\eta_{\max}\min\left\{\frac{n_{\mathrm{KRR}}(t)}{3},\,1\right\},
``` |  |

where $`n_{\mathrm{KRR}}(t)`$ denotes the number of completed KRR fits
and $`\eta_{\max}`$ is the environment-specific coefficient given in
Table [A1](#A2.T1 "Table A1 ‣ B.3 Environment-Specific Configuration ‣ Appendix B Implementation Details of TokenWorth ‣ Learning What to Remember: Resource-Efficient Self-Improvement for Lifelong Agents").
For a task reward $`r_{t}\in\{0,1\}`$, the execution label and residual
target are

|  |  |  |
|----|----|----|
|  |
``` math
y_{t}=2r_{t}-1,\qquad\widehat{y}^{\mathrm{base}}_{t}=2\sigma\!\left(s_{\mathrm{base},t}(q_{t},m_{t}^{\star})\right)-1,\qquad\delta_{t}=y_{t}-\widehat{y}^{\mathrm{base}}_{t}.
``` |  |

Only the selected pair $`(q_{t},m_{t}^{\star})`$ receives feedback.
These labels reflect downstream task outcomes, not same-task comparisons
among memories.

#### Kernel ridge regression and AGOP.

The residual predictor fits kernel ridge regression (KRR) to a FIFO
window of at most $`128`$ feedback pairs
$`\{(\mathbf{z}_{j},\delta_{j})\}`$, using the Laplacian kernel

|  |  |  |
|----|----|----|
|  |
``` math
K_{\mathbf{M}_{t}}(\mathbf{z},\mathbf{z}^{\prime})=\exp\!\left[-\gamma\sqrt{(\mathbf{z}-\mathbf{z}^{\prime})^{\top}\mathbf{M}_{t}(\mathbf{z}-\mathbf{z}^{\prime})}\right],
``` |  |

with $`\lambda_{\mathrm{KRR}}=0.01`$ and $`\gamma=1.0`$. The metric
$`\mathbf{M}_{t}`$ is diagonal. Fast KRR coefficients are periodically
refitted; slower feature-geometry updates use the diagonal Average
Gradient Outer Product (AGOP):

|  |  |  |  |
|----|----|----|----|
|  | $`\displaystyle\widetilde{\mathbf{G}}_{t}`$ | $`\displaystyle=\operatorname{Diag}\!\left(\frac{1}{N_{s}}\sum_{j=1}^{N_{s}}\nabla_{\mathbf{z}}f_{t}(\mathbf{z}_{j})\odot\nabla_{\mathbf{z}}f_{t}(\mathbf{z}_{j})\right),`$ |  |
|  | $`\displaystyle\mathbf{M}_{t+1}`$ | $`\displaystyle=\operatorname{NormClip}\!\left((1-\beta_{M})\mathbf{M}_{t}+\beta_{M}\widetilde{\mathbf{G}}_{t}\right).`$ |  |

The slow window contains at most $`256`$ feedback examples. We set
$`\beta_{M}=0.25`$, clip diagonal weights to $`[0.05,8.0]`$, and
normalize them to mean $`1`$. KRR is refitted after every AGOP update;
update intervals are listed in
Table [A1](#A2.T1 "Table A1 ‣ B.3 Environment-Specific Configuration ‣ Appendix B Implementation Details of TokenWorth ‣ Learning What to Remember: Resource-Efficient Self-Improvement for Lifelong Agents").

#### Execution-derived memory statistics.

A newly created memory starts with utility $`u(m)=1.0`$. After a task
with selected memory $`m_{t}^{\star}`$, its utility is updated without
an EMA:

|  |  |  |
|----|----|----|
|  |
``` math
u_{t}(m_{t}^{\star})=\operatorname{clip}\!\left(u_{t-1}(m_{t}^{\star})+\begin{cases}+0.25,&r_{t}=1,\\
-0.45,&r_{t}=0,\end{cases}-2,5\right).
``` |  |

Successful (unsuccessful) task execution with the selected memory
increments $`h_{m}`$ ($`d_{m}`$). Access count and recency are updated
after each use.

#### Memory admission, replacement, and eviction.

Only externally verified successful tasks produce candidate memories.
While $`|\mathcal{B}_{t}|<B_{\max}`$, each eligible candidate is
admitted to establish coverage. For a full bank, let
$`m_{\mathrm{near}}`$ denote the nearest existing memory in the same
hashed textual representation. Define

|  |  |  |  |
|----|----|----|----|
|  | $`\displaystyle\operatorname{nov}_{t}(m_{\mathrm{new}})`$ | $`\displaystyle=1-\max_{m_{i}\in\mathcal{B}_{t}}\operatorname{cos}(\mathbf{e}_{\mathrm{new}},\mathbf{e}_{i}),`$ |  |
|  | $`\displaystyle V_{t}(m)`$ | $`\displaystyle=\frac{1}{|\mathcal{P}_{t}|}\sum_{q\in\mathcal{P}_{t}}s_{t}(q,m),`$ |  |
|  | $`\displaystyle\rho_{t}^{+}(m_{\mathrm{new}})`$ | $`\displaystyle=\frac{1}{|\mathcal{P}_{t}|}\sum_{q\in\mathcal{P}_{t}}\mathbb{I}\!\left[s_{t}(q,m_{\mathrm{new}})>0\right].`$ |  |

The probe set $`\mathcal{P}_{t}`$ includes the current query and up to
eight previous queries on which memory retrieval occurred (FIFO), hence
$`|\mathcal{P}_{t}|\leq 9`$. The positive-score ratio $`\rho_{t}^{+}`$
measures the fraction of probe queries for which the candidate receives
a positive worth score, rather than the fraction on which it outperforms
the nearest memory.

For a full bank, a candidate passes the admission gate if

|  |  |  |  |
|----|----|----|----|
|  |  | $`\displaystyle\operatorname{nov}_{t}(m_{\mathrm{new}})>\tau_{\mathrm{nov}}`$ |  |
|  |  | $`\displaystyle\lor\left[V_{t}(m_{\mathrm{new}})>\max_{m\in\mathcal{B}_{t}}V_{t}(m)+\delta_{\mathrm{write}}\;\land\;\rho_{t}^{+}(m_{\mathrm{new}})\geq\tau_{\mathrm{pos}}\right],`$ |  |

where $`\tau_{\mathrm{nov}}=0.35`$, $`\delta_{\mathrm{write}}=0.02`$,
and $`\tau_{\mathrm{pos}}=0.45`$. Thus, admission requires either
sufficient novelty or a worth improvement over the best existing memory
together with a sufficiently high positive-score ratio.

Candidates passing this admission gate are added to the bank. The
capacity bound is then enforced by evicting the memory with the lowest
probe-averaged worth from the enlarged bank:

|  |  |  |
|----|----|----|
|  |
``` math
m_{\mathrm{evict}}=\arg\min_{m\in\mathcal{B}_{t}\cup\{m_{\mathrm{new}}\}}V_{t}(m),\qquad|\mathcal{B}_{t+1}|\leq B_{\max}.
``` |  |

The newly admitted candidate may itself be evicted if it has the lowest
probe-averaged worth.

If the candidate fails the admission gate, the controller instead
considers direct replacement of its nearest existing memory. Replacement
occurs only when the nearest memory has low utility and the candidate
exceeds its probe-averaged worth by a larger margin:

|  |  |  |
|----|----|----|
|  |
``` math
u(m_{\mathrm{near}})<\tau_{\mathrm{util}}=0.5,\qquad V_{t}(m_{\mathrm{new}})>V_{t}(m_{\mathrm{near}})+\delta_{\mathrm{rep}},\quad\delta_{\mathrm{rep}}=0.10.
``` |  |

When both conditions hold, $`m_{\mathrm{new}}`$ directly replaces
$`m_{\mathrm{near}}`$ without invoking the lowest-worth eviction rule.
Candidates satisfying neither the admission gate nor the fallback
replacement conditions are rejected.

### B.2 Common Hyperparameters

The main common parameters are $`\mathbf{w}_{0}=[1.0,0.10,0.10,0.02]`$,
$`\lambda_{w}=0.1`$, $`\beta_{w}=0.5`$, $`\lambda_{\mathrm{KRR}}=0.01`$,
$`\gamma=1.0`$, $`\beta_{M}=0.25`$, and $`\kappa=0.02`$. The base, fast
KRR, and slow AGOP feedback windows contain at most $`256`$, $`128`$,
and $`256`$ examples, respectively. The shared memory-management
thresholds are $`\tau_{\mathrm{nov}}=0.35`$,
$`\delta_{\mathrm{write}}=0.02`$, $`\tau_{\mathrm{pos}}=0.45`$, and
$`\delta_{\mathrm{rep}}=0.10`$. Further bounds and update rules are
specified in
Appendix [B](#A2 "Appendix B Implementation Details of TokenWorth ‣ Learning What to Remember: Resource-Efficient Self-Improvement for Lifelong Agents")
above, and the environment-dependent settings in

### B.4 Environment-Specific Memory Construction

#### DB.

Successful tasks are stored as compact demonstrations containing the
question, valid SQL actions, truncated database observations, and final
answer. Invalid actions and unnecessary output are omitted.

#### OS.

Complete shell trajectories contain instance-specific paths, user names,
and process identifiers that transfer poorly. We retain concise patterns
from successful Bash actions, including permission management, batch
file processing, text editing, symbolic links, and process management. A
task is successful when the environment evaluator reports correct,
including when the interaction limit is reached after a correct final
state.

#### KG.

Memories contain successful knowledge-graph tool calls and truncated
knowledge-graph observations, rather than SPARQL queries executed by the
backend. KG allows up to $`15`$ interaction rounds and $`4096`$
characters of injected memory; residual adaptation starts after at least
$`24`$ query–memory feedback pairs. In all three environments,
TokenWorth first screens up to $`K_{c}=12`$ memories and injects at most
one selected experience.

## Appendix C Generalization Beyond LifelongAgentBench

We evaluate online lifelong variants of
BigCodeBench \[[38](#bib.bib34)\] (code generation) and
ALFWorld \[[20](#bib.bib35)\] (text-based embodied decision making).
Each run starts without stored experience from benchmark tasks. Tasks
are processed sequentially, with retrieval using only preceding
experience. Memory is updated after the current task has been evaluated,
without access to future tasks. The language-model backbone remains
frozen throughout each run.

#### BigCodeBench.

We use BigCodeBench Full v0.1.4 in the Instruct format, comprising 1,140
coding problems. Each method makes a single pass through the same
deterministic sequence: the 992 problems in Full excluding Hard,
followed by the 148 problems in the Hard subset. Within these two
groups, we preserve the order of the pinned Full and Hard dataset files,
respectively; no random shuffling is applied. The memory bank is carried
across the two groups without resetting. For each problem, the agent
generates one solution, which is sanitized and evaluated using
BigCodeBench’s official execution-based evaluator inside a Docker
worker. A problem succeeds only when the evaluator returns pass;
generated-code failures and execution timeouts count as unsuccessful
outcomes. Evaluator infrastructure errors invalidate the run. We report
pass@1 over all 1,140 problems, counting each problem once. Memory is
updated after evaluation, and previously evaluated problems are not
revisited. The local deployment uses Qwen2.5-14B-Instruct. The API
deployment uses DeepSeek-V4-Flash with thinking explicitly disabled.
Both deployments use temperature zero. Reference solutions and unit
tests are excluded from the model’s memory and input prompts.

#### ALFWorld.

We use Qwen2.5-14B-Instruct as the frozen backbone, with temperature
zero and top-$`p`$ equal to one. A complete run contains 574 episodes:
300 training episodes selected by task-type-stratified sampling, all 140
validation-seen episodes, and all 134 validation-unseen episodes. The
phases run in this order. The base seed is 42; the sampling and ordering
routines use seeds 42, 43, and 44 for the three phases, respectively.
Within each phase, game paths are sorted, shuffled within task-type
groups using the phase seed, and selected by round-robin traversal of
the groups. The resulting ordered episode manifest is fixed and shared
across methods, and the runner checks that the environment follows this
order. Each selected episode is executed once. An episode succeeds when
TextWorld’s external won flag indicates task completion. The success
rate reported here is the total number of successful episodes divided by
574, including all three phases; it is not an unweighted average of
phase success rates. Memory persists across phase boundaries and is
updated after every completed episode, including validation-seen and
validation-unseen episodes. Thus, this is an online lifelong protocol
rather than evaluation with memory frozen after training. Expert
trajectories are excluded from memory.

#### Resource accounting.

We follow the resource-constrained evaluation principle in Sec. 3, using
benchmark-specific limits. Within each benchmark and deployment, methods
share the backbone, ordered task stream, solver-call output limit, and,
for ALFWorld, interaction controller. Memory contexts are bounded by the
complete injected block, including its headings and separators.
Injection lengths below are measured in *characters*. The two adapters
enforce output limits *per model call*, rather than pooling all calls
into a single per-task output allowance. Method-specific auxiliary
calls, including memory construction, reflection, and skill extraction,
have a separate limit of 512 output tokens per call. Their actual usage
is recorded in addition to solver usage, including action repairs in
ALFWorld. TokenWorth makes no auxiliary language-model calls.
Consequently, the methods share per-call limits but need not consume
equal total output tokens per task or episode.

#### BigCodeBench configuration.

The solver output limit is $`O_{\max}=1280`$ tokens per call for both
the local and API deployments. Auxiliary API calls have thinking
disabled. TokenWorth uses a memory capacity of $`B_{\max}=50`$ records,
injects at most $`K_{\max}=1`$ record, and caps the complete injection
block at $`L_{\max}=4096`$ characters. Each stored experience is also
capped at 4096 characters. BM25 recalls at most $`K_{c}=12`$ candidates
for learned worth ranking. All TokenWorth representation, learning, and
memory-management parameters are identical across the local and API
deployments; the solver output budget and thinking setting follow the
selected deployment.

#### ALFWorld configuration.

The interaction limit is $`J_{\max}=50`$ environment steps per episode.
Each action-generation call has an output limit of $`O_{\max}=128`$
tokens. An inadmissible action permits at most one repair call for that
step, also capped at 128 output tokens. These are per-call limits, not a
128-token allowance for the entire episode. The same action controller
is used for all methods, with memory-dependent loop removal disabled.
TokenWorth uses $`B_{\max}=128`$ records, $`K_{\max}=1`$, a complete
injection budget of $`L_{\max}=4200`$ characters, a per-experience limit
of 4096 characters, and a BM25 candidate pool of at most $`K_{c}=12`$.

#### Online learning configuration.

Both benchmarks use the same deterministic 512-dimensional hashing
representation of tokens and character 3–5-grams. Only a memory actually
injected into the agent receives outcome supervision. KRR and AGOP
updates are scheduled every 75 and 225 accumulated feedback examples,
respectively, with FIFO buffers of 128 and 256 examples. These counters
track feedback examples, not elapsed tasks or episodes. Each scheduled
residual fit requires at least four feedback examples; this minimum does
not trigger an immediate fit at the fourth example. Under these
settings, the first scheduled KRR fit occurs at feedback example 75. The
residual coefficient is $`\eta_{t}=0.10\min(1,u_{t}/3)`$, where
$`u_{t}`$ is the number of completed KRR fits: its influence ramps
linearly over the first three fits. KRR uses ridge regularization
$`0.01`$ and Laplacian-kernel scale $`1`$. AGOP uses smoothing $`0.25`$,
clips the updated diagonal metric to $`[0.05,8]`$, normalizes it to have
