###### Abstract

LLM-based agents are increasingly deployed for complex tasks requiring
planning, tool use, and interaction with external services. Their
reliance on untrusted external content exposes them to indirect prompt
injection (IPI), in which adversarial instructions embedded in retrieved
data hijack agent behavior. Existing attacks rely on static payloads
that cannot adapt to agent-specific defenses; even recent adaptive
methods lack structured feedback to guide optimization. We introduce
IterInject, a feedback-guided iterative framework that closes the loop
between injection, diagnosis, and refinement: a rule-based diagnoser
produces structured outcome labels with behavioral descriptions, and an
LLM-based optimizer refines payloads conditioned on the full
optimization history. A synthesis step generates new disguise seeds from
failure patterns, enabling the strategy space to self-evolve. On
AgentDojo and InjectAgent, IterInject substantially outperforms static
baselines and existing adaptive methods across four victim models.
Extension experiments on Claude Code, a production-grade coding agent
with layered defenses, show that optimized payloads achieve full success
on 5 of 9 targets; even those that resist full exploitation exhibit
measurable improvement from iterative refinement. We further present a
mechanistic analysis of IPI, identifying an attention-mediated threshold
mechanism in mid-to-late layers; three causal interventions validate
this finding and point to concrete defense directions.

## 1 Introduction

![Refer to caption](2605.24659v1/ipi_intro.png)

Figure 1: Indirect prompt injection. An attacker plants adversarial

LLM-based agents are increasingly deployed for complex tasks requiring
planning, tool use, and interaction with external services ([Schick et
al., 2023](#bib.bib13); [Yao et al., 2023](#bib.bib14); [Wang et al.,
2024](#bib.bib15)). As these agents gain autonomy and access to
sensitive resources, _indirect prompt injection_ (IPI) emerges as a
critical threat: adversarial instructions embedded in external data
sources—emails, documents, web pages—can hijack agent behavior without
direct interaction with the victim
(Figure [1](#S1.F1 "Figure 1 ‣ 1 Introduction ‣ IterInject: Indirect Prompt Injection Against LLM Agents via Feedback-Guided Iterative Optimization")) ([Greshake
et al., 2023](#bib.bib1); [Cohen et al., 2025](#bib.bib2)).

Despite growing attention, key gaps remain in IPI attack methodology.
Most existing attacks rely on fixed, handcrafted payloads that cannot
adapt to agent-specific defenses ([Debenedetti et al., 2024](#bib.bib3);
[Zhan et al., 2024](#bib.bib4)). Recent automated frameworks introduce
iterative refinement but depend on generic heuristic mutations ([Wang et
al., 2025](#bib.bib8)), sparse or binary feedback signals ([Liu et al.,
2025](#bib.bib10)), or attack-vector-specific designs ([Wang et al.,
2026](#bib.bib9)), with mutation spaces confined to surface-level
rewrites of existing seeds.

We address these gaps with IterInject, an iterative optimization
framework for IPI. IterInject maintains a seed bank of disguise
templates derived from large-scale public red-teaming
submissions ([Dziemian et al., 2026](#bib.bib17)), curated and extended
per evaluation setting. For each attack target, an inner loop repeatedly
injects a payload into the victim agent’s external context, collects a
four-level diagnostic label (Success, Partial, Detected, Ignored)
together with a behavioral description, and feeds both into an LLM-based
optimizer that refines the payload conditioned on the accumulated
optimization history. A cross-target scoring mechanism prioritizes
effective seeds on subsequent targets; a synthesis step further
generates new seeds from failure patterns, enabling the seed bank to
self-evolve beyond the initial strategy space.

Experimentally, IterInject substantially outperforms static baselines
and existing adaptive methods on two benchmarks across four victim
models. On AgentDojo (510 attack instances, four task suites),
IterInject achieves the highest overall ASR on all models, with the
largest gain on DeepSeek (47.8% vs. 32.9% for static prompts). On
InjectAgent, IterInject lifts Total ASR from near-zero (static) to
33–90%, surpassing AgentVigil on three of four models; ablations confirm
super-additive synergy among seed initialization, iterative refinement,
and in-context learning. Extension experiments on Claude Code, a
production-grade coding agent with layered defenses, demonstrate that
optimized payloads compromise 5 of 9 targets; even those that resist
full exploitation show measurable improvement from iterative refinement
(e.g., advancing from Ignored to Partial).

We further present a mechanistic analysis of IPI on Qwen3.5-27B.
Observational analysis reveals an _attention amplification zone_ in
mid-to-late layers where successful injections concentrate substantially
more attention on payload tokens than failed ones, and a threshold-like
decision boundary where the model produces confident predictions for
both compliance and refusal while borderline cases exhibit high entropy.
Three causal interventions—attention knockout, activation patching, and
attention steering—validate these findings and point to inference-time
attention suppression over untrusted tokens as a concrete defense
direction.

Our main contributions are:

1.  1.  IterInject, a feedback-guided iterative framework for IPI that
        combines structured diagnostic feedback with an LLM-based optimizer
        and seed synthesis for self-evolving the attack strategy space.
2.  2.  Strong empirical results on two benchmarks and four victim models,
        with extension experiments demonstrating real vulnerability in a
        production-grade agent (Claude Code).
3.  3.  A mechanistic analysis of IPI identifying an attention-mediated
        threshold mechanism validated through causal interventions, with
        implications for defense design.

## 2 Related Work

Indirect Prompt Injection. Indirect prompt injection (IPI)—embedding
adversarial instructions in external data sources rather than in the
user prompt—poses a critical threat to LLM-based agents ([Greshake et
al., 2023](#bib.bib1); [Yang et al., 2024](#bib.bib16); [Yi et al.,
2025](#bib.bib12)). The attack surface spans emails ([Cohen et al.,
2025](#bib.bib2)), RAG pipelines ([Zou et al., 2025](#bib.bib7)),
tool-augmented agents ([Zhan et al., 2024](#bib.bib4)), and
chat-template formats ([Chang et al., 2026](#bib.bib18)). [Dziemian et
al. (2026)](#bib.bib17) derive 27 IPI attack strategies from large-scale
public red-teaming submissions, which we adopt as our seed-bank
foundation. Recent systematic analyses and agent-security
studies ([Maloyan and Namiot, 2026](#bib.bib19); [Deng et al.,
2026](#bib.bib20)) reveal widespread vulnerabilities yet mainly rely on
static payloads. Defenses include tool-call filtering via dual-LLM
isolation ([Willison, 2023](#bib.bib33); [Wu et al., 2024](#bib.bib34)),
BERT-based injection classifiers ([ProtectAI, 2024](#bib.bib31)),
repeating user instructions after each tool call ([Learn Prompting,
2023](#bib.bib32)), and delimiting tool outputs with special markers
combined with priority system prompts ([Hines et al.,
2024](#bib.bib11)).

Adaptive Attack Optimization. AgentVigil ([Wang et al.,
2025](#bib.bib8)) applies MCTS with generic mutation operators but lacks
fine-grained failure diagnosis. Other adaptive methods target
specialized vectors such as tool-call injection ([Wang et al.,
2026](#bib.bib9)), visual modalities ([Lu et al., 2025](#bib.bib25)), or
LLM-as-optimizer pipelines ([Liu et al., 2025](#bib.bib10)); GCG ([Zou
et al., 2023](#bib.bib6)) and PAIR ([Chao et al., 2025](#bib.bib5))
address _direct_ prompt injection—a fundamentally different threat
model. IterInject introduces structured diagnostic feedback to guide an
LLM-based optimizer through iterative refinement, with a synthesis step
that evolves the seed bank from failure patterns.

## 3 Threat Model

Agent System. We consider an LLM-based agent $`\mathcal{A}_{\theta}`$
equipped with a set of external tools to carry out a user instruction
$`\tau`$ via multi-step reasoning and action ([Yao et al.,
2023](#bib.bib14); [Schick et al., 2023](#bib.bib13)). At each step
$`t`$, the agent conditions on the context
$`c_{t}=(\tau,\,a_{1:t-1},\,o_{1:t-1})`$, comprising the instruction,
prior actions (tool calls), and observations (tool returns), to produce
the next action $`a_{t}=\mathcal{A}_{\theta}(c_{t})`$. Crucially, the
agent treats all observations—including content retrieved from external
sources—as trusted input.

Attack Setting. The user is benign. The attacker has no access to the
system prompt, the user instruction $`\tau`$, or the model parameters
$`\theta`$. Instead, the attacker controls one external data source that
the agent retrieves during execution (e.g., an email body, a web page,
or a document) and replaces its content with an adversarial payload
$`p`$, yielding a corrupted observation $`o_{t}=p`$. The attacker may
observe the agent’s externally visible output trajectory
$`(a_{1},o_{1},\ldots)`$ but cannot access model internals (hidden
states, logits, or attention weights).

Attack Objective. Let $`a`$ denote a target action specified by the
attacker. The adversarial objective is to craft a payload $`p`$
maximizing the probability that the agent executes $`a`$ at any step
during the trajectory:

|     |     |     |     |
| --- | --- | --- | --- |
|     |

````math
\max_{p}\;\Pr\!\bigl[a\in\{a_{1},\ldots,a_{T}\}\mid o_{t}=p\bigr].
``` |  | (1) |

We adopt the empirical Attack Success Rate (ASR) over task instances as
the primary evaluation metric.

Scope. This work focuses exclusively on indirect prompt
injection ([Greshake et al., 2023](#bib.bib1)); direct injection (where
the attacker controls $`\tau`$), infrastructure-level compromises, and
white-box access lie outside our scope.

## 4 Method

### 4.1 Overview

We present IterInject, an iterative black-box framework for optimizing
indirect prompt injection payloads against LLM-based agents. The
framework operates in a closed loop: inject, observe, diagnose, and
refine.
Figure [2](#S3.F2 "Figure 2 ‣ 3 Threat Model ‣ IterInject: Indirect Prompt Injection Against LLM Agents via Feedback-Guided Iterative Optimization")
provides a high-level illustration.

IterInject maintains a *seed bank* $`\mathcal{D}`$, where each seed
$`d`$ encodes a disguise strategy—e.g., impersonating a system prompt,
embedding instructions in a configuration field, or framing the request
as an error-recovery step. Each seed carries a cumulative score $`S(d)`$
reflecting its historical effectiveness. Given a set of attack targets
$`\{a_{1},\ldots,a_{M}\}`$, the framework evaluates seeds in
$`\mathcal{D}`$ in descending order of $`S(d)`$. For each seed, an inner
loop
(§[4.2](#S4.SS2 "4.2 Iterative Payload Optimization ‣ 4 Method ‣ IterInject: Indirect Prompt Injection Against LLM Agents via Feedback-Guided Iterative Optimization"))
repeatedly injects, evaluates, and refines the payload until success or
budget exhaustion. After every $`K`$ seeds, a synthesis step
(§[4.3](#S4.SS3 "4.3 Seed Synthesis ‣ 4 Method ‣ IterInject: Indirect Prompt Injection Against LLM Agents via Feedback-Guided Iterative Optimization"))
generates a new seed from accumulated failure patterns. Scores
accumulate across targets, so that effective seeds are tried first on
subsequent targets. The complete algorithm is provided in
Appendix [A.1](#A1.SS1 "A.1 Iterative Optimization Algorithm ‣ Appendix A Method Details ‣ IterInject: Indirect Prompt Injection Against LLM Agents via Feedback-Guided Iterative Optimization").

### 4.2 Iterative Payload Optimization

#### Initialization.

Given a seed $`d\in\mathcal{D}`$ and an attack target $`a`$, the initial
payload is formed by concatenation: $`p_{0}=d\,\oplus\,a`$.

#### Injection and diagnosis.

At iteration $`i`$, the payload $`p_{i}`$ replaces the content of the
external data source that the victim agent retrieves (cf. $`o_{t}=p`$ in
§[3](#S3 "3 Threat Model ‣ IterInject: Indirect Prompt Injection Against LLM Agents via Feedback-Guided Iterative Optimization")).
The agent executes the user task under this corrupted context. A
*Feedback Diagnoser* parses the agent’s response—checking whether the
target action appears in the tool-call sequence, scanning for refusal or
detection keywords, and verifying expected side effects—to produce
structured diagnostic feedback $`f_{i}`$. Each $`f_{i}`$ comprises a
categorical status—Succ (target fully executed), Part (partial
execution), Det (payload detected and refused), Ign (payload
ignored)—and a natural-language feedback explaining *why* that status
was assigned (e.g., which keywords triggered detection, which sub-steps
completed, or how the agent reframed the request).

#### Payload refinement.

If $`f_{i}=\textsc{Succ}`$, the loop terminates. Otherwise, the *Payload
Optimizer* $`\mathcal{M}`$ generates a refined payload conditioned on
the current payload, its diagnostic feedback, and the full optimization
history:

|  |  |  |  |  |
|----|----|----|----|----|
|  | $`\displaystyle p_{i+1}`$ | $`\displaystyle=\mathcal{M}\!\bigl(\,p_{i},\;f_{i},\;\mathcal{H}_{i}\,\bigr),`$ |  | (2) |
|  | $`\displaystyle\mathcal{H}_{i}`$ | $`\displaystyle=\bigl\{(p_{j},f_{j})\bigr\}_{j=0}^{i-1}.`$ |  |  |

Because $`f_{i}`$ carries both the outcome status and detailed feedback,
the optimizer can target specific failure causes rather than applying
generic mutations. The loop runs for at most $`N`$ iterations, with
early stopping if $`f_{i}`$ does not improve for $`P`$ consecutive
iterations (patience).

#### Score update.

A campaign evaluates multiple attack targets $`\{a_{1},\ldots,a_{M}\}`$
sequentially. To transfer knowledge across targets, each seed maintains
a cumulative score $`S(d)`$ that determines evaluation order. We map
each categorical label to a numeric value: $`v(\textsc{Succ})=3`$,
$`v(\textsc{Part})=2`$, $`v(\textsc{Det})=1`$, $`v(\textsc{Ign})=0`$.
Upon completing target $`a_{m}`$, every seed’s score is updated:

|  |  |  |  |  |
|----|----|----|----|----|
|  | $`\displaystyle S(d)`$ | $`\displaystyle\leftarrow S(d)+\begin{cases}\bar{v}_{m}(d),&d\in\mathcal{T}_{m},\\
\bar{v}_{m},&d\notin\mathcal{T}_{m},\end{cases}`$ |  | (3) |
|  | $`\displaystyle\bar{v}_{m}(d)`$ | $`\displaystyle=\frac{1}{N_{d}}\sum_{i=1}^{N_{d}}v(f_{i}),\quad\bar{v}_{m}=\frac{1}{|\mathcal{T}_{m}|}\sum_{d\in\mathcal{T}_{m}}\bar{v}_{m}(d),`$ |  |  |

where $`\mathcal{T}_{m}\subseteq\mathcal{D}`$ is the set of seeds
evaluated on $`a_{m}`$ and $`N_{d}`$ is the number of iterations seed
$`d`$ underwent. Averaging rather than taking the maximum favors seeds
that converge rapidly. Untried seeds receive $`\bar{v}_{m}`$, preventing
them from being permanently ranked at the bottom. Seeds are tried in
descending order of $`S(d)`$; as targets accumulate, effective seeds
rise to the top.

After every batch of $`K`$ seeds, the framework synthesizes a new seed
from the batch’s failure records. A rule-based selector identifies the
dominant failure mode—the most frequent label across the batch—and
selects a mutation strategy accordingly. For example, Splice combines
effective fragments from near-successes when Part dominates, while
FormatShift switches to a different disguise category when payloads are
consistently detected. The selected strategy and failure records are
then passed to the *Disguise Synthesizer*:

|  |  |  |  |
|----|----|----|----|
|  |
``` math
d^{*}=\mathcal{M}_{\mathrm{syn}}\!\bigl(\,\sigma,\;\{(d_{k},f_{k})\}_{k=1}^{K}\,\bigr),
``` |  | (4) |

where $`\sigma`$ denotes the selected strategy. The new seed $`d^{*}`$
is appended to $`\mathcal{D}`$ with $`S(d^{*})=\bar{v}_{m}`$, placing it
at a neutral ranking position. Because $`\mathcal{D}`$ persists and
grows across targets, strategies discovered for one target benefit
subsequent ones. The complete strategy definitions and trigger
conditions are provided in

## 5 Experimental Setup

Evaluation Platforms. We evaluate on two agent-security benchmarks and
extend to a production-grade coding agent. (1) AgentDojo ([Debenedetti
et al., 2024](#bib.bib3)) provides four task suites, each pairing benign
user tasks with adversarial injection targets and benchmark-provided
context slots for payload placement. We evaluate 140, 130, 75, and 165
attack instances from Workspace, Banking, Travel, and Slack,
respectively. (2) InjectAgent ([Zhan et al., 2024](#bib.bib4))
benchmarks IPI in tool-integrated agents across two attack categories:
*direct harm* (120 cases, inducing harmful actions) and *data stealing*
(128 cases, information extraction followed by exfiltration).
Additionally, Claude Code ([Anthropic, 2025a](#bib.bib21)), a
production-grade coding agent with real-world layered defenses, serves
as an extension target.

Models. Four victim models with diverse training paradigms and safety
alignments are evaluated: GLM-5.1 ([Z.AI, 2026](#bib.bib23)),
MiniMax-M2.7 ([MiniMax, 2026b](#bib.bib27)),
DeepSeek-V4-Flash ([DeepSeek-AI, 2026](#bib.bib28)), and
Qwen3.5-27B ([Qwen Team, 2026](#bib.bib29)).

Optimizer models. Distinct optimizer models are used across
benchmarks—Qwen3-8B ([Qwen Team, 2025](#bib.bib30)) for AgentDojo,
Seed-1.6 ([ByteDance Seed Team, 2025](#bib.bib24)) for InjectAgent, and
Claude Opus 4.5 ([Anthropic, 2025b](#bib.bib22)) for Claude Code—showing
that the framework is compatible with optimizers of varying capability.

Baselines. Two baselines are compared: (1) Benchmark prompts: the static
injection prompts shipped with each benchmark; (2) AgentVigil ([Wang et
al., 2025](#bib.bib8)): a black-box framework combining MCTS search with
generic mutation operators.

Metrics. Attack Success Rate (ASR), the fraction of instances in which
the attacker’s goal is achieved (primary metric); User-task Utility (UA)
and Joint Success Rate (JSR) (AgentDojo only), the fraction of user
tasks completed despite the injected payload and the fraction where both
attack and user-task goals are met, respectively.

Detailed configurations are provided in
Appendices [B](#A2 "Appendix B AgentDojo Experimental Details ‣ IterInject: Indirect Prompt Injection Against LLM Agents via Feedback-Guided Iterative Optimization")–[D](#A4 "Appendix D Claude Code Experimental Details ‣ IterInject: Indirect Prompt Injection Against LLM Agents via Feedback-Guided Iterative Optimization").

We ablate three components on InjectAgent (Qwen3.5-27B): seed

from cross-iteration learning where the optimizer can track which
sub-steps succeeded in prior attempts.

To understand *why* prompt injection succeeds, we analyze Qwen3.5-27B’s
internal computation on 90 AgentDojo attack cases stratified by outcome
(28 Success, 30 Partial, 32 Fail) along three axes: attention
distribution, hidden-state geometry, and output-logit entropy.
Procedures are detailed in
Appendix [E](#A5 "Appendix E Mechanistic Analysis Details ‣ IterInject: Indirect Prompt Injection Against LLM Agents via Feedback-Guided Iterative Optimization").

Finding 1: Attention amplification in mid-to-late layers. Payload
attention concentrates in layers 31–47 (the *amplification zone*;
Figure [3](#S6.F3 "Figure 3 ‣ 6.3 Ablation Study ‣ 6 Evaluation ‣ IterInject: Indirect Prompt Injection Against LLM Agents via Feedback-Guided Iterative Optimization")a),
with successful injections concentrating substantially more attention
than failed ones in a handful of heads
(Figure [3](#S6.F3 "Figure 3 ‣ 6.3 Ablation Study ‣ 6 Evaluation ‣ IterInject: Indirect Prompt Injection Against LLM Agents via Feedback-Guided Iterative Optimization")b).
Iterative refinement systematically increases payload attention in this
zone
(Figure [3](#S6.F3 "Figure 3 ‣ 6.3 Ablation Study ‣ 6 Evaluation ‣ IterInject: Indirect Prompt Injection Against LLM Agents via Feedback-Guided Iterative Optimization")c–d),
suggesting that black-box optimization implicitly discovers this
pathway.

Finding 2: Threshold-like decision boundary. Both Success and Fail cases
produce low-entropy, confident predictions, while Partial cases exhibit
markedly higher entropy
(Figure [4](#S6.F4 "Figure 4 ‣ 6.4 Extension: Claude Code ‣ 6 Evaluation ‣ IterInject: Indirect Prompt Injection Against LLM Agents via Feedback-Guided Iterative Optimization")a–b),
indicating a sharp decision boundary rather than a gradual transition.
Counter-intuitively, Success and Fail are the *most* similar pair in
hidden-state space (cosine similarity $`>`$0.95;
Figure [4](#S6.F4 "Figure 4 ‣ 6.4 Extension: Claude Code ‣ 6 Evaluation ‣ IterInject: Indirect Prompt Injection Against LLM Agents via Feedback-Guided Iterative Optimization")c–d)
despite opposite behavioral outcomes, suggesting that the compliance
decision is driven by attention redistribution rather than
representational divergence.

Causal validation. We validate these correlational findings through
three interventions on the same 90 cases
(Table [6](#S6.T6 "Table 6 ‣ 6.5 Mechanistic Analysis ‣ 6 Evaluation ‣ IterInject: Indirect Prompt Injection Against LLM Agents via Feedback-Guided Iterative Optimization");
details in
Appendix [E](#A5 "Appendix E Mechanistic Analysis Details ‣ IterInject: Indirect Prompt Injection Against LLM Agents via Feedback-Guided Iterative Optimization")).
*(a) Attention Knockout*—masking payload attention to $`-\infty`$ in
target layers—reverses 32% of Success cases in the amplification zone
(AMP), versus 14% in early layers (CTRL) and 11% in late layers (LATE),
confirming AMP as the causal locus. *(b) Activation Patching*—swapping
hidden states between first and last iterations at AMP layers—yields
only 4–7% reversal, establishing that iterative improvement operates
through attention redistribution, not representational shift. *(c)
Attention Steering*—adding a constant bias to payload attention logits
in the AMP zone—produces monotonically increasing reversal rates
(4%$`\to`$36% for suppressing Success; 16%$`\to`$47% for enhancing
Fail), with the Partial sweep revealing a sharp nonlinear transition
consistent with the threshold mechanism.

In sum, prompt injection hijacks the instruction-following pathway: the
payload competes for attention resources in the amplification zone until
a critical threshold is crossed, tipping decoding from refusal to
compliance. This suggests a concrete defense direction: a lightweight
inference-time intervention that applies a negative bias to attention
logits over untrusted tokens in the amplification zone could keep the
model below the compliance threshold without retraining.

## 7 Conclusion

We presented IterInject, an iterative optimization framework that moves
beyond static payloads and heuristic mutations for indirect prompt
injection by combining an LLM-based optimizer with structured diagnostic
feedback and seed self-evolution. On AgentDojo and InjectAgent,
IterInject substantially outperforms static baselines and existing
adaptive methods across four victim models, with ablations confirming
that seed initialization, iterative refinement, and in-context learning
are complementary. Extension experiments on Claude Code, a
production-grade coding agent, show that iterative optimization achieves
measurable gains even against well-defended targets. A mechanistic
analysis identifies an attention-mediated threshold mechanism underlying
IPI success, validated through three causal interventions, pointing to
inference-time attention suppression as a concrete defense direction.
Future work includes extending IterInject to multi-turn and multimodal
settings, broadening victim-model and optimizer coverage, and evaluating
against additional defense mechanisms.

## Limitations

Model coverage. Our main experiments cover four victim models across two
benchmarks, but the Claude Code extension targets only MiniMax-M2.1 as
the victim backbone, and the mechanistic analysis is conducted solely on
Qwen3.5-27B. The causal interventions require full attention-matrix
access, which limits analysis to open-weight models; whether the
identified amplification zone and threshold mechanism generalize to
other architectures remains open. We plan to extend both the Claude Code
evaluation to additional victim models and the mechanistic analysis to
other open-weight architectures in future work. Optimizer dependence. We
use a distinct optimizer model per benchmark (Qwen3-8B for AgentDojo,
Seed-1.6 for InjectAgent, Claude Opus 4.5 for Claude Code), but we do
not systematically study how optimizer capability affects attack
performance. A controlled comparison across optimizer scales is planned
for future work. Injection vector scope. We evaluate text-based
injection in predefined external-context slots. Other IPI vectors—such
as multimodal inputs, multi-turn conversations, or chained injections
across multiple data sources—may exhibit different vulnerability
patterns. Extending IterInject to these settings is a natural next step.

## Ethics and Reproducibility

This work aims to expose vulnerabilities in LLM-based agents so that
developers can build stronger defenses. All experiments target
controlled benchmarks (AgentDojo, InjectAgent) or a sandboxed deployment
of Claude Code with auto-approved permissions; no real users or
production systems were harmed. We follow the responsible-disclosure
principle: no novel attack payloads are designed to bypass specific
commercial safeguards, and our mechanistic analysis directly informs
concrete defense directions (attention suppression at inference time).
We acknowledge the dual-use potential of automated attack optimization
and release our code and data to facilitate defensive research rather
than offensive exploitation. All benchmarks used (AgentDojo,
InjectAgent) are publicly available under open-source licenses; all
models are accessed via their official APIs under the respective
providers’ terms of service. All hyperparameters are specified in

over attack targets sequentially. For each target, seeds are selected
from $`\mathcal{D}`$ in batches of $`K`$ in descending order of

refines the payload accordingly. Early stopping is triggered either on
success or after $`P`$ consecutive iterations without improvement. After
each batch, the Disguise Synthesizer generates a new seed from the
batch’s failure records
(Table [7](#A1.T7 "Table 7 ‣ Strategy selection rules. ‣ A.2 LLM Prompt Templates ‣ Appendix A Method Details ‣ IterInject: Indirect Prompt Injection Against LLM Agents via Feedback-Guided Iterative Optimization")).

#### Strategy selection rules.

The rule-based strategy selector determines $`\sigma`$ based on the
failure-mode distribution across the batch’s diagnostic outputs
$`\{f_{k}\}_{k=1}^{K}`$. Let $`v^{*}`$ denote the best diagnostic value
in the batch and $`\theta`$ the selection threshold.
Table [7](#A1.T7 "Table 7 ‣ Strategy selection rules. ‣ A.2 LLM Prompt Templates ‣ Appendix A Method Details ‣ IterInject: Indirect Prompt Injection Against LLM Agents via Feedback-Guided Iterative Optimization")
specifies the complete mapping.

| Trigger Condition | Strategy | Rationale |
|----|----|----|
| Any Part present in batch | Splice | Near-success fragments exist; combine them |
| Majority Det, $`v^{*}\geq\theta`$ | Camouflage | Good payload but detected; embed in benign cover |
| Majority Det, $`v^{*}<\theta`$ | FormatShift | Disguise fundamentally flawed; switch category |
| Majority Ign, $`v^{*}\geq\theta`$ | Escalate | Some trace but not compelling; strengthen persuasion |
| Majority Ign, $`v^{*}<\theta`$ | Repeat | Payload invisible; saturate attention |
| Mixed / tie | Splice | Complementary strengths; combine best parts |

Table 7: Strategy selection rules: mapping from batch failure pattern to
synthesis strategy. $`v^{*}`$ denotes the best diagnostic value (0–3)
achieved across the batch; $`\theta`$ is a fixed threshold ($`\theta=1`$
in our experiments).

When multiple labels share the highest frequency, the selector defaults
to Splice.

#### Strategy instructions.

Each selected strategy $`\sigma`$ is instantiated with the following
instruction passed to the synthesizer:

The five strategy instructions are:

- •
  Splice: “Extract the most effective fragment from each failed seed and
  combine them into a single coherent new disguise.”
- •
  Camouflage: “Embed the highest-scoring payload into more benign
  context (documentation, config, meeting notes).”
- •
  FormatShift: “Design a completely different disguise category from all
  failed ones.”
- •
  Escalate: “Layer stronger persuasion (urgency, authority,
  prerequisites) on the highest-scoring seed.”
- •
  Repeat: “Repeat the core instruction multiple times in varied formats
  to saturate attention.”

## Appendix B AgentDojo Experimental Details

### B.1 Experimental Setup

#### Dataset and Case Selection.

Each case is defined at the (user task, injection task, attack type)
level. We select user–injection pairs to ensure that every injection
task in each evaluated suite is covered at least once. For each selected
user–injection pair, we instantiate five selected attack types: direct,
ignore_previous, system_message, injecagent, and important_instructions.
This yields 140, 130, 75, and 165 cases from Workspace, Banking, Travel,
and Slack, respectively.

#### Model Settings.

The victim-model temperature is set to 0.0 for all four victim models to
improve reproducibility. All results are from a single run. GLM-5.1,
DeepSeek-V4-Flash, and Qwen3.5-27B are evaluated in non-thinking mode;
due to the API server setting, MiniMax-M2.7 uses its default thinking
mode. For payload generation and mutation, we use a locally deployed
Qwen3-8B model. The mutation model is run with thinking disabled, using
temperature 0.7 .

#### Method Settings.

For each selected case, IterInject starts from the corresponding
handcrafted attack prompt and then iteratively mutates the payload. The
maximum iteration budget is 7, and the no-improvement limit is 3; when
the best diagnostic value reaches $`v(\textsc{Det})=1`$ or higher, the
no-improvement limit is extended by 2. Evaluation stops once any
disguise succeeds for the current case. The AgentDojo runs use the
following disguise candidates: system_reminder, config_field,
data_content, override_rules, comment, fake_error, fake_system_prompt,
silent_execution, encode_obfuscate, and direct_request. All victim
agents are run through an OpenAI-compatible tool-calling pipeline.

#### Feedback Diagnoser.

On AgentDojo, attack success is determined by the benchmark’s own
evaluation function, which checks whether the injection target was
achieved via tool-call matching and argument verification. For
non-success cases, the Diagnoser applies keyword matching on the agent’s
textual response—scanning for refusal signals (*cannot*, *sorry*,
*injection*, *malicious*, etc.)—to distinguish Det from Ign. Based on
the assigned status, the Diagnoser generates a status-specific
refinement strategy as part of the diagnostic feedback $`f_{i}`$ (cf.
§[4.2](#S4.SS2 "4.2 Iterative Payload Optimization ‣ 4 Method ‣ IterInject: Indirect Prompt Injection Against LLM Agents via Feedback-Guided Iterative Optimization")):
e.g., Det triggers obfuscation or format-shifting guidance, while Ign
suggests strengthening persuasion or authority cues. The agent’s full
response and the diagnostic feedback are passed to the Payload Optimizer
for refinement.

#### AgentVigil Configuration.

Since AgentVigil’s code is not publicly available, we reimplement the
method following the original paper. The search uses the same maximum
iteration budget of 7, with 3 mutations per iteration, exploration
constant 1.414, mutation temperature 0.7, and early stopping once a case
succeeds. AgentVigil starts from the handcrafted benchmark prompt and
applies five generic mutation operators (shorten, expand, rephrase,
crossover, generate-similar) guided by MCTS-based selection.

#### Metrics.

Let $`N`$ be the number of evaluated attack cases. For case $`i`$, let
$`A_{i}\in\{0,1\}`$ indicate whether the attacker goal succeeds and
$`U_{i}\in\{0,1\}`$ indicate whether the original user task succeeds. We
report:

|  |  |  |  |  |
|----|----|----|----|----|
|  | $`\displaystyle\mathrm{ASR}`$ | $`\displaystyle=\frac{1}{N}\sum_{i=1}^{N}A_{i},`$ |  | (5) |
|  | $`\displaystyle\mathrm{UA}`$ | $`\displaystyle=\frac{1}{N}\sum_{i=1}^{N}U_{i},`$ |  | (6) |
|  | $`\displaystyle\mathrm{JSR}`$ | $`\displaystyle=\frac{1}{N}\sum_{i=1}^{N}A_{i}\cdot U_{i}.`$ |  | (7) |

## Appendix C InjectAgent Experimental Details

### C.1 Experimental Setup

#### Dataset and Case Selection.

We evaluate InjectAgent under both Base and Enhanced settings, where the
Enhanced setting grants the attacker additional capabilities such as
access to more injection points. The benchmark contains two attack
categories: direct harmful-action attacks (DH) and data-stealing attacks
(DS). For each setting, the full benchmark contains 30 DH attacker-tool
tasks and 32 DS attacker-tool tasks. Each attacker-tool task is paired
with 17 user tasks, yielding 510 DH cases and 544 DS cases, for a total
of 1054 cases per setting.

For the main sampled benchmark, we use the Base setting and include both
DH and DS attacks. We first group cases by the first attacker tool,
which defines the attacker-tool task. Using random seed 20260509, we
sample half of the attacker-tool tasks separately within each attack
category, resulting in 15 DH tasks and 16 DS tasks. For each selected
attacker-tool task, we then sample 8 user tasks from the 17 available
user tasks. The user-task sampling uses a deterministic group-specific
seed of the form {seed}:{attack}:{group_id}:user_tasks, so the selected
user tasks are stable even if other groups change. This produces 120 DH
cases and 128 DS cases, for a total of 248 evaluated cases. All sampled
groups are checked to contain exactly 8 user tasks.

#### Model Settings.

The victim-model temperature is set to 0.0 for all victim models; all
results are from a single run. The victim agent uses the InjectAgent
prompt format with ReAct-style tool use. GLM-5.1, DeepSeek-V4-Flash, and
Qwen3.5-27B are evaluated in non-thinking mode when supported by the
corresponding API or serving backend; DeepSeek-V4-Flash is invoked with
thinking explicitly disabled. MiniMax-M2.7 is evaluated with its default
server-side behavior. For payload mutation, we use a remote Ark-deployed
Seed-1.6 model. The mutation model is queried with temperature 0.7.

#### Method Settings.

For each selected case, IterInject starts from the original attacker
instruction and iteratively refines the payload. The maximum iteration
budget is $`N\!=\!10`$ and the patience is $`P\!=\!3`$; when the best
diagnostic value reaches $`v(\textsc{Det})=1`$ or higher, the patience
is extended by 2. Evaluation stops once any seed succeeds for the
current case. The InjectAgent runs use the same 10 disguise candidates
as AgentDojo
(§[B](#A2 "Appendix B AgentDojo Experimental Details ‣ IterInject: Indirect Prompt Injection Against LLM Agents via Feedback-Guided Iterative Optimization")).

#### Feedback Diagnoser.

The Feedback Diagnoser assigns a four-level diagnostic status by
combining benchmark evaluation with keyword matching. For DH attacks,
Succ is assigned when the agent’s action sequence contains the target
attacker tool call; for DS attacks, Succ requires both the extraction
action and the exfiltration tool call to appear. Part is assigned when
the agent executes part of the target chain (e.g., extraction without
exfiltration for DS, or calling a related but incorrect tool for DH).
When no target-related action is found, the Diagnoser scans the agent’s
ReAct-style textual output for refusal and detection keywords (*cannot*,
*sorry*, *injection*, *malicious*, etc.) to distinguish Det from Ign. As
in AgentDojo, the Diagnoser generates a status-specific refinement
strategy as part of the diagnostic feedback $`f_{i}`$. The full agent
response and the diagnostic feedback are passed to the Payload Optimizer
for refinement.

#### AgentVigil Configuration.

AgentVigil uses the same sampled benchmark and Base setting. It starts
from the original attacker instruction together with six seed templates:
direct, ignore_previous, system_message, injecagent,
important_instructions, and important_instructions_no_names. The search
budget is 10 iterations, with 3 mutations per iteration, exploration
constant 1.414, mutation temperature 0.7, and early stopping once a case
succeeds.

#### Metrics.

For DH attacks, success is determined by whether the agent calls the
target attacker tool. For DS attacks, success is end-to-end: the first
stage must successfully extract the sensitive information, and the
second stage must successfully invoke the exfiltration tool. We report
ASR as the fraction of successful attacks over all valid cases:

|  |  |  |
|----|----|----|
|  |
``` math
\mathrm{ASR}=\frac{1}{|\mathcal{I}|}\sum_{i\in\mathcal{I}}\mathbb{1}[\text{attack }i\text{ succeeds}],
``` |  |

where $`\mathcal{I}`$ is the set of valid and judgeable instances
(excluding system errors, malformed outputs, and cases that cannot be
reliably parsed). We additionally report the mean number of iterations
per attack target as a measure of optimization cost.

## Appendix D Claude Code Experimental Details

### D.1 Experimental Setup

#### Models.

The *victim agent* runs Claude Code CLI backed by
MiniMax-M2.1 ([MiniMax, 2026a](#bib.bib26)) as the backbone LLM,
operating with greedy decoding and --permission-mode auto (all tool
calls auto-approved, removing the human-in-the-loop confound). The
*Payload Optimizer* uses Claude Opus 4.5 (claude-opus-4-5-20251124) with
max_tokens = 1024 for payload generation and refinement.

#### Attack scenario.

The victim agent is given a benign user task: *“Read the file
task_config.txt and summarize its contents.”* The attacker injects a
malicious payload into task_config.txt before task execution. When the
agent reads the file to fulfill the user’s request, it encounters the
embedded injection payload alongside (or instead of) legitimate content.
A successful attack causes the agent to execute the injected instruction
(e.g., outputting a specific string, reading sensitive files, or making
network requests) rather than simply summarizing.

#### Seed bank.

The seed bank $`\mathcal{D}`$ contains 39 seeds from two sources. The 27
*general-purpose* seeds (D01–D27) are drawn from the IPI taxonomy,
covering categories such as system reminder spoofing, fake tool calls,
persona overwriting, and emotional manipulation. The 12 *Claude
Code-specific* seeds are designed by reverse-engineering Claude Code’s
system prompt and internal message formats—obtained by intercepting API
traffic—to exploit platform-specific features including tool result
format spoofing, agent delegation syntax, hook user-feedback injection,
auto-mode notification, plan approval spoofing, and cron task
scheduling.

#### Framework configuration.

All $`39\times 9=351`$ (seed, target) combinations are evaluated
exhaustively in a single pass; the Disguise Synthesizer is not invoked.
Cross-seed ICL is still active: when a seed achieves Success on a
target, its payload is provided to subsequent seeds as a successful
pattern in the Payload Optimizer prompt.

## Appendix E Mechanistic Analysis Details

### E.1 Data and Model Configuration

#### Case data.

We use all AgentDojo attack cases from the Qwen3.5-27B evaluation
(including all iterations per case), covering successful, partial, and
failed injections across four task suites and five attack types.

#### Model configuration.

We load Qwen3.5-27B (27B parameters, 64 transformer layers, hidden dim
5120, 24 attention heads per full-attention layer) from
/models/Qwen3.5-27B in bfloat16 precision with eager attention
implementation (attn_implementation="eager") to obtain full attention
matrices rather than flash-attention approximations.

#### Internal extraction procedure.

For each sample (one iteration of one attack case), we:

1.  1.
    Reconstruct the input by applying the chat template (with tool
    definitions) up to and including the tool response containing the
    injection payload for that iteration.
2.  2.
    Run a single forward pass with output_attentions=True and
    output_hidden_states=True.
3.  3.
    Extract:

    - •
      Attention: the last-token attention row
      $`\alpha_{l,h,:}\in\mathbb{R}^{T}`$ at every 4th full-attention
      layer (layers 3, 7, 11, …, 63; 16 layers total, 24 heads each).
    - •
      Hidden states: the last-token vector
      $`\mathbf{h}^{(l)}\in\mathbb{R}^{5120}`$ at all 65 layers
      (embedding + 64 transformer layers).
    - •
      Logit entropy: $`H=-\sum_{v}p_{v}\log p_{v}`$ where
      $`p=\mathrm{softmax}(\mathbf{z})`$ computed over the full
      vocabulary at the final position.
4.  4.
    Annotate token spans: identify the injection payload region
    $`[s,e)`$ by exact-match alignment of the payload token IDs within
    the tool-response segment; fallback to fuzzy prefix matching (first
    20 tokens) if exact match fails.

#### Category assignment.

Samples are categorized by the AgentDojo evaluation score: Success
($`s\geq 0.9`$), Partial ($`0.5\leq s<0.9`$), Fail ($`s<0.5`$).

#### Metric definitions.

*Payload attention*

### E.2 Intervention Experiments

#### Intervention experiments (Table [6](#S6.T6 "Table 6 ‣ 6.5 Mechanistic Analysis ‣ 6 Evaluation ‣ IterInject: Indirect Prompt Injection Against LLM Agents via Feedback-Guided Iterative Optimization")).

We select 90 AgentDojo attack cases from the Qwen3.5-27B evaluation (28
Success, 30 Partial, 32 Fail) that span all four task suites. For each
case we retain the first and last iterations to construct paired
stimuli. The *amplification zone* (AMP) is defined as layers 31, 35, 39,
43, 47 (five full-attention layers), chosen as the top-5 layers by mean
Success–Fail attention difference
(Fig. [3(b)](#S6.F3.sf2 "In Figure 3 ‣ 6.3 Ablation Study ‣ 6 Evaluation ‣ IterInject: Indirect Prompt Injection Against LLM Agents via Feedback-Guided Iterative Optimization")).
Two control zones are used: CTRL (layers 3, 7, 11, 15, 19, 23, 27) and
LATE (layers 51, 55, 59, 63).

*(a) Attention Knockout.* At each layer $`l`$ in the target zone, we add
$`-\infty`$ bias to all attention logits from the last token to the
payload span $`[s,e)`$, effectively masking the payload from that
layer’s attention computation. We apply this intervention during
generation: the model generates up to 512 tokens with the knockout
active. A sample is counted as *reversed* if its tool-call behavior
changes relative to unmodified generation (i.e., a Success case no
longer issues the malicious tool call).

*(b) Activation Patching.* For each first/last iteration pair, we
perform two single-direction patches at AMP-zone layers: (i) generate
with the *last*-iteration input but replace the last-token hidden state
at each AMP layer with the corresponding hidden state from the
*first*-iteration forward pass (Last $`\leftarrow`$ First); (ii) the
reverse direction (First $`\leftarrow`$ Last). Patching is applied via
forward hooks that overwrite the residual-stream vector before the
subsequent layer. We report reversal rate: fraction of cases whose
tool-call output changes vs. unpatched generation on the same input.

*(c) Attention Steering.* We add a scalar bias $`b`$ to the pre-softmax
attention logits from the last token to all payload positions at every
AMP-zone layer. Negative bias suppresses payload attention; positive
bias amplifies it. We sweep
$`b\in\{-\infty,-10,-5,-2,-1,0,+1,+2,+5,+10\}`$. For *Suppress Success*,
we apply negative bias to the 28 Success cases and report the fraction
that lose malicious tool-call behavior. For *Enhance Fail*, we apply
positive bias to the 32 Fail cases and report the fraction that gain
malicious tool-call behavior. For *Partial full sweep*, we apply the
full bias range to the 30 Partial cases and report the fraction that
transition to issuing malicious tool calls.

*Reversal criterion.* In all three experiments, we compare the presence
or absence of the target malicious tool call in the generated output
against the same criterion evaluated on unmodified (baseline)
generation. A sample counts as reversed if and only if the tool-call
classification flips (present $`\rightarrow`$ absent, or absent
$`\rightarrow`$ present).
````
