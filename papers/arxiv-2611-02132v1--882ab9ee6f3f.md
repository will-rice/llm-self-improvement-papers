# TSSDA: An Autonomous Agent for Constructing a Time-Series Text-to-SQL Benchmark

Zhihan Zheng Affiliation: Tsinghua University, China email:

University, China email: <sxsong@tsinghua.edu.cn> , Haitao Yuan
Affiliation: NTU, Singapore email: <haitao.yuan@ntu.edu.sg> and Minxiao
Chen Affiliation: BUPT, China email: <chenminxiao@bupt.edu.cn>

###### Abstract.

As agents increasingly undertake data querying, Text-to-SQL serves as a
foundational capability for database access. However, for text-to-SQL in
time-series databases, high-quality benchmarks and large-scale training
corpora remain scarce, limiting the systematic evaluation and domain
adaptation of existing models and agents. Existing automated SQL
generation approaches lack sufficient autonomy, leaving key challenges
unresolved. First, numerous combinations of temporal syntax and
functions complicate comprehensive coverage of valid queries. Second, as
the corpus grows, generating valuable and diverse new data becomes
increasingly challenging. Third, schema and data heterogeneity hinder
reuse of temporal query structures, limiting generation efficiency. To
address these challenges, we propose TSSDA, a Time-Series SQL (TSSQL)
Generation Data Agent framework, and construct TERN, a comprehensive
Time-sERies text-to-SQL beNchmark. First, to achieve broad coverage of
valid queries, we systematically model TSSQL syntax and semantics to
construct a data generation space. Next, to explore the space and
improve diversity, we develop a Data Agent that autonomously
orchestrates data generation. The agent comprises a planning and
decision-making module and a query generation module, with online
adaptation for continuous self-improvement. Finally, we introduce a
temporal-aware memory that enables adaptive reuse of experience across
heterogeneous data instances, improving generation efficiency.
Comprehensive evaluations on TERN reveal the limitations of existing
methods in performing Text-to-TSSQL tasks. Furthermore, extensive
experiments demonstrate that TSSDA substantially improves coverage,
diversity, and complexity.

## 1. Introduction

![Refer to caption](2611.02132v1/intro.png)

Figure 1. Challenges of Text-to-SQL for TSDBs

With advances in large language models (LLMs), agents increasingly
undertake data querying ([Zhu et al., 2025a](#bib.bib78); [Cao et al.,
2026](#bib.bib79)) and processing ([Fan et al., 2025](#bib.bib62);
[Jiang et al., 2025](#bib.bib61)) tasks. Text-to-SQL, which translates
natural language requests into SQL queries, is becoming a foundational
capability for these agents ([Katsogiannis-Meimarakis and Koutrika,
2023](#bib.bib53); [Luo et al., 2025](#bib.bib54)). Numerous
approaches ([Xie et al., 2025](#bib.bib22); [Li et al.,
2025a](#bib.bib4); [Li et al., 2026](#bib.bib21)) have emerged,
alongside increasingly challenging benchmarks ([Koukouvinis et al.,
2026](#bib.bib39); [Deng et al., 2026](#bib.bib7); [Lei et al.,
2025](#bib.bib16)). However, existing studies primarily focus on
relational databases, leaving Text-to-SQL for time-series databases
(TSDBs) largely underexplored.

SQL in TSDBs differs fundamentally from conventional SQL in both query
semantics and language constructs. As shown in
Fig. [1](#S1.F1 "Figure 1 ‣ 1. Introduction ‣ TSSDA: An Autonomous Agent for Constructing a Time-Series Text-to-SQL Benchmark")(a),
we highlight several distinctive features of time-series SQL (TSSQL).
First, TSDBs support diverse time-series-specific syntax, including
temporal windows, missing-value filling, and result alignment, as
illustrated in the example. Second, TSSQL often composes multiple
functions and operators for complex temporal analytics. The example
detects absolute wind-speed changes exceeding 5 between consecutive
valid readings, while real-world queries may be more complex. Third,
TSDBs exhibit diverse schema organizations and are tightly coupled with
time-series syntax. For example, we illustrate IoTDB’s schema ([Wang et
al., 2023](#bib.bib1)) with a query aggregating matching OBD sensor
readings by vehicle in Brooklyn. Beyond SQL structure, time-series
queries also embody rich and distinctive temporal semantics.
Consequently, existing Text-to-SQL methods designed for relational
databases are inapplicable to TSDBs.

To comprehensively evaluate Text-to-SQL for TSDBs and provide a
domain-specific training corpus, there is a pressing need for a
high-quality, large-scale benchmark. Although recent efforts ([Dranca et
al., 2026](#bib.bib3); [Lyu et al., 2026](#bib.bib55)) have made initial
attempts, they often rely on manual curation or direct prompting,
limiting data coverage, diversity, and scalability. Driven by recent
developments in agentic AI, data agents ([Zhu et al.,
2025b](#bib.bib25)) have emerged as a promising paradigm for
autonomously handling complex data tasks. However, existing data agents
primarily focus on managing ([Li et al., 2025c](#bib.bib58)),
preparing ([Fan et al., 2025](#bib.bib62); [Fan et al.,
2026](#bib.bib59)), and analyzing ([Jiang et al., 2025](#bib.bib61);
[Tang et al., 2025](#bib.bib60)) existing data, with limited attention
to the autonomous generation of domain-specific data, such as NL–TSSQL
pairs. Unlike general-purpose data generation, TSSQL data generation is
subject to strict syntactic and semantic constraints, demanding higher
data quality. Meanwhile, existing LLM- and agent-based Text-to-SQL data
generation approaches ([Koukouvinis et al., 2026](#bib.bib39); [Deng et
al., 2026](#bib.bib7); [Li et al., 2025a](#bib.bib4); [Li et al.,
2025b](#bib.bib8)) lack sufficient autonomy for generating NL–TSSQL
pairs, leaving several key challenges unresolved:

Challenge 1: Modeling Valid Compositions in TSSQL. TSSQL introduces a
variety of specialized temporal syntax and numerous time-series
functions. As shown in
Fig. [1](#S1.F1 "Figure 1 ‣ 1. Introduction ‣ TSSDA: An Autonomous Agent for Constructing a Time-Series Text-to-SQL Benchmark")(b),
directly taking the Cartesian product leads to a combinatorial
explosion, while only a small subset is syntactically valid,
semantically meaningful, and compatible with the schema instance.
Existing manually constructed datasets ([Li et al., 2023](#bib.bib12);
[Lei et al., 2025](#bib.bib16); [Lyu et al., 2026](#bib.bib55)) require
experts or annotators, which are costly and difficult to scale, while
automated approaches primarily rely on instance
transformation ([Koukouvinis et al., 2026](#bib.bib39); [Sarwar et al.,
2026](#bib.bib9)), template instantiation ([Zhang et al.,
2023](#bib.bib15); [Deng et al., 2026](#bib.bib7)), or
instruction-guided synthesis ([Dranca et al., 2026](#bib.bib3); [Li et
al., 2025a](#bib.bib4); [Li et al., 2025b](#bib.bib8)). Instance- and
template-based methods constrain generation to predefined structural
neighborhoods, whereas instruction-guided methods are highly sensitive
to the quality of manually specified task requirements and constraints,
leaving query validity largely dependent on LLM reasoning and post-hoc
verification. Consequently, existing approaches lack systematic modeling
of valid SQL compositions, limiting both coverage and validity.

Challenge 2: Autonomous Orchestration for TSSQL Diversity. Data
generation is inherently dynamic: as the corpus evolves, the utility of
new data changes with the knowledge and characteristics represented in
the generated data. A key challenge is therefore to determine what is
most valuable to explore among numerous valid candidates at each
generation step to enhance data diversity. As shown in
Fig. [1](#S1.F1 "Figure 1 ‣ 1. Introduction ‣ TSSDA: An Autonomous Agent for Constructing a Time-Series Text-to-SQL Benchmark")(c),
existing agent-based approaches ([Li et al., 2025b](#bib.bib8); [Gao et
al., 2026](#bib.bib18); [Sullutrone et al., 2026](#bib.bib19)) introduce
multi-agent collaboration and environmental interaction, yet their
agents are typically embedded in predefined generation pipelines, with
autonomy largely confined to executing or coarsely selecting among
predefined procedures such as generation, expansion, and validation.
Such coarse-grained autonomy lacks fine-grained control over the
characteristics of generated data and cannot dynamically assess the
marginal utility of potential data additions based on the evolving
corpus. Consequently, these methods may repeatedly revisit well-covered
regions while under-exploring more informative combinations, limiting
the diversity and complexity of generated data.

Challenge 3: Efficiently Reusing Temporal Semantics. TSSQL generation
instantiates recurring local temporal semantics across diverse database
entities, creating a pronounced structure–instance asymmetry: similar
semantic structures must be repeatedly reconstructed across
heterogeneous data instances. However, the applicability of TSSQL
structures depends not only on schema compatibility but also on data
characteristics, such as sampling granularity, temporal distribution,
and synchronization. As illustrated in
Fig. [1](#S1.F1 "Figure 1 ‣ 1. Introduction ‣ TSSDA: An Autonomous Agent for Constructing a Time-Series Text-to-SQL Benchmark")(d),
asynchronous sampling invalidates point-wise operations, non-uniform
distribution undermines time-window aggregation, and continuous
variation requires linear rather than previous filling. Existing
approaches ([Sterbentz et al., 2026](#bib.bib56); [Guo et al.,
2025](#bib.bib57)) typically achieve reuse by extracting query-level
structural SQL templates. For TSSQL, however, structural compatibility
does not imply temporal applicability, while coarse SQL-level reuse
fails to capture local temporal structures.

To comprehensively address the aforementioned challenges, we propose a
novel data generation framework, TSSDA, and construct TERN, a
large-scale Text-to-TSSQL benchmark. To address the first challenge, we
systematically model TSSQL syntax and semantics to construct a data
generation space. We decompose TSSQL into core syntactic modules with
explicit semantic decision variables, and model their cross-module
dependencies. The resulting space integrates schema information,
dependency propagation, and evolving semantic states to provide valid
decision paths for composing diverse TSSQL queries. To address the
second challenge, we develop a Data Agent that autonomously navigates,
explores, and orchestrates the data space. Specifically, we design
dozens of Skills that provide the Agent with comprehensive autonomous
capabilities. The Data Agent consists of two collaborative agents: a
Semantic Decision Agent that dynamically plans Skill execution and makes
semantic decisions, and a Query Generation Agent that incrementally
materializes the temporal query. An online adaptation mechanism further
enables the Agent to adapt to the evolving data distribution and
accumulated experience, continuously improving generation quality and
diversity. To address the third challenge, we propose a temporal-aware
hierarchical memory for efficient reuse of generation experience. We
abstract data characteristics and generation states into temporal
profiles as memory indices. A hierarchical memory then retrieves
historical semantic decisions and operator expressions through temporal
profile matching and reliability-aware selection. An adaptive management
mechanism further dynamically updates the accumulated experience.

## 2. Preliminaries

### 2.1. Problem Formulation

Basic Definitions. We first introduce the basic concepts related to
time-series databases (TSDBs).

- •
  Time Series: A time series is an ordered sequence of observations,
  each consisting of a timestamp and its corresponding value, where time
  serves as the primary dimension in TSDBs.
- •
  Schema: A TSDB schema $`\mathcal{S}`$ describes the organization of
  time-series data under a specific data model, such as
  tree-based ([Wang et al., 2023](#bib.bib1)) or tag-based ([,
  2026](#bib.bib2)) models, including the associated entities, devices,
  measurements, and their structural relationships.
- •
  Temporal Operators:Temporal operators $`\mathcal{O}_{T}`$ are query
  operators or functions applied to time series for various temporal
  analysis tasks. They mainly include time-series generating functions
  (TSGFs) for sequence transformation and aggregate functions (AGGs) for
  sequence aggregation.
- •
  TSSQL: TSSQL refers to SQL-like query languages provided by TSDBs for
  querying and analyzing time-series data. A TSSQL query $`q`$ specifies
  target time series, temporal semantics, and optionally temporal
  operators from $`\mathcal{O}_{T}`$. Its execution under schema
  $`\mathcal{S}`$ is denoted as
  $`\operatorname{Exec}(q,\mathcal{S})\rightarrow Y`$, where $`Y`$ is
  the result.

NL2TSSQL. Given a natural language question $`u`$ and a time-series
schema $`\mathcal{S}`$, the NL2TSSQL task aims to translate $`u`$ into a
TSSQL query $`q`$ that correctly expresses the intended query semantics.
Formally, the task can be expressed as
$`f_{\mathrm{NL2TSSQL}}:(u,\mathcal{S},\mathcal{O}_{T},\Gamma_{T})\rightarrow q,`$
where $`\Gamma_{T}`$ denotes the temporal grammar and syntactic
constraints imposed by the target TSSQL dialect. The generated query
$`q`$ should conform to schema $`\mathcal{S}`$, the supported temporal
operator space $`\mathcal{O}_{T}`$, and the temporal grammar constraints
$`\Gamma_{T}`$, while faithfully preserving the semantics specified by
the natural language question $`u`$.

Data Generation. Given the schema $`\mathcal{S}`$ of a target TSDB
instance, the data generation task aims to generate a set of NL2TSSQL
instances $`\mathcal{Z}=\{(u_{i},q_{i})\}_{i=1}^{N}`$, where $`u_{i}`$
is a natural language question and $`q_{i}`$ is its corresponding TSSQL
query. Formally, the task is expressed as
$`f_{\mathrm{DG}}:(\mathcal{S},\mathcal{O}_{T},\Gamma_{T})\rightarrow\mathcal{Z}`$.
Each generated pair $`(u_{i},q_{i})`$ should be semantically consistent,
while $`q_{i}`$ should conform to $`\mathcal{S}`$, $`\mathcal{O}_{T}`$,
and $`\Gamma_{T}`$, and be executable on the target TSDB.

### 2.2. Benchmark Definition

TERN Benchmark. TERN is an NL2TSSQL benchmark defined as
$`\mathcal{B}=(\mathbb{E},\mathcal{Z},\mathcal{R},\Pi)`$, consisting of
the following components:

- •
  TSDB Environments:
  $`\mathbb{E}=\{(\mathcal{S}_{j},\mathcal{O}_{T,j},\Gamma_{T,j})\}_{j=1}^{N}`$,
  representing the TSDB environments, where $`N`$ is the number of TSDB
  instances.
- •
  NL2TSSQL Instances: $`\mathcal{Z}=\bigcup_{j=1}^{N}\mathcal{Z}_{j}`$,
  where $`\mathcal{Z}_{j}=\{(u_{j,i},q_{j,i})\}_{i=1}^{n_{j}}`$ denotes
  the set of NL–TSSQL pairs associated with environment $`j`$, and each
  pair $`(u_{j,i},q_{j,i})`$ satisfies the validity requirements.
- •
  Generation Specification: $`\mathcal{R}`$ is an optional set of
  requirements that specifies the desired benchmark construction targets
  and enables data generation under customized objectives.
- •
  Evaluation Protocol: $`\Pi`$ specifies the data partitioning strategy
  and evaluation settings of the benchmark.

Beyond instance-level validity, a benchmark should additionally satisfy
dataset-level requirements on coverage, diversity, and quality to enable
comprehensive and reliable evaluation of NL2TSSQL systems.

## 3. Framework Overview

![Refer to caption](2611.02132v1/framework.png)

Figure 2. Architecture of the TSSDA Framework

In this section, we present the design of our framework, TSSDA. Unlike
existing automated NL2SQL data generation approaches, which primarily
rely on instance transformation ([Koukouvinis et al., 2026](#bib.bib39);
[Sarwar et al., 2026](#bib.bib9)), template instantiation ([Zhang et
al., 2023](#bib.bib15); [Deng et al., 2026](#bib.bib7)), or predefined
workflows ([Li et al., 2025a](#bib.bib4); [Li et al., 2025b](#bib.bib8);
[Sullutrone et al., 2026](#bib.bib19)), our method constructs an
interactive data generation space by explicitly modeling syntax and
semantic dependencies, and develops a Data Agent system that
autonomously explores, orchestrates, and adapts this data
infrastructure. As illustrated in
Figure [2](#S3.F2 "Figure 2 ‣ 3. Framework Overview ‣ TSSDA: An Autonomous Agent for Constructing a Time-Series Text-to-SQL Benchmark"),
we collect diverse industrial time-series datasets as TSDB instances.
TSSDA comprises five key components, detailed below.

I. Semantic Dependency Modeling. Automated TSSQL generation should
jointly ensure broad compositional coverage and strong validity.
Existing approaches ([Deng et al., 2026](#bib.bib7); [Li et al.,
2025b](#bib.bib8); [Sullutrone et al., 2026](#bib.bib19)) largely rely
on prompt-specified rules and post-hoc augmentation, leaving the
definition of valid query compositions implicit and requiring costly
filtering to remove invalid queries. To address this issue, we model the
TSSQL generation process at a fine granularity from both syntactic and
semantic perspectives. Specifically, we first extract nine core
syntactic modules from the base TSSQL grammar. We then analyze temporal
dependencies and constraints from temporal semantics, official
documentation, and validity checks in the DBMS Analyzer to construct a
dependency graph.

II. Data Generation Space. Towards true autonomy in data generation, we
construct a structured generation space that enables the Data Agent to
explore autonomously. Based on the dependency graph, we topologically
order the nine core modules to progressively construct NL–SQL pairs.
Then, a unified time-series meta-schema with queryable details is
introduced to abstract heterogeneous schema models. To efficiently
propagate dependency information across phases, we introduce lightweight
Structured Phase Outputs (SPOs) and Flags as Dependency Signals. A
serialized Query Frame is further used to maintain the intermediate
query representation throughout generation. Finally, we define a Global
Context and combine it with the above structures to form the space
state, whose transitions are driven by Agent interactions.

III. Autonomous Agent Exploration. To enable autonomous fine-grained
control over the generation process and exploration of the data space,
we develop a Data Agent with orchestration, decision-making, and
generation capabilities. At each exploration step, we first construct
the generation state from the data space and the dependency information.
Next, we design a Skill Repository comprising dozens of Skills that
support diverse autonomous capabilities. A Semantic Decision Agent
$`\mathcal{M}_{D}`$ then selects a Skill $`\kappa`$ and leverages it to
determine an action $`a`$. The action $`a`$ drives exploration through
semantic decisions and tool execution, while dynamically updating the
set of eligible subsequent Skills. Based on the action, the Query
Generation Agent $`\mathcal{M}_{G}`$ is activated as needed to generate
a $`\Delta Query`$ for the corresponding query component under the
current semantics. The Agent’s operations constitute the Exploration
Outcome, which is then used to update the space environment accordingly.
The Data Agent continues exploration until all modules are completed,
generating a batch of queries. In addition, we design a memory mechanism
which is detailed later.

IV. Online Adaptation. Online adaptation enables the Agent to
continuously learn and improve, as illustrated by the red arrows in
Figure [2](#S3.F2 "Figure 2 ‣ 3. Framework Overview ‣ TSSDA: An Autonomous Agent for Constructing a Time-Series Text-to-SQL Benchmark").
To construct a high-quality benchmark, we guide the Agent from multiple
perspectives, including semantic validity, coverage and diversity, and
executability. Therefore, we propose three training-free online
adaptation mechanisms. The Semantic-Aware Adaptation uses rule-based and
model-based validators to assess semantic consistency and guide Skill
selection. The Distribution-Aware Adaptation provides decision guidance
through action priors derived from the distribution of validated data.
The Execution-Aware Adaptation leverages TSDB execution feedback to
refine query generation. At step $`t`$, the Data Agent leverages
adaptation knowledge accumulated up to step $`t-1`$, while the knowledge
generated at step $`t`$ is used to guide subsequent exploration.

V. Temporal-Aware Hierarchical Memory. TSSQL data inherently exhibit
high structural repetition but low instance-level overlap. To address
this efficiency challenge, we extract temporal patterns from the raw
state for efficient storage and retrieval. A hierarchical memory is then
introduced, with two levels tailored to the decision process and
fine-grained nested operator-chain generation, respectively. Before
Agent activation, the system retrieves memory using a matching
algorithm. A successful hit bypasses the computationally intensive Agent
invocation and directly returns the result. Finally, we design an
Adaptive Memory Management mechanism to dynamically update the memory.
This memory substantially improves system efficiency while achieving a
favorable trade-off between efficiency and generation performance.

## 4. Dependency-Aware Generation Space

### 4.1. Dependency Modeling

Given an industrial TSDB schema $`\mathcal{S}`$, comprehensive TSSQL
generation requires systematically exploring a vast query space spanning
diverse temporal intents. Existing LLM-based approaches ([Deng et al.,
2026](#bib.bib7); [Li et al., 2025a](#bib.bib4); [Dranca et al.,
2026](#bib.bib3)) typically rely on seed examples, templates, or
manually crafted instructions to guide generation. However, both
paradigms remain anchored to human-specified starting points and rely on
loosely constrained generation for expansion. Consequently, they lack an
explicit data-centric modeling of the query space, limiting data
coverage. Therefore, we systematically extract the syntactic and
semantic constraints of TSSQL and construct a dependency directed
acyclic graph (DAG) to explicitly model the implicit relationships among
query components.

First, we model the TSSQL syntax space to enable valid generation and
comprehensive exploration. An intuitive approach is to construct the
syntax based on the Abstract Syntax Tree (AST). However, a complete AST
is overly complex, introducing substantial overhead and limiting
practical feasibility. Prior work ([Guo et al., 2019](#bib.bib26); [Wu
et al., 2021](#bib.bib37)) explored SQL generation with lightweight
customized ASTs, but these methods largely predate the LLM era, as
tree-structured ASTs are poorly suited to serialized generation. To this
end, we analyze the formal TSSQL grammar by traversing its production
rules from the query-statement production and grouping related
non-terminals according to the query semantics they govern. Productions
describing the same query component are consolidated, while auxiliary
lexical rules are omitted. This process yields nine core syntactic
modules
$`V=\{\mu_{\mathrm{select}},\mu_{\mathrm{from}},...,\mu_{\mathrm{result}}\}`$,
which capture the major structural dimensions of TSSQL queries.

With these syntactic modules, we can comprehensively model all
components of TSSQL. However, organizing them remains challenging, as
syntactic order does not necessarily align with semantic reasoning. For
example, although SELECT appears first syntactically in a SQL statement,
semantically its valid functions and target time series can only be
determined after the query scope and grouping structure are established.
We therefore first identify the semantic task of each syntactic module,
including its query decision and corresponding choices. Specifically,
for each module $`\mu_{i}\in V`$, we introduce a set of semantic
decision variables $`X_{i}=\{x_{i,1},x_{i,2},\ldots,x_{i,m_{i}}\},`$
where each variable $`x_{i,k}`$ is associated with a candidate action
space $`\mathcal{A}_{i,k}`$. We then define a dependency constraint
$`r(x_{i,k},x_{j,l})`$ to exist whenever the resolved decision of
$`x_{i,k}`$ in module $`\mu_{i}`$ affects the decision of $`x_{j,l}`$ in
another module $`\mu_{j}`$. If $`r(x_{i,k},x_{j,l})`$ explicitly
prohibits an action a of $`x_{j,l}`$, we formulate a binary validity
function $`\phi_{r}(x_{i,k},a)\in\{0,1\}`$ and include $`x_{i,k}`$ in
$`\mathbf{x}_{j,l}^{r}`$. The feasible action space of $`x_{j,l}`$ is
then defined as:

|     |     |     |     |
| --- | --- | --- | --- |
| (1) |     |

````math
\mathcal{A}_{j,l}^{\,r}(\mathbf{x}_{j,l}^{r})=\left\{a\in\mathcal{A}_{j,l}\mid\phi_{r}(\mathbf{x}_{j,l}^{r},a)=1\right\},
``` |  |

where $`\mathbf{x}_{j,l}^{r}`$ denotes the preceding decision variables
that restrict the action space of $`x_{j,l}`$, and $`\phi_{r}=1`$
indicates that the action is valid. Based on these dependency
constraints, we define a dependency from module $`\mu_{i}`$ to
$`\mu_{j}`$ whenever $`r(x_{i,k},x_{j,l})`$ exists, denoted by:

|  |  |  |  |
|----|----|----|----|
| (2) |  |
``` math
E_{ij}=\left\{r\,\middle|\,\exists\,x_{i,k}\in\mathbf{x}_{j,l}^{r},\;x_{j,l}\in X_{j}\right\}.
``` |  |

Accordingly, we construct a module-level dependency DAG
$`\mathcal{G}=(V,E)`$ by treating the syntactic modules in $`V`$ as
vertices and adding a directed edge $`(\mu_{i},\mu_{j})`$ whenever
$`E_{ij}\neq\emptyset`$.

The constraints $`r`$ are derived from three complementary sources. We
first analyze the temporal semantics of TSSQL to identify ordering and
compatibility constraints among temporal decisions. We then extract
explicit cross-module restrictions from the official documentation, and
further inspect the semantic validity checks implemented in the DBMS
Analyzer to recover constraints enforced by the DBMS. The extracted
rules are normalized into the predicate form defined above and collected
as $`R_{c}=R_{T}\cup R_{D}\cup R_{A}`$. We further validate and
consolidate the candidate constraints $`R_{c}`$, yielding the final set
$`R`$ used to construct the module-level dependencies. The resulting
dependency graph is shown in
Figure [2](#S3.F2 "Figure 2 ‣ 3. Framework Overview ‣ TSSDA: An Autonomous Agent for Constructing a Time-Series Text-to-SQL Benchmark").

### 4.2. Generation Space Construction

Based on the dependency graph, we further model the generation process
as a data space, providing the Data Agent with a perceivable and
explorable environment. Specifically, given a TSDB schema
$`\mathcal{S}`$, we construct a structured generation space, denoted by
$`\Omega(\mathcal{S})=\left(\mathcal{P},\,\widehat{\mathcal{S}},\,\Psi,\,\mathcal{F},\,\Theta,\,\mathcal{Q},\,\delta\right)`$.
Next, we describe each component in detail.

Generation Phases $`\mathcal{P}`$: Given the dependency DAG
$`\mathcal{G}=(V,E)`$, we topologically order the syntactic modules as
$`\pi=\operatorname{TopoSort}(\mathcal{G}).`$ With initialization and
finalization phases, we define the space backbone as
$`\mathcal{P}=(P_{0},P_{\pi_{1}},P_{\pi_{2}},\ldots,P_{\pi_{9}},P_{f})`$,
where each $`P_{\pi_{i}}`$ corresponds to the syntactic module
$`\mu_{\pi_{i}}`$. Each phase $`P_{i}`$ contains its decision variables
$`X_{i}`$ and action spaces $`\{\mathcal{A}_{i,k}\}_{k=1}^{m_{i}}`$ for
agent interaction.

Unified TS-Schema $`\widehat{\mathcal{S}}`$: To accommodate large-scale
and heterogeneous TSDB schemas, we normalize the raw schema into a
unified representation
$`\widehat{\mathcal{S}}=(\mathcal{S}^{M},\mathcal{S}^{D})`$, where
$`\mathcal{S}^{M}`$ provides a concise schema-level overview, while
$`\mathcal{S}^{D}`$ maintains fine-grained schema details that can be
efficiently retrieved on demand.

Structured Phase Output (SPO) $`\Psi`$: SPOs provide lightweight
propagation of cross-phase dependencies. For an edge
$`(\mu_{i},\mu_{j})\in E`$, we extract the associated dependencies
$`r(x_{i,k},x_{j,l})`$. If the decision result of $`x_{i,k}`$
semantically affects $`x_{j,l}`$, we record this result in the SPO
$`\Psi`$. For each phase $`P_{j}`$, its input SPO is aggregated from the
predecessor phases:
$`\Psi_{j}^{\mathrm{in}}=\bigoplus_{P_{i}\in\operatorname{Pred}(P_{j})}\Pi_{ij}(\Psi_{i}),`$
$`\Pi_{ij}`$ projects the dependency-relevant information from
$`\Psi_{i}`$ for $`P_{j}`$, and $`\oplus`$ denotes aggregation over
multiple predecessors.

Dependency Flags $`\mathcal{F}`$: Flags encode explicit cross-phase
restrictions. Specifically, if $`r(x_{i,k},x_{j,l})`$ induces a validity
function $`\phi_{r}(x_{i,k},a)`$, the corresponding restriction is
recorded in $`\mathcal{F}`$.

Global Context $`\Theta`$: $`\Theta`$ maintains global context and
shared system states, such as temporal information and runtime settings.

Query Frame $`\mathcal{Q}`$: The Query Frame maintains a serialized
intermediate representation of the partially constructed query, denoted
as
$`Q=\operatorname{Serialize}\!\left(\{X_{i}\}_{i=1}^{9},\mathcal{O}_{T}\right),`$
which records the generated results of semantic decision variables
$`X_{i}`$ together with the intermediate expressions constructed from
the operator space $`\mathcal{O}_{T}`$.

Transition $`\delta`$: At step $`t`$, given a resolved action
$`a_{t}\in\mathcal{A}_{i,k}`$ for decision variable $`x_{i,k}`$, we
define the transition as $`\Omega_{t+1}=\delta(\Omega_{t},a_{t}),`$
where the relevant structures in $`\Omega_{t}`$ are updated accordingly.

## 5. Data Agent

### 5.1. Skill-Orchestrated Agent Architecture

The generation space defines the boundary and structure of data
construction, while raising a further challenge: how to effectively
explore this space? Existing approaches ([Li et al., 2025a](#bib.bib4);
[Li et al., 2025b](#bib.bib8); [Deng et al., 2026](#bib.bib7)) typically
use predefined workflows that assign LLMs or agents fixed roles, such as
generation, augmentation, or verification. The generation trajectory is
determined by the framework, limiting autonomous decision-making and
exploration. To address this challenge and endow the Agent with data
autonomy beyond monolithic prompting, we abstract dozens of fine-grained
capabilities into Skills organized in phase-specific repositories.
Specifically, we define two primary types of Skills: decision Skills and
generation Skills. A decision Skill is represented as
$`\kappa^{D}=\left\langle x_{i,k},\mathcal{A}_{i,k},\rho_{D}\right\rangle,`$
where $`x_{i,k}`$ is the target semantic decision variable,
$`\mathcal{A}_{i,k}`$ is action space, and $`\rho_{D}`$ denotes the
Skill execution policy. Given the current generation state $`\Omega`$,
the decision Skill $`\kappa^{D}`$ produces an action
$`a=\rho_{D}\!\left(\Omega,x_{i,k},\mathcal{A}_{i,k}^{r}\right),a\in\mathcal{A}_{i,k}^{r}.`$
Based on a resolved action $`a`$, the generation Skill is denoted as
$`\kappa^{G}=\langle a,\rho_{G}\rangle`$, where $`\rho_{G}`$ produces an
incremental intermediate representation $`\Delta Q=\rho_{G}(\Omega,a)`$.
These Skills provide complementary capabilities, such as planning,
reasoning, and instantiation, to support autonomous generation. Finally,
each phase $`P_{i}`$ is associated with a dedicated Skill repository
$`\mathcal{K}_{i}=\left(\kappa_{1}^{D},\ldots,\kappa_{m}^{D},\kappa_{1}^{G},\ldots,\kappa_{n}^{G}\right),`$
containing Skills specialized for that phase.

Next, we decouple data exploration into two specialized agents: the
Semantic Decision Agent $`\mathcal{M}_{D}`$ and the SQL Generation Agent
$`\mathcal{M}_{G}`$. The former autonomously navigates the data
generation space through semantic reasoning, while the latter
incrementally constructs queries based on these decisions. Specifically,
$`\mathcal{M}_{D}`$ makes semantic decisions such as selecting temporal
patterns and grouping paradigms, guided by semantic context and decision
Skill specifications. In turn, $`\mathcal{M}_{G}`$ constructs and
updates the intermediate query representation by incrementally
instantiating concrete query elements according to generation Skill
specifications. The collaboration between the two agents prevents
syntactic generation from directly determining high-level query
semantics and enables semantic decisions to be explicitly maintained and
constrained.

### 5.2. Autonomous Agent Exploration

In this section, we detail how the Data Agent autonomously analyzes and
explores the data space. Starting from the initialization phase
$`P_{0}`$, the Agent iteratively explores each phase until all phases
are completed. We next describe the exploration process.

State Preparation: Given the current space state $`\Omega_{t}`$, we
construct the input state $`\Omega^{\prime}_{t}`$ by extracting the
phase-relevant $`\Theta`$, $`\mathcal{Q}`$, and
$`\widehat{\mathcal{S}}`$. Next, according to the dependency DAG
$`\mathcal{G}=(V,E)`$, we retrieve the SPOs $`\Psi`$ and Flags
$`\mathcal{F}`$. For example, phase $`P_{4}`$ obtains dependency from
its related phases $`P_{1}`$, $`P_{2}`$, and $`P_{3}`$, as illustrated
in
Figure [2](#S3.F2 "Figure 2 ‣ 3. Framework Overview ‣ TSSDA: An Autonomous Agent for Constructing a Time-Series Text-to-SQL Benchmark").
The relevant SPOs $`\Psi`$ are incorporated into $`\Omega^{\prime}_{t}`$
to provide the semantic dependency context, while the Flags
$`\mathcal{F}`$ impose action masks on the action space of the available
Skills.

Dynamic Skill Routing: After preparing the input state, we derive the
set of currently eligible candidate Skills
$`\mathcal{K}^{\prime}_{i,t}`$ from the phase-specific Skill repository.
Rather than following a predetermined Skill sequence, the Semantic
Decision Agent $`\mathcal{M}_{D}`$ dynamically selects a Skill from the
candidate set based on the current semantics and the input state
$`\Omega^{\prime}_{t}`$:
$`\kappa_{t}^{D}=\mathcal{M}_{D}\left(\Omega^{\prime}_{t},\mathcal{K}^{\prime}_{i,t}\right)`$.
The Skill execution result further updates the set of eligible
subsequent Skills.

Agent Exploration: Our agent progressively explores the data space using
Skills. Specifically, each decision Skill defines the currently
admissible exploration actions $`\mathcal{A}_{i,k}^{r}`$. The Semantic
Decision Agent $`\mathcal{M}_{D}`$ then selects an action
$`a_{t}=\mathcal{M}_{D}(\Omega^{\prime}_{t},\kappa_{t}^{D})`$ according
to the current input state and the Skill policy $`\rho_{D}`$. Each
action advances the exploration and refines the query semantics.
Execution actions invoke the corresponding tools, while generation
actions activate the SQL Generation Agent $`\mathcal{M}_{G}`$ to
instantiate the current semantics. When invoked, the action $`a_{t}`$
provides $`\mathcal{M}_{G}`$ with the generation Skill
$`\kappa_{t}^{G}`$ required for the current step. The agent then
produces the corresponding incremental query:
$`\Delta Q_{t}=\mathcal{M}_{G}(\Omega^{\prime}_{t},\kappa_{t}^{G}).`$
Additionally, before either agent is activated, a memory mechanism is
accessed to directly obtain the required result when available. Further
details are provided in
Sec. [6](#S6 "6. Temporal-Aware Memory ‣ TSSDA: An Autonomous Agent for Constructing a Time-Series Text-to-SQL Benchmark").

Outcome Update: The decision $`a_{t}`$, its execution result, and the
generated $`\Delta Q_{t}`$ are recorded in the Exploration Outcome and
subsequently used to update the corresponding global context, query
frame, and dependency-related variables in the data space.

![Refer to caption](2611.02132v1/op.png)

Figure 3. Recursive Operator Expression Structure

Operator-Chain Exploration Algorithm: TSDBs support operator chains over
hundreds of temporal functions. To explore their semantics and
combinations, we develop an iterative chain-construction algorithm based
on the general exploration procedure.

Expressions in TSDBs include time-series generating functions
($`TSGFs`$) and aggregate functions ($`AGGs`$). The former produce
timestamp-indexed data points, while the latter collapse points within a
temporal segment to a single value. Due to their distinct computation
granularity and cardinality, $`SelectExpr`$ has two mutually exclusive
forms: $`SeriesExpr`$ and $`AggExpr`$. Additionally, the two expression
types can be nested when the semantic and syntactic constraints are
satisfied. Therefore, to automatically construct valid operator chains,
we formulate a recursive expression grammar, as illustrated in
Figure [3](#S5.F3 "Figure 3 ‣ 5.2. Autonomous Agent Exploration ‣ 5. Data Agent ‣ TSSDA: An Autonomous Agent for Constructing a Time-Series Text-to-SQL Benchmark").
A $`SeriesExpr`$ is initialized from raw time series $`TS`$ and
recursively extended with $`TSGFs`$, constants ($`Const`$), and
operators ($`op`$). We then define $`AggAtom`$, which applies an $`AGG`$
to an arbitrary $`SeriesExpr`$. An $`AggExpr`$ is built from $`AggAtom`$
and can be recursively extended with $`Const`$, $`op`$, and
scalar-compatible $`TSGFs`$, excluding those that accept only sequence
inputs.

As shown in
Algorithm [1](#algorithm1 "In 5.1. Skill-Orchestrated Agent Architecture ‣ 5. Data Agent ‣ TSSDA: An Autonomous Agent for Constructing a Time-Series Text-to-SQL Benchmark"),
we use operator-chain construction as an example to illustrate the
exploration algorithm. We first initialize $`\mathcal{C}_{S}`$ with raw
time series and $`\mathcal{C}_{A}`$ as an empty set. Next,
$`\mathcal{M}_{D}`$ performs Skill routing to determine the generation
trajectory. If $`\mathcal{M}_{D}`$ selects $`\kappa_{1}^{D}`$, we
iteratively construct the SeriesExpr (lines 3-7 of
Algorithm [1](#algorithm1 "In 5.1. Skill-Orchestrated Agent Architecture ‣ 5. Data Agent ‣ TSSDA: An Autonomous Agent for Constructing a Time-Series Text-to-SQL Benchmark")).
Specifically, $`\mathcal{M}_{D}`$ iteratively invokes $`\kappa_{1}^{D}`$
to select the next SeriesExpr extension action according to the grammar,
then invokes $`\kappa_{4}^{D}`$ or $`\kappa_{5}^{D}`$ based on the
selected action. Following this, we execute the Exploration procedure,
where $`\mathcal{M}_{D}`$ and $`\mathcal{M}_{G}`$ jointly perform one
instantiation step for $`\mathcal{C}_{S}`$. Then, if $`\kappa_{2}^{D}`$
is selected, we first construct an AggAtom using $`\kappa_{3}^{D}`$ and
subsequently extend the AggExpr iteratively in a manner analogous to
SeriesExpr (lines 8-13 of
Algorithm [1](#algorithm1 "In 5.1. Skill-Orchestrated Agent Architecture ‣ 5. Data Agent ‣ TSSDA: An Autonomous Agent for Constructing a Time-Series Text-to-SQL Benchmark")).

Exploration: within each exploration step, $`\mathcal{M}_{D}`$ first
invokes the input decision Skill $`\kappa^{D}`$ to select a function or
operator, including decisions on the function source, functional family,
and concrete function. Subsequently, after incorporating the decision
result into $`\Omega^{\prime}_{t}`$, $`\mathcal{M}_{G}`$ invokes
$`\kappa^{G}`$ to instantiate an expression as the incremental query
$`\Delta Q_{t}`$. The resulting expression is then added to the
corresponding set $`\mathcal{C}`$, and the relevant state in
$`\Omega^{\prime}_{t}`$ is updated accordingly.

### 5.3. Online Adaptation

Although the Data Agent can autonomously explore the data space, it
still lacks the capacity for autonomous learning. High-quality TSSQL
generation requires broad coverage, diversity, validity, and semantic
plausibility. To enable efficient self-improvement of the Data Agent
across these dimensions, we develop a training-free online adaptation
mechanism that leverages exploration feedback through three
complementary strategies, as detailed below.

Distribution-aware adaptation: Coverage and diversity are key dimensions
of data generation quality. Existing approaches ([Cai et al.,
2026](#bib.bib20); [Deng et al., 2026](#bib.bib7); [Li et al.,
2025b](#bib.bib8)) typically improve diversity through offline
augmentation by transforming query skeletons, templates, or existing
queries. In contrast, we introduce online distribution-aware adaptation
guided by the evolving data, enabling the Agent to autonomously improve
its decision-making and explore underrepresented regions. For each
semantic decision Skill $`\kappa`$, we track $`N_{\kappa,t}(a)`$, the
number of valid instances generated by each action
$`a\in\mathcal{A}_{\kappa}`$. The empirical action distribution at step
$`t`$ is:

|  |  |  |  |
|----|----|----|----|
| (3) |  |
``` math
p_{\kappa,t}(a)=\frac{N_{\kappa,t}(a)+\epsilon}{\sum_{a^{\prime}\in\mathcal{A}_{\kappa}}\left(N_{\kappa,t}(a^{\prime})+\epsilon\right)},
``` |  |

where $`\epsilon`$ is a smoothing factor. Given a target distribution
$`p^{\prime}_{\kappa}(a)`$, which may be derived from real-world
scenarios or user preferences, we quantify the distribution deficit of
each action as
$`D_{\kappa,t}(a)=\frac{\left[p^{\prime}_{\kappa}(a)-p_{\kappa,t}(a)\right]_{+}}{p^{\prime}_{\kappa}(a)},`$
where $`[x]_{+}=\max(x,0)`$. Larger deficits indicate greater
underrepresentation in the generated data. We derive an action prior
over the current feasible action set $`\mathcal{A}_{\kappa,t}^{r}`$ from
these deficits and provide it to $`\mathcal{M}_{D}`$ as online
distributional knowledge:

|  |  |  |  |
|----|----|----|----|
| (4) |  |
``` math
\varrho_{\kappa,t}(a)=\frac{\exp(D_{\kappa,t}(a)/\tau)}{\sum_{a^{\prime}\in\mathcal{A}_{\kappa,t}^{r}}\exp(D_{\kappa,t}(a^{\prime})/\tau)},
``` |  |

where $`\tau`$ controls the strength of distribution-aware guidance. The
action prior guides the Agent toward underexplored decisions while
preserving semantic validity.

Execution-aware adaptation: Despite our fine-grained modeling of TSSQL
syntax and semantics, the inherent uncertainty of LLMs may still cause
generated queries to violate DBMS-specific constraints. Therefore, we
design an execution-aware adaptation mechanism that continuously
distills DBMS execution feedback into reusable generation knowledge,
enabling $`\mathcal{M}_{G}`$ to progressively improve generation
quality. Given the complete query $`q_{t}`$ generated by the Agent, we
execute it on the database
$`\operatorname{Exec}(q_{t},\mathcal{S})\rightarrow(y_{t},e_{t}),`$
where $`y_{t}`$ denotes the execution result and $`e_{t}`$ captures the
DBMS feedback, such as the status code and error message.
$`\mathcal{M}_{G}`$ then repairs the query using execution feedback and
historical experience,
$`q^{\prime}_{t}=\mathcal{M}_{G}(q_{t},e_{t},\mathcal{H}_{t})`$, where
$`\mathcal{H}_{t}`$ denotes experience in the execution knowledge base.
After repair, we distill the repair experience into a reusable rule
$`h_{t}=\operatorname{Distill}(e_{t},q_{t},q^{\prime}t)`$ and add it to
the knowledge base: $`\mathcal{H}{t+1}=\mathcal{H}_{t}\cup{h_{t}}`$. For
subsequent generation, we incorporate relevant knowledge retrieved from
$`\mathcal{H}_{t}`$ based on the current query structure and operator
signatures into the generation context. If execution fails, we retrieve
additional experience based on the error category to guide repair.

Semantic-aware adaptation: Although the dependency mechanism improves
decision-making, it offers limited guidance for Skill routing. We
therefore introduce semantic-aware adaptation to learn the
state-dependent Skill suitability from online semantic feedback. A
rule-based validator checks local semantic consistency at each routing
step, while an LLM-based validator assesses overall Skill route
consistency after generation. Let
$`v_{t}^{\mathrm{r}},v_{t}^{\mathrm{LLM}}\in\{0,1\}`$ denote the two
validation results, we define the semantic reward as
$`r_{t}=v_{t}^{\mathrm{r}}\cdot v_{t}^{\mathrm{LLM}}`$. We then compress
$`\Omega^{\prime}_{t}`$ into a lightweight semantic context $`c_{t}`$
and track the selection count $`N_{t}(c_{t},\kappa)`$ and cumulative
semantic reward $`R_{t}(c_{t},\kappa)=\sum r_{t}`$. A routing score is
computed as:

|  |  |  |  |
|----|----|----|----|
| (5) |  |
``` math
S_{t}(\kappa)=\frac{R_{t}(c_{t},\kappa)+1}{N_{t}(c_{t},\kappa)+2}+\lambda\sqrt{\frac{\log\!\left(N_{t}(c_{t})+2\right)}{N_{t}(c_{t},\kappa)+1}},
``` |  |

where $`N_{t}(c_{t})=\sum_{\kappa}N_{t}(c_{t},\kappa)`$ and $`\lambda`$
controls the exploration strength. The resulting scores are incorporated
into the Agent context as online routing knowledge to guide subsequent
Skill selection.

## 6. Temporal-Aware Memory

![Refer to caption](2611.02132v1/memory.png)

Figure 4. Overview of the Temporal-Aware Hierarchical Memory Mechanism

Temporal queries essentially instantiate recurring temporal semantics
over heterogeneous schema entities. The same local temporal semantic
structure may appear across industrial scenarios, while their schemas
and temporal characteristics, such as sampling granularity, can differ
substantially. This gives rise to a structure-instance asymmetry between
reusable temporal structures and heterogeneous data instances. However,
the reuse of these structures depends not only on schema compatibility
but also on the temporal characteristics and semantics of the underlying
data. To address this challenge, we propose a temporal-aware
hierarchical memory that efficiently models temporal characteristics and
enables the reuse of generation experience across instances. As
illustrated in
Figure [4](#S6.F4 "Figure 4 ‣ 6. Temporal-Aware Memory ‣ TSSDA: An Autonomous Agent for Constructing a Time-Series Text-to-SQL Benchmark"),
we next detail the memory mechanism.

Temporal Pattern Profiling: To identify reusable experience, we need to
extract temporal characteristics from the data space. The raw state
$`\Omega_{t}`$ is unsuitable for direct matching due to substantial
redundancy. We therefore extract a temporal profile to capture the
current data characteristics and temporal semantics of the data space.
Specifically, we first canonicalize $`\Omega_{t}`$ as
$`\mathcal{I}_{C}=\operatorname{Canon}(\Omega_{t}),`$ where
$`\operatorname{Canon}`$ prunes the dependency information $`\Psi`$,
$`\mathcal{F}`$, and query representation $`\mathcal{Q}`$, and maps
their state values into matchable ordered sequences, sets, and atomic
values. Next, we design temporal profiling to extract a low-dimensional,
instance-agnostic representation of the temporal context. For the $`m`$
time series across $`n`$ devices in the current space state, let
$`I_{i}=[l_{i},r_{i}]`$ denote the valid interval of the $`i`$-th
series, $`D=[L,R]`$ the overall data interval with $`L=\min_{i}l_{i}`$
and $`R=\max_{i}r_{i}`$, $`Q=[a,b]`$ the query range, and
$`(\alpha,\beta)`$ the window parameters. We compute:

|  |  |  |  |
|----|----|----|----|
| (6) |  |
``` math
\mathcal{I}_{T}=\left\langle\sigma_{1}(n,m,\{I_{i}\}),\sigma_{2}(R-L),\sigma_{3}\!\left(\frac{|Q|}{|D|}\right),\ldots,\sigma_{k}(\alpha,\beta)\right\rangle,
``` |  |

which characterize temporal patterns, data span, query coverage, window
configuration, and other temporal properties. Each $`\sigma_{i}(\cdot)`$
discretizes a temporal characteristic into a compact representation,
abstracting instance-specific values while retaining temporal
information relevant to experience reuse. For expression-related states,
we additionally extract an expression profile $`\mathcal{I}_{E}`$, which
captures structural properties of the current expression, such as its
operator composition and input/output characteristics. Finally, we
combine the above features into a unified temporal profile
$`\mathcal{I}=\left\langle\mathcal{I}_{C},\mathcal{I}_{T},\mathcal{I}_{E}\right\rangle`$,
which serves as the key for subsequent memory retrieval.

Hierarchical Reuse Memory: Reusable decision and generation experiences
are associated with distinct temporal characteristics. We therefore
design a hierarchical memory architecture consisting of state-level
memory and operator-level memory, which store semantic decision results
for $`\mathcal{M}_{D}`$ and operator expressions for
$`\mathcal{M}_{G}`$, respectively. The current temporal profile
$`\mathcal{I}_{t}`$ is used to retrieve the memory. A valid match
enables direct result reuse without Agent invocation; otherwise, the
Agent is invoked, and its experience may be stored after validation.
Memory matching is based on a similarity function
$`\operatorname{Sim}(\mathcal{I}_{t},\mathcal{I}_{i})`$ that compares
the current temporal profile with each stored memory entry. Categorical
features use exact or neighboring-category matching, set-valued features
use set similarity, and ordered features use distance-based soft
matching. Entries above the similarity threshold form the retrieved
candidate set $`\mathcal{H}_{t}`$. For each memory entry
$`\varepsilon_{i}`$, we maintain its successful reuse count
$`N_{i}^{s}`$, failed reuse count $`N_{i}^{f}`$, and total reuse count
$`N_{i}^{r}`$. Then, its confidence is estimated as
$`\operatorname{Conf}(\varepsilon_{i})=\frac{N_{i}^{s}+1}{N_{i}^{s}+N_{i}^{f}+2}.`$
When multiple entries are matched, we score them by effectiveness and
frequency:

|  |  |  |  |
|----|----|----|----|
| (7) |  |
``` math
\operatorname{Score}(\varepsilon_{i}\mid\mathcal{I}_{t})=\frac{\operatorname{Sim}(\mathcal{I}_{t},\mathcal{I}_{i})\cdot\operatorname{Conf}(\varepsilon_{i})}{1+\lambda N_{i}^{r}},
``` |  |

where $`\lambda`$ controls the penalty on repeatedly reused entries.
Based on the retrieval scores, the system retains the top-$`K`$ entries
from the retrieved candidate set $`\mathcal{H}_{t}`$ and constructs a
normalized selection distribution:

|  |  |  |  |
|----|----|----|----|
| (8) |  |
``` math
P(\varepsilon_{i}\mid\mathcal{I}_{t})=\frac{\operatorname{Score}(\varepsilon_{i}\mid\mathcal{I}_{t})}{\sum_{\varepsilon_{j}\in\operatorname{TopK}(\mathcal{H}_{t})}\operatorname{Score}(\varepsilon_{j}\mid\mathcal{I}_{t})},
``` |  |

The system then samples one memory entry from this distribution as the
retrieval result.

Adaptive Memory Management: To maintain the reliability and
applicability of the reuse memory, we dynamically manage memory entries
through admission, update, refinement, and eviction. New experiences
produced by the Data Agent are first stored in a provisional buffer and
admitted into memory only after validation and redundancy checking. When
a memory entry is retrieved, its reuse outcome is temporarily recorded
in an update buffer; after validation, the corresponding success,
failure, and reuse statistics are updated. If reuse fails due to
temporal incompatibility, we refine the entry’s applicability as
$`\mathcal{I}_{i}\leftarrow\operatorname{(}\mathcal{I}_{i},\mathcal{I}_{f})`$,
where $`\mathcal{I}_{f}`$ denotes the failed reuse profile. Finally, an
entry $`\varepsilon_{i}`$ is removed when its failure ratio exceeds a
threshold $`\frac{N_{i}^{f}}{N_{i}^{s}+N_{i}^{f}}>\gamma.`$ This process
allows the memory to continuously absorb validated experience, refine
reuse conditions, and discard unreliable entries during generation.

  and NL2InfluxDB ([Dranca et al., 2026](#bib.bib3)).

- •
  DeepSeek ([DeepSeek-AI, 2026](#bib.bib27)): We use DeepSeek-V4.1-Flash
  as a reference baseline, augmented with RAG ([Lewis et al.,
  2020](#bib.bib77)) over a TSSQL knowledge base.
- •
  OmniSQL ([Li et al., 2025a](#bib.bib4)): This method proposes a

- •

  documentation-driven data synthesis pipeline for InfluxDB that
  integrates retrieval-augmented generation and knowledge-graph-based
  verification.

Benchmark Configuration. To enable more fine-grained evaluation on TERN,
we further organize the benchmark into three versions. TERN-Foundation
covers basic TSSQL knowledge with relatively short, simple queries.
TERN-Standard, the largest subset, targets moderately difficult NL2TSSQL
tasks. TERN-Analytical focuses on time-series analytical queries with
more complex temporal operator chains. Each version is split into
training, validation, and test sets at an 8:1:1 ratio. All collected
benchmark instances are validated through LLM-based and manual
verification.

Evaluation Metrics. For TERN, we adopt the widely used ([Li et al.,
2023](#bib.bib12); [Deng et al., 2026](#bib.bib7); [Gao et al.,
2026](#bib.bib18)) Execution Accuracy (EX) and Successful Execution Rate
(SER). EX measures the proportion of predictions matching ground-truth
execution results, while SER measures the proportion that execute
successfully. For TSSDA, we evaluate the coverage, diversity, and
complexity. Following SQL-Factory ([Li et al., 2025b](#bib.bib8)), we
compute Hybrid Similarity and the Vendi Scores to evaluate sample
similarity. The TSSQL Coverage metric builds on SQL coverage criteria
from prior work ([Suárez-Cabal and Tuya, 2009](#bib.bib63)), covering
temporal, SQL-structural, and schema dimensions. The Hill diversity
metric further measures TSSQL diversity, defined as
$`\mathrm{HD}=\exp\left(-\sum_{i=1}^{K}p_{i}\ln p_{i}\right)`$, where
$`p_{i}`$ is the frequency of the $`i`$-th TSSQL feature category.
Finally, following the SQL adaptation ([Vashistha and Jain,
2016](#bib.bib64)) of Halstead measures ([Halstead, 1977](#bib.bib65)),
we define Halstead Complexity as the geometric mean of the Halstead
measure and expression depth. The Halstead measure is computed as
$`\mathrm{H}(q)=\frac{n_{1}}{2}\cdot\frac{N_{2}}{n_{2}}\cdot\log_{2}(n_{1}+n_{2})`$,
where $`n_{1}`$, $`n_{2}`$, and $`N_{2}`$ denote the numbers of distinct
operators, distinct operands, and total operand occurrences.

Experimental Settings. All experiments are implemented with PyTorch 2.6
and Python 3.11 on Ubuntu 26.04. Methods requiring training are trained
using 4 NVIDIA A100 GPUs.

### 7.3. Evaluation on Benchmark

We comprehensively evaluate existing methods on TERN across three
categories: Fine-tuned LLMs, Frontier LLMs, and NL2SQL Methods. As shown
in
Table [2](#S7.T2 "Table 2 ‣ 7.2. Benchmark Statistics ‣ 7. Experiments ‣ TSSDA: An Autonomous Agent for Constructing a Time-Series Text-to-SQL Benchmark"),
we draw the following observations:

\(1\) Fine-tuned LLMs. Without fine-tuning, these models perform poorly,
with even Qwen3.8-27B achieving only 5.33% overall EX. We therefore
apply SFT, which substantially improves their EX and SER, supporting the
effectiveness of our training corpus. Qwen3.8-27B achieves the highest
EX across all three subsets, suggesting that larger models yield better
performance. Qwen2.5-Coder-7B shows no clear advantage over similarly
sized models, indicating limited benefits of code-oriented pretraining
for TSSQL.

\(2\) Frontier LLMs. Frontier LLMs exhibit substantial performance
variation. GPT-6.1 achieves the best EX and SER, outperforming GPT-5.6
by 11.65 pp in overall EX. In contrast, Qwen3.8 underperforms Qwen3.7,
potentially due to excessive reasoning. These differences suggest
varying degrees of transferability to TSSQL, making task-specific
validation essential for model selection.

\(3\) NL2SQL Methods. SFT-based NL2SQL models show no clear advantage
over general-purpose models, potentially due to the limited benefits of
standard SQL pretraining for TSSQL. ICL-based methods perform relatively
poorly, likely because their techniques designed for relational
databases inadequately address TSSQL challenges.

\(4\) Cross-paradigm Comparison. Comparing the strongest models from
each category, Qwen3.8-27B achieves the highest EX on TERN-F, while
GPT-6.1 performs better on TERN-S and TERN-A. This suggests that SFT is
particularly effective for basic TSSQL queries, whereas GPT-6.1’s
stronger reasoning capabilities better support complex TSSQL queries and
temporal analytics.

\(5\) Task-specific Performance Analysis. Across all baselines, EX
generally declines from TERN-F to TERN-S and TERN-A. Even the best model
achieves less than one-third EX on TERN-A, highlighting the challenges
of predicting analytical time-series queries.

\(6\) Executability vs. Correctness. Even the best methods achieve only
around 75% overall SER and 50% EX, indicating that limited ability to
generate executable TSSQL constrains EX accuracy.

### 7.5. Effectiveness Comparison

To evaluate generation effectiveness, we generate 500 executable samples
using each baseline on the same TSDB. For a fair comparison, all
baselines use DeepSeek-V4.1-Flash as the backbone model. In addition to
the baselines, we evaluate three ablated variants of TSSDA, removing
semantic dependencies, online adaptation, and memory, respectively, to

Table [3](#S7.T3 "Table 3 ‣ 7.5. Effectiveness Comparison ‣ 7. Experiments ‣ TSSDA: An Autonomous Agent for Constructing a Time-Series Text-to-SQL Benchmark")
reports the results and we have the following observations:

\(1\) Overall Effectiveness. TSSDA achieves the best performance across
all metrics. It improves Vendi Score, TSSQL Coverage, and Hill Diversity
by 55.80%, 21.56%, and 45.00%, respectively, over their strongest
baselines. These results demonstrate its effectiveness in generating
diverse TSSQL queries with broad feature coverage.

\(2\) Generation Diversity. Hybrid Similarity and Vendi Score assess
sample similarity, with TSSDA achieving the best results on both. TACO
performs worst, largely due to repeated instantiation of a limited
skeleton set. TSSDA also achieves the highest Hill Diversity, whereas
OmniSQL records the lowest score, indicating concentrated feature reuse
despite its complexity-oriented generation. Among the baselines,
SQL-Factory achieves the highest Vendi Score, potentially benefiting
from its diversity-oriented query rewriting. In contrast, NL2InfluxDB
performs best on Hybrid Similarity and Hill Diversity, likely due to its
balanced query-family sampling.

\(3\) Query Complexity. Among baselines, OmniSQL and TACO produce the
most complex queries, consistent with their complexity-oriented designs,
while DeepSeek produces the simplest. SQL-Factory and NL2InfluxDB also
show relatively low complexity. This trend contrasts with the diversity
results, potentially because complex queries share more common SQL
structures. In contrast, TSSDA achieves the best results in both
complexity and diversity.

\(4\) TSSQL Coverage. TSSDA achieves the highest coverage, benefiting
from its broad generation space and highly autonomous Agent, which
facilitate exploration of previously unexplored query features. In
contrast, TACO performs worst, indicating that its limited skeleton set
constrains generation beyond predefined patterns.

\(5\) Ablation Analysis. Removing adaptation causes the largest
degradation on most metrics, highlighting its central role in
effectiveness. Dependency removal also degrades performance, supporting
the value of semantic constraints and dependency context. Removing
memory yields only minor changes, including slight gains on some
metrics, suggesting that memory, designed to improve efficiency through
experience reuse, largely preserves effectiveness.

## 8. Related Work

### 8.1. Data Generation for NL2SQL

Data generation for NL2SQL can be broadly divided into two categories:
NL2SQL benchmark construction and SQL generation. We discuss these two
categories in detail below.

NL2SQL benchmark construction: Early NL2SQL benchmarks ([Yu et al.,
2018](#bib.bib13); [Li et al., 2023](#bib.bib12); [Yu et al.,
2019](#bib.bib40); [Lee et al., 2021](#bib.bib35)) relied mainly on
manual collection and annotation. However, manual construction requires
substantial human effort and becomes particularly inefficient in the era
of LLMs. To address this limitation, prior work has explored automated
benchmark generation through predefined templates or data augmentation.
DBPal ([Weir et al., 2020](#bib.bib36)) generates NL–SQL pairs by
instantiating templates with schema elements, while HIER ([Wu et al.,
2021](#bib.bib37)) synthesizes SQL from abstract syntax trees and
generates questions using a neural model. With the rise of LLMs, recent
work ([Wenz et al., 2026](#bib.bib66); [Saparina and Lapata,
2024](#bib.bib38); [Koukouvinis et al., 2026](#bib.bib39); [Malekpour et
al., 2026](#bib.bib67); [Jin et al., 2026](#bib.bib68)) has increasingly
leveraged LLMs to assist benchmark construction. CLARITY ([Sarwar et
al., 2026](#bib.bib9)) uses a schema-constrained LLM to generate
ambiguous queries and multi-turn conversations from Spider and BIRD
seeds. SQL-Exchange ([Daviran et al., 2026](#bib.bib76)) employs
template-guided query transformations to generate samples through
cross-database transfer. However, these approaches still rely on seed
data or templates, with LLMs primarily serving as auxiliary tools.
Moreover, none of the above approaches target TSDBs. Accordingly, a few
studies have begun to investigate generating time-series queries from
natural language for TSDBs. TEFD ([Wu et al., 2026](#bib.bib5))
synthesizes Flux ([, 2026](#bib.bib2)) queries from manually predefined
query templates. However, Flux is a pipeline-oriented query language
rather than an SQL dialect. NL2InfluxDB ([Dranca et al.,
2026](#bib.bib3)) provides InfluxDB ([, 2026](#bib.bib2)) documentation
to an LLM and directly generates queries. However, it produces only a
small dataset through direct LLM synthesis, limiting systematic
evaluation.

SQL generation: Beyond NL2SQL benchmark construction, SQL generation
also involves automated query synthesis, but primarily aims to generate
large-scale SQL workloads. Early SQL generation methods construct
workloads by instantiating predefined templates or grammars ([Slutz,
1998](#bib.bib43); [Poess and Stephens, 2004](#bib.bib44); [Nambiar and
Poess, 2006](#bib.bib42)). TPC-H ([Pöss and Floyd, 2000](#bib.bib41))
samples parameters for expert-designed query templates over a fixed
schema. JOB ([Leis et al., 2018](#bib.bib45)) grounds workloads in
real-world data using 33 query structures with predicate variants, while
DSB ([Ding et al., 2021](#bib.bib46)) extends TPC-DS ([Nambiar and
Poess, 2006](#bib.bib42)) with configurable workload distributions to
guide parameter instantiation. Despite increasing workload realism and
control, these methods remain constrained by predefined query
structures. Recent methods ([Davitkova and Michel, 2026](#bib.bib73);
[Yang et al., 2024](#bib.bib6); [Schmidt et al., 2025](#bib.bib10); [Lao
and Trummer, 2026](#bib.bib47)) use LLMs to enable more flexible and
scalable query synthesis. OmniSQL ([Li et al., 2025a](#bib.bib4)) builds
databases from web tables and synthesizes 2.54M pretraining samples
through LLM-based CoT. SQL-Factory ([Li et al., 2025b](#bib.bib8))
introduces a multi-agent framework for data generation, expansion,
rewriting, and validation. However, although these approaches introduce
LLM-based agents, their autonomy remains largely confined to predefined
pipelines and procedures. Consequently, they cannot autonomously control
the generation process according to the evolving data environment,
limiting data coverage and diversity. In contrast, we model the entire
generation process as an interactive and explorable data space,
transforming the agent from a passive data consumer into a Data Agent
capable of exploring, orchestrating, and managing data generation.

### 8.2. NL2SQL Methods

Early NL2SQL methods ([Li and Jagadish, 2014](#bib.bib48); [Saha et al.,
2016](#bib.bib49)) mapped natural language to SQL using hand-crafted
semantic representations and domain knowledge. With the advancement of
neural networks, subsequent studies ([Fu et al., 2023](#bib.bib50);
[Wang et al., 2020](#bib.bib51); [Scholak et al., 2021](#bib.bib52);
[Veltri et al., 2023](#bib.bib72)) began to predict SQL using
architectures such as LSTMs and attention mechanisms. However, limited
model capabilities and generalization constrained their practical
applicability. The emergence of LLMs substantially accelerated the
development of NL2SQL ([Gao et al., 2024](#bib.bib23); [Fan et al.,
2024](#bib.bib70)). DIN-SQL ([Pourreza and Rafiei, 2023](#bib.bib24))
employs in-context learning to decompose Text-to-SQL into multiple
modules, such as schema linking and SQL generation. FINER-SQL ([Hoang et
al., 2026](#bib.bib71)) enhances SLMs through reasoning distillation and
reinforcement learning with fine-grained execution feedback. More recent
studies ([Gong et al., 2025](#bib.bib75); [Pourreza et al.,
2025](#bib.bib69); [Pramanik et al., 2026](#bib.bib74)) have
increasingly focused on multi-stage reasoning. OpenSearch-SQL ([Xie et
al., 2025](#bib.bib22)) introduces a four-stage workflow with an
alignment mechanism to maintain pipeline consistency. DeepEye-SQL ([Li
et al., 2026](#bib.bib21)) follows the software development lifecycle,
integrating predefined reasoning, deterministic verification, and
execution-aware selection. However, these methods focus on schema
grounding and reasoning in relational databases, leaving TSSQL syntax
and semantics, temporal operators, and specialized TSDB schemas
insufficiently addressed.

## 9. Conclusion

We present TSSDA, a Data Agent framework for Text-to-TSSQL data
generation, and construct TERN, a large-scale benchmark. First, we
systematically model TSSQL syntax and semantics to construct a data
generation space, ensuring broad coverage and validity. Next, we develop
a Data Agent that autonomously explores and orchestrates data generation
through continuous decision-making, query generation, and adaptation,
improving data diversity and complexity. Finally, we design a
temporal-aware memory mechanism that improves generation efficiency by
reusing historical experience. Extensive experiments on real-world
industrial datasets demonstrate that Text-to-TSSQL remains challenging,
while TSSDA shows the best performance among the baseline methods.
````
