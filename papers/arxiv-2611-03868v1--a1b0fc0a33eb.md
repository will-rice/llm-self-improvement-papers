###### Abstract

With the rise of Group Agent such as Claude Tag, agents increasingly
serve as digital workers for long-term team collaboration. These agents
operate over shared contexts that continuously accumulate through
multi-user interactions. However, existing agent memory systems are
mainly designed for individual users and struggle to capture group-level
knowledge in shared contexts, including group relationships and
collaboratively formed knowledge. Manual memory strategies further limit
adaptation to diverse and evolving shared contexts. To this end, we
propose EvoGroup (EvoG), a self-evolving harness for group agents that
starts from a minimal six-tool cold start and adapts through interaction
with shared context. EvoG uses confidence and task outcomes to select
informative trajectories, while also eliciting self-reflections on
uncertainty in low-confidence cases. The analysis agent then examines
selected trajectories through adaptive progressive disclosure, followed
by bucketed analysis to synthesize high-level findings that guide the
evolve agent in revising the Harness. Empirically, pass@1 on held-out
split of EverMemBench improves from 71.07% to 89.58%, surpassing both
self-evolving memory and human-designed harnesses, including Claude Code
(85.83%). To evaluate generalization, we freeze the evolved harness and
evaluate it on the unseen GroupMemBench, where, with GPT-5.5, it
demonstrates effective generalization and outperforms both memory
baselines and human-designed harnesses.¹¹ 1 The code for this manuscript
is available at
[https://github.com/BigggFatttRabittt/EvoGroup](https://github.com/BigggFatttRabittt/EvoGroup).

## 1 Introduction

AI agents are gradually evolving from conversational assistants designed
for individual users into digital workers that directly participate in
multi-user interactions and team collaboration ([OpenAI,
2026b](#bib.bib18); [Spataro, 2025](#bib.bib22); [Anthropic,
2026](#bib.bib3)). In sustained multi-user collaboration, shared
contexts continuously accumulate and evolve through interactions among
multiple users. This makes memory essential for agents to accurately
extract and apply relevant information from long-term conversations. A
Group Agent must not only understand current messages but also integrate
discussion topics, key events, member roles, and group decisions from
prior interactions.

However, most existing agent memory systems are designed for single-user
settings, organizing memory around individual experiences, preferences,
and interaction histories ([Park et al., 2023](#bib.bib20); [Zhong
et al., 2024](#bib.bib31); [Packer et al., 2023](#bib.bib19)). In group
settings, information is distributed across multiple users, topics, and
reply threads, and events may be supplemented or reinterpreted by
different members. These characteristics make it difficult for existing
memory systems to capture group dynamics and collaboratively formed
knowledge ([Yang et al., 2026a](#bib.bib27)). In addition, existing
memory systems typically predefine how memory is represented, updated,
and retrieved ([Chhikara et al., 2025](#bib.bib6); [Liu et al.,
2026](#bib.bib14)). For example, interaction histories may be stored in
vector databases ([Chhikara et al., 2025](#bib.bib6)) or organized as
knowledge graphs ([Anokhin et al., 2024](#bib.bib1)), with fixed
mechanisms for updating outdated or conflicting information ([Fang
et al., 2026](#bib.bib8)). When group structures, shared contexts, or
task requirements change, adapting these systems often requires
redesigning their memory storage or retrieval mechanisms. Such
predefined designs limit the ability to adapt to different groups.

To address these challenges, we propose EvoGroup (EvoG), a self-evolving
harness framework for Group Agent memory. EvoG starts from a minimal
harness with only six tools and evolves through interaction. The
evolution loop consists of four stages. (1) Interaction. The Group Agent
uses the harness to answer queries over accumulated shared contexts,
producing trajectories and confidence scores. For low-confidence
queries, the agent additionally reflects on the reasons for its
uncertainty before accessing the ground-truth. (2) Trajectory Selection.
EvoG combines confidence with official evaluation to identify
informative trajectories, including confident-incorrect,
unconfident-correct, and unconfident-incorrect. (3) Analysis. The
analysis agent uses Adaptive Progressive Disclosure (APD) to analyze
selected trajectories, accessing trajectory details only when necessary.
The agent also compresses detailed rationales into concise rationales.
To identify recurring issues across trajectories, the agent performs
bucketed analysis by grouping rationales according to inferred query
semantics and further aggregating them into high-level findings. (4)
Revision. Finally, the evolve agent uses analysis outputs to revise the
Harness, producing $`H_{t+1}`$ for the next round of interaction.
Through this loop, EvoG enables the harness to continuously adapt to the
group and shared context.

![Refer to caption](2611.03868v1/EvoWorkspace_Self_Evolution_Loop.png)

Figure 2: Overview of the EvoGroup loop, which operates in four phases:
I) Interaction, which Group Agent collaborates with shared contexts; II)

Revision, which updates harness through four interfaces.

We conduct extensive experiments to evaluate the effectiveness of EvoG.
After evolution, the pass@1 of DeepSeek-V4-Flash on held-out split of
EverMemBench improves from 71.07% to 89.58%, outperforming the
human-designed Harnesses Codex (82.62%) and Claude Code (85.83%), as
well as the strongest self-evolving memory baseline (55.95%). Across two
additional backbone models, EvoG consistently improves pass@1 by
15.36–16.19 pp. To evaluate generalization beyond the evolution
distribution, we freeze the evolved harness and apply it to
GroupMemBench without further adaptation, where it continues to
outperform self-evolving memory baselines and Claude Code. We further
conduct component and process-level ablations and analyze capability
transitions, confidence, self-reflection, APD analysis, and harness
revisions to better understand how EvoG evolves. Together with our
findings and open-source release, we hope EvoG inspires future efforts
toward more capable and adaptive Group Agents.

## 2 EvoGroup

In this section, we propose EvoGroup (EvoG), a self-evolving harness
loop for Group Agent Memory over shared contexts, as illustrated in
Figure [2](#S1.F2 "Figure 2 ‣ 1 Introduction ‣ EvoGroup: A Self-Evolving Harness for Group Agents in Shared Contexts").

### 2.1 Interaction over Shared Contexts

In multi-user shared contexts, fixed memory organization and strategies
struggle to adapt to evolving group information and task requirements.
To address this limitation, EvoGroup enables self-evolution by treating
the harness itself as the object of evolution.

Specifically, EvoGroup starts from a minimal modular harness $`H_{0}`$.
The initial harness is equipped with only six basic tools: list_files,
read_file, grep_search, write_file, query_records and create_file. From
this cold start, EvoGroup repeatedly cycles through four stages:
_interaction_, _trajectory selection_, _analysis_, and _revision_,
allowing the harness to progressively accumulate memories and skills
from interaction experience and thereby producing a sequence of
increasingly capable harnesses:

|     |     |     |     |
| --- | --- | --- | --- |
|     |

       ``` math
       H_{0},H_{1},\ldots,H_{T}.
       ```                        |     | (1) |

At iteration $`t`$, the Group Agent interacts with a shared group
context and solves tasks using the current harness $`H_{t}`$. For a
query $`q_{i}`$, the interaction produces an answer $`a_{i}`$ and a
trajectory

|     |     |     |     |
| --- | --- | --- | --- |
|     |

````math
\tau_{i}=\bigl(q_{i},o_{i}^{1},u_{i}^{1},\ldots,o_{i}^{L_{i}},u_{i}^{L_{i}},a_{i}\bigr),
``` |  | (2) |

where $`o_{i}^{\ell}`$ denotes the information observed at step $`\ell`$
and $`u_{i}^{\ell}`$ denotes the corresponding reasoning, communication,
or tool-use action. The trajectory therefore records not only the final
response, but also the intermediate decisions through which the Group
Agent uses the components of $`H_{t}`$.

Along with its answer, the Group Agent reports a subjective confidence
score $`c_{i}\in[0,1]`$. We use a threshold $`\gamma`$ (set to $`0.5`$
in
Figure [2](#S1.F2 "Figure 2 ‣ 1 Introduction ‣ EvoGroup: A Self-Evolving Harness for Group Agents in Shared Contexts"))
to distinguish confident from unconfident responses. If
$`c_{i}\leq\gamma`$, EvoGroup asks the Group Agent to revisit its
reasoning and explain the source of its uncertainty. This
self-reflection is generated before any supervision is revealed: neither
the ground-truth answer nor the official evaluation result is provided
to the agent. Consequently, the reflection captures the agent’s own
diagnosis.

### 2.2 Confidence-Guided Trajectory Selection

During continuous interaction, different trajectories provide different
evolutionary signals for self-evolution. We therefore combine the
Agent’s confidence with official evaluation results to select
informative trajectories.

After the interaction, an official evaluator supplies an external
correctness signal $`y_{i}\in\{0,1\}`$ for the answer $`a_{i}`$.
Combining $`y_{i}`$ with the confidence indicator
$`z_{i}=\mathbf{1}[c_{i}>\gamma]`$ partitions the collected trajectories
into four groups:

|  |  |  |  |  |
|----|----|----|----|----|
|  | $`\displaystyle\mathcal{D}_{\mathrm{CC}}`$ | $`\displaystyle=\{\tau_{i}\mid z_{i}=1,\;y_{i}=1\},`$ |  | (3) |
|  | $`\displaystyle\mathcal{D}_{\mathrm{CW}}`$ | $`\displaystyle=\{\tau_{i}\mid z_{i}=1,\;y_{i}=0\},`$ |  |  |
|  | $`\displaystyle\mathcal{D}_{\mathrm{UC}}`$ | $`\displaystyle=\{\tau_{i}\mid z_{i}=0,\;y_{i}=1\},`$ |  |  |
|  | $`\displaystyle\mathcal{D}_{\mathrm{UW}}`$ | $`\displaystyle=\{\tau_{i}\mid z_{i}=0,\;y_{i}=0\}.`$ |  |  |

The confident-and-correct subset $`\mathcal{D}_{\mathrm{CC}}`$
represents routine successful behavior and is not prioritized for
diagnosis. EvoGroup instead selects

|  |  |  |  |
|----|----|----|----|
|  |
``` math
\mathcal{D}_{\mathrm{sel}}=\mathcal{D}_{\mathrm{CW}}\cup\mathcal{D}_{\mathrm{UC}}\cup\mathcal{D}_{\mathrm{UW}},
``` |  | (4) |

which covers three complementary signals. Confident but incorrect
trajectories reveal undetected reasoning failures or answer biases;
unconfident but correct trajectories indicate fragile successes; and
unconfident and incorrect trajectories capture failures that the Group
Agent can partially recognize.

### 2.3 Trajectory Analysis

Agent trajectories contain numerous tool calls, observations, and
shared-context details, making it difficult to locate the evidence
responsible for a failure. EvoGroup addresses this challenge at two
levels: it first uses *Adaptive Progressive Disclosure* (APD) to inspect
and attribute individual trajectories on demand, and then uses bucketed
analysis to aggregate recurring issues across trajectories into
high-level findings.

APD Analysis. Rather than loading an entire, potentially long
interaction into context at once, APD initially keeps the full
trajectory hidden and exposes only a compact structural view. The
Analysis Agent first locates a potentially problematic stage and then
jumps to the corresponding local segment, requesting additional
observations, actions, tool results, or communication records only when
needed. This on-demand access focuses the analysis on diagnostically
relevant evidence while reducing distraction from unrelated parts of the
trajectory.

For each $`\tau_{i}\in\mathcal{D}_{\mathrm{sel}}`$, the Analysis Agent
identifies the stage at which the behavior deviates from a reliable
solution process, attributes the observed failure or uncertainty to its
most likely cause, and produces a detailed rationale
$`r_{i}^{\mathrm{det}}`$. EvoGroup then compresses the detailed
diagnosis into a condensed rationale:

|  |  |  |  |
|----|----|----|----|
|  |
``` math
r_{i}^{\mathrm{con}}=\operatorname{Compress}\!\left(r_{i}^{\mathrm{det}}\right),
``` |  | (5) |

which retains the failure location, attributed cause, and actionable
implication while removing instance-specific details that are
unnecessary for cross-trajectory comparison.

Bucketed Analysis. To discover recurring issues beyond individual cases,
EvoGroup organizes condensed rationales according to the semantic types
of their queries. These types are not predefined. Instead, the Analysis
Agent infers a type label $`g_{i}`$ from each query, for example, user
profiling or temporal reasoning, and assigns analyses with the same
inferred type to a shared bucket:

|     |                                                       |     |     |
|-----|-------------------------------------------------------|-----|-----|
|     |
       ``` math
       \mathcal{B}_{g}=\{r_{i}^{\mathrm{con}}\mid g_{i}=g\}.
       ```                                                    |     | (6) |

The Analysis Agent first analyzes evidence within each bucket to
identify type-specific issues, and then compares the resulting issues
across buckets to derive high-level findings. The resulting condensed
rationales and high-level findings $`F_{t}`$ summarize recurring sources
of error and brittle success in the current Harness, and provide
actionable evidence for subsequent harness revision.

### 2.4 Harness Revision

To enable more comprehensive and effective harness revision, we organize
updates into four complementary interfaces: representation, operation,
intervention, and policy, each targeting a distinct aspect of harness
behavior to support continuous self-evolution from interaction.

Representation. This interface modifies how information is represented,
organized, and linked within the Harness, without changing selection
strategies. Updates include restructuring memory units, entity
relations, working memory, and the context provided to the underlying
model. Operation. This interface adds or modifies executable
capabilities and their implementations, such as introducing query tools
or revising retrieval algorithms. It determines what the harness can
execute and how each operation is implemented. Intervention. This
interface introduces checks, transformations, or constraints at
execution boundaries, such as validating tool arguments before calls,
normalizing returned results, and verifying outputs before returning
them as final answers. Policy. This interface modifies the rules
governing operation selection, timing, and ordering. Updates include
adjusting prompts, skill invocation rules, retrieval parameters, search
strategies, and operation composition and scheduling. Based on this
distinction, the Evolve Agent selects the interface or interfaces that
directly address each diagnosed issue.

## 3 Experiments

### 3.1 Setup

Benchmark & Baseline Methods. We use multi-party conversation benchmarks
to evaluate the memory capabilities of group-chat agents. EverMemBench
([Hu et al., 2026](#bib.bib10)) is divided using stratified sampling,
with 30% used as the held-in set for harness evolution and the remaining
70% used as the held-out set for evaluating the evolved harness. To
evaluate cross-benchmark transfer, we then freeze the evolved harness
and evaluate it on GroupMemBench ([Yang et al., 2026b](#bib.bib28)). We
compare EvoGroup with structured-memory and self-evolving memory
baselines, as well as human-designed agent Harnesses, including (1)
FullContext, (2) Mem0 ([Chhikara et al., 2025](#bib.bib6)), (3) MemOS
([Kang et al., 2025](#bib.bib12)), (4) A-MEM ([Xu et al.,
2025](#bib.bib25)), (5) MemRL ([Zhang et al., 2026b](#bib.bib30)), (6)
Codex ([OpenAI, 2025](#bib.bib16)), and (7) Claude Code ([Anthropic,
2025](#bib.bib2)).

Models. For the evolution iterations and frozen transfer experiments
(Sections [3.2](#S3.SS2 "3.2 Main Results ‣ 3 Experiments ‣ EvoGroup: A Self-Evolving Harness for Group Agents in Shared Contexts"),
the Group Agent, Analysis Agent, and Evolve Agent use the same base
model within each run. We evaluate three model configurations: GPT-5.5
([OpenAI, 2026a](#bib.bib17)) with the non-thinking reasoning setting,
DeepSeek-V4-Flash ([DeepSeek-AI, 2026](#bib.bib7)), and GLM-5.1 ([GLM-5
Team et al., 2026](#bib.bib9)).

### 3.2 Main Results

As shown in
Table [1](#S3.T1 "Table 1 ‣ 3.1 Setup ‣ 3 Experiments ‣ EvoGroup: A Self-Evolving Harness for Group Agents in Shared Contexts"),
we evaluate EvoGroup on GPT-5.5, DeepSeek-V4-Flash, and GLM-5.1. After
six self-evolution iterations, EvoGroup identifies the best-performing
harness configuration, denoted by $`H_{*}`$. On the held-out dataset,
compared with the initial configuration $`H_{0}`$, $`H_{*}`$ improves
the average pass rate by 16.2, 18.5, and 15.4 pp on the three models,
respectively, demonstrating EvoGroup’s ability to consistently discover
substantially better configurations. Meanwhile, EvoGroup outperforms the
Structured Memory and Self-Evolving Memory baselines, as well as Claude
Code and Codex, across all three backbones, except that its performance
on GPT-5.5 is slightly below both Codex and Claude Code. However, since
the evolution process is not limited to the number of iterations
evaluated in our experiments, further iterations may yield additional
performance gains. These results demonstrate that EvoGroup consistently
discovers substantially stronger memory harness configurations across
LLM backbones with different capabilities.

Generalization beyond the evolution benchmark. To evaluate whether the
evolved harness generalizes beyond the distribution used for evolution,
we freeze the harness evolved on EverMemBench and directly evaluate it
on the unseen GroupMemBench without further adaptation. As shown in
Table [4](#A1.T4 "Table 4 ‣ Appendix A Additional Experimental Results ‣ EvoGroup: A Self-Evolving Harness for Group Agents in Shared Contexts"),
on GPT-5.5, the evolved harness achieves the highest average pass rate
of 63.89%, outperforming the initial harness by 2.01 points and the
strongest human-designed harness by 8.46 points. On DeepSeek-V4-Flash,
it achieves 71.14%, remaining within 2.95 points of the initial harness
and 5.37 points of Codex, while outperforming the strongest memory
baseline by 28.46 points. These results show that EvoG can transfer to
an unseen benchmark while maintaining strong performance, although some
performance degradation is observed with DeepSeek-V4-Flash.

### 3.3 Ablation Study

Component-level ablations. We evaluate the contribution of each harness
component by replacing one component of the initial harness with its
counterpart from the fully evolved harness, while keeping all other
components unchanged. We consider Prompt, Tools, Middleware, Memory, and
Skills separately. As shown in
Figure [3](#S3.F3 "Figure 3 ‣ 3.2 Main Results ‣ 3 Experiments ‣ EvoGroup: A Self-Evolving Harness for Group Agents in Shared Contexts"),
Tools and Prompt provide the largest gains, improving accuracy by 10.90
and 7.41 pp, respectively. Middleware, Memory, and Skills yield smaller
gains of 1.27, 1.47, and 0.86 points. Using all evolved components
achieves 89.58% accuracy, an 18.51 pp improvement over the initial
harness at 71.07%. These results show that EvoGroup improves the harness
through multiple components rather than prompt optimization alone.

Process-level ablations. We further examine three mechanisms in the
self-evolution loop using DeepSeek-V4-Flash. All variants use the same
cold-start harness configuration, evolution set, and token budget. As
shown in
Figure [4](#S3.F4 "Figure 4 ‣ 3.2 Main Results ‣ 3 Experiments ‣ EvoGroup: A Self-Evolving Harness for Group Agents in Shared Contexts"),
removing trajectory selection increases Pass@1 from 73.33% to 74.86%,
with a peak of 75.69%. Thus, analyzing all trajectories can support
self-evolution, but requires more analysis time and greater token
consumption.

Replacing APD with full-trace analysis yields a final Pass@1 of 69.44%,
below its initial score. This suggests that, in shared-context task
settings, directly analyzing complete trajectories may introduce
irrelevant information and noise, whereas APD enables the Analysis Agent
to focus on diagnostically relevant evidence and produce more effective
evolution signals.

Removing bucketed analysis produces the lowest final Pass@1 of 67.08%.
Without cross-trajectory aggregation, individual diagnoses may miss
recurring failure patterns, resulting in more instance-specific and less
reliable harness updates.

### 3.4 Analysis of Capability Transition

To examine how model capabilities evolve during self-evolution, we
analyze task-level transitions between consecutive evolution rounds. As
shown in
Table [2](#S3.T2 "Table 2 ‣ 3.3 Ablation Study ‣ 3 Experiments ‣ EvoGroup: A Self-Evolving Harness for Group Agents in Shared Contexts"),
EvoGroup generally acquires new capabilities while retaining existing
ones, although capability stability varies across models and evolution
rounds. DeepSeek-V4-Flash maintains a retention rate above 91%, with
regression rates ranging from 5.40% to 8.36%. GPT-5.5 also exhibits
stable capability retention, with retention rates ranging from 92.5% to
94.3% and regression rates ranging from 5.7% to 7.5%. These results
demonstrate that EvoGroup can improve task-solving capabilities across
different LLM backbones while preserving most existing capabilities and
maintaining relatively low regression rates throughout the evolution
process.

### 3.5 Analysis of Confidence and Bias

We examine whether self-evolution improves both task performance and
agent confidence by grouping trajectories into the four types defined in
Section [2.2](#S2.SS2 "2.2 Confidence-Guided Trajectory Selection ‣ 2 EvoGroup ‣ EvoGroup: A Self-Evolving Harness for Group Agents in Shared Contexts").
As shown in
Figure [7](#A1.F7 "Figure 7 ‣ Appendix A Additional Experimental Results ‣ EvoGroup: A Self-Evolving Harness for Group Agents in Shared Contexts"),
for DeepSeek-V4-Flash, the proportion of confident-and-correct (CC)
trajectories increases by 15.83%, while that of confident-but-wrong (CW)
trajectories decreases by 6.25 %, indicating improvements in both task
performance and confidence calibration, despite some fluctuations across
intermediate iterations. For GPT-5.5, the proportion of CC trajectories
increases by 10.62%, while that of CW trajectories decreases by 6.04%.
Likewise, this shift indicates improved task performance and a more
favorable confidence–correctness distribution. Overall, both models
exhibit a higher proportion of confident-and-correct trajectories and a
lower proportion of confident-but-incorrect trajectories after
self-evolution.

### 3.6 Analysis of Self-reflection

To assess the agreement between self-reflection and trajectory-based
diagnosis, we adopt three measures: localization-agreement, cause
attribution-agreement, and diagnostic-evidence consistency.
Localization-agreement reaches 84.0% for DeepSeek-V4-Flash and 74.4% for
GPT-5.5, suggesting that self-reflection can often identify where a
problem likely occurs without examining the full trajectory. In
contrast, cause attribution-agreement is 49.2% and 62.0% for the two
models, while diagnostic-evidence consistency is only 7.1% and 16.8%,
respectively. These results indicate that self-reflection can provide a
valuable yet not fully reliable localization signal before the full
trajectory is read, directing the Analysis Agent toward likely problem
regions and offering a more efficient, token-saving diagnostic pathway
for harness self-evolution. Nevertheless, accurately verifying the root
cause with sufficient evidence still relies on full trajectory analysis.
Further improving the agent’s autonomous error-localization ability
could reduce this reliance and further accelerate the harness
self-evolution loop.

As shown in

## 4 Related Work

Agent Memory. Agent memory aims to store and retrieve interaction
information to support subsequent tasks ([Park et al.,
2023](#bib.bib20); [Packer et al., 2023](#bib.bib19); [Zhong et al.,
2024](#bib.bib31)). Existing methods typically organize memory using
predefined structures (e.g., trees or graphs), combined with mechanisms
such as profiling, reflection, and semantic compression ([Park et al.,
2023](#bib.bib20); [Shinn et al., 2023](#bib.bib21); [Packer et al.,
2023](#bib.bib19); [Chhikara et al., 2025](#bib.bib6); [Xu et al.,
2025](#bib.bib25); [Fang et al., 2026](#bib.bib8); [Liu et al.,
2026](#bib.bib14)). However, their memory storage and retrieval
mechanisms are relatively fixed, making it difficult to adapt memory
management to task requirements. Recent work has begun exploring
self-evolving memory by optimizing memory operations through
reinforcement learning or improving memory construction and
updating ([Yan et al., 2025](#bib.bib26); [Xu et al., 2025](#bib.bib25);
[Liu et al., 2026](#bib.bib14)). However, these methods primarily target
single-user. [Hu et al. (2026)](#bib.bib10); [Yang et al.
(2026b)](#bib.bib28) have begun to investigate group-chat memory and its
evaluation. Unlike single-user memory, group-chat memory must integrate
information distributed across speakers, sessions, and temporal states
while preserving user attribution, entity relationships, and contextual
dependencies. To overcome the limitations of single-user designs and
fixed memory paradigms, we propose EvoG, which enables memory mechanisms
to evolve continuously based on interaction feedback.

Agent harness. An agent harness is a framework that organizes memory,
planning, tools, and action policies around a foundation model to
support agent-environment interaction. ([Tang et al.,
2026](#bib.bib23)). Existing studies adapt harnesses through
self-improvement, programmatic optimization, trajectory analysis, and
code generation to improve task performance and adaptability ([Lin
et al., 2026](#bib.bib13); [Huang et al., 2026](#bib.bib11); [Chen
et al., 2026](#bib.bib5); [Zhou, 2026](#bib.bib32); [Zhang et al.,
2026a](#bib.bib29); [Ning et al., 2026](#bib.bib15); [Xu et al.,
2026](#bib.bib24); [Banu, 2026](#bib.bib4)). However, most target
coding, lacking efficient diagnostics for long interaction trajectories.
In multi-user shared contexts, evidence scattered across speakers,
sessions, and temporal states creates lengthy, interconnected
trajectories, making full-trace analysis costly and prone to irrelevant
information. To address this challenge, we propose EvoGroup.

## 5 Conclusion

In this work, we introduce EvoGroup, a self-evolving harness for group
agent memory. By treating the harness as an evolvable system and
learning evolution signals in the shared context, EvoGroup enables Group
Agents to autonomously adapt to diverse groups. Result demonstrates that
EvoGroup improves efficiency while maintaining strong performance. In
the future, we will explore more realistic collaborative scenarios with
diverse and long-term multi-user.

### A.1 Efficiency Analysis

Metric definitions. We separate online per-question cost from one-time
preparation. Online metrics are Tokens per Question (Tok.), Tool Calls
per Question (Calls), and Question Runtime (QA), each averaged over
completed trials, including both correct and incorrect answers. Trials
that terminate because of a system-level failure, timeout, crash,
exception, or missing output are excluded from all three averages. Tok.
is the sum of uncached input tokens, cached input tokens, and output
tokens attributed to a question across all model calls. Each
independently issued executable tool request counts as one call, and
parallel requests are counted individually. Requests made by sub-agents
are attributed to the parent question. Creating a sub-agent does not
itself count as a tool request. QA time is the elapsed wall-clock time
from the start of the question until completion and termination.
Cold-Start Time (Cold) is a separate one-time preparation cost before
answering. A dash denotes an unavailable or inapplicable measurement,
not zero cost.
