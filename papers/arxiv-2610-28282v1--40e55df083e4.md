###### Abstract

Multimodal large language models (MLLMs) have substantially advanced
chart understanding and reasoning, yet their performance remains highly
uneven across chart types. While modern MLLMs perform well on common
charts, their accuracy drops sharply on long-tail charts with diverse
visual structures and reasoning requirements. Tool-augmented agents can
improve complex chart reasoning by introducing specialized visual
capabilities, but manually engineering strategies and tools for the
heterogeneous and evolving long tail is difficult to scale. We introduce
ChartEvo, a recursive self-improvement framework that enables chart
agents to adapt to underperforming chart types through experience-driven
harness-level self-improvement. ChartEvo jointly evolves reusable
chart-specific Skills and executable Tools, while learning reusable
local tool-call chains to compose evolved capabilities and control the
inference overhead of tool-augmented reasoning. On long-tail charts from
ChartBench and ChartX, ChartEvo improves accuracy over its base MLLM,
Qwen3.7-Plus, by 45.6% and 32.5%, respectively, demonstrating the
effectiveness of recursive self-improvement for long-tail chart
adaptation.

## 1 Introduction

Recent advances in multimodal large language models (MLLMs) have
substantially improved chart understanding and reasoning, yielding
strong overall performance on established chart question answering (CQA)
benchmarks chartqa; chartbench. Tool-augmented approaches such as
ChartAgent chartagent further extend chart reasoning by incorporating
specialized visual tools for complex visual and numerical tasks.
However, strong aggregate performance can obscure substantial
performance disparities across chart types chartqapro; chartmind. On the
numerical question answering (NQA) task in ChartBench, Qwen3.7-Plus
achieves an average accuracy of 80.0% across 26 chart types. Among them,
17 types exceed 90% accuracy, with an average of 96.9%, whereas the
remaining nine average only 48.0%. As illustrated in
Fig. [1](#S1.F1 "Figure 1 ‣ 1 Introduction ‣ ChartEvo: Self-Evolving Agent Harnesses for Long-Tail Chart Reasoning"),
this disparity reveals a highly uneven performance distribution: while
many chart types are handled reliably, the remaining underperforming
types form a heterogeneous tail with distinct visual structures and
reasoning requirements. We refer to these persistently underperforming
chart types as _long-tail charts_. This uneven performance distribution
suggests that further progress in CQA increasingly depends on an agent’s
ability to adapt to these diverse, chart-specific capability gaps.

Addressing this heterogeneous long tail requires capable MLLMs to
continually acquire new capabilities for chart types they have not yet
mastered. One possible route is to further train the model, encoding the
missing capabilities into its parameters. However, repeatedly adapting
model parameters to address localized capability gaps across diverse
chart structures and reasoning patterns is neither naturally modular nor
readily extensible. Tool-augmented chart agents provide a more modular
alternative by introducing specialized visual operations that complement
the MLLM. Yet, existing approaches largely rely on manually predefined
tools and usage strategies, leaving the agent’s capability boundary
constrained by human engineering. As unresolved failures span diverse
chart structures and reasoning requirements, manually extending the
agent for each distinct failure mode becomes difficult to scale. This
motivates shifting long-tail adaptation from manual capability
engineering toward _autonomous capability acquisition_.

To this end, we introduce ChartEvo, a recursively self-improving chart
agent that autonomously evolves its harness to acquire and organize
capabilities for long-tail chart reasoning. An illustrative overview of
ChartEvo and its contrast with direct MLLM and fixed-tool reasoning is
shown in
Fig. [2](#S1.F2 "Figure 2 ‣ 1 Introduction ‣ ChartEvo: Self-Evolving Agent Harnesses for Long-Tail Chart Reasoning").
ChartEvo progressively accumulates reusable capabilities in its external
harness. Specifically, it jointly evolves chart-specific Skills that
capture reusable reasoning knowledge and executable Tools that expand
the agent’s visual and numerical capabilities. Skills thus encode how to
reason, while Tools extend what the agent can execute, enabling acquired
capabilities to be retained and effectively applied across related chart
instances.

Beyond capability acquisition, a complementary challenge lies in how to
efficiently organize and execute these capabilities. Conventional
ReAct-style agents repeatedly interleave reasoning, tool invocation, and
observation react. In chart reasoning, many tasks require global
reasoning to determine what should be measured, but once the target and
procedure are established, the remaining computation often consists of
locally structured visual operations with stable dependencies. Executing
each intermediate step through the ReAct loop therefore requires routing
tool outputs back through the MLLM, introducing additional model–tool
interaction overhead. We introduce Self-Evolving Local Toolchains (SELT)
to address this issue. Through SELT, ChartEvo evolves and preserves
validated local Tool compositions as reusable execution structures,
enabling structured procedures to execute with fewer MLLM-mediated tool
interactions while retaining the flexibility of dynamic Tool composition
for previously unseen cases. Skills capture reusable reasoning
knowledge, Tools expand executable capabilities, and SELT organize how
these capabilities are locally composed and executed. ChartEvo therefore
evolves not only the agent’s capability boundary but also the execution
structure through which these capabilities are applied. Comprehensive
experiments validate the effectiveness of ChartEvo for long-tail chart
reasoning and its ability to control the execution overhead of
tool-augmented reasoning. Our contributions are summarized as follows:

1. Harness Recursive Self-Improvement: We introduce ChartEvo, a
   harness-level recursive self-improvement framework that autonomously
   evolves reusable Skills and executable Tools through iterative feedback,
   enabling continual capability acquisition for long-tail chart reasoning.

2. Self-Evolving Local Toolchains: We propose SELT, extending
   harness-level self-improvement to execution structures by evolving and
   reusing validated Tool compositions, thereby reducing redundant
   model–tool interactions and improving execution efficiency in
   ReAct-style reasoning.

3. Effective and Efficient Long-Tail Chart Reasoning: On long-tail
   charts from ChartBench and ChartX, ChartEvo improves accuracy over the
   baseline MLLM by 45.6% and 32.5%, respectively, while substantially
   reducing model calls with comparable accuracy.

## 2 Related Work

### 2.1 Chart Question Answering

Early CQA studies formulated chart understanding as task-specific visual
question answering, progressing from synthetic charts and template-based
questions figureqa; DVQA to real-world charts and more complex numerical
and logical reasoning PlotQA; LEAFQA; chartqa. Vision-language
pretraining further enabled more general chart understanding through
derendering and structured representations matcha; unichart.

With the rise of MLLMs, recent studies have adapted general-purpose
models to CQA through chart-specific instruction tuning and multimodal
alignment chartllama; chartinstruct; chartassisstant, while increasingly
challenging benchmarks expose persistent limitations in precise visual
and numerical reasoning chartbench; chartx; CharXiv; chartqapro. Most
recently, ChartAgent addresses such limitations through tool-augmented
visual reasoning chartagent. However, its reliance on predefined tools
and usage strategies makes manual capability engineering difficult to
scale across long-tail charts with diverse structures and reasoning
requirements, motivating us to explore RSI for autonomously expanding
agent capabilities.

### 2.2 Recursive Self-Improvement

Recursive self-improvement (RSI) studies how AI systems leverage
self-generated experience to improve their capabilities. Existing
research explores complementary pathways, including updating model
parameters through self-generated data and reinforcement learning spin;
lsp; spell, as well as evolving the external systems that mediate agent
behavior. We focus on the latter. Gödel Agent enables agents to
recursively modify their logic and behavior, while Meta-Harness further
treats the entire agent harness as an optimization object, extending
self-improvement to the system level godel; metaharness.

Recent work increasingly instantiates such improvement through modular
and reusable agent capabilities skillsmith; coevoskill; anything2skill;
managing. SkillForge, SkillOpt, and MetaSkill-Evolve enable agents to
construct and refine reusable skills from execution
experience skillforge; skillopt; metaskill. In parallel, early studies
such as CREATOR and LATM established autonomous tool creation creator;
latm, while recent self-evolving agents increasingly incorporate
autonomous tool discovery, construction, repair, and
maintenance toolmaker; stella; toolmaking; toolscope. Building on these
advances, we jointly evolve chart-specific Skills and Tools for
long-tail chart reasoning, while learning reusable local tool-call
chains for efficient execution.

## 3 Methodology

### 3.1 Overview

ChartEvo treats the external harness of a chart-reasoning agent as the
object of continual self-evolution. Given a chart image $`I`$ and a
question $`q`$, the underlying model reasons with the current harness to
produce an answer. In ChartEvo, the harness consists of Skills, Tools,
and Self-Evolving Local Toolchains (SELT). Skills encode reusable
chart-specific reasoning and capability-use knowledge, Tools provide
executable visual and numerical operations, and SELT persist validated
compositions of Tool calls together with their execution dependencies.
Skills and Tools thus define the reasoning knowledge and executable
capabilities available to the agent, while SELT organize how these
capabilities are composed and executed.

ChartEvo formulates harness-level recursive self-improvement as an
iterative outer-loop process. Given the current harness and its
execution outcomes on chart-reasoning tasks, an agentic proposer
introduces or revises Skills, Tools, and SELT. Validated updates are
persisted into the next harness state, which is subsequently reused for
chart reasoning and serves as the basis for further harness evolution.

During self-evolution, supervision signals are used to evaluate
execution outcomes and guide harness updates. After evolution, the
resulting harness is deployed for inference on unseen chart instances.
Overall, ChartEvo instantiates the agent as a _Model + Evolving Harness_
system: the model serves as the general reasoning core, while the
harness progressively accumulates Skills, Tools, and SELT to acquire new
capabilities and more structured execution patterns for long-tail chart
reasoning.

### 3.2 Harness Recursive Self-Improvement

ChartEvo starts self-evolution from initial harness $`\mathcal{H}_{0}`$
containing a set of generic chart-processing Tools. These Tools provide
the basic primitives for bootstrapping chart reasoning, while
task-specific capabilities are progressively acquired through
self-evolution. At evolution step $`t`$, the current harness
$`\mathcal{H}_{t}`$ is used to solve a task, producing both a prediction
and its execution trajectory $`\tau_{t}`$. The agentic proposer jointly
considers the final answer, task-level evaluation feedback, and the
observed execution trajectory to analyze the behavior of the current
harness and identify components that require further improvement. This
joint observation allows the proposer to assess both task-level
correctness and the reliability of the execution process, including
cases where an apparently acceptable prediction is supported by an
unreliable trajectory.

Based on the current harness, its execution trajectory, and the
supervision available during self-evolution, the agentic proposer can
introduce new harness components or revise existing Skills, Tools, and
SELT. ChartEvo allows multiple component types to evolve jointly within
the same step, enabling coordinated updates to reasoning knowledge,
executable capabilities, and execution structures. A proposal may
therefore span multiple harness components and be evaluated as a
coordinated update to the current harness. Ground-truth answers are
available during self-evolution for task evaluation and candidate
validation, while no ground-truth solution traces are provided.

Candidate updates are validated by re-executing the task under the
updated harness. Both the resulting task outcome and the corresponding
execution trajectory are examined to determine whether the updated
harness behaves as intended. Validated components and structures are
then persisted into $`\mathcal{H}_{t+1}`$, which becomes the basis for
subsequent execution and further self-evolution. Through repeated
execution, analysis, proposal or revision, and validation, ChartEvo
recursively evolves its harness over successive tasks, such that
subsequent proposals are made over an already evolved harness.

### 3.3 Skill and Tool Evolution

ChartEvo treats Skills and Tools as two complementary carriers of
harness capabilities. Skills encode reusable reasoning and
capability-use knowledge, guiding the model in how to interpret, select,
and use available capabilities. Tools provide executable visual and
numerical operations that transform chart information into structured
evidence consumable by subsequent reasoning. Together, they define the
reasoning knowledge and executable capabilities available to the current
harness. During self-evolution, agentic proposer determines whether an
observed deficiency primarily arises from how existing capabilities are
composed and used, or from the lack of an executable evidence
capability. When the available Tools can already provide the required
information but their selection, invocation, or use does not support
correct reasoning, evolution primarily targets Skills. When the existing
Tool set cannot provide the required structured evidence, or when a Tool
exhibits incorrect behavior, insufficient coverage, or an inadequate
output interface, the proposer introduces or revises Tools. Existing
components are revised when their intended semantics remain valid,
whereas new components are introduced when the required reasoning
pattern or executable capability is semantically distinct from those
already available.

Skill and Tool evolution can be coupled within the same self-evolution
step, allowing newly introduced or revised executable capabilities to be
incorporated into corresponding reasoning and capability-use knowledge.
Candidate Skills and Tools are re-executed and validated under the
updated harness, with Tools additionally checked for executable
behavior. Validated updates are persisted in the harness and remain
available for reasoning and further evolution. While Skill and Tool
evolution expands the capabilities available to the harness, stable
multi-step execution structures over these capabilities are captured
through SELT.

### 3.4 Self-Evolving Local Toolchains

Self-Evolving Local Toolchains (SELT) persist validated Tool
compositions as reusable execution structures, avoiding repeated
reconstruction of the same Tool-call patterns through model-mediated
interaction. Each SELT represents a bounded executable transformation
with explicit inputs, outputs, execution order, and internal Tool
dependencies. The boundedness of a SELT is defined by its functional
contract: the Agent resolves the task-specific target and required
arguments, after which the SELT executes the structured transformation
and returns its designated output.

During self-evolution, the Agent can reuse an existing SELT when an
applicable execution structure is available. Otherwise, it dynamically
composes individual Tools, coordinating their execution and intermediate
results through model interactions. Validated compositions with stable
execution structures can subsequently be persisted as new SELT, while
existing SELT can be revised as Tools, Skills, or execution requirements
evolve. Unlike dynamic Tool composition, SELT delegate inter-step
parameter resolution and intermediate output propagation to the runtime,
eliminating repeated Agent planning and binding within established
Toolchains.

SELT usage is jointly mediated by Skills, the Agent, and the runtime.
Skills maintain the available SELT together with their routing and usage
knowledge. The runtime progressively discloses context-relevant
candidate SELT according to the current question, execution stage, and
accumulated observations, exposing only a relevant subset of the harness
capabilities at each decision step. The Agent selects a concrete SELT
based on question semantics, available evidence, and Skill-provided
routing knowledge, and binds the task-specific arguments required for
execution. The runtime then executes the selected SELT while enforcing
invocation constraints, Tool versions, and execution checks.

Skills and SELT therefore play complementary roles: Skills specify when
and how an execution structure should be used, whereas SELT encode its
concrete Tool composition and dependencies. Once the Agent binds the
task target, entities, and execution conditions, the selected SELT
executes the structured procedure without further model-mediated
coordination of internal Tool calls. When no applicable SELT is
available, the Agent can fall back to dynamic Tool composition, whose
successful execution may drive subsequent SELT evolution.

### 3.5 Inference with the Evolved Harness

After self-evolution, ChartEvo fixes the resulting harness and applies
it to unseen chart instances. The Agent uses the evolved Skills, Tools,
and SELT according to the current question and execution context. When
an applicable SELT is available, its persistent execution structure can
be directly reused; otherwise, the Agent can dynamically compose Tools
to complete the task. To handle unsuccessful execution, ChartEvo
supports two fallback conditions: the Agent may proactively switch to
direct visual answering when it determines that harness-assisted
reasoning can no longer proceed, or the system triggers fallback when
the maximum action budget of 15 is reached. In both cases, direct visual
answering is performed using only the original chart image and question.

## 4 Experiments

We evaluate ChartEvo on two chart reasoning benchmarks, ChartBench and
ChartX. We focus on Numerical Question Answering (NQA), which demands
precise visual evidence extraction and numerical reasoning, providing a
comprehensive evaluation of an agent’s chart reasoning capabilities. We
select 9 long-tail chart types from ChartBench and 8 from ChartX. For
each chart type, we use 100 training questions for self-evolution and
evaluate on a total of 450 test questions from ChartBench and 265 from
ChartX. Self-evolution is conducted independently for the two
benchmarks.

Following common evaluation practices in chart reasoning, we adopt a 5%
relative-error tolerance to account for uncertainty in visual
representations and numerical readings. After self-evolution, the
resulting harness is used for evaluation on the test set. For charts
with explicit numerical annotations, the Agent directly performs visual
answering.

We employ Qwen3.7-Plus as the main Agent and GPT-5.6-Sol as the agentic
proposer. The maximum Agent action budget is set to 15. We compare
ChartEvo against two groups of baselines: (1) direct MLLMs, including
DeepSeek-v4.1-Flash deepseekv41flash, Qwen3.7-Plus qwen37, Qwen3.8-27B,
Qwen3.8-Max qwen3.8, Kimi-K2.6, GPT-5.6-Luna, GPT-5.6-Terra, and
GPT-5.6-Sol gpt56; and (2) chart-specialized methods, including
DePlot deplot, TinyChart tinychart, ChartInstruct chartinstruct,
ChartVLM chartx, and ChartAgent chartagent.

### 4.1 Comparison with State-of-the-art Solvers

Tables [1](#S3.T1 "Table 1 ‣ 3.5 Inference with the Evolved Harness ‣ 3 Methodology ‣ ChartEvo: Self-Evolving Agent Harnesses for Long-Tail Chart Reasoning")

present the comparison of ChartEvo with existing methods on ChartBench
and ChartX, respectively. On ChartBench, ChartEvo achieves an average
accuracy of 93.6% across nine long-tail chart types, outperforming its
base model, Qwen3.7-Plus, by 45.6 percentage points (93.6% vs. 48.0%),
while surpassing all evaluated direct visual MLLMs and chart-specialized
models and agents. Notably, ChartEvo achieves the best performance
across all nine chart types, with eight reaching at least 90% accuracy,
demonstrating consistent improvements across diverse chart structures.
For instance, on 3D-stack charts with complex spatial structures,

## 5 Conclusion

This paper presents ChartEvo, a harness-level recursive self-improvement
framework for long-tail chart reasoning. By evolving Skills, Tools, and
Self-Evolving Local Toolchains, ChartEvo enables autonomous capability
acquisition and efficient execution. On ChartBench and ChartX, it
improves accuracy over Qwen3.7-Plus by 45.6% and 32.5%, respectively,
while SELT substantially reduce model calls without accuracy loss. These
results demonstrate the effectiveness of harness-level self-improvement
for long-tail chart adaptation.

## Limitations

The effectiveness of ChartEvo depends partly on the coverage and
diversity of the data used for self-evolution. Limited training examples
may lead to overly specialized harness components, while conservative
validation and admission criteria can restrict the acquisition of new
capabilities. Furthermore, substantial distribution shifts between
evolution and test data may limit the transferability of evolved Skills,
Tools, and SELT. Improving the robustness and generalization of
harness-level self-improvement remains an important direction for future
work.

## Appendix A Chart Question Answering Problem Formulation

Chart Question Answering (CQA) is formulated as a multimodal reasoning
task in which a system is given a chart image $`\mathcal{I}_{i}`$ and a
corresponding natural language question $`\mathcal{Q}_{i}`$, and is
required to produce an answer $`\mathcal{A}_{i}`$. In this work, we
focus on Numerical Question Answering (NQA), where the answer is a
numerical value that must be inferred from the visual and quantitative
information encoded in the chart. Solving these questions may require
identifying relevant chart elements, extracting numerical evidence, and
performing quantitative reasoning to derive the final answer.

## Appendix B Experimental Details

### B.1 Benchmark Selection and Data Organization

We evaluate ChartEvo on two chart question-answering benchmarks,
ChartBench and ChartX, both of which cover diverse chart types and
provide numerical question-answer pairs. We focus on Numerical Question
Answering (NQA) and select chart types where the base model exhibits
relatively weak performance for subsequent self-evolution and
evaluation.

Specifically, we first evaluate Qwen3.7-Plus on the randomly selected
100 questions from train splits of ChartBench and ChartX to obtain
per-type NQA accuracy. Chart types with a baseline accuracy below 85%
are selected as long-tail chart types. This procedure yields 9 chart
types from ChartBench and 8 from ChartX.

For each selected chart type, we use 100 training questions to drive
harness-level self-evolution and evaluate the evolved system on the
corresponding test questions. Self-evolution is conducted independently
for ChartBench and ChartX, with separate evolving harnesses for the two
benchmarks. The resulting evaluation sets contain 450 NQA questions
across 9 chart types in ChartBench and 265 NQA questions across 8 chart
types in ChartX.

### B.2 Self-Evolution Implementation

#### B.2.1 Training Organization.

For each long-tail chart type, we partition 100 training questions into
10 clusters of 10 questions each. Self-evolution proceeds sequentially
across clusters, with the current harness used to execute the tasks in
each cluster. The resulting answers, correctness feedback, and execution
trajectories are collected to guide subsequent analysis and evolution.
Within each cluster, harness evolution may involve multiple iterations.
After each update, the system re-evaluates relevant tasks to assess
whether previous failures have been resolved and continues refining the
harness to address remaining failures. Once most failures within the
cluster have been addressed, the process advances to the next cluster.
Verified and accepted harness updates are persisted, allowing subsequent
clusters to build upon the accumulated Skills, Tools, and SELT.

#### B.2.2 Failure Analysis and Harness Updates

Failure Identification. After completing each training cluster, the
system identifies tasks requiring further investigation based on final
answers, correctness feedback, and execution trajectories. For NQA
tasks, predictions with a relative error exceeding 5% are marked as
incorrect, while ground-truth values of zero are handled separately to
avoid division by zero. Additionally, predictions with errors between 3%
and 5% are flagged for further inspection, as numerically correct
answers may still arise from unreliable execution trajectories. Beyond
answer correctness, the system also examines fallback behavior and the
task coverage of existing Tool-call chains. Together, these signals
identify tasks that are not yet reliably handled by the current harness
and guide subsequent evolution.

Failure Clustering and Trajectory Analysis. The agentic proposer
analyzes the collected execution trajectories to identify recurring
failure patterns across training questions. Rather than relying solely
on numerical discrepancies, the analysis considers the Agent’s action
sequences, Tool invocations, and returned observations to locate the
underlying sources of failure. These may include incorrect Tool
selection, parameter binding, or evidence utilization despite sufficient
existing capabilities; missing Tools for extracting necessary visual or
numerical evidence; or ineffective execution order and information
dependencies across multiple Tool calls. By clustering failures with
shared characteristics, the proposer identifies recurring capability
gaps that can guide reusable harness improvements across tasks.

Harness Updates and Verification. Based on the identified failure
patterns, the agentic proposer proposes targeted harness updates by
revising existing Skills, Tools, and SELT or introducing new components.
A single evolution iteration may jointly update multiple component types
to coordinate capability acquisition, capability utilization, and
execution structure. Candidate updates are evaluated by re-executing
relevant training tasks with the modified harness and examining both
answer correctness and the resulting execution trajectories.
Verification considers whether previous failures have been resolved,
whether the Agent correctly invokes the updated components, whether Tool
executions produce useful evidence, and whether tasks previously
unsupported by harness-based reasoning become solvable. Accepted updates
are persisted, while remaining failures may trigger further rounds of
analysis and evolution within the same training cluster.

## Appendix C Harness Specifications

### C.1 Harness Representation and Organization

ChartEvo organizes the capabilities acquired through self-evolution into
a persistent harness comprising Skills, Tools, and Self-Evolving Local
Toolchains (SELT). Each component adopts a representation suited to its
role. Skills are stored as metadata-annotated textual knowledge,
specifying applicability conditions, reasoning guidance, and knowledge
for capability selection and utilization. Tools are registered as
executable components with explicit input and output interfaces for
visual and numerical processing. SELT preserve validated Tool-call
compositions as reusable execution structures with defined functional
contracts, execution order, and internal dependencies. Together, these
components form an extensible collection of capabilities accessible to
the Agent during reasoning.

Harness components are connected through explicit references that
coordinate knowledge, executable capabilities, and execution structures.
Skills provide reasoning guidance for particular chart structures and
question types, together with the selection and usage knowledge of
relevant Tools and the registration and routing information of SELT.
Guided by these Skills, the Agent can invoke individual Tools,
dynamically compose multiple Tool calls, or reuse persisted SELT. Each
SELT specifies its constituent Tool calls, execution order, and
parameter dependencies across steps, enabling multiple executable
capabilities to operate within a predefined structure. These
cross-component references allow reasoning knowledge, executable
capabilities, and execution structures to be organized and utilized
together.

Verified and accepted harness updates are persisted in the corresponding
asset stores and remain available throughout subsequent training stages
and inference tasks. Existing components may be revised to accommodate
new capability requirements, while new Skills, Tools, or SELT can be
introduced to extend the range of supported tasks and execution
patterns. When an evolution iteration involves multiple component types,
their associated guidance, executable capabilities, and execution
structures can be updated jointly and retained as interconnected assets.
This persistent organization enables the harness to accumulate reusable
capabilities across successive evolution iterations and supports
subsequent reasoning with the expanded capability repertoire.

### C.2 Hierarchical Retrieval and Progressive Disclosure

As the harness evolves, its growing collection of Skills, Tools, and
SELT introduces an increasing amount of potentially relevant knowledge
and executable capabilities. ChartEvo employs hierarchical retrieval and
progressive disclosure to construct a task-relevant execution context,
selectively exposing harness information according to task
characteristics and evolving execution states.

ChartEvo adopts a two-stage retrieval mechanism to select relevant
Skills without loading the entire Skill Store. In the first stage, Skill
frontmatter metadata is used to filter and rank candidates based on
chart type, question characteristics, and applicability conditions. Only
the selected Skills are subsequently loaded for reasoning. For each
question, the system retrieves at most three Skills, comprising up to
one universal Skill and two chart-specific Skills, with a combined
Skill-body budget of 1,600 tokens. Near-duplicate Skills with similarity
exceeding 0.80 are suppressed, while chart- or feature-specific matches
are prioritized over overly general or mismatched candidates. This
mechanism limits the knowledge introduced into the Agent’s context while
preserving guidance relevant to the current reasoning task.

Beyond initial retrieval, ChartEvo progressively discloses Skill content
according to observed execution states. Each Skill may contain general
routing guidance alongside conditional instructions associated with
different Tool outcomes. At the beginning of a task, the Runtime exposes
only the initial routing guidance rather than all possible execution and
recovery branches. As reasoning proceeds, Tool outcomes such as
accepted, rejected, and argument_error trigger the disclosure of
corresponding Skill branches. Instructions associated with unobserved
conditions remain hidden. Consequently, a Skill can encode normal
execution, error handling, and recovery guidance while exposing only the
instructions relevant to the current stage of reasoning.

ChartEvo organizes executable capabilities through a two-level Tool
Catalog. The overview level provides the names and concise functional
descriptions of all registered Tools, allowing the Agent to discover
available capabilities. The detail level selectively exposes complete
interfaces for a small set of relevant Tools, including input schemas,
output fields, invocation constraints, and usage examples. During
initial context construction, at most six detailed Tool interfaces are
disclosed; after context refresh, this limit is reduced to four.
Candidate selection incorporates signals from the retrieved Skills,
Tools referenced by relevant SELT, question semantics, recently invoked
Tools, and Tools associated with preceding execution failures. This
separation preserves broad capability discoverability while limiting the
context occupied by detailed executable interfaces.

The set of available SELT is further restricted by the retrieved Skills
and task-specific applicability conditions. The Runtime first collects
SELT references from the selected Skills and then filters candidates
according to chart metadata, question semantics, and parameter
bindability. An eligible SELT must satisfy its chart applicability
conditions, match relevant question terms, and admit the binding of
required selectors from the question, legend, or axis metadata.
Candidates with unresolved references, ambiguous identifiers, or
unsatisfied execution prerequisites are excluded from the available SELT
catalog. The remaining SELT are presented to the Agent as reusable
execution structures, from which the Agent may select an appropriate
composition for the current task.

Together, these mechanisms enable ChartEvo to organize an expanding
harness into a compact, task-relevant reasoning context. Skill
knowledge, executable Tool interfaces, and reusable SELT are disclosed
selectively, with subsequent guidance adapting to observed execution
states.

### C.3 Harness Execution and Runtime Contracts

Following harness retrieval and disclosure, the Agent selects individual
Tools, reuses existing SELT, or dynamically composes Tool calls based on
the current question, chart information, and accumulated observations.
For individual Tools, the Agent constructs invocation arguments using
relevant chart elements, data series, axis information, and available
evidence. For SELT, the Agent determines whether the functional contract
matches the current task and binds the required external parameters,
while the internal execution order and parameter dependencies are
predefined by the persisted composition. This separation allows the
Agent to retain control over semantic decisions and capability selection
while delegating predefined execution procedures to the Runtime.

The Runtime executes the selected harness capabilities and validates
their outputs against the corresponding contracts. For individual Tools,
it performs the requested operations using the Agent-provided arguments
and returns structured visual or numerical evidence. For SELT, the
Runtime executes the constituent Tool calls sequentially according to
the predefined composition, resolves parameter dependencies across
steps, and aggregates the resulting observations. These internal Tool
calls proceed without requiring a separate Agent decision at each step,
reducing repeated MLLM–Tool interactions. Both individual Tools and SELT
are subject to contract validation, including input/output interface
constraints and component-specific functional requirements. Successful
execution alone does not guarantee that the resulting evidence is
accepted; the outputs must also satisfy the corresponding validity
conditions before being used in subsequent reasoning. This
contract-aware execution mechanism provides the Agent with structured
evidence accompanied by explicit acceptance states.

After execution, the Runtime returns the resulting observations and
execution states to the Agent. Outputs satisfying the applicable
contracts are marked as accepted, allowing the Agent to incorporate the
evidence into subsequent numerical reasoning or Tool invocations.
Outputs that fail the relevant acceptance conditions are marked as
rejected, while invalid invocation arguments produce states such as
argument_error. Based on this feedback, the Agent may revise arguments,
select alternative Tools, reorganize subsequent execution steps, or
proceed with the available evidence. These execution states also inform
the conditional Skill disclosure mechanism described in
Section [C.2](#A3.SS2 "C.2 Hierarchical Retrieval and Progressive Disclosure ‣ Appendix C Harness Specifications ‣ ChartEvo: Self-Evolving Agent Harnesses for Long-Tail Chart Reasoning"),
providing additional guidance aligned with the observed execution
outcomes. Through this interaction, semantic reasoning and
contract-aware execution remain coordinated throughout multi-step chart
reasoning.

### D.2 Error Recovery Cases

We further investigate reasoning trajectories in which ChartEvo
encounters intermediate execution errors but ultimately reaches correct
predictions. These cases highlight how the Agent interprets Tool
feedback, revises its actions, and recovers from unsuccessful
intermediate steps.

Figure [7](#A4.F7 "Figure 7 ‣ D.3 Failure Cases ‣ Appendix D Case Study ‣ ChartEvo: Self-Evolving Agent Harnesses for Long-Tail Chart Reasoning")
illustrates two forms of recovery within a single treemap reasoning
trajectory. The Agent initially attempts rectangle-based segmentation,
which fails due to overlapping regions. It then switches to mask-based
segmentation, successfully identifying the target category and measuring
its area. A subsequent attempt to measure the total area triggers an
argument error because an incompatible parameter is supplied. After
removing the invalid argument, the Agent obtains the total area and
computes a percentage of 10.019%, closely matching the ground truth of
10%. This case demonstrates how execution feedback supports both
strategy-level adaptation and parameter-level correction without
requiring harness updates.

### D.3 Failure Cases

Finally, we examine unsuccessful reasoning trajectories to characterize
the remaining limitations of ChartEvo. These cases investigate
situations where the available harness capabilities or intermediate
observations are insufficient for reliable numerical inference, as well
as cases where the Agent fails to appropriately handle uncertain
evidence.

Figure [8](#A4.F8 "Figure 8 ‣ D.3 Failure Cases ‣ Appendix D Case Study ‣ ChartEvo: Self-Evolving Agent Harnesses for Long-Tail Chart Reasoning")
illustrates a failure on a 3D stacked bar chart. Although the target
series and category are correctly identified, the thin target segment
introduces substantial uncertainty in endpoint localization. The
measurement Tool consequently returns an estimated interval rather than
an accepted precise value. However, the Agent adopts the interval
midpoint, producing 22.2648 million against the ground truth of 20.1
million. This case highlights a remaining limitation in reasoning with
uncertain numerical evidence.
