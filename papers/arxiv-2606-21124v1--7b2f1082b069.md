###### Abstract

Conversational AI agents in Customer Experience (CX) typically suffer
from a Closed-World Constraint, ignoring high-velocity external shifts
like viral trends or outages. Ad-hoc web search attempts to bridge this
gap but often introduce prohibitive latency and context poisoning. We
introduce PulseCX, a framework that decouples knowledge acquisition from
consumption. Adopting a structure-first paradigm, PulseCX employs an
asynchronous agent to linearize signals into a Decay-Aware Temporal
Knowledge Graph (DA-TKG) governed by reinforcement–decay dynamics to
actively manage information lifecycles. By coupling this self-evolving
memory with hierarchical intent gating, PulseCX removes synchronous
search bottlenecks ($`<`$10ms overhead) and drives significant gains in
Intent Resolution (IRR) and Customer Satisfaction (s-CSAT) in dynamic
environments.

## 1 Introduction

Large Language Models (LLMs) have transformed automated Customer
Experience (CX), enabling agents that reason and act across complex
workflows. Yet most deployed agentic systems suffer from a fundamental
disconnect: they are grounded in static internal artifacts (manuals,
FAQs, dashboards) while operating in a world shaped by fast-moving
external events. This gap is most visible during high-impact
moments—such as influencer-driven PR crises or early-stage safety
incidents (e.g., widespread reports of device overheating)—where
customer perception shifts long before internal systems update. We
define this mismatch as the Closed-World Constraint: the misalignment
between an agent’s static internal state and high-velocity external
reality. In practice, this manifests as context blindness in Dynamic
intents, where successful resolution depends on external, time-sensitive
knowledge. Common attempts to bridge this gap via web search or news
APIs frequently introduce unacceptable latency and severe _context
poisoning_, flooding the inference window with noisy, dangerous or
contradictory signals which may become security risks [Chen et al.
(2024a)](#bib.bib3); [Eslami and Yu (2025)](#bib.bib4).

To address this challenge, we propose PulseCX, a framework for
selectively injecting real-time CXM context into agentic systems without
sacrificing reliability. PulseCX adopts a structure-first paradigm ([Xu
et al., 2025](#bib.bib1)), utilizing an asynchronous discovery loop to
linearize raw external signals into structured Context Objects before
they enter the reasoning window. Building on recent work on agent
memory [Hu et al. (2025)](#bib.bib5), we store these objects in a
Decay-Aware Temporal Knowledge Graph (DA-TKG) governed by
reinforcement–decay dynamics. This allows the system to actively
maintain the lifecycle of facts—amplifying persistent signals (e.g.,
outages or fraud campaigns) while allowing transient noise to fade.
Together, these mechanisms enable agents to resolve Dynamic intents
while preserving low latency, bounded noise and poisoning signals , and
reduced hallucination risk.

## 2 Related Work

Agent Memory. Prior work on memory for LLM-based agents emphasizes
short-term, episodic, or long-term recall for coherence and planning,
typically assuming a static external world [Wang et al.
(2024)](#bib.bib6); [Hu et al. (2025)](#bib.bib5). Related efforts
augment LLMs with temporal knowledge by injecting facts from predefined
Temporal Knowledge Graphs into prompts or aligning model representations
with TKG embeddings (e.g., TimeR4 [Chen et al. (2024b)](#bib.bib14) and
GenTKGQA [Gao et al. (2024b)](#bib.bib13)), but these approaches
primarily target temporal reasoning for QA tasks rather than maintaining
a lightweight, continuously evolving world-state memory for real-time
agent grounding. PulseCX instead targets _environment factual memory_,
explicitly modeling the lifecycle of external events via
reinforcement–decay dynamics. Retrieval-Augmented and Online Agents.
Retrieval-Augmented Generation (RAG) and tool-using agents extend LLMs
with external knowledge at inference time [Lewis et al.
(2020)](#bib.bib7); [Yao et al. (2023)](#bib.bib8). While effective for
factual lookup, these approaches often incur latency and introduce noise
in dynamic settings. PulseCX decouples context acquisition from
inference by asynchronously structuring external signals into bounded,
low-latency context. Related work in other ML systems have similarly
explored gated mechanisms to control how contextual signals influence
downstream optimization ([Gao et al., 2024a](#bib.bib2)). Context in CX
Systems. Most deployed CX systems rely on session history, customer
profiles, and business rules. Although effective for routine
interactions, they struggle with _Dynamic intents_ driven by rapidly
evolving external events. While prior work has emphasized the importance
of real-time context in CX systems [Kim (2022)](#bib.bib12); [Motevalli
and Razavi (2024)](#bib.bib9); [Vashishth et al. (2024)](#bib.bib10);
[Badheka (2014)](#bib.bib11), such capabilities remain largely absent in
practice. PulseCX addresses this gap by selectively injecting real-time
situational context only when required. Overall, PulseCX formalizes
real-time external context as a first-class, evolving memory substrate
rather than an ad-hoc retrieval artifact.

## 3 Methodology: The PulseCX Framework

![Refer to caption](2606.21124v1/ICLR_PulseCX_2.png)

Figure 1: PulseCX Architecture: Offline Stage: Asynchronous discovery
and world modeling via DA-TKG memory evolution. Online Stage: Real-time
intent-aware grounding and feedback-driven refinement

PulseCX decouples high-latency knowledge acquisition from real-time
inference via a two-stage architecture: an Offline Asynchronous Stage
that structures world knowledge into a Decay-Aware Temporal Knowledge
Graph (DA-TKG), and an Online Synchronous Stage that selectively grounds
user queries using this dynamic substrate, preserving contextual
awareness of the "wild" without the latency or noise of synchronous web
search.

### 3.1 Stage 1: Offline World Modeling (Structure-First)

To capture high-velocity signals without slowing down inference, we
employ a periodic Social Search Agent (SSA) that scans external sources
at fixed intervals (e.g., $`T=15m`$). This stage transforms raw noise
into structured intelligence through two phases.

Phase 1: Linearization and Context Object Creation. Raw streams from web
search or social APIs are unstructured and noisy. PulseCX enforces a
Structure-First paradigm: the SSA output is immediately linearized into
a structured Context Object. This object encapsulates not just the
information, but its provenance and scope. By formalizing the input as a
tuple $`O=\{\text{Type},\text{Scope},\text{Confidence},\text{State}\}`$,
we ensure that only high-quality signals enter the graph (see Appendix
[A](#A1 "Appendix A Context Object: The Offline Intelligence Unit ‣ PulseCX: Breaking the Closed-World Assumption in Real-Time CX")
for details).

Phase 2: Memory Evolution (Reinforcement-Decay). Unlike static
databases, the DA-TKG is self-evolving, utilizing a Reinforcement-Decay
mechanism to manage node lifecycles. To prune stale context (e.g.,
expired sales), node weight $`W`$ decays over time $`t`$:

|     |     |     |     |
| --- | --- | --- | --- |
|     |

````math
W_{t}=W_{last}\cdot e^{-\lambda(t-t_{last})}\quad\text{and}\quad W_{new}=\min(1.0,W_{decayed}+\beta\cdot C_{conf})
``` |  | (1) |

where volatility coefficient $`\lambda`$ is high for viral trends and
low for infrastructure persistence. Conversely, reinforcement constant
$`\beta`$ ensures that signals re-confirmed by the SSA (with confidence
$`C_{conf}`$) gain salience while one-off noise naturally fades. This
ensures the graph accurately reflects the current reality rather than
historical noise.

### 3.2 Stage 2: Online Synchronous Grounding

When a user queries the system, PulseCX executes a high-speed retrieval
pipeline designed to inject relevant context without introducing latency
or hallucinations. The process begins with a Hierarchical Gating Engine
that classifies the user’s intent. Static intents (e.g., “Reset
Password”) bypass the graph entirely to prevent context poisoning, while
Dynamic intents (e.g., “Why is the site slow?”) trigger retrieval. To
select the most pertinent information, we employ a Salience-Weighted
Semantic Reranker that scores candidate nodes ($`N`$) by combining their
semantic similarity to the query ($`Q`$) with their current
decay-adjusted weight ($`W_{t}`$):

|     |                                 |     |     |
|-----|---------------------------------|-----|-----|
|     |
       ``` math
       R(N)=\text{Sim}(Q,N)\cdot W_{t}
       ```                              |     | (2) |

This scoring function ensures the agent prioritizes nodes that are both
relevant and temporally active, naturally filtering out expired events
like old flash sales. The top-ranked nodes are then synthesized into a
deterministic Context Card—a structured briefing injected into the main
agent’s system prompt (see Appendix
[B](#A2 "Appendix B Context Card Synthesis and Online Injection ‣ PulseCX: Breaking the Closed-World Assumption in Real-Time CX")).
Finally, the system closes the loop via a Query Refiner that analyzes
chat logs for information gaps (e.g., unknown slang), generating
targeted search queries for the Social Search Agent’s next offline
cycle.

## 4 Experimental Evaluation

We evaluate PulseCX as a specialized grounding layer designed to bridge
the “Closed-World” gap. Our primary hypothesis is that by decoupling
intelligence gathering (Offline) from context injection (Online),
PulseCX can resolve dynamic user intents without the latency penalties
or hallucination risks inherent to naive web-search agents.

### 4.1 Experimental Setup and Baselines

We constructed a World-Lab Simulation modeling a 24-hour window with 10
distinct world events (e.g., trends, outages) and ambient noise. We
generated $`N=1,000`$ user queries split evenly between Static
(internal) and Dynamic (external-dependent) intents (see Appendix
[C](#A3 "Appendix C Intent Taxonomy and Experimental Instantiations ‣ PulseCX: Breaking the Closed-World Assumption in Real-Time CX")).
PulseCX is evaluated against two baselines: (1) Static RAG, the industry
standard utilizing fixed manuals, and (2) a Naive Online Agent, which
executes synchronous web searches ¹¹ 1
([https://platform.openai.com/docs/guides/tools-web-search](https://platform.openai.com/docs/guides/tools-web-search)).
per query. Implementation details are provided in Appendix
[D](#A4 "Appendix D Implementation Details and Hyperparameters ‣ PulseCX: Breaking the Closed-World Assumption in Real-Time CX").

of customer sentiment (s-CSAT) and support costs (Escalation Rate).
Static RAG agents typically fail in dynamic scenarios by defaulting to

Vocabulary Bridge (Revenue Driver): By mapping viral slang (e.g.,
“Glazed Donut Stick”) to internal SKUs, PulseCX converts search intent
into sales opportunities where static agents return "Item Not Found." b)
Situational Validation (Retention Driver): In "Outage" scenarios,
PulseCX preempts user frustration by acknowledging the external reality
rather than gaslighting the user with "Green" internal logs. This
validation creates trust, raising s-CSAT to 4.2 and reducing unnecessary
human handoffs by 21.7% compared to the baseline.

hours post-conclusion, leading to a sharp increase in false positives.
Restoring the Reinforcement-Decay mechanism ensured the node was pruned
at $`T+8h`$, confirming that temporal lifecycle management is essential
for maintaining trust over time.

## 5 Conclusion

PulseCX bridges the gap between static internal knowledge and dynamic
reality by formalizing unstructured signals into a Decay-Aware Temporal
Knowledge Graph (DA-TKG). Our results demonstrate that environment
factual memory is essential for navigating the volatility of the real
world. However, some limitations remain: (1) Temporal blindness bounded
by the fixed cycle time ($`T`$), which may obscure events occurring
between updates; (2) vulnerability to adversarial poisoning via
coordinated inauthentic activity; and (3) reliance on heuristic decay
parameters ($`\lambda`$) rather than learned coefficients. In
conclusion, PulseCX demonstrates that the Closed-World Constraint of
modern agents is an architectural choice, not a fundamental limitation.
By adopting a structure-first approach to real-time memory evolution, we
can build agentic systems that are not only faster and safer but also
truly aligned with the rapidly shifting reality of the human experience.

## Appendix A Context Object: The Offline Intelligence Unit

The Context Object is the fundamental unit of the DA-TKG, created
offline by the Social Search Agent (SSA). It translates unstructured
social signals into a provenance-aware format that preserves uncertainty
and scope.

### A.1 Schema Definition

Each object $`O`$ is stored as a structured metadata tuple to allow for
rapid mathematical weighting and filtering without LLM intervention.

``` ltx_verbatim
ContextObject = {
  type:            {crisis, brand, influencer, trend},
  entity_scope:    {brand, product, region, industry},
  confidence:      numeric (0.0 - 1.0),
  summary_state:   "Natural language description of the event",
  source_ref:      "Traceable pointer to the original signal",
  initial_weight:  numeric (assigned based on source volume)
}
````

### A.2 Graph Injection

When the SSA identifies a signal (e.g., a competitor flash sale), it
populates this schema. This object is then injected into the DA-TKG as a
node. The Memory Evolution logic (Phase 2) then manages this object’s
weight over time, ensuring that the "State" is only considered for
retrieval as long as it remains salient.

## Appendix B Context Card Synthesis and Online Injection

The Context Card is the bridge between the DA-TKG and the CX (Customer
Experience) agent response. To ensure our system meets the sub-400ms
latency requirement, the construction of this card relies on
deterministic logic, not runtime generation.

### B.1 Mechanism: Type-Based Playbook Mapping

The "Guidance" or "Playbook" section of the card is derived
algorithmically based on the type attribute of the retrieved Context
Object. We maintain a static mapping table of event types to safety
instructions.

| Context Object Type | Injected Playbook Logic (Deterministic)                           |
| ------------------- | ----------------------------------------------------------------- |
| CRISIS / OUTAGE     | “Priority: External Signal \> Internal Dashboard. Validate user.” |
| VIRAL_TREND         | “Bridge Vocabulary Gap. Map slang to internal SKU.”               |
| COMPETITOR_PROMO    | “Do not deny deal existence. Pivot to retention offer.”           |

Table 2: The Playbook Injection Map. This lookup occurs in almost
realtime.

### B.2 Synthesis Logic

Once the Salience-Weighted Semantic Reranker (Online Stage) identifies
the top-$`k`$ relevant Context Objects, a rendering engine combines the
dynamic data (Summary State) with the static instruction (Playbook) into
a text block.

Rendering Template:

```ltx_verbatim
[SYSTEM CONTEXT: EXTERNAL REALITY]
SITUATION: {{summary_state}}  <-- Inserted from Graph Node
RELIABILITY: {{confidence}} (Weight: {{current_salience}})
PLAYBOOK:
{{lookup_instruction(type)}}  <-- Inserted from Mapping Table
```

### B.3 Representative Example: Telecom Network Crisis

Retrieved Context Object:

- •
  type: OUTAGE
- •
  summary_state: "Hyperlocal network degradation in Austin, TX."

Final Injected Context Card:

```ltx_verbatim
[SYSTEM CONTEXT: EXTERNAL REALITY]
SITUATION: Hyperlocal network degradation in Austin, TX.
RELIABILITY: 0.98
PLAYBOOK:
- Priority: External Signal > Internal Dashboard.
- Validate user frustration; our internal maps may be lagging.
```

By treating the "Playbook" as a structural property of the event type
rather than generating it creatively, we eliminate generation latency
while ensuring the agent always adheres to safety protocols during
high-risk events.

## Appendix C Intent Taxonomy and Experimental Instantiations

To evaluate PulseCX, we formally distinguish between Static and Dynamic
intents. This distinction drives the Hierarchical Gating Engine
(Methodology Phase 3) and determines whether external context is
required.

### C.1 Definition of Intent Classes

- •
  Static Intents: Queries where the ground truth is strictly internal
  and immutable (e.g., "What is my account balance?", "Return Policy").
  Injecting external context here causes Context Poisoning.
- •
  Dynamic Intents: Queries where the ground truth is mutable and
  dependent on the external environment (e.g., "Why is the internet
  down?", "Do you match the \$5 offer?"). Relying solely on internal
  tools here causes Gaslighting or Missed Opportunity.

## Appendix D Implementation Details and Hyperparameters

To ensure reproducibility, we provide the technical specifications for
the PulseCX pipeline components, including the Social Research Agent
(SSA), the memory evolution math, and the retrieval gating parameters.

### D.1 Asynchronous Surveillance (SSA) Specifications

The Social Search Agent (SSA) is implemented as a recurring task with a
cycle time $`T=15`$ minutes.

- •
  Search Engine: The SSA utilizes the x.ai search toolset to retrieve
  high-velocity social signals.
- •
  Linearizer Model: We utilize GPT-4o-mini for the one-shot extraction
  of unstructured reports into the Context Object schema defined in
  Appendix
  [A](#A1 "Appendix A Context Object: The Offline Intelligence Unit ‣ PulseCX: Breaking the Closed-World Assumption in Real-Time CX").
- •
  Linearization Threshold: A signal is only linearized if it appears in
  at least $`N=5`$ independent sources within a single window, ensuring
  noise reduction.

### D.2 Memory Evolution: Volatility and Decay Classes

The salience of information in the DA-TKG is governed by the
Reinforcement–Decay mechanism. We categorize dynamic intents into three
Volatility Classes based on their expected information half-life in the
"wild."

|     |     |     |     |
| --- | --- | --- | --- |
|     |

       ``` math
       W_{t}=W_{last}\cdot e^{-\lambda(t-t_{last})}
       ```                                           |     | (3) |

| Volatility Class   | Decay Rate ($`\lambda`$) | Half-life ($`t_{1/2}`$) | Example Intents                      |
| ------------------ | ------------------------ | ----------------------- | ------------------------------------ |
| High (Viral)       | $`0.50`$ $`h^{-1}`$      | $`\approx 1.4`$ hours   | Viral Slang, Influencer Trends       |
| Medium (Transient) | $`0.20`$ $`h^{-1}`$      | $`\approx 3.5`$ hours   | Flash Sales, Daily Promos            |
| Low (Persistent)   | $`0.05`$ $`h^{-1}`$      | $`\approx 13.8`$ hours  | Infrastructure Outages, Fraud Alerts |

Table 4: Decay coefficients ($`\lambda`$) grouped by event volatility.
High $`\lambda`$ values ensure that "fleeting" social noise is pruned
quickly to prevent context poisoning.

Reinforcement Constant ($`\beta`$): For all classes, we set
$`\beta=0.4`$. This allows a signal that is re-confirmed by a subsequent
SSA run to recover its salience weight quickly, effectively "resetting"
the forgetting curve for active events.

### D.3 Synchronous Reranker Implementation

To achieve the sub-millisecond latency required for real-time
conversation, the Salience-Weighted Semantic Reranker is implemented as
a vectorized dot-product operation rather than a heavy neural network.

- •
  Scoring Logic: The ranking score is calculated as the cosine
  similarity between the Query Embedding ($`E_{Q}`$) and the Context
  Object Embedding ($`E_{N}`$), scaled by the object’s current memory
  weight ($`W_{t}`$).
- •
  Conflict Handling: While the ranker relies on semantic similarity, the
  Epistemic Conflict (External vs. Internal mismatch) is handled
  downstream by the Context Card Generator. If a high-weight conflict
  node (e.g., "Outage") is retrieved, the generator automatically
  appends the "Priority: External \> Internal" instruction.
