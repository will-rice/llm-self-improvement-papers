###### Abstract

Large language models often solve tasks from a fully specified prompt
but degrade when the same requirements unfold over multiple turns, known
as the lost-in-conversation (LiC) gap. We trace part of this degradation
to self-contamination: intermediate assistant replies enter later
context and carry early deviations forward. Motivated by this mechanism,
we propose MAIGO¹¹ 1 Code is available at
[https://github.com/Chihaya-Anon-chan/MAIGO](https://github.com/Chihaya-Anon-chan/MAIGO).,
an on-policy self-distillation method that reduces this contamination
using history-cleaned references from the model’s own policy. For middle
turns, MAIGO removes prior assistant replies while preserving the
user-visible sharded prefix; for answer turns, it distills from paired
full-view references conditioned on the completed user-side dialogue. A
reliability weight downweights middle-turn samples that disagree with
the clean reference. MAIGO requires no verifier rewards, state labels,
or inference-time scaffolding. Under the LiC paired-view protocol with
deterministic verifiers, MAIGO improves Qwen2.5-7B-Instruct SHARDED
accuracy from 52.8 to 66.1 and the SHARDED/FULL ratio from 66.5% to
84.1%, while keeping FULL accuracy within 2.3 points. These results show
that self-contamination is a trainable component of the LiC gap.

## 1 Introduction

![Refer to caption](2605.27186v2/intro_3_single_column.png)

Figure 1: FULL-vs-SHARDED task delivery. The same requirements appear
either in one complete prompt or across turns, where earlier assistant
replies become part of the final context.

Large language models (LLMs) have shown strong ability to follow complex
instructions when all requirements are specified in a single
prompt ([Ouyang et al., 2022](#bib.bib1); [DeepSeek-AI and others,
2025](#bib.bib39); [Qwen Team, 2025a](#bib.bib45); [Qwen Team,
2025b](#bib.bib40)). In real assistant use, however, requirements are
often accumulated, clarified, and revised across multiple turns. This
conversational setting exposes the Lost-in-Conversation (LiC) gap: a
model may solve a task in the FULL view, where all requirements are
provided at once, but fail in the SHARDED view, where the same
requirements are revealed progressively before the final answer ([Laban
et al., 2026](#bib.bib15)). Because the two views contain the same task
requirements, this gap is not simply a failure of single-turn
competence, but a failure to solve from a dialogue history shaped by
both user turns and the model’s own earlier responses. This
distinguishes LiC from ordinary long-context access failures, where
relevant information may be present but used unevenly depending on where
and how it appears ([Liu et al., 2024](#bib.bib3)), and aligns with
evidence that extended reasoning depends on intermediate planning and
optimization states rather than only on the final prompt ([Zheng et al.,
2026b](#bib.bib11)). Related benchmarks also show that language models
can be sensitive to the order, structure, and ambiguity of presented
information ([Kang et al., 2026](#bib.bib18); [Wang et al.,
2025](#bib.bib20)).

Existing LiC-oriented methods improve multi-turn robustness, but they do
not directly supervise the intermediate turns where a model can
contaminate its own future context. RLSTA ([Chen et al.,
2026](#bib.bib8)), for example, anchors optimization to the single-turn
full-prompt view through scalar GRPO feedback and reports gains on
contextual inertia. Other reward-based methods, including RLAAR ([Li et
al., 2026](#bib.bib6)) and ICPO ([Wang et al., 2026b](#bib.bib37)),
shape the policy with verifiable-accuracy or illocution-calibrated
rewards, while inference-time methods such as Grounded Continuation ([He
et al., 2026](#bib.bib14)) introduce a runtime verifier. These
approaches provide answer-level rewards, full-view anchors, or runtime
checks, but they do not provide dense supervision for middle-turn
assistant replies. As a result, premature assumptions, overconfident
partial solutions, or stale intermediate states can still be written
into the dialogue history and later treated as context by the same
model. This creates a compounding self-contamination effect, analogous
to the distributional drift studied in sequential prediction and
imitation learning ([Ross et al., 2011](#bib.bib4); [Bengio et al.,
2015](#bib.bib5)).

We introduce MAIGO, an on-policy self-distillation method designed to
reduce this self-contamination. The key idea is to train the model on
references that preserve the user-visible conversational prefix while
removing the assistant outputs that could otherwise bias the reference
distribution. For middle turns, MAIGO constructs history-cleaned
references by deleting previous assistant replies but keeping the
sharded user-side prefix intact. This teaches the model how to respond
to the current conversational state without inheriting its own earlier
mistakes. For answer turns, MAIGO distills from a paired full-view
reference conditioned on the completed user-side dialogue, aligning the
final answer with the fully specified task. A reliability weight further
reduces the influence of middle-turn updates when the sampled response
diverges from the clean reference. The method requires no verifier
rewards, no additional state annotations, and no inference-time
scaffolding.

We evaluate MAIGO on Math, Actions, Database, and Code under the LiC
FULL-vs-SHARDED paired-view protocol with deterministic verifiers. On
Qwen2.5-7B-Instruct, MAIGO improves average SHARDED accuracy from 52.8
to 66.1 and raises the SHARDED/FULL ratio from 66.5% to 84.1%, while no
FULL task changes by more than 2.3 points relative to the base model.
These results show that reducing self-contamination can substantially
narrow the LiC gap without compromising performance on fully specified
tasks.

Our contributions are threefold:

- •
  We identify self-contamination from intermediate assistant replies as
  a trainable contributor to the LiC gap, connecting multi-turn
  degradation to the compounding effects of self-conditioned dialogue
  histories.
- •
  We propose MAIGO, a turn-role-specific on-policy self-distillation
  method that uses history-cleaned middle-turn references, paired
  full-view answer references, and reliability-weighted supervision to
  reduce self-contamination without verifier rewards, state annotations,
  or inference-time scaffolding.
- •
  We provide a controlled evaluation across math, tool-call generation,
  text-to-SQL, and Python code generation under the LiC paired-view
  protocol, showing substantial SHARDED gains while preserving FULL
  performance.

## 2 Related Work

#### Lost-in-Conversation and its mitigations.

LiC introduced a controlled FULL/SHARDED comparison: a task that is
solvable from a complete single-turn instruction is split into user
turns, and performance is measured after the same information has been
revealed conversationally ([Laban et al., 2026](#bib.bib15)). The key
implication is that the multi-turn gap is not explained by lack of task
competence alone. A model that solves the FULL version can still fail in
SHARDED form because of early assumptions, premature answer attempts,
over-reliance on previous attempts, and weak recovery once the missing
information arrives. A growing line of subsequent studies characterizes
this regime as a family of multi-turn state failures rather than a
single error type, including attention drift over goal tokens,
conversational inertia, and constraint or temporal-scope
violations ([Dongre et al., 2026](#bib.bib13); [Wan et al.,
2026](#bib.bib26); [Liu et al., 2026](#bib.bib36); [Canaverde et al.,
2026](#bib.bib24); [Kruthof, 2026](#bib.bib12); [Atri et al.,
2026](#bib.bib25); [Zheng et al., 2026c](#bib.bib10)). Existing
mitigations mostly attack this regime through scalar rewards, anchoring,
or runtime checks: verifiable-accuracy, abstention, or clarification
rewards ([Li et al., 2026](#bib.bib6); [Wang et al., 2026b](#bib.bib37);
[Qiu et al., 2026](#bib.bib9)), single-turn-anchor GRPO ([Shao et al.,
2024](#bib.bib38); [Chen et al., 2026](#bib.bib8)), and inference-time
dependency verification ([He et al., 2026](#bib.bib14)). MAIGO is
complementary but adopts a different lens: it treats assistant-generated
history itself as the trainable failure mode and supplies dense,
history-cleaned reference distributions on the student’s own SHARDED
rollout.

#### On-policy distillation and context-conditioned self-teaching.

On-policy distillation (OPD) trains on student-generated rollouts rather
than fixed reference outputs, reducing the train–test mismatch that can
undermine imitation in sequential decoding ([Agarwal et al.,
2024](#bib.bib27)). Its self-distilled variant (OPSD) uses the same
model as student and teacher under different contexts, with dense
token-level matching on sampled rollouts ([Zhao et al.,
2026](#bib.bib7)), while step-wise peer-based objectives provide another
form of intermediate trajectory signal ([Shi et al., 2026](#bib.bib19)).
OPSD has also been extended to context-conditioned
self-distillation ([Ye et al., 2026](#bib.bib28)) and
easier-context-to-harder-context transfer for long-context
generation ([Zhang et al., 2026b](#bib.bib29)). Beyond text-only
generation, this paradigm has also supported short-to-long recovery of
pruned LLMs and regional-to-global transfer for fine-grained multimodal
perception ([Zhang et al., 2026a](#bib.bib30); [Yuan et al.,
2026](#bib.bib31)). Recent studies further show that on-policy signals
are not uniformly reliable: peer-rollout contexts, temporal curricula,
scope-aware schedules, and teacher-choice analyses all suggest that not
every on-policy update should be weighted equally ([Yu et al.,
2026](#bib.bib33); [Wang et al., 2026a](#bib.bib34); [Zheng et al.,
2026a](#bib.bib35); [Zhu et al., 2026](#bib.bib32)). MAIGO follows this
methodological line but adapts it to sharded conversations, where the
main failure mode is self-contamination from earlier assistant replies.
Rather than using a uniform reference context, it constructs
turn-role-specific references: history-cleaned supervision for middle
turns and paired-view recovery supervision for answer turns. A
divergence-adaptive weight further modulates middle-turn updates,
connecting the method to reliability-aware OPD while targeting the
distinctive structure of multi-turn LiC failures.

Broader evaluations also probe robustness under cross-lingual factual
reasoning, multilingual hallucination mitigation, and multimodal
cultural grounding ([Zheng et al., 2026d](#bib.bib21); [Zheng et al.,
2025](#bib.bib22); [Zheng et al., 2026e](#bib.bib23)).

## 3 Method

MAIGO is an on-policy self-distillation method for sharded multi-turn
tasks. The method trains on the student’s own sharded rollouts, but
computes reference distributions under cleaner training-time contexts.
This allows the student to learn from the histories it actually induces,
while preventing its own earlier replies from contaminating the
reference signal.

The training signal has three components. First, middle turns are
supervised with history-cleaned sharded references that preserve the
user-visible prefix but remove previous assistant replies. Second, the
final answer turn is supervised with a completed-task reference that
preserves the full user-side sharded dialogue and appends a canonical
reserialization of the paired FULL specification. Third, a separate
FULL-view branch regularizes the model toward its original full-prompt
behavior. MAIGO requires no verifier rewards, no extra state labels, and
no inference-time scaffolding.

stop-gradient reference distributions computed from cleaner

### 3.1 Sharded On-Policy Setup

Each training instance contains two paired views of the same task: a
FULL specification $`x`$, and a sequence of user turns $`u_{1:T}`$ that
reveal the same requirements incrementally, following the FULL/SHARDED
setting of Lost-in-Conversation ([Laban et al., 2026](#bib.bib15)). The
final user turn $`u_{T}`$ is the answer turn. Assistant replies before
$`T`$ are not final outputs, but they remain in the dialogue history and
therefore shape the context for later turns.

The student policy $`\pi_{\theta}`$ is rolled out on the sharded
dialogue on-policy. At turn $`t`$, the student context is

|     |     |     |     |
| --- | --- | --- | --- |
|     |

````math
C_{t}^{S}=(u_{1},\hat{a}_{1},\ldots,u_{t-1},\hat{a}_{t-1},u_{t}),
``` |  | (1) |

and the student samples

|  |  |  |  |
|----|----|----|----|
|  |
``` math
\hat{a}_{t}\sim\pi_{\theta}(\cdot\mid C_{t}^{S}),\qquad t=1,\ldots,T.
``` |  | (2) |

Thus training is performed on the same self-conditioned history
distribution that can produce SHARDED failures, rather than on a clean
offline transcript.

For a sampled assistant response
$`\hat{a}=(\hat{y}_{1},\ldots,\hat{y}_{n})`$ generated under student
context $`C^{S}`$, all distillation losses use the same token-level
form:

|  |  |  |  |
|----|----|----|----|
|  |
``` math
\mathcal{D}_{\beta}(C^{S},C^{\mathrm{ref}};\hat{a})=\frac{1}{n}\sum_{i=1}^{n}d_{\beta}\!\left(P_{i}^{\mathrm{ref}},P_{i}^{S}\right),
``` |  | (3) |

where

|     |                                                      |     |     |
|-----|------------------------------------------------------|-----|-----|
|     |
       ``` math
       P_{i}^{S}=\pi_{\theta}(\cdot\mid C^{S},\hat{y}_{<i})
       ```                                                   |     | (4) |

is the student next-token distribution, and

|  |  |  |  |
|----|----|----|----|
|  |
``` math
P_{i}^{\mathrm{ref}}=\operatorname{sg}\!\left[\pi_{\theta^{-}}(\cdot\mid C^{\mathrm{ref}},\hat{y}_{<i})\right]
``` |  | (5) |

is the stop-gradient reference distribution evaluated under a
role-specific reference context $`C^{\mathrm{ref}}`$. Here
$`\pi_{\theta^{-}}`$ is an exponential-moving-average (EMA) reference
policy ([Agarwal et al., 2024](#bib.bib27); [Zhao et al.,
2026](#bib.bib7)).

The divergence $`d_{\beta}`$ follows the generalized Jensen–Shannon
divergence used in OPSD. For $`0<\beta<1`$, let

|     |                               |     |     |
|-----|-------------------------------|-----|-----|
|     |
       ``` math
       m_{\beta}=\beta p+(1-\beta)q,
       ```                            |     | (6) |

and define

|  |  |  |  |  |
|----|----|----|----|----|
|  | $`\displaystyle d_{\beta}(p,q)`$ | $`\displaystyle=\beta\,\mathrm{KL}(p\,\|\,m_{\beta})`$ |  | (7) |
|  |  | $`\displaystyle+(1-\beta)\,\mathrm{KL}(q\,\|\,m_{\beta}).`$ |  |  |

For the endpoints, we follow the OPSD convention and set
$`d_{0}(p,q)=\mathrm{KL}(p\|q)`$ and $`d_{1}(p,q)=\mathrm{KL}(q\|p)`$.
In
Eq. [3](#S3.E3 "In 3.1 Sharded On-Policy Setup ‣ 3 Method ‣ MAIGO: Mitigating Lost-in-Conversation with History-Cleaned On-Policy Self-Distillation"),
$`p=P_{i}^{\mathrm{ref}}`$ and $`q=P_{i}^{S}`$. In our reported
configuration, $`\beta_{\mathrm{mid}}=0.5`$ and
$`\beta_{\mathrm{final}}=\beta_{\mathrm{full}}=1.0`$, so the middle
branch uses the symmetric Jensen–Shannon loss, while the answer and FULL
branches use reverse KL. Gradients pass only through the student
distribution $`P_{i}^{S}`$.

The remainder of this section specifies the reference context
$`C^{\mathrm{ref}}`$ for each turn role.

### 3.2 History-Cleaned Middle-Turn Supervision

Middle turns are partial-information states. Supervising them with a
full-task reference can encourage premature solution tokens, while
supervising them with a reference that conditions on the same
assistant-generated history can inherit the student’s earlier mistakes.
MAIGO therefore uses a history-cleaned reference for every eligible
middle turn:

|  |  |  |  |
|----|----|----|----|
|  |
``` math
C_{t,\mathrm{mid}}^{\mathrm{ref}}=(\sigma_{\mathrm{sys}},u_{1},u_{2},\ldots,u_{t}),\qquad t<T,
``` |  | (8) |

where $`\sigma_{\mathrm{sys}}`$ denotes the task-specific system block
shared by the FULL and SHARDED views; no previous assistant replies,
unrevealed user turns, or full-task content appear in the reference.
Intuitively, the reference asks what the EMA reference policy assigns to
the student’s sampled middle response when the model’s own earlier
outputs are not part of the conditioning context.

The local middle-turn loss is

|  |  |  |  |
|----|----|----|----|
|  |
``` math
\ell_{t}^{\mathrm{mid}}=\mathcal{D}_{\beta_{\mathrm{mid}}}(C_{t}^{S},C_{t,\mathrm{mid}}^{\mathrm{ref}};\hat{a}_{t}).
``` |  | (9) |

The sampled tokens are generated from the student’s actual sharded
context $`C_{t}^{S}`$, keeping the update on-policy. In contrast, the
reference distribution is evaluated under the history-cleaned context
$`C_{t,\mathrm{mid}}^{\mathrm{ref}}`$, where previous assistant replies
have been removed. Thus, the loss aligns the student’s middle-turn
behavior with what the EMA reference policy would assign under a clean
user-side prefix, rather than under a context already shaped by the
student’s earlier outputs. This encourages middle-turn replies that are
less likely to introduce self-generated errors into later dialogue
context.

#### Reliability weighting.

Not every sampled middle turn provides an equally reliable reference
signal: on-policy rollouts can contain low-quality questions, verbose
partial answers, or histories that the clean sharded prefix would not
support. We therefore weight each middle turn by the realized
student–reference log-probability discrepancy on the sampled tokens. Let
$`\mathcal{I}`$ collect the pre-answer turns whose sampled replies are
non-empty and retained for token-level loss. If $`\mathcal{I}`$ is
empty, the sharded branch skips the middle loss for that example. For
each $`t\in\mathcal{I}`$, define a detached scalar

|  |  |  |  |
|----|----|----|----|
|  |
``` math
\delta_{t}=\operatorname{sg}\!\left[\tfrac{1}{m_{t}}\!\sum_{i=1}^{m_{t}}\!\big|\log P_{t,i}^{S}(\hat{y}_{t,i})-\log P_{t,i}^{\mathrm{ref}}(\hat{y}_{t,i})\big|\right],
``` |  | (10) |

where $`P_{t,i}^{S}`$ and $`P_{t,i}^{\mathrm{ref}}`$ are the student and
reference next-token distributions at position $`i`$ of middle turn
$`t`$, and $`m_{t}`$ is the number of supervised tokens in the sampled
middle reply. Intuitively, $`\delta_{t}`$ tracks how far the realized
middle response has drifted from a clean-history view of the same
on-policy state. Let
$`\mathcal{I}_{\leq t}=\{j\in\mathcal{I}:j\leq t\}`$ and
$`\delta_{j}^{+}=\max(\delta_{j},\epsilon)`$, where $`\epsilon=10^{-6}`$
provides numerical stability. We turn $`\delta_{t}`$ into a bounded
weight using the median discrepancy over eligible turns up to $`t`$,

|  |  |  |  |  |
|----|----|----|----|----|
|  | $`\displaystyle\tilde{\delta}_{t}`$ | $`\displaystyle=\operatorname{median}_{j\in\mathcal{I}_{\leq t}}(\delta_{j}^{+}),`$ |  | (11) |
|  | $`\displaystyle w_{t}`$ | $`\displaystyle=\operatorname{sg}\!\left[\frac{\tilde{\delta}_{t}}{\tilde{\delta}_{t}+\delta_{t}^{+}}\right]\in(0,1],`$ |  |  |

The form gives $`w_{t}=1/2`$ at the median and decays approximately as
$`1/\delta_{t}`$ for outliers, so middle supervision is strongest when
the sampled response stays close to the history-cleaned view and more
conservative when the trajectory has drifted far from it. This follows
the broader OPSD observation that on-policy reference signals vary in
quality across samples ([Wang et al., 2026a](#bib.bib34); [Zheng et al.,
2026a](#bib.bib35); [Zhu et al., 2026](#bib.bib32)).

The middle-turn objective for a realized trajectory is the mean over
eligible turns,

|  |  |  |  |
|----|----|----|----|
|  |
``` math
\bar{\mathcal{L}}_{\mathrm{mid}}=\frac{1}{|\mathcal{I}|}\sum_{t\in\mathcal{I}}\alpha_{t}w_{t}\ell_{t}^{\mathrm{mid}},
``` |  | (12) |

where $`\alpha_{t}`$ is a middle-turn scale, set to $`1.0`$ for all
eligible turns in our experiments. For efficiency, each trajectory
samples one eligible middle turn,
$`\tau\sim\operatorname{Unif}(\mathcal{I})`$, and uses

|  |  |  |  |
|----|----|----|----|
|  |
``` math
\mathcal{L}_{\mathrm{mid}}=\alpha_{\tau}w_{\tau}\ell_{\tau}^{\mathrm{mid}},
``` |  | (13) |

which is an unbiased single-turn estimator of
Eq. [12](#S3.E12 "In Reliability weighting. ‣ 3.2 History-Cleaned Middle-Turn Supervision ‣ 3 Method ‣ MAIGO: Mitigating Lost-in-Conversation with History-Cleaned On-Policy Self-Distillation")
under uniform $`\tau`$ when the per-turn weights are treated as detached
scalars.

### 3.3 Answer-Turn Recovery and Full-Prompt Preservation

Middle supervision alone is not enough: the target is task completion
after the required information arrives. At turn $`T`$, the student’s
context $`C_{T}^{S}`$ may still contain earlier replies that are
incomplete, speculative, or inconsistent with later user information. A
reference that conditions on the same assistant-generated history would
inherit those errors, while a reference that conditions only on the full
task view would ignore the sharded delivery the student must handle.
MAIGO therefore builds a training-only answer-turn reference context

|  |  |  |  |
|----|----|----|----|
|  |
``` math
C_{T,\mathrm{ans}}^{\mathrm{ref}}=(\sigma_{\mathrm{sys}},u_{1},\ldots,u_{T},\sigma_{\mathrm{canon}}(x)),
``` |  | (14) |

which keeps the completed user-side sharded dialogue and appends a
deterministic canonical reserialization $`\sigma_{\mathrm{canon}}(x)`$
of the paired FULL specification $`x`$ as an additional message, with
previous student replies removed before serialization (full
role-assignment details in
App. [A.3](#A1.SS3 "A.3 Training-Only Reference Views ‣ Appendix A Experimental Protocol and Reproducibility ‣ MAIGO: Mitigating Lost-in-Conversation with History-Cleaned On-Policy Self-Distillation")).
The canonical block is a reserialization of requirements already present
in the paired task; it does not add a gold answer or verifier signal.
The answer-turn loss is

|  |  |  |  |
|----|----|----|----|
|  |
``` math
\mathcal{L}_{\mathrm{final}}=\mathcal{D}_{\beta_{\mathrm{final}}}(C_{T}^{S},C_{T,\mathrm{ans}}^{\mathrm{ref}};\hat{a}_{T}),
``` |  | (15) |

and teaches solution recovery at the natural answer turn: the reference
gives the EMA reference policy a cleaner organization of the same
completed task, while the student loss is still applied to tokens
sampled from the ordinary sharded dialogue.

#### FULL-view preservation.

Because the sharded branch reshapes behavior under sharded delivery, we
preserve FULL-view capability with an EMA anchor on the FULL view. Let
$`C^{F}`$ be the full task context built from $`x`$ and sample
$`\hat{a}^{F}\sim\pi_{\theta}(\cdot\mid C^{F})`$. The student and
reference share the same FULL context here, so

|  |  |  |  |
|----|----|----|----|
|  |
``` math
\mathcal{L}_{\mathrm{full}}=\mathcal{D}_{\beta_{\mathrm{full}}}(C^{F},C^{F};\hat{a}^{F})
``` |  | (16) |

is an EMA self-anchor rather than a source of new task information; it
discourages the model from trading away competence it already exhibits
when all requirements are provided at once.

### 3.4 Training Objective

The training objective has two branches. The sharded trajectory branch
combines answer-turn recovery with weighted history-cleaned middle-turn
distillation, and the FULL-view branch acts as a preservation
regularizer:

|  |  |  |  |  |
|----|----|----|----|----|
|  | $`\displaystyle\mathcal{L}_{\mathrm{train}}`$ | $`\displaystyle=(1\!-\!z)(\mathcal{L}_{\mathrm{final}}+\mathcal{L}_{\mathrm{mid}})+z\,\mathcal{L}_{\mathrm{full}},`$ |  | (17) |
|  | $`\displaystyle z`$ | $`\displaystyle\sim\operatorname{Bernoulli}(\rho),`$ |  |  |

where $`\rho`$ controls how often the preservation branch is sampled;
with probability $`1-\rho`$, the update uses the sharded trajectory
branch. Taking the expectation over $`z`$ recovers the mixture of the
two branches. After each optimizer step, the EMA reference is updated as
$`\theta^{-}\leftarrow\lambda\theta^{-}+(1-\lambda)\theta`$ with decay
$`\lambda`$.

summarizes a training step.

|----|----|
|  Output: updated student parameters $`\theta`$. |  |
| 1 |  Sample $`z\sim\operatorname{Bernoulli}(\rho)`$. |

| 7 |  If $`\mathcal{I}\!\neq\!\emptyset`$, sample $`\tau\!\in\!\mathcal{I}`$ and set $`\mathcal{L}_{\mathrm{mid}}\!=\!\alpha_{\tau}w_{\tau}\ell_{\tau}^{\mathrm{mid}}`$; else set $`\mathcal{L}_{\mathrm{mid}}=0`$. |

### 4.1 Evaluation Setup

We follow the Lost-in-Conversation FULL-vs-SHARDED paired-view protocol:
each item has a complete-prompt view and a sharded conversational view
with the same requirements revealed across user turns ([Laban et al.,
2026](#bib.bib15)). Following LiC and subsequent LiC-based training
studies, SHARDED evaluation uses a model-assisted user simulator that
reveals at most one unrevealed shard per turn, lets the evaluated
assistant respond, and then decides whether an answer attempt should be
scored ([Laban et al., 2026](#bib.bib15); [Li et al., 2026](#bib.bib6)).
All methods use the same fixed DeepSeek-V3.1-Terminus simulator for user
turns and answer-attempt classification ([DeepSeek-AI and others,
2025](#bib.bib39)), along with the same shard files, prompts, seeds, and
deterministic scorers. Fine-tuning uses disjoint sharded training sets
of 6,400 examples for Math, Actions, and Code, and 6,397 examples for
Database. The Code training pool combines filtered DeepMind Code
Contests examples with deduplicated APPS training examples, while
evaluation uses the full 164-example HumanEval split;
Appendix [A.1](#A1.SS1 "A.1 Tasks and Metrics ‣ Appendix A Experimental Protocol and Reproducibility ‣ MAIGO: Mitigating Lost-in-Conversation with History-Cleaned On-Policy Self-Distillation")
gives the exact source counts and construction details. Outputs that
fail to parse, are empty, violate the response protocol, or are
truncated by the generation budget count as incorrect. For MAIGO, these
scorers are evaluation-only, not training rewards.

#### Tasks and metrics.

We use the four objectively scored task families from LiC—the same
subset adopted by recent LiC-based training studies ([Li et al.,
2026](#bib.bib6); [Chen et al., 2026](#bib.bib8); [Qiu et al.,
2026](#bib.bib9))—and exclude the two judge-scored ones (summary,
captioning) so that every cell is auditable by a deterministic verifier.
Math is instantiated by LiC-style GSM8K with numeric matching ([Cobbe et
al., 2021](#bib.bib41)); Actions by BFCL parallel/parallel-multiple tool
calls with deterministic AST matching ([Patil et al.,
2025](#bib.bib44)); Database by fixed-schema sharded text-to-SQL on
Spider no-easy with execution matching ([Yu et al., 2018](#bib.bib42));
and Code by HumanEval Python function generation scored by unit
tests ([Chen et al., 2021](#bib.bib43)). Together, they cover numeric,
tool-call, SQL, and program outputs, giving deterministic probes of
different contamination channels.

#### Models and baselines.

The primary comparison uses Qwen2.5-7B-Instruct, with 3B rows as a
smaller-backbone validation ([Qwen Team, 2025a](#bib.bib45)). Baselines
are per-task SFT, GRPO with sparse verifiable rewards ([Shao et al.,
2024](#bib.bib38)), and RLSTA, which uses the stronger single-turn view
as a GRPO anchor ([Chen et al., 2026](#bib.bib8)). All trained methods
use Low-Rank Adaptation (LoRA) adapters ([Hu et al., 2022](#bib.bib46));
adapter weights are merged into the base model before evaluation. All
methods use the same paired FULL/SHARDED prompts under a matched
100-step fine-tuning budget. We report the mean of four training seeds
for each fine-tuned method.
Appendix [A.2](#A1.SS2 "A.2 Optimization and Baselines ‣ Appendix A Experimental Protocol and Reproducibility ‣ MAIGO: Mitigating Lost-in-Conversation with History-Cleaned On-Policy Self-Distillation")
reports optimizer, context, and generation settings.

### 4.2 Main Results

Table [1](#S4.T1 "Table 1 ‣ 4 Experiments ‣ MAIGO: Mitigating Lost-in-Conversation with History-Cleaned On-Policy Self-Distillation")
reports per-task FULL and SHARDED accuracy, their averages, and the
SHARDED-to-FULL ratio. The base model is strong on FULL but much weaker
once the same requirements arrive through turns; on Qwen2.5-7B-Instruct
Actions, accuracy drops from 82.2 FULL to 17.8 SHARDED, and the base S/F
ratio is 66.5%, close to the roughly 60% ratio reported by LiC for
closed-source models ([Laban et al., 2026](#bib.bib15)). MAIGO improves
every 7B SHARDED task, with the largest gain on Actions (+29.0).
Averaged over the four 7B task families, SHARDED accuracy rises from
52.8 to 66.1 and the S/F ratio rises from 66.5% to 84.1%, while average
FULL changes only from 79.3 to 78.6, with no individual task FULL
changing by more than 2.3 points.

the per-task adapters: the mixed run uses a global batch size of 256,

#### Direct history intervention.

To isolate the proposed self-contamination mechanism, we replayed each
Base model terminal trace with the same user turns and decoder, once
with its naturally accumulated assistant history and once after deleting
all prior assistant replies. The clean-history intervention
substantially improves accuracy on three task families and is
directional on HumanEval
(Table [3](#S4.T3 "Table 3 ‣ Direct history intervention. ‣ 4.2 Main Results ‣ 4 Experiments ‣ MAIGO: Mitigating Lost-in-Conversation with History-Cleaned On-Policy Self-Distillation"));
exact paired McNemar tests give $`p=7.88\times 10^{-40}`$, $`0.00219`$,
and $`7.03\times 10^{-34}`$ for Actions, Database, and GSM8K,
respectively. Because the intervention changes only the recorded
assistant history, these results provide direct evidence that
self-generated history is a contributor to the LiC gap, while not
implying that it explains every failure mode.

#### Direct-verifier rescoring.

We further test whether the observed improvement could be attributed to
the model-assisted answer-attempt classifier or answer extractor. On a
fixed set of GSM8K terminal outputs, we bypass both components and score
the same responses directly with deterministic whole-response matching.
Under this setting, MAIGO reaches 79.91% accuracy, compared with 63.00%
for the Base model, yielding a paired gain of 16.91 points
($`p=7.9\times 10^{-32}`$). The corresponding gap under the standard
evaluation pipeline is 12.21 points. Thus, removing the model-assisted
scoring components increases rather than attenuates the relative gain,
supporting the interpretation that MAIGO improves task completion rather
than merely adherence to the expected answer surface.

#### Comparison to supervised and RL baselines.

The baseline rows show limits of standard fine-tuning signals in this
setting. On Qwen2.5-7B-Instruct, SFT changes average SHARDED accuracy
marginally. GRPO and RLSTA raise the 7B SHARDED average to 55.2 and
57.6, but they leave a large residual gap on Actions, where early tool
arguments and partial calls remain in later context. MAIGO instead
supplies dense token-level supervision on sampled sharded rollouts under
cleaned reference histories, which better targets assistant replies that
will become part of the future state.

#### Task-level behavior.

Actions benefits most because tool calls and shared arguments accumulate
across turns. Math and Database show smaller but clear improvements when
facts or SQL constraints arrive conversationally. Code is the one family
where SHARDED can exceed FULL for some rows. This is possible because
FULL is not an absolute upper bound: the HumanEval SHARDED view reveals
the same function requirements as short conversational constraints,
which can make the required signature and late conditions explicit near
generation time before the same unit-test scorer is applied. The
relevant pattern is therefore SHARDED improvement together with FULL
preservation; by that measure, MAIGO gives stable Code gains (+4.6 on 7B
and +6.7 on 3B) without degrading average FULL behavior.

Across tasks, gains are largest when early replies commit to partial
interpretations that later turns must revise, especially for
accumulating tool arguments. Math, Database, and Code show task-specific
recovery patterns, motivating MAIGO’s role-specific middle-turn and
answer-turn references.

### 4.3 Component Ablations

Table [4](#S4.T4 "Table 4 ‣ Task-level behavior. ‣ 4.2 Main Results ‣ 4 Experiments ‣ MAIGO: Mitigating Lost-in-Conversation with History-Cleaned On-Policy Self-Distillation")
isolates the main components. Removing the middle-turn loss causes the
largest degradation: average SHARDED accuracy falls by 4.5 points and
the S/F ratio drops from 84.1% to 77.7%, showing that final-answer
supervision alone misses useful signal from history-cleaned intermediate
replies. Flattening the adaptive weight to a uniform value gives a
similar 3.4-point SHARDED drop; although this variant has a slightly
higher FULL average, it does not recover the same sharded behavior. Thus
the trajectory-local weight has an effect beyond simply scaling the
middle loss. A FULL-only answer reference is the strongest ablation in
average SHARDED accuracy (65.9 vs. 66.1), slightly exceeding MAIGO on
Actions but lowering mean FULL (77.6 vs. 78.6). The preservation branch
acts as a regularizer: removing it lowers both averages, with Actions
the only task where removal improves SHARDED accuracy.

Figure [4](#S4.F4 "Figure 4 ‣ 4.4 Hyperparameter Sensitivity ‣ 4 Experiments ‣ MAIGO: Mitigating Lost-in-Conversation with History-Cleaned On-Policy Self-Distillation")

## 5 Conclusion

We studied sharded multi-turn task solving as a self-generated-history
problem: when requirements arrive across turns, intermediate assistant
replies enter later context and can hinder final completion. MAIGO
addresses this with adaptive on-policy self-distillation on the
student’s own sharded rollouts, combining history-cleaned middle-turn
supervision, answer-turn recovery, and full-prompt preservation. Across
math, tool/action generation, SQL, and Python code generation, MAIGO
improves SHARDED completion over SFT, sparse-reward RL, and
single-turn-anchor RL while keeping FULL performance comparable. These
results suggest that robust multi-turn solving benefits from supervising
student-generated histories under reference contexts that preserve
user-provided requirements while removing earlier assistant replies.

## Limitations

MAIGO may improve a language model’s ability to preserve and recover
task requirements over longer conversations, but the same capability
could also make harmful or inappropriate objectives more persistent. The
reference views used during training can also encode biased, incorrect,
or unsafe requirements, and those errors may be distilled into the
student model. Our evaluation focuses on objectively scored tasks, so it
does not establish safety, privacy protection, or refusal behavior in
open-domain dialogue. Deployment should therefore pair the method with
safety filtering, permission controls, and careful handling of sensitive
information.

### A.1 Tasks and Metrics

Each task is evaluated in paired FULL and SHARDED views: FULL presents
the complete task in one prompt, while SHARDED reveals the same
requirements across user turns and scores the final answer. The
evaluation uses GSM8K ($`N{=}1319`$, numeric answer match), Actions
($`N{=}382`$, tool-call AST match), Database ($`N{=}715`$, SQL execution
match), and HumanEval ($`N{=}164`$, unit tests).

Table [6](#A1.T6 "Table 6 ‣ A.1 Tasks and Metrics ‣ Appendix A Experimental Protocol and Reproducibility ‣ MAIGO: Mitigating Lost-in-Conversation with History-Cleaned On-Policy Self-Distillation")
summarizes how the paired views are constructed. We follow the LiC
principle that FULL and SHARDED expose the same task requirements, with
SHARDED delaying their presentation across user turns. The conversion
follows the fixed task-family protocols used for our LiC-style

For SHARDED interaction, we retain the simulator roles from the LiC
protocol: an evaluated assistant, a model-assisted user model that
decides which unrevealed shard to reveal next, and a system component
that classifies answer attempts and extracts the candidate answer for
the task verifier. Our experiments use a fixed DeepSeek-V3.1-Terminus
model for the user model, answer-attempt classifier, and answer
extractor. This model controls only the interaction environment around
the evaluated assistant; the sharding protocol, turn budget, answer
extraction interface, and deterministic task verifiers remain aligned
with the LiC evaluation protocol. Every model and training method is
evaluated with the same simulator model, same shard files, same prompt
templates, same turn budget, and same task verifier.

Outputs that fail to parse, are empty, violate the response protocol,
exceed the context limit, or reach the interaction limit are counted as
incorrect. This convention keeps FULL and SHARDED comparable: a model
must both produce an answer in the expected format and solve the
underlying task.

#### Evaluation decoding and failure handling.

The evaluated assistant and simulated user both use temperature 1.0. The
answer-attempt classifier and answer extractor use temperature 0.0.
Assistant outputs are capped at 2,048 tokens for non-code tasks and
4,096 tokens for Code, under a 32,768-token context window. Structured
simulator outputs receive up to four schema attempts, and answer
extraction receives up to three attempts. Malformed outputs, timeouts,
protocol violations, exhausted retries, and evaluation errors are all
counted as incorrect.

### A.3 Training-Only Reference Views

The reference contexts are used only for computing distillation losses
during training. They do not change the information available to the
deployed student, and they are built from the same paired task views
used by the LiC-style FULL/SHARDED protocol. The following rules define
the three reference views used by MAIGO.

#### Middle turns.

The middle-turn reference keeps the user turns through the current shard
and task-specific system information that is shared by the paired views.
It removes earlier assistant replies and withholds both unrevealed user
turns and the full task view.

#### Answer turn.

The answer-turn reference keeps all user turns in order and preserves
the same task-specific system information as the evaluation prompt. It
adds a canonical serialization built from the completed dialogue and its
paired FULL view, then removes earlier assistant replies such as
premature calls, draft SQL, or partial code attempts. The paired FULL
view is used only to render the completed requirements in the fixed task
format, not to add a gold answer or a verifier signal.

#### Full branch.

The full branch uses the complete single-turn task prompt and no sharded
history. It is an EMA anchor for FULL preservation rather than a source
of new sharded supervision.

The task-specific keep/remove rules are:

GSM8K.
Middle references keep the math system instruction and user shards
through turn $`t`$, while removing earlier assistant replies, later
facts, and the full problem text. Answer references keep all user shards
and append a canonical serialization of the completed problem
requirements.

Actions.
Middle references keep the tool-use instruction and the user-visible
tool requirements revealed so far. Answer references keep all user turns
and append the completed tool-use request in canonical form, while
removing earlier assistant calls.

Database.
The schema remains in the system context for both student and reference.
Middle references keep query shards through turn $`t`$; answer
references keep all query shards and append the completed
natural-language query in canonical form, while removing earlier draft
SQL.

HumanEval.
Middle references keep the coding instruction and function-specification
shards through turn $`t`$. Answer references keep all specification
shards and append the completed programming task requirements in
canonical form, while removing earlier partial code.

Thus the reference view changes the serialization of completed
user-provided requirements for training; it does not add a gold-answer
label and does not change what the student receives at inference time.

### B.4 Offline Shard Construction

Shard construction is an offline preprocessing step. Runtime evaluation
and fine-tuning consume the resulting shard lists and do not call the
shard constructor. We use fixed task-family prompt programs following
the LiC paired-view protocol: GSM8K uses arithmetic segmentation
followed by conversational rewriting; Actions uses BFCL request
segmentation and conversational rewriting while keeping function schemas
in the task system prompt; Database uses a fixed-schema delayed-query
construction; and Code uses HumanEval-style function-specification
segmentation, conversational rewriting, and validation. All compared
methods use the same generated shard files.
````
