###### Abstract

Small language models (SLMs) offer a promising foundation for on-device
agents through low-latency, resource-efficient inference, yet limited
reasoning and planning capabilities constrain their performance on
long-horizon tasks requiring multi-step interaction with the
environment. Step-level collaboration between SLMs and larger
cloud-hosted models can bridge this gap, but identifying states that
warrant cloud assistance remains challenging: the contribution of each
cloud call is entangled with subsequent actions and can be assessed only
from the final task outcome. Compounding this challenge, the SLM must
balance two competing objectives: maximizing task success and minimizing
cloud calls. To address this, we propose Sibyl, an algorithm that trains
SLM agents to selectively consult cloud models at the step level and
internalize their guidance for subsequent decisions, achieving strong
task performance with minimal cloud reliance. Sibyl follows a
three-stage training pipeline that (1) builds a robust base policy
through consultation-free self-evolving reinforcement learning (RL); (2)
cold-starts consultation behavior via decisive-disagreement state
mining; and (3) jointly optimizes consultation decisions and guidance
internalization through consultation-aware RL. Experiments on ALFWorld
and WebShop demonstrate that Sibyl, using only a 0.6B-parameter model,
outperforms state-of-the-art baselines, including agent training and
routing methods, by 95.2% and 80.4% in success rate while averaging only
0.8 and 3.9 cloud calls per trajectory, respectively. We release the
code and trained model weights at
[https://github.com/real-fzw/Sibyl](https://github.com/real-fzw/Sibyl)

## 1 Introduction

Language model agents have recently shown strong promise on long-horizon
tasks such as embodied interaction ([Seo et al., 2026](#bib.bib27);
[Kwon et al., 2026](#bib.bib28)), web navigation ([Yang et al.,
2025b](#bib.bib30); [Liu et al., 2026](#bib.bib29)), and software
engineering ([Antoniades et al., 2025](#bib.bib32); [Zhang et al.,
2025a](#bib.bib31)), which require sustained iteration over reasoning,
tool use, observation, and revision across many interdependent
steps ([Shinn et al., 2023](#bib.bib4); [Xu et al., 2026](#bib.bib5)).
However, much of this progress has been driven by cloud-hosted large
language models (LLMs) (e.g., GPT-5.6 ([OpenAI, 2026](#bib.bib17)),
Gemini 3.1 Pro ([Gemini Team, 2026](#bib.bib16)), Qwen3.7-Max ([Qwen
Team, 2026](#bib.bib15)), and Kimi K3 ([Kimi Team, 2026](#bib.bib18))),
while small language models (SLMs) suitable for edge deployment remain
markedly less capable, particularly in the 3B-and-below regime ([Liu et
al., 2024](#bib.bib22); [Mai et al., 2026](#bib.bib23)). Their limited
reasoning and planning degrade decision quality over sustained
interaction with the environment, undermining reliability on
long-horizon tasks and posing a critical barrier to autonomous-agent
deployment in latency- and resource-constrained applications that
require efficient on-device execution ([Wan et al., 2025](#bib.bib26);
[Wen et al., 2024](#bib.bib25)).

A natural solution is edge–cloud collaboration: on-device SLMs handle
most steps locally and selectively consult stronger cloud-hosted
LLMs ([Ong et al., 2025](#bib.bib19); [Liao et al., 2026](#bib.bib24)),
combining efficient local execution with advanced reasoning and
planning. However, collaboration on long-horizon agentic tasks is
fundamentally more challenging than conventional SLM–LLM routing. First,
model selection is no longer a one-time decision for each task, but a
sequence of decisions throughout an evolving trajectory ([Zhang et al.,
2026](#bib.bib33)). Consequently, the utility of step-level consultation
is entangled with subsequent actions and often discernible only from the
final outcome, complicating the precise identification of beneficial
consultation states required to maximize task success with minimal cloud
calls ([Feng et al., 2025](#bib.bib12)). Second, existing SLM–LLM
collaboration methods typically rely on an external router ([Ong et al.,
2025](#bib.bib19); [Chen et al., 2024](#bib.bib11)), which is ill-suited
to long-horizon agents: routing decisions are tightly coupled with the
agent’s acting policy, making it difficult to train a separate router
that generalizes across diverse, evolving states and remains aligned as
the policy is updated. Moreover, a separate router adds supervision
overhead and system complexity, complicating end-to-end agent training.

We address these challenges with Sibyl, a policy optimization method
that trains SLM agents to selectively consult cloud-hosted LLMs and
internalize their guidance;
Figure [1](#S1.F1 "Figure 1 ‣ 1 Introduction ‣ Sibyl: an efficient small–large model collaboration framework for long-horizon tasks")
illustrates the step-level collaboration paradigmd. Without a separate
router, Sibyl treats consultation as an SLM action and optimizes it
alongside local actions from trajectory-level outcomes, while
progressively reducing cloud reliance through guidance internalization.
Sibyl training proceeds in three stages: (1) consultation-free
self-evolving reinforcement learning (RL) distills hindsight skills from
on-policy trajectories to strengthen SLM agent before introducing cloud
assistance; (2) decisive-disagreement state mining identifies states
where a one-step cloud intervention turns a failed SLM trajectory into a
successful one, providing targeted supervision to cold-start
consultation behavior; (3) consultation-aware RL jointly optimizes local
actions and cloud calls using trajectory-level outcomes while
internalizing LLM guidance through hindsight skill distillation, thereby
improving task success and reducing cloud reliance.

![Refer to caption](2610.05383v1/fig1.png)

Figure 1: Sibyl enables step-level device–cloud collaboration on
long-horizon tasks, combining high success with low latency and cost.
Right: success-rate comparisons with representative baselines; see
§ [5](#S5 "5 Experiments ‣ Sibyl: an efficient small–large model collaboration framework for long-horizon tasks")
for further results.

Experiments on challenging ALFWorld and WebShop benchmarks demonstrate
that Sibyl establishes a new task-success–execution-cost Pareto frontier
relative to both state-of-the-art agent training and routing methods.
Notably, with only a 0.6B-parameter SLM, Sibyl achieves success rates of
95.2% and 80.4% while averaging only 0.8 and 3.9 cloud calls per
trajectory, respectively.

Our contributions are threefold:

- •
  We formulate long-horizon SLM–LLM collaboration as SLM policy
  optimization over local actions and step-level cloud consultation,
  eliminating the need for an external router.
- •
  We propose Sibyl, a three-stage training algorithm that enables SLM
  agents to learn when to ask for cloud assistance and internalize the
  resulting guidance, thereby minimizing cloud calls while preserving
  task success.
- •
  Across challenging agent benchmarks, Sibyl advances the success–cost
  Pareto frontier over state-of-the-art agent training and routing
  methods.

## 2 Related Work

#### Reinforcement learning for language-model agents.

Language-model agents show substantial promise for autonomous
decision-making by coupling reasoning with sustained environment
interaction ([Yao et al., 2023](#bib.bib3); [Shinn et al.,
2023](#bib.bib4)). RL has become a central paradigm for training agents
through direct policy improvement from interaction outcomes. Building on
the widely adopted clipped actor–critic objective ([Schulman et al.,
2017](#bib.bib6)), GRPO ([Shao et al., 2024](#bib.bib7)) replaces the
learned critic with group-relative advantage estimation. GiGPO ([Feng et
al., 2025](#bib.bib12)) further introduces hierarchical trajectory- and
step-level grouping for long-horizon credit assignment. RAGEN ([Wang et
al., 2025](#bib.bib10)) studies stability in self-evolving agentic RL,
while SEED ([Wu et al., 2026](#bib.bib13)) uses on-policy distillation
(OPD) to distill hindsight skills from on-policy trajectories into the
acting policy. However, these methods optimize individual agents rather
than multi-agent collaboration, making them less effective for
capacity-limited SLMs, particularly those with $`<1`$B parameters.

#### SLM–LLM collaboration.

Leveraging assistance from stronger LLMs has emerged as a prominent
approach to mitigating SLM capacity limitations while balancing
execution efficiency and cost ([Zhang et al., 2025b](#bib.bib2)).
FrugalGPT ([Chen et al., 2024](#bib.bib11)) and Hybrid LLM ([Ding et
al., 2024](#bib.bib8)) route requests based on predicted quality–cost
trade-offs, while Eagle ([Zhao et al., 2024](#bib.bib20)) and
RouteLLM ([Ong et al., 2025](#bib.bib19)) use historical similarity or
preference-based predictions. MinionS instead assigns subtask
decomposition and verification to the cloud model ([Narayan et al.,
2025](#bib.bib9)). However, these methods target independent requests
rather than evolving long-horizon trajectories. Most related to our
work, Hera ([Zhang et al., 2026](#bib.bib33)) extends collaboration to
the step level but relies on a separately trained router over fixed
device and cloud policies, leaving SLM capability unchanged. In
contrast, Sibyl integrates consultation and guidance internalization
into the SLM policy, eliminating the external router while improving the
system’s capability ceiling and cost efficiency.

## 3 Problem Formulation

Given a long-horizon task $`x\sim p(\mathcal{X})`$, an on-device SLM
agent with policy $`\pi_{\theta^{\mathrm{S}}}`$, parameterized by
$`\theta^{\mathrm{S}}`$, interacts with the environment over $`T`$
steps. At step $`t`$, the agent observes a state $`s_{t}\in\mathcal{S}`$
and selects an action $`a_{t}\in\mathcal{A}(s_{t})`$ according to
$`a_{t}\sim\pi_{\theta^{\mathrm{S}}}(\cdot\mid s_{t},x)`$, where
$`\mathcal{A}(s_{t})`$ denotes the admissible action set at state
$`s_{t}`$. After executing $`a_{t}`$, the environment transitions to the
next state $`s_{t+1}`$. A completed episode induces a trajectory:

|     |     |     |     |
| --- | --- | --- | --- |
|     |

       ``` math
       \tau=\{(s_{t},a_{t})\}_{t=1}^{T},
       ```                                |     | (1) |

with a trajectory-level return $`R(\tau)\in\mathbb{R}`$. In many agentic
environments, $`R(\tau)`$ is sparse and observed only upon trajectory
termination. The training objective is to optimize policy parameters
$`\theta^{\mathrm{S}}`$ to maximize expected return:

|     |     |     |     |
| --- | --- | --- | --- |
|     |

````math
\max_{\theta^{\mathrm{S}}}\;\mathbb{E}_{x\sim p(\mathcal{X}),\,\tau\sim\pi_{\theta^{\mathrm{S}}}(\cdot\mid x)}[R(\tau)].
``` |  | (2) |

To compensate for the SLM’s limited capabilities, we augment its action
space to enable one-step consultation with a stronger cloud-hosted LLM:

|  |  |  |  |
|----|----|----|----|
|  |
``` math
\widetilde{\mathcal{A}}(s_{t})=\mathcal{A}(s_{t})\cup\{\texttt{call\_cloud}\}.
``` |  | (3) |

If the agent selects an action in $`\mathcal{A}(s_{t})`$, it acts
locally as usual; if it selects call_cloud, a stronger cloud-based
policy $`\pi_{\theta^{\mathrm{L}}}`$ receives the current state
$`s_{t}`$ and the task instruction $`x`$, and returns one executable
action $`\tilde{a}_{t}\in\mathcal{A}(s_{t})`$ according to
$`\tilde{a}_{t}\sim\pi_{\theta^{\mathrm{L}}}(\cdot\mid s_{t},x)`$ for
step $`t`$. The environment executes $`\tilde{a}_{t}`$, after which the
local policy $`\pi_{\theta^{\mathrm{S}}}`$ resumes action selection.

Under this formulation, $`\pi_{\theta^{\mathrm{S}}}`$ jointly learns
which local actions to take and when to consult the cloud
$`\pi_{\theta^{\mathrm{L}}}`$, balancing expected task return against
cloud-invocation cost. Let $`C(\tau)`$ denote the cumulative cost of
$`\pi_{\theta^{\mathrm{L}}}`$ along trajectory $`\tau`$, such as API
charges. We optimize the following cost-regularized policy objective:

|  |  |  |  |
|----|----|----|----|
|  |
``` math
\max_{\theta^{\mathrm{S}}}\;\mathbb{E}_{x\sim p(\mathcal{X}),\,\tau\sim\pi_{\theta^{\mathrm{S}}}^{\mathrm{coll}}(\cdot\mid x)}\left[R(\tau)-\lambda C(\tau)\right].
``` |  | (4) |

where $`\lambda\geq 0`$ controls the trade-off between task return and
cloud cost, and $`\pi_{\theta^{\mathrm{S}}}^{\mathrm{coll}}`$ denotes
the SLM policy augmented with call_cloud action, and
$`\pi_{\theta^{\mathrm{L}}}`$ remains fixed.

## 4 Method

### 4.1 Overview

Building on
§ [3](#S3 "3 Problem Formulation ‣ Sibyl: an efficient small–large model collaboration framework for long-horizon tasks"),
we present Sibyl, a method that trains SLM agents to selectively consult
stronger cloud models and internalize their guidance to maximize task
success while minimizing cloud calls. Sibyl follows a three-stage
training pipeline, as illustrated in
Figure [2](#S4.F2 "Figure 2 ‣ 4.1 Overview ‣ 4 Method ‣ Sibyl: an efficient small–large model collaboration framework for long-horizon tasks"):

- •
  Consultation-Free Self-Evolving RL
  (§ [4.2](#S4.SS2 "4.2 Consultation-Free Self-Evolving RL ‣ 4 Method ‣ Sibyl: an efficient small–large model collaboration framework for long-horizon tasks")).
  The SLM is first trained through RL with skill-conditioned on-policy
  distillation, providing a reliable basis for consultation.
- •
  Consultation Cold Start
  (§ [4.3](#S4.SS3 "4.3 Consultation Cold Start ‣ 4 Method ‣ Sibyl: an efficient small–large model collaboration framework for long-horizon tasks")).
  Matched local and one-step cloud-assisted branches identify
  decisive-disagreement states to cold-start selective consultation.
- •
  RL with Consultation and Internalization
  (§ [4.4](#S4.SS4 "4.4 RL with Consultation and Internalization ‣ 4 Method ‣ Sibyl: an efficient small–large model collaboration framework for long-horizon tasks")).
  On-policy RL uses step-level credit to jointly optimize local actions
  and consultation decisions while internalizing cloud guidance to
  strengthen local capability and reduce repeated calls.

![Refer to caption](2610.05383v1/fig2.png)

Figure 2: Three-stage training pipeline of Sibyl, which trains an SLM to
act locally, consult the cloud at critical steps, and internalize its
guidance to achieve high task success with few cloud calls.

### 4.2 Consultation-Free Self-Evolving RL

Learning effective consultation requires a sufficiently capable base
policy; otherwise, the SLM may improve task success by overusing cloud
assistance rather than identifying states where consultation is truly
necessary. We therefore first train $`\pi_{\theta^{\mathrm{S}}}`$ as a
robust standalone agent without consultation. Inspired by self-evolving
agent training ([Wu et al., 2026](#bib.bib13)), we distill reusable
hindsight guidance from the agent’s own trajectories, providing dense
supervision beyond sparse outcome rewards for long-horizon behaviors
such as subgoal planning and failure avoidance.

#### Trajectory-level skill supervision.

We first execute training task $`x`$ using the SLM policy
$`\pi_{\theta^{\mathrm{S}}}`$ alone, yielding a trajectory
$`\tau^{\mathrm{S}}`$. Given $`x`$, $`\tau^{\mathrm{S}}`$, and its
return $`R(\tau^{\mathrm{S}})`$, the cloud LLM
$`\pi_{\theta^{\mathrm{L}}}`$ serves as a trajectory teacher
$`\mathcal{T}_{\theta^{\mathrm{L}}}`$ to extract a concise causal
summary and reusable hindsight skill:

|  |  |  |  |
|----|----|----|----|
|  |
``` math
z_{\tau^{\mathrm{S}}}=\mathcal{T}_{\theta^{\mathrm{L}}}(x,\tau^{\mathrm{S}},R(\tau^{\mathrm{S}})).
``` |  | (5) |

Beyond the sparse return, $`z_{\tau^{\mathrm{S}}}`$ captures
trajectory-level behavioral structure, such as effective subgoal
ordering, decisive observations, and failure-avoidance rules. We then
fine-tune $`\pi_{\theta^{\mathrm{S}}}`$ on the resulting
trajectory–skill pairs, using the trained model both as the trajectory
analyzer $`\mathcal{T}_{\theta^{\mathrm{S}}}`$ for subsequent on-policy
distillation and as the initialization of $`\pi_{\theta^{\mathrm{S}}}`$
itself. This bootstrapping eliminates repeated cloud queries for
trajectory annotation during online training.

#### Skill-conditioned on-policy distillation.

Since the trajectory–skill fine-tuning above trains
$`\pi_{\theta^{\mathrm{S}}}`$ for trajectory analysis rather than action
generation, we first restore its acting capability through a supervised
cold start. We collect action trajectories from the stronger
$`\pi_{\theta^{\mathrm{L}}}`$ and fine-tune
$`\pi_{\theta^{\mathrm{S}}}`$ on standard state–action pairs
$`(s_{t},x)\rightarrow a_{t}`$, providing both protocol-consistent
action generation and an initial capability transfer before on-policy
optimization.

Next, we perform self-evolving RL with skill-conditioned on-policy
distillation. Specifically, for each task $`x_{i}`$, cold-started
$`\pi_{\theta^{\mathrm{S}}}`$ generates a trajectory
$`\tau_{i}=\{(s_{i,t},a_{i,t})\}_{t=1}^{T_{i}}`$, which is then analyzed
by the trajectory analyzer $`\mathcal{T}_{\theta^{\mathrm{S}}}`$ to
produce a trajectory-level hindsight skill
$`z_{i}=\mathcal{T}_{\theta^{\mathrm{S}}}(x_{i},\tau_{i},R(\tau_{i}))`$.
Each action $`a_{i,t}`$ is a token sequence
$`a_{i,t}=(y_{i,t,1},\dots,y_{i,t,L_{i,t}})`$ of length $`L_{i,t}`$. The
sampled action tokens are kept fixed and re-scored by
$`\pi_{\theta^{\mathrm{S}}}`$ under the ordinary context
$`(s_{i,t},x_{i})`$ and its skill-augmented counterpart
$`H(s_{i,t},x_{i},z_{i})`$, yielding the respective log-probabilities:

|  |  |  |  |  |
|----|----|----|----|----|
|  | $`\displaystyle\ell^{\varnothing}_{i,t,k}`$ | $`\displaystyle=\log\pi_{\theta^{\mathrm{S}}}(y_{i,t,k}\mid s_{i,t},x_{i},y_{i,t,<k}),`$ |  | (6) |
|  | $`\displaystyle\ell^{z}_{i,t,k}`$ | $`\displaystyle=\log\pi_{\theta^{\mathrm{S}}}(y_{i,t,k}\mid H(s_{i,t},x_{i},z_{i}),y_{i,t,<k}),`$ |  | (7) |

The skill-induced probability lift forms a detached confidence weight:

|  |  |  |  |
|----|----|----|----|
|  |
``` math
w_{i,t,k}=\sigma\!\left(\beta_{\mathrm{opd}}\operatorname{sg}[\ell^{z}_{i,t,k}-\ell^{\varnothing}_{i,t,k}]\right),
``` |  | (8) |

and the OPD objective is:

|  |  |  |  |
|----|----|----|----|
|  |
``` math
\mathcal{L}_{\mathrm{opd}}(\theta^{\mathrm{S}})=\mathbb{E}_{i,t,k}\left[w_{i,t,k}\left(\operatorname{sg}[\ell^{z}_{i,t,k}]-\ell^{\varnothing}_{i,t,k}\right)\right],
``` |  | (9) |

where $`\beta_{\mathrm{opd}}`$ controls the confidence weighting
sharpness, and $`\operatorname{sg}`$ denotes stop-gradient. Gradients
flow only through the ordinary branch, enabling
$`\pi_{\theta^{\mathrm{S}}}`$ to learn from online skill-supported
behaviors.

The final consultation-free policy is jointly optimized with the OPD
loss above and a group-based RL objective. For $`N`$ trajectories
sampled from the same task $`x_{i}`$, we define the group-relative
advantage as
$`A_{i,n}=R(\tau_{i,n})-\frac{1}{N}\sum_{n^{\prime}=1}^{N}R(\tau_{i,n^{\prime}})`$.
Let $`\ell^{\mathrm{old}}_{i,n,t,k}`$ denote the token log-probability
under the rollout policy and
$`\rho_{i,n,t,k}(\theta^{\mathrm{S}})=\exp(\ell^{\varnothing}_{i,n,t,k}-\ell^{\mathrm{old}}_{i,n,t,k})`$
the corresponding importance ratio. Following GRPO ([Shao et al.,
2024](#bib.bib7)), the RL loss is:

|  |  |  |  |
|----|----|----|----|
|  |
``` math
\mathcal{L}_{\mathrm{rl}}(\theta^{\mathrm{S}})=-\mathbb{E}_{i,n,t,k}\left[\min\!\left(\rho_{i,n,t,k}(\theta)A_{i,n},\operatorname{clip}(\rho_{i,n,t,k}(\theta),1-\epsilon,1+\epsilon)A_{i,n}\right)\right]+\beta_{\mathrm{KL}}D_{\mathrm{KL}},
``` |  | (10) |

where $`\epsilon`$ and $`\beta_{\mathrm{KL}}`$ control policy clipping
and KL regularization, respectively.

The full objective of the consultation-free stage in Sibyl is:

|  |  |  |  |
|----|----|----|----|
|  |
``` math
\mathcal{L}_{\mathrm{confree}}=\mathcal{L}_{\mathrm{rl}}+\lambda_{\mathrm{opd}}\mathcal{L}_{\mathrm{opd}}.
``` |  | (11) |

Here, $`\mathcal{L}_{\mathrm{rl}}`$ improves task-level performance from
environment feedback, while $`\mathcal{L}_{\mathrm{opd}}`$ supplies
dense hindsight supervision on the same on-policy trajectories, with
$`\lambda_{\mathrm{opd}}`$ controlling the OPD signal strength. After
the complete self-evolving RL in this section, we freeze the resulting
checkpoint as $`\pi_{\bar{\theta}^{\mathrm{S}}}`$, which serves as the
pre-consultation snapshot for subsequent training with active
consultation and consultation-feedback internalization.

### 4.3 Consultation Cold Start

This section introduces call_cloud as a new action for
$`\pi_{\theta^{\mathrm{S}}}`$
(Eq. [3](#S3.E3 "In 3 Problem Formulation ‣ Sibyl: an efficient small–large model collaboration framework for long-horizon tasks"))
and provides an explicit cold start for its use.

#### Decisive-Disagreement State Mining.

The pre-consultation policy $`\pi_{\bar{\theta}^{\mathrm{S}}}`$ is first
rolled out on each training task $`x_{i}`$ to collect the
failed-trajectory set:

|  |  |  |  |
|----|----|----|----|
|  |
``` math
\mathcal{D}^{-}=\{\tau_{i}\mid R(\tau_{i})=0,\ \tau_{i}\sim\pi_{\bar{\theta}^{\mathrm{S}}}(\cdot\mid x_{i})\},\qquad\tau_{i}=\{(s_{i,t},a^{\mathrm{S}}_{i,t})\}_{t=1}^{T_{i}}.
``` |  | (12) |

For each $`s_{i,t}`$ visited in $`\mathcal{D}^{-}`$, the environment
instance, action history, current observation, and admissible action set
are recorded and fed to the cloud policy $`\pi_{\theta^{\mathrm{L}}}`$
to perform a one-step action:

|  |  |  |  |
|----|----|----|----|
|  |
``` math
a_{i,t}^{\mathrm{L}}\sim\pi_{\theta^{\mathrm{L}}}(\cdot\mid s_{i,t},x_{i}).
``` |  | (13) |

If $`a_{i,t}^{\mathrm{L}}=a_{i,t}^{\mathrm{S}}`$, the cloud and local
policies agree on this step; otherwise, a disagreement branch is formed
by replacing $`a_{i,t}^{\mathrm{S}}`$ with $`a_{i,t}^{\mathrm{L}}`$ at
state $`s_{i,t}`$, after which the subsequent steps are executed by
$`\pi_{\bar{\theta}^{\mathrm{S}}}`$:

|  |  |  |  |
|----|----|----|----|
|  |
``` math
\widetilde{\tau}_{i}=\{(s_{i,1},a_{i,1}^{\mathrm{S}}),\dots,(s_{i,t-1},a_{i,t-1}^{\mathrm{S}}),(s_{i,t},a_{i,t}^{\mathrm{L}}),(s_{i,t+1},\widetilde{a}_{i,t+1}),\dots,(s_{i,\widetilde{T}_{i,t}},\widetilde{a}_{i,\widetilde{T}_{i,t}})\},
``` |  | (14) |

where
$`\widetilde{a}_{i,u}\sim\pi_{\bar{\theta}^{\mathrm{S}}}(\cdot\mid s_{i,u},x_{i})`$
for $`u>t`$. We define the set of decisive-disagreement states as:

|  |  |  |
|----|----|----|
|  |
``` math
\mathcal{S}_{\mathrm{D}}=\left\{s_{i,t}\mid a_{i,t}^{\mathrm{L}}\neq a_{i,t}^{\mathrm{S}},\;R(\widetilde{\tau}_{i})-R(\tau_{i})=1\right\},
``` |  |

identifying critical decision points where a single cloud intervention
can reverse the outcome, thereby providing precise supervision for when
to ask for cloud assistance.

#### Consultation Cold-Start Fine-Tuning.

The mined decisive-disagreement states are converted into supervised
trajectories for initializing the consultation behavior of
$`\pi_{\theta^{\mathrm{S}}}`$. For each
$`s_{i,t}\in\mathcal{S}_{\mathrm{D}}`$, the original action history
$`\{(s_{i,1},a_{i,1}^{\mathrm{S}}),\dots,(s_{i,t-1},a_{i,t-1}^{\mathrm{S}})\}`$
is retained, and the target action at step $`t`$ is replaced by
call_cloud. The resulting trajectory with consultation is:

|  |  |  |  |
|----|----|----|----|
|  |
``` math
\tau_{i}^{\mathrm{call}}=\{(s_{i,1},a_{i,1}^{\mathrm{S}}),\dots,(s_{i,t-1},a_{i,t-1}^{\mathrm{S}}),(s_{i,t},\texttt{call\_cloud})\}.
``` |  | (15) |

These consultation trajectories are mixed with successful
consultation-free trajectories sampled from
$`\pi_{\bar{\theta}^{\mathrm{S}}}`$ to fine-tune
$`\pi_{\theta^{\mathrm{S}}}`$, cold-starting selective cloud
consultation at decisive states while preserving its standalone acting
capability.

### 4.4 RL with Consultation and Internalization

After consultation cold start, we continue training
$`\pi_{\theta^{\mathrm{S}}}`$ with on-policy RL to jointly learn when to
consult and internalize cloud guidance, enabling it to handle similar
states independently while retaining consultation for cases beyond its
capability.

#### Consultation-aware credit assignment.

We retain the group-based RL objective $`\mathcal{L}_{\mathrm{rl}}`$
from
§ [4.2](#S4.SS2 "4.2 Consultation-Free Self-Evolving RL ‣ 4 Method ‣ Sibyl: an efficient small–large model collaboration framework for long-horizon tasks")
to optimize $`\pi_{\theta^{\mathrm{S}}}`$ over the augmented action
space. However, its trajectory-level advantage cannot disentangle the
contribution of a consultation from subsequent actions. We therefore
introduce consultation-aware credit by comparing cloud-assisted and
local continuations from matched states.

Specifically, we construct an exact-state key $`g_{i,n,t}`$ for each
visited state from its current observation and admissible action set.
For each state $`s_{i,n,t}`$, we associate it with the matched-state set
indexed by its key, formed over all states in the $`N`$ trajectories
sampled for task $`x_{i}`$:

|  |  |  |  |
|----|----|----|----|
|  |
``` math
\mathcal{I}_{g_{i,n,t}}=\left\{s_{i,m,u}\;\middle|\;1\leq m\leq N,\;1\leq u\leq T_{i,m},\;g_{i,m,u}=g\right\},\qquad g=g_{i,n,t}.
``` |  | (16) |

Let $`\mu_{i,n,t}`$ denote the mean trajectory return of the states in
$`\mathcal{I}_{g_{i,n,t}}`$. We define the matched-state advantage as
$`A^{\mathrm{step}}_{i,n,t}=R(\tau_{i,n})-\mu_{i,n,t}`$.

To further isolate the contribution of consultation, for
$`q\in\{\mathrm{call},\mathrm{local}\}`$, we define the
action-conditioned mean return within $`\mathcal{I}_{g}`$ as:

|  |  |  |  |
|----|----|----|----|
|  |
``` math
\overline{R}^{q}_{g}=\frac{\sum_{s_{i,m,u}\in\mathcal{I}_{g}}\mathbb{I}_{q}(a_{i,m,u})R(\tau_{i,m})}{\sum_{s_{i,m,u}\in\mathcal{I}_{g}}\mathbb{I}_{q}(a_{i,m,u})},
``` |  | (17) |

where $`\mathbb{I}_{\mathrm{call}}(a)=1`$ if $`a=\texttt{call\_cloud}`$,
and $`\mathbb{I}_{\mathrm{local}}(a)=1`$ if $`a\in\mathcal{A}(s)`$. For
each consultation state $`s_{i,n,t}`$, we define:

|  |  |  |  |
|----|----|----|----|
|  |
``` math
A^{\mathrm{cf}}_{i,n,t}=\overline{R}^{\mathrm{call}}_{g_{i,n,t}}-\overline{R}^{\mathrm{local}}_{g_{i,n,t}}.
``` |  | (18) |

Notably, $`A^{\mathrm{cf}}_{i,n,t}=0`$ for local actions or when no
matched local continuation exists. Combining this consultation-specific
term with the trajectory- and matched-state-level advantages, we define

|  |  |  |  |
|----|----|----|----|
|  |
``` math
A^{Sibyl}_{i,n,t}=A_{i,n}+\alpha_{\mathrm{step}}A^{\mathrm{step}}_{i,n,t}+\alpha_{\mathrm{cf}}A^{\mathrm{cf}}_{i,n,t},
``` |  | (19) |

where $`\alpha_{\mathrm{step}}`$ and $`\alpha_{\mathrm{cf}}`$ control
the contributions of matched-state and consultation-specific credit,
respectively. This formulation preserves trajectory-level optimization
while assigning finer-grained credit to matched states and beneficial
consultations.

#### Cloud-guidance internalization.

To further reduce cloud cost while preserving task success, we
internalize guidance from on-policy cloud-assisted trajectories,
enabling $`\pi_{\theta^{\mathrm{S}}}`$ to handle similar states
independently whenever possible while retaining consultation for cases
beyond its capability.

We reuse the frozen trajectory-skill supervisor
$`\mathcal{T}_{\theta^{\mathrm{S}}}`$ from
§ [4.2](#S4.SS2 "4.2 Consultation-Free Self-Evolving RL ‣ 4 Method ‣ Sibyl: an efficient small–large model collaboration framework for long-horizon tasks").
After each rollout, $`\mathcal{T}_{\theta^{\mathrm{S}}}`$ analyzes the
trajectory $`\tau_{i,n}`$, including consultation decisions, executed
cloud actions, subsequent observations, and the final outcome, to
extract a hindsight skill:

|  |  |  |  |
|----|----|----|----|
|  |
``` math
z_{i,n}=\mathcal{T}_{\theta^{\mathrm{S}}}\bigl(x_{i},\tau_{i,n},R(\tau_{i,n})\bigr).
``` |  | (20) |

The skill-conditioned $`\mathcal{L}_{\mathrm{opd}}`$ from
§ [4.2](#S4.SS2 "4.2 Consultation-Free Self-Evolving RL ‣ 4 Method ‣ Sibyl: an efficient small–large model collaboration framework for long-horizon tasks")
(Eq. [9](#S4.E9 "In Skill-conditioned on-policy distillation. ‣ 4.2 Consultation-Free Self-Evolving RL ‣ 4 Method ‣ Sibyl: an efficient small–large model collaboration framework for long-horizon tasks"))
is then applied to distill behaviors favored under $`z_{i,n}`$ into the
ordinary policy.

Since $`z_{i,n}`$ is extracted from on-policy trajectories, cloud
guidance internalization tracks the evolving state distribution.

Combining the above components, the final-stage training objective of
Sibyl is:

|  |  |  |  |
|----|----|----|----|
|  |
``` math
\mathcal{L}_{Sibyl}=\mathcal{L}_{\mathrm{rl}}\bigl(\theta^{\mathrm{S}};A^{Sibyl}\bigr)+\lambda_{\mathrm{opd}}\mathcal{L}_{\mathrm{opd}},
``` |  | (21) |

where $`\lambda_{\mathrm{opd}}`$ controls the strength of guidance
internalization. At inference time, the trajectory-skill supervisor and
skill-augmented branch are removed.

Through the full three-stage training pipeline, Sibyl enables SLM agents
to seek cloud assistance when beneficial and internalize reusable
guidance to strengthen local capability, thereby further reducing cloud
cost while preserving task success.
Algorithm [A](#A1 "Appendix A Pseudocode ‣ Sibyl: an efficient small–large model collaboration framework for long-horizon tasks")
details the training procedure.

Together, matched-state credit and guidance internalization indirectly
pursue the success–cost objective in
Eq. [4](#S3.E4 "In 3 Problem Formulation ‣ Sibyl: an efficient small–large model collaboration framework for long-horizon tasks")
by focusing consultations on consequential states and reducing repeated
cloud use. Tuning $`\alpha_{\mathrm{cf}}`$ provides an implicit control
over the performance–cost balance represented by $`\lambda`$ in
Eq. [4](#S3.E4 "In 3 Problem Formulation ‣ Sibyl: an efficient small–large model collaboration framework for long-horizon tasks"),
producing the empirical Pareto frontier shown in
§ [5](#S5 "5 Experiments ‣ Sibyl: an efficient small–large model collaboration framework for long-horizon tasks")
and
Figure [3](#S5.F3 "Figure 3 ‣ 5.3 Analysis of Cloud Consultation ‣ 5 Experiments ‣ Sibyl: an efficient small–large model collaboration framework for long-horizon tasks").

### 5.1 Experimental Setup

#### Benchmarks.

We evaluate Sibyl on challenging benchmarks including
ALFWorld ([Shridhar et al., 2021](#bib.bib1)) and WebShop ([Yao et al.,
2022](#bib.bib21)). ALFWorld is a text-based embodied benchmark with
3,827 instances across six household task types: Pick & Place (Pick),
Examine in Light (Look), Clean & Place (Clean), Heat & Place (Heat),
Cool & Place (Cool), and Pick Two & Place (Pick2). WebShop requires
agents to navigate a simulated e-commerce site and purchase suitable
products from over 1.1 million items based on 12K user instructions. Our
detailed dataset splits are provided in
Appendix [B](#A2 "Appendix B Benchmark Protocol and Data Splits ‣ Sibyl: an efficient small–large model collaboration framework for long-horizon tasks").

#### Training details.

We train Qwen3-0.6B/1.7B ([Yang et al., 2025a](#bib.bib14)) as the
on-device SLMs, assisted by Qwen3.7-Max ([Qwen Team, 2026](#bib.bib15))
and Gemini 3.1 Pro ([Gemini Team, 2026](#bib.bib16)) as cloud LLMs.
Agent outputs follow the ReAct ([Yao et al., 2023](#bib.bib3)) format.
Training is conducted on eight AMD Instinct MI308X GPUs. Stage 1
(§ [4.2](#S4.SS2 "4.2 Consultation-Free Self-Evolving RL ‣ 4 Method ‣ Sibyl: an efficient small–large model collaboration framework for long-horizon tasks"))
trains $`\mathcal{T}_{\theta^{\mathrm{S}}}`$ with learning rate (lr)
$`5\times 10^{-6}`$ and batch size (bs) 8, then performs
consultation-free RL with $`\pi_{\theta^{\mathrm{S}}}`$ at lr
$`10^{-6}`$ with group size 8, bs 256, $`\beta_{\mathrm{opd}}=5.0`$, and
$`\lambda_{\mathrm{opd}}=0.01`$. Stage 2
(§ [4.3](#S4.SS3 "4.3 Consultation Cold Start ‣ 4 Method ‣ Sibyl: an efficient small–large model collaboration framework for long-horizon tasks"))
trains at lr $`2\times 10^{-6}`$ with bs 16. Stage 3
(§ [4.4](#S4.SS4 "4.4 RL with Consultation and Internalization ‣ 4 Method ‣ Sibyl: an efficient small–large model collaboration framework for long-horizon tasks"))
performs RL at lr $`10^{-6}`$ with group size 8, bs 256,
$`\lambda_{\mathrm{opd}}=0.01`$, $`\alpha_{\mathrm{step}}=0.5`$, and
$`\alpha_{\mathrm{cf}}=0.25`$. Further details are provided in
Appendix [C](#A3 "Appendix C Experimental Details ‣ Sibyl: an efficient small–large model collaboration framework for long-horizon tasks").

#### Baselines.

We compare Sibyl against four baseline families: (1) cloud-only methods
directly prompt the frontier closed-source Qwen3.7-Max and Gemini 3.1
Pro; (2) device-only methods train SLMs with agentic RL, including
GRPO ([Shao et al., 2024](#bib.bib7)) with group-relative critic-free
optimization and GiGPO ([Feng et al., 2025](#bib.bib12)) with
hierarchical step-level credit assignment; (3) training-time
cloud-assisted methods include SEED ([Wu et al., 2026](#bib.bib13)) with
cloud-guided on-policy hindsight-skill distillation, and GRPO/GiGPO
cold-started through supervised fine-tuning on cloud-generated
trajectories; (4) inference-time collaborative methods include
RouteLLM ([Ong et al., 2025](#bib.bib19)) and Hera ([Zhang et al.,
2026](#bib.bib33)), which train routers for request-level and step-level
routing, respectively.

### 5.2 Overall Results

Table [1](#S5.T1 "Table 1 ‣ 5 Experiments ‣ Sibyl: an efficient small–large model collaboration framework for long-horizon tasks")
shows that Sibyl improves long-horizon task success across both SLM
sizes. With Qwen3-0.6B, it achieves 95.2% success on ALFWorld and 80.4%
on WebShop, versus 37.4% and 33.4% for the strongest device-only
baselines. Cloud-assisted training substantially improves the SLM, but
Sibyl further raises ALFWorld success from 91.7% to 95.2% and achieves a
higher WebShop score (90.7 versus 86.7); its WebShop success is
comparable to the best training-time baseline (80.4% versus 80.6%). The
higher score despite similar exact success suggests better partial
progress on episodes that do not result in a complete purchase. With
Qwen3-1.7B, Sibyl exceeds the strongest training-time baselines by 5.4
and 7.3 success points on the two benchmarks, indicating that selective
consultation remains useful as local model capacity increases. Among
methods that use cloud assistance at inference time, Sibyl achieves
higher success than RouteLLM and Hera with fewer cloud calls, as
detailed in the next section. Both baselines train an external router to
allocate decisions between fixed device and cloud policies. Sibyl
instead jointly optimizes local actions and consultation within the SLM,
enabling it to seek help at consequential states and internalize cloud
guidance for similar future states. Notably, Sibyl surpasses cloud-only
Qwen3.7-Max on both benchmarks while consulting that same model for only
a subset of steps, suggesting that it learns to combine local execution
and targeted cloud intervention into more effective trajectories than
cloud-only execution.

### 5.3 Analysis of Cloud Consultation

Table [2](#S5.T2 "Table 2 ‣ 5.2 Overall Results ‣ 5 Experiments ‣ Sibyl: an efficient small–large model collaboration framework for long-horizon tasks")
shows that Sibyl achieves strong task success with exceptionally low
cloud-invocation cost. With a 0.6B SLM, it reaches 95.2% success on
ALFWorld and 80.4% on WebShop while reducing cost by 21.5$`\times`$ and
3.0$`\times`$ relative to cloud-only Qwen3.7-Max. With a 1.7B SLM,
success rises to 97.4% and 84.6%, at 43$`\times`$ and 44$`\times`$ lower
cost; only 2.8% and 3.1% of steps invoke the cloud. The ALFWorld result
approaches cloud-only Gemini 3.1 Pro (98.6%), while the WebShop result
substantially exceeds it (60.0%). Although RouteLLM and Hera use
external routers to coordinate fixed device and cloud policies, Sibyl
jointly learns local actions and consultation while internalizing cloud
guidance. The SLM can thus handle similar states independently and
reserve calls for cases beyond its capability, achieving a stronger
success–cost trade-off.

Figure [3](#S5.F3 "Figure 3 ‣ 5.3 Analysis of Cloud Consultation ‣ 5 Experiments ‣ Sibyl: an efficient small–large model collaboration framework for long-horizon tasks")
further shows that this advantage persists across cloud budgets. These
results are from a first run checkpoint, rather than the averages
reported earlier. On ALFWorld, Sibyl reaches 94.3% success at an
approximately 8% call ratio, or 92.1% with fewer than 5% of steps
delegated; the corresponding WebShop frontier reaches 80.4% at 67% and
77.8% at 45%. These settings outperform random consultation, RouteLLM,
and Hera, indicating that the gains stem from learning when to seek
assistance rather than simply having access to the cloud. Moreover,
neither removing consultation-specific credit
($`\alpha_{\mathrm{cf}}=0`$) nor assigning it excessive weight
($`\alpha_{\mathrm{cf}}=1`$) reaches the frontier. Intermediate weights
most effectively reward consequential consultations while suppressing
unnecessary cloud calls.

### 5.4 Ablation Study

Figure [4](#S5.F4 "Figure 4 ‣ 5.3 Analysis of Cloud Consultation ‣ 5 Experiments ‣ Sibyl: an efficient small–large model collaboration framework for long-horizon tasks")
traces the contribution of each training stage on ALFWorld and WebShop.
Starting from base SLM success rates of 0.7% and 0.8%, Stage 1 raises
success to 90.0% and 60.8% without inference-time consultation,
establishing a capable local policy. Adding random cloud calls yields
only modest further gains, showing that cloud access alone is
insufficient. Stage 2 improves success by cold-starting consultation at
states where a one-step cloud action can reverse failure, but its higher
call ratios indicate that this supervision has yet to learn when
consultation can be avoided. Stage 3 effectively resolves this
trade-off: success rises to 94.3% and 80.2% while call ratios fall to
7.7% and 64.8%, respectively. It also substantially outperforms random
consultation at nearly the same call ratios, supporting the value of
jointly optimizing consultation decisions and internalizing cloud
guidance. Notably, replacing Qwen3.7-Max with the stronger Gemini 3.1
Pro only at inference improves success on both benchmarks without
retraining the SLM, suggesting that the learned consultation policy can
transfer across cloud models and benefit from stronger assistance.

## 6 Conclusion

We presented Sibyl as a policy-optimization framework that trains SLM
agents to selectively consult stronger cloud models and internalize
their guidance. By treating consultation as a native policy action, its
three-stage training jointly strengthens local capability, learns when
to ask, and reduces repeated cloud dependence. Experiments on
challenging long-horizon benchmarks show that Sibyl achieves strong task
success while substantially reducing cloud calls, advancing the
success–cost trade-off over existing agent training and routing methods.
More broadly, Sibyl offers an integrated framework that unifies
coordination and capability transfer across heterogeneous language-model
agents; its limitations and future directions are discussed in
Appendix [F](#A6 "Appendix F Limitations and Future Work ‣ Sibyl: an efficient small–large model collaboration framework for long-horizon tasks").

## Appendix A Pseudocode

1:  Input: Training tasks $`\mathcal{X}`$; SLM policy
$`\pi_{\theta^{\mathrm{S}}}`$; fixed cloud policy
$`\pi_{\theta^{\mathrm{L}}}`$; rollouts per task $`N`$; weights
$`\lambda_{\mathrm{opd}},\alpha_{\mathrm{step}},\alpha_{\mathrm{cf}}`$.

2:  Output: Trained SLM policy $`\pi_{\theta^{\mathrm{S}}}`$.

3:  Stage 1: Consultation-free self-evolving RL

4:  Roll out $`\pi_{\theta^{\mathrm{S}}}`$ without consultation and
obtain hindsight skills from the cloud trajectory teacher.

5:  Fine-tune $`\pi_{\theta^{\mathrm{S}}}`$ on trajectory–skill pairs to
initialize the skill supervisor $`\mathcal{T}_{\theta^{\mathrm{S}}}`$;
restore action generation through SFT on cloud-generated state–action
pairs.

6:  for each RL iteration do

7:   for all tasks $`x_{i}`$ do

8:    Sample $`N`$ local-only trajectories $`\{\tau_{i,n}\}_{n=1}^{N}`$.

9:    Extract
$`z_{i,n}=\mathcal{T}_{\theta^{\mathrm{S}}}(x_{i},\tau_{i,n},R(\tau_{i,n}))`$
and compute group-relative advantages $`A_{i,n}`$.

10:   end for

11:   Update $`\theta^{\mathrm{S}}`$ using
$`\mathcal{L}_{\mathrm{rl}}+\lambda_{\mathrm{opd}}\mathcal{L}_{\mathrm{opd}}`$.

12:  end for

13:  Freeze the resulting policy as $`\bar{\pi}^{\mathrm{S}}`$ and the
skill supervisor $`\mathcal{T}_{\theta^{\mathrm{S}}}`$.

14:  Stage 2: Consultation cold start

15:  Collect failed trajectories $`\mathcal{D}^{-}`$ and successful
trajectories $`\mathcal{D}^{+}`$ using $`\bar{\pi}^{\mathrm{S}}`$.

16:  for all states $`s_{i,t}`$ in trajectories
$`\tau_{i}\in\mathcal{D}^{-}`$ do

17:   Sample one cloud action
$`a^{\mathrm{L}}_{i,t}\sim\pi_{\theta^{\mathrm{L}}}(\cdot\mid s_{i,t},x_{i})`$.

18:   if $`a^{\mathrm{L}}_{i,t}\neq a^{\mathrm{S}}_{i,t}`$ then

19:    Replace $`a^{\mathrm{S}}_{i,t}`$ with $`a^{\mathrm{L}}_{i,t}`$
and complete the branch using $`\bar{\pi}^{\mathrm{S}}`$, obtaining
$`\tilde{\tau}_{i}`$.

20:    if $`R(\tilde{\tau}_{i})-R(\tau_{i})=1`$ then

21:     Add the original trajectory prefix followed by
$`(s_{i,t},\texttt{call\_cloud})`$ to $`\mathcal{D}^{\mathrm{call}}`$.

22:    end if

23:   end if

24:  end for

25:  Fine-tune $`\pi_{\theta^{\mathrm{S}}}`$ on
$`\mathcal{D}^{\mathrm{call}}\cup\mathcal{D}^{+}`$.

26:  Stage 3: RL with consultation and internalization

27:  for each RL iteration do

28:   for all tasks $`x_{i}`$ do

29:    Sample $`N`$ trajectories using the augmented action space; each
call_cloud executes one cloud action before local control resumes.

30:    Group matching states by exact-state key $`g`$ and compute
trajectory advantages $`A_{i,n}`$ and matched-state advantages
$`A^{\mathrm{step}}_{i,n,t}`$.

31:    For consultation actions, compute
$`A^{\mathrm{cf}}_{i,n,t}=\overline{R}^{\mathrm{call}}_{g}-\overline{R}^{\mathrm{local}}_{g}`$
when both groups exist; otherwise set it to zero.

32:    Set
$`A^{\mathrm{SIBYL}}_{i,n,t}=A_{i,n}+\alpha_{\mathrm{step}}A^{\mathrm{step}}_{i,n,t}+\alpha_{\mathrm{cf}}A^{\mathrm{cf}}_{i,n,t}`$.

33:    Extract hindsight skills $`z_{i,n}`$ using the frozen
$`\mathcal{T}_{\theta^{\mathrm{S}}}`$.

34:   end for

35:   Update $`\theta^{\mathrm{S}}`$ using
$`\mathcal{L}_{\mathrm{rl}}(A^{\mathrm{SIBYL}})+\lambda_{\mathrm{opd}}\mathcal{L}_{\mathrm{opd}}`$.

36:  end for

37:  return $`\pi_{\theta^{\mathrm{S}}}`$.

Algorithm 1 Sibyl: Three-Stage Training for Step-Level Device–Cloud
Collaboration

## Appendix B Benchmark Protocol and Data Splits

We evaluate the Sibyl on two interactive benchmarks, ALFWorld and
WebShop, under the benchmark-specific protocols described below.

#### ALFWorld.

ALFWorld ([Shridhar et al., 2021](#bib.bib1)) provides a text-based view
of household tasks aligned with the embodied ALFRED environment. An
agent receives a natural-language goal, observes the environment through
text, and selects admissible actions until the goal is completed. The
benchmark covers six task types: Pick & Place, Examine in Light, Clean &
Place, Heat & Place, Cool & Place, and Pick Two & Place. The official
split contains 3,553 training games, 140 Seen games, and 134 Unseen
games. Seen games use rooms encountered during training with new object
configurations, whereas Unseen games use previously unseen rooms and
layouts. We report the main results on the 140-task Seen split and use
the 134-task Unseen split to assess out-of-distribution generalization.
Each episode is limited to 30 steps, and the prompt contains the most
recent 5 interaction steps. The prompt and response limits are 2,048 and
512 tokens, respectively.

#### WebShop.

WebShop ([Yao et al., 2022](#bib.bib21)) is a simulated shopping website
built from more than 1.1 million products and 12,087 crowdsourced
instructions. Each instruction specifies requirements such as product
attributes, options, and a price limit. The agent searches the catalog,
navigates product and detail pages, selects options, and buys a product.
The environment computes a reward from the match between the selected
product and the instruction, including its type, attributes, options,
and price. We report Task Score, defined as 100 times the mean reward,
and Success Rate, the fraction of episodes with reward one. We evaluate
all methods on 500 test samples, with a maximum of 15 steps per episode
and the most recent 5 interaction steps included in the prompt. The
prompt and response limits are 12,288 and 512 tokens, respectively.

the primary cloud model, and Gemini 3.1 Pro is used for the separate
cloud-model comparison. The primary ALFWorld run uses 8 AMD Instinct
MI308X GPUs.

Stage 1 first collects 180 training tasks with eight trajectories per
task, yielding 1,440 trajectory–skill examples (1,296 train and 144
validation). Skill SFT uses three epochs, maximum sequence length 8,192,
learning rate $`5\times 10^{-6}`$, and batch size 8. We then perform
action/protocol-repair SFT on 512 train and 64 validation examples for
one epoch, with maximum sequence length 4,096, learning rate
$`2\times 10^{-6}`$, and batch size 8. Consultation-free RL runs for 160
updates at learning rate $`10^{-6}`$, with group size 8, batch size 256,
$`\beta_{\mathrm{opd}}=5.0`$, and $`\lambda_{\mathrm{opd}}=0.01`$.

Stage 2 starts from the Stage 1 policy. Failure mining uses 1,024
label-training games, 256 validation games, and 256 runtime games; each
failed trajectory contributes at most three candidate states, and replay
uses the exact prefix. The resulting cold-start SFT train for two epochs
with maximum sequence length 4,096, learning rate $`2\times 10^{-6}`$,
and batch size 16.

Stage 3 continues in the augmented action space, where each consultation
executes one cloud action before local control resumes. We train for one
epoch over these rows, yielding 160 optimizer updates, and use learning
rate $`10^{-6}`$, group size 8, batch size 256,
$`\alpha_{\mathrm{step}}=0.5`$, $`\alpha_{\mathrm{cf}}=0.25`$, and
$`\lambda_{\mathrm{opd}}=0.01`$.

## Appendix E Cases Study

Success rates quantify the overall benefit of consultation but do not
establish whether the cloud model’s input was strictly necessary. To
examine this question, we analyze four representative rescue cases from
the evaluation traces in Table 7 under aligned comparison settings. Both
ALFWorld branches use the same 30-step budget, while both WebShop
branches use the same 15-step budget, start from the same restored
session, and share the same frozen edge continuation, differing only in
the action taken at the disputed state. We present two representative
cases from each benchmark to illustrate our central finding: targeted
cloud consultation can resolve decision bottlenecks and recover
successful trajectories.

In all four cases, the on-device SLM makes an incorrect decision when
operating alone. The cloud model is consulted at this decision
bottleneck and provides an executable corrective action; the on-device
SLM then resumes control and completes the task successfully. This
reflects Sibyl’s intended division of labor: the cloud model resolves a
difficult local decision, while the edge model executes the remaining
routine steps.

The two ALFWorld cases involve cloud-guided search and target
disambiguation. Once the cloud model identifies the correct location or
target, the on-device SLM correctly performs subsequent actions such as
picking up, cleaning, and placing the object. The two WebShop cases are
more localized: the on-device SLM fails to select the required product
option on its own, whereas the cloud model selects the correct option.
The on-device SLM then executes the same final “buy now” action, which
succeeds with the correct option in place. Together, these traces
provide qualitative evidence that Sibyl invokes the cloud at decision
bottlenecks, corrects local edge-model errors, and delegates the
remaining workflow to the on-device model.

## Appendix F Limitations and Future Work

Sibyl focuses on when an on-device agent should request one-step
assistance from a fixed cloud model. This formulation assumes that the
cloud service is available when needed and that the agent can share
sufficient task context to obtain a useful action. Privacy-sensitive
applications and intermittent connectivity introduce additional
constraints: the agent may need to limit the context it transmits or
continue safely when a consultation fails. Future work could incorporate
privacy-aware context selection and fallback behavior into the
consultation policy.

The current formulation also treats the cloud as a single source of
assistance. A deployed agent may instead have access to models with
different capabilities, prices, and response times. Extending Sibyl to
choose both when to consult and which model to consult could improve its
flexibility under changing workloads and service conditions, while
retaining local execution as the default.
