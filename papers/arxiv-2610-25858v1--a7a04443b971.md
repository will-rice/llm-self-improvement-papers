###### Abstract

Large language model agents are often deployed in environments where new
knowledge, tools, and workflows keep arriving. Such an agent is
therefore expected to adapt continually, learning new tasks as they
arrive without forgetting earlier ones. This resembles the continual
learning problem, but at a pace that conventional gradient updates
cannot sustain. Nonparametric self-evolving agents are a natural
alternative: they adapt by rewriting their own harness, such as prompts,
memory, and skills, from task feedback while the model weights stay
frozen. We study whether such agents are effective continual learners
across four drifting task streams that shift in topic, workflow, or
domain (built from BIRD, BFCL, and ScienceWorld). Evaluating three
representative methods spanning experience retrieval and
self-modification (ReasoningBank, GEPA, and Meta-Harness), we find that
although self-evolution improves aggregate performance on most streams,
higher plasticity consistently comes at the cost of stability.
Specifically, self-modifying methods apply global edits to a shared
prompt or workspace, interfering with unseen tasks and overwriting
earlier knowledge as the stream shifts. Conversely, similarity-based
memory retrieval localizes updates across distant domains, but still
retrieves foreign memories on unseen tasks and suffers from retrieval
collision when similar queries require conflicting workflows. These
findings show that current self-evolving agents remain incomplete
continual learners.

## 1 Introduction

Large language models (LLMs) are increasingly used as agents that act in
interactive environments: they operate software tools and systems ([Yao
et al., 2023](#bib.bib38); [Patil et al., 2025](#bib.bib41); [Zhang et
al., 2025b](#bib.bib49)), navigate embodied simulators ([Shridhar et
al., 2020](#bib.bib33); [Wang et al., 2022](#bib.bib32)), and query
databases or write code on behalf of users ([Li et al.,
2023](#bib.bib23); [Wang et al., 2025](#bib.bib34)). The skills such an
agent requires are not fixed at training time. New tasks, tools, and
workflows continue to emerge after the weights are frozen, and an agent
that serves users over an extended period must learn each new task as it
arrives while preserving what it has already learned. This form of
learning resembles the classical continual learning problem, which
studies how a model can be trained on new tasks over time without
forgetting earlier ones ([Parisi et al., 2019](#bib.bib9); [De Lange et
al., 2022](#bib.bib10); [van de Ven and Tolias, 2019](#bib.bib6)).
Continual learning has recently emerged as a central challenge for LLMs
([Ke et al., 2023](#bib.bib43); [Jang et al., 2022](#bib.bib47); [Luo et
al., 2023](#bib.bib46); [Shenfeld et al., 2026](#bib.bib42); [Shi et
al., 2024](#bib.bib44); [Wu et al., 2024](#bib.bib45)). Conventionally,
it has been realized through gradient updates. An LLM agent, however, is
expected to adapt at the timescale of use: every interaction with the
environment may yield knowledge that is useful in a later session, and
that knowledge should be available as soon as the next session begins.
Performing gradient updates at this pace is challenging: retraining an
LLM after every session is prohibitively expensive, and fine-tuning on a
small number of recent interactions is known to erode general
capabilities ([Luo et al., 2023](#bib.bib46)).

The in-context learning ability of LLMs ([Brown et al.,
2020](#bib.bib48); [Dong et al., 2022](#bib.bib51)) suggests an
alternative route to adaptation. Rather than the weights, an agent can
update its _harness_, everything wrapped around the model: the system
prompt, the accumulated memory, the skill libraries, and the control
code that orchestrates them. _Nonparametric_ self-evolving agents adopt
precisely this strategy, refining the harness from task outcomes and
environment feedback while the weights remain frozen. Two paradigms have
emerged. _Self-modification_ rewrites the artifacts on which the agent
runs, such as its system prompt or the code of the harness itself ([Zhou
et al., 2022](#bib.bib30); [Pryzant et al., 2023](#bib.bib31); [Agrawal
et al., 2025](#bib.bib15); [Lee et al., 2026](#bib.bib39)); _experience
augmentation_ appends past reflections, successful trajectories, or tool
libraries to an external store and retrieves them during execution
([Wang et al., 2024](#bib.bib16); [Zhao et al., 2024](#bib.bib17);
[Ouyang et al., 2025](#bib.bib35)). In either paradigm the harness
constitutes a state carried across tasks; updating it is inexpensive,
takes effect immediately, and leaves the model weights untouched.
Self-evolving agents are therefore natural candidates for continual
learning at inference time.

Both paradigms demonstrate substantial gains on stationary,
single-domain benchmarks, yet whether they support continual learning
has not been examined. Iterative feedback may drive an agent toward
narrow, task-specific shortcuts, such as idiosyncratic formatting
templates or environment-specific action sequences, rather than
transferable problem-solving strategies. Real-world scenarios, moreover,
extend beyond a single benchmark: the agent faces a stream of
heterogeneous tasks served by one shared harness, and every update made
for one task applies to all tasks that follow. Whether self-evolution
under these conditions accumulates durable gains or compounding
interference is unknown. In short: _Are current self-evolving LLM agents
effective continual learners?_

We address this question by evaluating the continual learning dynamics
of self-evolving agents on non-stationary task streams. After
formalizing the _evolver_, the function that updates the harness from
collected experience, together with task streams over multiple task
groups
(§[2](#S2 "2 Background ‣ Are Self-Evolving Agents Continual Learners?")),
we construct four _drifting_ stream scenarios that train one task group
at a time in contiguous blocks
(§[3](#S3 "3 Methodology ‣ Are Self-Evolving Agents Continual Learners?"),
§[4.1](#S4.SS1 "4.1 Experimental Setup ‣ 4 Experiments ‣ Are Self-Evolving Agents Continual Learners?")).
Built from BIRD ([Li et al., 2023](#bib.bib23)), BFCL ([Patil et al.,
2025](#bib.bib41)), and ScienceWorld ([Wang et al., 2022](#bib.bib32)),
these streams isolate shifts in subject matter (_topic drift_),
interaction workflow (_workflow drift_), environment and action space
(_domain drift_), and their sequential combination (_compound drift_).
We evaluate three representative self-evolving methods that span both
paradigms and progressively larger harness surfaces: ReasoningBank
([Ouyang et al., 2025](#bib.bib35)) retrieves accumulated memory items,
GEPA ([Agrawal et al., 2025](#bib.bib15)) rewrites a strategy section in
the system prompt, and Meta-Harness ([Lee et al., 2026](#bib.bib39))
edits the system prompt, memory and skill files, and controller code. To
characterize these dynamics, we measure terminal and average advantage
over the seed harness
(§[3.2](#S3.SS2 "3.2 Metrics ‣ 3 Methodology ‣ Are Self-Evolving Agents Continual Learners?"))
and decompose stream performance into within-block _plasticity_ ($`P`$)
and cross-block _stability_ ($`S`$), combining pre-block interference
($`\bar{I}`$) on unseen groups and post-block forgetting ($`\bar{F}`$)
on earlier groups.

Three main findings emerge:

- •
  Current methods trade stability for plasticity
  (§[4.2](#S4.SS2 "4.2 Current Methods Trade Stability for Plasticity ‣ 4 Experiments ‣ Are Self-Evolving Agents Continual Learners?")).
  While self-evolution improves overall stream performance in most
  settings, no method achieves both high plasticity and high stability:
  expanding the editable surface from retrieved memories (ReasoningBank)
  to the system prompt (GEPA) and full workspace (Meta-Harness)
  increases plasticity or edit freedom at the cost of cross-block
  stability.
- •
  Self-modification causes cross-task interference and overwriting
  (§[4.3](#S4.SS3 "4.3 Self-Modification Causes Cross-Task Interference and Overwriting ‣ 4 Experiments ‣ Are Self-Evolving Agents Continual Learners?")).
  Because GEPA and Meta-Harness apply a single shared prompt or
  workspace to every incoming task, task-specific rules specialized to
  one block interfere with unseen tasks before their block begins and
  are compressed or overwritten by later blocks.
- •
  Similarity-based retrieval cannot prevent interference or collision
  (§[4.4](#S4.SS4 "4.4 Similarity-Based Retrieval Cannot Prevent Interference or Collision ‣ 4 Experiments ‣ Are Self-Evolving Agents Continual Learners?")).
  Retrieving experiences by query similarity (ReasoningBank) avoids
  post-block forgetting across distant domains, but still injects
  foreign memories into unseen task groups and causes retrieval
  collision when distinct workflows share the same domain and embedding
  space.

Our results show that current self-evolving agents remain incomplete
continual learners, calling for mechanisms that isolate task-specific
updates in the harness and condition retrieval beyond surface query
similarity.

## 2 Background

### 2.1 Continual Learning over Task Streams

We define a _task family_ $`\mathcal{F}`$ as a tuple
$`\mathcal{F}=(\mathcal{X},\mathcal{D},\mathcal{Y},R)`$, where
$`\mathcal{X}`$ is an input space (e.g., a query), $`\mathcal{D}`$ is a
distribution over $`\mathcal{X}`$ from which inputs are sampled,
$`\mathcal{Y}`$ is an output space (e.g., a response trajectory), and
$`R:\mathcal{X}\times\mathcal{Y}\to\mathbb{R}`$ is a reward function
that measures the quality of a response trajectory given a query. A
stochastic policy $`\pi:\mathcal{X}\to\Delta(\mathcal{Y})`$ defined on
the task family $`\mathcal{F}`$ takes a query $`x\in\mathcal{X}`$ as
input and outputs a response trajectory $`y\sim\pi(\cdot\mid x)`$, and
the corresponding reward signal is $`r=R(x,y)`$. In the agentic setting
studied here, $`y`$ is an _episode_, the full interaction trajectory
generated in the task environment, and the reward is binary task
success, $`R(x,y)\in\{0,1\}`$.

A continual learning process is defined on $`K`$ task families
$`\mathcal{F}_{k}=(\mathcal{X}_{k},\mathcal{D}_{k},\mathcal{Y}_{k},R_{k})`$,
$`k\in[K]`$, and a weight schedule $`w=(w_{t})_{t=0}^{T-1}`$ with
$`w_{t}=(w_{t,1},\dots,w_{t,K})`$ and $`\sum_{k=1}^{K}w_{t,k}=1`$. A
_task stream_ $`S_{w}=(x_{t})_{t=0}^{T-1}`$ is a sequence of inputs
drawn from the mixture over the families that $`w`$ specifies at each
position,

|     |     |     |     |
| --- | --- | --- | --- |
|     |

````math
x_{t}\sim P_{t}\;:=\;\sum_{k=1}^{K}w_{t,k}\,\mathcal{D}_{k},\qquad t\in\{0,\dots,T-1\}.
``` |  | (1) |

At each timestep $`t=0,\dots,T-1`$, the continual learner receives the
input $`x_{t}`$ from the stream, generates an output
$`y_{t}\sim\pi^{(t)}(\cdot\mid x_{t})`$ with its current policy,
observes a reward $`r_{t}`$, and then outputs the policy $`\pi^{(t+1)}`$
for the next timestep. The average performance of a policy $`\pi`$ over
the $`K`$ families is

|  |  |  |  |
|----|----|----|----|
|  |
``` math
J(\pi)\;=\;\frac{1}{K}\sum_{k=1}^{K}J_{k}(\pi),\qquad J_{k}(\pi)\;=\;\mathbb{E}_{x\sim\mathcal{D}_{k},\;y\sim\pi(\cdot\mid x)}\big[R_{k}(x,y)\big].
``` |  | (2) |

The continual learner seeks to maximize the expected performance
averaged over the whole stream,

|  |  |  |  |
|----|----|----|----|
|  |
``` math
\bar{J}_{w}\;:=\;\mathbb{E}_{S_{w}}\Big[\frac{1}{T}\sum_{t=1}^{T}J\big(\pi^{(t)}\big)\Big],
``` |  | (3) |

where the expectation is over the draw of the stream $`S_{w}`$.

This objective formalizes the tension between plasticity and forgetting.
At every position, $`J`$ evaluates the policy on all $`K`$ families, not
only the one supplying the current input. Each update should therefore
improve the policy on the families it is currently learning from without
degrading it on families seen earlier: a degraded family lowers the
average at every remaining position until it is relearned.

### 2.2 Nonparametric Self-Evolving Agents

We study how a self-evolving agent can serve as the continual learner
above, with its self-evolution step generating the update from
$`\pi^{(t)}`$ to $`\pi^{(t+1)}`$. The agent implements this update
through an *evolver* $`f`$. Let
$`\mathcal{H}_{t}:=\{(x_{\tau},y_{\tau},r_{\tau})\}_{\tau=0}^{t}`$
denote the experience collected up to timestep $`t`$. After each
episode, the evolver maps the current policy and the accumulated
experience to the next policy,

|     |                                                     |     |     |
|-----|-----------------------------------------------------|-----|-----|
|     |
       ``` math
       \pi^{(t+1)}=f\big(\pi^{(t)},\;\mathcal{H}_{t}\big).
       ```                                                  |     | (4) |

Note that the evolver may use only a subset of the history to generate
an update, which is usually the case in current self-evolving methods.
Existing self-evolving methods are formulated on a single task family,
which corresponds to the special case $`K=1`$ of the stream above; we
apply the same update on a stream, with $`x_{t}`$ drawn from $`P_{t}`$.

In the LLM-agent setting, a policy is an agent determined by an LLM with
parameters $`\theta`$ and a *harness* $`c`$: the system prompt,
accumulated memory, skill libraries, and the control code that
orchestrates them. Given an input $`x`$, rolling out the model in the
task environment yields an episode $`y\sim\pi_{\theta}(\cdot\mid x,c)`$;
we write this episode-level policy $`\pi_{\theta,c}`$. An evolver may
update either component. In this work, we study the nonparametric case,
in which $`\theta`$ is frozen and only the harness is updated, such as
in GEPA ([Agrawal et al., 2025](#bib.bib15)), Meta-Harness ([Lee et al.,
2026](#bib.bib39)), and ReasoningBank ([Ouyang et al.,
2025](#bib.bib35)), so that Eq.
[4](#S2.E4 "In 2.2 Nonparametric Self-Evolving Agents ‣ 2 Background ‣ Are Self-Evolving Agents Continual Learners?")
reduces to

|     |                                             |     |     |
|-----|---------------------------------------------|-----|-----|
|     |
       ``` math
       c_{t+1}=f\big(c_{t},\;\mathcal{H}_{t}\big).
       ```                                          |     | (5) |

On a stream, the evolver traverses the inputs in arrival order and
updates the harness as in Eq.
[5](#S2.E5 "In 2.2 Nonparametric Self-Evolving Agents ‣ 2 Background ‣ Are Self-Evolving Agents Continual Learners?"),
yielding $`c_{0},c_{1},\dots,c_{T}`$ with
$`\pi^{(t)}=\pi_{\theta,c_{t}}`$ throughout; the seed harness $`c_{0}`$
defines the initial policy $`\pi^{(0)}`$. We define the performance of
$`f`$ under a schedule $`w`$ as the objective of Eq.
[3](#S2.E3 "In 2.1 Continual Learning over Task Streams ‣ 2 Background ‣ Are Self-Evolving Agents Continual Learners?")
evaluated on the policy sequence that $`f`$ generates,

|  |  |  |  |
|----|----|----|----|
|  |
``` math
\bar{J}_{w}(f)\;:=\;\mathbb{E}_{S_{w},f}\Big[\frac{1}{T}\sum_{t=1}^{T}J\big(\pi^{(t)}\big)\Big].
``` |  | (6) |

## 3 Methodology

In this work, we study two factors of the problem, the evolver $`f`$ and
the weight schedule $`w`$ of the task stream, and we evaluate an evolver
by how much it improves the objective $`\bar{J}_{w}(f)`$ of Eq.
[6](#S2.E6 "In 2.2 Nonparametric Self-Evolving Agents ‣ 2 Background ‣ Are Self-Evolving Agents Continual Learners?")
over the seed harness.

### 3.1 Task Stream Configurations

We instantiate the task stream as a *drifting* stream, in which
$`w_{t}`$ is one-hot and piecewise-constant: the stream is a sequence of
contiguous blocks, each drawing all of its tasks from a single task
group, and the active group changes only at block boundaries. Within a
block, every update is driven by the active group, while earlier groups
receive no further tasks and hence no further feedback, and later groups
have not yet been encountered. In continual deployment, transitions
between blocks may alter the subject matter (topic drift), the
interaction workflow required for a correct response (workflow drift),
the environment and action space itself (domain drift), or a combination
of all three (compound drift); we detail the concrete benchmark streams
that instantiate these four drift scenarios in
§[4.1](#S4.SS1 "4.1 Experimental Setup ‣ 4 Experiments ‣ Are Self-Evolving Agents Continual Learners?").

In every stream the method maintains one shared harness across the
entire horizon. The stream never reveals the group label of a task or
the block boundaries, and the agent is never told that it operates in a
drifting stream or that it should balance performance across groups. The
agent must infer the structure of incoming tasks on its own and encode
any distinction it finds in the harness, mirroring task-free continual
learning scenarios ([Aljundi et al., 2019](#bib.bib5); [De Lange et al.,
2022](#bib.bib10); [Buzzega et al., 2020](#bib.bib8)).

### 3.2 Metrics

We evaluate self-evolving agents by how much evolution improves the
objective $`\bar{J}_{w}(f)`$ of Eq.
[6](#S2.E6 "In 2.2 Nonparametric Self-Evolving Agents ‣ 2 Background ‣ Are Self-Evolving Agents Continual Learners?")
over the seed harness. Because evaluating the harness after every update
is costly, we compute accuracy at $`M`$ checkpoints
$`0<t_{1}<\dots<t_{M}=T`$ along with the seed position $`t_{0}=0`$. For
a stream position $`t`$ and a family $`k`$, let $`A[t,k]`$ denote the
accuracy (in %) of the frozen harness $`c_{t}`$ on a disjoint hold-out
set $`\mathcal{D}_{k}^{\text{eval}}`$ of family $`k`$:

|  |  |  |  |
|----|----|----|----|
|  |
``` math
A[t,k]\;=\;\frac{1}{|\mathcal{D}_{k}^{\text{eval}}|}\sum_{x\in\mathcal{D}_{k}^{\text{eval}}}\mathbb{E}_{y\sim\pi_{\theta,c_{t}}(\cdot\mid x)}\big[R_{k}(x,y)\big].
``` |  | (7) |

The seed harness $`c_{0}`$ gives the per-family baseline
$`B_{k}:=A[0,k]`$ before any evolution. Offsetting $`A[t,k]`$ against
$`B_{k}`$ isolates what evolution contributes, reported in percentage
points (pp.). We summarize overall stream performance with two
quantities: the *terminal advantage* (Term.), which averages
$`A[T,k]-B_{k}`$ over all $`K`$ families at the end of the stream, and
the *average advantage* ($`\bar{\Delta}`$), which averages
$`A[t_{m},k]-B_{k}`$ over all $`K`$ families and all $`M`$ post-seed
checkpoints:

|  |  |  |  |
|----|----|----|----|
|  |
``` math
\bar{\Delta}\;=\;\frac{1}{MK}\sum_{m=1}^{M}\sum_{k=1}^{K}\big(A[t_{m},k]-B_{k}\big),\qquad\text{Term.}\;=\;\frac{1}{K}\sum_{k=1}^{K}\big(A[T,k]-B_{k}\big).
``` |  | (8) |

Overall advantage measures the size of the improvement but not its
composition: the same value can come from balanced gains on every family
or from gains on the active family paid for by losses on the others. In
a drifting stream where the block of family $`k`$ occupies positions
$`\sigma_{k}<t\leq\tau_{k}`$, we decompose performance into *plasticity*
and *stability*:

- •
  *Plasticity* $`P`$ measures how much each family learns during its own
  training block ([Riemer et al., 2018](#bib.bib29); [Kemker et al.,
  2018](#bib.bib26)), defined as the advantage over the seed at the end
  $`\tau_{k}`$ of family $`k`$’s block, $`P_{k}=A[\tau_{k},k]-B_{k}`$,
  averaged over all $`K`$ families:

  |     |                                                               |     |     |
  |-----|---------------------------------------------------------------|-----|-----|
  |     |
         ``` math
         P\;=\;\frac{1}{K}\sum_{k=1}^{K}\big(A[\tau_{k},k]-B_{k}\big).
         ```                                                            |     | (9) |
- •
  *Stability* $`S`$ measures the degradation a family incurs while the
  stream trains the other families ([Lopez-Paz and Ranzato,
  2017](#bib.bib4); [Kemker et al., 2018](#bib.bib26)). It combines
  *pre-block interference* $`I_{k}`$, the mean drop below the seed at
  checkpoints before family $`k`$’s block begins ($`\sigma_{k}`$), and
  *post-block forgetting* $`F_{k}`$, the drop from the end of family
  $`k`$’s block ($`\tau_{k}`$) to the end of the stream ($`T`$):

  |  |  |  |  |
  |----|----|----|----|
  |  |
  ``` math
  I_{k}\;=\;\frac{1}{M_{k}}\sum_{0<t_{m}\leq\sigma_{k}}\max\big(0,\,B_{k}-A[t_{m},k]\big),\qquad F_{k}\;=\;\max\big(0,\,A[\tau_{k},k]-A[T,k]\big),
  ``` |  | (10) |

  where $`M_{k}`$ is the number of checkpoints with
  $`0<t_{m}\leq\sigma_{k}`$ (with $`I_{k}=0`$ when $`M_{k}=0`$, and
  $`F_{k}=0`$ when $`\tau_{k}=T`$). Averaging $`I_{k}`$ and $`F_{k}`$
  over the $`K`$ families gives stream-level interference $`\bar{I}`$
  and forgetting $`\bar{F}`$, and

  |  |  |  |  |
  |----|----|----|----|
  |  |
  ``` math
  S\;=\;-\frac{1}{K}\sum_{k=1}^{K}\big(I_{k}+F_{k}\big)\;=\;-\big(\bar{I}+\bar{F}\big).
  ``` |  | (11) |

## 4 Experiments

### 4.1 Experimental Setup

#### Datasets and streams.

We construct task streams from three agentic benchmarks: BIRD ([Li et
al., 2023](#bib.bib23)), text-to-SQL querying over relational databases;
BFCL ([Patil et al., 2025](#bib.bib41)), multi-turn user requests served
by calling stateful APIs; and ScienceWorld ([Wang et al.,
2022](#bib.bib32)), interactive science experiments in a text
environment. Every stream consists of consecutive blocks of 50 training
tasks per group, evaluated on disjoint hold-out sets
$`\mathcal{D}_{k}^{\text{eval}}`$ of 50 tasks per group (90 for
ScienceWorld). Following
§[3.1](#S3.SS1 "3.1 Task Stream Configurations ‣ 3 Methodology ‣ Are Self-Evolving Agents Continual Learners?"),
we construct four drifting streams that isolate three types of
distribution shift and their combination:

- •
  *Topic drift* ($`T=150,K=3`$). The environment and workflow stay fixed
  while the underlying topic changes: the agent trains on three BIRD
  databases in sequence, BIRD-F1 (formula_1) $`\to`$ BIRD-Code
  (codebase_community) $`\to`$ BIRD-TP (thrombosis_prediction). While
  the high-level text-to-SQL task remains the same, each database
  carries its own schema and local conventions that must be learned
  without transferring stale assumptions to the next.
- •
  *Workflow drift* ($`T=100,K=2`$). The environment and tool catalog
  stay fixed while the workflow required for a correct response changes:
  the agent trains on BFCL-Miss followed by BFCL-Base. Both groups use
  the same APIs, but BFCL-Miss requires the agent to ask the user to
  clarify missing arguments, whereas BFCL-Base supplies all required
  arguments and penalizes unnecessary clarification.
- •
  *Domain drift* ($`T=150,K=3`$). The environment itself changes along
  with its observation and action spaces: the agent trains across
  ScienceWorld $`\to`$ BFCL-Base $`\to`$ BIRD-F1, spanning interactive
  embodied environments, multi-turn tool use, and database querying.
- •
  *Compound drift* ($`T=200,K=4`$). Over a longer deployment horizon,
  shifts in topic, domain, and workflow occur in sequence rather than in
  isolation: BIRD-Code $`\to`$ BIRD-F1 (*topic*) $`\to`$ BFCL-Miss
  (*domain*) $`\to`$ BFCL-Base (*workflow*), requiring the evolver to
  handle both cross-domain transitions and conflicting within-domain
  shifts in a single stream.

#### Model and harness.

We hold the base model fixed across methods and streams so that
differences arise from the evolver alone, and use Gemini 3.6 Flash
([Google DeepMind, 2026](#bib.bib36)) in a ReAct-style loop ([Yao et
al., 2023](#bib.bib38)), which alternates environment observations with
actions. Per-family action interfaces are described in Appendix
[D](#A4 "Appendix D Implementation Details ‣ Are Self-Evolving Agents Continual Learners?").

#### Self-evolving algorithms.

We compare three representative methods that span experience
augmentation and self-modification across progressively larger update
spaces: ReasoningBank ([Ouyang et al., 2025](#bib.bib35)), which
distills completed episodes into memory items in an external store and
retrieves the top-$`1`$ most similar item into the context of later
episodes; GEPA ([Agrawal et al., 2025](#bib.bib15)), which rewrites a
shared strategy section in the system prompt by reflective mutation over
collected rollouts; and Meta-Harness ([Lee et al., 2026](#bib.bib39)),
which proposes edits to a persistent workspace (including the system
prompt, memory and skill files, and the controller code harness.py)
through a coding agent and accepts an edit only when it improves
validation accuracy on the active sub-block. Every run starts from the
same seed harness $`c_{0}`$ with an empty state and receives binary
task-success feedback $`r_{t}\in\{0,1\}`$ after each training task.

#### Evaluation protocol.

We checkpoint the harness at every block boundary (every 50 stream
positions) and evaluate each frozen checkpoint on the hold-out sets of
all $`K`$ groups in the stream, averaging over eight rollouts per
instance to estimate $`A[t,k]`$. Further details are in Appendix
[D](#A4 "Appendix D Implementation Details ‣ Are Self-Evolving Agents Continual Learners?").

### 4.2 Current Methods Trade Stability for Plasticity

Evaluating the three methods across the four drifting streams shows that
self-evolution improves both terminal and average performance in most
settings (Table

Figure
[1](#S4.F1 "Figure 1 ‣ Evaluation protocol. ‣ 4.1 Experimental Setup ‣ 4 Experiments ‣ Are Self-Evolving Agents Continual Learners?")).
All three methods achieve positive gains on workflow, domain, and
compound drift, as well as in the mean across the four scenarios:
averaged over streams, terminal advantage reaches $`+3.7`$ for GEPA,
$`+2.5`$ for ReasoningBank, and $`+1.4`$ for Meta-Harness, with average
advantage $`\bar{\Delta}`$ between $`+1.8`$ and $`+3.1`$. Only topic
drift yields near-zero or slightly negative net change ($`-1.7`$ for
GEPA, $`+0.3`$ for ReasoningBank, and $`-1.5`$ for Meta-Harness).

Decomposing these aggregate scores into within-block plasticity $`P`$
and cross-block stability $`S`$, however, reveals a consistent negative
correlation between learning the active block and preserving performance
on the others (Table
[1](#S4.T1 "Table 1 ‣ Model and harness. ‣ 4.1 Experimental Setup ‣ 4 Experiments ‣ Are Self-Evolving Agents Continual Learners?");
Figure
[2](#S4.F2 "Figure 2 ‣ 4.2 Current Methods Trade Stability for Plasticity ‣ 4 Experiments ‣ Are Self-Evolving Agents Continual Learners?")).
Across all four scenarios, plasticity and stability exhibit a clear
trade-off: higher plasticity on the group being trained is accompanied
by larger stability losses across blocks, so the most plastic method in
each scenario is always less stable than the most conservative one.

This trade-off reflects where each method applies its updates. GEPA
rewrites a single shared strategy prompt that is injected into every
rollout. A rule discovered during a block therefore changes the agent’s
behavior broadly across all tasks of that group, giving GEPA the highest
plasticity in every scenario ($`+6.2`$ on average, reaching $`+11.0`$ on
workflow drift and $`+7.5`$ on compound drift). Because later blocks
rewrite the same shared prompt and apply it to every group, however,
GEPA also incurs the largest stability loss ($`-4.3`$ on average).
ReasoningBank, by contrast, leaves the system prompt untouched,
appending one memory item per episode to an external store and
retrieving only the single most similar item at read time. Because an
item is injected only into episodes whose query resembles its source
episode, updates remain localized and ReasoningBank achieves the highest
average stability ($`-1.9`$, with $`-0.4`$ on domain drift and $`-1.4`$
on compound drift), at the cost of roughly half the plasticity of GEPA
($`+3.3`$ on average). Like GEPA, Meta-Harness modifies a shared global
workspace and is the least stable method on domain and compound drift
($`S=-3.1`$ and $`-4.4`$). It appears stable on topic and workflow drift
($`S=-0.3`$ and $`-0.5`$) only because its validation gate rejects half
or more of the candidate updates, freezing the workspace on later blocks
at the cost of low plasticity. Removing this gate so that every
checkpoint accepts the best candidate drops its stability to $`-3.1`$ on
topic drift and $`-5.5`$ on workflow drift.

### 4.3 Self-Modification Causes Cross-Task Interference and Overwriting

#### Pre-block interference from task-specific rules.

In self-modifying methods (GEPA and Meta-Harness), every update writes
to a shared instruction or workspace surface that is injected into all
subsequent rollouts, creating two forms of instability: pre-block
interference $`I_{k}`$ and post-block forgetting $`F_{k}`$ (Eq.
[10](#S3.E10 "In 2nd item ‣ 3.2 Metrics ‣ 3 Methodology ‣ Are Self-Evolving Agents Continual Learners?")).
Before a group’s training block begins ($`t\leq\sigma_{k}`$), rules
specialized to earlier blocks are applied unconditionally to unseen
tasks, pushing their accuracy below the seed harness $`B_{k}`$ (Table

and Figure

Across unrelated domains, training on ScienceWorld in domain drift
lowers BFCL-Base at position 50 by $`5.5`$ under GEPA and $`1.5`$ under
Meta-Harness, and training on the two BIRD blocks in compound drift

#### Behavioral reversal under conflicting workflows.

Forgetting is most severe when consecutive blocks have nearly identical
queries and domains but require opposite workflows, as in workflow drift
and the BFCL transition of compound drift (Figure
[3](#S4.F3 "Figure 3 ‣ Pre-block interference from task-specific rules. ‣ 4.3 Self-Modification Causes Cross-Task Interference and Overwriting ‣ 4 Experiments ‣ Are Self-Evolving Agents Continual Learners?")c).
Because the surface domain and tool catalog do not change, the model
fails to recognize a shift and rewrites the earlier policy into its
opposite. Before the BFCL-Miss block, the seed agent calls tools
speculatively on $`91\%`$ to $`93\%`$ of BFCL-Miss episodes and asks the
user for missing arguments on only $`3.8\%`$ to $`5.8\%`$. Training on
BFCL-Miss teaches both self-modifying methods to withhold speculative
calls and ask for clarification, raising the clarification rate after
the BFCL-Miss block to $`29.8\%`$ under GEPA on workflow drift
($`+15.5`$ accuracy gain) and $`60.8\%`$ under Meta-Harness on compound
drift ($`+13.8`$). In the subsequent BFCL-Base block, however, all
required arguments are already supplied and asking unnecessary
clarifying questions is penalized. Both methods consequently rewrite
their instructions to execute tool calls directly without asking the
user. On workflow drift, this rewrite under GEPA cuts the clarification
rate on BFCL-Miss from $`29.8\%`$ ($`119/400`$ rollouts) to $`11.2\%`$
($`45/400`$) and drops BFCL-Miss accuracy by $`13.0`$ (from $`+15.5`$ at

[1](#S4.T1 "Table 1 ‣ Model and harness. ‣ 4.1 Experimental Setup ‣ 4 Experiments ‣ Are Self-Evolving Agents Continual Learners?")).
Meta-Harness shows the same reversal on compound drift. At position 150,
it writes a rule across its prompt, memory, and skill files that forbids
speculative calls when arguments are missing. During the BFCL-Base block
at position 175, however, an accepted edit overwrites all three files
with instructions to execute tools immediately in sequence. This reduces
clarification asks on BFCL-Miss from $`60.8\%`$ to $`8.5\%`$
($`34/400`$) and drops accuracy by $`10.2`$ at position 200.

streams, however, retrieval alone still fails to prevent continual
learning instability (Table
[1](#S4.T1 "Table 1 ‣ Model and harness. ‣ 4.1 Experimental Setup ‣ 4 Experiments ‣ Are Self-Evolving Agents Continual Learners?")
and Figure
[4](#S4.F4 "Figure 4 ‣ 4.4 Similarity-Based Retrieval Cannot Prevent Interference or Collision ‣ 4 Experiments ‣ Are Self-Evolving Agents Continual Learners?")).

#### Pre-block interference from foreign memory retrieval.

Because retrieval always injects the nearest stored match without a
similarity threshold, any group evaluated before its own training block
begins ($`t\leq\sigma_{k}`$) has zero in-group entries in the store and
receives foreign memories in $`100\%`$ of episodes (Figure
[4](#S4.F4 "Figure 4 ‣ 4.4 Similarity-Based Retrieval Cannot Prevent Interference or Collision ‣ 4 Experiments ‣ Are Self-Evolving Agents Continual Learners?")a).
On domain drift, injecting ScienceWorld memories into BFCL-Base at
position 50 lowers accuracy by $`1.2`$; on compound drift, every
BFCL-Miss episode at positions 50 and 100 receives a BIRD SQL
reflection, pulling BFCL-Miss up to $`3.2`$ below the seed; and on topic
drift, retrieving BIRD-F1 and BIRD-Code memories lowers BIRD-TP by
$`3.5`$ at position 100. While adding a similarity threshold could
mitigate this unconditional retrieval, query similarity alone struggles
to distinguish how related two queries actually are: even within the
same text-to-SQL task, queries across different topics have a
nearest-match similarity ($`0.60`$–$`0.64`$, dashed box in Figure
[4](#S4.F4 "Figure 4 ‣ 4.4 Similarity-Based Retrieval Cannot Prevent Interference or Collision ‣ 4 Experiments ‣ Are Self-Evolving Agents Continual Learners?")b)
that is barely higher than the similarity across completely different
tasks and domains ($`0.56`$–$`0.63`$).

#### Retrieval collision when similar queries require conflicting workflows.

Even with a similarity threshold, retrieval cannot prevent pre-block
interference or post-block forgetting when distinct task groups occupy
the same region of the embedding space (Figure
[4](#S4.F4 "Figure 4 ‣ 4.4 Similarity-Based Retrieval Cannot Prevent Interference or Collision ‣ 4 Experiments ‣ Are Self-Evolving Agents Continual Learners?")b).
Under workflow shifts, BFCL-Miss and BFCL-Base queries refer to the same
API catalog and are phrased in nearly identical language, exhibiting a
mean pairwise cosine similarity of $`0.667`$ and a mean nearest-match
similarity of $`0.835`$–$`0.840`$, which is indistinguishable from their
within-group similarity ($`0.664`$–$`0.666`$ pairwise and
$`0.834`$–$`0.837`$ nearest-match; red box in Figure
[4](#S4.F4 "Figure 4 ‣ 4.4 Similarity-Based Retrieval Cannot Prevent Interference or Collision ‣ 4 Experiments ‣ Are Self-Evolving Agents Continual Learners?")b).
No similarity threshold can separate the two groups. Before the
BFCL-Base block begins on workflow drift, BFCL-Miss abstention memories
are retrieved into BFCL-Base episodes, causing pre-block interference
($`-1.5`$ at position 50). Conversely, once the BFCL-Base block
populates the store with memories that reward multi-step tool execution,
$`52\%`$ of BFCL-Miss evaluation episodes at the end of both workflow
drift and compound drift (Figure
[4](#S4.F4 "Figure 4 ‣ 4.4 Similarity-Based Retrieval Cannot Prevent Interference or Collision ‣ 4 Experiments ‣ Are Self-Evolving Agents Continual Learners?")a)
retrieve a BFCL-Base memory (while $`46\%`$ of BFCL-Base episodes
retrieve a BFCL-Miss memory), displacing the earlier abstention examples
and dropping BFCL-Miss accuracy by $`8.0`$ on workflow drift
($`+12.5\to+4.5`$). Semantic similarity between queries captures topical
overlap, but cannot determine whether a stored trajectory’s workflow is
compatible with the incoming task.

## 5 Related Work

#### Self-evolving agents.

Self-evolving agents update themselves from their own experience rather
than remaining fixed after training. In the nonparametric form studied
here, the evolver edits the harness and leaves the weights untouched,
following one of two paradigms. *Self-modification* rewrites the
artifacts the agent runs on: automatic prompt optimization such as GEPA
([Agrawal et al., 2025](#bib.bib15)), TextGrad ([Yuksekgonul et al.,
2024](#bib.bib24)), and PromptBreeder ([Fernando et al.,
2024](#bib.bib14)) rewrites the system prompt from rollout feedback,
while ADAS ([Hu et al., 2025](#bib.bib18)), Darwin Gödel Machine ([Zhang
et al., 2025c](#bib.bib50)), EvoTest ([He et al., 2026](#bib.bib25)),
and Meta-Harness ([Lee et al., 2026](#bib.bib39)) extend the edits to
the agent’s code ([Yin et al., 2024](#bib.bib21)). *Experience
augmentation* keeps the artifacts fixed and accumulates an external
store that later episodes retrieve from: reflections in Reflexion
([Shinn et al., 2023](#bib.bib11)) and ExpeL ([Zhao et al.,
2024](#bib.bib17)), skills in Voyager ([Wang et al., 2024](#bib.bib16)),
and memory items in ReasoningBank ([Ouyang et al., 2025](#bib.bib35)),
MemGen ([Zhang et al., 2025a](#bib.bib22)), and Mem0 ([Chhikara et al.,
2025](#bib.bib19)). Parametric counterparts instead update the weights
at test time, through self-correction training in SCoRe ([Kumar et al.,
2024](#bib.bib12)), reinforcement learning in TTRL ([Zuo et al.,
2025](#bib.bib13)) and TTT-Discover ([Yuksekgonul et al.,
2026](#bib.bib20)), or a learned evolver in LSE ([Chen et al.,
2026](#bib.bib40)). Unlike prior work evaluated within a single task
family, we study nonparametric methods on heterogeneous streams.

#### Continual learning.

Continual learning studies a learner that faces a sequence of tasks and
must acquire each without degrading performance on earlier ones, known
as catastrophic forgetting ([McCloskey and Cohen, 1989](#bib.bib1);
[French, 1999](#bib.bib2)). Gradient-based methods counter it by
protecting weights important to earlier tasks ([Kirkpatrick et al.,
2017](#bib.bib3)), rehearsing stored examples ([Lopez-Paz and Ranzato,
2017](#bib.bib4); [Chaudhry et al., 2019](#bib.bib7); [Buzzega et al.,
2020](#bib.bib8)), or shaping updates to maximize transfer and minimize
interference ([Riemer et al., 2018](#bib.bib29)); see [Parisi et al.
(2019)](#bib.bib9) and [De Lange et al. (2022)](#bib.bib10) for surveys.
Our plasticity and stability metrics adapt standard continual-learning
evaluation ([Lopez-Paz and Ranzato, 2017](#bib.bib4); [Kemker et al.,
2018](#bib.bib26)); task-free and online formulations relax explicit
task boundaries ([Aljundi et al., 2019](#bib.bib5); [Koh et al.,
2022](#bib.bib28)), and continual evaluation exposes transient drops
missed by end-of-task evaluation ([De Lange et al., 2023](#bib.bib27)),
motivating our checkpoint resolution. For LLMs, continual learning has
focused on weight updates ([Shi et al., 2024](#bib.bib44); [Wu et al.,
2024](#bib.bib45)): continual pre-training on emerging corpora ([Ke et
al., 2023](#bib.bib43); [Jang et al., 2022](#bib.bib47)), forgetting
under sequential fine-tuning ([Luo et al., 2023](#bib.bib46)), and
mitigation algorithms ([Shenfeld et al., 2026](#bib.bib42)). Rather than
updating weights, the agents studied here keep weights frozen and carry
their state in the harness.

## 6 Conclusion

We asked whether nonparametric self-evolving LLM agents are effective
continual learners, and found that current methods remain caught in a
trade-off between plasticity and stability. Across four drifting stream
scenarios spanning shifts in topic, workflow, domain, and their
combination, self-evolution improves overall performance over the seed
harness in most settings, yet no method learns new task groups strongly
without degrading others. Self-modifying methods (GEPA and Meta-Harness)
can achieve high plasticity when rewriting a shared prompt, but because
task-specific rules are applied globally across all subsequent rollouts,
instructions learned on one block interfere with unseen tasks and are
compressed or overwritten by later blocks, most severely when
consecutive blocks share a domain but require conflicting workflows.
Experience augmentation via query-similarity retrieval (ReasoningBank)
avoids overwriting the shared prompt and prevents forgetting across
distant domains, but still injects foreign memories before a group is
encountered and suffers from retrieval collision when distinct workflows
occupy the same region of the embedding space. Together, these findings
expose the limitations of current self-evolving agents as continual
learners.

## Appendix A Results on the Interleaved Mixture Stream

As a stationary reference, we also evaluate a *mixture* stream in which
$`w_{t}`$ is uniform across $`t`$ and every position samples a random
task group, corresponding to rehearsal in gradient-based continual
learning ([Lopez-Paz and Ranzato, 2017](#bib.bib4); [Chaudhry et al.,
2019](#bib.bib7)). To test whether interleaving task groups throughout
the stream eliminates the instability observed on drifting streams, we
evaluate a uniformly interleaved Mix schedule on the four-group compound
stream (BIRD-Code, BIRD-F1, BFCL-Miss, and BFCL-Base sampled uniformly
across $`T=200`$ tasks; Table
[2](#A1.T2 "Table 2 ‣ Appendix A Results on the Interleaved Mixture Stream ‣ Are Self-Evolving Agents Continual Learners?")).
Because all groups are active throughout, pre-block interference and
post-block forgetting are not defined, and we compare terminal advantage
(Term.) and average advantage ($`\bar{\Delta}`$) directly against the
corresponding blocked stream.

Interleaving tasks does not resolve the contention on a shared prompt:
GEPA’s terminal advantage drops from $`+5.8`$ on the blocked stream to
$`+0.9`$ on Mix (with BIRD-F1 falling to $`-4.5`$ and BIRD-Code to
$`-1.0`$), while Meta-Harness also degrades on BIRD-F1 ($`-0.5\to-3.0`$)
even as its overall terminal advantage rises from $`+0.8`$ to $`+1.9`$.
Figure
[5](#A1.F5 "Figure 5 ‣ Appendix A Results on the Interleaved Mixture Stream ‣ Are Self-Evolving Agents Continual Learners?")
tracks the composition of GEPA’s shared strategy prompt across
checkpoints of the compound Mix stream, where lines are attributed by
benchmark section and group-specific terms (and rules not specific to
any group are counted as generic). Even when all four groups are active
throughout the stream, they contend for space in the single shared
prompt: BIRD-Code’s share falls from $`37.0\%`$ at position 50 to
$`21.8\%`$ at position 100 and $`5.8\%`$ at position 200 while BIRD-F1
rises from $`0\%`$ to $`22.8\%`$, and competing SQL and BFCL updates
leave both BIRD databases below the seed at the end of the stream.

#### Seed harness.

At each step the agent receives the environment observation and outputs
an action in an act block (Appendix
[E](#A5 "Appendix E Seed System Prompt and Environment Preambles ‣ Are Self-Evolving Agents Continual Learners?")).
In BIRD, the agent interacts with a read-only SQLite database via a Bash
workspace (with the sqlite3 CLI and per-table CSV descriptions) and
finishes by writing its SQL query to /workspace/answer.sql and calling
submit(path="/workspace/answer.sql"); in BFCL, the block carries a list
of Python function calls executed against stateful multi-turn APIs (such
as a file system, a trading account, and a travel-booking service) or a
reply(...) message to the user; in ScienceWorld, legal text actions are
defined and processed directly by the simulator.

#### Retrieval.

ReasoningBank embeds its memory items and the current query with
gemini-embedding-2, and retrieves the nearest stored entry by cosine
similarity in that space. It is the only method with a retrieval step:
GEPA and Meta-Harness carry their state in a shared prompt and workspace
respectively, both of which are read in full.

#### Meta-Harness proposer.

Meta-Harness may rewrite the code of the harness itself, so its proposer
has to read and edit a working codebase. We therefore run the proposer
in the opencode harness ([anomalyco, 2026](#bib.bib37)) rather than in
the seed harness, which is the plain ReAct loop of
§[4.1](#S4.SS1 "4.1 Experimental Setup ‣ 4 Experiments ‣ Are Self-Evolving Agents Continual Learners?")
and offers no such capability. The proposer uses the same Gemini 3.6
Flash ([Google DeepMind, 2026](#bib.bib36)) as the backend model, with
the same generation parameters in Table
[5](#A4.T5 "Table 5 ‣ Appendix D Implementation Details ‣ Are Self-Evolving Agents Continual Learners?").
````
