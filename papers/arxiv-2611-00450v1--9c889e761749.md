# From Lookups to Lessons: Turning Retrieved Knowledge into Parametric Memory

Changjiang Han, Bowei He, Ye Yuan, Weixu Zhang, Haolun Wu, Xue Liu,
Jikun Kang MBZUAI, McGill University, Mila, Salesforce
Changjiang.Han@mbzuai.ac.ae

###### Abstract

Retrieval-augmented generation (RAG) helps large language models (LLMs)
answer factual questions beyond their training data, but it adds storage
and inference costs. Distilling previously retrieved information into
parametric memories enables reuse without online retrieval. However,
training the memory to mimic a retriever rewards accurate independent
predictions, which do not necessarily improve the final output quality
when combined with the LLM’s existing predictions. To address this, we
introduce ResMem, in which the LLM reads retrieved text offline to
generate teacher targets. This design avoids storing massive token
representations, unlike existing parametric memory approaches such as
MLP Memory, which relies on k-nearest neighbor (kNN) datastores.
Furthermore, by using the LLM as an offline teacher that reads
privileged retrieved evidence alongside the input, we train a parametric
memory to learn an additive logit residual. This residual aligns the
predictions of a student sharing the same backbone with the teacher
distribution, while self-distillation updates remain confined to the
parametric memory. On a Wikipedia subset, ResMem reduces the storage
retained for teacher construction by 94.7% compared with the evaluated
kNN pipeline. Across five question answering datasets, ResMem raises
mean token F1 from 32.83% for the frozen LLM to 34.48%. It also breaks
21% fewer of the LLM’s correct answers than a kNN-trained memory. These
findings validate our motivation of treating retrieval as a learning
resource, with parametric memory shaped by how retrieved knowledge is
used to inform the model’s future predictions. Code and model weights
are available at
[https://github.com/SSRand/From-Lookups-to-Lessons](https://github.com/SSRand/From-Lookups-to-Lessons)
and
[https://huggingface.co/RandHan/ResMem-Mistral-7B-v0.3](https://huggingface.co/RandHan/ResMem-Mistral-7B-v0.3).

## 1 Introduction

Nowadays, many LLM applications need information beyond the current
prompt, such as knowledge from external corpora and facts introduced in
earlier interactions ([Park et al., 2023](#bib.bib33); [Zhang et al.,
2025](#bib.bib52)). One option is to keep such information in the
model’s active context. However, longer context windows do not ensure
reliable use of information at every position ([Liu et al.,
2024b](#bib.bib28)), and growing histories still require managing a
finite active context ([Packer et al., 2023](#bib.bib32)).
Retrieval-augmented generation (RAG) is a widely used way to recover
relevant evidence from external storage ([Lewis et al.,
2020](#bib.bib23)). This access requires maintaining a corpus and its
index, while retrieving and reading the evidence adds inference latency.
At corpus scale, these costs motivate storing knowledge for use without
online retrieval.

![Refer to caption](2611.00450v1/framework.png)

Figure 1: Training pipelines. (a) MLP Memory fits a memory alone to kNN
targets; the base enters only at inference
(Eq. [5](#S3.E5 "In 3.3 Inference and matched control ‣ 3 Methodology ‣ From Lookups to Lessons: Turning Retrieved Knowledge into Parametric Memory")).
(b) ResMem fits a logit residual so that base plus residual matches an
evidence-reading teacher; inference drops the teacher and scales the
residual by $`\gamma`$
(Eq. [3](#S3.E3 "In 3.3 Inference and matched control ‣ 3 Methodology ‣ From Lookups to Lessons: Turning Retrieved Knowledge into Parametric Memory")).

Retriever-pretrained parametric memories offer such retrieval-free
storage: they learn what a retriever would return and keep it in network
weights, so inference needs no index or search. Building on kNN language
models ([Khandelwal et al., 2020](#bib.bib18)), MLP Memory and Memory
Decoder train a memory to reproduce a retriever’s next-token
distribution, then interpolate its prediction with a frozen base model
([Wei et al., 2025](#bib.bib44); [Cao et al., 2025](#bib.bib5)). MLP
Memory reports storage compression and faster inference, while Memory
Decoder enables reuse across compatible base models. Both memories,
however, learn to match the retriever alone and meet the base model only
at inference. Their training loss never sees the base prediction
(Figure [1](#S1.F1 "Figure 1 ‣ 1 Introduction ‣ From Lookups to Lessons: Turning Retrieved Knowledge into Parametric Memory")a).
A memory that reproduces the retriever well can therefore still change
the combined prediction in unhelpful ways. For example, it can override
a correct base answer.

We introduce ResMem, which trains the memory through the base prediction
it will later modify
(Figure [1](#S1.F1 "Figure 1 ‣ 1 Introduction ‣ From Lookups to Lessons: Turning Retrieved Knowledge into Parametric Memory")b).
The frozen base model serves as its own teacher by reading the query
together with retrieved evidence, while the student sees only the query.
The memory adds a logit residual to the student’s logits, and the
distillation and next-token losses are computed on this sum. Because the
loss is computed on the base prediction plus the residual, positions
where the base already matches the training target give little gradient.
The memory thus learns a correction to the base, not a second copy of
the retriever. This builds on context distillation and retrieval-free
dialogue distillation ([Snell et al., 2022](#bib.bib36); [Zhu et al.,
2024](#bib.bib55)). Inference then needs only the frozen base and the
trained memory, with a coefficient $`\gamma`$ setting how strongly the
residual adjusts the base
(Eq. [3](#S3.E3 "In 3.3 Inference and matched control ‣ 3 Methodology ‣ From Lookups to Lessons: Turning Retrieved Knowledge into Parametric Memory")).

Because retriever-pretrained memories draw their supervision from a kNN
datastore of corpus representations, they also pay a construction cost.
Memory Decoder names the neighbor search over this datastore as a
training bottleneck ([Cao et al., 2025](#bib.bib5), Sec. 9), and later
work scales the search with compression and sharding ([Wei et al.,
2026](#bib.bib45)). An evidence-reading teacher needs no such datastore.
ResMem retrieves passages with BM25 and caches only the teacher’s top-64
targets, which cuts retained construction storage from 602.0 to 32.0 GiB
on a subset of English Wikipedia, a 94.7% ($`18.8\times`$) reduction
(Section [5.2](#S5.SS2 "5.2 Construction storage ‣ 5 Results ‣ From Lookups to Lessons: Turning Retrieved Knowledge into Parametric Memory")).

On five knowledge-QA datasets, ResMem improves exact match (EM) and
token F1 over the base model on every dataset and raises mean F1 from
32.83 to 34.48. Compared with MLP Memory, it corrects 11% more base
errors and breaks 21% fewer correct base answers, so most of its
advantage comes from avoided harms. Under a shared teacher, the residual
objective mainly preserves correct answers, and its extra repairs come
with the evidence-reading teacher. Memory Decoder falls below both
memories under the same teacher.

Our main contributions are: (i) We introduce residual self-distillation,
which trains an additive logit residual through the joint
base-plus-memory prediction and keeps it at inference. (ii) We replace
the kNN datastore with text retrieval and an evidence-reading teacher.
This cuts retained construction storage by 94.7% ($`18.8\times`$). The
teacher’s targets also keep the shape of the base prediction. The kNN
targets are much sharper. (iii) We evaluate the recipe and its parts on
knowledge QA, answer-level corrections and harms, and shared-teacher
ablations.

## 2 Related Work

Retrieval and parametric memory. Retrieval keeps information outside
model parameters. RAG, RETRO, and Atlas condition generation on
retrieved text ([Lewis et al., 2020](#bib.bib23); [Borgeaud et al.,
2022](#bib.bib4); [Izacard et al., 2023](#bib.bib13)), and xRAG
compresses each retrieved document into a one-token representation
([Cheng et al., 2024](#bib.bib6)). kNN-LM instead forms a next-token
distribution from neighboring contexts ([Khandelwal et al.,
2020](#bib.bib18)). Memorizing Transformers and LongMem attend to stored
representations of earlier tokens ([Wu et al., 2022](#bib.bib46); [Wang
et al., 2023](#bib.bib42)). Product quantization, GPU similarity search,
and efficient kNN-LMs reduce the cost of such stores ([Jégou et al.,
2011](#bib.bib14); [Johnson et al., 2021](#bib.bib16); [He et al.,
2021](#bib.bib10)). All of these methods query a store during inference.
Parametric memories instead learn to reproduce a store, building on the
view of feed-forward layers as key–value memories ([Geva et al.,
2021](#bib.bib9)). kNN knowledge distillation moves retrieval into
preprocessing for translation ([Yang et al., 2022](#bib.bib49)). MLP
Memory and Memory Decoder train separate parametric memories to imitate
retriever distributions ([Wei et al., 2025](#bib.bib44); [Cao et al.,
2025](#bib.bib5)). Memory Decoder at Scale extends this route to larger
memories and corpora with compressed, sharded search ([Wei et al.,
2026](#bib.bib45)). MemSFT adds learned token-level routing between a
retrieval-supervised memory and the frozen backbone ([Wang et al.,
2026a](#bib.bib41)). We instead train the memory’s contribution through
the joint prediction. Parametric RAG still retrieves documents, each
encoded as LoRA parameters ([Su et al., 2025](#bib.bib38)). Test-time
training layers, Titans, and $`\delta`$-mem update memory states online
while processing a stream ([Sun et al., 2025](#bib.bib39); [Behrouz
et al., 2025](#bib.bib2); [Lei et al., 2026b](#bib.bib22)). ResMem
instead trains its memory offline.

Distillation and output composition. Knowledge distillation transfers a
teacher’s predictions to a student ([Hinton et al., 2015](#bib.bib11)),
and the teacher may use privileged information that is absent at
deployment ([Lopez-Paz et al., 2016](#bib.bib29)). Context distillation
internalizes the benefit of extra instructions, examples, or reasoning
in language models ([Snell et al., 2022](#bib.bib36)). Cartridges uses
it to learn compact KV caches offline ([Eyuboglu et al.,
2025](#bib.bib7)). TTCD updates a short-context student’s fast weights
online from long-context supervision ([Wang et al., 2026b](#bib.bib43)).
Born-Again Networks show that the teacher need not be larger than the
student ([Furlanello et al., 2018](#bib.bib8)). In ResMem, teacher and
student share the frozen backbone, and only the parametric memory is
trained. Retrieval-conditioned distillation carries the benefits of
retrieval into retrieval-free students, as in QUILL, RA2FD, and
InstructRetro ([Srinivasan et al., 2022](#bib.bib37); [Zhu et al.,
2024](#bib.bib55); [Wang et al., 2024](#bib.bib40)). TS-Memory distills
kNN-induced corrections into a time-series adapter ([Lyu et al.,
2026](#bib.bib30)). TransMem is the closest work. It also trains a
memory by evidence-conditioned self-distillation with a shared frozen
backbone ([Lei et al., 2026a](#bib.bib21)). However, its student reads
the full long context and outputs gated hidden-state shifts. Our student
lacks the evidence and outputs a logit residual. DExperts, contrastive
decoding, proxy-tuning, and context-aware decoding combine or contrast
model predictions at decoding time ([Liu et al., 2021](#bib.bib26); [Li
et al., 2023b](#bib.bib25); [Liu et al., 2024a](#bib.bib27); [Shi
et al., 2024](#bib.bib35)). ResMem instead learns its residual through a
loss on the combined prediction and needs evidence only offline. ResMem
also trains on fixed teacher-forced continuations. On-policy
distillation, OPSD, and OPSDL use student-generated trajectories instead
([Agarwal et al., 2024](#bib.bib1); [Zhao et al., 2026](#bib.bib53);
[Zhang et al., 2026](#bib.bib51)).

## 3 Methodology

ResMem writes external knowledge into a parametric memory while keeping
the language model frozen. The memory architecture follows MLP Memory.
ResMem changes the teacher and the objective
(Section [3.2](#S3.SS2 "3.2 Residual self-distillation ‣ 3 Methodology ‣ From Lookups to Lessons: Turning Retrieved Knowledge into Parametric Memory")),
and the teacher’s cached targets replace the kNN datastore
(Section [3.4](#S3.SS4 "3.4 Construction storage ‣ 3 Methodology ‣ From Lookups to Lessons: Turning Retrieved Knowledge into Parametric Memory")).

### 3.1 Memory input and architecture

For a token sequence $`x`$, causal position $`t`$ predicts the next
token $`y_{t}=x_{t+1}`$. The frozen base produces logits
$`z_{B,t}\in\mathbb{R}^{|V|}`$ over vocabulary $`V`$. At the same
position, we extract $`h_{t}\in\mathbb{R}^{d}`$ at the input to the
final Transformer block’s feed-forward sublayer
(Appendix [A](#A1 "Appendix A Implementation details ‣ From Lookups to Lessons: Turning Retrieved Knowledge into Parametric Memory")).

The memory maps this contextual vector to vocabulary logits,
$`s_{\theta,t}=m_{\theta}(h_{t})\in\mathbb{R}^{|V|}`$. Following MLP
Memory ([Wei et al., 2025](#bib.bib44)), it consists of a stack of
feed-forward blocks with RMS normalization and residual connections,
followed by a final normalization and its own trainable vocabulary
projection. Each gated block acts on one position; the base
representation already carries the preceding context, so the memory
needs no attention over tokens. Only memory parameters, including its
output projection, are trained.

### 3.2 Residual self-distillation

Distilling the privileged gain into memory. On-policy self-distillation
(OPSD) ([Zhao et al., 2026](#bib.bib53)) turns privileged input into
supervision: the same model, given information the student lacks,
produces a dense token-level output distribution. Teacher and student
share one backbone, so this distribution lives in the base model’s own
output space. It differs from the base prediction only through what the
privileged input adds. A residual on the base must learn exactly this
part
(Eq. [2](#S3.E2 "In 3.2 Residual self-distillation ‣ 3 Methodology ‣ From Lookups to Lessons: Turning Retrieved Knowledge into Parametric Memory")).
ResMem uses retrieved evidence as the privileged input, as in context
distillation ([Lopez-Paz et al., 2016](#bib.bib29); [Snell et al.,
2022](#bib.bib36)), and distills this gain into the parametric memory.
The teacher $`\pi_{T}(\cdot\mid c,x_{\leq t})`$ is the frozen model
reading passages $`c`$ retrieved by BM25 ([Robertson & Zaragoza,
2009](#bib.bib34)) before the span $`x`$. The student
$`\pi_{S}(\cdot\mid x_{\leq t})=\mathrm{softmax}(z_{B,t}+s_{\theta,t})`$
is the same model reading only $`x`$, plus the memory’s residual.
Training minimizes the per-token divergence between the two roles over
corpus prefixes,

|     |     |     |     |
| --- | --- | --- | --- |
|     |

````math
\min_{\theta}\;\mathbb{E}_{x}\sum_{t}D_{\mathrm{KL}}\bigl(\pi_{T}(\cdot\mid c,x_{\leq t})\,\big\|\,\pi_{S}(\cdot\mid x_{\leq t})\bigr).
``` |  | (1) |

Only the memory is updated. The gain that the evidence gives the teacher
is written into $`\theta`$, and the backbone stays fixed.

Teacher targets. Teacher and student follow the same continuation under
teacher forcing. After the evidence prefix, teacher outputs are aligned
to the student’s next-token targets. The evidence changes the
supervision, while the memory input remains $`h_{t}`$ from the student
base. Retrieval and teacher forwarding run once, offline. At each
supervised position, we cache the teacher’s top-$`K`$ token
probabilities with $`K=64`$. We renormalize them and put zero mass
elsewhere, which gives $`p_{T,t}^{(K)}`$. This target is zero outside
$`K`$ tokens, while $`\pi_{S}`$ has full support.
Eq. [1](#S3.E1 "In 3.2 Residual self-distillation ‣ 3 Methodology ‣ From Lookups to Lessons: Turning Retrieved Knowledge into Parametric Memory")
uses the forward KL, because the reverse direction would be infinite.
Algorithm [1](#alg1 "Algorithm 1 ‣ 3.2 Residual self-distillation ‣ 3 Methodology ‣ From Lookups to Lessons: Turning Retrieved Knowledge into Parametric Memory")
summarizes the procedure, and the paragraphs below specify the student
and the loss.

1: frozen language model $`f`$, corpus spans $`\mathcal{X}`$, retriever
$`R`$, cache size $`K`$, loss weight $`\alpha`$

2: for all $`x\in\mathcal{X}`$ do

3:   $`c\leftarrow R(x)`$; $`p_{T}^{(K)}\leftarrow`$ renormalized
top-$`K`$ of $`f(\cdot\mid[c;x])`$ at every position

4: end for

5: repeat

6:   sample spans $`x\sim\mathcal{X}`$;
$`(h_{t},z_{B,t})\leftarrow f(x)`$

7:
  $`q_{R,t}\leftarrow\mathrm{softmax}\bigl(z_{B,t}+m_{\theta}(h_{t})\bigr)`$

8:
  $`\mathcal{L}\leftarrow\alpha\,\mathcal{L}_{\mathrm{KL}}+(1-\alpha)\,\mathcal{L}_{\mathrm{CE}}`$

9:   $`\theta\leftarrow\theta-\eta\nabla_{\theta}\mathcal{L}`$

10: until the token budget is spent

11: return $`m_{\theta}`$; inference uses
$`\mathrm{softmax}\bigl(z_{B,t}+\gamma\,m_{\theta}(h_{t})\bigr)`$

Algorithm 1 Residual self-distillation

Joint prediction. We train the memory through its joint prediction with
the base ($`\oplus`$ in
Figure [1](#S1.F1 "Figure 1 ‣ 1 Introduction ‣ From Lookups to Lessons: Turning Retrieved Knowledge into Parametric Memory")b),
$`z_{R,t}=z_{B,t}+s_{\theta,t}`$ and
$`q_{R,t}=\mathrm{softmax}(z_{R,t})`$. During training the residual
enters at unit scale, which corresponds to $`\gamma=1`$ in the inference
rule of
Section [3.3](#S3.SS3 "3.3 Inference and matched control ‣ 3 Methodology ‣ From Lookups to Lessons: Turning Retrieved Knowledge into Parametric Memory").
Because the loss evaluates $`q_{R,t}`$ with $`z_{B,t}`$ fixed, the
memory learns the change needed by the combined prediction.

Loss components. Let $`\mathcal{C}`$ contain all valid causal prediction
positions in a training batch and $`\mathcal{A}\subseteq\mathcal{C}`$
the positions selected for label supervision. As in knowledge
distillation with soft targets and labels ([Hinton et al.,
2015](#bib.bib11)), we combine teacher-to-student KL,
$`\mathcal{L}_{\mathrm{KL}}=|\mathcal{C}|^{-1}\sum_{t\in\mathcal{C}}D_{\mathrm{KL}}(p_{T,t}^{(K)}\,\|\,q_{R,t})`$,
with next-token cross-entropy,
$`\mathcal{L}_{\mathrm{CE}}=-|\mathcal{A}|^{-1}\sum_{t\in\mathcal{A}}\log q_{R,t}(y_{t})`$.
KL transfers the teacher’s distribution over possible continuations; CE
supervises the observed target token. A hyperparameter
$`\alpha\in[0,1]`$ weighs the two,
$`\mathcal{L}=\alpha\,\mathcal{L}_{\mathrm{KL}}+(1-\alpha)\,\mathcal{L}_{\mathrm{CE}}`$.
Each term is averaged over its own selected positions, excluding
padding. In corpus-continuation training, both terms cover the complete
valid span, so $`\mathcal{A}=\mathcal{C}`$.

What the residual learns. With $`\mathcal{A}=\mathcal{C}`$, each
position contributes
$`\ell_{t}=-\sum_{v\in V}\tilde{p}_{t}(v)\log q_{R,t}(v)`$ up to a
constant, where the training target
$`\tilde{p}_{t}=\alpha\,p_{T,t}^{(K)}+(1-\alpha)\,e_{y_{t}}`$ mixes the
teacher with the one-hot label $`e_{y_{t}}`$. The gradient of
$`\ell_{t}`$ with respect to the residual logits is
$`\partial\ell_{t}/\partial s_{\theta,t}=\mathrm{softmax}(z_{B,t}+s_{\theta,t})-\tilde{p}_{t}`$.
A position whose joint prediction already matches the target therefore
produces no update. While the residual is small, these are the positions
where the base already agrees with the target. Let $`\mathcal{S}_{t}`$
be the support of $`\tilde{p}_{t}`$, the $`K`$ cached tokens and
$`y_{t}`$. If the memory could fit every position exactly, the loss
would approach its infimum with $`s_{\theta,t}\to-\infty`$ outside
$`\mathcal{S}_{t}`$ and, on $`\mathcal{S}_{t}`$,

|     |                                                       |     |     |
|-----|-------------------------------------------------------|-----|-----|
|     |
       ``` math
       s_{\theta,t}^{\star}=\log\tilde{p}_{t}-z_{B,t}+c_{t},
       ```                                                    |     | (2) |

with a free per-position constant $`c_{t}`$. The residual thus learns
the log-ratio between the target and the base prediction. The standalone
objective of
Section [3.3](#S3.SS3 "3.3 Inference and matched control ‣ 3 Methodology ‣ From Lookups to Lessons: Turning Retrieved Knowledge into Parametric Memory")
instead drives the memory’s own distribution toward $`\tilde{p}_{t}`$,
regardless of the base.

### 3.3 Inference and matched control

At each decoding step, the base supplies $`h_{t}`$ and $`z_{B,t}`$, and
the memory produces $`s_{\theta,t}`$. A residual scale $`\gamma\geq 0`$
multiplies the memory logits before the final softmax:

|  |  |  |  |
|----|----|----|----|
|  |
``` math
z_{\mathrm{final},t}=z_{B,t}+\gamma s_{\theta,t},\qquad p_{\mathrm{final},t}=\mathrm{softmax}(z_{\mathrm{final},t}).
``` |  | (3) |

This retains the additive structure used in training; $`\gamma=0`$
recovers the base prediction. Evidence retrieval and teacher forwarding
are offline; inference uses only the base and learned memory (cost in
Appendix [D](#A4 "Appendix D Precision and deployment cost ‣ From Lookups to Lessons: Turning Retrieved Knowledge into Parametric Memory")).
At the optimum of
Eq. [2](#S3.E2 "In 3.2 Residual self-distillation ‣ 3 Methodology ‣ From Lookups to Lessons: Turning Retrieved Knowledge into Parametric Memory"),
the scaled logits on $`\mathcal{S}_{t}`$ become
$`(1-\gamma)\,z_{B,t}+\gamma\,(\log\tilde{p}_{t}+c_{t})`$, and $`c_{t}`$
cancels in the softmax. In this limit, tokens outside
$`\mathcal{S}_{t}`$ receive zero probability for $`\gamma>0`$, and on
$`\mathcal{S}_{t}`$ the scaled readout is a geometric interpolation
between the base distribution $`p_{B,t}=\mathrm{softmax}(z_{B,t})`$ and
the training target:

|  |  |  |  |
|----|----|----|----|
|  |
``` math
p_{\mathrm{final},t}\propto p_{B,t}^{\,1-\gamma}\,\tilde{p}_{t}^{\,\gamma},
``` |  | (4) |

so $`\gamma`$ moves the prediction along a log-linear path from Base at
$`\gamma=0`$ to the fitted target at $`\gamma=1`$.

The residual can still suppress a base answer, as the condition below
shows.

For the shared-teacher standalone control, we reuse the architecture,
targets, examples, position masks, loss weights, and optimizer. Its loss
replaces $`q_{R,t}`$ with the memory-only distribution
$`q_{M,t}=\mathrm{softmax}(s_{\phi,t})`$, where $`s_{\phi,t}`$ are the
logits of a separately trained memory with parameters $`\phi`$.
Inference follows the MLP Memory probability mixture, with interpolation
weight $`\lambda\in[0,1]`$:

|  |  |  |  |
|----|----|----|----|
|  |
``` math
p_{\mathrm{final},t}=(1-\lambda)\,\mathrm{softmax}(z_{B,t})+\lambda\,q_{M,t}.
``` |  | (5) |

Both readouts recover Base at zero. The mixture interpolates linearly
between Base and the memory, and the additive readout interpolates
geometrically
(Eq. [4](#S3.E4 "In 3.3 Inference and matched control ‣ 3 Methodology ‣ From Lookups to Lessons: Turning Retrieved Knowledge into Parametric Memory")).
We therefore select $`\lambda`$ and $`\gamma`$ separately for each
readout
(Section [5.4](#S5.SS4 "5.4 Ablations ‣ 5 Results ‣ From Lookups to Lessons: Turning Retrieved Knowledge into Parametric Memory")).

When a readout overrides the base. Consider a position where the base
prefers token $`y`$ to $`v`$, both in $`\mathcal{S}_{t}`$, with log-odds
margin $`m_{B}=\log p_{B,t}(y)-\log p_{B,t}(v)>0`$, while the fitted
target prefers $`v`$ with margin
$`m_{T}=\log\tilde{p}_{t}(v)-\log\tilde{p}_{t}(y)>0`$. By
Eq. [4](#S3.E4 "In 3.3 Inference and matched control ‣ 3 Methodology ‣ From Lookups to Lessons: Turning Retrieved Knowledge into Parametric Memory"),
the readout’s log-odds of $`v`$ over $`y`$ are

|  |  |  |
|----|----|----|
|  |
``` math
\log\frac{p_{\mathrm{final},t}(v)}{p_{\mathrm{final},t}(y)}=\gamma\,m_{T}-(1-\gamma)\,m_{B},
``` |  |

so the additive readout switches to $`v`$ if and only if

|     |                                  |     |     |
|-----|----------------------------------|-----|-----|
|     |
       ``` math
       \gamma\,m_{T}>(1-\gamma)\,m_{B},
       ```                               |     | (6) |

whereas the mixture of
Eq. [5](#S3.E5 "In 3.3 Inference and matched control ‣ 3 Methodology ‣ From Lookups to Lessons: Turning Retrieved Knowledge into Parametric Memory"),
with the memory at its standalone optimum $`q_{M,t}=\tilde{p}_{t}`$,
switches if and only if
$`\lambda\,[\tilde{p}_{t}(v)-\tilde{p}_{t}(y)]>(1-\lambda)\,[p_{B,t}(y)-p_{B,t}(v)]`$.
The additive rule compares log-odds, so overriding a confident base
token requires a correspondingly confident target. The mixture compares
probability gaps, and these never exceed one. A memory that puts all its
mass on $`v`$ therefore overrides any base margin once $`\lambda>1/2`$.
Preserving confident base answers then forces a small $`\lambda`$. Under
greedy decoding, this token-level condition is how a memory breaks a
correct base answer
(Section [5.3](#S5.SS3 "5.3 Correction and harm analysis ‣ 5 Results ‣ From Lookups to Lessons: Turning Retrieved Knowledge into Parametric Memory")).

### 3.4 Construction storage

The cached targets are all that training needs from the teacher. Both
routes cache them. The kNN route also retains a datastore and a FAISS
IVF-PQ index. The RAG route retains the retrieved text and a BM25 index
instead. Per valid position, a datastore entry holds a $`d`$-dimensional
FP16 key and an INT32 token ID. An index entry holds a $`P`$-byte PQ
code and an 8-byte ID. A cached target holds $`K`$ INT32 token IDs and
$`K`$ FP16 probabilities. Over $`n`$ positions, the two routes retain

|  |  |  |  |  |
|----|----|----|----|----|
|  | $`\displaystyle S_{\mathrm{kNN}}(n)`$ | $`\displaystyle=(2d+4)n+(P+8)n+6Kn,`$ |  | (7) |
|  | $`\displaystyle S_{\mathrm{RAG}}(n)`$ | $`\displaystyle=6Kn+bn,`$ |  |  |

where $`b`$ is the text and BM25 index per position. With $`d=4096`$,
$`P=64`$, and $`K=64`$, the kNN route needs $`8196+72+384=8652`$ bytes
per position. The ratio
$`S_{\mathrm{kNN}}/S_{\mathrm{RAG}}=8652/(384+b)`$ does not depend on
$`n`$, so the saving holds at every corpus size. It approaches 22.5 as
$`b`$ goes to zero, since the datastore alone takes
$`(2d+4)/6K\approx 21.3`$ times the bytes of the targets.
Section [5.2](#S5.SS2 "5.2 Construction storage ‣ 5 Results ‣ From Lookups to Lessons: Turning Retrieved Knowledge into Parametric Memory")
measures $`b`$ and both routes.

## 4 Experimental Setup

Models. We use Mistral-7B-v0.3 ([Jiang et al., 2023](#bib.bib15)) as the
base model. ResMem and MLP Memory each attach an eight-layer memory with
hidden size 4096, intermediate size 14336, and approximately 1.54B
parameters. Additional baselines are BM25-RAG ([Robertson & Zaragoza,
2009](#bib.bib34); [Lewis et al., 2020](#bib.bib23)), LoRA ([Hu et al.,
2022](#bib.bib12)), and Memory Decoder ([Cao et al., 2025](#bib.bib5)).
On the Wikipedia subset, we train two memories with this architecture on
a kNN teacher built from the subset. Both start from the same
initialization, follow the same example order, and train for three
epochs (220.8M tokens). One uses the standalone objective, and the other
uses the residual objective
(Section [5.3](#S5.SS3 "5.3 Correction and harm analysis ‣ 5 Results ‣ From Lookups to Lessons: Turning Retrieved Knowledge into Parametric Memory");
Appendix [A](#A1 "Appendix A Implementation details ‣ From Lookups to Lessons: Turning Retrieved Knowledge into Parametric Memory")).
For knowledge QA, the correction analysis, HaluEval, and the precision
study, ResMem, MLP Memory, and Memory Decoder are each trained for one
epoch on full English Wikipedia. MLP Memory and Memory Decoder follow
their official pipelines, including the kNN teacher. The shared-teacher
ablation trains eight new paired seeds for each objective and for Memory
Decoder, all with equal exposure
(Section [5.4](#S5.SS4 "5.4 Ablations ‣ 5 Results ‣ From Lookups to Lessons: Turning Retrieved Knowledge into Parametric Memory")).

Datasets. Following MLP Memory, we use the December 2021 English
Wikipedia dump as the corpus for memory training. The Wikipedia subset,
used for the storage comparison and these two memories, contains 74 of
its 4,716 source shards, about 1/64 of the corpus. Knowledge QA contains
38,627 questions from Natural Questions (NQ) ([Kwiatkowski et al.,
2019](#bib.bib20)), WebQuestions ([Berant et al., 2013](#bib.bib3)),
TriviaQA ([Joshi et al., 2017](#bib.bib17)), PopQA ([Mallen et al.,
2023](#bib.bib31)), and HotpotQA ([Yang et al., 2018](#bib.bib48)). We
also use HaluEval’s Dialogue, QA, and Summarization splits ([Li et al.,
2023a](#bib.bib24)). Hardware, training schedules, and evaluation
configurations are given in
Appendix [A](#A1 "Appendix A Implementation details ‣ From Lookups to Lessons: Turning Retrieved Knowledge into Parametric Memory").

### 5.1 Knowledge QA Task Performance

The QA checkpoints are each trained for one epoch on full Wikipedia
(Section [4](#S4 "4 Experimental Setup ‣ From Lookups to Lessons: Turning Retrieved Knowledge into Parametric Memory")).
We report EM, token F1, and reference-answer PPL on 38,627 questions,
averaging the five datasets equally. For each memory and dataset, we
select $`\lambda`$ or $`\gamma`$ to maximize EM on the validation set.
We then use that coefficient to compute EM, F1, and PPL on the
evaluation set
(Appendix [A](#A1 "Appendix A Implementation details ‣ From Lookups to Lessons: Turning Retrieved Knowledge into Parametric Memory")).
A QA-supervised tokenwise gate changes mean EM by only $`+0.07`$ points
and mean F1 by $`-0.02`$ points, so ResMem is reported without it
(Table [6](#A5.T6 "Table 6 ‣ Appendix E Tokenwise gate ablation ‣ From Lookups to Lessons: Turning Retrieved Knowledge into Parametric Memory")
in
Appendix [E](#A5 "Appendix E Tokenwise gate ablation ‣ From Lookups to Lessons: Turning Retrieved Knowledge into Parametric Memory")).

ResMem has the highest EM and F1 and the lowest PPL in all three task
families
(Table [1](#S5.T1 "Table 1 ‣ 5 Results ‣ From Lookups to Lessons: Turning Retrieved Knowledge into Parametric Memory")).
Over Base, it raises mean EM from 25.91 to 26.74 and mean F1 from 32.83
to 34.48. Both metrics improve on every dataset
(Appendix [B](#A2 "Appendix B Per-dataset knowledge-QA results ‣ From Lookups to Lessons: Turning Retrieved Knowledge into Parametric Memory")).
Its F1 margin over MLP Memory grows from 0.32 points on open-domain QA
to 1.08 on long-tail and 1.77 on multi-hop QA. On HaluEval hallucination
detection, the same checkpoints raise mean accuracy from 54.83 to 63.09,
against 60.34 for MLP Memory
(Appendix [C](#A3 "Appendix C Hallucination detection ‣ From Lookups to Lessons: Turning Retrieved Knowledge into Parametric Memory")).
Answer likelihood alone does not explain these results. BM25-RAG lowers
open-domain answer PPL below Base (10.02 versus 11.11), yet it loses
5.42 EM points. Generation must choose its own words and decide when to
stop.

### 5.2 Construction storage

We measure both routes of
Eq. [7](#S3.E7 "In 3.4 Construction storage ‣ 3 Methodology ‣ From Lookups to Lessons: Turning Retrieved Knowledge into Parametric Memory")
on nested shard sets of the corpus, from the Wikipedia subset to 652M
positions
(Figure [2](#S5.F2 "Figure 2 ‣ 5.2 Construction storage ‣ 5 Results ‣ From Lookups to Lessons: Turning Retrieved Knowledge into Parametric Memory")).
At every set, the kNN datastore files match $`(2d+4)n`$ bytes. A BM25
index and its passages, built on the same shards, grow linearly at 3.5
to 3.7 bytes per position.

Figure 2: Retained storage of the kNN and RAG routes, measured on nested

The index over all of English Wikipedia takes 16.7 GB. On the subset,
$`b`$ is 72.9 bytes. The stored files add small overheads, such as span
token IDs. They take 8665 and 461 bytes per position, a ratio of 18.8.
The kNN route retains a 570.011 GiB datastore and a 5.069 GiB FAISS
index. The RAG route retains 5.067 GiB of retrieved text and BM25 index.
Both cache 26.967 GiB of targets. The totals are 602.047 versus
32.033 GiB, a 94.7% ($`18.8\times`$) reduction in retained assets.

### 5.3 Correction and harm analysis

A change in mean EM is the net of two opposing effects: the memory fixes
some questions the base model answers wrongly and breaks some it answers
correctly. We pair the answers to all 38,627 questions with the frozen
Base answers and count corrections $`C`$ (Base wrong, memory right) and
harms $`H`$ (Base right, memory wrong) under normalized EM. The net EM
gain is $`(C-H)/Q`$ over the $`Q`$ questions. Each method uses one
global coefficient chosen on 4,091 NQ/TriviaQA development questions
disjoint from the test sets: $`\lambda^{*}=0.3`$ for MLP Memory,
$`\gamma^{*}=0.3`$ for ResMem, and $`\lambda^{*}=0.2`$ for Memory
Decoder.
Figure [3](#S5.F3 "Figure 3 ‣ 5.3 Correction and harm analysis ‣ 5 Results ‣ From Lookups to Lessons: Turning Retrieved Knowledge into Parametric Memory")a
traces correction against harm rate as the coefficient varies. Net EM
rises while a curve is steeper than the $`\Delta\mathrm{EM}=0`$ line.
Figure [3](#S5.F3 "Figure 3 ‣ 5.3 Correction and harm analysis ‣ 5 Results ‣ From Lookups to Lessons: Turning Retrieved Knowledge into Parametric Memory")b
splits the net gain into corrections and harms at the selected
coefficients.

Figure 3: Correction–harm trade-off on 38,627 QA questions. (a)
Correction versus harm rates across coefficients; stars (^(∗)) mark
coefficients selected on development data, and the dotted line marks
zero net gain. (b) Correction and harm contributions at the selected
coefficients.

ResMem corrects 704 answers and harms 381, against 633 and 482 for MLP
Memory. Its net EM gain is 0.84 points, against 0.39 (paired difference
0.45, 95% interval \[0.25, 0.64\]). Most of this difference comes from
the 101 avoided harms. Memory Decoder nets $`-0.04`$ points, with 124
corrections and 138 harms.

Figure 4: Distribution concentration. (a) Percentage of positions whose
most likely token has probability at least 95%; the base prediction is
truncated to its top 64. (b) Tokens covering 95% of the memory’s own
softmax, averaged over positions, for memories trained on the kNN
teacher from a shared initialization, either alone (as in MLP Memory) or
through base plus memory (as in ResMem). The standalone memory’s softmax
is its mixture component. The residual’s softmax is not used at
inference and is shown for reference.

One source of the harm gap is the shape of the kNN target
(Figure [4](#S5.F4 "Figure 4 ‣ 5.3 Correction and harm analysis ‣ 5 Results ‣ From Lookups to Lessons: Turning Retrieved Knowledge into Parametric Memory")a).
Over all 74.6M cached positions, a single token carries at least 95% of
its mass at 87% of positions. Its median entropy is 0, and its mean
top-1 probability is 0.95. The evidence-reading teacher is shaped like
the base instead. It does so at 24% of 1.05M positions, and the base at
22%. Their mean top-1 probabilities are 0.60 and 0.59. This sharpness is
a known property of kNN-LM. The kNN distribution comes from $`k\ll|V|`$
neighbors through a softmax over negative distances, so it is sharper
than a model’s output ([Xu et al., 2023](#bib.bib47)). A higher
temperature spreads the mass ([Khandelwal et al., 2021](#bib.bib19)).
However, it also gives distant, noisier neighbors almost the same weight
as the nearest one ([Zheng et al., 2021](#bib.bib54)). The original
kNN-LM therefore mixes this distribution at a small weight,
$`\lambda=0.25`$ on WikiText-103 ([Khandelwal et al.,
2020](#bib.bib18)). Our kNN teacher follows the MLP Memory pipeline at
$`T=16`$. This is flatter than the original $`T=1`$, so the choice
favors the baselines. Even so, the target stays sharp.

A teacher shaped like the base suits a residual. The residual learns the
log-ratio between the target and the base
(Eq. [2](#S3.E2 "In 3.2 Residual self-distillation ‣ 3 Methodology ‣ From Lookups to Lessons: Turning Retrieved Knowledge into Parametric Memory")).
Our teacher is the base itself, reading retrieved evidence. The two
share an output space and a similar shape. The residual therefore mainly
encodes what the evidence changes. The teacher also keeps the base’s
uncertainty. When several continuations are plausible, it does not force
one of them. The kNN target commits to one token at most positions. A
memory that fits it learns to commit as well.

MLP Memory shows this effect. On the same kNN teacher, initialization,
and example order, a memory trained alone narrows from 21,051 tokens
covering 95% of its mass to 310
(Figure [4](#S5.F4 "Figure 4 ‣ 5.3 Correction and harm analysis ‣ 5 Results ‣ From Lookups to Lessons: Turning Retrieved Knowledge into Parametric Memory")b).
In MLP Memory, this distribution is the component that the mixture adds
to the base
(Eq. [5](#S3.E5 "In 3.3 Inference and matched control ‣ 3 Methodology ‣ From Lookups to Lessons: Turning Retrieved Knowledge into Parametric Memory")).
A sharp component can override a confident base answer once $`\lambda`$
grows
(Section [3.3](#S3.SS3 "3.3 Inference and matched control ‣ 3 Methodology ‣ From Lookups to Lessons: Turning Retrieved Knowledge into Parametric Memory")).
The additive readout only shifts base log-odds
(Eq. [6](#S3.E6 "In 3.3 Inference and matched control ‣ 3 Methodology ‣ From Lookups to Lessons: Turning Retrieved Knowledge into Parametric Memory")).
The residual’s own softmax is not used at inference, so we judge it by
the combined predictions.
Figure [3](#S5.F3 "Figure 3 ‣ 5.3 Correction and harm analysis ‣ 5 Results ‣ From Lookups to Lessons: Turning Retrieved Knowledge into Parametric Memory")
shows the expected pattern. MLP Memory breaks 482 correct answers, and
ResMem breaks 381. The MLP Memory curve flattens earlier.
Section [5.4](#S5.SS4 "5.4 Ablations ‣ 5 Results ‣ From Lookups to Lessons: Turning Retrieved Knowledge into Parametric Memory")
holds the teacher fixed to test the objective and readout alone.

The comparisons above differ in teacher, objective and readout, and
memory architecture at once. Holding the teacher fixed, we first vary
the objective and readout, and then the architecture.

Objective and readout. Both memories use the same BM25-RAG teacher,
cached inputs, eight-layer architecture, paired initialization, and
example order. Eight paired seeds each receive 8,388,608
supervised-position exposures over eight epochs. Each configuration
selects one coefficient on 1,024 development questions disjoint from the
test sets. Pairing the seeds lets each comparison share its
initialization and data order.

We call the standalone objective with mixture readout and the residual
objective with additive readout the native configurations. Both improve
mean F1 over Base
(Table [2](#S5.T2 "Table 2 ‣ 5.4 Ablations ‣ 5 Results ‣ From Lookups to Lessons: Turning Retrieved Knowledge into Parametric Memory")).
The residual configuration leads by 0.117 points, with a 95%
question-cluster bootstrap interval of $`[-0.020,0.258]`$, or
$`[-0.180,0.477]`$ when seeds are also resampled.

In the four-cell diagnostic on 4,096 shared questions, both crossed
configurations select coefficient zero and recover Base. Residual scores
read as a standalone distribution yield an F1 of 0.06, so they are
useful only when added to the base logits. Pooled over the eight runs at
native operating points, the residual configuration preserves 96.11% of
Base-correct answers, against 94.05%. It repairs 1.51% of Base errors,
against 2.25% (point estimates). With the teacher fixed, it thus trades
some repair for preservation.

Architecture. Memory Decoder replaces the hidden-state memory with a
separate 0.47B-parameter decoder that reads the token sequence
(Appendix [A](#A1 "Appendix A Implementation details ‣ From Lookups to Lessons: Turning Retrieved Knowledge into Parametric Memory")).
With the same supervision, exposure, and optimizer schedule and a
mixture readout, it reaches F1 32.87. This is 0.26 and 0.37 points below
the standalone and residual configurations ($`[-0.42,-0.09]`$ and
$`[-0.49,-0.25]`$). Development selection sets its coefficient to zero
for six of the eight seeds
(Table [2](#S5.T2 "Table 2 ‣ 5.4 Ablations ‣ 5 Results ‣ From Lookups to Lessons: Turning Retrieved Knowledge into Parametric Memory")).
Under this training budget and at these sizes, the hidden-state memory
is the stronger design.

Unlike the shared-teacher runs, full-recipe ResMem both corrects more
and harms less than MLP Memory
(Section [5.3](#S5.SS3 "5.3 Correction and harm analysis ‣ 5 Results ‣ From Lookups to Lessons: Turning Retrieved Knowledge into Parametric Memory")).
The objective and readout thus contribute to the better preservation.
The extra repairs come with the evidence-reading teacher, in line with
the sharper kNN targets in
Figure [4](#S5.F4 "Figure 4 ‣ 5.3 Correction and harm analysis ‣ 5 Results ‣ From Lookups to Lessons: Turning Retrieved Knowledge into Parametric Memory")a.

## 6 Conclusion

ResMem distills a retrieval-augmented teacher into an additive logit
residual on a frozen base model. On a Wikipedia subset, it cuts retained
construction storage by 94.7% ($`18.8\times`$). On five knowledge-QA
datasets, it raises mean F1 from 32.83 to 34.48. It also corrects more
base errors and harms fewer correct answers than MLP Memory. With a
shared teacher, the residual objective mainly preserves correct answers,
and the extra repairs come with the evidence-reading teacher. The
storage saving and the extra repairs thus share one source, the teacher
that reads retrieved text.

With only the parametric memory trained, the base model stays unchanged.
A limitation of this design is that the memory reads one hidden state
and writes only to the output logits. The teacher’s gain is therefore
not integrated through the base model’s intermediate layers. Memories
that read from and write to several layers are a natural next step.

## Appendix A Implementation details

Memory input. In the Mistral backbone, $`h_{t}`$ is the state after the
attention residual connection and its following RMS normalization
([Zhang & Sennrich, 2019](#bib.bib50)). Base logits are computed
separately through the remaining feed-forward computation, final
normalization, and frozen vocabulary head.

Subset kNN teacher and Memory Decoder. The kNN teacher for the Wikipedia
subset is built with the original teacher’s builder. It reproduces the
original position count and 26.967 GiB target cache. Memory Decoder uses
a Qwen3-0.6B-Base body with the Mistral vocabulary (0.47B parameters).

Knowledge-QA configuration. For each dataset, we select $`\lambda`$ for
MLP Memory and Memory Decoder and $`\gamma`$ for ResMem by the highest
EM on the validation set. Each memory then uses its selected coefficient
for all three metrics on the evaluation set: EM, F1, and PPL, with EM
and F1 computed from the same generated answers. LoRA uses strength
0.25, chosen on development data. BM25-RAG retrieves five Wikipedia
passages with a 4096-token input and up to 64 output tokens; the other
methods use 384 input tokens and at most 12 output tokens. PPL scores
answer tokens and excludes the prompt and EOS. On a separate Wikipedia
sample, with coefficients selected on 128 calibration sequences and
scored on 256 others, the QA checkpoints reach perplexity 7.441 (MLP
Memory), 8.660 (ResMem), and 9.959 (Base). MLP Memory fits held-out text
more closely, yet ResMem answers more questions correctly
(Table [1](#S5.T1 "Table 1 ‣ 5 Results ‣ From Lookups to Lessons: Turning Retrieved Knowledge into Parametric Memory")).
A closer fit to the corpus thus does not by itself give better final
answers.

Hardware. The two memories trained on the subset’s kNN teacher use
A100-SXM4-80GB GPUs. Knowledge-QA memory sweeps use NVIDIA
A100-SXM4-40GB GPUs. QA inference uses BF16 base computation, eager
attention, batch size 16, and greedy decoding. The shared-teacher
ablation and precision measurements use two eight-GPU A100-SXM4-80GB
hosts, with one model worker per GPU. The precision study uses BF16 Base
with FP32 or BF16 memory and SDPA/KV caching. Deployment timing uses one
GPU. Detailed schedules, checkpoint sources, and scoring configurations
are recorded in the repository’s experimental-protocol note.

The gate decides when the memory should act on the base output. The
residual matters only at decoding steps where it changes the base’s top
token. At such a step, it either repairs a base error or overrides a
correct base token. The gate aims to keep the repairs and block the
overrides, using only signals available during decoding.

At step $`t`$, we compute the base logits $`z_{B,t}`$ and the fused
logits $`z_{B,t}+\gamma s_{\theta,t}`$. From both, we form 22 features.
They describe each distribution (entropy, top-token probability, and
top-two margin) and how the two top tokens compare, such as the
residual’s advantage for the fused token. They also cover the step
index, the generated prefix, and whether either top token would end the
answer. A logistic classifier maps the features to a score $`g_{t}`$.
The step uses the fused logits if $`g_{t}\geq 0.5`$ and the base logits
otherwise, so the residual scale is $`\gamma_{t}\in\{0,\gamma\}`$. The
gate uses no labels or future tokens. On the test questions, the fused
top token differs from the base top token at 19,254 of 463,520 decoding
steps (4.2%). The gate accepts 10,614 of these changes and blocks 8,640.
Of the accepted changes, 7,493 occur at the first answer token.

The gate is fitted on 264 NQ/TriviaQA training questions and selected on
a disjoint 4,091-question development split, so it adds QA supervision
beyond memory training. On all 38,627 questions, relative to
fixed-strength ResMem, the gate changes mean EM by $`+0.07`$ points (95%
question-cluster bootstrap interval $`[-0.06,0.19]`$) and mean F1 by
$`-0.02`$ points. It alters 190 answers, 113 for the better and 77 for
the worse, and the interval for every dataset includes zero.
Table [1](#S5.T1 "Table 1 ‣ 5 Results ‣ From Lookups to Lessons: Turning Retrieved Knowledge into Parametric Memory")
therefore reports ResMem without the gate.
````
