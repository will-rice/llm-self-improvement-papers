# EchoKV: Self-Corrective KV Cache Eviction via Iterative Query Feedback

JianKun Zou    Tongtong Yuan Affiliation: Beijing University of
Technology Email: [zoujiankun2006@emails.bjut.edu.cn](mailto:)
Email: [yuantt@bjut.edu.cn](mailto:)

###### Abstract

KV cache eviction is not merely a token-ranking problem: the workspace
retained for generating eviction queries also determines the quality of
those queries. Consequently, an early workspace error can distort later
query observations and reinforce an incorrect final eviction decision,
particularly when evidence is dispersed across a long context. We
present EchoKV, which discovers and addresses this failure mode with
iterative correction. It initializes a feedback-compatible bootstrap
workspace using proposals at future decode positions, then uses early
decode-generated queries to recover the workspace before the remaining
lookahead steps. It uses the same number of workspace forward passes as
LAQ while adding a tensor re-scoring operation for workspace repair. On
LongBench (16 tasks, Mistral-7B-Instruct-v0.2 and Qwen2.5-7B-Instruct),
EchoKV shows notable improvements over LAQ on several tasks requiring
dispersed evidence, including multi-hop cross-document QA and long
single-document comprehension. Across budgets and backbones, EchoKV
selectively improves evidence-intensive tasks while maintaining
comparable performance on the remaining LongBench subsets. These results
identify query–workspace coupling as a practical failure mode of
query-driven KV eviction.

## 1 Introduction

KV cache eviction is not merely a token-ranking problem. In query-driven
eviction, the tokens retained during workspace construction determine
the future queries used for subsequent eviction decisions. This creates
a self-dependent feedback loop: an early omission changes the hidden
states, the changed hidden states produce drifting queries, and those
queries can reinforce the original omission.

The deployment of LLMs in long-context settings is bottlenecked by the
growth of the KV cache. Eviction-based approaches ([Zhang et al.,
2023](#bib.bib22); [Li et al., 2024](#bib.bib13); [Wang et al.,
2025](#bib.bib19)) selectively discard cache entries deemed unimportant
for future generation, enabling sub-linear cache sizes at the cost of
approximation error.

A key insight of LAQ ([Wang et al., 2025](#bib.bib19)) is that eviction
quality improves when the selection query reflects _future_ decode
queries rather than the tail of the prompt. LAQ generates $`T`$ greedy
lookahead tokens on a compressed workspace, collects their queries, and
uses them to re-score the full prompt KV. While effective, LAQ leaves
this feedback loop unresolved:

#### Window-biased stage-1 compression.

LAQ builds its lookahead workspace via SnapKV ([Li et al.,
2024](#bib.bib13)), which scores token importance using only the last
$`w`$ prompt queries. For tasks where relevant content is spread across
multiple document sections (e.g. Qasper) or requires multi-hop reasoning
(e.g. HotpotQA), the window is unlikely to capture all necessary
evidence, leading to a degraded workspace and, consequently, degraded
lookahead queries.

This failure is self-reinforcing rather than a one-time ranking error.
Once an initial workspace excludes relevant evidence, the model
generates lookahead queries from hidden states that cannot attend to
that evidence; later eviction scores are therefore conditioned on a
distorted observation. A robust solution must address both stages of
this loop: it must construct a decoding-aligned workspace before any
generated query is available, and it must give the model an opportunity
to use early queries to revise an imperfect initial workspace. This
perspective motivates EchoKV’s feedback-compatible workspace bootstrap
and its feedback-driven workspace repair.

We present EchoKV with the following contributions:

1.  1.  Diagnosis. We formulate query-driven KV eviction as a partially
        observable, self-dependent process: workspace quality conditions the
        query observations used to make the next eviction decision. We
        provide a direct measurement
        (Section [3](#S3 "3 Observations ‣ EchoKV: Self-Corrective KV Cache Evictionvia Iterative Query Feedback"))
        showing that query fidelity to true decode queries degrades with
        lookahead depth on a frozen workspace.
2.  2.  Closed-loop correction. EchoKV turns KV eviction into a closed-loop
        correction process. It constructs a _feedback-compatible bootstrap
        workspace_ before any decoded query exists, then uses round-1
        generated queries not only for final scoring but also for
        _feedback-driven workspace repair_. Future-position proposals are
        used only for initialization. The method uses $`T`$ forward passes
        over a $`B_{1}`$-sized workspace— identical to LAQ—plus one tensor
        re-scoring pass.
3.  3.  Targeted gains without overclaiming. On 16-task LongBench, EchoKV’s
        most consistent gains occur on dispersed-evidence tasks such as
        multi-hop QA and cross-passage retrieval. Its aggregate performance
        is comparable to LAQ, which motivates a failure-mode-specific claim
        rather than a universal one.

## 2 Related Work

#### KV cache compression.

Context-extension and efficient-attention methods ([Chen et al.,
2023](#bib.bib5); [Peng et al., 2024](#bib.bib17); [Ding et al.,
2024](#bib.bib8); [Chen et al., 2024](#bib.bib6); [Dao et al.,
2022](#bib.bib7); [Beltagy et al., 2020](#bib.bib2)) enlarge or
accelerate attention, but do not select which KV entries remain stored.
EchoKV is complementary: it operates at inference time on an unmodified
decoder. StreamingLLM ([Xiao et al., 2024](#bib.bib21)) retains only
sink and recent tokens. H2O ([Zhang et al., 2023](#bib.bib22)) keeps
globally heavy-hitter tokens via accumulated attention. SnapKV ([Li
et al., 2024](#bib.bib13)) uses the attention of the prompt’s final
window to score tokens. PyramidKV ([Cai et al., 2024](#bib.bib4))
allocates layer-varying budgets. AdaKV ([Feng et al., 2024](#bib.bib9))
and HeadKV ([Fu et al., 2025](#bib.bib10)) further differentiate budgets
per attention head. All these methods rely on prompt-phase queries for
eviction, ignoring decode-phase query directions. Orthogonal approaches
reduce the byte footprint of every retained KV entry rather than
selecting a subset of tokens. KIVI ([Liu et al., 2024](#bib.bib14)) uses
asymmetric low-bit quantization for keys and values, while
KVQuant ([Hooper et al., 2024](#bib.bib11)) combines low-precision
quantization with outlier handling. These methods are complementary to
EchoKV: quantization changes the representation precision, whereas
EchoKV improves which entries are retained for the decode cache.

#### Pseudo-query eviction.

LAQ ([Wang et al., 2025](#bib.bib19)) first introduced greedy lookahead
queries for KV eviction and demonstrated consistent gains over
window-based methods across budgets. DapQ ([Tian et al.,
2026](#bib.bib18)) shows that query position can strongly affect which
keys are ranked highest, and therefore replaces the observation window
with position-aware pseudo-queries synthesised at future decode
positions—obtaining a decoding-aligned observation window without
decoding at all. EchoKV repurposes positional pseudo-queries for a
distinct role: initializing the first feedback-compatible workspace
before any model-generated query exists. DapQ addresses where an
eviction query should look; EchoKV addresses how to construct the first
workspace that makes subsequent generated queries reliable. The latter
is coupled with feedback-driven workspace repair, which iteratively
corrects the workspace using model-generated queries once content-level
evidence about the answer becomes available.

#### Long-context retrieval and memory.

Memory-augmented models extend the effective context through retrieved
or recurrent state, including kNN memory in Memorizing Transformers ([Wu
et al., 2022](#bib.bib20)), recurrent memory tokens in RMT ([Bulatov
et al., 2022](#bib.bib3)), and tiered virtual context management in
MemGPT ([Packer et al., 2023](#bib.bib16)). These approaches change the
memory architecture or introduce an external memory-management policy.
EchoKV instead operates on the KV cache of an unmodified decoder at
inference time. This makes long-context RAG and agent memory motivating
application settings, not direct evaluation claims in this paper.

Iterative inference methods, such as speculative decoding and
Self-Refine ([Leviathan et al., 2023](#bib.bib12); [Madaan et al.,
2023](#bib.bib15)), adapt computation using intermediate outputs; EchoKV
instead applies feedback to the eviction workspace.

## 3 Observations

This section measures a query-fidelity pattern that motivates EchoKV’s
feedback-driven workspace repair. Let $`\mathbf{q}^{*,\ell,g}_{k}`$
denote the step-$`k`$ query for layer $`\ell`$ and KV group $`g`$,
obtained by greedy decoding on the uncompressed KV cache. Let
$`\mathcal{I}^{\ell,g}_{B}(\mathbf{Q})`$ be the top-$`B`$ token indices
selected by query set $`\mathbf{Q}`$ under the scoring rule in Eq. (3).
_KV overlap_ is

|     |     |     |     |
| --- | --- | --- | --- |
|     |

````math
\operatorname{Overlap}_{k}=\frac{1}{|\mathcal{L}||\mathcal{G}|}\sum_{\ell,g}\frac{\left|\mathcal{I}^{\ell,g}_{B}(\hat{\mathbf{Q}})\cap\mathcal{I}^{\ell,g}_{B}(\mathbf{q}^{*,\ell,g}_{k})\right|}{B}.
``` |  | (1) |

where $`\mathcal{L}`$ and $`\mathcal{G}`$ are the layer and KV-group
sets. An overlap of $`1`$ means exact agreement on the retained token
indices.

### 3.1 Greedy-lookahead fidelity decays with step count

LAQ generates $`T`$ greedy tokens on a frozen workspace
$`\mathcal{W}_{1}`$ and uses all $`T`$ queries for final eviction. If
every step contributed equal fidelity to $`\mathbf{q}^{*}`$, nothing
would be gained by refreshing the workspace mid-lookahead: one-shot on
the best available $`\mathcal{W}_{1}`$ would already be optimal.

Table [1](#S3.T1 "Table 1 ‣ 3.1 Greedy-lookahead fidelity decays with step count ‣ 3 Observations ‣ EchoKV: Self-Corrective KV Cache Evictionvia Iterative Query Feedback")
shows the opposite. On a frozen workspace, KV overlap with
$`\mathbf{q}^{*}_{k}`$ *falls* as $`k`$ grows. This decline is
consistent with error accumulation along the query trajectory, although
it does not by itself identify the source of the drift. Overlap drops
from $`0.92`$ at $`k{=}1`$ to $`0.77`$ at $`k{=}8`$ (a $`16\%`$ relative
decline), with the steepest degradation occurring in the second half
($`0.88\to 0.83\to 0.77`$ for steps 3, 6, 8). The Refreshed row shows
that rebuilding the workspace at $`k{=}T/2`$ using round-1 queries halts
the decay: overlap recovers in the second half, reaching $`0.85`$ at
$`k{=}6`$ and $`0.80`$ at $`k{=}8`$ (versus $`0.83`$ and $`0.77`$ for
the frozen baseline)—a relative improvement of $`+2.4\%`$ and $`+3.9\%`$
respectively. The joint $`[\mathbf{Q}_{1};\mathbf{Q}_{2}]`$ pool from
the refreshed path therefore better approximates the oracle’s selection
behavior in this measurement.

This pattern provides empirical evidence consistent with the proposed
error-propagation mechanism: under a frozen workspace, query–KV overlap
declines across lookahead steps, while mid-point refreshing partially
recovers it. This observation does not isolate the source of the drift,
but motivates the $`T/2{+}T/2`$ recovery schedule at equal forward-pass
count.

## 4 Method

Figure 1: EchoKV overview. Bootstrap builds a feedback-compatible

$`\mathbf{Q}_{2}`$; the joint pool $`[\mathbf{Q}_{1};\mathbf{Q}_{2}]`$

$`T`$ forwards on the workspace plus one additional re-scoring pass.

### 4.1 Stage-1: Feedback-Compatible Workspace Bootstrapping

#### The workspace selection problem.

The bootstrap workspace $`\mathcal{W}_{1}`$ must be selected at
prefill—before any decode queries are observed—yet it determines which
prompt tokens remain accessible during all $`T`$ lookahead steps. Its
purpose is not to make the final eviction decision, but to preserve
enough evidence for the first generated queries to support reliable
subsequent correction. Prior work (SnapKV, LAQ) scores the full prompt
KV cache using the last $`w`$ prompt queries, issued at positions
$`[L{-}w{+}1,L]`$. Under RoPE, these queries assign exponentially
decaying attention weights to earlier tokens purely due to
relative-distance penalties, systematically under-selecting evidence
from the prompt’s first half even when that evidence is critical for
future decode queries at positions $`{\geq}L{+}1`$. We address this with
*position-diverse* proposals that approximate the union of attention
patterns across all $`T`$ decode steps.

#### Position-aware proposal generation.

Our construction uses the positional pseudo-query mechanism of
DapQ ([Tian et al., 2026](#bib.bib18)): because the RoPE phase of a
query determines the relative distances at which it attends most
strongly, a query rotated to a future position behaves like a query
*issued* at that position, even though its content is inherited from the
prompt. DapQ uses this to build a decoding-aligned observation window
for eviction; we repurpose it to bootstrap the greedy workspace, where
no decoded token is yet available and position is the only reliable
signal. This bootstrap is not a final eviction score: it establishes the
observation substrate on which model-generated feedback can subsequently
be obtained.

Let $`L`$ be the prompt length,
$`\mathcal{K}^{\ell,g}=\{\mathbf{k}^{\ell,g}_{i},\mathbf{v}^{\ell,g}_{i}\}_{i=1}^{L}`$
the KV cache for layer $`\ell`$ and KV group $`g`$, and $`d_{k}`$ the
key dimension. We use $`S`$ semantic anchors per layer; in all
experiments $`S{=}1`$, namely the final prompt query. For anchor $`s`$,
let $`\widetilde{\mathbf{q}}^{\ell,g}_{s}\in\mathbb{R}^{d_{k}}`$ be its
pre-RoPE vector. $`\mathbf{R}(p)`$ denotes the RoPE rotation at absolute
position $`p`$. Rotating each anchor to the $`T`$ future positions
yields $`P=S\,T`$ proposals:

|  |  |  |  |
|----|----|----|----|
|  |
``` math
\mathbf{q}^{\ell,g}_{s,p}=\mathbf{R}(p)\,\widetilde{\mathbf{q}}^{\ell,g}_{s}.
``` |  | (2) |

Here $`s\in[S]`$ and $`p\in\{L+1,\dots,L+T\}`$. For any query set
$`\mathbf{Q}^{\ell,g}`$, we score prompt token $`i`$ by accumulating its
attention probability across queries:

|  |  |  |  |
|----|----|----|----|
|  |
``` math
s_{i}^{\ell,g}(\mathbf{Q})=\sum_{\mathbf{q}\in\mathbf{Q}^{\ell,g}}\frac{\exp(\mathbf{q}^{\top}\mathbf{k}^{\ell,g}_{i}/\sqrt{d_{k}})}{\sum_{j=1}^{L}\exp(\mathbf{q}^{\top}\mathbf{k}^{\ell,g}_{j}/\sqrt{d_{k}})}.
``` |  | (3) |

Here, $`\operatorname{TopK}_{B^{\prime}}`$ returns the indices of the
$`B^{\prime}`$ largest entries; thus
$`\mathcal{I}^{\ell,g}_{B^{\prime}}(\mathbf{Q})=\operatorname{TopK}_{B^{\prime}}(s^{\ell,g}(\mathbf{Q}))`$
and the bootstrap workspace is
$`\mathcal{W}_{1}^{\ell,g}=\mathcal{I}^{\ell,g}_{B_{1}}(\mathbf{Q}_{\mathrm{prop}})`$.
We evaluate the softmax in chunks over $`L`$ tokens. For grouped-query
attention, queries are mapped to their shared KV group before applying
Eq. (3); thus all selection is performed per layer and KV group.

### 4.2 Final Query Selection: Why Decode-Generated Queries Dominate

Stage 1 selects a workspace; final eviction must make the precise choice
of which $`B`$ tokens survive. A natural cheap alternative is to score
with a *real* observation window—the last $`w`$ prompt queries, as
SnapKV and its descendants do. We deliberately do not, for four reasons.

#### (1) A real window has the wrong RoPE phase.

The queries that will actually read the surviving cache are issued at
absolute positions $`>L`$, whereas a real window lives at positions
$`[L{-}w{+}1,L]`$. Under RoPE, the score
$`\langle\mathbf{q}_{p},\mathbf{k}_{i}\rangle`$ depends on the relative
offset $`p-i`$, so shifting the query position reorders which keys rank
highest. This is precisely DapQ’s observation, and it is why our stage 1
rotates proposals forward instead of reading the window directly. A real
window cannot be repositioned without ceasing to be real.

#### (2) A real decode window is not obtainable at prefill.

One could instead observe *oracle* decode queries by generating the
first few tokens and recording them on the uncompressed cache. Waiting
for a genuine observation window costs $`T`$ full-cache forward passes
at peak memory $`O(L)`$ per layer, which forfeits the memory saving that
motivates eviction. Generated pseudo queries run on the $`B_{1}`$-sized
workspace instead, so the cost is $`O(T\,B_{1})`$ with $`B_{1}\ll L`$.

#### (3) Generated queries match the decode distribution in content as well as position.

Table 2: KV overlap at step $`k{=}3`$ (budget 128) for position-only
approximation strategies against the true decode query. *Prompt*: rotate

A rotated proposal is position-correct but content-stale: it still
carries the semantics of the prompt’s last token. Once a workspace
exists, the model can be run autoregressively on it, and the resulting
queries are produced by the same network, in the same decode regime, at
the correct future positions—so they match the target distribution along
both axes.

quantifies the gap that remains for position-only approximations: KV
overlap with the true step-3 query falls to $`0.427`$ at layer 31,
indicating that position alone is insufficient for final selection in
deeper layers.

#### (4) Only generated queries permit error correction.

A real window is a single fixed measurement: if the evidence it points
to is incomplete, nothing downstream can detect this. Generated queries
provide a decode-conditioned signal for revisiting stage-1 choices. This
is what makes iteration meaningful: re-scoring the *full* cache with
round-1 queries can recover evidence the initial workspace dropped. A
fixed observation window offers no such feedback signal, and neither
does one-shot lookahead on a frozen workspace.

Points (3) and (4) together imply the specific scheme below: generate,
use the generated queries to rebuild the workspace, then generate again.

### 4.3 Feedback-Driven Workspace Repair

Standard greedy lookahead runs all $`T`$ steps on a fixed workspace
$`\mathcal{W}_{1}`$, accumulating queries $`\mathbf{Q}`$ that drive
final eviction from the full cache to the final budget $`B`$. If
$`\mathcal{W}_{1}`$ omits useful tokens, later generated queries may be
less faithful to the uncompressed-cache trajectory.

We break this compounding via feedback-driven workspace repair. The
first $`T/2`$ greedy steps produce queries $`\mathbf{Q}_{1}`$ that
reveal which prompt regions the model attempts to attend to, even on
incomplete $`\mathcal{W}_{1}`$. We use $`\mathbf{Q}_{1}`$ as a
*diagnostic signal* to re-score the *full* prompt KV cache—still
resident at prefill—and rebuild the workspace to $`\mathcal{W}_{2}`$
before continuing. The second $`T/2`$ steps then run on
$`\mathcal{W}_{2}`$, producing queries $`\mathbf{Q}_{2}`$ from the
refreshed workspace. The joint pool $`[\mathbf{Q}_{1};\mathbf{Q}_{2}]`$
drives final eviction.

#### Two-round decode scheme.

Concretely:

1.  1.
    Round 1. Decode $`T/2`$ tokens greedily on $`\mathcal{W}_{1}`$ (size
    $`B_{1}`$), starting from the prompt’s boundary token. Accumulate
    per-layer queries $`\mathbf{Q}_{1}`$.
2.  2.
    Rebuild workspace. Score the full prompt KV cache (size $`L`$) with
    $`\mathbf{Q}_{1}`$ under the same attention-pooling rule in Eq. (2).
    Select top-$`B_{1}`$ tokens per layer and KV group
    $`\to\mathcal{W}_{2}`$.
3.  3.
    Round 2. Continue greedy decode for the remaining $`T/2`$ tokens on
    $`\mathcal{W}_{2}`$, starting from the token generated at step
    $`T/2`$. Accumulate queries $`\mathbf{Q}_{2}`$.

Total forward passes remain $`T`$ (identical to LAQ). The workspace
rebuild is a scoring operation over existing tensors. Its cost scales
linearly with prompt length and with the $`T/2`$ round-1 queries per
layer; it requires no additional transformer calls.

#### Complexity and overhead.

EchoKV adds to standard full-cache prefill two costs: (a) $`T`$ greedy
decode steps over a $`B_{1}`$-sized workspace—cost
$`O(T\cdot B_{1}\cdot d)`$, identical to LAQ, with $`B_{1}\ll L`$; and
(b) one mid-point re-scoring pass over the full prompt KV using $`T/2`$
query vectors per layer. EchoKV, like other post-prefill eviction
methods, retains the full KV cache until final selection; it then
reduces the retained decode cache to $`B`$ tokens. No additional
transformer forward passes are required, and recovery is a tensor
re-scoring operation. EchoKV therefore has end-to-end latency that
depends on prompt length and implementation; we therefore do not claim
latency parity beyond the equal number of workspace forward passes.

#### Potential applications.

Several tasks on which EchoKV improves, including HotpotQA and 2WikiMQA,
require connecting facts from non-adjacent context segments. Exactly
this pattern arises in (i) *Long-Context RAG*, where retrieved passages
are concatenated and the model must locate relevant spans scattered
across the context; (ii) *multi-document reasoning*, where supporting
evidence appears in different source documents; and (iii) *agent
long-context memory*, where tool outputs and observations from many
prior turns accumulate in the context window and must be recalled
coherently. Standard window-biased eviction can drop this dispersed
evidence early; EchoKV’s feedback-compatible bootstrap and
feedback-driven repair are designed to preserve it. These are motivating
application patterns, rather than claims of performance on dedicated RAG
or agent-memory benchmarks; evaluating them on such benchmarks is future
work.

## 5 Experiments

### 5.1 Setup

#### Model and data.

We evaluate on two backbones with Flash Attention 2:
Mistral-7B-Instruct-v0.2 and Qwen2.5-7B-Instruct. Mistral serves as the
primary model, matching the setting of LAQ ([Wang et al.,
2025](#bib.bib19)) so that our numbers are directly comparable to
published baselines; Qwen2.5-7B-Instruct tests whether the method
transfers across attention configurations (Qwen2.5 uses grouped-query
attention with a different head/KV-group ratio). Both are evaluated on
the 16 English subsets of LongBench ([Bai et al., 2024](#bib.bib1)),
spanning single-document QA (NarrativeQA, Qasper, MultifieldQA-en),
multi-document QA (HotpotQA, 2WikiMQA, Musique), summarization
(GovReport, QMSum, MultiNews), few-shot learning (TREC, TriviaQA,
SAMSum), synthetic retrieval (PassageCount, PassageRetrieval-en), and
code completion (Lcc, RepoBench-P).

#### Baselines.

We report FullKV (no eviction) and compare against StreamingLLM,
H₂O ([Zhang et al., 2023](#bib.bib22)), SnapKV ([Li et al.,
2024](#bib.bib13)), PyramidKV ([Cai et al., 2024](#bib.bib4)), and
LAQ ([Wang et al., 2025](#bib.bib19)) (greedy, $`T{=}8`$). The component
variants are described in
Section [6.1](#S6.SS1 "6.1 Targeted Comparison with LAQ ‣ 6 Analysis ‣ EchoKV: Self-Corrective KV Cache Evictionvia Iterative Query Feedback").

#### Evaluation protocol.

We use the official LongBench prompts and task metrics, greedy
generation, and the same cache budgets for every compression method.
Scores are computed over the 16 English LongBench subsets listed above.
Unless stated otherwise, the analysis experiments use
Mistral-7B-Instruct-v0.2 at $`B{=}128`$; all workspace selection is
performed independently per layer and KV group.

#### EchoKV settings.

$`S{=}1`$ (single semantic anchor), $`T{=}8`$ lookahead steps (two
rounds of 4), workspace capacity $`B_{1}{=}1024`$, stage2_window=0. KV
budgets $`B\in\{128,256,512\}`$ to match prior work.

EchoKV is competitive with LAQ across budgets and backbones. At

Tables [3](#S4.T3 "Table 3 ‣ Two-round decode scheme. ‣ 4.3 Feedback-Driven Workspace Repair ‣ 4 Method ‣ EchoKV: Self-Corrective KV Cache Evictionvia Iterative Query Feedback")

evaluate EchoKV on both Mistral-7B-Instruct-v0.2 and Qwen2.5-7B-Instruct
(which uses grouped-query attention with a different head/KV-group
ratio), across all three budgets ($`B\in\{128,256,512\}`$). Both
architectures show that the method remains competitive overall, while
the size and location of task-level gains vary.

#### Comparison with baselines.

On Qwen at $`B{=}128`$, EchoKV improves over LAQ ($`T{=}8`$) on HotpotQA
($`57.10`$ vs. $`56.76`$) and 2WikiMQA ($`46.50`$ vs. $`44.96`$). Its
aggregate advantage is not uniform across budgets. This distinction is
important: EchoKV is intended to address failure cases associated with
dispersed evidence, not to replace every eviction strategy on every
task.

#### Code-subset anomaly.

Lcc and RB have unusually low FullKV scores on Qwen ($`6.62`$ and
$`9.79`$), so the code-subset results should be interpreted with
caution. We do not attribute this pattern to cache eviction without a
separate validation of the evaluation pipeline; conclusions about
transfer should therefore be read together with the Mistral results and
non-code Qwen subsets.

### 6.3 Discussion

EchoKV is most useful when decoding reconnects distant evidence, as in
HotpotQA and 2WikiMQA. The overlap and retention analyses are consistent
with this mechanism, not causal proof. Recency-biased tasks may already
be served by window eviction; RAG, agent-memory, and long-context
latency evaluations remain future work.

## 7 Conclusion

EchoKV bootstraps a workspace with future-position proposals and repairs
it with early generated queries. It is competitive with LAQ on
LongBench, with targeted gains on retrieval-intensive tasks, while
requiring full-cache retention until final selection and one extra
re-scoring pass. The overlap and evidence-retention analyses further
show that workspace refreshing improves later query fidelity and retains
more annotated evidence, which is consistent with the proposed
closed-loop correction mechanism. These findings position EchoKV as a
targeted inference-time complement to window-based eviction: it is most
useful when a future query must reconnect non-local evidence, rather
than as a universal replacement for all cache compression strategies.

## Limitations

Proposal scoring costs $`O(PL)`$ per layer and can be non-trivial at
long contexts. We do not isolate random/oracle refreshes or alternative
intervals; stage2_window$`\,{=}\,0`$ also provides no recency guarantee.
````
