# MemAdapter: Counterfactual Adaptation against Memory-Induced Sycophancy

Ruqing Ning, Haibo Meng, Zhishang Xiang, Zerui Chen, Jinsong Su, Xin
Wang, Qinggang Zhang Jilin University Xiamen University
{ningrq2222,menghb2423}@mails.jlu.edu.cn; qinggangzhang@jlu.edu.cn

###### Abstract

Long-term memory enables LLM-based agents to retain and reuse
information across tasks and sessions, supporting personalization and
long-horizon interactions. However, persistent memories can also induce
sycophancy, causing agents to over-align with users’ historical beliefs
even when they are inaccurate, outdated, or inconsistent with objective
evidence. Existing mitigation methods assume that memory-induced
sycophancy originates from biased or incorrect memories and attempt to
reduce this risk by filtering such memories at different stages of the
memory pipeline. However, in the real world, objective and correct
memories can still induce sycophancy, and the same memory can warrant
different influence across different contexts. To this end, we propose
MemAdapter, a novel framework that adaptively integrates retrieved
memories to support objective and reliable reasoning. Specifically,
MemAdapter consists of three components: (i) Counterfactual Induction,
which leverages counterfactual reasoning to uncover the potential risk
of retrieved memories; (ii) Context-Aware Reflection, which calibrates
the inferential influence of each retrieved memory in light of the
current task via self-reflection; and (iii) Evidence-Based Reasoning,
which grounds the final response in appropriate evidence while
preserving the legitimate influence of memory. Extensive experiments on
three benchmarks demonstrate that MemAdapter consistently improves
memory reliability across diverse scenarios. Our code is available at
[https://github.com/DEEP-JLU/MemAdapter](https://github.com/DEEP-JLU/MemAdapter).

## 1 Introduction

Long-term memory has become a core component of LLM-based agents,
enabling them to retain and reuse information across tasks and sessions.
A typical memory system extracts useful information from historical
interactions, store it in external memory banks, and retrieve relevant
memories for new requests, thereby supporting personalization and
long-horizon interactions ([Zhong et al., 2024](#bib.bib7); [Packer et
al., 2023](#bib.bib8); [Chhikara et al., 2025](#bib.bib9); [Xiang et
al., 2026b](#bib.bib14)). However, long-term memory is not always
beneficial. Historical information, such as past beliefs, stated
preferences, and prior judgments, can be preserved across interactions
and repeatedly reintroduced into subsequent reasoning, giving rise to
memory-induced sycophancy, where agents over-align with users’
historical views even when they are inaccurate, outdated, or
inconsistent with the available evidence ([Xiang et al.,
2026a](#bib.bib28); [Pulipaka et al., 2026](#bib.bib4); [Chao et al.,
2026](#bib.bib13)). Memory-induced sycophancy is particularly severe in
long-horizon tasks, where historical memories can persist beyond the
interactions in which they were formed and be repeatedly retrieved
across subsequent tasks and sessions ([Mao et al., 2026](#bib.bib30)).
As a result, user influence that would otherwise be temporary or
confined to a particular interaction can develop into persistent
behavioral bias, undermining factuality and objective judgment.

Several approaches have attempted to mitigate these issues by
intervening at different stages of the memory pipeline. (i) At the
extraction stage, several interventions have been proposed to reduce the
persistence of misleading or outdated information by improving memory
extraction, summarization, retention, and forgetting. Specifically,
Recalling Too Well shows that lossy memory extraction can encode and
amplify users’ erroneous beliefs, and that retaining assistant turns or
using conversation summarization instead of discrete memory extraction
can substantially reduce this effect ([Bensal et al.,
2026](#bib.bib26)). PersistBench further examines the risks of overly
persistent memories and when long-term memories should be forgotten,
highlighting the importance of selective memory retention and
forgetting ([Pulipaka et al., 2026](#bib.bib4)). (ii) At the memory
retrieval stage, OP-Bench reveals that agents may unnecessarily retrieve
and over-attend to personal memories, and proposes Self-ReCheck to
filter unnecessary memory use and mitigate over-personalization ([Hu et
al., 2026](#bib.bib21)). MemGate uses a query-conditioned gating
mechanism to selectively admit candidate memories into the model context
based on the current request ([Zhang et al., 2026](#bib.bib27)). (iii)
At the memory organization stage, Structured Memory reorganizes
retrieved memories into domain-structured representations before
generation to reduce inappropriate cross-domain influence, although
memory-induced sycophancy remains largely unresolved under such
structural interventions ([Hannoon et al., 2026](#bib.bib32)).
Collectively, these approaches improve memory reliability by controlling
how memories are extracted and maintained, which memories are retrieved,
and how retrieved memories are organized before reasoning.

Despite recent advances, existing interventions largely operate before
reasoning. They assume that memory-induced sycophancy originates from
biased or incorrect memories and attempt to reduce this risk by
filtering, suppressing, or restructuring such memories at different
stages of the memory pipeline. However, this perspective overlooks two
critical limitations in practice: (i) the risk of memory-induced
sycophancy is not fully observable at the level of memory content. An
objectively correct and task-relevant memory may contain no apparent
bias, yet still enable biased reasoning when it is reused under
particular downstream conditions. The potential risk therefore lies not
only in what the memory stores, but also in the ways it may be invoked
in future reasoning. (ii) The influence of a memory is
context-dependent: the same memory may be useful for personalization in
one task but provide no valid basis for an objective decision in
another. For example, as shown in
Figure [2(b)](#S1.F2.sf2 "In Figure 2 ‣ 1 Introduction ‣ MemAdapter: Counterfactual Adaptation against Memory-Induced Sycophancy"),
knowing that a user is a cardiologist may appropriately help an agent
calibrate the technical level of its explanation. Yet when evaluating a
treatment decision, favoring the user’s judgment solely on the basis of
this identity while discounting case-specific medical evidence may
introduce sycophantic bias. The appropriateness of memory use is
therefore not an intrinsic property of the memory itself, but a
relational property determined by its interaction with the current
reasoning context. Reliable memory use thus requires post-retrieval
calibration: beyond deciding which memories are available to the model,
it must determine the role each memory should play and the degree of
influence it should exert in the current reasoning process.

To this end, we propose MemAdapter, a novel framework that adaptively
integrates retrieved memories to support objective and reliable
reasoning. Specifically, MemAdapter consists of three components: (i)
Counterfactual Induction, which leverages counterfactual reasoning to
uncover the potential risk of retrieved memories; (ii) Context-Aware
Reflection, which calibrates the inferential influence of each retrieved
memory in light of the current task via self-reflection; and (iii)
Evidence-Based Reasoning, which grounds the final response in
appropriate evidence while preserving the legitimate influence of
memory. Together, these components allow MemAdapter to regulate memory
use according to the reasoning context without modifying the upstream
memory construction or retrieval process. Our contributions are listed
as follows:

- •
  We identify the key limitations of existing approaches for mitigating
  memory-induced sycophancy and propose MemAdapter, a novel framework
  that adaptively regulate how retrieved memories influence reasoning
  while retaining their legitimate use.
- •
  MemAdapter adopts a novel Counterfactual Induction module that
  leverages counterfactual reasoning to examine each retrieved memory
  under alternative task conditions, proactively uncovering potential
  risks that may not be apparent from the memory content itself.
- •
  MemAdapter further performs Context-Aware Reflection and
  Evidence-Based Reasoning: the former calibrates the inferential
  influence of each retrieved memory in light of the current task and
  available evidence, while the latter grounds the final response in
  appropriate evidence while preserving legitimate memory influence.
- •
  Extensive experiments across three benchmarks demonstrate that
  MemAdapter consistently improves overall memory-use reliability across
  heterogeneous memory systems.

## 2 Preliminary Study

Before going into the technical details, we examine memory-induced
sycophancy through two analyses. First, we conduct a controlled
evaluation to test whether accurate and task-relevant memories can still
induce sycophancy. Second, we analyze a fixed-memory case in which only
the task context changes, to examine how the appropriate influence of
the same memory varies across tasks. Together, these analyses show that
memory risk cannot be determined from content alone, but depends on how
the memory is used in context. Detailed experimental setup is provided
in
Appendix [B](#A2 "Appendix B Setup of Preliminary Study ‣ MemAdapter: Counterfactual Adaptation against Memory-Induced Sycophancy").

### 2.1 Accurate and Relevant Memories Can Still Induce Sycophancy

A memory can be factually correct and task-relevant yet still induce
sycophancy. To verify this, we construct test sets from MemSyco-Bench,
PersistBench, and MemTrapBench containing only instances whose retrieved
memories are accurate and highly relevant to the task, and compare model
predictions with and without memory. As shown in
Figure [2(a)](#S1.F2.sf1 "In Figure 2 ‣ 1 Introduction ‣ MemAdapter: Counterfactual Adaptation against Memory-Induced Sycophancy"),
adding memory reduces overall accuracy from 96.0% to 77.3%. The same
pattern holds across the three benchmarks, with accuracy decreasing from
96.0% to 68.0%, 100.0% to 84.0%, and 92.0% to 80.0%, respectively. More
importantly, among predictions that are correct without memory, 19.4%
become incorrect after memory is introduced, and every such reversal
follows the retrieved memory. This shows that the performance drop is
driven by the memory rather than by simply adding more context. These
results demonstrate that even accurate and relevant memories can
introduce sycophancy, meaning that their potential risk cannot be judged
from memory content alone.

### 2.2 The Same Memory Warrants Different Influence Across Contexts

How a memory should be used depends on the current task. To illustrate
this, we analyze a case in which the retrieved memory remains unchanged
while only the task context varies, as shown in
Figure [2(b)](#S1.F2.sf2 "In Figure 2 ‣ 1 Introduction ‣ MemAdapter: Counterfactual Adaptation against Memory-Induced Sycophancy").
The shared memory states that the user is a cardiologist. When the user
asks for an explanation of a new cardiovascular treatment guideline,
this information can help the model adjust the response by using
professional terminology, emphasizing clinically relevant distinctions,
and omitting unnecessary introductory material. In contrast, consider a
treatment-selection task in which the user prefers treatment A while
patient-specific evidence supports treatment B. In this case, knowing
that the user is a cardiologist may still help the model communicate
with the user, but it should not affect which treatment is selected. If
the model favors treatment A because of the user’s professional identity
rather than the patient-specific evidence, the memory induces
sycophantic behavior. This example shows that the same memory can shape
how a response is presented in one task while having no basis for
changing the conclusion in another. Therefore, How the memory is used
should be determined by the current task and available evidence.

### 2.3 Discussion

These observations suggest a broader principle: the safety of a memory
is not an intrinsic property of its content, but depends on how it
interacts with the downstream reasoning context. Therefore,
memory-induced sycophancy should be viewed not only as a memory-quality
problem, but also as a problem of how retrieved memories are used during
reasoning. Reliable memory use requires separating potential risk from
actual influence: an agent should first anticipate when a memory could
become misleading, and then determine whether and how that risk applies
given the current task and available evidence. This reframes memory
management from selecting which memories to expose to the model toward
adapting their inferential role after retrieval. The central challenge
is thus not merely whether a memory should be available, but what it is
justified to support, how strongly it should influence the response, and
where that influence should be constrained.

## 3 The Framework of MemAdapter

In this section, we introduce MemAdapter in detail. As shown in
Figure [3](#S2.F3 "Figure 3 ‣ 2.1 Accurate and Relevant Memories Can Still Induce Sycophancy ‣ 2 Preliminary Study ‣ MemAdapter: Counterfactual Adaptation against Memory-Induced Sycophancy"),
MemAdapter consists of three components: (i) Counterfactual Induction,
which leverages counterfactual reasoning to uncover potential risks in
using retrieved memories; (ii) Context-Aware Reflection, which
determines how each retrieved memory should influence reasoning based on
the current task and available evidence through self-reflection; and
(iii) Evidence-Based Reasoning, which grounds the final response in
task-relevant evidence while preserving the appropriate influence of
memory. The complete procedures of the three components are provided in
Appendix [G](#A7 "Appendix G Algorithm of MemAdapter ‣ MemAdapter: Counterfactual Adaptation against Memory-Induced Sycophancy").

### 3.1 Counterfactual Induction

Memory-induced sycophancy is a conditional failure rather than a
property that can be determined from memory content alone. The same
memory may be harmless in one setting yet distort reasoning in another
as the task objective or available evidence changes. Therefore, we
formulate memory-risk identification as a counterfactual
boundary-discovery problem: rather than asking whether a memory is
globally safe, we ask under what downstream conditions its influence
becomes inappropriate. By holding the memory fixed and systematically
varying plausible task conditions, Counterfactual Induction turns
otherwise hidden risks into observable differences across contexts.

Specifically, for each retrieved memory $`m_{i}`$, our objective is to
uncover potential risks that are not directly observable from its
content. We achieve this through counterfactual reasoning, in which we
keep $`m_{i}`$ fixed, vary the downstream task conditions under which it
may be invoked, and derive a conditional boundary from changes in its
appropriate contribution across contexts.

First, we construct a counterfactual task space to expose the range of
downstream conditions under which the same memory may participate in
reasoning. Specifically, for each $`m_{i}`$, we identify a
memory-specific set of task types from the content and scope explicitly
stated in the memory and construct one or more concrete settings for
each type. The content, provenance, and temporal scope of $`m_{i}`$
remain fixed throughout this construction. The resulting counterfactual
task space is represented as

|     |     |     |     |
| --- | --- | --- | --- |
|     |

       ``` math
       \mathcal{H}_{i}=\{(t_{ij},h_{ij})\}_{j=1}^{N_{i}}.
       ```                                                 |     | (1) |

where $`t_{ij}`$ identifies a task type in which $`m_{i}`$ may
participate and $`h_{ij}`$ instantiates that type with a concrete
request and evidence configuration.

Then, we assess the memory’s appropriate contribution in each
constructed setting to make the consequences of these variations
explicit. Specifically, for every $`h_{ij}`$, we derive a
setting-specific contribution $`v_{ij}`$ that records what $`m_{i}`$ can
support, which parts of the reasoning or response it may affect, and
which conclusions it cannot justify. These setting–contribution pairs
form

|     |     |     |     |
| --- | --- | --- | --- |
|     |

       ``` math
       \mathcal{V}_{i}=\{(h_{ij},v_{ij})\}_{j=1}^{N_{i}}.
       ```                                                 |     | (2) |

Finally, we induce a cross-context risk characterization by identifying
the conditions under which an otherwise useful memory may enable biased
reasoning. Specifically, we compare the setting-specific contributions
in $`\mathcal{V}_{i}`$, retain substantive changes in appropriate
contribution while discarding differences that only reflect surface
wording, and group settings with equivalent contributions. The resulting
distinctions are consolidated into

|     |     |     |     |
| --- | --- | --- | --- |
|     |

````math
B_{i}=\{(a_{ir},v_{ir})\}_{r=1}^{R_{i}},\qquad\mathcal{B}=\{B_{i}\}_{i=1}^{n}.
``` |  | (3) |

where $`a_{ir}`$ summarizes a condition distinguished by the comparison
and $`v_{ir}`$ describes the appropriate contribution of $`m_{i}`$ under
that condition. Together, $`\mathcal{B}`$ provides a task-agnostic
characterization of the potential risks associated with each memory for
subsequent calibration in the actual task.

### 3.2 Context-Aware Reflection

Counterfactual Induction reveals how the appropriate use of a memory can
change across possible downstream conditions, but these cross-context
boundaries do not directly determine how the memory should be used in
the current task. Context-Aware Reflection bridges this gap by adapting
the identified risks to the current request and available evidence.
Through self-reflection, it reassesses each retrieved memory in context
and determines what role it should play, which parts of the reasoning it
may affect, and how strongly it should influence the response.

Given the current request $`q`$, the model-visible context and available
evidence $`c`$, the retrieved memories $`\mathcal{M}`$, and the
conditional boundaries $`\mathcal{B}`$, we first establish the decision
or response required by $`q`$ and identify the relevant evidence and
constraints in $`c`$. We then examine each $`m_{i}`$ and $`B_{i}`$
jointly with the retrieved set to determine the appropriate role and
degree of influence of $`m_{i}`$ while accounting for updates,
qualifications, and conflicts among memories. The resulting
task-conditioned representation is written as

|     |                                  |     |     |
|-----|----------------------------------|-----|-----|
|     |
       ``` math
       \mathcal{U}=\{u_{i}\}_{i=1}^{n}.
       ```                               |     | (4) |

Each $`u_{i}`$ operationalizes the calibrated influence of $`m_{i}`$ as
a natural-language instruction that states what the memory may support,
which parts of the reasoning or response it may affect, the extent of
its influence within those parts, and which conclusions it cannot
justify.

### 3.3 Evidence-Based Reasoning

After the appropriate influence of each memory has been determined, the
remaining challenge is to ensure that these constraints are respected
during answer generation. In particular, information that is useful for
personalization or response framing should not be implicitly promoted
into evidence for factual claims or objective decisions. Evidence-Based
Reasoning therefore grounds the final response in appropriate evidence
while preserving the memory influence permitted by the task-specific
instructions.

Given $`q`$, $`c`$, the original memories $`\mathcal{M}`$, and the
task-specific influence instructions $`\mathcal{U}`$, we jointly
generate the answer $`y`$ and an internal answer-support trace
$`\mathcal{L}`$:

|  |  |  |  |
|----|----|----|----|
|  |
``` math
(y,\mathcal{L})=\mathcal{R}_{\mathrm{EBR}}(q,c,\mathcal{M},\mathcal{U}).
``` |  | (5) |

The support trace $`\mathcal{L}`$ makes the grounding process explicit
by associating each major response span with its role, supporting
source, and applicable memory-influence instruction. Before returning
$`y`$, we verify that each recorded source is present and supports the
corresponding response span, and that every use of memory remains within
the scope specified by its instruction. The support trace is used only
for internal verification, and only $`y`$ is returned to the user.

For completeness, the prompt templates used for Counterfactual
Induction, Context-Aware Reflection, and Evidence-Based Reasoning are
provided in
Appendix [H.1](#A8.SS1 "H.1 MemAdapter Prompts ‣ Appendix H Prompt Templates ‣ MemAdapter: Counterfactual Adaptation against Memory-Induced Sycophancy").

## 4 Experiments

In this section, we evaluate MemAdapter from three complementary
perspectives: overall effectiveness, cross-backbone generalization, and
component contribution. The experiments are organized around the
following research questions. RQ1 (Effectiveness). Compared with
existing memory-use intervention methods, can MemAdapter improve
memory-use performance across different benchmarks and memory systems?
RQ2 (Cross-Backbone Generalization). Can MemAdapter maintain its
effectiveness when applied to different backbone models and
heterogeneous memory systems? RQ3 (Ablation Study). What are the
respective contributions of Counterfactual Induction and Context-Aware
Reflection to the overall performance of MemAdapter?

### 4.1 Experimental Settings

Datasets: We evaluate MemAdapter on three memory-use benchmarks:
MemSyco-Bench, MemTrapBench, and PersistBench. ([Xiang et al.,
2026a](#bib.bib28); [Wang et al., 2026](#bib.bib34); [Pulipaka et al.,
2026](#bib.bib4)). MemSyco-Bench evaluates inappropriate memory use in
sycophancy-related scenarios. MemTrapBench focuses on memory-induced
cognitive traps, including reasoning fixation and belief distortion.
PersistBench evaluates long-term memory failures, including cross-domain
leakage and memory-induced sycophancy. All task-specific metrics follow
the official definitions and evaluation protocols of the corresponding
benchmarks.

Baselines: We evaluate MemAdapter with five memory systems: A-MEM, Mem0,
NaiveRAG, MemoryBank, and LightMem. For each memory system, we first
construct a corresponding memory-system baseline without any additional
memory-use intervention. We then compare MemAdapter with four
representative memory-use intervention methods: Anti-Sycophancy,
Self-ReCheck, Dynamic Partition, and MemGate. All intervention methods
are applied after memory retrieval and receive the same retrieved memory
candidates under the corresponding memory system. The compared methods
and their detailed configurations are described in
Appendix [A.2](#A1.SS2 "A.2 Retrieval and Fair-Comparison Protocol ‣ Appendix A Experimental Protocol and Reproducibility ‣ MemAdapter: Counterfactual Adaptation against Memory-Induced Sycophancy").

Evaluation Metrics: All task metrics follow the official definitions and
evaluation protocols of the corresponding benchmarks. For MemSyco-Bench,
we additionally report Avg. Acc., *When to Use Memory*, and *How to Use
Memory*, all computed as sample-weighted averages. The exact aggregation
formulas and further details on the datasets, task settings, evaluation
objectives, task-specific metrics, and memory-use requirements are
provided in
Appendix [D](#A4 "Appendix D Dataset Details ‣ MemAdapter: Counterfactual Adaptation against Memory-Induced Sycophancy").

## 5 Conclusion

In this paper, we identify a post-retrieval failure mode in long-term
memory agents, where even accurate and relevant memories can be used
beyond what the current task justifies, and the appropriate use of the
same memory can vary across reasoning contexts. Motivated by this, we
propose MemAdapter, a novel post-retrieval adaptation framework that
dynamically adjusts how retrieved memories participate in reasoning.
Specifically, MemAdapter examines each memory under counterfactually
constructed tasks to induce conditional-use rules, then evaluates these
rules against the current task and available evidence to determine
task-specific usage scopes, and finally generates the response according
to the resolved scopes. Extensive experiments on MemSyco-Bench,
PersistBench, and MemTrapBench demonstrate consistent improvements
across different memory systems and backbone models, showing that
explicitly adapting post-retrieval memory use can effectively improve
the reliability of long-term memory agents without modifying the
upstream memory system.

## Appendix A Experimental Protocol and Reproducibility

We distinguish between memory systems and memory-use methods. A memory
system determines how historical interactions are represented,
maintained, and retrieved, whereas a memory-use method determines how
retrieved memories are processed when answering the query. MemAdapter
operates strictly after retrieval and does not modify memory
construction or retrieval results.

### A.1 Compared Memory Systems and Methods

We evaluate MemAdapter with five representative memory systems: A-MEM,
Mem0, NaiveRAG, LightMem, and MemoryBank. These systems differ in how
they construct, organize, update, and retrieve long-term memory from
historical interactions. Evaluating across these systems allows us to
assess whether MemAdapter remains effective under substantially
different memory representations and retrieval pipelines.

#### A.1.1 Memory Systems

##### A-MEM.

A-MEM constructs an interconnected memory network from structured notes
derived from historical interactions ([Xu et al., 2025](#bib.bib10)).
Each note contains the interaction content together with contextual
descriptions, keywords, tags, and links to related notes. When new
information is added, the system can update existing note attributes and
connections, allowing memory structure to evolve over time. We use the
top-10 notes retrieved by A-MEM as memory context.

##### Mem0.

Mem0 maintains a persistent memory store by using an LLM to extract
salient information from interaction history and determine whether
stored memories should be added, updated, merged, or removed ([Chhikara
et al., 2025](#bib.bib9)). The resulting memory entries are indexed for
semantic retrieval, enabling the system to retrieve information relevant
to the current query without supplying the complete dialogue history. We
use the top-10 memories returned by Mem0.

##### NaiveRAG.

NaiveRAG is a retrieval-only baseline that stores raw dialogue chunks
without explicit memory abstraction, consolidation, or updating ([Lewis
et al., 2020](#bib.bib15)). For a new query, it ranks historical chunks
by vector similarity and directly provides the most relevant chunks to
the generation model. This baseline measures the effect of using raw
retrieved dialogue evidence rather than an explicitly constructed memory
representation. We use the top-10 retrieved dialogue chunks.

##### LightMem.

LightMem organizes memory through a lightweight multi-stage design
inspired by the Atkinson–Shiffrin memory model ([Fang et al.,
2026a](#bib.bib11)). It first filters and groups incoming interaction
information through sensory memory, consolidates topic-related content
in short-term memory, and periodically updates long-term memory through
an offline sleep-time process. At inference time, the system retrieves
relevant memories from this structured memory store and provides them to
the generation model.

##### MemoryBank.

MemoryBank maintains long-term memory through continual storage,
retrieval, and updating ([Zhong et al., 2024](#bib.bib7)). It summarizes
past events and user characteristics into persistent memory records,
while an Ebbinghaus-inspired mechanism adjusts memory strength according
to elapsed time and memory importance. This design allows the system to
retain salient user information while gradually weakening less important
or infrequently reinforced memories. For each query, we use the relevant
memories retrieved from the resulting memory bank.

#### A.1.2 Memory-use Methods

Unlike memory systems, memory-use methods operate after retrieval. They
do not determine which memories enter the candidate set; instead, they
determine whether and how the retrieved memories should influence the
response. We compare MemAdapter with direct generation and four
post-retrieval intervention baselines.

##### Direct Generation.

The direct-generation baseline provides the retrieved memories to the
backbone model together with the query and task context. It does not
filter, reorganize, reinterpret, or otherwise modify the retrieved
memory context. Its performance therefore reflects the default behavior
of the backbone model when historical memories are appended to the
generation prompt.

##### Anti-Sycophancy.

Anti-Sycophancy adds an explicit disclaimer to the generation prompt
([Bensal et al., 2026](#bib.bib26)). The disclaimer states that
retrieved memories may contain opinions, preferences, or misconceptions
rather than verified facts, and instructs the model to evaluate the
current question as a neutral third-party observer. All retrieved
memories remain available to the model; the intervention changes only
the instruction governing how they should be interpreted.

##### Self-ReCheck.

Self-ReCheck is a lightweight, model-agnostic memory-filtering method
designed to mitigate over-personalization ([Hu et al.,
2026](#bib.bib21)). Before answer generation, it asks the model to
reassess the relevance of each retrieved memory to the current query.
Only memories judged relevant are retained in the final context, while
the remaining memories are removed. Thus, Self-ReCheck controls memory
use by selecting a subset of the retrieved memories rather than by
specifying usage boundaries for each memory.

##### Dynamic Partition.

Dynamic Partition restructures the retrieved memory set into
domain-based groups before generation ([Hannoon et al.,
2026](#bib.bib32)). Rather than injecting memories as a flat list, it
assigns each memory to a predefined domain or, when necessary, to a
dynamically introduced category. The generation model receives the same
memory content under domain headers, making the contextual relationship
among memories more explicit while preserving every retrieved memory.
This method therefore reduces interference by changing the presentation
structure rather than filtering memories out.

##### MemGate.

MemGate is a learned, query-conditioned memory-admission mechanism
positioned between retrieval and prompt construction ([Zhang et al.,
2026](#bib.bib27)). For each retrieved memory, it predicts whether the
memory should be admitted into the generation context while keeping both
the backbone model and the memory store unchanged. We use the released
implementation and pretrained checkpoint, retaining memories whose gate
scores exceed 0.07. Unlike prompt-based methods, MemGate filters
candidate memories through a learned gate and requires no additional LLM
judgment during inference.

### A.2 Retrieval and Fair-Comparison Protocol

For memory-system comparisons, each system uses its native memory
construction and retrieval pipeline. MemAdapter receives the memories
returned by the corresponding system and regulates their use without
modifying their content, order, or retrieval source. These experiments
therefore evaluate whether MemAdapter remains effective across different
memory representations and retrieval mechanisms.

All five memory systems use BAAI/bge-m3 as the embedding model, with an
embedding dimension of 1,024. For memory construction or
memory-processing operations that require an LLM, we use
deepseek-V4-flash. The evaluation wrapper applies a common retrieval
budget to all systems: it retrieves the top 10 memories on MemTrapBench,
whereas on PersistBench it retrieves the number of memories specified by
each instance, ranging from 4 to 16. Thus, differences among systems
arise from their memory representations and native processing procedures
rather than from the embedding model or a system-specific retrieval
budget.

For completeness, we summarize the system-specific implementation
settings in prose. A-MEM stores structured notes with keywords,
descriptions, and tags; relation-based retrieval is disabled, with
evo_threshold=100 and query_limit=40. Mem0 inserts memories verbatim on
PersistBench with infer=False and uses persistent Qdrant storage.
NaiveRAG stores raw memories without chunking or LLM-based processing
and performs direct vector retrieval without reranking. LightMem applies
topic segmentation, short- and long-term memory processing, and summary
generation, followed by Qdrant-based summary retrieval with
extract_threshold=0.1. MemoryBank maintains date-based, personality, and
global summaries and performs vector-score retrieval with date-based
aggregation; forgetting and memory-strength updates are disabled. These
settings are used consistently throughout the memory-system comparisons.

For memory-use method comparisons, all methods paired with the same
memory system receive an identical frozen set of retrieved memories. For
each benchmark instance and memory system, retrieval is performed once,
and the resulting memory set is reused across all compared methods. The
benchmark instance, current query, dialogue context, task-specific
evidence, backbone model, decoding configuration, and evaluation
protocol are kept identical across methods.

MemAdapter preserves the retrieved memory set and applies three
post-retrieval stages: Counterfactual Induction, Context-Aware
Reflection, and Evidence-Based Reasoning. Therefore, performance
differences among methods paired with the same memory system can be
attributed to how they process and use the same retrieved memories
rather than to differences in retrieval results.

### A.3 Inference, Evaluation, and Reproducibility Settings

Generation Backbones. We use DeepSeek-V4-Flash, GPT-5.6-sol, and
Qwen3-8B as generation backbones. For DeepSeek-V4-Flash, we run it with
a temperature of 0.2, a maximum output length of 4,096 tokens, and
thinking disabled. GPT-5.6-sol is also run with a temperature of 0.2 and
a maximum output length of 4,096 tokens. Qwen3-8B is run locally with
4-bit NF4 quantization, bfloat16 precision, greedy decoding, and
thinking disabled. Within each experimental setting, all compared
methods use the same backbone and decoding configuration; that is, the
same generation backbone and the same decoding configuration are used by
all compared methods under that setting, and no compared method is run
with a different generation backbone or a different decoding
configuration.

Evaluation Protocol. We follow the official evaluation protocols of the
respective benchmarks and use their task-specific rubrics. For
evaluation, all judges use deterministic decoding and return structured
outputs for metric computation. These structured outputs are used for
metric computation, so that the evaluation metrics are computed from the
structured outputs returned by the judges, and the evaluation process
follows the official protocols and task-specific rubrics of the
respective benchmarks. In this way, the evaluation is conducted
according to the official protocols and task-specific rubrics, and
metric computation is based on the structured outputs.

Runtime and Reproducibility. DeepSeek-V4-Flash and GPT-5.6-sol are
accessed through API-based inference, whereas Qwen3-8B is run locally
with Transformers. Retrieval embeddings are computed locally using
BGE-M3. To support reproducibility, we preserve the retrieved memories,
boundary cards, memory-use instructions, and final responses for every
evaluated instance. These preserved artifacts are kept for each
evaluated instance, so that the retrieved memories, boundary cards,
memory-use instructions, and final responses remain available for
reproducibility. Accordingly, these items are saved as part of the
evaluated instance records, and their availability supports
reproducibility.

## Appendix B Setup of Preliminary Study

In
Section [2](#S2 "2 Preliminary Study ‣ MemAdapter: Counterfactual Adaptation against Memory-Induced Sycophancy"),
we examine whether accurate and relevant memories can still interfere
with current-task decisions. We construct a controlled paired evaluation
with 75 instances, including 25 instances derived from each of
MemSyco-Bench, PersistBench, and MemTrapBench. For each benchmark, we
first randomly sample candidate instances and manually review them
according to four criteria: the supplied memory must be accurate with
respect to the source scenario, benign, semantically relevant to the
current task, and insufficient to determine the task-specific answer.
Instances satisfying these criteria are retained; when necessary, they
are reconstructed to satisfy the controlled setting while preserving the
underlying task scenario. This procedure isolates memory use from
confounding factors such as incorrect, irrelevant, or contradictory
memories. For MemTrapBench, we exclude explicit safety-conflict
scenarios and consider ordinary reasoning cases involving cognitive
inertia, inappropriate transfer across tasks, or overgeneralization from
prior experience. The construction and evaluation controls are
summarized in
Table [4](#A2.T4 "Table 4 ‣ Appendix B Setup of Preliminary Study ‣ MemAdapter: Counterfactual Adaptation against Memory-Induced Sycophancy").

We report accuracy under the No-Memory and With-Memory conditions,
together with their difference,
$`\Delta_{\mathrm{Mem}}=\operatorname{Acc}^{\mathrm{WithMem}}-\operatorname{Acc}^{\mathrm{NoMem}}`$.
To examine whether memory changes otherwise correct decisions, we
additionally report the proportion of samples that are correct without
memory but become incorrect after memory is introduced
($`\mathrm{C}\rightarrow\mathrm{I}`$), normalized by the number of
correct No-Memory predictions. For each such reversal, we further
examine whether the new incorrect prediction is aligned with the
supplied memory, distinguishing memory-aligned reversals from changes
toward unrelated answers.

### C.5 Runtime Analysis

This section evaluates the efficiency of MemAdapter as a post-retrieval
memory-use intervention. Specifically, we examine the latency overhead
introduced by its additional reasoning stages and assess whether this
overhead remains acceptable in practical deployment. Rather than
considering only the number of model calls, we measure both typical
response time and tail latency to characterize the responsiveness and
stability of different interventions. All reported measurements cover
post-retrieval processing and final response generation under the
corresponding execution settings.

#### C.5.1 Measurement Protocol

For each successfully completed instance $`i`$, we measure runtime
$`L_{i}`$ from the initiation of the first post-retrieval model request
to the completion of the final response. The measurement includes the
model calls required by the method, together with any retries and
waiting time recorded during the execution of that instance. It excludes
memory construction, retrieval, LLM-based evaluation, model loading, and
cross-process shutdown.

Given $`N`$ successfully completed instances, the mean runtime is
computed as

|     |                                              |     |
|-----|----------------------------------------------|-----|
|     |
       ``` math
       \overline{L}=\frac{1}{N}\sum_{i=1}^{N}L_{i}.
       ```                                           |     |

We additionally report the P50, P95, and P99 runtimes, defined as the
50th, 95th, and 99th percentiles of the empirical distribution of
$`\{L_{i}\}_{i=1}^{N}`$, respectively. P50 reflects the runtime of a
typical instance and is less sensitive to a small number of slow
requests. P95 indicates the latency that 95% of instances do not exceed,
whereas P99 characterizes the tail latency of the slowest requests.

## Appendix D Dataset Details

We evaluate MemAdapter on three benchmarks that examine post-retrieval
memory use from complementary perspectives: MemSyco-Bench, MemTrapBench,
and PersistBench [Xiang et al. (2026a)](#bib.bib28); [Wang et al.
(2026)](#bib.bib34); [Pulipaka et al. (2026)](#bib.bib4). These
benchmarks do not primarily evaluate whether a memory system can store
or retrieve information. Instead, they evaluate whether retrieved
memories are assigned an appropriate role in the current task. Across
the three benchmarks, a model may need to determine whether a retrieved
memory should be used, restricted to a particular scope, overridden by
current evidence, updated in favor of a newer memory, or ignored because
it is irrelevant or outdated. The following sections summarize the
benchmark composition, task definitions, evaluation metrics, and
memory-use requirements.

### D.1 MemSyco-Bench

MemSyco-Bench evaluates whether a memory-augmented agent can assign
retrieved user memories appropriate decision authority: namely, whether
the agent can determine when a memory should influence the current
decision and how it should be used when memory-based personalization or
updating is appropriate. The benchmark distinguishes semantic relevance
from legitimate decision authority: a memory can be related to the query
without constituting valid evidence for the final answer. We use the
complete set of 1,550 instances. MemSyco-Bench organizes its five task
scenarios into two primary dimensions: When to Use Memory and How to Use
Memory. The former contains Objective Fact Judgment, Contextual Scope
Control, and Memory–Evidence Conflict, with 300 instances each. The
latter contains Personalized Memory Use with 300 instances and Valid
Memory Selection with 350 instances.

##### How to Use Memory.

This primary dimension evaluates whether a model can use memory
appropriately when memory should influence the current response.
Personalized Memory Use evaluates whether the model uses valid and
relevant personal information when personalization is explicitly
appropriate. The model should substantively use the relevant memory
while preserving a correct and useful response. Valid Memory Selection
evaluates whether the model selects the currently valid preference or
user state when multiple historical memories are available. The model
should follow the latest valid memory rather than an outdated or
superseded one.

#### D.1.1 Official Evaluation Metrics

We report task-level accuracy for the five MemSyco-Bench scenarios:
Objective Fact Judgment, Contextual Scope Control, Memory–Evidence
Conflict, Personalized Memory Use, and Valid Memory Selection. For each
scenario, an instance is counted as correct when the response satisfies
the scenario-specific correctness and memory-use requirements defined by
the official evaluation protocol. The task-level accuracy is the
proportion of correct instances within the corresponding scenario.
Higher accuracy indicates better performance.

We additionally report the average accuracy (Avg.Acc.) over all 1,550
instances. Avg.Acc. is computed as the sample-size-weighted average of
the five task-level accuracies:

|  |  |  |
|----|----|----|
|  |
``` math
\operatorname{Avg.Acc.}=\frac{300A_{\mathrm{Obj}}+300A_{\mathrm{Scope}}+300A_{\mathrm{Conflict}}+300A_{\mathrm{Personal}}+350A_{\mathrm{Valid}}}{1550},
``` |  |

where $`A_{\mathrm{Obj}}`$, $`A_{\mathrm{Scope}}`$,
$`A_{\mathrm{Conflict}}`$, $`A_{\mathrm{Personal}}`$, and
$`A_{\mathrm{Valid}}`$ denote the task-level accuracies of Objective
Fact Judgment, Contextual Scope Control, Memory–Evidence Conflict,
Personalized Memory Use, and Valid Memory Selection, respectively.

The two primary dimensions, *When to Use Memory* and *How to Use
Memory*, are also computed as sample-size-weighted averages over their
constituent scenarios:

|  |  |  |
|----|----|----|
|  |
``` math
A_{\mathrm{When}}=\frac{300A_{\mathrm{Obj}}+300A_{\mathrm{Scope}}+300A_{\mathrm{Conflict}}}{900},
``` |  |

|  |  |  |
|----|----|----|
|  |
``` math
A_{\mathrm{How}}=\frac{300A_{\mathrm{Personal}}+350A_{\mathrm{Valid}}}{650}.
``` |  |

In particular, *How to Use Memory* is not the simple average of
Personalized Memory Use and Valid Memory Selection because these two
scenarios contain 300 and 350 instances, respectively.

### D.2 MemTrapBench

MemTrapBench evaluates memory-induced cognitive traps, in which
retrieved historical context distorts a model’s reasoning or beliefs and
thereby degrades performance on the current task. The benchmark contains
1,050 instances spanning four scenarios, which are organized under two
primary categories: Reasoning Fixation and Belief Distortion. Reasoning
Fixation contains three scenarios, whereas Belief Distortion contains
one scenario.

#### D.2.1 Official Evaluation Metrics

MemTrapBench reports two primary category-level metrics: Reasoning
Fixation Score and Belief Distortion Score. Reasoning Fixation Score
summarizes performance on Task Boundary, Cognitive Bias, and Trauma,
whereas Belief Distortion Score corresponds to performance on the Safety
scenario. The benchmark may additionally report scenario-level scores
for the four individual scenarios. All reported MemTrapBench scores are
higher-is-better.

### D.3 PersistBench

PersistBench evaluates whether long-term memories remain appropriate
when the domain, task, or user state changes. It contains 500
human-validated samples divided into three scenarios: Cross-Domain
Leakage, Sycophancy, and Beneficial Memory Use, with 200, 200, and 100
samples, respectively. Each sample contains between 4 and 16 memory
items, with an average of 10 memory items. The Beneficial Memory Use
scenario further includes simple factual retrieval, multi-fact
retrieval, multi-hop reasoning, and cases containing semantically
similar distractors.

#### D.3.1 Official Evaluation Metrics

Let $`N_{\mathrm{CD}}=200`$, $`N_{\mathrm{Syco}}=200`$, and
$`N_{\mathrm{Ben}}=100`$ denote the numbers of Cross-Domain Leakage,
Sycophancy, and Beneficial Memory Use samples, respectively. For
Cross-Domain Leakage and Sycophancy, let
$`s_{i,j}^{(c)}\in\{1,\ldots,5\}`$ be the judge score for the $`j`$-th
generation of sample $`i`$, where $`c\in\{\mathrm{CD},\mathrm{Syco}\}`$
and $`j\in\{1,2,3\}`$. A sample is counted as a failure if at least one
of its three generations receives a score of at least $`3`$. Thus,

|  |  |  |
|----|----|----|
|  |
``` math
\mathrm{FR@3}^{(c)}=\frac{1}{N_{c}}\sum_{i=1}^{N_{c}}\mathbb{I}\left[\max_{j\in\{1,2,3\}}s_{i,j}^{(c)}\geq 3\right],\quad c\in\{\mathrm{CD},\mathrm{Syco}\}.
``` |  |

For Beneficial Memory Use, let $`s_{i}^{(\mathrm{Ben})}\in\{1,2,3\}`$
denote the single-generation judge score for sample $`i`$, corresponding
to correct use of all relevant memories, partial use, and no relevant
memory use, respectively. A score of $`2`$ or $`3`$ is counted as a
failure:

|  |  |  |
|----|----|----|
|  |
``` math
\mathrm{Beneficial\ FR}=\frac{1}{N_{\mathrm{Ben}}}\sum_{i=1}^{N_{\mathrm{Ben}}}\mathbb{I}\left[s_{i}^{(\mathrm{Ben})}\geq 2\right].
``` |  |

All metrics are reported as percentages and are lower-is-better.

### D.4 Memory-Use Requirements

The three benchmarks share a common principle: semantic relevance alone
does not determine whether a retrieved memory should influence the
current response. The appropriate role of a memory depends on the
current task, available evidence, memory validity, and the intended use
of personalization. Depending on the task, a retrieved memory may need
to be rejected as factual evidence, restricted to its valid contextual
scope, overridden by reliable current evidence, replaced by a newer or
currently valid memory, used to support appropriate personalization, or
ignored when it is irrelevant or outdated. MemSyco-Bench primarily
evaluates whether the model can assign the correct decision authority to
retrieved memories. MemTrapBench evaluates whether memory induces
reasoning fixation or belief distortion even when the historical context
may be relevant. PersistBench evaluates both harmful memory influence
and the ability to retain beneficial memory use. Together, these
benchmarks evaluate memory use as a task-dependent decision problem
rather than as a binary retain-or-discard operation.

This task-dependent view motivates MemAdapter. MemAdapter preserves
retrieved memories while explicitly modeling their applicable conditions
and regulating how they may influence the final response. The framework
is therefore designed to suppress inappropriate memory influence without
eliminating valid memory use or beneficial personalization.

## Appendix F Related Work

Long-term memory has become a fundamental capability for LLM-based
agents, enabling them to maintain user information, interaction history,
and task experience across sessions ([Zhang et al., 2025c](#bib.bib6);
[Yang et al., 2026a](#bib.bib38)). Early agent systems explored how
historical experiences could be stored, retrieved, and reflected upon to
support long-horizon interactions ([Feng et al., 2026](#bib.bib37);
[Xiao et al., 2026](#bib.bib39); [Wang et al., 2024](#bib.bib12); [Tan
et al., 2025](#bib.bib18)). Generative Agents introduced a memory stream
that records experiences and retrieves relevant memories to support
long-term social behaviors ([Park et al., 2023](#bib.bib19)). Reflexion
further demonstrated that agents can store verbal feedback from previous
attempts as persistent memory to improve future behaviors ([Shinn et
al., 2023](#bib.bib33)). Subsequent works focused on designing memory
architectures and improving memory management ([Zhang et al.,
2025c](#bib.bib6)). MemGPT introduced hierarchical memory with explicit
read–write operations to manage information beyond the context
window ([Packer et al., 2023](#bib.bib8)), while LongMem employed an
external retriever-reader architecture for accessing long historical
contexts ([Wang et al., 2023a](#bib.bib23)). MemoryBank and Mem0 studied
memory extraction, updating, consolidation, and forgetting mechanisms
for personalized agents ([Zhong et al., 2024](#bib.bib7); [Chhikara et
al., 2025](#bib.bib9)). More recent approaches explored structured and
efficient memory organization, such as A-MEM, which represents memories
as interconnected evolving notes ([Xu et al., 2025](#bib.bib10)), and
LightMem, which separates online memory access from offline
consolidation ([Fang et al., 2026a](#bib.bib11)).

Beyond memory construction, another line of research investigates how
retrieved information should be selected before being incorporated into
model reasoning ([Tan et al., 2025](#bib.bib18); [Wu et al.,
2026](#bib.bib40); [Zhang et al., 2025a](#bib.bib41)).
Retrieval-Augmented Generation improves LLMs by leveraging external
knowledge ([Lewis et al., 2020](#bib.bib15)), but retrieved information
may contain irrelevant, noisy, incomplete, or conflicting
evidence ([Zhang et al., 2025b](#bib.bib20)). Self-RAG enables models to
determine when retrieval is needed and to critique retrieved evidence
through self-reflection ([Asai et al., 2024](#bib.bib24)). FILCO selects
retrieved contexts according to their usefulness for the current
task ([Wang et al., 2023b](#bib.bib25)), while Corrective RAG evaluates
retrieval quality and performs corrective retrieval when retrieved
evidence is insufficient ([Yan et al., 2024](#bib.bib35)). Similar
concerns have been extended to personal memory systems. MemGate
introduces a query-conditioned gating mechanism to determine whether
retrieved memories should enter the generation context ([Zhang et al.,
2026](#bib.bib27)). OP-Bench studies excessive personalization caused by
inappropriate memory usage and proposes Self-ReCheck to reduce
unnecessary memory influence ([Hu et al., 2026](#bib.bib21)). These
approaches mainly focus on controlling which retrieved information is
exposed to the model before generation ([Hannoon et al.,
2026](#bib.bib32)).

Recent studies further reveal that persistent memory introduces new
reliability challenges beyond retrieval quality, particularly
memory-induced sycophancy and inappropriate personalization ([Sun et
al., 2026](#bib.bib22); [Fang et al., 2026b](#bib.bib36)). Sycophancy
studies show that language models may prioritize agreement with users
over independent judgment, including imitating user misconceptions or
revising correct answers under user pressure([Sharma et al.,
2024](#bib.bib1); [Wei et al., 2023](#bib.bib17)). Recent evaluations
demonstrate that such behaviors can persist across multi-turn
interactions([Hong et al., 2025](#bib.bib2); [Liu et al.,
2025](#bib.bib3); [Jain et al., 2026](#bib.bib16)). In long-term memory
settings, Recalling Too Well shows that memory extraction may preserve
and amplify users’ incorrect beliefs ([Bensal et al.,
2026](#bib.bib26)). PersistBench investigates when persistent memories
should be retained or forgotten and evaluates memory-related failures
across different scenarios ([Pulipaka et al., 2026](#bib.bib4)). Mao et
al. further study persistent sycophancy in stateful personal agents and
show that agreement behaviors can accumulate across sessions through
memory ([Mao et al., 2026](#bib.bib30)). Other benchmarks, including
MemSyco-Bench, BenchPreS, HUSH-Bench, and STALE, evaluate contextual
scope control, preference persistence, sensitive memory usage, and
memory validity under changing user states ([Xiang et al.,
2026a](#bib.bib28); [Yoon et al., 2026](#bib.bib5); [Xu et al.,
2026](#bib.bib29); [Chao et al., 2026](#bib.bib13); [Wang et al.,
2026](#bib.bib34)). Together, these studies demonstrate that retrieving
relevant memories alone does not guarantee reliable memory behavior.

Existing approaches mainly intervene at the stages before reasoning,
including memory construction, retrieval, filtering, and
organization ([Chhikara et al., 2025](#bib.bib9); [Zhang et al.,
2026](#bib.bib27); [Yang et al., 2026b](#bib.bib31); [Hannoon et al.,
2026](#bib.bib32)). However, once a memory has been retrieved and
incorporated into the context, how it should contribute to the current
reasoning process remains underexplored. A memory can be accurate and
relevant while still providing insufficient support for a particular
conclusion under the current task ([Xiang et al., 2026a](#bib.bib28);
[Wang et al., 2026](#bib.bib34); [Sun et al., 2026](#bib.bib22)). Our
work focuses on this post-retrieval setting and studies how retrieved
memories should contribute according to the current task and available
evidence without modifying the upstream memory pipeline.

### H.1 MemAdapter Prompts

This section presents the core prompts used by MemAdapter. To keep the
appendix readable, we retain the instructions that define each module’s
role, its evidence boundary, and its input–output interface, while
omitting repetitive formatting constraints and illustrative details
using ellipses. The complete implementation follows three stages: (i)
Counterfactual Induction derives abstract conditions under which each
retrieved memory may be used; (ii) Context-Aware Reflection grounds

produces the final response under the resulting memory-use instructions.
Placeholders enclosed in double braces are instantiated at inference
time.

The first stage receives the retrieved memories without the current
query or task-specific evidence. For each memory, it constructs
hypothetical task contexts, assesses the memory’s warranted influence in
each context, and induces conditional-use boundaries from substantive
differences between these assessments.

MemTrapBench uses text-based judge templates. A shared template

The shared template evaluates general answer quality along factual
