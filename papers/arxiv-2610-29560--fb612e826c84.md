###### Abstract

Vision-language-action (VLA) models achieve strong performance across
embodied manipulation tasks by unifying visual understanding, language
conditioning, and action generation. However, long-horizon tasks can
involve non-Markovian dependencies: successful decisions may require
retaining task progress and past interaction outcomes, while partial
observability and execution errors compound over time. Existing work has
begun to address these challenges by augmenting foundation-model
policies with memory and by introducing hierarchical architectures that
separate high-level planning from low-level execution. We organize the
high-level VLM as a robotic agent through an editable harness to
maintain task context and improve planning through execution experience.
We instantiate this approach as SERA (Self-Evolving Robotic Agent), with
a fixed VLA executor providing low-level control. The harness maintains
and updates task context using observations and execution feedback to
guide subsequent planning. Self-evolution uses environment rollouts to
propose and evaluate harness revisions, with the selected configuration
fixed before held-out testing. On RoboMME, SERA achieves 51.38% overall
success with autonomous selection, compared with 44.38% without
self-evolution. Our exploration suggests that agentic planning is a
promising direction for history-dependent robotic manipulation.

## 1 Introduction

Vision-language-action (VLA) models connect visual observations and
language instructions to robot actions, providing a foundation for
general-purpose manipulation ([Brohan et al., 2023](#bib.bib1); [Kim et
al., 2024](#bib.bib3); [Black et al., 2024](#bib.bib4)). Long-horizon
tasks, however, can require information that the current observation
does not reveal ([Koo et al., 2025](#bib.bib12); [Dai et al.,
2026](#bib.bib19)). For example, when a robot must repeat an operation a
specified number of times, similar images may call for different
decisions depending on how many repetitions have actually succeeded. An
earlier observation may also contain a cue that is no longer visible.
Such history-dependent decisions require preserving task-relevant
information and tracking execution outcomes over successive
interactions.

Existing research provides several foundations for these capabilities.
Memory-augmented policies equip VLA models with mechanisms for retaining
and using historical information, including compact temporal
representations ([Koo et al., 2025](#bib.bib12); [Jang et al.,
2025](#bib.bib17); [Zhu et al., 2026](#bib.bib14)), memory retrieval,
and recurrent state updates ([Shi et al., 2025a](#bib.bib13); [Hu et
al., 2026](#bib.bib15); [Li et al., 2026](#bib.bib16)). Hierarchical
architectures introduce a high-level planning layer that issues
intermediate decisions to low-level executors ([Ahn et al.,
2022](#bib.bib5); [Belkhale et al., 2024](#bib.bib10); [Duan et al.,
2025](#bib.bib11); [Sridhar et al., 2025](#bib.bib18)) and can
incorporate environment feedback ([Huang et al., 2022](#bib.bib6)).
Agentic systems further organize reasoning, actions, and feedback into
iterative decision processes ([Yao et al., 2022](#bib.bib29); [Shinn et
al., 2023](#bib.bib30); [Wang et al., 2023](#bib.bib31)). Recent
embodied harnesses explore external task management ([Zhang et al.,
2026b](#bib.bib20); [Gu et al., 2026](#bib.bib21)) and experience-driven
adaptation ([Chen et al., 2026](#bib.bib22); [Wang et al.,
2026](#bib.bib24); [Ding et al., 2026](#bib.bib23)). Together, these
developments motivate studying how the high-level planner in a
hierarchical architecture can manage task context and make use of
execution experience.

Our focus is on two connected responsibilities of this planning process.
Within an episode, issuing a command does not establish that the
intended operation has succeeded. In the repetition example, updating
progress requires interpreting subsequent observations and feedback,
while retaining information needed for later decisions. Access to
history therefore needs to be accompanied by an explicit process for
maintaining decision-relevant task context. Across attempts, an
execution record must be translated into a reusable change to influence
future planning. This raises a question: how can we support both ongoing
context management and improvements to the planning process from
execution experience? We explore an editable harness around the
high-level VLM as a common mechanism for these responsibilities. The
harness organizes context and feedback during execution, while providing
an explicit object for revision during self-evolution. This also offers
a way to investigate experience reuse when additional demonstrations and
manual annotations are costly.
Figure [1](#S1.F1 "Figure 1 ‣ 1 Introduction ‣ From VLM Planners to Robotic Agents: Self-Evolving Harnesses for History-Dependent Manipulation")
illustrates this design direction.

We present SERA (Self-Evolving Robotic Agent), which organizes a VLM as
an agent within an editable harness around a fixed VLA executor. During
task execution, the harness supports sustained context management over
long horizons, guiding the extraction, retention, and updating of task
progress and execution outcomes from observations and feedback. This
context supports the VLM’s subsequent planning. However, a predefined
harness may not anticipate all task requirements, motivating
execution-driven self-evolution to identify and repair its limitations.
Analysis and revision agents autonomously diagnose failures from
execution traces and propose candidate repairs to planning guidance,
assessment criteria, and control rules. A verifier evaluates these
candidates through environment rollouts, providing feedback for further
revision and harness selection. This process revises the harness without
manually constructing additional demonstration datasets for supervised
fine-tuning of the high-level VLM planner. The selected harness is fixed
before held-out testing, while task context continues to be updated
within each episode.

We evaluate SERA on RoboMME, a benchmark for history-dependent robotic
manipulation ([Dai et al., 2026](#bib.bib19)). Autonomous SERA achieves
51.38% overall success, compared with 44.38% without self-evolution.
These results support an empirical exploration of agentic planning and
the aggregate effect of execution-driven harness revisions. Our
contributions are:

- •
  An agentic planning framework that organizes a high-level VLM within
  an editable harness for sustained task-context management over long
  horizons, tracking task progress and execution feedback to guide a
  fixed VLA executor.
- •
  An execution-driven self-evolution procedure that autonomously
  proposes and evaluates revisions to planning guidance, assessment
  criteria, and control rules from rollout feedback, without
  constructing an SFT dataset.
- •
  We evaluate SERA on RoboMME and achieve 51.38% overall success.
  Harness self-evolution improves success by 7.00 percentage points over
  the initial configuration.

## 2 Related Work

### 2.1 Memory-Augmented Policies

Generalist robot policies learn language-conditioned manipulation from
diverse data ([Brohan et al., 2022](#bib.bib36); [Open X-Embodiment
Collaboration, 2023](#bib.bib40); [Octo Model Team et al.,
2024](#bib.bib39)). VLA models connect pretrained vision-language
representations with action learning ([Brohan et al., 2023](#bib.bib1);
[Kim et al., 2024](#bib.bib3); [Black et al., 2024](#bib.bib4); [NVIDIA
et al., 2025](#bib.bib38); [Physical Intelligence et al.,
2025](#bib.bib32)). Related embodied models, including PaLM-E,
incorporate visual and continuous state inputs into language models for
embodied reasoning and planning ([Driess et al., 2023](#bib.bib2)).
These developments provide a foundation for language-conditioned
manipulation, while history-dependent tasks additionally require
information beyond the current observation. Recent work has also
emphasized the importance of historical information in manipulation,
with benchmarks such as RoboMME explicitly evaluating history-dependent
behavior ([Dai et al., 2026](#bib.bib19)).

Memory-augmented policies incorporate such information through different
representations and update mechanisms ([Fang et al., 2025](#bib.bib33)).
HAMLET aggregates compact moment tokens across timesteps to condition
action prediction ([Koo et al., 2025](#bib.bib12)). MemoryVLA retrieves
perceptual and cognitive information from a memory bank and fuses it
with current representations ([Shi et al., 2025a](#bib.bib13)), while
ContextVLA compresses past observations into a context token for
efficient multi-frame conditioning ([Jang et al., 2025](#bib.bib17)).
Other designs address cross-subtask information transfer through
event-triggered latent memory in WeaveLA ([Zhu et al.,
2026](#bib.bib14)), hierarchical experience retrieval in ECHO ([Hu et
al., 2026](#bib.bib15)), and temporal aggregation through frame- and
chunk-level recurrent queries in ReMem-VLA ([Li et al.,
2026](#bib.bib16)). These methods integrate historical information into
action prediction through compact temporal representations, memory
retrieval, or recurrent updates.

### 2.2 Hierarchical Robotic Planning

Hierarchical approaches connect high-level reasoning to executable robot
behavior through intermediate decisions ([Rana et al.,
2023](#bib.bib42); [Shi et al., 2025b](#bib.bib43); [Zhang et al.,
2026a](#bib.bib45)). SayCan combines language-model planning with
affordance estimates for pretrained skills ([Ahn et al.,
2022](#bib.bib5)), and Inner Monologue incorporates environment feedback
into subsequent planning ([Huang et al., 2022](#bib.bib6)). Code as
Policies expresses robot behavior as programs invoking perception and
control APIs ([Liang et al., 2022](#bib.bib7)). Other interfaces include
the spatial value maps of VoxPoser, the relational keypoint constraints
of ReKep, and the language motions of RT-H ([Huang et al.,
2023](#bib.bib8); [Huang et al., 2024](#bib.bib9); [Belkhale et al.,
2024](#bib.bib10)). RoboPARA further uses dependency graphs and resource
constraints to organize parallel dual-arm execution ([Duan et al.,
2025](#bib.bib11)).

Memory and hierarchical planning can also be combined. MemER trains a
high-level VLM to nominate historical keyframes and predict language
subtasks; selected keyframes inform subsequent decisions, while a
low-level VLA executes the subtasks ([Sridhar et al.,
2025](#bib.bib18)). Goal2Skill combines structured task memory with
subtask verification and replanning in a VLM–VLA hierarchy ([Liu et al.,
2026](#bib.bib26)).

### 2.3 Agentic Embodied Systems and Self-Evolution

Research on language models and agents studies reasoning, interaction,
and feedback-driven refinement ([Madaan et al., 2023](#bib.bib37)).
ReAct interleaves reasoning with actions and observations ([Yao et al.,
2022](#bib.bib29)); Reflexion stores textual feedback for subsequent
attempts ([Shinn et al., 2023](#bib.bib30)); and Voyager accumulates
reusable executable skills through interaction in Minecraft ([Wang et
al., 2023](#bib.bib31)). Related methods improve prompts or agent code
using execution feedback ([Agrawal et al., 2025](#bib.bib34); [Zhang et
al., 2025](#bib.bib44)). These works provide precedents for agent loops
and experience reuse, although their evaluation settings differ from
robotic manipulation.

Recent embodied systems place these ideas around learned executors ([Ahn
et al., 2024](#bib.bib35)). Harness VLA combines a frozen VLA primitive
with analytic primitives and task-specific and global memories ([Zhang
et al., 2026b](#bib.bib20)). HarnessWAM maintains evidence-grounded task
state and a task graph, and compiles plans into capability-constrained
WAM skills ([Gu et al., 2026](#bib.bib21)). RoboMemory combines spatial,
temporal, episodic, and semantic memories with a planner–critic
loop ([Lei et al., 2025](#bib.bib28)). HELM couples episodic memory with
a learned state verifier and recovery control around a frozen VLA ([Zeng
et al., 2026](#bib.bib25)). Cortex combines task-context memory and
skill constraints in a deployment harness ([Peng et al.,
2026](#bib.bib41)).

Execution-driven harness adaptation is also an emerging research
direction. ETA studies experience-derived strategy and skill updates
subject to runtime checks before promotion ([Chen et al.,
2026](#bib.bib22)). SHAPER evolves textual skills and a context-code
harness using rollout feedback and validation while keeping its planner
and executor frozen ([Wang et al., 2026](#bib.bib24)). Zetta revises
runtime critics, recovery playbooks, and executable tools from failed
rollouts ([Ding et al., 2026](#bib.bib23)). Within this line of work,
SERA explores an editable harness for high-level planning in
history-dependent robotic manipulation. The harness supports
within-episode context management and is revised using development-stage
execution experience, with the selected version fixed before testing.

## 3 Method

### 3.1 Problem Formulation

We consider history-dependent robotic manipulation tasks specified by a
language instruction $`{\color[rgb]{0,0,0}i}`$. Each episode may provide
initial context $`c_{0}`$, such as a demonstration or previously
observed events. At a policy query time $`t`$, the robot receives a
sensory observation $`o_{t}`$, and the policy predicts an action chunk
$`A_{t}`$. The decision problem is non-Markovian with respect to the
instantaneous observation: similar current observations can require
different actions depending on earlier interactions. For example, the
correct placement target may depend on the order in which locations were
visited in an earlier demonstration, which cannot be inferred from the
current observation alone.

We define the interaction history $`h_{t}`$ and predicted action chunk
$`A_{t}`$ as

|     |     |     |     |
| --- | --- | --- | --- |
|     |

````math
h_{t}=(c_{0},o_{0},a_{0},\ldots,a_{t-1},o_{t}),\qquad A_{t}=(a_{t},\ldots,a_{t+K-1}),
``` |  | (1) |

where $`K`$ is the prediction horizon and
$`a_{{\color[rgb]{0,0,0}j}}\in\mathcal{A}`$ is a control action. The
objective is to complete the task within a bounded interaction budget
using a history-conditioned policy,

|     |                                                       |     |     |
|-----|-------------------------------------------------------|-----|-----|
|     |
       ``` math
       A_{t}\sim\pi(\,\cdot\mid{\color[rgb]{0,0,0}i},h_{t}).
       ```                                                    |     | (2) |

SERA maintains an explicit task context alongside recent observations to
make past information available for high-level planning. This context is
an approximate record of task state and is updated as new execution
evidence arrives.

### 3.2 Agentic Harness for Planning

#### Framework overview.

SERA organizes a high-level VLM as an agent through an editable harness,
with a fixed VLA executor for low-level control. We denote the harness
configuration by $`H`$: it specifies how inputs are assembled, task
context is maintained, commands are checked, and execution feedback is
used in subsequent decisions.
Figure [2](#S3.F2 "Figure 2 ‣ Framework overview. ‣ 3.2 Agentic Harness for Planning ‣ 3 Method ‣ From VLM Planners to Robotic Agents: Self-Evolving Harnesses for History-Dependent Manipulation")(a)
shows the resulting planning–execution loop. Execution-driven
self-evolution revises $`H`$ using rollout feedback, without requiring
additional training of the VLM planner
(Section [3.3](#S3.SS3 "3.3 Execution-Driven Self-Evolution ‣ 3 Method ‣ From VLM Planners to Robotic Agents: Self-Evolving Harnesses for History-Dependent Manipulation")).

![Refer to caption](2610.29560v1/method_overview_image.png)

Figure 2: Agentic execution and harness self-evolution. (a) The harness
maintains task context and uses a VLM to plan commands for a VLA
executor, incorporating execution feedback in subsequent rounds. (b)
Execution traces guide revisions to planning guidance, assessment

#### Episode initialization and task context.

At initialization, the harness derives episode guidance $`g`$, including
a task description, from the instruction $`i`$ and initial context
$`c_{0}`$. This guidance remains fixed within the episode. During
execution, the harness updates the task context $`c_{n}`$ using recent
observations and execution feedback. The context contains a compact
summary of task progress, decision-relevant facts, execution outcomes,
and unresolved uncertainty, together with control state for tracking
lack of progress. By retaining relevant information after its supporting
images leave the recent observation window, the context makes earlier
events available to later planning. Initialization priors and context
fields are detailed in
Appendix [B.2](#A2.SS2 "B.2 Context State and Runtime Control ‣ Appendix B Harness Implementation Details ‣ From VLM Planners to Robotic Agents: Self-Evolving Harnesses for History-Dependent Manipulation").

#### Context-aware planning.

At planning round $`n`$, the harness provides the VLM with $`g`$, recent
visual observations $`V_{n}`$, runtime context $`c_{n}`$, and the
previously executed command $`u_{n-1}`$. To support command generation,
it also supplies action candidates $`A_{\mathrm{cand},n}`$ from the
executor’s supported command set. These candidates specify available
commands and their required arguments. Candidate retrieval and
command-format details are given in
Appendix [B.1](#A2.SS1 "B.1 RoboMME Command Interface ‣ Appendix B Harness Implementation Details ‣ From VLM Planners to Robotic Agents: Self-Evolving Harnesses for History-Dependent Manipulation").

The VLM uses the observations to assess the effect of the previous
command, then proposes an updated context and a high-level command in
the same call. Action-specific assessment criteria, when available,
guide attention to relevant execution evidence. The harness checks the
response and applies its execution-control rules before storing the
resulting context and issuing the command. The combined update is

|  |  |  |  |
|----|----|----|----|
|  |
``` math
({\color[rgb]{0,0,0}c_{n+1}},u_{n})=\mathcal{P}_{H}({\color[rgb]{0,0,0}g},V_{n},{\color[rgb]{0,0,0}c_{n}},u_{n-1};{\color[rgb]{0,0,0}A_{\mathrm{cand},n}}).
``` |  | (3) |

Here, $`\mathcal{P}_{H}`$ includes both the VLM call and the surrounding
harness operations; $`u_{n}`$ is the command actually passed to the
executor. The first round uses an initial context and no preceding
command.

#### Execution and feedback.

The harness converts $`u_{n}`$ into the executor’s required input
format. Let $`x_{t}`$ denote the executor’s native conditioning inputs,
including its observations and any required task or history inputs. At
the policy query time $`t_{n}`$ for planning round $`n`$, the VLA with
fixed parameters $`\theta`$ predicts an action chunk,

|     |                                                         |     |     |
|-----|---------------------------------------------------------|-----|-----|
|     |
       ``` math
       A_{t_{n}}\sim\pi_{\theta}(\,\cdot\mid x_{t_{n}},u_{n}).
       ```                                                      |     | (4) |

The execution loop applies a bounded prefix of this chunk over multiple
control steps and collects the resulting observations. After this
execution interval, the harness starts the next planning round unless
the episode terminates or exhausts its budget. Each round queries the
VLA once; the same subtask can continue across rounds with newly
predicted chunks. The next round combines this execution evidence with
the retained context to decide whether to continue, advance, or recover
a missing prerequisite. Harness control state tracks repeated uncertain
or stagnant outcomes and can request reconsideration or another command
selection. Context and control details appear in
Appendix [B.2](#A2.SS2 "B.2 Context State and Runtime Control ‣ Appendix B Harness Implementation Details ‣ From VLM Planners to Robotic Agents: Self-Evolving Harnesses for History-Dependent Manipulation");
the runtime context is reset between episodes.

### 3.3 Execution-Driven Self-Evolution

A predefined harness may not anticipate all task requirements, leading
to recurring errors in progress tracking, command selection, or
recovery. Execution-driven self-evolution uses environment rollouts to
identify and revise these limitations. Starting from $`H_{0}`$, analysis
and revision agents propose candidate harness changes, and a verifier
supplies feedback for further revision and selection
(Figure [2](#S3.F2 "Figure 2 ‣ Framework overview. ‣ 3.2 Agentic Harness for Planning ‣ 3 Method ‣ From VLM Planners to Robotic Agents: Self-Evolving Harnesses for History-Dependent Manipulation")(b)).
This process changes the procedure that maintains and uses task context,
beyond updating the context of an individual episode.

#### Failure diagnosis.

An analysis agent examines recorded observations, task context, issued
commands, and outcomes to identify where execution first diverged from
the intended behavior. It considers physical execution and task-progress
reasoning separately, tracing their relationship to the terminal
failure. The diagnosis specifies a repair target, supporting evidence,
uncertainty, and task scope, forming a hypothesis for subsequent rollout
evaluation. Offline diagnostic materials and restrictions on deployable
repair triggers are specified in
Appendix [B.3](#A2.SS3 "B.3 Development Selection and Revision Scope ‣ Appendix B Harness Implementation Details ‣ From VLM Planners to Robotic Agents: Self-Evolving Harnesses for History-Dependent Manipulation").

#### Candidate harness revisions.

A revision agent translates the diagnosis into a candidate bundle with
activation conditions and intended behavioral changes. Candidates can
revise three parts of $`H`$: *planning guidance* directs the VLM’s
planning and recovery; *assessment criteria* specify evidence for
judging execution outcomes; and *control rules* govern recovery and task
transitions. Here, planning guidance refers to procedural instructions
in the harness, while $`g`$ denotes the episode guidance established at
initialization. The harness incorporates candidate changes into prompt
construction and runtime control, allowing the candidate to alter the
execution loop in
Section [3.2](#S3.SS2 "3.2 Agentic Harness for Planning ‣ 3 Method ‣ From VLM Planners to Robotic Agents: Self-Evolving Harnesses for History-Dependent Manipulation").
The revision process operates on these external components without
constructing an additional demonstration dataset for supervised
fine-tuning of the high-level VLM planner.

Candidate revisions are expressed as structured updates to supported
harness components. They can change the guidance supplied to the planner
or activate registered runtime control mechanisms, while preserving the
executor’s command interface. This constrains the repair process to
changes the execution loop can apply and inspect.

#### Verification and iterative revision.

A verifier evaluates candidate harnesses through environment rollouts.
For a given repair target, it compares candidate outcomes with cached
baseline outcomes on the same evaluation episodes, recording repaired
failures, regressed successes, and unchanged outcomes. A subsequent
review examines whether the intervention activated and how it affected
execution. These findings guide another revision, a different repair
target, or rejection within the search budget. Candidates meeting the
initial evaluation criteria can be assessed on additional episodes
excluded from their diagnosis and revision. Panel construction and
selection rules are described in
Appendix [B.3](#A2.SS3 "B.3 Development Selection and Revision Scope ‣ Appendix B Harness Implementation Details ‣ From VLM Planners to Robotic Agents: Self-Evolving Harnesses for History-Dependent Manipulation").

#### Selection and deployment.

The autonomous selection procedure allows both candidates passing fresh
validation and eligible fallbacks retained when the search budget is
exhausted; tasks without a selected revision retain the base harness
(Appendix [B.3](#A2.SS3 "B.3 Development Selection and Revision Scope ‣ Appendix B Harness Implementation Details ‣ From VLM Planners to Robotic Agents: Self-Evolving Harnesses for History-Dependent Manipulation")).
The selected configuration $`H^{\star}`$ is fixed before held-out
testing, and test outcomes do not enter its revision process. During
testing, task context $`c_{n}`$ continues to update, while $`H^{\star}`$
and executor parameters $`\theta`$ remain fixed.

## 4 Experiments

We evaluate SERA on RoboMME to examine agentic planning on
history-dependent tasks and execution-driven harness repair, combining
aggregate results with execution cases. We then discuss directions for
improving execution reliability.

### 4.1 Experimental Setup

#### Benchmark and metric.

RoboMME ([Dai et al., 2026](#bib.bib19)) contains 16 history-dependent
manipulation tasks in four suites: Counting, Permanence, Reference, and
Imitation. We evaluate each SERA configuration on 50 episodes per task,
totaling 800 episodes. Success rate (SR) is averaged equally across
tasks within each suite and across all 16 tasks for the overall score.
Appendix [A](#A1 "Appendix A Additional Evaluation Details ‣ From VLM Planners to Robotic Agents: Self-Evolving Harnesses for History-Dependent Manipulation")
gives the aggregation rule and per-task counts.

#### Baselines.

We consider three categories of baselines in
Table [1](#S4.T1 "Table 1 ‣ 4.2 Agentic Planning ‣ 4 Experiments ‣ From VLM Planners to Robotic Agents: Self-Evolving Harnesses for History-Dependent Manipulation"),
following the evaluated configurations in RoboMME ([Dai et al.,
2026](#bib.bib19)). VLA baselines directly predict actions from their
inputs: $`\pi_{0.5}`$ ([Physical Intelligence et al., 2025](#bib.bib32))
uses the current observation without historical context, while
$`\pi_{0.5}`$ w/ action history additionally includes past actions in
its language input ([Dai et al., 2026](#bib.bib19)). Memory-augmented
policies equip action models with mechanisms for retaining and using
history. SAM2Act ([Fang et al., 2025](#bib.bib33)) uses a memory bank
and memory attention to condition waypoint prediction on past
observations; FrameSamp+Modul ([Dai et al., 2026](#bib.bib19)) samples
historical frames and uses their visual features to modulate the action
expert. Hierarchical policies separate high-level subgoal planning from
low-level execution. SimpleSG+QwenVL generates language subgoals,
whereas GroundSG+Gemini and GroundSG+QwenVL use grounded subgoals to
specify execution targets ([Dai et al., 2026](#bib.bib19)).
MemER ([Sridhar et al., 2025](#bib.bib18)) maintains selected historical
keyframes as visual context for subgoal prediction. We evaluate SERA,
which organizes a VLM planner through an editable harness for
task-context management and execution-driven self-evolution. We use
gpt-5.6-sol through Codex as the high-level VLM planner, with reasoning
effort set to high.

How does agentic planning perform on manipulation tasks requiring
historical information?

### 4.3 Execution-Driven Self-Evolution

Can execution-driven self-evolution repair limitations in the initial
harness and improve task performance?

An initial harness may contain incomplete planning guidance, imperfect
assessment criteria, or unsuitable control rules. Feedback obtained from
execution provides an opportunity to identify where these limitations
affect task performance and to revise the corresponding parts of the
harness. With execution-driven self-evolution, SERA improves overall
success from 44.38% to 51.38%, a gain of 7.00 percentage points
(Figure [3](#S4.F3 "Figure 3 ‣ 4.3 Execution-Driven Self-Evolution ‣ 4 Experiments ‣ From VLM Planners to Robotic Agents: Self-Evolving Harnesses for History-Dependent Manipulation")a).
Revisions address inconsistent spatial interpretation, insufficient
checks before advancing task stages, and missing action candidates,
improving performance on tasks such as SwingXtimes and PatternLock.

The revision history also shows how verifier feedback guides subsequent

rollout feedback; they do not constitute an isolated comparison of the
two repair components.

### 4.4 Further Improvements and Discussion

What further improvements could help our agentic planner translate
high-level decisions into more reliable task execution?

One direction is to extend the harness with mechanisms that can
intervene more directly in execution when replanning is insufficient.
Exploratory RoboMemArena ([Lei et al., 2026](#bib.bib27)) evaluations
motivate this direction. In a task requiring two pours followed by
placing the container in a rack, the planner requests the second pour,
but the executor places the container in the rack. Although task context
retains the unfinished requirement, subsequent regrasp attempts fail.
This observation suggests that maintaining the intended task state could
be complemented by mechanisms for correcting execution deviations.

Exploratory gripper interventions provide an initial indication of this
possibility. Some development runs complete the task with the
intervention when matched runs without it fail, while another remains
unsuccessful. These interventions operate beyond the scope of our
current planner-side harness. The mixed outcomes observed across these
runs indicate that achieving reliable recovery remains an open problem
for this setting. Future work could investigate how an agentic planner
can select and assess execution-level interventions, connecting its task
understanding with more effective recovery.

## 5 Conclusion

We presented SERA, a self-evolving robotic agent for history-dependent
robotic manipulation that organizes a high-level VLM within an editable
harness around a fixed VLA executor. The harness manages task context
during execution, while self-evolution uses development-time execution
experience to revise planning guidance, assessment criteria, and control
rules. The selected harness is fixed before held-out testing. On
RoboMME, autonomous SERA achieves 51.38% success, compared with 44.38%
without self-evolution. These results support further investigation into
how the organization and adaptation of the high-level planner can
contribute to VLA-based robotic control over long execution horizons.

#### Limitations and future work.

VLM reasoning introduces planning latency into the execution loop.
Repeated inference over observations and task context can accumulate
substantial overhead during long-horizon execution, potentially limiting
timely responses in dynamic tasks. The resulting trade-off between
reasoning quality and execution responsiveness remains to be
systematically evaluated. Future work will investigate more efficient
context processing and reasoning strategies to reduce planning latency
while preserving decision quality.

### A.1 Metric Aggregation and Evaluation Scope

Let $`N=16`$ be the number of tasks and $`n_{i}=50`$ the number of
evaluation episodes for task $`i`$. Let $`b_{ij}\in\{0,1\}`$ indicate
full task success for episode $`j`$ of task $`i`$. We report

|  |  |  |  |
|----|----|----|----|
|  |
``` math
\mathrm{SR}=\frac{100}{N}\sum_{i=1}^{N}\frac{1}{n_{i}}\sum_{j=1}^{n_{i}}b_{ij}.
``` |  | (5) |

Suite-level scores use the same rule restricted to the four tasks in
that suite. Since each task has the same number of episodes, task
averaging and episode pooling coincide. Scores are computed before
rounding for display.

On RoboMME, autonomous SERA selects intervention bundles before test
evaluation. The selection includes candidates passing development and
fresh-validation checks, as well as terminal development fallbacks
allowed by the procedure in
Section [3.3](#S3.SS3 "3.3 Execution-Driven Self-Evolution ‣ 3 Method ‣ From VLM Planners to Robotic Agents: Self-Evolving Harnesses for History-Dependent Manipulation").
Tasks without a selected intervention retain the base result. Selected
candidates remain in the aggregate even when their test score decreases;
they are not replaced after observing test outcomes. The comparison
therefore reflects the selection procedure as applied, rather than a
per-task maximum over base and adapted test results.

## Appendix B Harness Implementation Details

### B.1 RoboMME Command Interface

The command catalog is extracted from released executor training labels.
Each entry specifies a skill identifier, an exact language template, its
grounding-point count, and recorded task and transition statistics. The
base retrieval scheme first restricts candidates to the known task’s
entries when available. It combines rankings for the preceding skill,
recorded successors, and skill frequency using reciprocal-rank fusion,
supplying the top five candidates or all candidates if fewer are
available. This scheme does not use semantic query similarity, even
though the retrieval interface accepts text.

The VLM selects a catalog entry and copies its template. Each required
grounding point includes an object description, a source front-camera
frame, and integer coordinates normalized to $`[0,999]`$ along each
image axis. The harness checks the template, point count, coordinate
bounds, and frame validity before rendering the command. For example,
the catalog contains pick up the peg at \<point_1\>; a subsequent
hooking template requires points for the cube and its destination. These
are catalog examples, not measured trajectory outcomes. Zero-point
templates require no grounding points.

The VLA retains its native task-goal and observation interface. In the
RoboMME driver, this includes current front/wrist images, proprioceptive
state, and the executor’s image/state buffer. This buffer is distinct
from the recent visual window supplied to the high-level planner. The
command interface does not establish physical success; execution
evidence is processed in the next planning round.

### B.2 Context State and Runtime Control

For RoboMME, episode initialization processes the instruction and
initial context using benchmark-provided task-specification priors.
Synchronized front- and wrist-camera observations supply scene-level and
local interaction evidence during execution.

The RoboMME base planner emits a rewritten progress summary bounded to
1,600 characters. Its prompt requests the current phase, completed
steps, task state, physical state, execution state, and material
uncertainty. Structured execution fields also describe the held object,
object support, and gripper state. These values are model estimates. The
description and guidance obtained at episode initialization remain
fixed, while the runtime summary and control state are updated and reset
between episodes.

Execution status distinguishes progressing, completed, uncertain,
stagnant, and regressed outcomes, with a separate initial status.
Harness-maintained counters track repeated lack of progress and
stagnation. In the catalog-only base configuration, they select normal
planning, reconsideration of the current state, or renewed selection
among known commands. The counters are not counts of verified
task-completion events. The action-specific visual check is advisory
within the same VLM call; it has no independent Python-side veto over
the visual judgment. Subsequent runtime control determines the effective
command and context stored for the next round.

### B.3 Development Selection and Revision Scope

Offline failure analysis may use benchmark-internal traces or expert
demonstrations in addition to recorded planner and execution data. These
are diagnostic materials: deployed revisions must express their
activation conditions using task identity and runtime-observable
information.

The autonomous selection protocol permits both candidates passing
development and fresh-validation checks and terminal development
fallbacks. In the reported protocol, a fallback with one additional
successful episode and no observed regression can be retained for
selection after search-budget exhaustion. A task with no selected
intervention retains its base result. The deployed version records the
selection route; the aggregate is not restricted to candidates passing
fresh validation. A panel containing only baseline failures cannot
establish retention of previously successful episodes.

Candidate manifests describe task scope, activation conditions,
components, and revision lineage. The checked runtime loads prompt
guidance, criterion overlays, and control rules into their corresponding
harness operations. The manifest format also defines broader extension
types, but their presence in the schema does not establish that they
were executed: in particular, the checked runtime rejects unregistered
Python intervention plugins. We do not treat this interface as evidence
of unrestricted online code modification.
````
