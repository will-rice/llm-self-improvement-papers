###### Abstract

Speculative decoding’s effectiveness is governed by two quantities: the
acceptance rate of drafted tokens and the cost of producing them. We
show the two objectives can be co-optimized with algorithm-system
co-design, and present JetSpec++, which retains a strong learned draft
model while hiding its cost almost entirely. JetSpec++ combines three
components: intra-block self refinement, which trains the draft model to
iteratively correct its own parallel predictions within a block of
tokens; inter-block foresight drafting, which begins the next block
before the current one is verified; and pipelined drafting and
verification, which overlaps the two stages so drafting’s marginal
wall-clock cost approaches zero. In comparison with state-of-the-art
speculative decoding methods, JetSpec++ attains a wall-clock speedup of
up to 7.45$`\times`$ over autoregressive (AR) decoding and
1.54$`\times`$ over DSpark, with up to 1,361 tokens per second for a
single request on GB200, and an average acceptance length of 8.94 across
seven benchmarks, while preserving the target model’s output
distribution. Our code and models are available at:
https://github.com/hao-ai-lab/JetSpec.

## 1 Introduction

Speculative decoding (SD) is a widely adopted technique for
parallelizing large language model (LLM) generation (Leviathan et al.,
2023; Chen et al., 2023). Its effectiveness is determined by two
factors, the acceptance rate and the drafting cost. Earlier work showed
that the target model’s hidden states of the verified context can align
the draft model with the target distribution and thereby raise the
acceptance rate (Li et al., 2024a; Li et al., 2025). DFlash employs
parallel drafting and has further reduced per-token drafting cost (Chen
et al., 2026), providing bigger headroom for higher throughput (Cheng
et al., 2026) and lower latency (Hu et al., 2026a). A natural question
to ask is whether we can further reduce drafting cost to zero on the
critical path.

One solution is to further push down the drafting cost. Cheap drafting
usually relies on model-free techniques such as prompt lookup decoding
(Saxena, 2023; Somasundaram et al., 2025) or retrieval from the text
generated so far (Oliaro et al., 2025; Hu et al., 2025). However,
model-free methods show high variance and low average acceptance rates,
particularly when reusable patterns are sparse or fail to generalize.
The question then becomes, can we retain the high acceptance rate of
model-based drafting, while removing drafting cost from the
draft-then-verify critical path?

The drafting cost can be removed from the critical path by overlapping
drafting for the next round with verification in the current round
(Figure 1). However, for a learned draft model conditioned on the target
model’s hidden states, the key challenge is that it must draft ahead
before the next verified context becomes available (Zhang et al.,
2026c). Accurately predicting this future context is therefore critical
to maintaining draft quality.

(b) JetSpec++ runs foresight and Jacobi passes while block $`t`$ is

We present JetSpec++, which maintains a target-conditioned parallel
draft model and overlaps drafting for the next step with verification of
the current step. To draft block $`t{+}1`$ while block $`t`$ is still
being verified, however, the draft model must operate without two pieces
of information that become available only after verification: (1) the
number of accepted draft tokens in block $`t`$ and the corresponding
bonus token, which becomes the _anchor_, the first token of block
$`t{+}1`$, and (2) the target hidden states for the newly verified
context in block $`t`$.

JetSpec++ addresses both missing components through _Foresight
Drafting_. Rather than waiting for the verification outcome, the draft
model anticipates multiple possible “world lines,” each corresponding to
a different acceptance-length outcome. For each request, a
hidden-to-hidden adapter predicts the target hidden states of block
$`t`$, which is still being verified. A lightweight decoder then maps
these predicted states to possible anchor tokens. The predicted hidden
states and anchor token are then used to draft block $`t{+}1`$.

Because drafting runs concurrently with target verification, additional
draft-model computation incurs no extra latency as long as it remains
within the verification window. JetSpec++ exploits this otherwise idle
compute by augmenting a causal parallel draft model built on the
architecture of JetSpec (Hu et al., 2026a) with Jacobi-style
self-refinement, allowing the draft model to iteratively revise its
parallel predictions over multiple passes. Each additional refinement
pass progressively moves the draft distribution toward a more
autoregressive factorization with better target alignment. Between two
consecutive passes of the draft model, JetSpec++ additionally simulates
verification with the adapter and the decoder as a proxy for the target.
A _context refresh_ re-predicts the target states of the draft, an
_anchor replacement_ replaces the first draft token that disagrees with
the decoder, and the next pass refines the rest of the block
(Section 4.3). In summary:

- •
  We propose _Foresight Drafting_, which enables draft-verification
  pipelining for modern speculative decoding whose learned draft models
  depend on target-model hidden states. It anticipates possible
  verification outcomes and predicts the corresponding target hidden
  states and anchor tokens, thereby drafting the next block before the
  current block is verified.
- •
  We introduce Jacobi-style self-refinement with context refresh and
  anchor replacement for a causal parallel draft model that builds on
  JetSpec’s architecture and is trained to refine its own draft
  (Section 4.3), exploiting otherwise hidden drafting compute within the
  verification window to progressively strengthen causal token
  dependence and improve target alignment over multiple passes.
- •
  We evaluate JetSpec++ on seven benchmarks, where at verification
  budget 16 it attains the longest acceptance length of all methods on
  every benchmark at temperatures 0 and 1, with an average of 8.94
  tokens per round against 6.89 for DSpark at temperature 0 (Table 1).
- •
  We integrate JetSpec++ into a serving engine with CUDA graphs and the
  draft model on a second GPU, where its end-to-end speedup is up to
  7.45$`\times`$ and 1.54$`\times`$ over AR and DSpark, at up to 1,361
  tokens per second for a single request, and JetSpec++ cuts the
  per-round overhead beyond verification by up to 84% relative to DSpark
  (Table 3).

## 2 Related Work

Speculative Decoding. Speculative decoding drafts several tokens and
verifies them in one target forward pass, and its rejection-sampling
rule leaves the output distribution unchanged (Leviathan et al., 2023;
Chen et al., 2023). Its speedup grows with the number of accepted tokens
and shrinks with the cost of drafting them. To accept more tokens per
pass, tree verification scores many candidate branches at once (Miao
et al., 2024; Chen et al., 2024; Li et al., 2024b), and knowledge
distillation aligns the draft model with the target (Zhou et al., 2024;
Liu et al., 2024; Goel et al., 2024). Medusa (Cai et al., 2024) predicts
future positions from the last hidden state, and EAGLE (Li et al.,
2024a), EAGLE-3 (Li et al., 2025) and HASS (Zhang et al., 2025) draft
from the target’s features. To draft cheaply, parallel drafting reduces
draft cost by predicting an entire block in one forward pass (An et al.,
2026; Xiao et al., 2024). Recent methods further improve parallel
drafting alignment by conditioning on target hidden states (Chen et al.,
2026), but their parallel per-position predictions are not conditioned
on the earlier realized draft tokens within the block (Wang et al.,
2026c). Sequential heads (Cheng et al., 2026; Huang et al., 2026; Zheng
& Li, 2026) restore this dependency at the cost of serial computation.
DSpine (Zhang et al., 2026a) instead writes each position’s predicted
feature into its successor after every layer, so the dependency forms
through depth within one forward pass. JetSpec (Hu et al., 2026a)
introduces causal conditioning over hidden states within the block,
while xPress (Wang et al., 2026b) trains a separate refiner and refines
the draft by Jacobi iteration. JetSpec++ instead lets the draft model
refine its own block.

Parallel Decoding. Parallel decoding lets a model itself generate
several of its own tokens per forward pass, without a separate draft
model. Jacobi decoding updates every position of a block by fixed-point
iteration and converges to the greedy output (Song et al., 2021;
Santilli et al., 2023). Lookahead decoding (Fu et al., 2024) collects
$`n`$-grams from the Jacobi trajectory and verifies them, while
consistency distillation (Kou et al., 2024) and Jacobi forcing (Hu
et al., 2026b) train an AR model to reach the fixed point in fewer
iterations. Discrete diffusion models generate text by denoising all
positions in parallel over several steps (Sahoo et al., 2024; Nie
et al., 2025; Ye et al., 2025). Block-wise discrete diffusion denoises
one block at a time and conditions each block on the earlier
ones (Arriola et al., 2025; Wu et al., 2026a), while caching (Wu et al.,
2026b), pseudo-trajectory distillation (Qian et al., 2026) and
multi-block decoding (Wang et al., 2026a) further accelerate diffusion
inference. JetSpec++ applies Jacobi iteration to the draft model rather
than the target.

Draft-Verification Pipelining. Prior work hides drafting latency by
running the draft model asynchronously with target verification (Liu
et al., 2025; McDanel, 2025). Because the verification outcome is not
yet known, recent methods hedge against multiple outcomes:
SpecBranch (Shen et al., 2026) explores alternative branches, while
speculative speculative decoding (SSD) (Kumar et al., 2026) prepares
drafts for likely verification outcomes. SwiftSpec (Zhang et al., 2026c)
uses asynchronous tree drafting to remove draft latency from the
critical path. Target-conditioned draft models make pipelining harder
because the representation of the context under verification is
unavailable. Prior approaches obtain an early target-side signal from
partial-depth computation (Bhendawade et al., 2025; Venkatesha et al.,
2025; Yu et al., 2026), and SSD substitutes the draft model’s own
activations for it (Kumar et al., 2026, Appendix E). D²SD (Zhang et al.,
2026b) forms a distribution over the number of accepted tokens $`k`$
from the draft model’s own confidences, and a second draft model
redrafts the block from the most likely prefix lengths, without
pipelining. DPara (Liu et al., 2026) pipelines a DSpark (Cheng et al., 2026) draft model without a fallback by precomputing its backbone for
every possible $`k`$, so the backbone reads the tokens under
verification without their target states. In contrast, JetSpec++
predicts the missing target hidden states directly, enabling a
target-conditioned parallel draft model to speculate ahead without
executing the target model.

## 3 Preliminaries

An AR model generates one token per forward pass, and each pass is bound
by memory bandwidth, so compute sits idle. Speculative decoding
(SD) (Leviathan et al., 2023; Chen et al., 2023) uses this idle compute
to verify several drafted tokens in one forward pass. A cheap draft
model $`q`$ proposes $`\gamma`$ tokens $`d_{1},\dots,d_{\gamma}`$ after
the verified context $`x`$, and the target model $`p`$ scores all of
them in a single forward pass. From left to right, draft token $`d_{i}`$
is accepted with probability
$`\min\{1,p(d_{i}\mid x,d_{<i})/q(d_{i}\mid x,d_{<i})\}`$. At the first
rejection the rest of the draft is discarded and the target model
samples a token of its own, the bonus token, from the residual
distribution $`\propto\max\{p-q,0\}`$. If every draft token is accepted,
the bonus token is sampled from $`p`$ at position $`\gamma+1`$. This
procedure is lossless: it preserves the target model’s generation
distribution exactly.

Each round commits the accepted prefix plus one bonus token, and its
expected number of committed tokens is the acceptance length $`\tau`$. A
round costs one drafting step and one verification step, which take
times $`T_{\text{draft}}`$ and $`T_{\text{verify}}`$. The
per-committed-token latency is therefore
$`L=(T_{\text{draft}}+T_{\text{verify}})/\tau`$, so a more accurate
draft model raises $`\tau`$ and a faster draft model lowers
$`T_{\text{draft}}`$.

### 3.1 Parallel Drafting

An AR draft model needs $`\gamma`$ sequential forward passes, so
$`T_{\text{draft}}`$ grows with $`\gamma`$. Modern parallel draft models
such as DFlash take the previous bonus token as the anchor $`y_{0}`$.
From here on, $`x`$ denotes the verified context before $`y_{0}`$.
Conditioned on the target hidden states $`h_{x}`$ of $`x`$, these models
fill the other $`\gamma`$ positions with mask tokens, and predict all
$`\gamma`$ positions in one forward pass of the draft model
$`q_{\theta}`$ with parameters $`\theta`$ (Chen et al., 2026):

```math
q_{\theta}(y_{1},\dots,y_{\gamma}\mid x,h_{x},y_{0})\;=\;\prod_{i=1}^{\gamma}q_{\theta}(y_{i}\mid x,h_{x},y_{0}) \tag{1}
```

$`T_{\text{draft}}`$ then barely depends on $`\gamma`$, but each
position is predicted without the tokens chosen at the other positions
of the block. JetSpec (Hu et al., 2026a) makes the draft model causal,
so in one forward pass every position attends to the hidden states at
its own position and at the positions before it. We build on this
architecture to enable causal token factorization via multi-pass Jacobi
iterations.

### 3.2 Jacobi Decoding for Parallel Drafting

Parallel decoding lets an AR LLM decode a $`\gamma`$-token block of its
own greedy output, $`y_{i}=\arg\max_{v}p(v\mid x,y_{<i})`$ for
$`i=1,\dots,\gamma`$, by updating all $`\gamma`$ positions in one
forward pass. Jacobi decoding (Song et al., 2021; Santilli et al., 2023)
formulates this process as solving these $`\gamma`$ equations by
fixed-point iteration, updating every position from the previous
iteration $`r`$:

```math
y_{i}^{(r+1)}\;=\;\arg\max_{v}\;p\big(v\mid x,\,y^{(r)}_{<i}\big),\qquad i=1,\dots,\gamma \tag{2}
```

Under a causal mask, each Jacobi iteration requires a single forward
pass. The resulting iterates form a Jacobi trajectory that converges to
the AR fixed point under greedy decoding (Santilli et al., 2023).
JetSpec++ trains the draft model on both fully noised inputs and
partially converged blocks (Section 4.3).

## 4 Methods

In this section, we describe how JetSpec++ works. Draft-verification
pipelining (Section 4.1) overlaps drafting with verification, reducing
the critical-path latency for decoding and yielding the throughput model
in Eq. 4. The challenge is that, in a pipelined round, the draft model
must begin before the verification outcome is available. JetSpec++
addresses this with _Foresight Drafting_ (Section 4.2), which learns
predictive features that recover most of the acceptance-length loss
(Appendix A). Finally, intra-block causal self-refinement (Section 4.3)
makes use of the bubble exposed by pipelining to further increase the
acceptance length. Between two passes of the draft model, a context
refresh and an anchor replacement rerun the adapter and the decoder of
Foresight Drafting to correct the draft.

### 4.1 Draft-Verification Pipelining

Draft-verification pipelining drafts block $`t+1`$ while block $`t`$ is
being verified. In SSD’s terms (Kumar et al., 2026), the draft process
anticipates the verification outcome $`(k,a)`$, the number $`k`$ of
accepted draft tokens together with the bonus anchor token $`a`$, and
fills a speculation cache with one pre-drafted block per anticipated
outcome. When verification returns, the realized $`(k,a)`$ is matched. A
cache hit makes the matching pre-drafted block the next block, and a
cache miss falls back to an ordinary speculative step. Every committed
token is verified by the rejection sampling acceptance rule (Leviathan
et al., 2023), so the output distribution is unchanged.

Figure 2: Illustration of Foresight Drafting. (a) _Foresight Drafting_
drafts the set $`S`$ of selected outcomes (Eq. 7) in one batch with
$`J{+}1`$ passes. (b) At each target layer $`\ell`$ that the draft model
reads, the adapter attends to the verified prefix states
$`h^{\ell}_{<n}`$ and predicts the current-block states
$`\hat{h}^{\ell}_{n:n+\gamma}`$. A decoder converts the top-layer hidden
state predictions into the outcome distribution $`P(k,a)`$ of Eq. 6. (c)
The speculation cache for block $`t{+}1`$ contains outcome $`k`$, the
draft tokens $`d_{1},\dots,d_{k}`$ that outcome $`k`$ accepts, the
corresponding adapted states $`\hat{h}`$ the draft model will read, and
the decoded bonus token $`a`$ as the anchor of block $`t{+}1`$. An
outcome whose calibrated score (Appendix B.1) reaches the threshold
$`\lambda`$ will be pre-drafted as a $`\gamma`$-token block.

_Foresight Drafting_ (Section 4.2) predicts the target hidden states
that are missing until verification ends and estimates the distribution
of the outcome from the prediction (Figure 2). The draft process of
Figure 2 (a) is hidden when

```math
T_{\text{draft}}=T_{\text{pred}}(1)+R\,T_{\text{pred}}(|S|)+(J+1)\,T_{\text{pass}}(|S|)+T_{\text{host}}\;\leq\;T_{\text{verify}} \tag{3}
```

where $`T_{\text{pred}}(\cdot)`$ is the time of one call of the adapter
and the decoder over the given number of blocks, one for the foresight
call on the block under verification and $`|S|`$ for each context
refresh on the drafts of the selected outcomes, $`T_{\text{pass}}(|S|)`$
is the time of one batched draft-model forward over the set $`S`$ of
selected outcomes, $`J`$ is the number of Jacobi refinement passes,
$`R`$ is the number of context refreshes (Section 4.3), and
$`T_{\text{host}}`$ is the time of the CPU work between GPU phases. A
choice of more selected outcomes raises $`T_{\text{pass}}(|S|)`$, so
under Eq. 3 it leaves fewer refinement passes $`J`$.

Throughput Model. Through draft-verification pipelining, on a hit the
critical path overhead reduces to
$`\max(T_{\text{verify}},T_{\text{draft}})+T_{\text{comm}}`$, where
$`T_{\text{comm}}`$ is the communication time between the two processes.
On a miss, the draft model drafts a fallback block from the verified
context in one pass (the initial draft $`J_{0}`$ of Section 4.3), which
adds $`T_{\text{fallback}}`$ to the critical path, and the same round
verifies it. With $`p_{\text{hit}}`$ being cache hit probability, and
$`\tau_{\text{hit}}`$ and $`\tau_{\text{miss}}`$ being pre-drafted block
and fallback block acceptance lengths, we adapt the speedup model of
SSD (Kumar et al., 2026) and write

```math
\text{throughput}\;=\;\frac{p_{\text{hit}}\,\tau_{\text{hit}}+(1-p_{\text{hit}})\,\tau_{\text{miss}}}{\max\!\big(T_{\text{verify}},\,T_{\text{draft}}\big)+T_{\text{comm}}+(1-p_{\text{hit}})\,T_{\text{fallback}}} \tag{4}
```

In the numerator, since $`\tau_{\text{miss}}`$ is smaller than
$`\tau_{\text{hit}}`$, throughput grows with $`p_{\text{hit}}`$.
Foresight drafting (Section 4.2) raises $`p_{\text{hit}}`$ while keeping
$`\tau_{\text{hit}}`$ close to its value under true hidden states
(Section 5), and Jacobi iterations (Section 4.3) raise
$`\tau_{\text{hit}}`$.

Placement. JetSpec++ targets per-request latency. Because the two
processes are separate, they can run on separate devices, as in
SSD (Kumar et al., 2026).

### 4.2 Inter-Block Foresight Drafting

Foresight drafting consists of an adapter, a decoder, and a draft-model
backbone, where data flow is illustrated in Figure 2. Under each
possible outcome $`k`$, positions $`1,\dots,k`$ of block $`t`$ hold the
known draft tokens $`d_{1},\dots,d_{k}`$, so the missing target-side
hidden states belong to known tokens, and the state at each position
$`j\leq k`$ is predictable by a learned map from the tokens up to
position $`j`$. This allows training a specialized adapter to predict
the hidden state at each position $`j`$ of block $`t`$.

Hidden-to-Hidden Adapter. The adapter predicts, in one parallel pass,
the target hidden states of all $`\gamma+1`$ positions of the block
under verification. At each target layer $`\ell`$ that the draft model
reads, the adapter attends to the cached prefix at that layer and
predicts the hidden states of the new future positions:

```math
\hat{h}^{\ell}_{n+j}\;=\;A_{\ell}\!\big(\,h^{\ell}_{<n},\;\hat{h}^{\ell^{-}}_{n:n+j}\,\big),\qquad j=0,\dots,\gamma \tag{5}
```

Here $`n`$ is the position of the anchor $`y_{0}`$, the bonus token of
the latest verification. $`A_{\ell}`$ is the adapter module for layer
$`\ell`$, a short stack of transformer layers copied from the target
(Appendix A). $`h^{\ell}_{<n}`$ is the target’s cached context states at
layer $`\ell`$, the layer-$`\ell`$ slice of $`h_{x}`$ in Eq. 1, and
$`\hat{h}^{\ell^{-}}`$ is the adapter’s prediction at the next lower
target layer that the draft model reads, or the block’s token embeddings
for the lowest layer. The adapter is trained separately from the draft
model. During training, each module $`A_{\ell}`$ reads the prediction of
the module below it $`\hat{h}^{\ell^{-}}_{n:n+j}`$, as at inference, and
the adapter is trained using a Smooth L1 loss plus a cosine distance
between its predictions and the target’s true hidden states
$`h^{\ell}_{n:n+j}`$, concatenated over the layers that the draft model
reads (Appendix A).

Decoder. The decoder turns the adapter’s predictions into the outcome
distributions. The decoder reuses frozen weights from the target’s last
few layers, above the deepest layer the adapter predicts, followed by
the target’s final norm and LM head. It attends to the verified context
through keys and values computed from the target’s true states
(Appendix B.1). The decoder then runs under a causal mask over the
adapter’s top-layer predictions
$`\hat{h}_{n},\dots,\hat{h}_{n+\gamma}`$. Position $`j`$ yields
$`\hat{p}(\cdot\mid j)`$, an estimate of the target’s next-token
distribution after the prefix up to $`j`$. The estimate at position
$`j-1`$ assigns draft token $`d_{j}`$ the probability
$`\hat{p}_{j}=\hat{p}(d_{j}\mid j-1)`$. For each $`k<\gamma`$,

```math
P(k)=\hat{p}_{1}\cdots\hat{p}_{k}\,(1-\hat{p}_{k+1}),\qquad P(k,a)\;=\;\hat{p}_{1}\cdots\hat{p}_{k}\;\hat{p}(a\mid k),\quad a\neq d_{k+1} \tag{6}
```

If all $`\gamma`$ draft tokens are accepted, then
$`P(\gamma)=\prod_{j=1}^{\gamma}\hat{p}_{j}`$ and
$`P(\gamma,a)=P(\gamma)\,\hat{p}(a\mid\gamma)`$. One decoder pass
therefore scores every outcome at once, since row $`j`$ serves both the
acceptance of $`d_{j+1}`$ and the bonus distribution at $`k=j`$
(Figure 3 in Appendix B). We call the decoder _perfect_ if its estimate
$`\hat{p}(\cdot\mid j)`$ equals the target’s next-token distribution at
the sampling temperature after every prefix $`j`$ of the draft. With a
perfect decoder, Eq. 6 is the exact distribution of the outcome under
speculative sampling at any temperature, for any draft that is fixed
before verification, such as the Jacobi-refined argmax draft of Eq. 8
(see Appendix F.1). In Appendix B.3 (Table 9), we show that the current
design closely approximates the perfect decoder.

Outcome Selection. Given the outcome distributions, the draft process
still needs to select the outcomes to pre-draft. Due to limited
draft-side compute, the draft process selects, computes and caches a
finite set of $`B`$ most promising outcomes $`(k,a)`$ of Eq. 6 and
$`(\gamma,a)`$. Outcomes are disjoint events, so the hit probability of
a cache is the sum of its entries’ probabilities:

```math
S^{\star}\;=\;\arg\max_{|S|\leq B}\;\sum_{(k,a)\in S}P(k,a) \tag{7}
```

The optimum is the $`B`$ most probable outcomes. In practice, decoder
scores are imperfect, especially at longer lengths where errors compound
through Eq. 6, so we calibrate the outcome scores on held-out prompts
and retain candidates above a split-conformal threshold
$`\lambda`$ (Angelopoulos & Bates, 2023), up to cache size $`B`$. The
threshold is fit offline to include the realized outcome at a target
rate on held-out rounds. At inference, this threshold can yield a
variable number of cached outcomes across rounds. For simplicity, our
experiments instead cache the $`B`$ highest-scoring outcomes in every
round (Appendix B.1). Calibration affects only which outcomes are
pre-drafted, never the verified output (Appendix F.3). Unlike SSD (Kumar
et al., 2026), which fixes how many anchors each value of $`k`$
receives, Eq. 7 selects the cache dynamically from each round’s outcome
scores. With a perfect decoder, this selection is at least as good as
any fixed allocation in every round (Proposition 2, Appendix F.2).

Batched Drafting. Having selected the outcomes to predict, each outcome
$`(k,a)`$ is then drafted in the same way as an ordinary block. Its
anchor is $`a`$, its context ends with $`d_{1},\dots,d_{k}`$, and the
draft model reads the adapter’s predictions at the positions up to $`k`$
in place of the target’s hidden states. The predicted states are the
only approximation, and verification keeps the output lossless whatever
they are. All selected outcomes are drafted as one batch, with the
refinement passes of Section 4.3.

### 4.3 Intra-Block Self Refinements

A parallel draft model marginalizes each position over its possible
predecessors, so its marginals are what PRESTO (Wang et al., 2026c)
calls _prefix-blind_. DSpark (Cheng et al., 2026) gives an example: when
the context admits _“of course”_ and _“no problem”_, the block may read
_“of problem”_. Sequential heads and separate refiners repair
prefix-blindness at the cost of a sequential or recurrent module. We
instead let the draft model refine its own draft in parallel, with no
module beyond those of Foresight Drafting, in the time that pipelining
frees under verification. Self-refinement combines three operations,
Jacobi iterations of the draft model, context refresh and anchor
replacement.

Jacobi Iterations. Eq. 1 factorizes the block into per-position
marginals, whereas the target generates it token by token,
$`p(y_{1:\gamma}\mid x,y_{0})=\prod_{i=1}^{\gamma}p(y_{i}\mid x,y_{<i})`$.
JetSpec++ makes the draft model follow this causal, token-level
factorization through Jacobi iterations. Our draft model takes
_natural-language tokens_, not mask embeddings, as the inputs, and
attends causally within the block (Section 3.1), so each position can
condition on the tokens drafted before it. Refinement is a Jacobi
iteration (Section 3.2) of the draft model on its own draft:

```math
y_{i}^{(r+1)}\;=\;\arg\max_{v}\;q_{\theta}\!\big(v\,\big|\,x,\;h_{x},\;y^{(r)}_{\leq i}\big),\qquad i=1,\dots,\gamma \tag{8}
```

Here $`y^{(r)}`$ is the block after $`r`$ iteration passes, and
$`J_{r}`$ names a round that stops at it, so $`J`$ in Eq. 3 counts these
passes. $`J_{0}`$ is the initial draft, whose inputs are a fully noised
block of tokens drawn from the verified context, and $`y_{0}`$ is the
anchor, the verified bonus token on a miss or the guessed $`a`$ of a
pre-drafted block. Causal attention lets position $`i`$ read
$`y_{\leq i}`$ for each iteration. The block therefore moves from the
factorization of Eq. 1 toward an explicit causal token factorization, in
which each position conditions on the drafted tokens $`y_{<i}`$ before
it.

Context Refresh. Jacobi iterations alone bring diminishing returns in
acceptance length (Table 5, $`R=0`$). Between two consecutive passes,
JetSpec++ therefore simulates verification on the current draft with the
adapter and the decoder of Foresight Drafting. In a _context refresh_,
the adapter re-predicts the target hidden states of the current draft
$`y^{(r)}`$. Block $`t`$ is still under verification, so both modules
read the foresight predictions at its positions up to $`k`$ in place of
true states. Like the states of Foresight Drafting, the refreshed states
are predictions, because the target has not yet read the draft.

Anchor Replacement. The decoder then reads the refreshed states and
finds the first position at which its most likely token differs from the
draft. An _anchor replacement_ fixes the draft tokens before that
position for the rest of the round, writes the decoder’s token
$`\hat{a}`$ at it, and fixes that position too. Like the anchor $`a`$ of
a pre-drafted block, $`\hat{a}`$ is a guess of the token that the target
would emit there. The next pass redrafts only the positions after the
last fixed one (Appendix D). A round runs at most one context refresh,
with its anchor replacement, between two consecutive passes, so it has
$`R\leq J`$ context refreshes. Both operations change only the proposal,
so verification keeps the output lossless (Appendix F.3).

Training. A draft model trained only on masked blocks is never trained
to condition on tokens at its inputs. Following Jacobi forcing (Hu
et al., 2026b), we train on blocks that pair a clean prefix with a noisy
suffix, the shape of a partially converged Jacobi iterate. The first
$`m`$ positions hold the true tokens and the rest hold noise tokens
$`\tilde{y}`$, which we draw from the sequence’s own context rather than
from Jacobi trajectories. We train the draft model to match the target
model at every position:

```math
\mathcal{L}\;=\;\mathbb{E}_{m}\sum_{i=1}^{\gamma}\mathcal{D}\!\Big(p(\cdot\mid x,y_{<i})\,\Big\|\,q_{\theta}\big(\cdot\mid x,h_{x},[\,y_{0:m};\,\tilde{y}_{m+1:\gamma}\,]_{\leq i}\big)\Big) \tag{9}
```

where $`\mathcal{D}(\cdot\,\|\,\cdot)`$ denotes a divergence. We use
forward KL, which outperforms reverse KL and cross-entropy SFT in our
ablations (Section 5.5). The clean prefix length $`m`$ is sampled per
block from a fixed schedule (Appendix E), so the model is trained to
repair any clean-prefix block in Jacobi decoding. Appendix E provides
our clean-prefix selection rule and details on our training setup.

### 5.2 Results

Table 1 reports the acceptance length. At both temperatures and both
budgets, JetSpec++ commits more tokens per round than every baseline on
all seven benchmarks. At temperature 0 and budget 16,
$`J_{1}`$-$`R_{1}`$ averages 7.50 against 6.89 for DSpark, the strongest
baseline, and $`J_{3}`$-$`R_{3}`$ raises it to 8.94. Foresight drafting
costs little acceptance length. At each of $`J_{0}`$ to $`J_{3}`$
without context refresh, the draft model keeps 95 to 98% of the $`\tau`$
it reaches from the target’s true states (Table 6).

Although every draft model is trained on blocks of 16, JetSpec++
extrapolates to blocks of 32. At budget 32, $`J_{1}`$-$`R_{1}`$ gains
$`\tau`$ on every benchmark at both temperatures, whereas DFlash, DSpark
and Domino lose it. On MATH-500 at temperature 0, for example, $`\tau`$
rises from 9.63 to 11.45 for $`J_{1}`$-$`R_{1}`$ and falls from 9.01 to
8.66 for DSpark. With causal attention inside the block, the 16 added
positions leave the draft of the first 16 unchanged, and JetSpec, also
causal, likewise gains $`\tau`$ at temperature 0. DFlash and Domino
attend bidirectionally within the block, so the 16 added positions also
change the draft of the first 16.

### 5.6 Limitations

Our serving integration can be further improved through systems
optimization. In particular, fused kernels and optimized communication
could reduce drafting overhead and enable additional refinement passes
and context refreshes to further improve throughput.

## 6 Conclusion

We presented JetSpec++, which drafts the next block while the current
one is verified. Foresight Drafting predicts the target states and the
verification outcome before verification returns. We train the causal
parallel draft model on blocks with a clean prefix and a noisy suffix,
so that self-refinement can spend the freed draft-side time on Jacobi
passes and context refreshes. On GB200 GPUs, JetSpec++ decodes up to
7.45$`\times`$ faster than AR decoding and 1.54$`\times`$ faster than
DSpark.

## Appendix A Adapter Design and Ablations

The predicted states of the adapter (Section 4.2) recover most of the
acceptance length that the target’s true states give (Sections 5.2
and 5.5). In this appendix, we describe the adapter’s architecture and
training, measure this recovery, and ablate the number of adapter layers
and the position weight in the loss.

Architecture. The adapter has one module $`A_{\ell}`$ of Eq. 5 for each
target layer $`\ell`$ that the draft model reads, and each module is a
short stack of transformer layers. Module $`A_{\ell}`$ takes the block’s
states at the next lower layer $`\ell^{-}`$ that the draft model reads
and predicts the block’s states at $`\ell`$. The lowest module takes the
block’s token embeddings instead, so the modules form one chain from the
tokens to the deepest layer that the draft model reads. In each module,
the queries come from the block positions, and the keys and values come
from the true states $`h^{\ell}_{<n}`$ of the verified context and the
block’s states $`\hat{h}^{\ell^{-}}`$ at earlier block positions. We
initialize each module with copies of target layers between $`\ell^{-}`$
and $`\ell`$, ending with layer $`\ell`$. The adapter reuses the
target’s token embedding and keeps it frozen. We train all other weights
of the adapter, and it adds no projection or head of its own. The
adapter has 2.32B trainable parameters for Qwen3-8B and 4.47B for
Qwen3.8-27B.

Target layers. The draft model reads five target layers. Layer indices
start at 0. The modules for the three lowest layers each copy only their
own layer, and the two deepest modules copy four and five layers, twelve
layers in all.

- •
  Qwen3-8B (36 layers): the draft model reads layers 1, 9, 17, 25 and
  33, spaced uniformly from the second layer to the third-to-last as in
  DFlash (Chen et al., 2026).
- •
  Qwen3.8-27B (64 layers): the draft model reads layers 5, 19, 33, 47
  and 61. Each adapter layer for this target takes its MLP from the
  copied layer and its attention from the nearest full-attention layer
  at or below it.

Training objective. We train the adapter against the frozen target,
which computes the true states online, on blocks of $`\gamma+1=16`$
positions. Let $`\mathbf{h}_{n+j}`$ be the concatenation of the target’s
true states $`h^{\ell}_{n+j}`$ at the layers that the draft model reads,
and $`\hat{\mathbf{h}}_{n+j}`$ the adapter’s prediction of it. For a
block whose anchor is at position $`n`$, the loss is

```math
\mathcal{L}_{\text{adapter}}\;=\;\sum_{j=0}^{\gamma}\frac{\omega_{j}^{\kappa}}{\sum_{j^{\prime}=0}^{\gamma}\omega_{j^{\prime}}^{\kappa}}\Big[\operatorname{SmoothL1}\big(\hat{\mathbf{h}}_{n+j},\mathbf{h}_{n+j}\big)+1-\cos\big(\hat{\mathbf{h}}_{n+j},\mathbf{h}_{n+j}\big)\Big], \tag{10}
```

where $`\omega_{j}`$ is the probability that verification reaches block
position $`j`$, taken from served runs. The exponent $`\kappa`$ sets how
the positions are weighted: $`\kappa=0`$ weights every position equally,
and $`\kappa=1`$ weights each position by $`\omega_{j}`$. We use
$`\kappa=1/2`$.

Training data and optimization. We train on the 800k training sequences
of the draft model (Appendix E), less 24k held out, with each sequence
capped at 3,072 tokens. We use AdamW with a peak learning rate of
$`3\times 10^{-4}`$ (linear warmup over the first 4% of steps, then
cosine decay), gradient clipping at norm 1.0 and no weight decay. For
Qwen3-8B, we train for six epochs at a global batch of 4 to 8 sequences,
in 219 GPU-hours. For Qwen3.8-27B, we train for two epochs at a global
batch of 8, with the AdamW $`\beta_{2}`$ set to 0.95, in 172 GPU-hours.

## Appendix B Decoder and Outcome Scores

We describe the served configuration of the decoder of Section 4.2,
which reuses the target’s upper layers without training. Figure 3 shows
how one decoder pass supplies every factor of the outcome score in
Eq. 6. We then calibrate this score, compare the decoder with a
fine-tuned copy, and compare the calibrated score with other selection
rules.

Figure 3: Scoring every outcome with one decoder pass. The adapter
predicts the block’s states from the verified context, and the decoder
reads them with the verified context as keys and values. Layers
$`\ell_{1},\dots,\ell_{\text{top}}`$ are the target layers that the
draft model reads, and $`\ell_{\text{top}}`$ is the deepest of them. Row
$`j`$ is the decoder’s $`\hat{p}(\cdot\mid j)`$. For the outcomes with
$`k=5`$ (outlined), rows 0 to 4 supply the acceptance probabilities
$`\hat{p}_{1},\dots,\hat{p}_{5}`$ of the draft tokens, row 5 supplies
the bonus distribution with $`d_{6}`$ excluded, and later rows are not
read. The bars give each outcome’s score against the threshold
$`\lambda`$ of Section 4.2: solid bars reach $`\lambda`$ and are cached,
and dashed bars are dropped. Heights are schematic. Our experiments
instead cache the $`B`$ outcomes with the highest calibrated score in
every round (Appendix B.1).

### B.1 Scoring Rule and Cache Size

Reused target layers. The decoder reuses the target layers above the
deepest layer that the adapter predicts, followed by the target’s final
norm and LM head, all frozen. Its estimate $`\hat{p}(\cdot\mid j)`$ is
the softmax of the LM head’s logits at temperature 1, at both sampling
temperatures. For Qwen3-8B, the decoder reuses the two target layers
above layer 33 (layers 34 and 35). The target sends its layer-33 states
to the draft process after each verification. For Qwen3.8-27B, the
decoder reuses the two target layers above layer 61 (layers 62 and 63).
After each verification, the target sends the committed recurrent and
convolution states of layer 62 (a Gated DeltaNet layer) and the keys and
values of layer 63.

Calibrated score. JetSpec++ scores each outcome $`(k,a)`$ by the
_calibrated score_ $`\tilde{P}(k)\,P_{\beta}(a\mid k)`$. To compute
$`\tilde{P}(k)`$, JetSpec++ replaces each factor $`\hat{p}_{i}`$ of
Eq. 6 with a logistic function $`\tilde{p}_{i}`$ of a feature vector
$`\bm{\phi}_{i}`$,

```math
\tilde{p}_{i}\;=\;\sigma\big(\mathbf{w}^{\top}\bm{\phi}_{i}\big),\qquad G(k)=\prod_{i\leq k}\tilde{p}_{i},\qquad\tilde{P}(k)=G(k)-G(k+1),\quad G(\gamma+1)=0. \tag{12}
```

Here $`\mathbf{w}`$ holds one coefficient for each feature. The product
$`G(k)`$ estimates the probability that verification accepts the first
$`k`$ draft tokens, so $`\tilde{P}(k)`$ estimates the probability that
verification accepts exactly $`k`$. The vector $`\bm{\phi}_{i}`$ holds
six features of position $`i`$:

- •
  the logit of the draft model’s top-1 probability at position $`i`$ in
  its final pass,
- •
  the logit of the decoder’s probability $`\hat{p}_{i}`$ of $`d_{i}`$,
- •
  an indicator of whether $`d_{i}`$ is the decoder’s top token
  $`\arg\max_{v}\hat{p}(v\mid i-1)`$,
- •
  the logit of the decoder’s largest renormalized probability
  $`\max_{a\neq d_{i}}\hat{p}(a\mid i-1)/(1-\hat{p}_{i})`$ of a token
  other than $`d_{i}`$,
- •
  the scaled position $`i/14`$,
- •
  a constant bias feature.

The factor $`P_{\beta}(a\mid k)\propto\hat{p}(a\mid k)^{1/\beta}`$ is
the decoder’s bonus distribution at $`k`$, tempered by the anchor
temperature $`\beta`$. JetSpec++ renormalizes this distribution over the
decoder’s top 32 candidates, with $`d_{k+1}`$ removed when $`k<\gamma`$.
We fit $`\mathbf{w}`$ and $`\beta`$ on the calibration rounds of
Appendix B.2.

Cache size. For both targets, the draft process caches the $`B`$
highest-scoring outcomes per round, or all distinct outcomes when fewer
exist. The cache size $`B`$ is 16 in Tables 1 and 2, and 4 in Table 3.
In the offline replays of Tables 10 and 11, the served rule caches
outcomes in the same way at each $`B`$.

### B.2 Fitting the Calibrated Score

We collect the calibration rounds by serving a pooled set of 56 held-out
prompts for each target. For Qwen3-8B, each of GSM8K, MATH-500,
HumanEval, MBPP and LCB contributes 8 prompts, drawn after its
evaluation prompts. UltraChat (Ding et al., 2023) and the GSM8K training
split contribute 8 prompts each. We fit once per target and verification
budget, and the same fit serves every benchmark and both temperatures.

The served rule has three fitted parts: the six coefficients
$`\mathbf{w}`$ of Eq. 12, the anchor temperature $`\beta`$, and the
split-conformal thresholds on the calibrated score. We fit
$`\mathbf{w}`$ by maximum likelihood of the realized $`k`$ on the
calibration rounds, and $`\beta`$ by maximum likelihood of the realized
anchor. We set the thresholds on the same rounds by split-conformal
prediction.

## Appendix D Self-Refinement Example and Drafting Without Pipelining

A context refresh (Section 4.3) uses both the adapter and the decoder.
Figure 4 traces one context refresh and its anchor replacement, and we
measure self-refinement without pipelining. Appendix F.3 shows that the
output stays lossless when anchor replacement rewrites the draft.

Anchor replacement rule. After a context refresh, the decoder reads the
refreshed states of the draft $`y^{(r)}`$, and anchor replacement uses
the first disagreement between the decoder’s argmax and the draft:

```math
\begin{gathered}\hat{k}=\max\big\{\,0\leq i\leq\gamma-1:y^{(r)}_{j}=\arg\max_{v}\hat{p}(v\mid j-1)\;\,\forall\,1\leq j\leq i\,\big\},\\
\hat{a}=\arg\max_{v}\hat{p}(v\mid\hat{k})\end{gathered} \tag{13}
```

Here $`\hat{p}(\cdot\mid j)`$ are the decoder’s next-token estimates of
Section 4.2, and $`(\hat{k},\hat{a})`$ is the outcome that greedy
verification of the draft would return if the decoder were the target.
Anchor replacement fixes the tokens up to position $`\hat{k}`$ for the
rest of the round. If $`\hat{a}`$ differs from the draft token at
position $`\hat{k}+1`$, it writes $`\hat{a}`$ there and fixes that
position too. A position fixed earlier keeps its token. The next pass
reads the refreshed states only up to position $`\hat{k}`$, because a
token written at position $`\hat{k}+1`$ has no refreshed state, and it
redrafts only the positions after the last fixed one.

## Appendix E Training and Evaluation Details

Training data and optimization. We take the prompts of the 800k training
sequences from Nemotron-Post-Training-Dataset-v2 (NVIDIA, 2025) and
CodeAlpaca-20k (Chaudhary, 2023), and each target model generates the
responses greedily in non-thinking mode. We train the draft model of
Section 4.3 on these sequences for six epochs with AdamW and a peak
learning rate of $`3\times 10^{-4}`$ (linear warmup over the first 4% of
steps, then cosine decay). We use gradient clipping at norm 1.0, no
weight decay, a global batch of 16 sequences and seed 42. Training takes
347 GPU-hours on GB200 GPUs for Qwen3-8B and 710 for Qwen3.8-27B. The
ablation draft models are for Qwen3-8B. They use the same learning rate,
learning-rate schedule, global batch and seed, but train for two epochs
on the 239k mathematics sequences of the 800k set.

Training blocks. Training sequences have at most 3,072 tokens for
Qwen3-8B and 4,096 for Qwen3.8-27B, and we sample up to 512 anchor
positions per sequence. An anchor must be a supervised response token
that leaves room for a full block of 16 positions (the anchor and
$`\gamma=15`$ draft positions). Under the prefix-length schedule, the
clean prefix length $`m`$ of Eq. 9 is 0 (a fully noised block) with
probability 0.25 and each of $`1,\dots,15`$ with probability 0.05. Each
noise token in $`\tilde{y}`$ copies the token at an independent,
uniformly random position of the sequence up to and including the
anchor.

Draft model architecture. The draft model has five transformer layers
and ends with a final normalization. It concatenates the target’s hidden
states $`h_{x}`$ at the five target layers of Appendix A, passes the
concatenation through a linear layer and normalizes the result. Every
draft layer projects this result into keys and values of the verified
context, as in DFlash (Chen et al., 2026), and attends causally within
the block (Section 4.3). We reuse the target’s embedding and LM head and
keep them frozen. The draft model has 1.05B trainable parameters for
Qwen3-8B and 1.73B for Qwen3.8-27B.

Training objective. We use the forward KL divergence at temperature 1 as
the divergence of Eq. 9 and average it over the supervised draft
positions of a batch, with no decay along the block. In the loss
ablations of Table 14 (Appendix C), SFT is the cross-entropy to the next
token of the training sequence, and reverse KL is
$`\mathrm{KL}(q_{\theta}\,\|\,p)`$ at temperature 1.

Baselines. The DFlash, DSpark, JetSpec and Domino draft models are
trained for six epochs on the same 800k sequences as our draft model.
DFlash, DSpark, Domino and JetSpec also share our maximum length, anchor
count, warmup and seed. DFlash and JetSpec have five transformer layers
and read the same five target layers as our draft model. However, both
baselines fill every draft position of a training block with a mask
token.

- •
  We train DFlash without the positional loss decay and at our learning
  rate of $`3\times 10^{-4}`$. It attends bidirectionally within the
  block and is trained with the SFT loss at our global batch.
- •
  We reproduce DSpark with 15 draft tokens after the anchor, its Markov
  head and its confidence head. The loss also follows DSpark: a weighted
  sum of the cross-entropy, the L1 distance between the draft and target
  distributions, and the confidence loss, with weights 0.1, 0.9 and 1.
  DSpark weights all three terms at draft position $`i`$ by
  $`\exp(-(i-1)/7)`$, the positional loss decay of DFlash. We train
  DSpark at a learning rate of $`6\times 10^{-4}`$. Its global batch is
  8 for Qwen3-8B and 16 for Qwen3.8-27B.
- •
  Domino attends bidirectionally within the block and adds its Domino
  head. It is trained with its cross-entropy loss and a positional loss
  decay constant of 7. We train it at our learning rate of
  $`3\times 10^{-4}`$ and at a global batch of 48.
- •
  JetSpec attends causally within the block and is trained with our loss
  and learning rate at a global batch of 8.
- •
  SSD uses the off-the-shelf Qwen3-0.6B model as its draft model. It
  drafts 4 tokens per round (a block of 5 with the anchor) and
  pre-drafts three outcomes $`(k,a)`$ for each $`k`$ on GSM8K and one on
  MATH-500, a flat fan-out as in SSD’s released code.

Benchmarks. For the fixed shuffle of Section 5.1, we shuffle the test
split of each benchmark with seed 0. We use the sanitized MBPP and
release v6 of LCB. The runs of the ablation draft models use the first
164 prompts of GSM8K and MATH-500 from the same shuffle, at temperature
0 and with at most 256 generated tokens. On MT-Bench, we evaluate both
turns of the 80 questions. Every method starts the second turn from the
same first-turn answer, which the target generates with AR.

Repetition loops. Some outputs, mostly greedy ones at temperature 0,
fall into a verbatim repetition loop that runs to the 2,048-token cap.
Draft models can predict repeated text almost perfectly, which would
inflate $`\tau`$ and the speedup. In Tables 1, 2, 3, 5 and 16, we
therefore treat an output that reaches the cap as a repetition loop if
its final 64 tokens occur verbatim at least three times in it, without
overlap. We stop such an output at the onset of the loop, the first
occurrence of that 64-token span, and keep other capped outputs whole.
We handle this stop like an EOS stop: the round that crosses the onset
counts only its tokens before the onset. We measure time through the end
of that round. We cut every method, AR included, at its own onsets. On
MT-Bench, the rule applies to each turn separately. The runs of Tables 6
and 12, in which every round drafts only the block of the verified
outcome, stop only at EOS or the cap.

Metrics. We compute $`\tau`$ as the committed tokens per verification
round, pooled over all rounds of the requests of a benchmark, including
the first round of each request. $`\tau`$ includes the bonus token of
each round, and the token that the target produces at prefill belongs to
no round. In the last round of a request, $`\tau`$ counts only the
tokens committed before EOS or the generation cap. We compute throughput
as the tokens per second, also pooled over the requests of a benchmark.
Throughput counts every round after the first of each request. A round
is a hit round when it verifies the pre-drafted block of the previous
round’s outcome, and a miss round otherwise. The hit rate is the share
of hit rounds, and $`\tau_{\text{hit}}`$ and $`\tau_{\text{miss}}`$ are
the values of $`\tau`$ on the hit and the miss rounds. These three
values also exclude the first round of each request, whose block comes
from no cache.

Serving protocol. For Table 3, each method generates responses to the
128 prompts of GSM8K and MATH-500 in Table 1, in four groups of 32,
until EOS or 2,048 tokens. Each method runs at temperature 0 and batch
size 1, with budget 16 (5 for SSD, with the settings of the Baselines
paragraph above). JetSpec++ runs $`J_{1}`$-$`R_{1}`$ for Qwen3-8B and
$`J_{3}`$-$`R_{3}`$ for Qwen3.8-27B, with a cache of $`B=4`$ outcomes
(Appendix B.1). We pool the four groups, weighting $`\tau`$ by rounds
and throughput by time, and the mean times exclude the first round of
each request. Each speedup is relative to the AR row of the same target
and benchmark.

Correctness checks. In exact arithmetic, verification makes the greedy
output of every speculative method equal to that of AR. We run two
checks on GSM8K with JetSpec++ at $`J_{1}`$-$`R_{1}`$ for Qwen3-8B, as
in Table 3. First, we run the target model in fp32. The first 256 tokens
that JetSpec++ generates for each of the first 8 prompts of the fixed
shuffle (2,048 tokens in all) match AR token by token. Second, we check
the CUDA graphs of the draft process against eager execution. On the
first 3 prompts, JetSpec++ replays 492 draft rounds from a CUDA graph,
and we recompute each of them eagerly in the same round. No recomputed
output differs from the graph’s.

In the three subsections of this appendix, we prove results that support

- •

  exact probability of the verification outcome $`(k,a)`$ when the
  decoder is perfect (Section 4.2).
- •

### F.1 Exact Outcome Probabilities with a Perfect Decoder

Outcome selection (Eq. 7) ranks the outcomes $`(k,a)`$ by the decoder
score $`P(k,a)`$ of Eq. 6. We show that, with a perfect decoder,
$`P(k,a)`$ is exactly the probability that verification of the block
ends at outcome $`(k,a)`$, at any temperature and for any draft that is
fixed before verification. Eq. 7 then selects the cache with the largest
hit probability.

Example. Take $`\gamma=2`$. Verification uses the point-mass proposal of
Appendix F.3, so it accepts each draft token with the target’s
probability of that token. The target gives $`d_{1}`$ probability
$`0.8`$, and after $`d_{1}`$ it gives $`d_{2}`$ probability $`0.5`$ and
another token $`b`$ probability $`0.3`$. Verification ends at $`(1,b)`$
when it accepts $`d_{1}`$ (probability $`0.8`$), rejects $`d_{2}`$
(probability $`1-0.5=0.5`$) and draws $`b`$ from the residual
(probability $`0.3/0.5=0.6`$). This gives
$`0.8\cdot 0.5\cdot 0.6=0.24`$, which equals
$`P(1,b)=\hat{p}_{1}\,\hat{p}(b\mid 1)=0.8\cdot 0.3`$ for a perfect
decoder. The rejection probability cancels against the normalization of
the residual, and the proof of Proposition 1 shows that this
cancellation holds for every outcome.

###### Assumption 1 (Perfect decoder).

1.  (i)
    The draft tokens $`d_{1},\dots,d_{\gamma}`$ of the block are fixed
    before the verification of the block starts.
2.  (ii)
    The random draws that verify this block are independent of what
    chose $`x`$ and the draft.
3.  (iii)
    Verification uses the acceptance rule of Section 3 with the
    point-mass proposal (Appendix F.3).
4.  (iv)
    The decoder is perfect in that its estimate after prefix $`j`$
    equals the target’s next-token distribution at the sampling
    temperature, $`\hat{p}(\cdot\mid j)=p(\cdot\mid x,d_{\leq j})`$. In
    this appendix, $`x`$ includes the anchor $`y_{0}`$, which Eq. 1
    lists separately, and $`d_{\leq 0}`$ is empty, so row $`0`$ of the
    decoder estimates $`p(\cdot\mid x)`$, the target’s distribution for
    $`d_{1}`$. At temperature $`0`$, every $`p(\cdot\mid x,d_{\leq j})`$
    is the point mass on the target’s argmax, and a fixed rule breaks a
    tie.

Every draft of Sections 4.1 to 4.3 satisfies conditions (i) and (ii) of
Assumption 1: the initial draft $`J_{0}`$ and the fallback block of a
miss, the passes of Eq. 8, drafts from predicted states, and blocks
edited by anchor replacement (Appendix F.3).

Let $`o^{\star}=(k^{\star},a^{\star})`$ be the realized outcome of the
block, where $`k^{\star}`$ is the number of accepted draft tokens and
$`a^{\star}`$ is the committed bonus token. Let $`P(k,a)`$ be the score
of Section 4.2 computed from the draft $`d_{1:\gamma}`$ of the block, by
Eq. 6 for $`k<\gamma`$ and by
$`P(\gamma,a)=P(\gamma)\,\hat{p}(a\mid\gamma)`$ for $`k=\gamma`$.

###### Proposition 1 (Exact outcome distribution).

Under Assumption 1 and at any temperature,
$`\Pr[o^{\star}=(k,a)\mid x,d_{1:\gamma}]=P(k,a)`$ for every outcome
$`(k,a)`$, with $`a\neq d_{k+1}`$ when $`k<\gamma`$.

###### Proof.

Write $`p_{i}(\cdot):=p(\cdot\mid x,d_{<i})`$ for the target
distribution at draft position $`i`$, and
$`\hat{p}_{i}:=\hat{p}(d_{i}\mid i-1)`$. Because the proposal is the
point mass on $`d_{i}`$, the acceptance rule gives

```math
\Pr[\text{accept }d_{i}\mid d_{<i}\text{ accepted}]=\min\{1,p_{i}(d_{i})/1\}=p_{i}(d_{i}).
```

Each acceptance test uses a fresh draw that is independent of the draft
and of the earlier tests, so the acceptance probabilities of successive
positions multiply. Let $`k<\gamma`$, and assume first that the
rejection probability at position $`k+1`$ is positive. Given that
$`d_{1},\dots,d_{k}`$ are accepted, rejection at $`k+1`$ has probability
$`1-p_{k+1}(d_{k+1})`$, and the bonus token is drawn from the residual
$`\max\{p_{k+1}(\cdot)-\delta_{d_{k+1}}(\cdot),0\}/[1-p_{k+1}(d_{k+1})]`$,
where $`\delta_{d_{k+1}}`$ is the point mass at $`d_{k+1}`$. Thus, for
$`a\neq d_{k+1}`$,

```math
\Pr[o^{\star}=(k,a)\mid x,d_{1:\gamma}]=\Big(\prod_{i=1}^{k}p_{i}(d_{i})\Big)[1-p_{k+1}(d_{k+1})]\frac{p_{k+1}(a)}{1-p_{k+1}(d_{k+1})}=\Big(\prod_{i=1}^{k}\hat{p}_{i}\Big)\hat{p}(a\mid k).
```

The last equality applies condition (iv) of Assumption 1 to each factor.
If instead $`p_{k+1}(d_{k+1})=1`$, then $`p_{k+1}(a)=0`$ for every
$`a\neq d_{k+1}`$, and both sides vanish. For $`k=\gamma`$, every draft
token is accepted and the bonus token is drawn from
$`p_{\gamma+1}(\cdot)`$, so

```math
\Pr[o^{\star}=(\gamma,a)\mid x,d_{1:\gamma}]=\Big(\prod_{i=1}^{\gamma}\hat{p}_{i}\Big)\hat{p}(a\mid\gamma).
```

Both expressions equal $`P(k,a)`$ of Section 4.2. ∎

### F.2 Per-Round Selection and the Geometric Fan-Out of SSD

Section 4.2 contrasts the per-round selection of Eq. 7 with the fixed
geometric fan-out of SSD (Kumar et al., 2026), and Proposition 2 states
the two facts behind this contrast. Under SSD’s assumptions, a
continuous surrogate of Eq. 7 recovers SSD’s geometric series on the
lengths that the surrogate’s maximizer keeps (part (a)). Selection by
each round’s posterior is at least as good as any fixed allocation in
every round (part (b)). Table 11 is the measured counterpart of part
(b).

SSD caches $`F_{k}`$ anchors for each accepted length $`k`$ (its
Definition 10). It keeps two fixed allocations and uses one of them in
each round. The choice depends on whether the block under verification
came from the speculation cache or from SSD’s fallback after a cache
miss, so it is whether the previous round hit the cache.

We model the accepted length $`k`$ in terms of the acceptance rate
$`\alpha`$ of the draft model. We write the resulting law of $`k`$ over
rounds as $`P_{\alpha}(k)`$, to keep it apart from the per-round score
$`P(k)`$ of Eq. 6.

###### Assumption 2 (Constant acceptance rate and power-law hit rate).

The draft model has constant acceptance rate $`\alpha\in(0,1)`$. Over
rounds, each draft token is accepted with probability $`\alpha`$,
independently given the acceptance of the tokens before it, so the
realized accepted length $`k`$ has the law

```math
P_{\alpha}(k)=\begin{cases}\alpha^{k}(1-\alpha),&k<\gamma,\\
\alpha^{\gamma},&k=\gamma.\end{cases}
```

For the surrogate problem of part (a) only, the hit mass captured by
$`F`$ anchors at length $`k`$, conditional on $`k`$, is modeled by the
surrogate curve $`1-F^{-\rho}`$ for real $`F\geq 1`$ and some
$`\rho>0`$.

###### Remark 1 (Source of the assumption).

The acceptance law is the model of SSD’s Theorem 12, and the curve is
the per-length form of SSD’s power-law hit rate (its Definition 11).

For part (a), we follow SSD and replace Eq. 7 by a continuous allocation
over lengths with the surrogate curve of Assumption 2. The curve is zero
at $`F=1`$, so a single anchor at length $`k`$ captures no hit mass in
the surrogate problem. The surrogate problem maximizes
$`\sum_{k}P_{\alpha}(k)\,(1-F_{k}^{-\rho})`$ over
$`F_{k}\in\{0\}\cup[1,\infty)`$ subject to $`\sum_{k}F_{k}\leq B`$,
where $`B>1`$ is the cache size of Eq. 7 and the hit mass at length
$`k`$ is $`0`$ when $`F_{k}=0`$. A length $`k`$ is active when
$`F_{k}\geq 1`$.

For part (b), let $`I_{t}`$ be the information that the selection
observes in round $`t`$, such as the outputs of the decoder and the
draft model and whether the previous round hit the cache. For an outcome
$`o=(k,a)`$ and the realized outcome $`o^{\star}`$, let

```math
\pi_{t}(o):=\Pr[o^{\star}=o\mid I_{t}],\qquad\pi_{t}(S):=\sum_{o\in S}\pi_{t}(o)\quad\text{for a cache }S.
```

We call $`\pi_{t}`$ the posterior of round $`t`$. Let $`a_{k,s}`$ denote
the anchor at length $`k`$ with the $`s`$-th largest value of
$`\pi_{t}(k,\cdot)`$, with ties broken by a fixed order on tokens. A
fixed allocation $`\{F_{k}\}`$ caches
$`(k,a_{k,1}),\dots,(k,a_{k,F_{k}})`$ at each length $`k`$. Order the
outcomes by decreasing $`\pi_{t}`$, with ties broken by smaller $`s`$,
then by smaller $`k`$. Let $`S_{t}^{\star}`$ be the set of the first
$`B`$ outcomes in this order. This set is a solution of Eq. 7 with $`P`$
replaced by $`\pi_{t}`$.

Suppose that $`I_{t}`$ contains the verified context $`x`$ and the draft
$`d_{1:\gamma}`$, that the target’s draws in round $`t`$ are independent
of $`I_{t}`$, and that the decoder is perfect (Assumption 1). Then
Proposition 1 gives $`\pi_{t}(k,a)=P(k,a)`$, so $`S_{t}^{\star}`$ is a
solution of Eq. 7 itself. With an imperfect decoder, Remark 3 bounds the
loss of the cache of Eq. 7.

###### Proposition 2 (Adaptive selection and the geometric fan-out).

1.  (a)
    Under Assumption 2, every active length $`k`$ at any maximizer of
    the surrogate problem receives

    ```math
    F_{k}=C\alpha^{k/(1+\rho)}\quad(k<\gamma),\qquad F_{\gamma}=C\alpha^{\gamma/(1+\rho)}(1-\alpha)^{-1/(1+\rho)}.
    ```

    Here $`C>0`$ is the constant that makes the active $`F_{k}`$ sum to
    $`B`$, and $`C=F_{0}`$ when $`\gamma\geq 1`$ and length $`0`$ is
    active.

2.  (b)
    In every round and for every cache $`S_{t}`$ chosen from $`I_{t}`$
    with $`|S_{t}|\leq B`$, including a fixed allocation $`\{F_{k}\}`$
    with $`\sum_{k}F_{k}\leq B`$ and a pair of fixed allocations chosen
    by whether the previous round hit the cache,

    ```math
    \pi_{t}(S_{t}^{\star})\geq\pi_{t}(S_{t}).
    ```

    If $`\pi_{t}(k,a_{k,s})`$ is the same in every round, then
    $`S_{t}^{\star}`$ selects the same ranks $`(k,s)`$ in every round.
    It is therefore one fixed allocation, and the best fixed allocation
    ties with it.

Example. The surrogate problem of part (a) can drop a length. Take
$`\alpha=0.6`$, $`\rho=1`$, $`\gamma=4`$ and $`B=10`$. The series of
part (a) over all lengths $`0,\dots,4`$ captures hit mass $`0.535`$. The
same series, rescaled over the lengths $`\{0,1,2,4\}`$, captures
$`0.567`$ and is the maximizer.

###### Proof of (a).

We first show that a maximizer exists and that every active $`F_{k}`$
exceeds $`1`$. We then show that the active lengths have equal marginal
gains, which gives the stated series. Finally, we show that the active
lengths are a set of $`M`$ lengths of largest $`P_{\alpha}(k)`$ for some
$`M`$.

Each $`F_{k}`$ ranges over the compact set $`\{0\}\cup[1,B]`$ and the
objective is continuous, so a maximizer exists. Because
$`\alpha\in(0,1)`$, every $`P_{\alpha}(k)`$ is positive. At a maximizer
the constraint $`\sum_{k}F_{k}\leq B`$ binds, because raising an active
$`F_{k}`$, or setting one $`F_{k}=B`$ when no length is active, strictly
raises the objective. An active length with $`F_{k}=1`$ adds no hit
mass. If another length is active, moving this unit to it raises the
objective, and otherwise the binding constraint gives $`F_{k}=B>1`$.
Hence every active $`F_{k}`$ exceeds $`1`$.

The marginal gain of $`P_{\alpha}(k)(1-F_{k}^{-\rho})`$ in $`F_{k}`$ is
$`P_{\alpha}(k)\rho F_{k}^{-\rho-1}`$. If two active lengths had unequal
marginals, moving a small amount of allocation toward the larger
marginal would raise the objective. Hence the marginals of the active
lengths equal a common value $`\mu`$, which gives

```math
P_{\alpha}(k)\rho F_{k}^{-\rho-1}=\mu\quad\Longrightarrow\quad F_{k}\propto P_{\alpha}(k)^{1/(1+\rho)},
```

and substituting $`P_{\alpha}(k)`$ from Assumption 2 gives the stated
series.

An active length has $`F_{k}>1`$, so $`P_{\alpha}(k)\rho>\mu`$, and a
length with $`P_{\alpha}(k)\rho\leq\mu`$ is therefore inactive. The
converse fails: in the example above, $`P_{\alpha}(3)\rho>\mu`$ and the
maximizer still leaves length $`3`$ inactive. If $`k`$ is active, $`j`$
is inactive and $`P_{\alpha}(j)>P_{\alpha}(k)`$, then setting
$`F_{j}:=F_{k}`$ and $`F_{k}:=0`$ keeps $`\sum_{k}F_{k}`$ and raises the
objective by $`(P_{\alpha}(j)-P_{\alpha}(k))(1-F_{k}^{-\rho})>0`$. Hence
the active lengths are a set of $`M`$ lengths of largest
$`P_{\alpha}(k)`$ for some $`M`$. For each $`M\in\{1,\dots,\gamma+1\}`$,
restricting the series of part (a) to such a set gives one candidate
allocation. A maximizer is a best one among the candidates that keep
every $`F_{k}\geq 1`$. ∎

###### Proof of (b).

Each $`S_{t}=S(I_{t})`$ is feasible in Eq. 7, so
$`\pi_{t}(S_{t}^{\star})\geq\pi_{t}(S_{t})`$ pointwise, and the
inequality also holds in expectation over rounds. If
$`\pi_{t}(k,a_{k,s})`$ does not depend on $`t`$, the order that defines
$`S_{t}^{\star}`$ selects the same ranks $`(k,s)`$ in every round.
Because $`\pi_{t}(k,a_{k,s})`$ is nonincreasing in $`s`$ and ties prefer
smaller $`s`$, the selected ranks at length $`k`$ are the top $`F_{k}`$
ranks, which form a fixed allocation. ∎

###### Remark 2 (Relation of the proposition to SSD).

The allocation of part (a) is the geometric series of SSD restricted to
the active lengths, and it equals the fan-out of SSD’s Theorem 12 when
every length $`k=0,\dots,\gamma`$ is active. SSD derives the
equal-marginal condition of part (a) in its Theorem 18, but its
statement has no inactive lengths. SSD fills each length with the top
anchors of the draft model’s logits. The resulting cache is chosen from
$`I_{t}`$, so part (b) covers it. This cache can fall strictly below
$`S_{t}^{\star}`$.

###### Remark 3 (Estimated scores).

In serving, the draft process ranks outcomes by an estimate
$`\hat{\pi}_{t}`$ of $`\pi_{t}`$. For any cache $`\hat{S}_{t}`$ of at
most $`B`$ outcomes, let

```math
\nu_{t}:=\max_{|S|\leq B}\big|\pi_{t}(S)-\hat{\pi}_{t}(S)\big|,\qquad\zeta_{t}:=\max_{|S|\leq B}\hat{\pi}_{t}(S)-\hat{\pi}_{t}(\hat{S}_{t}).
```

Then
$`\pi_{t}(S_{t}^{\star})-\pi_{t}(\hat{S}_{t})\leq 2\nu_{t}+\zeta_{t}`$
in every round. The bound holds because $`\nu_{t}`$ bounds the
estimation error at both $`S_{t}^{\star}`$ and $`\hat{S}_{t}`$, and
$`\zeta_{t}`$ bounds the estimated gap between $`S_{t}^{\star}`$ and
$`\hat{S}_{t}`$.

### F.3 Lossless Verification

This subsection shows why the output stays lossless for every draft,
including one that anchor replacement rewrites.

JetSpec++ determines every draft token before verification. Each token
is an argmax of the draft model, from the initial draft $`J_{0}`$ (also
the fallback block of a miss) or a pass of Eq. 8, or it is the decoder’s
token that anchor replacement writes. The noise tokens that $`J_{0}`$
reads are drawn independently of the target’s draws in the round that
verifies the block.

Given the draft, the proposal at position $`i`$ is the point mass
$`q_{i}=\delta_{d_{i}}`$. Let $`p_{i}=p(\cdot\mid x,d_{<i})`$ be the
target’s distribution at the sampling temperature. With this proposal,
the acceptance rule of Section 3 accepts $`d_{i}`$ with probability
$`p_{i}(d_{i})`$. On a rejection, the rule samples from $`p_{i}`$ with
$`d_{i}`$ removed and renormalized. When $`p_{i}(d_{i})=1`$, a rejection
has probability $`0`$ and the rule never uses this residual. This rule
is equivalent to drawing $`v\sim p_{i}`$, accepting $`d_{i}`$ if and
only if $`v=d_{i}`$, and committing $`v`$ otherwise. DARTree (Li et al., 2026) describes this exact-match verification for DFlash (Chen et al.,
2026). Every committed token is thus the target’s own draw, at any
temperature and whichever model produced the draft token.

Using the draft model’s softmax as $`q`$ for an argmax token would break
this guarantee, because the token is not drawn from that softmax. For
example, if the softmax puts $`0.9`$ on $`d_{i}`$ and the target puts
$`0.6`$ on it, the rule with that $`q`$ commits $`d_{i}`$ with
probability $`2/3`$ instead of $`0.6`$.
