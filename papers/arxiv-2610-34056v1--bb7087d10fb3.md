# INTRA: Interleaved Non-contiguous Token spaRse Attention

Yuxuan Xia    Wenbo Lu    Shaoyi Zheng    Shengjie Wang Affiliation: New
York University

###### Abstract

Transformers achieve strong performance across modalities but are
bottlenecked by the quadratic cost of attention. Sparse attention can
reduce this cost, but effective sparsity must preserve useful long-range
communication and map well to GPU hardware. We introduce
INTRA–Interleaved Non-contiguous Token spaRse Attention–a hardware-aware
static sparse attention design based on a relay-communication view under
Computational Query Set (CQS) constraints. Rather than directly covering
all token-to-token interactions within each sparse layer, INTRA uses
complementary sparse groups to provide short mediated communication
paths across layers. Scatter forms relay groups that sample broadly
across local neighborhoods, while Gather reconnects these groups in
subsequent layers. Under a partition model, this structure guides
CQS-compatible sparse patterns with global reachability. Our CQS-aware
FlashAttention-style kernel computes structured indices at runtime,
loads selected non-contiguous tokens, and packs them densely for
computation. On an A100, INTRA achieves a $`1.53\times`$ speedup in
$`2\mathrm{K}`$ FLUX.1-dev generation, with better measured image
quality than evaluated CLEAR configurations after LoRA
self-distillation. On LLaMA-3.1-8B, it improves long-context prefill
efficiency with strong teacher-forced retrieval performance under
matched LoRA adaptation. Attention-only benchmarks further show up to
$`8.4\times`$ and $`10.4\times`$ speedups over MoBA and
density-constrained NSA, respectively.

## 1 Introduction

Transformers excel across domains such as NLP and image generation, but
their attention cost scales quadratically with sequence length, creating
a bottleneck for long contexts and high-resolution generation. For
instance, FLUX.1-dev ([Black Forest Labs, 2024](#bib.bib2)) requires
nearly a minute to produce a 2048$`\times`$2048 image on a single A100,
precluding real-time generation.

Sparse attention reduces full-attention overhead ([Liu et al.,
2025](#bib.bib22); [Jiang et al., 2024](#bib.bib16)). We distinguish
input-dependent (dynamic) from input-independent (static) connectivity
separately from whether a method requires training or adaptation. INTRA
uses static connectivity to avoid runtime pattern selection and
evaluates adaptation of pretrained models to GPU-friendly sparse
patterns.

Sparsity changes communication as well as FLOPs. Many modalities have
coherent local neighborhoods, such as image patches, spatial regions, or
short contiguous token segments. Local attention can mix nearby
information within these neighborhoods; the remaining challenge is
communication between neighborhoods under hardware constraints. A
partition-based sparse layer permits interactions only within groups.
Covering all dense edges would require many such layers, motivating
relay paths that connect neighborhoods through successive groups.

Efficient execution constrains this design space. CLEAR ([Liu et al.,
2025](#bib.bib22)) uses circular local sparsity, and NATTEN ([Hassani
et al., 2023](#bib.bib9)) uses sliding windows. Fine-grained masks can
leave partially used computational blocks
(Figure [2](#S1.F2 "Figure 2 ‣ 1 Introduction ‣ INTRA: Interleaved Non-contiguous Token spaRse Attention")).
Computing whole blocks before masking unused scores diminishes realized
speedups relative to nominal FLOP reductions. We formalize a
hardware-oriented design class through Computational Query Sets (CQSs):
query groups with structured key sets and local-to-global index mappings
aligned with FlashAttention-style query blocks.

Figure 1: The figure reports the relative speedup achieved by INTRA
compared to CLEAR and FlashAttention 2 on 4K and 16K input lengths,
evaluated on an A100 GPU. Note that the axis density differs between the
left and right sides of the figure to accommodate varying inference
times.

INTRA combines two CQS-compatible patterns. Under equal-size partitions,
Scatter groups same-position tokens across neighborhoods, giving each
group one representative per neighborhood. Gather reconnects these
channels. If every Scatter group intersects every Gather group, two
layers permit graph-theoretic reachability between any source and
target. This motivates complementary patterns for efficient sparse
communication.

Our contribution is the joint study of structured static attention, GPU
execution, and pretrained-model adaptation. Building on factorized and
local–global attention ([Child et al., 2019](#bib.bib5); [Tu et al.,
2022](#bib.bib33)), we (1) formulate coverage and overlap objectives
within the Intra Sparse Pattern Design (ISPD) Principle and its CQS
constraints; (2) implement selected Scatter/Gather patterns using
runtime indexing, dense shared-memory packing, and scatter-back; and (3)
evaluate their quality–latency trade-offs after adaptation.

## 2 Related Works

### 2.1 Static Sparse Attention

Static sparse attention uses fixed, input-independent patterns. Sparse
Transformer ([Child et al., 2019](#bib.bib5)) combines local and strided
factorizations with short communication paths and interleaves patterns
across layers. MaxViT ([Tu et al., 2022](#bib.bib33)) combines block and
grid attention for local and distributed global interactions. These are
close precedents for Scatter/Gather. Sliding-window methods ([Jiang
et al., 2023](#bib.bib15); [Hassani et al., 2023](#bib.bib9); [Liu
et al., 2025](#bib.bib22)), Longformer, and BigBird ([Beltagy et al.,
2020](#bib.bib1); [Zaheer et al., 2020](#bib.bib39)) provide other
local/global constructions. INTRA focuses on CQS-compatible indexing,
dense-tile execution, and adaptation of complementary patterns in
pretrained models.

### 2.2 Dynamic Sparse Attention

Dynamic sparse methods adapt connectivity to the input or model state.
MInference ([Jiang et al., 2024](#bib.bib16)), FlexPrefill ([Lai et al.,
2025](#bib.bib20)), and XAttention ([Xu et al., 2025](#bib.bib36))
select heads, blocks, or patterns at runtime. NSA, MoBA, and H2O ([Yuan
et al., 2025](#bib.bib38); [Lu et al., 2025a](#bib.bib24); [Zhang
et al., 2023](#bib.bib42)) also use input-dependent selection or
routing, with different training requirements. INTRA evaluates adapted
static patterns that avoid runtime selection and target simpler GPU
kernels.

### 2.3 Other Image Acceleration Methods

Token pruning and merging methods reduce the effective sequence length
for vision transformers by removing or combining tokens ([Rao et al.,
2021](#bib.bib28); [Kong et al., 2022](#bib.bib18); [Bolya et al.,
2023](#bib.bib3); [Lu et al., 2025b](#bib.bib25)). These methods are
orthogonal to INTRA, which keeps the token set but changes the sparse
communication pattern and kernel implementation.

### 2.4 Sparse Video Generation

Sparse video methods reduce spatiotemporal attention through
hardware-aware regions, shifted windows, or spatial/temporal head
specialization ([Zhang et al., 2025](#bib.bib40); [Liu et al.,
2022](#bib.bib23); [Xi et al., 2025](#bib.bib34)). INTRA formulates a
CQS-compatible communication principle applicable across architectures.
Our image and language workloads cover high-resolution generation and
long-context prefill; the 16K-token setting is also comparable to
smaller video models, such as Wan 1.3B at 480p ([Team Wan et al.,
2025](#bib.bib32)). We additionally evaluate video transfer on
Wan2.2-TI2V-5B
(Appendix [G.8](#A7.SS8 "G.8 Video Generation Results ‣ Appendix G Additional Experiments and Ablations ‣ INTRA: Interleaved Non-contiguous Token spaRse Attention")).

## 3 Hardware-Efficient Sparse Communication

### 3.1 Computational Query Sets and ISPD Constraints

We study a class of sparse attention patterns compatible with
FlashAttention-style execution. A Computational Query Set (CQS) is a
group of query tokens evaluated together, with structured
local-to-global mappings for selecting the corresponding key/value
tokens. A CQS may use query-dependent key indices, as long as they are
generated by structured mappings that can be evaluated uniformly for the
group. We call a sparse pattern ISPD-compatible if it satisfies:

1.  1.  Coverage: The union of all CQSs covers the query-token set. A query
        token may belong to more than one CQS.
2.  2.  Index Mapping: There exist structured functions $`f_{q}`$ and
        $`f_{k}`$ such that, for a given CQS index $`i^{\text{cqs}}`$,

    |     |     |     |     |
    | --- | --- | --- | --- |
    |     |

    ````math
    i^{q}_{g}=f_{q}(i^{q}_{l},i^{\text{cqs}}),\quad i^{k}_{g}=f_{k}(i^{k}_{l},i^{q}_{l},i^{\text{cqs}}).
    ``` |  | (1) |
    ````

3.  3.  Block Alignment: Each CQS contains a number of queries approximately
        divisible by the query block size $`B`$; we use $`B=64`$ for
        FlashAttention-style kernels.

The “approximately” qualifier only accounts for a final partial block
when the sequence length is not divisible by $`B`$. Within this design
class, intra-CQS computation avoids cross-thread-group synchronization:
queries from the same CQS can be grouped, and the required
non-contiguous K/V tokens can be packed contiguously for
FlashAttention-style computation. Our Scatter and Gather patterns
satisfy these constraints; their explicit $`f_{q}`$ and $`f_{k}`$
mappings are in
Appendix [C](#A3 "Appendix C Sparse Pattern Index Function ‣ INTRA: Interleaved Non-contiguous Token spaRse Attention").

### 3.2 Sparse Attention as Communication

We model a sparse attention layer as a directed information-flow graph
over tokens:

|     |     |     |
| --- | --- | --- |
|     |

````math
G^{(l)}=(V,E^{(l)}),\qquad(j,i)\in E^{(l)}\Longleftrightarrow\text{query token }i\text{ attends to key token }j.
``` |  |

A path follows the direction in which token information can be used by
later queries. A *partition-based* sparse layer divides tokens into
groups and computes attention within each group. We use this abstraction
to reason about Scatter/Gather communication paths. We assume tokens are
partitioned into local neighborhoods

|  |  |  |
|----|----|----|
|  |
``` math
\mathcal{P}=\{P_{1},\ldots,P_{T}\},\qquad P_{t}\cap P_{t^{\prime}}=\varnothing\;(t\neq t^{\prime}),\qquad\bigcup_{t=1}^{T}P_{t}=V.
``` |  |

Here $`P_{t}`$ may be an image patch, spatial neighborhood, or short
text segment. Our modeling premise is that local attention already
provides useful intra-neighborhood mixing; the sparse-design problem is
communication between neighborhoods while staying inside the
ISPD-compatible design class. We call the sparse groups used to move
information between neighborhoods *relay groups*.

## 4 Scatter-Gather Relay Design

### 4.1 Static Sparse Attention Under Unknown Long-Range Demand

Dynamic sparse attention can select important keys after observing the
input or attention scores. This adaptivity incurs runtime
pattern-selection costs and can introduce irregular memory access. INTRA
instead fixes connectivity in advance, enabling simple local-to-global
index mappings and structured token loading. A static pattern cannot
know which long-range token pairs matter for a given input, head, or
layer. It should therefore allocate communication opportunities across
possible long-range interactions, rather than specialize to a single
assumed attention pattern. We express this goal through a worst-case
neighborhood-coverage objective.

### 4.2 From Direct Edges to Relay Paths

A sparse layer with per-query budget $`g`$ can preserve at most $`ng`$
directed token-token interactions, while dense attention contains
$`n^{2}`$ possible interactions. When $`g\ll n`$, a static sparse mask
cannot directly preserve all potentially important dense edges.

Two sparse layers can provide a mediated path for a missing direct
interaction through a relay token:

|     |                              |     |
|-----|------------------------------|-----|
|     |
       ``` math
       j\rightarrow r\rightarrow i.
       ```                           |     |

Our analysis counts the relay opportunities connecting source and target
neighborhoods.

This observation guides INTRA: the sparse pattern should provide broad
and balanced relay opportunities while remaining compatible with
efficient CQS execution.

### 4.3 Locality as a Design Motivation

Nearby image patches often share visual structure, while short text
segments provide coherent local context. This motivates separating two
roles: local attention mixes nearby tokens, and non-local groups provide
paths between neighborhoods. When an interaction involves distant
neighborhoods, their local representatives are plausible relay carriers.
The combinatorial objective formalizes this intuition by balancing
coverage across neighborhood pairs.

### 4.4 Why Scatter Is Uniform and Non-Contiguous

Let $`N=TR`$ tokens be divided into $`T\geq 2`$ local neighborhoods,
with integer $`R\geq 1`$:

|     |                                     |     |
|-----|-------------------------------------|-----|
|     |
       ``` math
       P_{1},\ldots,P_{T},\qquad|P_{t}|=R.
       ```                                  |     |

A group of $`T`$ tokens covers all $`T`$ neighborhoods only by taking
one representative from each; repeated samples from one neighborhood
leave another uncovered.

Scatter avoids this failure mode. Writing tokens as $`(t,r)`$, where
$`t`$ is the neighborhood index and $`r`$ is the local index, Scatter
forms

|     |                                                   |     |
|-----|---------------------------------------------------|-----|
|     |
       ``` math
       S_{r}=\{(t,r):t=1,\ldots,T\},\qquad r=1,\ldots,R.
       ```                                                |     |

Each Scatter group contains one token from every local neighborhood.
Thus, every group is a global low-resolution view of the sequence or
image.

Sampling distant neighborhoods makes Scatter non-contiguous. The $`R`$
groups of size $`T`$ compute $`RT^{2}=N^{2}/R`$ attention pairs,
retaining a $`1/R`$ fraction of dense pairs. At fixed $`R`$, the
complexity is $`O(N^{2})`$. Gather 0, the image variant using
$`16\times 16`$ local neighborhoods, instead uses $`O(Nw)`$ pairs for a
fixed window of $`w`$ keys per query.

### 4.5 Why Gather Is Needed

Scatter provides global relay groups but separates communication by
local index. Tokens in $`S_{r}`$ can exchange information across
neighborhoods with other tokens in $`S_{r}`$, while different channels
$`S_{r}`$ and $`S_{r^{\prime}}`$ remain disconnected. This matters
because useful source-side and target-side representatives need not
share the same local index: broad coverage within a channel alone cannot
connect every source–target pair.

Gather is introduced to reconnect these Scatter channels. Let

|     |                                 |     |
|-----|---------------------------------|-----|
|     |
       ``` math
       \mathcal{G}=\{G_{b}\}_{b=1}^{R}
       ```                              |     |

be the second partition, and define the Scatter-to-Gather overlap

|     |                           |     |
|-----|---------------------------|-----|
|     |
       ``` math
       X_{rb}=|S_{r}\cap G_{b}|.
       ```                        |     |

If $`X_{rb}=0`$, then Scatter channel $`S_{r}`$ has no relay witness
into Gather group $`G_{b}`$. A good Gather pattern should therefore make
these overlaps as balanced as possible, avoiding weak or missing channel
connections.

A simple balanced construction is cyclic:

|     |                                      |     |
|-----|--------------------------------------|-----|
|     |
       ``` math
       G_{b}=\{(t,r):b\equiv t+r\pmod{R}\}.
       ```                                   |     |

Its minimum overlap is $`\lfloor T/R\rfloor`$. Thus every Scatter group
intersects every Gather group, enabling universal two-layer reachability
in this abstract construction, only when $`T\geq R`$.

### 4.6 Design Summary

Within equal-size partitions, uniform Scatter maximizes minimum
neighborhood-pair coverage, and balanced Gather maximizes minimum
inter-partition overlap. These objectives motivate complementary
patterns under a static communication budget.

Thus INTRA implements the following communication structure:

|  |  |  |
|----|----|----|
|  |
``` math
\text{local mixing}\;\rightarrow\;\text{uniform non-contiguous relay}\;\rightarrow\;\text{balanced relay reconnection}.
``` |  |

Appendix [D](#A4 "Appendix D Formal Relay Analysis for Static CQS Design ‣ INTRA: Interleaved Non-contiguous Token spaRse Attention")
proves the coverage and overlap results for the partition model. We next
describe its image and language instantiations.

## 5 CQS-Aware Token-Sparse FlashAttention Kernel

For token-level Scatter/Gather patterns, INTRA implements a CQS-aware
variant of FlashAttention ([Dao, 2024](#bib.bib6)). Each CQS is
scheduled in query blocks of 64 tokens. Structured mappings $`f_{q}`$
and $`f_{k}`$ compute global positions at runtime; the kernel loads the
selected Q, K, and V tokens, packs them into dense shared-memory tiles,
and applies the FlashAttention-style online-softmax core. Outputs are
scattered back using the query mapping. This avoids computing and
masking unused scores in mixed blocks. Masking within the packed tiles
supports full and causal attention.

Scatter and Gather 0 use strided cross-neighborhood access and
two-dimensional local offsets, respectively. Gather 1 is the
repeated-segment token grouping illustrated in
Appendix [A](#A1 "Appendix A Token-Level Scatter and Gather 1 Patterns ‣ INTRA: Interleaved Non-contiguous Token spaRse Attention");
all three share the kernel with different index mappings and underlie
the token-level benchmarks. Language retrieval uses the block-level
extension in
Section [4.7](#S4.SS7 "4.7 Mapping Back to INTRA ‣ 4 Scatter-Gather Relay Design ‣ INTRA: Interleaved Non-contiguous Token spaRse Attention"),
with selected 256-token blocks in global layers and sliding windows with
sinks elsewhere.
Appendix [E](#A5 "Appendix E Overhead Analysis ‣ INTRA: Interleaved Non-contiguous Token spaRse Attention")
profiles the token-level kernels’ indexing, memory traffic, and
computation.

## 6 Evaluation

We evaluate whether the CQS-compatible relay design is practical in both
the FLUX.1-dev ([Black Forest Labs, 2024](#bib.bib2)) image generation
model and the LLaMA 3 ([Dubey et al., 2024](#bib.bib8)) language model.
INTRA changes how the model exchanges information between tokens,
requiring adaptation; LoRA ([Hu et al., 2022](#bib.bib12)) suffices in
our evaluated settings.

### 6.1 Experiments

Baseline    INTRA provides broad communication through fixed sparse
patterns. For image generation, we compare with CLEAR, an adapted static
sparse-attention method, to evaluate pattern design and execution in the
same pretrained-model setting.

For text generation, we compare with MInference ([Jiang et al.,
2024](#bib.bib16)) and XAttn ([Xu et al., 2025](#bib.bib36)) on the
long-context SCROLLS benchmark ([Shaham et al., 2022](#bib.bib30)).

Experiment Setup    We fine-tune FLUX.1-dev using CLEAR’s 10K
self-generated image-text dataset. Following CLEAR, we sample 5k
COCO ([Lin et al., 2014](#bib.bib21)) validation prompts and evaluate
generated images using FID ([Heusel et al., 2017](#bib.bib10); [Seitzer,
2020](#bib.bib29)), LPIPS ([Zhang et al., 2018](#bib.bib41)), and
CLIPI ([Radford et al., 2021](#bib.bib27)). For LLaMA 3, we fine-tune
and evaluate on SCROLLS ([Shaham et al., 2022](#bib.bib30)), covering
GovReport ([Huang et al., 2021](#bib.bib13)), Qasper ([Dasigi et al.,
2021](#bib.bib7)), QMSum ([Zhong et al., 2021](#bib.bib43)),
QuALITY ([Pang et al., 2022](#bib.bib26)), SummScreen-FD ([Chen et al.,
2022](#bib.bib4)), and ContractNLI ([Koreeda & Manning,
2021](#bib.bib19)). These tasks fit our 16K-token fine-tuning budget and
provide reliable validation sets.

Resource Usage and Practicality    All fine-tuning and evaluation use
NVIDIA A100 GPUs. FLUX.1-dev fine-tuning takes 43 GPU hours. The matched
language retrieval protocol uses rank-16 LoRA and takes about one hour
on eight GPUs per run (approximately 8 GPU hours).

### 6.3 Limitations

Our partition analysis optimizes coverage and overlap, not attention
approximation or downstream quality. The deployed geometric and causal
masks impose additional constraints; causal connectivity is restricted
to preceding tokens. Comparisons with other factorized patterns and
larger models remain future work.

Quality is task-dependent: INTRA trails both SCROLLS baselines on five
of six tasks. Relative to adapted dense attention, GovReport falls from
31.05 to 27.77, while Qasper changes from 40.09 to 39.64
(Table [14](#A7.T14 "Table 14 ‣ SCROLLS fine-tuning. ‣ G.2 Language Adaptation Protocols ‣ Appendix G Additional Experiments and Ablations ‣ INTRA: Interleaved Non-contiguous Token spaRse Attention")).
Image comparisons do not establish dense-quality parity. Wan’s aesthetic
and imaging scores decrease by 0.0194 and 0.0564; shared zeros remain
unexplained. Video quality is evaluated only at 49 frames.

Retrieval measures teacher-forced exact match after shared-budget
adaptation, rather than free-generation or zero-shot performance or
general rankings of MoBA/NSA. Layer ablations compare quality and
density, not matched FLOPs; configuration sweeps vary both density and
layer allocation. The SD 1.5 comparison also differs in architecture and
training data. Quality scores lack confidence intervals; timing
repetitions do not measure quality uncertainty.

Runtime indexing and non-contiguous loads add overhead; unchanged
components limit end-to-end gains
(Appendix [E](#A5 "Appendix E Overhead Analysis ‣ INTRA: Interleaved Non-contiguous Token spaRse Attention")).
Token kernels and block-sparse retrieval use distinct configurations.
MoBA/NSA timing comparisons cover attention only, not full-model
prefill. Reshaping changes scheduling and occupancy, preventing isolated
overhead measurement.

## 7 Conclusion

We introduced INTRA as a sparse communication design under ISPD/CQS
constraints. In a partition-based relay model, Scatter gives max-min
local-neighborhood coverage and Gather gives balanced two-layer
reconnection. Together, they provide a communication criterion for
complementary static patterns.

The CQS-aware kernel turns these patterns into dense-tile GPU
computation through runtime indexing and non-contiguous token packing.
After adaptation, INTRA delivers $`1.53\times`$ faster 2K FLUX.1-dev
generation and better measured image metrics than evaluated CLEAR
configurations. Language experiments demonstrate faster prefill and
effective long-range retrieval with a small allocation of global sparse
layers, supporting structured static attention as a practical
acceleration strategy.

## Appendix B GPU Memory Hierarchy

NVIDIA GPUs use a memory hierarchy consisting primarily of global
memory, shared memory, and registers. Global memory is large but
high-latency; shared memory is faster and shared within a thread block;
registers are fastest and private to individual threads. INTRA changes
which global-memory tokens are loaded, then packs the selected tokens
contiguously in shared memory before applying FlashAttention-style
computation.

## Appendix C Sparse Pattern Index Function

### C.1 Scatter

For the LLM Scatter pattern with query block size 64 and 8 groups, let
$`i^{\text{cqs}}`$ be the CQS index. The local-to-global mappings are

|  |  |  |  |
|----|----|----|----|
|  |
``` math
f_{q}(i^{q}_{l},i^{\text{cqs}})=i^{\text{cqs}}+8\cdot i^{q}_{l},
``` |  | (2) |

|  |  |  |  |
|----|----|----|----|
|  |
``` math
f_{k}(i^{k}_{l},i^{q}_{l},i^{\text{cqs}})=i^{\text{cqs}}+8\cdot i^{k}_{l}.
``` |  | (3) |

### C.2 Gather 0

Assume an image feature map with width $`W`$ and height $`H`$, both at
least 16 and divisible by 8. Each CQS is an $`8\times 8`$ query patch
attending to a $`16\times 16`$ image-key window. We use zero-based,
row-major indexing within the image. For CQS index $`i^{\text{cqs}}`$,
let $`r=\lfloor i^{\text{cqs}}/(W/8)\rfloor`$ and
$`c=i^{\text{cqs}}\bmod(W/8)`$. For $`0\leq i_{l}^{q}<64`$,

|  |  |  |  |
|----|----|----|----|
|  |
``` math
f_{q}(i^{q}_{l},i^{\text{cqs}})=\left(8r+\left\lfloor i_{l}^{q}/8\right\rfloor\right)W+8c+(i_{l}^{q}\bmod 8).
``` |  | (4) |

The window is shifted inward at image boundaries. Its top-left row and
column are

|  |  |  |  |
|----|----|----|----|
|  |
``` math
r_{0}=\min\!\bigl(\max(8r-4,0),H-16\bigr),\qquad c_{0}=\min\!\bigl(\max(8c-4,0),W-16\bigr).
``` |  | (5) |

All queries in the CQS share the same image-key mapping, with
$`0\leq i_{l}^{k}<256`$:

|  |  |  |  |
|----|----|----|----|
|  |
``` math
f_{k}(i_{l}^{k},i_{l}^{q},i^{\text{cqs}})=\left(r_{0}+\left\lfloor i_{l}^{k}/16\right\rfloor\right)W+c_{0}+(i_{l}^{k}\bmod 16).
``` |  | (6) |

The kernel packs the window into four 64-key tiles ($`i_{l}^{k}=64t+j`$,
$`0\leq t<4`$, $`0\leq j<64`$), each covering four rows of 16 keys. Thus
every image index lies in $`[0,HW)`$, including at corners. In the
released FLUX implementation, $`H=W\in\{64,128\}`$ and 512 text tokens
precede the image tokens, so these image indices receive an offset of
512. Every query also attends to all text keys; text queries retain
their Scatter image-key groups.

## Appendix D Formal Relay Analysis for Static CQS Design

This appendix formalizes the relay-design intuition used in
Section [4](#S4 "4 Scatter-Gather Relay Design ‣ INTRA: Interleaved Non-contiguous Token spaRse Attention").
The mask-level analysis establishes uniform Scatter and balanced Gather
as minimax allocations for neighborhood coverage and inter-partition
overlap under CQS-style partition constraints.

### D.1 Setup

Let $`T\geq 2`$ and $`R\geq 1`$ be integers. Partition $`N=TR`$ tokens
into $`T`$ local neighborhoods:

|     |                                     |     |
|-----|-------------------------------------|-----|
|     |
       ``` math
       P_{1},\ldots,P_{T},\qquad|P_{t}|=R.
       ```                                  |     |

We consider static partition-based CQS groups. Scatter consists of $`R`$
relay groups

|     |                                                  |     |
|-----|--------------------------------------------------|-----|
|     |
       ``` math
       \mathcal{S}=\{S_{a}\}_{a=1}^{R},\qquad|S_{a}|=T,
       ```                                               |     |

which partition the token set. Define

|     |                            |     |
|-----|----------------------------|-----|
|     |
       ``` math
       c_{a,t}=|S_{a}\cap P_{t}|.
       ```                         |     |

The proof uses token counts and intersections of fixed sets. The local
neighborhoods specify the partition over which coverage is evaluated.

### D.2 Uniform Scatter as Minimax Neighborhood-Pair Coverage

For a pair of neighborhoods $`(P_{s},P_{t})`$, define the relay
opportunity count

|     |                                       |     |
|-----|---------------------------------------|-----|
|     |
       ``` math
       K_{s,t}=\sum_{a=1}^{R}c_{a,s}c_{a,t}.
       ```                                    |     |

This counts how many ordered source-target representative pairs from
$`P_{s}`$ and $`P_{t}`$ are co-grouped in some Scatter relay group.

Let $`W_{s,t}\geq 0`$ be an arbitrary normalized long-range demand
matrix over ordered neighborhood pairs:

|     |                          |     |
|-----|--------------------------|-----|
|     |
       ``` math
       \sum_{s\neq t}W_{s,t}=1.
       ```                       |     |

Define the demand-weighted coverage of $`\mathcal{S}`$ as

|     |                                                   |     |
|-----|---------------------------------------------------|-----|
|     |
       ``` math
       \Phi(\mathcal{S};W)=\sum_{s\neq t}W_{s,t}K_{s,t}.
       ```                                                |     |

Since the static mask does not know $`W`$ in advance,

|     |                                                    |     |
|-----|----------------------------------------------------|-----|
|     |
       ``` math
       \min_{W}\Phi(\mathcal{S};W)=\min_{s\neq t}K_{s,t}.
       ```                                                 |     |

Thus robustness to arbitrary neighborhood-level demand reduces to
maximizing the weakest relay opportunity count.

#### Proposition D.1.

For any partition into $`R`$ relay groups of size $`T`$,

|     |                              |     |
|-----|------------------------------|-----|
|     |
       ``` math
       \min_{s\neq t}K_{s,t}\leq R.
       ```                           |     |

Uniform Scatter achieves equality by taking exactly one token from every
neighborhood in every relay group:

|     |                                       |     |
|-----|---------------------------------------|-----|
|     |
       ``` math
       |S_{a}\cap P_{t}|=1\qquad\forall a,t.
       ```                                    |     |

Consequently,

|     |                                                  |     |
|-----|--------------------------------------------------|-----|
|     |
       ``` math
       \max_{\mathcal{S}}\min_{W}\Phi(\mathcal{S};W)=R.
       ```                                               |     |

#### Proof.

For each relay group $`S_{a}`$,

|     |                          |     |
|-----|--------------------------|-----|
|     |
       ``` math
       \sum_{t=1}^{T}c_{a,t}=T.
       ```                       |     |

Therefore,

|  |  |  |
|----|----|----|
|  |
``` math
\sum_{s\neq t}c_{a,s}c_{a,t}=\left(\sum_{t}c_{a,t}\right)^{2}-\sum_{t}c_{a,t}^{2}\leq T^{2}-T,
``` |  |

because $`\sum_{t}c_{a,t}^{2}\geq T`$ for nonnegative integers summing
to $`T`$. Summing over all $`R`$ groups gives

|     |                                    |     |
|-----|------------------------------------|-----|
|     |
       ``` math
       \sum_{s\neq t}K_{s,t}\leq RT(T-1).
       ```                                 |     |

There are $`T(T-1)`$ ordered neighborhood pairs, so the average value of
$`K_{s,t}`$ is at most $`R`$. Hence

|     |                              |     |
|-----|------------------------------|-----|
|     |
       ``` math
       \min_{s\neq t}K_{s,t}\leq R.
       ```                           |     |

Uniform Scatter has $`c_{a,t}=1`$ for all $`a,t`$, so

|     |                                  |     |
|-----|----------------------------------|-----|
|     |
       ``` math
       K_{s,t}=\sum_{a=1}^{R}1\cdot 1=R
       ```                               |     |

for every ordered pair $`s\neq t`$, attaining the upper bound.
$`\square`$

#### Interpretation.

Any non-uniform relay group that samples one neighborhood multiple times
must under-sample another. This can improve some neighborhood pairs only
by weakening others. If long-range demand is unknown, the weakened pair
becomes the worst case. Uniform Scatter is therefore the no-prior robust
static allocation of relay opportunities.

### D.3 Balanced Gather as Minimax Channel Reconnection

Scatter creates global relay groups but separates them by local index.
Write

|     |                                                   |     |
|-----|---------------------------------------------------|-----|
|     |
       ``` math
       S_{r}=\{(t,r):t=1,\ldots,T\},\qquad r=1,\ldots,R.
       ```                                                |     |

Let Gather be another partition

|     |                                                  |     |
|-----|--------------------------------------------------|-----|
|     |
       ``` math
       \mathcal{G}=\{G_{b}\}_{b=1}^{R},\qquad|G_{b}|=T,
       ```                                               |     |

and define the overlap matrix

|     |                           |     |
|-----|---------------------------|-----|
|     |
       ``` math
       X_{rb}=|S_{r}\cap G_{b}|.
       ```                        |     |

The entry $`X_{rb}`$ counts the number of relay witnesses from Scatter
channel $`S_{r}`$ into Gather group $`G_{b}`$. If $`X_{rb}=0`$, then
that channel-to-group connection is absent.

For arbitrary reconnection demand, the weakest entry controls the worst
case. Since each Scatter group has size $`T`$,

|     |                         |     |
|-----|-------------------------|-----|
|     |
       ``` math
       \sum_{b=1}^{R}X_{rb}=T.
       ```                      |     |

Therefore,

|     |                                                         |     |
|-----|---------------------------------------------------------|-----|
|     |
       ``` math
       \min_{b}X_{rb}\leq\left\lfloor\frac{T}{R}\right\rfloor.
       ```                                                      |     |

Thus no Gather partition can make the weakest overlap larger than
$`\lfloor T/R\rfloor`$.

A cyclic Gather construction achieves this value:

|     |                                      |     |
|-----|--------------------------------------|-----|
|     |
       ``` math
       G_{b}=\{(t,r):b\equiv t+r\pmod{R}\}.
       ```                                   |     |

For fixed $`r`$ and $`b`$,

|  |  |  |
|----|----|----|
|  |
``` math
|S_{r}\cap G_{b}|=|\{t:b\equiv t+r\pmod{R}\}|\in\left\{\left\lfloor\frac{T}{R}\right\rfloor,\left\lceil\frac{T}{R}\right\rceil\right\}.
``` |  |

Thus cyclic Gather maximizes the weakest Scatter-to-Gather overlap under
the same equal-size partition constraint. Universal two-layer
connectivity additionally requires $`T\geq R`$, so that
$`\lfloor T/R\rfloor\geq 1`$. If $`T<R`$, zero overlaps remain and the
construction does not provide universal two-layer connectivity.

### D.4 Relation to Implemented Patterns

The results optimize neighborhood-pair coverage and inter-partition
overlap within equal-size partitions. Uniform Scatter distributes
representatives across neighborhoods, and cyclic Gather balances
connections between the resulting channels. These objectives guide the
implementations in
Section [4.7](#S4.SS7 "4.7 Mapping Back to INTRA ‣ 4 Scatter-Gather Relay Design ‣ INTRA: Interleaved Non-contiguous Token spaRse Attention"):
image generation combines Scatter with geometric Gather 0 neighborhoods,
while language retrieval combines causal global block attention with
local windows and sink tokens. The global-layer and image-pattern
ablations evaluate these complementary roles after adaptation.

#### Balanced Gather reconnection.

Given fixed Scatter groups and fixed Gather group sizes, the row and
column sums of $`X_{ab}`$ are fixed by the partition sizes. Maximizing
$`\min_{a,b}X_{ab}`$ therefore favors balancing the overlap matrix and
avoiding zero entries. When every entry is positive, the two-layer
reachability result applies.

#### Matched retrieval adaptation.

For the NIAH comparisons and language ablations, all methods, including
the dense control, use the same data and adaptation budget. The training
mixture contains 60% public train-split conversations in the evaluation
format, 25% synthetic retrieval examples, and 15% plain continuation.
The data are packed into 400 blocks of 16,384 tokens and are disjoint
from all evaluation documents. We train for 1,200 steps using rank-16
LoRA on the attention $`q/k/v/o`$ and MLP gate/up/down projections.
Supervision comes from each model’s own dense outputs, following
knowledge distillation ([Hinton et al., 2015](#bib.bib11)), without
ground-truth task labels. One adapter is trained per model and reused
across its evaluation tasks. For LLaMA-3.1-8B, the adapters contain
41.9M trainable parameters (approximately 0.5% of the model), and each
run takes about one hour on eight A100 GPUs, or approximately 8 GPU
hours. Qwen3-8B uses the same adaptation recipe and budget, with the
number and retained density of its global sparse layers configured as
described in the main text.

### G.6 Mask Construction and Caching

For the block-level language configuration, the block mask is
constructed once per configuration and cached for reuse. Mask
construction takes 3.4 ms at a context length of 16K. This is a one-time
mask-construction cost; repeated calls with the same cached
configuration reuse the mask.
````
