## 1 Introduction

![Refer to caption](2611.12109v1/01_coevolution_en.png)

Figure 1: From Local-guided policy learning to model–skill co-evolution.
Left: trajectory-specific Local skills supervise parameter updates

LLM agents can retain interaction experience through two routes:
training-free approaches accumulate experience as external textual
skills that guide later behavior, whereas training-based approaches
internalize it into model parameters through SFT or RL. Textual skills
can play both roles at once, serving as supervision for parameter
updates and as guidance for future tasks. Recent work extracts
retrievable, editable skills from interaction trajectories or distills
their guidance into model parameters during RL \[[1](#bib.bib1),
[2](#bib.bib2), [3](#bib.bib3)\]. Other methods consolidate lessons
across trajectories or refine skill documents using execution feedback
\[[4](#bib.bib4), [5](#bib.bib5)\].

However, a skill that provides useful supervision for the current
parameter update may not remain useful as guidance for the updated
model’s subsequent interactions. A skill may become redundant once the
model acquires the capabilities it supports. Other skills may remain
useful, but their relevance can decline as the model’s behavior changes.
Retained skills may also conflict with newly learned behavior or
existing guidance. Retained skills therefore need to be reassessed
throughout training in light of both their content and the model’s
changing capabilities. Coordinating skill selection and refinement with
parameter updates is central to skill-level recursive self-improvement
(RSI), yet the two routes are usually studied separately. Coupling them
is difficult: the model changes at every step, judging a skill’s value
through task execution is expensive, and the training objective itself
provides no criterion for deciding which skills remain worth retaining.

Two observations from our experiments motivate this need for
reassessment. On ALFWorld, guidance extracted from earlier trajectories
substantially improves task completion early in training. When the
guidance remains fixed, its gains diminish as training progresses, with
a negative mean gain in the final stage (Section 3.1). In a separate
evaluation, the same learned global skill set has different effects when
supplied to two trained models
(Section [4.6](#S4.SS6 "4.6 Global content and model compatibility ‣ 4 Experiments ‣ SkillDuet: Co-Evolving Models and Skillsthrough Response Feedback")).
These observations show that the value of retained skills depends on
both their content and their compatibility with the current model.

We introduce SkillDuet, a framework that coordinates parameter updates
and skill evolution through model response feedback
(Figure [1](#S1.F1 "Figure 1 ‣ 1 Introduction ‣ SkillDuet: Co-Evolving Models and Skillsthrough Response Feedback")).
SkillDuet couples continuous internalization with periodic
consolidation. The agent acts with guidance from its global skill set
(Global), and an external analyzer extracts local skills (Local) from
the resulting trajectories. Local skills continuously provide privileged
context for on-policy distillation (OPD), yielding token-level
supervision for parameter updates at every step. We extend response
feedback to long-term skill retention through Strength, a score that
ranks recent Local skills by the magnitude of the shift they induce in
the current model’s responses. The selected skills are periodically
consolidated with the existing Global. The updated model and Global
jointly guide subsequent interactions, shaping the experience available
for further parameter updates and skill extraction, so that
internalization and consolidation reinforce each other. This feedback
loop implements skill-level RSI through model–skill co-evolution.

We evaluate SkillDuet with Qwen3-4B on ALFWorld and WebShop, where it
achieves success rates of 98.57% and 92.97%, respectively. These results
exceed the matched SEED-API baseline by 2.86 and 5.47 percentage points.
Ablation studies demonstrate the benefits of response-based Local
selection and Global consolidation. Further comparisons identify the
best-performing Local retention ratio among those tested and show how
the content of retained skills and their compatibility with the model
affect task performance.

Our main contributions are twofold:

- •
  A framework for model–skill co-evolution. SkillDuet coordinates
  parameter updates and persistent skill updates within a single
  interaction loop. The evolving model and its skills jointly shape the
  experience used for subsequent learning.
- •
  Response-guided skill evolution. We introduce an approach to skill
  evolution that extends model response feedback from immediate
  distillation to long-term skill retention. Strength selects Local
  skills for Global consolidation based on the shift they induce in the
  current model’s responses.

## 2 Related Work

Skill construction and evolution. Execution traces reveal reusable
procedures as well as recurring mistakes. SkillRL maintains hierarchical
skill libraries alongside reinforcement learning and recursive skill
updates \[[1](#bib.bib1)\]. Trace2Skill analyzes a frozen agent’s
successful and failed trajectories in parallel, then hierarchically
consolidates the resulting edits into transferable skills
\[[4](#bib.bib4)\]. SkillOpt proposes bounded edits through minibatch
reflection, accepts them based on validation performance, and reuses
rejected edits as feedback \[[5](#bib.bib5)\]. D2Skill combines
success–failure comparisons with dynamic skill banks \[[6](#bib.bib6)\].
These methods use interaction outcomes to extract or refine external
procedural guidance.

Persistent knowledge and skill consolidation. Retaining experience
across updates requires deciding what to store and how to combine it.
WikiSkill separates raw trajectories, persistent wiki knowledge, and
executable skills. Behavioral patterns from past experience guide new
proposals, while knowledge and edit history are preserved even when a
skill update is rolled back \[[7](#bib.bib7)\]. SkillGLoW groups
experiences that share a solution procedure, compresses them into
general guidance, and evaluates the updated guidance through execution;
the agent then combines it with task-specific information
\[[2](#bib.bib2)\]. Procedural Memory Distillation combines online
reflection with batch experience and slower procedural consolidation
\[[8](#bib.bib8)\]. We build on this view of skills as persistent
procedural knowledge and study how the current policy’s responses can
guide the choice of new experience to consolidate.

Skill internalization and policy distillation. SEED extracts hindsight
skills with the policy model during RL and uses skill-conditioned
response scores for on-policy distillation \[[3](#bib.bib3)\].
OPD-Evolver organizes distillation around a multilevel experience
memory, while UCOB studies bidirectional distillation with and without
skill conditioning, together with skill-utility updates
\[[9](#bib.bib9), [10](#bib.bib10)\]. ATOD introduces annealed
turn-aware distillation for multi-turn agents \[[11](#bib.bib11)\].
These methods convert textual or teacher-provided guidance into policy
updates. SkillDuet retains this use of skills for immediate training and
also uses model response feedback to select skills for persistent reuse.

Skill management during policy adaptation. Skill0.5 distinguishes skills
used for internalization from those used during execution; SLIM uses a
skill’s contribution to execution to decide whether to retain, retire,
or expand it \[[12](#bib.bib12), [13](#bib.bib13)\]. UniSkill also
evaluates skill proposals using the current actor’s responses. It
compares candidate and retrieved skills through action log-likelihood
gaps on held-out successful and failed trajectories from the same task,
and uses the signed success–failure difference to train the proposer and
guide skill edits \[[14](#bib.bib14)\]. SkillDuet instead ranks recent
Local skills by the magnitude of the response shift they induce and
synthesizes the selected skills into Global. All eligible Local skills
remain available for OPD, independently of this selection.

SkillDuet focuses on coordinating policy optimization and persistent
skill updates as training proceeds. The current policy provides feedback
for skill selection, and the retained skills guide future interactions.
This two-way dependence allows skills to adapt as the model’s
capabilities change.

## 3 Motivation and Method

### 3.1 Motivation: skill utility changes during training

Measuring the effect of fixed skills. We train the model on ALFWorld for
150 steps using Group Relative Policy Optimization (GRPO). Before
training, we extract a set of skills from the base model’s trajectories
and keep it fixed throughout the run (Appendix A). At each step, the
same pre-update model generates eight unguided rollouts per task for the
GRPO update and four additional rollouts with the fixed skills added to
the input. These four skill-guided rollouts are used only for comparison
and do not contribute to parameter updates. The success-rate difference
between the guided and unguided rollouts therefore measures the
execution-time effect of the fixed skills at that policy state.

The same guidance becomes less useful as training proceeds. Mean gains
are +26.98, +9.64, and -2.00 percentage points over steps 1–50, 51–100,
and 101–150, respectively
(Figure [2](#S1.F2 "Figure 2 ‣ 1 Introduction ‣ SkillDuet: Co-Evolving Models and Skillsthrough Response Feedback")).
Thus, guidance that substantially helps early in training can become
unhelpful later, even though the skill text has not changed. This result
motivates updating the retained skills as the policy learns.

### 3.2 Framework overview

Figure [3](#S3.F3 "Figure 3 ‣ 3.1 Motivation: skill utility changes during training ‣ 3 Motivation and Method ‣ SkillDuet: Co-Evolving Models and Skillsthrough Response Feedback")
presents two coupled uses of interaction experience: parameter learning
and skill evolution. The agent acts with its global skills (Global) in
the prompt and collects eight trajectories per task. An external
analyzer extracts local skills (Local) from these trajectories,
capturing procedures or corrections grounded in the agent’s recent
behavior. Throughout, each Local refers to a single recently extracted
skill, while Global refers to the consolidated set that persists across
updates.

In the parameter-learning path
(Figure [3](#S3.F3 "Figure 3 ‣ 3.1 Motivation: skill utility changes during training ‣ 3 Motivation and Method ‣ SkillDuet: Co-Evolving Models and Skillsthrough Response Feedback")a),
the agent scores sampled responses with and without Local guidance.
These conditional scores provide token-level OPD supervision alongside
the RL objective. All eligible Local skills can support the current
policy update, regardless of their rank or whether they are later
selected for Global consolidation (Sections 3.3–3.4).

In the skill-evolution path
(Figure [3](#S3.F3 "Figure 3 ‣ 3.1 Motivation: skill utility changes during training ‣ 3 Motivation and Method ‣ SkillDuet: Co-Evolving Models and Skillsthrough Response Feedback")b),
an eligible success–failure pair yields a shared Local skill; groups
without such a pair instead yield one Local per trajectory (Section
3.3). The remaining eligible trajectories provide held-out responses for
Strength scoring (Section 3.5). The highest-scoring of the recent skills
are periodically synthesized with the current Global to produce guidance
reusable across task instances (Section 3.6). The updated policy and
Global then guide further interactions, producing new experience for
both learning paths.

Let $`\theta`$ denote the model parameters, $`G`$ the Global, and
$`\mathcal{W}`$ the recent Local candidate window; initially,
$`G_{0}=\varnothing`$. For task context $`C`$, $`\pi_{\theta}`$ denotes
the model’s conditional response distribution. We maintain one Global
per task category on ALFWorld and a shared Global for all tasks on
WebShop. The extraction, scoring, and synthesis procedures stay fixed,
while the policy, skill content, and resulting response feedback change
during training.

### 3.3 Extracting Local skills from on-policy trajectories

The trajectory group collected at each training step supplies the
evidence for Local extraction
(Figure [3](#S3.F3 "Figure 3 ‣ 3.1 Motivation: skill utility changes during training ‣ 3 Motivation and Method ‣ SkillDuet: Co-Evolving Models and Skillsthrough Response Feedback")b).
Environment feedback determines which of the eight trajectories succeed.
If the group contains eligible successful and failed trajectories, an
external Qwen3.8-27B analyzer compares one of each and generates a
shared Local skill. Otherwise, it analyzes each eligible trajectory
individually and generates one Local skill per trajectory. Appendix A
specifies the trajectory and skill eligibility checks.

Learning from success–failure pairs. We select the first eligible
successful trajectory and the first eligible failed trajectory in
trajectory order. The analyzer receives only the task description and
the observation–response histories of these two trajectories, identifies
the decisions that distinguish them, and produces one shared Local
skill. This comparison grounds corrective guidance in successful
behavior that the current policy has already demonstrated. The shared
skill provides OPD supervision for all eligible trajectories in the
group, including its two source trajectories. We score its usefulness
for Global consolidation on the remaining, held-out trajectories, of
which there are at most six.

Learning from individual trajectories. If no eligible success–failure
pair exists, the analyzer processes each eligible trajectory using the
task description and its observation–response history. It extracts
reusable procedures from successes and guidance for avoiding or
correcting failures. Each resulting Local skill supervises OPD on its
own source trajectory and does not enter Global consolidation.

### 3.4 Updating model parameters with Local-guided OPD

In the parameter-learning path
(Figure [3](#S3.F3 "Figure 3 ‣ 3.1 Motivation: skill utility changes during training ‣ 3 Motivation and Method ‣ SkillDuet: Co-Evolving Models and Skillsthrough Response Feedback")a),
the external analyzer provides Local text, while the agent model
supplies the teacher log probabilities used for distillation. For a
sampled response, the student branch computes token log probabilities
under context $`C`$ and Global $`G`$. Adding a Local skill $`L`$ to this
context produces the teacher branch, which scores the same response
tokens. Their log-probability difference provides a token-level OPD
signal, and a confidence gate weights each token’s supervision according
to this difference \[[3](#bib.bib3)\]. Let $`s_{i}`$ and $`t_{i}`$
denote the student and teacher token log probabilities at token position
$`i`$, $`M_{i}`$ the supervision mask, and $`\operatorname{sg}`$ the
stop-gradient operator:

|     |                                             |                                                                                                                           |     |
| --- | ------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------- | --- |
|     | $`\displaystyle g_{i}`$                     | $`\displaystyle=\operatorname{sg}[\sigma(\beta(t_{i}-s_{i}))],\hskip 10.00002pt\beta=5,`$                                 |     |
|     | $`\displaystyle\mathcal{L}_{\mathrm{OPD}}`$ | $`\displaystyle=\frac{\sum_{i}M_{i}g_{i}(\operatorname{sg}[t_{i}]-s_{i})}{\sum_{i}M_{i}},`$                               |     |
|     | $`\displaystyle\mathcal{L}`$                | $`\displaystyle=\mathcal{L}_{\mathrm{PPO}}+\lambda_{\mathrm{OPD}}\mathcal{L}_{\mathrm{OPD}}+\mathcal{L}_{\mathrm{reg}}.`$ |     |

The policy is optimized with the combined objective in Equation (1).
Proximal policy optimization (PPO) supplies the outcome-based RL
objective \[[15](#bib.bib15)\], while $`\mathcal{L}_{\mathrm{reg}}`$
contains the active regularization terms. Using an external Qwen3.8-27B
analyzer allows skill extraction without requiring the policy itself to
analyze trajectories. Appendix A describes how teacher scores are cached
and aggregated.

### 3.5 Selecting Local skills with model response feedback

A persistent skill set should retain experience that remains useful to
the current policy. If a Local skill barely changes the model’s response
probabilities, its guidance may already be reflected in the model’s
parameters. A larger change may instead identify information worth
retaining. This motivates Strength, a score used to rank recent Local
skills by the magnitude of the response shift they induce.

The skill-evolution path in
Figure [3](#S3.F3 "Figure 3 ‣ 3.1 Motivation: skill utility changes during training ‣ 3 Motivation and Method ‣ SkillDuet: Co-Evolving Models and Skillsthrough Response Feedback")b
evaluates each Local on a scoring set $`H_{L}`$ of held-out trajectories
that were not used to generate it. Scoring keeps the model parameters,
interaction context, sampled responses, and Global fixed. Let
$`\Delta_{r}(L)`$ denote the mean response log-probability shift over
the valid tokens of trajectory $`r`$. Appendix A specifies the scoring
reference and its implementation.

Strength takes the absolute value of each trajectory-level mean and then
averages these values, giving equal weight to each scoring trajectory:

|     |     |     |
| --- | --- | --- |
|     |

````math
\operatorname{Strength}(L)=\frac{1}{|H_{L}|}\sum_{r\in H_{L}}|\Delta_{r}(L)|.
``` |  |

Each scorable Local skill is evaluated before the parameter update at
its generation step. Its Strength score is cached at generation and used
to rank candidates at the end of the window; each score therefore
reflects the policy at the corresponding skill’s generation step.
Scoring reuses sampled trajectories and requires no additional
environment interaction. Appendix A, Algorithm 1, gives the full
procedure.

### 3.6 Periodically consolidating Local skills into Global

Skill selection and Global consolidation operate every ten training
steps
(Figure [3](#S3.F3 "Figure 3 ‣ 3.1 Motivation: skill utility changes during training ‣ 3 Motivation and Method ‣ SkillDuet: Co-Evolving Models and Skillsthrough Response Feedback")b).
SkillDuet deduplicates the recent Local candidates for each Global and
retains the top 50% by cached Strength. The synthesizer receives these
skills together with the current Global. If the input exceeds the
context budget, hierarchical compression first combines shared
procedures and preserves the conditions under which they apply. The
synthesizer then integrates the selected experience with existing rules
to produce compact, reusable guidance (Figure [Appendix G. A worked
example of hierarchical Global
synthesis](#Sx7 "Appendix G. A worked example of hierarchical Global synthesis ‣ SkillDuet: Co-Evolving Models and Skillsthrough Response Feedback");
Appendix G).

After the update, we clear the temporary Local window and use the new
Global in subsequent agent prompts. The next training window therefore
collects experience under both an updated policy and updated skill
guidance.

capability of the initial model before adaptation.

### 4.4 Response-based criteria for Local selection

We next examine which response-based criterion best supports Local skill
selection: response-shift magnitude, reward weighting, or
success–failure contrast.

We compare Strength, Utility, Contrast, and Random in a historical
ALFWorld candidate pool. Each configuration is trained for 300 steps
using the skills selected by its criterion. We measure peak validation
success and normalized area under the validation curve (AUC). Appendix C
provides details of pool management and score accumulation.

Strength measures the magnitude of a Local-induced response shift.
Utility weights the shift by trajectory advantage, and Contrast compares
shifts on successful and failed trajectories. Random assigns priorities
independently of model responses. The three response-based scores are:

|  |  |  |  |
|----|----|----|----|
|  | $`\displaystyle S(L)`$ | $`\displaystyle=\frac{1}{|H_{L}|}\sum_{r\in H_{L}}|\Delta_{r}(L)|,`$ |  |
|  | $`\displaystyle U(L)`$ | $`\displaystyle=\frac{1}{|H_{L}|}\sum_{r\in H_{L}}A_{r}\Delta_{r}(L),`$ |  |
|  | $`\displaystyle C(L)`$ | $`\displaystyle=\frac{1}{|H_{L}^{+}|}\sum_{r\in H_{L}^{+}}\Delta_{r}(L)`$ |  |
|  |  | $`\displaystyle-\frac{1}{|H_{L}^{-}|}\sum_{r\in H_{L}^{-}}\Delta_{r}(L).`$ |  |

Here, $`\Delta_{r}(L)`$ is the trajectory-mean response shift defined in
Section 3.5; $`H_{L}`$ is the scoring set; $`A_{r}`$ is the
trajectory-mean training advantage; and $`H_{L}^{+}`$ and $`H_{L}^{-}`$
are the successful and failed subsets of $`H_{L}`$. Contrast falls back
to Utility when the scoring set does not support a success–failure
comparison.

Strength achieves the highest peak validation success rate, 97.9%, and
the highest AUC, 88.26%, among the four criteria. Its AUC exceeds Random
by 9.29 percentage points
(Figure [4.4](#S4.SS4 "4.4 Response-based criteria for Local selection ‣ 4 Experiments ‣ SkillDuet: Co-Evolving Models and Skillsthrough Response Feedback")).

Figure 4: Local-selection criteria in the historical ALFWorld candidate
pool. Strength achieves the highest peak validation success (left) and
normalized area under the validation curve (AUC; right).

Trajectory rewards and success labels describe behavior before the
candidate skill is introduced; they do not directly measure the skill’s
value for future execution. Increasing the likelihood of a successful
response, or decreasing that of a failed one, likewise does not
establish that the skill will improve later decisions. Weighting
response shifts by the original trajectory’s quality can therefore mix
trajectory quality with the effect of the skill.

In this study, response-shift magnitude is more effective for skill
selection than reward weighting or success–failure contrast. These
results support Strength as a practical criterion for long-term skill
retention, without treating the direction of the probability shift as a
direct measure of benefit.

### 4.5 Local retention ratio

We test how the fraction of Local skills retained for Global
consolidation affects task performance. Retaining too few candidates may
discard useful procedures, whereas retaining too many may introduce
redundancy or conflicting guidance.

We compare Top25%, Top50%, and Top75% retention on ALFWorld and WebShop,
selecting candidates in descending Strength order for each Global. All
eligible Local skills continue to support OPD, so this comparison
changes only the experience used for Global consolidation. We report
peak validation success during training; evaluation details and exact
values are given in Appendices A and D.

Top50% matches Top25% on ALFWorld and achieves the highest result on
WebShop, while Top75% performs worse than Top50% on both tasks
(Figure [4.5](#S4.SS5 "4.5 Local retention ratio ‣ 4 Experiments ‣ SkillDuet: Co-Evolving Models and Skillsthrough Response Feedback")).
Top50% therefore provides the best overall performance among the tested

## 5 Conclusion

We presented SkillDuet, a framework for coordinating LLM parameter
updates and the evolution of reusable textual skills during RL. These
processes are interdependent: skills guide model learning, while
parameter updates change which skills remain useful. Model response
feedback connects them in a shared learning loop. The evolving model and
its skills jointly shape subsequent interactions and the experience
available for further learning.

Experiments with Qwen3-4B on ALFWorld and WebShop show gains over the
matched SEED-API baseline. Ablations support the benefits of
response-based skill selection and consolidation. Further analyses show
that a skill’s benefit depends on its content and its compatibility with
the model. SkillDuet provides a concrete mechanism for skill-level
recursive self-improvement through model–skill co-evolution.

## Appendix A. Training and implementation details

#### Training configurations

We use Qwen3-4B as the backbone. SkillDuet starts RL without SFT, trains
for 300 steps, and samples eight trajectories per task. The OPD
coefficient is .05 for ALFWorld and .03 for WebShop. Each Global has a
ten-step candidate window, from which the top 50% of eligible Local
skills are retained. SEED-API runs for 300 steps with the same
task-specific OPD coefficients as SkillDuet. Both methods use
confidence-gated OPD.

Our SEED reproduction uses SFT initialization followed by 150 RL steps
with an OPD coefficient of .01. The external annotator (UDE in the
implementation) generates the SFT skill targets; during RL, the policy
analyzes its own trajectories without external analyzer calls.

GRPO provides the outcome-based RL baseline. Our reproduction of
Self-Distilled Agentic Reinforcement Learning (SDAR) follows the
official implementation and uses its static skill files. The student
samples responses without skills, and the same model scores those
responses under the original prompt augmented with static skills to
provide detached teacher targets. Training combines GRPO with
confidence-gated distillation, using a gate scale of five and a
distillation coefficient of .01. SDAR runs for 300 steps without SFT,
online skill generation, skill updates, or external analyzer calls.

ALFWorld has one Global for each of its six task categories; WebShop
uses one shared Global. Within each window, Local skills with identical
text after whitespace normalization are deduplicated while their source
records are retained. A skill is scored once when it is generated,
before the policy update. At the window boundary, we read these cached
scores, check candidate eligibility, and round the retention count
upward, keeping at least one candidate from a nonempty eligible set.
Consolidation occurs before the next rollout step. The temporary
candidates and scores are then cleared.

For Strength scoring, the reference context uses token-length-matched
neutral text $`N_{L}`$ in place of Local. With the policy and sampled
response fixed, the trajectory-level shift is:

|  |  |  |  |
|----|----|----|----|
|  | $`\displaystyle\Delta_{r}(L)`$ | $`\displaystyle=\frac{1}{T_{r}}\sum_{i\in r}\Big[`$ |  |
|  |  | $`\displaystyle\log\pi(a_{i}\mid C,G,L,a_{<i})`$ |  |
|  |  | $`\displaystyle-\log\pi(a_{i}\mid C,G,N_{L},a_{<i})\Big].`$ |  |

To construct neutral text, we repeat or truncate a fixed filler passage
containing no task instructions or procedures. We match the token counts
of the complete, untruncated prompts while keeping the prompt template
and interaction context fixed. The verified main WebShop configuration
permits a difference of at most two tokens, and neither prompt may
exceed its length limit. The scoring set $`H_{L}`$ excludes the skill’s
generation pair and retains only held-out trajectories with valid
response tokens, scores under both conditions, and valid length
matching. A Local skill without a valid score is not considered for
Global selection.

#### Assigning Local skills to supervision trajectories

Trajectory analysis groups records by trajectory identity and
reconstructs the sequence of observations and responses. We decode
responses using the generation mask and prefer raw environment
observations when available. Terminal success indicators distinguish
successful and failed trajectories; action validity is not used to
filter the response text. For immediate OPD, a generated skill must
contain a parsable, nonempty episode_skill field with at least five
whitespace-separated words, excluding punctuation-only strings and
placeholders.

A per-trajectory Local skill supervises only its source trajectory. A
skill generated from a success–failure pair supervises all eligible
trajectories in the group. We choose the first eligible success and
failure for generation and exclude both from Strength scoring. To enter
Global selection, a shared Local skill must also receive a valid score
on at least one held-out trajectory. Skills that cannot be scored can
still provide immediate OPD supervision. Appendix C describes the
separate historical-pool experiments.

The analyzer is instructed to produce actionable guidance grounded in
the supplied trajectories. The paired prompt contains: “Two trajectories
of the SAME task are given below. Compare them, locate the earliest step
where their decisions diverge, and write one episode_skill that turns
that divergence into a rule the policy can act on.” The response schema
is {”episode_skill”: ”string”}. Single-trajectory prompts ask for
reusable procedures from successes or guidance for avoiding and
correcting failures.

#### Global synthesis and deployment

Global starts empty and is first synthesized after the initial ten-step
window. Local extraction and Global synthesis use the same external API
client and model endpoint, with separate prompts for trajectory analysis
and skill consolidation. Selected Local skills are merged with the
current Global, either directly or after hierarchical compression
(Figure [Appendix G. A worked example of hierarchical Global
synthesis](#Sx7 "Appendix G. A worked example of hierarchical Global synthesis ‣ SkillDuet: Co-Evolving Models and Skillsthrough Response Feedback")).
The generated skill set must be parsable, nonempty, and satisfy the
required structure and length constraints. If these checks fail, we keep
the existing Global. Appendix D describes the optional execution-based
Commit check.

The recorded main WebShop synthesis configuration uses a context budget
of 24,000, reserving 12,288 for output and 1,024 as a safety margin,
leaving 10,688 for input. The implementation estimates this budget from
UTF-8 byte counts rather than exact provider token counts. Larger inputs
trigger hierarchical compression, with up to five levels. In the example
from steps 11–20, the initial input estimate is 22,280 and the final
synthesis input is 9,287.

Global contains at most six skills, each with at least five words, and
is limited to 2,400 characters in total, with a target of about 45 words
per skill. These values describe the recorded configuration.

The Global system prompt is: “Synthesize evidence-linked procedural
skills. Return JSON only.” The user prompt asks the synthesizer to merge
duplicate procedures, preserve conditions and exceptions, remove
instance identifiers, and return the complete updated Global. Useful
existing rules must be preserved verbatim even if the recent window
contains no matching examples. New or revised rules must cite supplied
source identifiers. The output schema is {”skills”: \[{”text”:
”conditional procedure”, ”source_ids”: \[”L0000”\]}\]}. Intermediate
hierarchical summaries also retain source identifiers and applicability
conditions.

#### Teacher scores and implementation details

The external analyzer supplies Local text, while the skill-conditioned
agent supplies the teacher log probabilities. In the main WebShop
configuration, teacher scores are cached before each actor update and
refreshed at the next RL step. Student scores are recomputed during
optimization. Both the teacher scores and the confidence gate are
detached from the gradient. When the teacher–student difference is zero,
the sigmoid gate equals 0.5; a zero loss value therefore does not imply
a zero gradient.

The original SEED formulation evaluates both branches with the current
model parameters during optimization. Complete deployment records are
unavailable for some earlier and original configurations.

#### Optimization and runtime

RL training uses a learning rate of 1e-6, weight decay of .01, no
warmup, a constant learning-rate schedule, a training batch size of 16,
and eight trajectories per task. Rollouts use temperature=1 and top-p=1.
Validation samples one trajectory per task at temperature=.4, with a
response limit of 512 tokens.

For ALFWorld, SkillDuet uses mini/micro batch sizes of 256/16, GRPO and
SDAR use 64/8, and SEED uses 256/32. The main WebShop configurations use
64/8, and the main WebShop SkillDuet configuration uses AdamW. The
configurations specify a single node with eight GPUs; the GPU model is
not fully documented in the available records.

We refer to the external analyzer as Qwen3.8-27B. The verified synthesis
requests use the endpoint alias edu-vlm-rm, which does not identify an
immutable backend weight version for all earlier experiments. Runtime
records for the main WebShop SkillDuet configuration list PyTorch 2.6.0,
vLLM 0.8.5.post1, Transformers 4.51.3, and Ray 2.43.0.

## Appendix C. Additional analyses of response-based skill selection

#### Do OPD gains require an intact skill structure?

We compare OPD training with intact skills, sentence-shuffled skills,
and neutral text, each containing 2,355 words. Neutral text is used in
the OPD branch rather than serving only as an inference-time baseline.
Across the four shared validation steps, 90, 105, 120, and 135, intact
skills exceed neutral text by 18.4 percentage points, shuffled skills
exceed it by 14.3 points, and intact skills exceed shuffled skills by
4.1 points.

Training still benefits after the sentences are shuffled, so an intact
procedural structure is not the sole explanation for the OPD gains. This
observation motivates examining how text changes model responses.
Whether a Local skill is worth retaining is a separate question, tested
through the selection experiments in
Sections [4.3](#S4.SS3 "4.3 Global consolidation and response-based selection ‣ 4 Experiments ‣ SkillDuet: Co-Evolving Models and Skillsthrough Response Feedback")
and [4.4](#S4.SS4 "4.4 Response-based criteria for Local selection ‣ 4 Experiments ‣ SkillDuet: Co-Evolving Models and Skillsthrough Response Feedback").

#### Historical candidate pool and score updates

The metric comparison in
Section [4.4](#S4.SS4 "4.4 Response-based criteria for Local selection ‣ 4 Experiments ‣ SkillDuet: Co-Evolving Models and Skillsthrough Response Feedback")
compares the three response-based criteria in Equation (3) with Random
for long-term skill retention. This earlier configuration accumulates
candidates by task category, deduplicates whitespace-normalized text,
and keeps at most eight candidates per category. Valid scores are
recorded before ranking and capacity-based eviction. The top 50% of the
remaining pool enters Global synthesis, so a criterion affects both pool
membership and consolidation. The main framework instead uses
independent recent windows and clears all candidates and scores after
each window.

If a pooled candidate is scored repeatedly, its first valid score
initializes the metric. Later scores are combined by an exponential
moving average with coefficient .1: .9 on the previous value and .1 on
the new value. Contrast updates its contrastive score only when a
scoring event contains both successful and failed trajectories; until
the first valid contrastive score, it falls back to Utility.

Random uses a fixed priority obtained by hashing ranking seed zero with
the normalized skill text. Candidates without valid scores cannot enter
Global selection, and an empty selection leaves Global unchanged. In the
main framework, selection reads the Strength score cached at skill
generation rather than re-scoring candidates at window boundaries.

Normalized AUC is computed from ten validation success rates at steps
30, 60, …, 300. We sum the trapezoidal areas between adjacent
measurements and divide by the 270-step interval, then express the
result as a percentage. AUC therefore summarizes mean validation
performance over steps 30–300, while the peak reports the highest
observed success rate.

#### Do training gains imply an immediate benefit from skill prompts?

A separate paired probe holds the policy parameters fixed and compares
late-stage execution with and without injected text.
Injection-minus-baseline differences are -3.53 percentage points for
neutral text, -19.18 for shuffled text, -24.00 for the tested intact
text, and -29.24 for antonym replacement. These texts come from a
historical pool distinct from the fixed-guidance experiment in Section
3.1.

For this checkpoint and text configuration, direct injection does not
improve task execution. The effect of teacher-side guidance during
training must therefore be evaluated separately from the effect of
adding that text to the policy’s execution context. Response-based
selection should be used with synthesis that preserves applicability
conditions and with subsequent task evaluation.

#### Early Global-injection probes

An earlier ALFWorld configuration, labeled ALFWorld Full in the records,
contains 79 valid ON/OFF probes with the same model parameters and
training tasks. A Clean probe after update 110 uses eight tasks and two
rollouts per condition: 14/16 succeed with Global ON and 5/16 with
Global OFF. This provides an example of immediate skill-guidance gains
for that policy and task set.

These probes are supplementary and are separate from the main SkillDuet
checkpoint evaluation. The available training logs indicate that the
injected trajectories were excluded from parameter updates in this
configuration. Complete deployment and task-level probe records are
unavailable.

#### Optional Commit checks

By default, SkillDuet deploys an updated Global after the synthesis
checks pass. We also test Commit, an optional acceptance check based on
task execution. With policy parameters fixed, Commit compares the
candidate and current Global on the same training tasks. Commit32 uses
32 training tasks per Global and two rollouts per task under each
condition. These tasks are separate from formal validation. For the
comparison tasks $`Q`$, the mean reward difference is:

|  |  |  |  |
|----|----|----|----|
|  | $`\displaystyle\Delta_{\mathrm{Commit}}`$ | $`\displaystyle=\frac{1}{|Q|}\sum_{q\in Q}\Big[\bar{R}(q,G_{\mathrm{new}})`$ |  |
|  |  | $`\displaystyle-\bar{R}(q,G_{\mathrm{old}})\Big].`$ |  |

The candidate replaces the current Global only when all 32 valid task
comparisons are available and the mean reward difference is nonnegative.
Otherwise, the current skill set is retained. This rule does not use a
significance test. Commit controls which Global is deployed; it does not
roll back policy updates already made using Local skills.
````
