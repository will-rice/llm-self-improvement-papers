###### Abstract.

Serving web queries at scale with multi-agent systems requires jointly
configuring large language models, collaboration modes, agent counts,
interaction rounds, and skills. However, the resulting configuration
space grows combinatorially, while sparse execution rewards provide
limited fine-grained supervision for interdependent planning decisions.
We propose EvoRouter, a self-evolving multi-agent routing framework
driven by insight-guided on-policy distillation. A dedicated expert
periodically synthesizes performance–cost feedback from configuration
trajectories across tasks into reusable conditional routing insights
about capability requirements, returns from resource scaling, and
interactions among configuration choices. A privileged teacher combines
these evolving insights with current execution feedback to provide dense
token-level supervision for the router’s own planning trajectories
through on-policy distillation. Cost-aware reinforcement learning
jointly optimizes task performance and computational cost. Together,
these training signals internalize execution insights into the routing
policy. The updated policy generates new trajectories that support
subsequent insight extraction, forming an execution-driven
self-improvement loop. We evaluate EvoRouter on 19 in-domain datasets
spanning five domains and two out-of-domain benchmarks. EvoRouter
achieves an average in-domain accuracy of 68.69%, outperforming the
strongest routing baseline by 7.23 percentage points while reducing
inference compute cost by 50.95%. Our code is open-sourced at
[https://github.com/CenYangtze/EvoRouter](https://github.com/CenYangtze/EvoRouter).

## 1. Introduction

![Refer to caption](2610.35690v1/mas_routing_task.png)

Figure 1. MAS router for web queries.

![Refer to caption](2610.35690v1/overview.png)

Figure 2. Motivation and performance of EvoRouter. Left: Two challenges

Agents powered by large language models (LLMs) are rapidly expanding the
capabilities of Web services ([Moslem and Kelleher, 2026](#bib.bib63);
[Li et al., 2026c](#bib.bib64)), from information seeking to complex
reasoning and problem solving ([Pesl et al., 2025](#bib.bib36); [Izzi et
al., 2025](#bib.bib21)). LLM routers have emerged as a key component of
agentic infrastructure, selecting suitable models for individual queries
to balance response quality and inference cost ([Chen et al.,
2024](#bib.bib4); [Feng et al., 2025](#bib.bib12); [Wang et al.,
2026a](#bib.bib45); [Ong et al., 2025](#bib.bib34)). With the growing
adoption of multi-agent systems (MAS) in agentic web services such as
Grok Bot and WorkBuddy, routing must extend beyond model selection to
jointly determine model assignments, collaboration modes, agent counts,
interaction rounds, and the skills and subtasks assigned to each agent.
For service providers handling Web queries across diverse domains and
difficulty levels, adaptively selecting MAS configurations to jointly
optimize reasoning performance and compute cost has become a central
research problem.

Existing MAS routing research primarily improves routing decisions
through two mechanisms. Parametric policy optimization internalizes
execution feedback into router parameters through reinforcement learning
or feedback-conditioned distillation, learning policies for model
assignment and system orchestration ([Yue et al., 2025b](#bib.bib57);
[Su et al., 2026](#bib.bib42); [Ke et al., 2026](#bib.bib25); [Feng et
al., 2026](#bib.bib13)). Explicit experience evolution updates
retrievable execution records, routing rules, or orchestration skills,
allowing accumulated experience to guide subsequent decisions without
gradient updates to the router ([Zhang et al., 2026a](#bib.bib58);
[Rajib et al., 2026](#bib.bib39); [Lin et al., 2026](#bib.bib30); [Li et
al., 2026a](#bib.bib27)). Connecting experience reuse with policy
learning is particularly challenging for joint MAS configuration: the
benefits of a model, collaboration mode, or resource allocation depend
jointly on task requirements and the surrounding configuration choices.
Reusable experience must therefore preserve these conditions of
applicability, while effective policy learning must translate the
relevant knowledge into the ability to plan new configurations. As
illustrated in
Figure [1](#S1.F1 "Figure 1 ‣ 1. Introduction ‣ EvoRouter: Cost-Efficient Multi-Agent Routing via Insight-Guided On-Policy Distillation"),
this raises a central open question: How can configuration experience be
distilled into reusable knowledge of conditional dependencies and
internalized in the router’s pre-execution planning policy to improve
the system-level trade-off between accuracy and cost?

Addressing this question presents two challenges, as highlighted in
Figure [2](#S1.F2 "Figure 2 ‣ 1. Introduction ‣ EvoRouter: Cost-Efficient Multi-Agent Routing via Insight-Guided On-Policy Distillation").
(i) Discovering reusable routing principles within a complex,
multidimensional configuration space. Jointly selecting models,
collaboration modes, agent counts, interaction rounds, and skills causes
a combinatorial explosion in the configuration space, making exhaustive
evaluation computationally prohibitive ([Wang et al.,
2025](#bib.bib46)). Moreover, because configuration benefits depend on
both the task and the combination of choices, a single execution
trajectory reveals only the outcome under a specific configuration ([Yu
et al., 2026](#bib.bib54)). It provides insufficient evidence to
identify necessary, redundant, or suboptimal decisions. The router must
therefore move beyond learning from isolated outcomes and analyze
execution trajectories across tasks and configurations to uncover
conditional configuration patterns that generalize to subsequent tasks.
(ii) Translating post-execution experience into fine-grained supervision
for pre-execution routing. Existing reinforcement learning approaches to
routing derive reward signals solely from highly sparse feedback on
final task success and computational cost ([Zhang et al.,
2025](#bib.bib59); [Cui et al., 2026](#bib.bib7); [Liao et al.,
2026](#bib.bib29)). However, a complete MAS configuration involves
multiple coupled planning decisions. Terminal rewards provide limited
guidance on which decisions are effective, which waste resources, and
how individual configuration choices should be adjusted. Even when
valuable routing insights can be distilled from historical trajectories,
they do not automatically translate into effective action selection at
specific decision states of the current routing policy. This mismatch
between high-dimensional combinatorial decisions and coarse, sparse
execution feedback limits the router’s ability to learn efficiently and
improve continually from limited execution experience.

To address these challenges, we propose EvoRouter, an adaptive
multi-agent routing framework built around an insight-guided
self-improvement loop. To address the first challenge, we conduct
preliminary experiments that systematically examine how configuration
changes affect reasoning performance and computational cost across
tasks, revealing task dependence, diminishing marginal returns, and
configuration interdependence. We then design an LLM-based expert that
distills routing insights by periodically aggregating configurations,
execution outcomes, and costs across tasks. The expert derives
conditional insights into task-specific capability bottlenecks, marginal
returns from resource scaling, and interactions among configuration
choices. These insights guide exploration according to task
characteristics, steering the router toward optimal configurations. To
address the second challenge, we develop a router training method that
combines privileged on-policy distillation (OPD) with cost-aware
reinforcement learning (RL). OPD transforms configuration insights
accumulated across trajectories into dense, token-level rewards informed
by routing insights, while RL optimizes the performance–cost trade-off
using end-to-end execution outcomes. These complementary training
signals address the challenge of learning interdependent multi-agent
configuration decisions from sparse execution feedback.

Our main contributions are summarized as follows:

1. Conditional routing insights distillation. We identify task
   dependence, diminishing marginal returns, and interdependence among MAS
   configuration choices. We distill cross-trajectory performance–cost
   feedback into configuration insights with explicit applicability
   conditions to guide exploration.

2. Insight-guided router post-training. We propose EvoRouter, which
   internalizes conditional insights into the routing policy through OPD
   and jointly optimizes execution utility with RL, providing fine-grained
   supervision for routing decisions.

3. Comprehensive empirical validation. We construct a benchmark covering
   21 scenarios across seven domains, demonstrating that EvoRouter achieves
   better performance, lower cost, and greater robustness than
   representative baselines.

## 2. Related Work

#### LLM Routing and Multi-Agent Orchestration.

LLM routing spans per-query model selection ([Chen et al.,
2024](#bib.bib4); [Feng et al., 2025](#bib.bib12); [Ong et al.,
2025](#bib.bib34); [Wang et al., 2026a](#bib.bib45); [Farahani et al.,
2026a](#bib.bib11); [Farahani et al., 2026b](#bib.bib10)) and
output-budget allocation ([Xue et al., 2026](#bib.bib52)), sequential
model invocation ([Zhang et al., 2025](#bib.bib59); [Qian et al.,
2025](#bib.bib37)), and joint MAS configuration ([Yue et al.,
2025b](#bib.bib57); [Zhao et al., 2026](#bib.bib61); [Su et al.,
2026](#bib.bib42); [Ke et al., 2026](#bib.bib25); [Xiao et al.,
2026](#bib.bib51)). Beyond team design, routers adapt delegation ([Feng
et al., 2026](#bib.bib13); [Cui et al., 2026](#bib.bib7)), agent or
context selection ([Zhang et al., 2026b](#bib.bib60); [Liu et al.,
2026](#bib.bib31)), and execution state ([Li et al., 2026b](#bib.bib28);
[Rajib et al., 2026](#bib.bib39)). Experience-based approaches retain
reusable routing knowledge ([Wang et al., 2026c](#bib.bib48); [Zhang et
al., 2026a](#bib.bib58); [Lin et al., 2026](#bib.bib30)) or co-evolve
routing with worker capabilities ([Huang et al., 2026](#bib.bib19)).
RSI-Router([Li et al., 2026a](#bib.bib27)) evolves subtask assignments
and model-specific skills through Pareto selection. EvoRouter targets
pre-execution joint configuration over fixed heterogeneous workers,
informed by our analysis of task-dependent scaling and configuration
interactions.

#### Post-Training for LLMs.

LLM post-training commonly combines supervised fine-tuning (SFT) on
demonstrations with preference optimization ([Ouyang et al.,
2022](#bib.bib35); [Rafailov et al., 2023](#bib.bib38)). Reinforcement
learning with verifiable rewards further develops reasoning capabilities
from outcome feedback ([Guo et al., 2025](#bib.bib16)). Complementing
reward-based optimization, on-policy distillation provides teacher
supervision on student-generated sequences and can reduce the
training–inference distribution mismatch associated with offline
distillation ([Agarwal et al., 2024](#bib.bib2)). Recent methods enrich
this supervision with textual feedback ([Hübotter et al.,
2026](#bib.bib20)), trajectory-derived skills ([Wang et al.,
2026b](#bib.bib47); [Wu et al., 2026](#bib.bib50)), and role-specific
coordination feedback ([Zhong et al., 2026](#bib.bib62)). Building on
these principles, EvoRouter combines group-relative RL with OPD on
student-generated configuration plans, conditioning the teacher on
evolving cross-task insights and current execution feedback. The
resulting policy operates without privileged feedback at inference.

## 3. Routing Insights and Problem Definition

### 3.1. Routing Insights In Multi-Class Tasks

![Refer to caption](2610.35690v1/method.png)

Figure 4. EvoRouter’s initialization and evolution loop.

Efficient MAS routing requires determining which resources to scale, to
what extent, and how to combine them. Using $`m_{\alpha}`$
(Qwen3.5-35B-A3B) and $`m_{\beta}`$ (Qwen3.5-397B-A17B) as
representative backbones, we systematically examine how resource
selection, scaling scale, and configuration combinations govern task
success and compute cost.
Figure [3](#S1.F3 "Figure 3 ‣ 1. Introduction ‣ EvoRouter: Cost-Efficient Multi-Agent Routing via Insight-Guided On-Policy Distillation")
highlights three key insights.

Where to Scale? Different tasks exhibit distinct capability demands,
leading to task-dependent benefits from resource scaling. As shown in
Figure [3](#S1.F3 "Figure 3 ‣ 1. Introduction ‣ EvoRouter: Cost-Efficient Multi-Agent Routing via Insight-Guided On-Policy Distillation")(a),
switching from $`m_{\beta}+\mathrm{IO}`$ to
$`m_{\alpha}+\mathrm{FullConnected}`$ improves the success rate on
Multimodal by 13.1 points, while reducing that on QA tasks by 5.0
points. This suggests that scaling decisions should be driven by task
demands, prioritizing task-aligned resource configurations (Insight 1).

How Much to Scale? Increasing resource allocation does not necessarily
yield proportional gains.
Figure [3](#S1.F3 "Figure 3 ‣ 1. Introduction ‣ EvoRouter: Cost-Efficient Multi-Agent Routing via Insight-Guided On-Policy Distillation")(b)
shows that different models and collaboration strategies reach peak
performance at different interaction rounds or agent counts, beyond
which further scaling may increase costs while degrading success rates.
Thus, resource scaling exhibits configuration-dependent saturation
points, and the allocation scale should be tailored to the underlying
model and collaboration strategy (Insight 2).

What to Combine? The effectiveness of individual resources depends on
their interactions within the overall configuration.
Figure [3](#S1.F3 "Figure 3 ‣ 1. Introduction ‣ EvoRouter: Cost-Efficient Multi-Agent Routing via Insight-Guided On-Policy Distillation")(c)
reveals that the relative performance of model compositions can reverse
across collaboration strategies: an all-$`m_{\beta}`$ configuration
outperforms an all-$`m_{\alpha}`$ configuration under FullConnected,
whereas the latter achieves higher success rates under Debate while
reducing MAS FLOPs by 79.8%. Therefore, routing insights should capture
effective resource combinations and the conditions under which they
excel (Insight 3).

Together, these insights guide subsequent insights distillation from
three complementary perspectives: task alignment, scaling saturation,
and configuration interactions. Building on these findings, we jointly
analyze tasks, complete configurations, execution outcomes, and costs to
distill accumulated execution insights into condition-aware routing
knowledge.

### 3.2. Problem Definition

We consider cost-aware multi-agent routing, where a router maps a given
task $`q\sim\mathcal{Q}`$ to a tailored MAS configuration
$`\mathcal{P}`$ drawn from a broad design space spanning models, skills,
subtasks, collaboration modes, and agent counts. The router produces a
final answer based on the resulting system execution.

Let $`\mathcal{M}`$, $`\mathcal{C}`$, and $`\mathcal{S}`$ denote the
available pools of models, collaboration modes, and skills,
respectively. Given these resources, the router constructs a detailed
MAS configuration $`\mathcal{P}`$:

|     |     |     |     |
| --- | --- | --- | --- |
| (1) |     |

````math
\mathcal{P}=\left(c,r,\left\{(u_{j},m_{j},s_{j},p_{j})\right\}_{j=1}^{n}\right),
``` |  |

where $`c\in\mathcal{C}`$ specifies the collaboration mode, $`r`$ is the
number of interaction rounds within the system, and $`n`$ is the number
of agents. Each agent $`j`$ is defined by its identifier $`u_{j}`$,
model $`m_{j}\in\mathcal{M}`$, skill $`s_{j}\in\mathcal{S}`$, and
assigned subtask $`p_{j}`$.

The environment instantiates and executes the MAS, returning an
execution outcome $`o\sim\mathcal{E}(\cdot\mid q,\mathcal{P})`$ to the
router, where $`\mathcal{E}(\cdot\mid q,\mathcal{P})`$ denotes the
distribution of execution outcomes conditioned on the task and
configuration. The router then generates a final answer $`\hat{y}`$ for
task $`q`$, forming a complete trajectory $`\tau`$. A task-specific
verifier (e.g., sandbox tests for code generation or exact-match
evaluation for question answering) evaluates the final answer, with
$`s(\tau)\in\{0,1\}`$ indicating whether it passes verification.

Let $`C(\tau)\geq 0`$ denote the execution cost of the routed MAS along
trajectory $`\tau`$, and let $`B(q)>0`$ be a reference budget for task
$`q`$. We aim to learn a routing policy that jointly optimizes task
success and resource efficiency:

|  |  |  |  |
|----|----|----|----|
| (2) |  |
``` math
\pi^{\star}\in\arg\max_{\pi}\mathbb{E}_{\begin{subarray}{c}q\sim\mathcal{Q}\\
\tau\sim p_{\pi,\mathcal{E}}(\cdot\mid q,\mathcal{C},\mathcal{S},\mathcal{M})\end{subarray}}\left[U\left(s(\tau),\frac{C(\tau)}{B(q)};\lambda_{C}\right)\right],
``` |  |

where $`p_{\pi,\mathcal{E}}`$ denotes the trajectory distribution
jointly induced by the routing policy and multi-agent execution,
accounting for stochasticity in both policy generation and system
execution. The utility function $`U`$ balances task success against
budget-normalized execution cost, with $`\lambda_{C}`$ controlling the
cost penalty. Its specific form is defined in
Section [4.3](#S4.SS3 "4.3. Cost-Aware Policy Optimization ‣ 4. Method ‣ EvoRouter: Cost-Efficient Multi-Agent Routing via Insight-Guided On-Policy Distillation").

## 4. Method

We parameterize the routing policy as $`\pi_{\theta}`$ and initialize it
through SFT. We then collect online trajectories across diverse task
categories and employ an insight distillation expert to iteratively
extract routing insights, which are internalized into the policy through
training. This establishes an iterative evolution loop, sustained by
reinforcement learning and on-policy distillation in an online
environment, as illustrated in
Fig. [4](#S3.F4 "Figure 4 ‣ 3.1. Routing Insights In Multi-Class Tasks ‣ 3. Routing Insights and Problem Definition ‣ EvoRouter: Cost-Efficient Multi-Agent Routing via Insight-Guided On-Policy Distillation").

### 4.1. Evolution Loop

#### Routing and execution.

We construct the router context $`x`$, comprising role specifications,
task descriptions and available routing resources. The router first
analyzes the task and reasons within the \<analysis\> tag, then
generates a structured plan as defined in
Eq. ([1](#S3.E1 "In 3.2. Problem Definition ‣ 3. Routing Insights and Problem Definition ‣ EvoRouter: Cost-Efficient Multi-Agent Routing via Insight-Guided On-Policy Distillation"))
within the \<plan\> tag. A deterministic executor in the environment
parses this plan and instantiates the specified MAS.

The MAS then executes the plan in the environment, producing execution
outcomes that are returned as observations for the router’s subsequent
response. The router analyzes these observations within the \<analysis\>
tag and generates the final answer $`\hat{y}`$ within the \<answer\>
tag, forming a two-stage trajectory $`\tau`$. Each trajectory records
the task description, multi-agent configuration, execution outcomes, and
verifier-evaluated final answer.

#### Sampling and evolution.

We deploy the router in an online environment and sample execution
trajectories from a training set spanning diverse capability dimensions.
Building on the observations from our preliminary experiments
(Section [4](#S3.F4 "Figure 4 ‣ 3.1. Routing Insights In Multi-Class Tasks ‣ 3. Routing Insights and Problem Definition ‣ EvoRouter: Cost-Efficient Multi-Agent Routing via Insight-Guided On-Policy Distillation")),
we develop an insight distillation expert to analyze these trajectories
and continually refine routing insights. The expert integrates newly
observed routing patterns from recent online trajectories with
accumulated insights, capturing task-dependent preferences for resources
and subtask decomposition strategies across different domains,
difficulty levels, and budgets. This process enables routing knowledge
to evolve continuously as new execution insights accumulate, as detailed
in
Section [4.4](#S4.SS4 "4.4. Insight-Guided On-Policy Distillation ‣ 4. Method ‣ EvoRouter: Cost-Efficient Multi-Agent Routing via Insight-Guided On-Policy Distillation").

### 4.2. Supervised Initialization

We initialize the routing policy through SFT to establish protocols for
task analysis, system planning, and result synthesis. Specifically, a
frozen powerful LLM acts as a bootstrap router to collect trajectories
across training tasks $`\mathcal{Q}_{\mathrm{sft}}`$ under context
$`x`$. We retain only demonstrations with valid formats and correct
answers to construct $`\mathcal{D}_{\mathrm{SFT}}`$. Letting
$`\mathcal{T}(y)`$ index the router-generated tokens in sequence $`y`$,
the initialization objective minimizes

|  |  |  |  |
|----|----|----|----|
| (3) |  |
``` math
\mathcal{L}_{\mathrm{SFT}}(\theta)=-\sum_{(x,y)\in\mathcal{D}_{\mathrm{SFT}}}\sum_{t\in\mathcal{T}(y)}\log\pi_{\theta}(y_{t}\mid x,y_{<t}).
``` |  |

Prompt contexts and environment feedback are masked during loss
computation. The supervised policy initializes subsequent iterative
evolution and provides a frozen reference policy $`\pi_{\mathrm{ref}}`$.

### 4.3. Cost-Aware Policy Optimization

#### Reward curation.

For each trajectory $`\tau`$, the task verifier assigns an outcome
reward $`R_{\mathrm{perf}}=s(\tau)\in\{0,1\}`$. We measure execution
compute $`C(\tau)`$ and impose a cost penalty
$`R_{\mathrm{cost}}=\log_{2}(1+C(\tau)/B(q))`$, calibrated against a
task-specific reference budget $`B(q)`$. We then instantiate the utility
in
Eq. ([2](#S3.E2 "In 3.2. Problem Definition ‣ 3. Routing Insights and Problem Definition ‣ EvoRouter: Cost-Efficient Multi-Agent Routing via Insight-Guided On-Policy Distillation"))
as the following reward function $`R(\tau)`$:

|     |     |                                                         |     |
|-----|-----|---------------------------------------------------------|-----|
| (4) |     |
             ``` math
             R(\tau)=R_{\mathrm{perf}}-\lambda_{C}R_{\mathrm{cost}},
             ```                                                      |     |

where $`\lambda_{C}`$ controls cost sensitivity. To strictly separate
the reward ranges of successful and failed rollouts, we further cap the
weighted cost penalty at $`c_{\mathrm{max}}\in[0,1)`$ to ensure that
successful trajectories receive rewards of at least
$`1-c_{\mathrm{max}}>0`$, while unsuccessful trajectories receive
nonpositive rewards. Details of cost weighting are provided in
Appendix [A.2](#A1.SS2 "A.2. Dataset ‣ Appendix A Experimental Details ‣ EvoRouter: Cost-Efficient Multi-Agent Routing via Insight-Guided On-Policy Distillation").

#### Group-relative policy updates.

For each task $`q`$, we sample $`G`$ rollouts
$`\tau_{q,1},\dots,\tau_{q,G}`$ and compute normalized group advantages
$`A_{q,i}`$. Let $`\mathcal{T}_{q,i}`$ index the router-generated tokens
in trajectory $`\tau_{q,i}`$, conditioned on the preceding interaction
history $`H_{q,i,t}`$. Sharing the same token masking as SFT, the policy
loss is defined as:

|  |  |  |  |
|----|----|----|----|
| (5) |  |
``` math
\mathcal{L}_{\mathrm{RL}}(\theta)=-\frac{1}{Z_{\mathrm{RL}}}\sum_{q}\sum_{i=1}^{G}A_{q,i}\sum_{t\in\mathcal{T}_{q,i}}\log\pi_{\theta}\left(y_{q,i,t}\mid H_{q,i,t}\right),
``` |  |

where $`Z_{\mathrm{RL}}`$ is the total number of masked response tokens
from trajectories with nonzero advantages in the batch. To prevent
policy drift, we regularize $`\pi_{\theta}`$ against the frozen
reference $`\pi_{\mathrm{ref}}`$ via a token-level KL penalty:

|  |  |  |  |
|----|----|----|----|
| (6) |  |
``` math
\mathcal{L}_{\mathrm{KL}}(\theta)=\frac{1}{Z_{\mathrm{KL}}}\sum_{q}\sum_{i=1}^{G}\sum_{t\in\mathcal{T}_{q,i}}\left[r_{q,i,t}(\theta)-\log r_{q,i,t}(\theta)-1\right],
``` |  |

where
$`r_{q,i,t}(\theta)=\frac{\pi_{\mathrm{ref}}(y_{q,i,t}\mid H_{q,i,t})}{\pi_{\theta}(y_{q,i,t}\mid H_{q,i,t})}`$
denotes the reference-to-policy probability ratio, and
$`Z_{\mathrm{KL}}=\sum_{q,i}|\mathcal{T}_{q,i}|`$ counts all router
response tokens across the batch, including zero-advantage trajectories.

### 4.4. Insight-Guided On-Policy Distillation

#### Recursive insight consolidation.

Guided by the analytical framework in
Section [4](#S3.F4 "Figure 4 ‣ 3.1. Routing Insights In Multi-Class Tasks ‣ 3. Routing Insights and Problem Definition ‣ EvoRouter: Cost-Efficient Multi-Agent Routing via Insight-Guided On-Policy Distillation"),
we initialize an insight pool $`\mathcal{I}_{0}`$ and employ an expert
$`\mathcal{F}`$ to periodically distill execution observations into
generalizable routing rules with explicit applicability conditions only
during training. For the $`k`$-th insight update using recent rollout
batch $`\mathcal{B}_{k}`$, the expert refines the insight set through a
three-step procedure: (i) Rule induction: comparing intra-category
trajectories across success or failure and cost spectra to derive
conditional rules on capability alignment, scaling saturation, and
configuration interactions; (ii) Precondition refinement: resolving
empirical conflicts within $`\mathcal{I}_{k}`$ by tightening boundaries,
such as specifying finer-grained task difficulty and domains; and (iii)
Capacity pruning: merging redundant entries and enforcing a strict
capacity ceiling to curb context inflation. Formally, the update is
expressed as:

|  |  |  |  |
|----|----|----|----|
| (7) |  |
``` math
\mathcal{I}_{k+1}=\mathcal{F}\left(\mathcal{I}_{k},\mathcal{B}_{k}\right).
``` |  |

Distillation steps always condition on the latest insights
$`\mathcal{I}`$. Further details on insight distillation are provided in
Appendix [A.3](#A1.SS3 "A.3. Training ‣ Appendix A Experimental Details ‣ EvoRouter: Cost-Efficient Multi-Agent Routing via Insight-Guided On-Policy Distillation").

#### Insight-conditioned supervision.

For each trajectory $`\tau_{i}`$ sampled from the student policy, the
frozen teacher model $`\pi_{\phi}`$ receives additional privileged
information $`z_{i}=(\mathcal{I},\mathcal{P}_{i},o_{i},s(\tau_{i}))`$,
where $`o_{i}`$ denotes the MAS execution outcome, while sharing the
same context $`x_{i}`$ and prefix $`y_{i,<t}`$ as the student.
Specifically, at each token position $`t`$ in the routing response, let
$`p_{i,t}^{\mathrm{S}}=\pi_{\theta}(\cdot\mid x_{i},y_{i,<t})`$ and
$`p_{i,t}^{\mathrm{T}}=\pi_{\phi}(\cdot\mid x_{i},z_{i},y_{i,<t})`$
denote the next-token distributions of the student and teacher,
respectively. Following MiniLLM ([Gu et al., 2024](#bib.bib15)), we
minimize the reverse KL divergence over the vocabulary $`\Omega`$ shared
by the teacher and student:

|  |  |  |  |
|----|----|----|----|
| (8) |  |
``` math
D_{i,t}=D_{\mathrm{KL}}\left(p_{i,t}^{\mathrm{S}}\,\middle\|\,\operatorname{sg}\left[p_{i,t}^{\mathrm{T}}\right]\right)=\sum_{a\in\Omega}p_{i,t}^{\mathrm{S}}(a)\log\frac{p_{i,t}^{\mathrm{S}}(a)}{\operatorname{sg}\left[p_{i,t}^{\mathrm{T}}(a)\right]},
``` |  |

where $`D_{\mathrm{KL}}(\textperiodcentered)`$ denotes the KL
divergence, and $`\operatorname{sg}[\cdot]`$ denotes the stop-gradient
operator.

#### Insight internalization and joint optimization.

Distillation is applied to the initial routing response of each
trajectory. Let $`\mathcal{T}_{i}^{\mathrm{ana}}`$ and
$`\mathcal{T}_{i}^{\mathrm{plan}}`$ denote the positions of
student-generated content tokens within the \<analysis\> and \<plan\>
tags, respectively, excluding formatting and environment tokens. The OPD
objective minimizes their weighted distillation losses:

|  |  |  |  |
|----|----|----|----|
| (9) |  |
``` math
\mathcal{L}_{\mathrm{OPD}}(\theta)=\frac{\sum_{i}\sum_{t\in\mathcal{T}_{i}^{\mathrm{plan}}}D_{i,t}}{\sum_{i}|\mathcal{T}_{i}^{\mathrm{plan}}|}+\alpha\frac{\sum_{i}\sum_{t\in\mathcal{T}_{i}^{\mathrm{ana}}}D_{i,t}}{\sum_{i}|\mathcal{T}_{i}^{\mathrm{ana}}|},
``` |  |

where $`\alpha`$ controls the contribution of the analysis tokens.

The final joint training objective is defined as:

|  |  |  |  |
|----|----|----|----|
| (10) |  |
``` math
\mathcal{L}(\theta)=\mathcal{L}_{\mathrm{RL}}(\theta)+\lambda_{D}\mathcal{L}_{\mathrm{OPD}}(\theta)+\beta\mathcal{L}_{\mathrm{KL}}(\theta),
``` |  |

where $`\lambda_{D}`$ and $`\beta`$ are the coefficients for
distillation and KL regularization, respectively. The updated policy
$`\pi_{\theta}`$ continues to generate execution trajectories that
inform subsequent insight refinement, closing the recursive feedback
loop among execution, insight synthesis, and policy internalization.

synthesis for QA. All routing methods share the same resources and are
provided with identical descriptions of available LLMs, collaboration
modes, and skills wherever applicable.

We compare five categories of methods. (I) Vanilla LLMs: Direct

2025](#bib.bib59)), ReCal ([Yu et al., 2026](#bib.bib54)), and
xRouter ([Qian et al., 2025](#bib.bib37)). (IV) Multi-Agent Routing:

## 6. Conclusion

We presented EvoRouter, a framework that learns to jointly configure
heterogeneous LLM-based MAS from execution experience. Combining
cost-aware reinforcement learning with on-policy distillation, EvoRouter
internalizes cross-task configuration insights and trajectory feedback
into its routing policy, enabling deployment without privileged
feedback. Across 21 datasets spanning seven domains, EvoRouter achieves
higher average accuracy at lower computational cost than the evaluated
routing baselines in both in-domain and out-of-domain settings. Our
current framework is designed for cloud-based agent services. Future
work will extend EvoRouter to resource-constrained edge environments
through coordinated cloud–edge routing that accounts for device
heterogeneity and inter-agent communication overhead.

## Appendix A Experimental Details

### A.1. Resource

All LLMs in the pool use temperature 1.0 and maximum output length 1,024
tokens (4,096 for code tasks). For multimodal tasks, models lacking
multimodal support receive a fixed placeholder declaring image
invisibility, forcing them to answer solely based on text. In
generalization experiments
(Section [5.4](#S5.SS4 "5.4. Generalization Analysis ‣ 5. Experiments ‣ EvoRouter: Cost-Efficient Multi-Agent Routing via Insight-Guided On-Policy Distillation")),
the model pool comprises Qwen3.8-Flash, Kimi-K2.8-Preview, and
Qwen3.8-Max; the collaboration mode pool comprises Self-Consistency and
Hierarchical; and the skill pool contains skills unused elsewhere.

Details of the collaboration modes are as follows:

- •
  IO: A single agent answers in a single turn.
- •
  CoT: A single agent reasons step-by-step across multiple turns before
  delivering the final answer.
- •
  Reflection: A single agent iteratively reflects on its previous
  response to generate a revised answer.
- •
  Self-Consistency: A single agent is invoked multiple times
  independently. A subsequent invocation then inspects all candidate
  answers, evaluates consistency, resolves discrepancies, and aggregates
  the final result.
- •
  Chain: Agents are activated sequentially, each receiving its
  predecessor’s output. When an agent exhausts its allocated reasoning
  turns, the next agent is triggered.
- •
  FullConnected: All agents are activated concurrently, receiving peers’
  responses from the prior turn. Final-turn responses are routed to the
  router to synthesize the answer.
- •
  Debate: All agents run concurrently, critiquing peers or rebutting
  critiques in subsequent turns. Final-turn responses are routed to the
  router for answer synthesis.
- •
  Hierarchical: The initial agent plans task decomposition and
  scheduling, intermediate agents execute independently in parallel, and
  the final agent synthesizes findings. Turn limits govern reasoning
  turns per agent.

Certain collaboration modes impose cross-configuration constraints. For
example, if the router pairs CoT with two agents, the MAS plan is
rejected (as CoT admits at most one agent) and marked incorrect.

### A.2. Dataset

We construct a dataset comprising 12,800 questions across five domains,
as described in
Section [5.1](#S5.SS1 "5.1. Experimental Setup ‣ 5. Experiments ‣ EvoRouter: Cost-Efficient Multi-Agent Routing via Insight-Guided On-Policy Distillation").
The dataset is partitioned into 10,500 training, 1,000 development, and
1,300 test questions. For out-of-domain evaluation, we use 175 questions
from the LiveCodeBench ([Jain et al., 2025](#bib.bib22)) and 200 from
the BBH-LD ([Suzgun et al., 2023](#bib.bib43)).

For each training task domain, we set a shared budget in our cost units.
We calibrate it from pre-collected successful traces by computing the
25th percentile of trace costs for each question, taking the median
across questions in the domain, and adding a 15% margin, with a minimum
budget of 512. Budgets vary across domains (as well as trace
collections); for example, the budget for the math tasks is 12,374.00,
and 5,722.02 for commonsense tasks.

### A.3. Training

We evaluate three router backbones: Qwen3-4B, Qwen3-8B, and
Llama-3.1-8B, yielding EvoRouter-4B, EvoRouter-8B, and
EvoRouter-LLaMa-8B, respectively, through our iterative training
framework. All experiments run on 8 NVIDIA A100 80GB GPUs. Task sets
across SFT, RL, and evaluation are mutually disjoint.

For supervised initialization, DeepSeek-V4-Pro serves as a bootstrap
router to collect trajectories, yielding 2,000 filtered instances to
fine-tune each backbone for 2 epochs. In subsequent training, we use a
batch size of 8 with 16 rollouts per question and a learning rate of
$`3\times 10^{-6}`$, setting $`\beta=0.001`$, $`c_{\mathrm{max}}=0.1`$,
$`\lambda_{D}=0.03`$, and $`\alpha=0.25`$. For on-policy distillation,
Qwen3-32B and Llama-3.1-70B serve as teachers for the Qwen and Llama
backbones, respectively. DeepSeek-V4-Pro also acts as the insight
distillation expert, leveraging its context window and reasoning
capabilities to analyze dozens of trajectories simultaneously, but does
not directly supervise the student. Finally, we cap insight capacity at
$`|\mathcal{I}|\leq 8`$ and total length at 6,144 characters to limit
context overhead.

### A.4. Evaluation

Across all evaluations, we report accuracy averaged over three
independent runs, rounding the mean number of correct predictions to the
nearest integer before normalizing by the total number of test
instances. For baselines without native model selection, we fix the
backbone to GLM-5, the model with the largest active parameter in our
pool, to ensure strong reasoning capability across tasks. The baselines
evaluated in
Table [2](#S4.T2 "Table 2 ‣ Group-relative policy updates. ‣ 4.3. Cost-Aware Policy Optimization ‣ 4. Method ‣ EvoRouter: Cost-Efficient Multi-Agent Routing via Insight-Guided On-Policy Distillation")
are summarized below:

- •
  Vanilla LLMs: Directly use the corresponding LLM to generate responses
  in a single-turn interaction.
- •
  RouteLLM ([Ong et al., 2025](#bib.bib34)): A classifier-based binary
  routing method that chooses between GLM-5 and Qwen3.5-35B-A3B for each
  query based on the predicted win rate of the stronger model against a
  fixed threshold.
- •
  GraphRouter ([Feng et al., 2025](#bib.bib12)): Models relations among
  tasks, queries, and candidate LLMs with a heterogeneous graph,
  employing a graph neural network to select the suitable model.
- •
  ICL-Router ([Wang et al., 2026a](#bib.bib45)): Constructs capability
  representations of candidate models from historical performance and
  routes each query to the model predicted to be the best.
- •
  RouterDC ([Chen et al., 2024](#bib.bib4)): A dual contrastive learning
  based routing approach that selects an LLM based on the similarity
  between the query and candidate capability vectors.
- •
  Router-R1 ([Zhang et al., 2025](#bib.bib59)): An RL-based agentic
  routing method where the router actively dispatches sub-tasks to
  candidate models during reasoning and aggregates returned information
  to synthesize the final answer.
- •
  ReCal ([Yu et al., 2026](#bib.bib54)): An RL-based agentic routing
  method following routing behaviors similar to Router-R1 ([Zhang et
  al., 2025](#bib.bib59)), enhancing policy optimization under
  multi-task and multi-objective settings via reward decomposition and
  calibration.
- •
  xRouter ([Qian et al., 2025](#bib.bib37)): A multi-turn routing method
  that allows the router to answer directly, invoke candidate models, or
  select an existing model response as the final answer.
- •
  MAS-Orchestra ([Ke et al., 2026](#bib.bib25)): Encapsulates diverse
  collaborative reasoning patterns into callable modules coordinated by
  an orchestrator, using GLM-5 as the LLM backbone.
- •
  OrchMAS ([Feng et al., 2026](#bib.bib13)): Dynamically instantiates
  agent roles and task prompts while advancing problem-solving via
  runtime agent feedback, adopting GLM-5 as the backbone.
- •
  DAAO ([Su et al., 2026](#bib.bib42)): Dynamically selects reasoning
  operators and their LLM backbones based on predicted problem
  difficulty, constructing an adaptive hierarchical collaborative
  workflow for each query.
- •
  MasRouter ([Yue et al., 2025b](#bib.bib57)): Employs cascaded
  controllers to select collaboration modes, agent counts, roles, and
  LLM backbones, instantiating tailored MAS per query.
- •
  RCR-Router ([Liu et al., 2026](#bib.bib31)): Allocates shared memory
  to agents based on task-role relevance, where all agents are backed by
  GLM-5 and iteratively analyze and answer queries according to a
  predefined topology.
- •
  AgentRouter ([Zhang et al., 2026b](#bib.bib60)): Employs a knowledge
  graph to characterize relationships among queries, entities, and
  candidate agents, using a GNN to compute a weighted aggregation of
  responses across model-strategy combinations.
- •
  Uno-Orchestra ([Cui et al., 2026](#bib.bib7)): An agentic
  orchestration method based on SFT and RL that dispatches subtasks to
  compatible model-primitive pairs, iteratively delegating or
  synthesizing the answer based on execution feedback.

## Appendix B Derivation of Inference Computational Cost

Measuring computational overhead via commercial API pricing often fails
to reflect actual resource consumption, as pricing fluctuates across
service providers and over time. For clarity and conciseness, we instead
model a standard decoder-only Mixture-of-Experts model $`m`$ with $`L`$
layers and hidden dimension $`D`$, where each layer activates $`k`$
equally sized routed experts. Let $`P_{\mathrm{sh}}`$ denote the
parameter count of the always-active backbone matrices—including
attention projections, routers, and shared experts—and
$`P_{\mathrm{exp}}`$ denote that of a single routed expert. The active
matrix parameter count per token is then
$`A_{m}=P_{\mathrm{sh}}+LkP_{\mathrm{exp}}`$, as unselected experts
incur no matrix operations ([Abnar et al., 2025](#bib.bib1); [Jiang et
al., 2025](#bib.bib23)).

Counting one multiplication and one addition as one FLOP each, parameter
matrix operations incur a dominant cost of $`2A_{m}`$ FLOPs per token.
Under standard multi-head causal attention, attending to $`t`$ positions
requires an additional $`4LDt`$ FLOPs for query-key dot products and
attention-weighted value aggregation ([Wang et al., 2025](#bib.bib46)).
For a model invocation with input length $`n^{\mathrm{in}}`$, output
length $`n^{\mathrm{out}}`$, and total sequence length
$`N=n^{\mathrm{in}}+n^{\mathrm{out}}`$, let $`F_{m}`$ denote the total
computational cost and $`\mathcal{R}_{m}`$ capture all remaining
operations. Assuming KV caching within each request and counting causal
attention pairs, we obtain:

|  |  |  |  |  |
|----|----|----|----|----|
| (11) |  | $`\displaystyle F_{m}`$ | $`\displaystyle\approx 2A_{m}N+4LD\sum_{t=1}^{N}t+\mathcal{R}_{m}`$ |  |
|  |  |  | $`\displaystyle=2A_{m}N+2LDN(N+1)+\mathcal{R}_{m}.`$ |  |

Since parameter matrix operations dominate overall computation
(exceeding 95% of total FLOPs in our experiments), we omit both the
attention interaction term and $`\mathcal{R}_{m}`$, yielding the FLOPs
proxy $`\widehat{F}_{m}=2A_{m}(n^{\mathrm{in}}+n^{\mathrm{out}})`$.
Taking the active parameter count of the smallest model in our LLM pool,
Qwen3.5-35B-A3B ($`A_{0}=3\times 10^{9}`$), as the reference baseline,
we define $`2A_{0}`$ FLOPs as one cost unit. Let
$`\mathcal{I}_{W}(\tau)`$ denote the index set of worker calls along
trajectory $`\tau`$, where the $`j`$-th call invokes model $`m_{j}`$
with input length $`n_{j}^{\mathrm{in}}`$, output length
$`n_{j}^{\mathrm{out}}`$, and estimated cost $`\widehat{F}_{j}`$. The
normalized trajectory cost is then defined as:

|  |  |  |  |  |
|----|----|----|----|----|
| (12) |  | $`\displaystyle C(\tau)`$ | $`\displaystyle\mathrel{:=}\frac{\sum_{j\in\mathcal{I}_{W}(\tau)}\widehat{F}_{j}}{2A_{0}}`$ |  |
|  |  |  | $`\displaystyle=\sum_{j\in\mathcal{I}_{W}(\tau)}\frac{A_{m_{j}}}{A_{0}}\bigl(n_{j}^{\mathrm{in}}+n_{j}^{\mathrm{out}}\bigr).`$ |  |

In practice, we approximate $`A_{m}`$ using the active parameter counts
reported by model providers. For dense models, this equals the total
parameter count, since all weights participate in each autoregressive
forward pass. Active parameter counts for all evaluated models are
summarized in
````
