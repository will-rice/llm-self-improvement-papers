# Globe: Evolving Structured Agentic Memory for E-commerce Product Optimization in Generative Search

Hyunseo Kim    Suil Choe    Sukkyoung So    Daeyeon Yi Affiliation: AI
Lab, CTO Division, LG Electronics, South Korea
Affiliation: {hyunseo00.kim, suil.choe, sukkyoung.so,
daeyeon.yi}@lge.com

###### Abstract

Optimizing product listings for generative search requires language
agents not only to rewrite effectively but also to continually
self-improve by retaining successful strategies across diverse
categories. However, existing approaches often treat structured listings
as free-form text, leaving effective strategies implicit in prompts,
search trajectories, or rewritten outputs rather than accumulating them
as a reusable agentic memory. To address this limitation, we introduce
Globe, an agentic framework that drives continual self-improvement by
storing optimization knowledge in an evolving handbook of explicit,
field-scoped behaviors. In each episode, an Editor applies relevant
behaviors and receives rank-based feedback, which a Reflector converts
into behavior updates. Crucially for dependable execution in real-world
settings, a Moderator removes redundant proposals, a Curator commits
accepted changes, and consistently harmful behaviors are deactivated.
This cycle transforms episodic feedback into a persistent, field-scoped
optimization memory. Experiments show that structured behaviors
outperform monolithic prompt optimization, while feedback-driven
evolution and moderation further improve effectiveness and reduce
downside risk. The learned behaviors also remain effective on unseen
product categories, suggesting that agentic memory evolution supports
interpretable and transferable product optimization.

## 1 Introduction

![Refer to caption](2610.23709v1/introduction.png)

Figure 1: Comparison between monolithic prompt optimization and Globe’s
structured handbook optimization. A generic rewrite prompt performs an
undifferentiated text transformation, whereas each Globe behavior
specifies both a concrete editing operation and its permitted target
field, enabling constrained reuse across products.

Language agents increasingly improve themselves not by updating weights,
but by accumulating experience in an external memory that is continually
refined through feedback ([Shinn et al., 2023](#bib.bib9); [Wang et al.,
2023](#bib.bib25)). Building on these advances, agent-centric frameworks
are expanding into e-commerce, as large language models (LLMs) shift
search toward generative engines that directly compare and rank products
by reasoning over rich textual contexts ([Li et al., 2024](#bib.bib15);
[Sun et al., 2023](#bib.bib16); [Hou et al., 2024](#bib.bib17); [Kim et
al., 2025b](#bib.bib26)). In this environment, an agent optimizing a
product listing must shift from conventional search engine optimization
methods ([Davis, 2006](#bib.bib23); [Gudivada et al., 2015](#bib.bib24))
to strategic content structuring, as its success heavily depends on how
favorably the downstream generative engine interprets the presented
information.

A key challenge in this real-world setting lies in the structured nature
of e-commerce product data. Product listings are not arbitrary free-form
documents but consist of distinct fields, such as titles, feature
bullets, and descriptions, each serving a different functional role.
Nevertheless, prior methods commonly optimize a listing through a single
prompt that rewrites the document as a whole ([Bagga et al.,
2025](#bib.bib4); [Yuan et al., 2026](#bib.bib6)). This monolithic
approach lacks structural boundaries, treating optimization as
unstructured text generation. As illustrated in
Figure [1](#S1.F1 "Figure 1 ‣ 1 Introduction ‣ Globe: Evolving Structured Agentic Memory for E-commerce Product Optimization in Generative Search"),
relying on generic prompt optimization leads to critical structural
errors, because the agent cannot restrict specific editing operations to
their appropriate target fields.

Beyond this lack of structural control, current approaches fail to
generalize successful strategies across multiple optimization episodes.
Even if a specific rewrite tactic successfully improves a product’s rank
in one category, monolithic prompt optimization cannot abstract this
success into a reusable principle. As further demonstrated in
Figure [1](#S1.F1 "Figure 1 ‣ 1 Introduction ‣ Globe: Evolving Structured Agentic Memory for E-commerce Product Optimization in Generative Search"),
when a generic prompt attempts to transfer a durability strategy to new
categories, it fails to adapt the context, forcing overfitted keywords
(e.g., applying "rubber insulation" to leather boots) rather than
grounding the edit in existing product facts. Consequently, effective
strategies must be repeatedly rediscovered, making optimization
dependent on fragmented and costly trial and error. Product optimization
therefore requires an explicit agentic memory mechanism that transforms
transient ranking outcomes into persistent, generalizable editing
knowledge ([Shinn et al., 2023](#bib.bib9); [Zhao et al.,
2024](#bib.bib10)).

To address these limitations, we introduce GLOBE (GeneraLizable
Optimization Behavior Evolution), an agentic framework that represents
product optimization knowledge as a structured behavior handbook. Rather
than relying on a single unconstrained rewrite instruction, Globe
decomposes optimization into explicit and reusable editing behaviors.
Each behavior specifies a concrete editing operation, the listing fields
in which the operation may be applied, and metadata summarizing its
historical ranking outcomes. For example, a behavior may instruct the
agent to specify the material of a likely wear point, strictly limiting
this addition to the feature field. This formulation separates what
should be changed from where the change is permitted, providing a more
interpretable and structurally bounded interface for product-listing
optimization.

Globe further transforms transient ranking feedback into persistent
optimization knowledge through an iterative deployment-and-evolution
cycle. The current handbook is repeatedly applied to batches of
query-product pairs, producing episode-level feedback from the resulting
rank changes. Recurring success and failure patterns are then used to
refine the handbook, after which the updated behaviors are redeployed in
subsequent batches. By repeatedly alternating between handbook
deployment and feedback-driven refinement, Globe converts
episode-specific ranking outcomes into persistent and reusable
optimization knowledge.

This formulation provides two complementary advantages. First,
field-scoped behaviors explicitly specify both the editing operation and
the product fields in which it may be applied, making individual
strategies more structured and inspectable. Second, the evolving
handbook preserves and reuses knowledge acquired from past ranking
episodes rather than discarding it after each rewrite. We therefore
investigate whether field-scoped behavior representations improve
ranking effectiveness, whether feedback-driven handbook evolution
reduces harmful outcomes, and whether the learned optimization knowledge
transfers to unseen product categories.

Our main contributions are as follows:

- •
  We propose Globe, an agentic product-optimization framework that
  maintains reusable optimization knowledge as a structured memory of
  field-scoped behaviors.
- •
  We introduce a feedback-driven evolution mechanism that converts
  episode-level ranking outcomes into persistent editing knowledge,
  while filtering redundant and consistently harmful behaviors.
- •
  We demonstrate that Globe improves ranking effectiveness and
  stability, with learned behaviors transferring to unseen product
  categories and ranking models.

## 2 Related Work

### 2.1 Generative Engine Optimization for E-commerce

Generative Engine Optimization (GEO) aims to improve the visibility of
target items in generative search by modifying their textual
representations. Initial approaches showed that strategically injected
text sequences can influence item exposure and output rankings ([Kumar
and Lakkaraju, 2024](#bib.bib2); [Jin et al., 2026](#bib.bib5)).
Subsequent prompt-based methods formulate GEO as document rewriting,
using LLMs to modify content according to the inferred preferences of a
target generative engine ([Bagga et al., 2025](#bib.bib4); [Wu et al.,
2025](#bib.bib3)). Recent agentic frameworks further automate this
process by iteratively searching for effective document-modification
strategies ([Yuan et al., 2026](#bib.bib6)). Despite this progression,
existing approaches largely optimize documents through free-form,
document-level generation, offering limited control over individual
fields of structured product listings. Moreover, effective strategies
typically remain embedded in prompts, search trajectories, or rewritten
outputs rather than being retained as explicit and reusable knowledge.

### 2.2 Feedback-Driven Knowledge Evolution

Effective optimization requires systems to not only generate
high-quality outputs but also learn from past successes and failures to
avoid repeatedly rediscovering the same strategies. Driven by this need,
a growing line of research studies how feedback can be transformed from
a transient correction signal into reusable knowledge ([Kim et al.,
2025a](#bib.bib27)). Early self-refinement methods use self- or
peer-generated critiques to revise the current output ([Madaan et al.,
2023](#bib.bib7); [Schick et al., 2022](#bib.bib8)). Cross-episode
approaches go beyond local revision by abstracting successful and failed
trajectories into reusable reflections or lessons ([Shinn et al.,
2023](#bib.bib9); [Zhao et al., 2024](#bib.bib10)). At the system level,
automatic prompt optimizers use natural-language critiques, textual
feedback, or trajectory-level reflection to revise the instructions
governing future executions ([Pryzant et al., 2023](#bib.bib20);
[Yuksekgonul et al., 2024](#bib.bib21); [Agrawal et al.,
2026](#bib.bib19)). Recent memory-centric systems further externalize
such abstractions into persistent handbooks, evolving playbooks, or
learned memory architectures ([Didolkar et al., 2025](#bib.bib11);
[Zhang et al., 2025](#bib.bib12); [Xiong et al., 2026](#bib.bib13)).
Together, these works demonstrate a progression from local output
correction to persistent knowledge evolution, but largely focus on
open-ended reasoning, coding, or planning. In contrast, structured
product optimization requires reusable knowledge to be field-scoped and
learned from indirect, relative ranking feedback.

## 3 Proposed Method: Globe

![Refer to caption](2610.23709v1/method.png)

Figure 2: Overview of the Globe framework. Each iteration deploys the
active handbook $`\mathcal{H}_{n}`$ over a batch of $`K`$ query-product
pairs: the editor rewrites the target listing and the ranker returns
episode-level rank feedback. The Reflector then proposes behavior
additions or modifications, the Moderator removes redundant proposals,
and the Curator commits the survivors into $`\mathcal{H}_{n+1}`$, which
replaces $`\mathcal{H}_{n}`$ as the handbook deployed over the next
batch. Repeating this deployment-and-evolution cycle accumulates
episodic feedback into persistent editing knowledge.

Globe maintains a structured agentic memory of reusable
product-optimization behaviors through an iterative
deployment-and-evolution cycle, illustrated in
Figure [2](#S3.F2 "Figure 2 ‣ 3 Proposed Method: Globe ‣ Globe: Evolving Structured Agentic Memory for E-commerce Product Optimization in Generative Search").
At iteration $`n`$, the current handbook $`\mathcal{H}_{n}`$ is deployed
across a batch of $`K`$ query-product pairs. Each deployment produces an
episode that records the rewritten listing, the behaviors applied by the
editor, and the resulting rank change. After the batch is completed,
Globe aggregates these episodes to refine the handbook, producing
$`\mathcal{H}_{n+1}`$. The updated handbook is then deployed in the next
iteration, allowing optimization knowledge from individual ranking
outcomes to accumulate as explicit, reusable editing behaviors.

#### Task Formulation.

Given a user query $`q`$ and a candidate product set
$`\mathcal{P}=\{p_{1},\ldots,p_{m}\}`$, a generative ranking model
$`\mathcal{M}`$ orders the products according to their relevance to
$`q`$. We denote the rank of product $`p`$ by
$`r_{\mathcal{M}}(q,\mathcal{P},p)`$, where a smaller value indicates a
higher position.

Unlike free-form documents, each product $`p`$ is represented as a
structured listing consisting of fields such as title, features, and
description:

|     |     |     |
| --- | --- | --- |
|     |

````math
p=\left(p^{\mathrm{title}},p^{\mathrm{features}},p^{\mathrm{description}}\right).
``` |  |

For a target product $`p_{t}`$, Globe generates a rewritten listing
$`p^{\prime}_{t}`$ by applying editing behaviors whose permitted fields
are compatible with the product schema. Let $`\mathcal{P}^{\prime}`$
denote the candidate set in which $`p_{t}`$ is replaced by
$`p^{\prime}_{t}`$. We measure the episode-level outcome using rank
gain:

|  |  |  |
|----|----|----|
|  |
``` math
g(q,p_{t})=r_{\mathcal{M}}(q,\mathcal{P},p_{t})-r_{\mathcal{M}}(q,\mathcal{P}^{\prime},p^{\prime}_{t}).
``` |  |

The goal is to learn a handbook that produces positive rank gains across
diverse query-product contexts while limiting harmful ranking outcomes.

### 3.1 Behavior Handbook

A behavior is a reusable, field-scoped editing strategy for product
listings. Each behavior stores an identifier, a name, an editing
instruction, permitted target fields, conflicting behaviors, and
feedback metadata. The instruction defines a concrete editing operation,
such as making the product type explicit or foregrounding a
query-relevant specification. The target-field set specifies where the
operation may be applied, with
$`\mathrm{targets}(b)\subseteq\{\mathrm{title},\mathrm{features},\mathrm{description}\}`$.
The conflicts field records behaviors that should not be applied
together. Rather than strictly filtering these rules, this field serves
as a soft constraint that instructs the editor to avoid applying
conflicting behaviors simultaneously. Finally, the feedback metadata
tracks the number of helpful, harmful, and neutral outcomes associated
with behavior $`b`$, denoted by $`h^{+}(b)`$, $`h^{-}(b)`$, and
$`h^{0}(b)`$, respectively. We summarize the empirical utility of each
behavior using the score $`s(b)=h^{+}(b)-h^{-}(b)`$. Let
$`n(b)=h^{+}(b)+h^{-}(b)+h^{0}(b)`$ denote the number of episodes in
which the behavior has been applied. To ensure that newly introduced
behaviors receive sufficient opportunities for evaluation, a behavior
$`b`$ remains active if it is still within its initial probation period
($`n(b)<N_{\min}`$) or maintains a non-negative empirical score
($`s(b)\geq 0`$). Behaviors with negative scores after the probation
period remain stored for traceability but are excluded from the active
behavior pool used in subsequent iterations. Examples of deactivated
behaviors are listed in
Appendix [D](#A4 "Appendix D Deactivated Behaviors ‣ Globe: Evolving Structured Agentic Memory for E-commerce Product Optimization in Generative Search").

### 3.2 Handbook Deployment

At iteration $`n`$, the active behavior set
$`\mathcal{H}^{\mathrm{act}}_{n}`$ is deployed across a batch of $`K`$
query-product pairs. For each episode $`(q_{i},p_{i})`$, the LLM editor
receives the user query, the original structured product listing, and
the complete active behavior set as a strategy pool. The editor selects
the behaviors relevant to the current query-product context and
generates a rewritten target product $`p^{\prime}_{i}`$. Each selected
behavior may be applied only to the listing fields specified by its
target-field scope. The editor is also instructed to preserve the
original section structure and leave fields outside the permitted scopes
unchanged. To record behavior usage, the editor also reports the subset
of active behaviors applied during rewriting, denoted by
$`\mathcal{A}_{i}\subseteq\mathcal{H}^{\mathrm{act}}_{n}`$. Once the
rewritten target product replaces the original product, the ranking
model re-ranks the entire candidate set. Defining $`r_{i}`$ and
$`r^{\prime}_{i}`$ as the target product’s rank before and after
rewriting, respectively, the episode-level rank gain is calculated as:

|     |                             |     |
|-----|-----------------------------|-----|
|     |
       ``` math
       g_{i}=r_{i}-r^{\prime}_{i}.
       ```                          |     |

A positive value indicates rank improvement, a negative value indicates
degradation, and zero indicates no change.

The episode log therefore records the complete optimization trajectory,
including the query, original and rewritten listings, reported behavior
usage, and observed rank change. Each episode is stored as

|  |  |  |
|----|----|----|
|  |
``` math
e_{i}=\left(q_{i},p_{i},p^{\prime}_{i},\mathcal{A}_{i},r_{i},r^{\prime}_{i},g_{i}\right).
``` |  |

At this stage, Globe only records the episode outcome and does not
immediately update the handbook or behavior statistics. All episode logs
collected under $`\mathcal{H}_{n}`$ are aggregated after the $`K`$
episodes in the current batch have been completed.

### 3.3 Handbook Evolution

After collecting all $`K`$ episodes under the current handbook
$`\mathcal{H}_{n}`$, Globe aggregates their ranking outcomes and updates
the handbook at the batch level. For each episode, the $`h^{+}`$,
$`h^{-}`$, or $`h^{0}`$ count of every applied behavior is incremented
depending on whether the target product’s rank improves, degrades, or
remains unchanged, respectively. Because the individual contribution of
each behavior cannot be isolated, we assign the episode’s overall
directional outcome to all applied behaviors. The accumulated statistics
are then used to recompute each behavior’s score and active status for
the next iteration. Using the aggregated episode logs and updated
behavior statistics, Globe evolves the handbook through three
components: 1) Reflector, 2) Moderator, and 3) Curator.

#### Reflector.

The Reflector analyzes recent episode logs together with the current
handbook to identify recurring success and failure patterns. Rather than
rewriting the handbook as unrestricted text, it proposes structured
delta operations that either add a new behavior or modify an existing
one. An Add operation is proposed when the observed pattern is not
adequately covered by the current handbook. A Modify operation refines
an existing behavior by clarifying its instruction, application
condition, or permitted target fields. The Reflector does not directly
delete behaviors, since behaviors associated with consistently harmful
outcomes are excluded through the active-status criterion while
remaining stored for traceability.

#### Moderator.

The Moderator filters Reflector proposals before they are committed to
the handbook. It performs (1) embedding-based deduplication to reject
proposals that are semantically too similar to existing active
behaviors. A proposed behavior $`b_{\mathrm{new}}`$ is rejected when

|  |  |  |
|----|----|----|
|  |
``` math
\max_{b\in\mathcal{H}^{act}_{n}}\operatorname{sim}\left(E(b_{\mathrm{new}}),E(b)\right)>\tau,
``` |  |

where $`E(\cdot)`$ denotes the behavior embedding function and
$`\operatorname{sim}(\cdot,\cdot)`$ denotes cosine similarity. The
remaining proposals undergo (2) functional deduplication, in which an
LLM compares their application conditions and intended editing
operations with those of existing behaviors. When substantial overlap is
detected, the existing behavior is retained, since unrestricted
rewriting of committed behaviors would make the handbook fluctuate with
the noise of individual batches.

#### Curator.

The Curator deterministically commits the proposals accepted by the
Moderator. New behaviors receive stable identifiers and zero-initialized
feedback metadata, while modified behaviors are updated in place,
advancing their version but retaining their accumulated metadata. The
Curator then constructs the next handbook $`\mathcal{H}_{n+1}`$ and
determines its active behavior pool using the accumulated feedback
statistics. The updated handbook is applied to the next batch of
query-product pairs, thereby repeating the rewriting, feedback
collection, and handbook evolution cycle.

### 3.4 Training and Inference

Starting from a seed handbook $`\mathcal{H}_{1}`$ containing nine
general GEO heuristics, Globe repeats the deployment-and-evolution cycle
for $`N`$ training batches. The handbook and its active behavior pool
remain fixed within each batch. Feedback collected during the batch
affects behavior status and handbook contents only in the subsequent
iteration, ensuring that all episodes in the same batch are generated
under a consistent handbook version. After the final training batch, the
handbook is frozen. At test time, the active behaviors from the frozen
handbook are supplied to the editor using the same deployment procedure
as during training. The editor selects and applies behaviors for each
query-product pair, but no feedback statistics or handbook contents are
updated during evaluation.

### 4.1 Experimental Setup

#### Dataset.

We evaluate Globe using the E-GEO benchmark ([Bagga et al.,
2025](#bib.bib4)), which pairs real-world shopping queries from Reddit
(r/BuyItForLife) with structured Amazon product listings. We categorize
the products into six macro-categories: Home & Kitchen, Fashion &
Accessories, Electronics, Tools & DIY, Sports & Outdoors, and Health &
Beauty. We use 1,000 training queries to construct the behavior handbook
and a disjoint, category-balanced set of 900 queries (150 per category)
for evaluation. The handbook remains frozen during testing.

#### Baselines.

We evaluate Globe against the following configurations.¹¹ 1 Recent
self-evolving agents are not directly applicable as our baselines
because they are fundamentally designed for free-form document
optimization, rendering field-scoped constraints incompatible with their
core exploration mechanism. Prompt Opt. applies a single monolithic
rewriting instruction following the prompt-based E-GEO setting ([Bagga
et al., 2025](#bib.bib4)). Static HB utilizes a fixed, non-evolving
handbook of 9 generic rewrite rules ([Aggarwal et al.,
2023](#bib.bib1)). GLOBE w/o Mod. evolves the handbook without
Moderator, using episode feedback but commits Reflector proposals
without redundancy filtering.

#### Evaluation Metrics.

We evaluate system performance using four metrics. Mean Rank Gain (MRG)
and Success Rate (SR) measure the average position improvement and the
frequency of successful optimizations, respectively. To evaluate
stability, we evaluate Downside Risk (DSR), which applies a quadratic
penalty to rank degradations to capture the severity of harmful
rewrites. Finally, Category Variance (CV) measures the variance of MRG
across the six categories, where a lower score indicates generalized
performance. More details are presented in
Appendix [B.2](#A2.SS2 "B.2 Metrics ‣ Appendix B Experimental Details ‣ Globe: Evolving Structured Agentic Memory for E-commerce Product Optimization in Generative Search").

#### Training Details.

The initial handbook contains 9 general GEO heuristics in
Appendix [B.4](#A2.SS4 "B.4 Seed Handbook ‣ Appendix B Experimental Details ‣ Globe: Evolving Structured Agentic Memory for E-commerce Product Optimization in Generative Search").
We process the 1,000 training queries in 10 batches of 100 query-product
pairs. Within each batch, the current handbook remains fixed while
product rewrites and episode logs are collected. After all episodes in
the batch have been completed, behavior statistics are accumulated and
the handbook is updated through the Reflector, Moderator, and Curator.
We use GPT-5.4²² 2 https://platform.openai.com/docs/models/gpt-5.4 for
all LLM-based components. Embedding-based deduplication uses
all-MiniLM-L6-v2 ([Reimers and Gurevych, 2019](#bib.bib18); [Wang et
al., 2020](#bib.bib22)) with a cosine-similarity threshold of
$`\tau=0.9`$. More details and prompts are provided in
Appendix [B](#A2 "Appendix B Experimental Details ‣ Globe: Evolving Structured Agentic Memory for E-commerce Product Optimization in Generative Search")
and [F](#A6 "Appendix F Prompts ‣ Globe: Evolving Structured Agentic Memory for E-commerce Product Optimization in Generative Search").

### 4.2 Effectiveness of the Behavior Handbook

To evaluate the effectiveness of our proposed handbook framework, we
examine the contribution of its core design components to the overall
performance of Globe. As shown in
Table [1](#S4.T1 "Table 1 ‣ 4 Experiment ‣ Globe: Evolving Structured Agentic Memory for E-commerce Product Optimization in Generative Search"),
the Static HB already achieves a substantial improvement over monolithic
prompt optimization in both ranking effectiveness and downside risk.
Because this baseline uses only the initial generic behaviors without
feedback-based updates, its improvement suggests that decomposing
optimization knowledge into explicit operations, together with field
scoping, provides a stronger foundation than the evaluated monolithic
prompt baseline. This result further shows that structured behavior
representation contributes substantially to Globe’s performance even
before feedback-driven evolution is introduced.

Feedback-based evolution further improves MRG and SR by extending the
handbook beyond its initial generic heuristics. However, the unmoderated
variant also produces a larger handbook and higher category variance,
suggesting that unrestricted accumulation may introduce redundant or
narrowly specialized behaviors. The increase in handbook capacity also
means that its improvement cannot be attributed entirely to
feedback-based learning. Evolution expands the available optimization
knowledge, but accumulating more behaviors does not necessarily produce
a more consistent handbook.

The full Globe addresses this limitation by filtering semantically
redundant and functionally overlapping proposals before they are
committed. Despite retaining fewer behaviors than the unmoderated
variant, it achieves stronger overall performance together with lower
DSR and CV. This pattern suggests that the Moderator acts as
handbook-level regularization, improving the composition of the
accumulated knowledge rather than simply expanding its size. Overall,
moderated evolution produces a more compact handbook with a better
balance between ranking effectiveness and consistency.

### 4.3 Impact of Feedback-driven Refinement

![Refer to caption](2610.23709v1/figures/image.png)

Figure 3: Performance of the trained handbook as the number of training
queries increases.

To examine whether iterative handbook evolution produces sustained
improvements beyond the final aggregate results, we trace ranking
performance as the number of training examples increases.

As shown in
Figure [3](#S4.F3 "Figure 3 ‣ 4.3 Impact of Feedback-driven Refinement ‣ 4 Experiment ‣ Globe: Evolving Structured Agentic Memory for E-commerce Product Optimization in Generative Search"),
MRG improves rapidly in the early stages of training, as feedback from
the initial batches reveals optimization patterns not covered by the
seed handbook, and then plateaus as additional batches are processed.
This trajectory indicates that feedback-based evolution progressively
enriches the handbook, but its benefits exhibit diminishing returns once
broadly useful behaviors have been acquired. DSR also declines overall,
though not monotonically, indicating that evolution gradually mitigates
harmful ranking outcomes. Together, these patterns suggest that once
frequently occurring optimization patterns have been observed, further
improvement depends less on training-set size than on broader coverage
of query intents and product contexts that provide genuinely new
feedback.

Additionally, to test whether refinement improves the specific behaviors
it targets, rather than merely coinciding with handbook growth, we
compare each modified behavior’s episode-level outcomes before and after
modification
(Appendix [C](#A3 "Appendix C Effect of modify Operations on Behavior-Level Outcomes ‣ Globe: Evolving Structured Agentic Memory for E-commerce Product Optimization in Generative Search")).
Among the nine under-performing behaviors that were modified, eight
showed improvements beyond a matched mean-reversion control (sign test,
p = 0.020), with an average adjusted increase of 5.3 percentage points
in helpful rate. In contrast, modifying behaviors that were already
performing above average yields no measurable gain. These results
suggest that modify operations act as targeted repairs for
under-performing behaviors rather than as indiscriminate handbook
expansion.

optimization knowledge rather than category-specific heuristics, we
conduct a leave-one-category-out (LOCO) evaluation. Specifically, for
each macro-category, we evolve a separate handbook using only the
training queries from the remaining five categories.
Figure [4](#S4.F4 "Figure 4 ‣ 4.4 Cross-Category Generalizability ‣ 4 Experiment ‣ Globe: Evolving Structured Agentic Memory for E-commerce Product Optimization in Generative Search")
compares the MRG improvement over the seed handbook for the LOCO models
and the fully trained Globe model. The result confirms that the benefits
of feedback-driven evolution are not strictly bound to domain-specific
exposure. The LOCO handbook consistently retains a substantial portion
of the aggregate improvements seen in the fully trained model.
Furthermore, the LOCO approach even surpasses full training in some
categories. These category-level differences suggest that training on
all categories can occasionally hurt a specific category through
cross-category interference, which we leave for future analysis.
Nevertheless, they show that in-category exposure is not a strict
prerequisite for generating effective rewrites. Together with the modest
overall MRG decrease of 0.07, these results suggest that feedback-driven
evolution extracts transferable optimization strategies that remain
effective without target-category exposure, avoiding category-specific
memorization.

optimization knowledge traceable by explicitly linking observed failures
to structural behavior updates and their downstream ranking
improvements.

## 5 Conclusion

We introduced Globe, a framework that maintains product-optimization
knowledge as explicit, field-scoped behaviors in an evolving handbook.
By converting ranking feedback into persistent and reusable editing
knowledge, Globe enables effective and interpretable optimization while
transferring to unseen product categories. More broadly, our findings
suggest that evolving structured behaviors offers a practical path
toward interpretable and transferable agentic memory for generative
search.

## Limitations

A key limitation is that the editor, ranker, Reflector, and Moderator
are all instantiated from the same model (GPT-5.4). Because the ranker
that provides the reward signal shares a model family with the
components optimized against it, the learned behaviors may partly
capture ranker-specific preferences rather than ranker-agnostic
optimization knowledge. We probe this with a cross-ranker evaluation in
Section [4.5](#S4.SS5 "4.5 Cross-Ranker Transferability ‣ 4 Experiment ‣ Globe: Evolving Structured Agentic Memory for E-commerce Product Optimization in Generative Search");
fully disentangling transferable knowledge from ranker-specific
artifacts remains future work. In addition, credit assignment over
behaviors is approximate. Since each episode yields a single rank change
for the entire rewrite, the episode’s directional outcome is attributed
to all applied behaviors rather than to each behavior’s individual
contribution
(Section [3.3](#S3.SS3 "3.3 Handbook Evolution ‣ 3 Proposed Method: Globe ‣ Globe: Evolving Structured Agentic Memory for E-commerce Product Optimization in Generative Search")).
A useful behavior can thus absorb harmful counts from co-applied
behaviors. These counts also rely on the editor’s self-reported list of
applied behaviors, which is not verified against the actual edits; an
audit of 50 training episodes judged by a separate LLM (Claude Opus 5)
found 88.3% of reported behaviors consistent with the edits made and few
applied behaviors left unreported. Batch-level aggregation and the
probation period mitigate this attribution noise but do not eliminate
it. More precise attribution, such as per-behavior counterfactual
rewrites, would incur substantially higher ranking costs per episode,
and we leave its efficient integration into the evolution loop to future
work. Moreover, because modified behaviors inherit their accumulated
feedback counts, the active-status criterion reacts slowly to a harmful
modify, and Globe currently has no mechanism to revert such a revision.
Beyond these signal-level limitations, while establishing a rigorous
performance ceiling with high-end models necessitates substantial
computational overhead during the multi-agent learning phase, our
inference stage remains highly efficient; the compiled handbook acts as
a static set of rules that applies verified behaviors in a single pass
without iterative optimization loops. Furthermore, distilling these
structured behaviors into smaller, open-source models via fine-tuning
represents a promising direction to drastically reduce future deployment
costs. Finally, as real-world e-commerce search algorithms are dynamic
and continuously updated, accumulated editing behaviors may experience
temporal degradation and require periodic re-evolution. Extending our
current text-only, field-scoped constraints to multimodal settings also
remains an open avenue for future research.

## Ethical Considerations

#### Factuality and Consumer Protection.

Methods for improving product visibility in generative search may be
used to unfairly influence rankings, and rank improvement should not be
interpreted as evidence of superior product quality. To reduce
misleading edits, Globe includes a factual-grounding behavior that
requires rewritten claims to remain supported by the original listing.
Nevertheless, language models may still introduce unsupported
implications or overstate product benefits. In practical deployments,
rewritten listings should therefore be verified against the original
listing and monitored for deceptive or exaggerated claims.

#### Model Bias and Accessibility.

The ranking feedback used by Globe may reflect model-specific
preferences rather than general shopper preferences. We partially
examine this risk through cross-ranker evaluation, but it cannot be
fully eliminated. In addition, evolving the handbook with high-capacity
language models may favor organizations with greater computational
resources. Reusing a frozen handbook and adapting it to smaller models
may help reduce this barrier.

## Appendix B Experimental Details

### B.1 Dataset and Evaluation Setup

Every method optimizes the same target product in the same competitive
context, and is scored against the same reference ranking. Each E-GEO
query ([Bagga et al., 2025](#bib.bib4)) comes with a candidate set of
ten Amazon listings, each serialized into the title, features, and
description fields. We sample one candidate uniformly at random as the
target product, store that index once, and reuse it for GLOBE, its
ablations, and all baselines; the pre-rewrite ranking
$`r_{\mathcal{M}}(q,\mathcal{P},p_{t})`$ is likewise computed once and
cached. This shared setup is intended to isolate differences arising
from the rewriting strategy.

We use 1,000 queries for handbook construction, processed as ten batches
of 100 pairs, and a disjoint set of 900 queries for evaluation. Category
labels are not provided by the benchmark at the query level. We first
use GPT-5.4-nano to construct a mapping table from the unique Amazon
main category values in the dataset to the six macro-categories. This
mapping table is applied deterministically to every candidate product.
Each query is assigned the majority macro-category among the candidates
in its product set. The evaluation set is built by sampling 150 queries
per macro-category. An episode is discarded when the editor returns no
usable rewrite or when the ranker’s output cannot be parsed into a
complete permutation of the ten candidates after all retries; such
failures are excluded rather than imputed, since scoring them as zero
gain would reward methods that fail more often. This leaves 887 of the
900 episodes for GLOBE, with 146 to 149 episodes per category, and
comparable counts for the baselines. GLOBE uses no validation set, as
the handbook is updated directly from training-batch feedback; only the
prompt-optimization baseline needs one, selecting its final prompt on
100 held-out validation queries evaluated after each epoch.

### B.2 Metrics

All four metrics are computed from the episode-level rank gain
$`g_{i}=r_{i}-r^{\prime}_{i}`$, where $`r_{i}`$ and $`r^{\prime}_{i}`$
are the target’s $`0`$-indexed positions before and after rewriting, and
all are macro-averaged over the six categories so that each category
contributes equally. Let $`\mathcal{C}`$ be the set of categories and
$`\mathcal{E}_{c}`$ the episodes of category $`c`$, with per-category
mean gain

|  |  |  |  |
|----|----|----|----|
|  |
``` math
\mathrm{MRG}_{c}=\frac{1}{|\mathcal{E}_{c}|}\sum_{i\in\mathcal{E}_{c}}g_{i}.
``` |  | (1) |

Mean Rank Gain measures how far the rewritten product moves up on
average:

|  |  |  |  |
|----|----|----|----|
|  |
``` math
\mathrm{MRG}=\frac{1}{|\mathcal{C}|}\sum_{c\in\mathcal{C}}\mathrm{MRG}_{c}.
``` |  | (2) |

Success Rate measures how often a rewrite helps at all, irrespective of
magnitude:

|  |  |  |  |
|----|----|----|----|
|  |
``` math
\mathrm{SR}=\frac{1}{|\mathcal{C}|}\sum_{c\in\mathcal{C}}\frac{1}{|\mathcal{E}_{c}|}\sum_{i\in\mathcal{E}_{c}}\mathbf{1}\left[g_{i}>0\right].
``` |  | (3) |

Downside Risk penalizes only how far gains fall below zero,
distinguishing harmful failures from beneficial volatility ([Zhou et
al., 2026](#bib.bib14)). Gains are clipped out and the remaining losses
squared, so that severe drops dominate a collection of small ones:

|  |  |  |  |
|----|----|----|----|
|  |
``` math
\mathrm{DSR}=\frac{1}{|\mathcal{C}|}\sum_{c\in\mathcal{C}}\frac{1}{|\mathcal{E}_{c}|}\sum_{i\in\mathcal{E}_{c}}\bigl[\min(0,g_{i})\bigr]^{2}.
``` |  | (4) |

Category Variance measures whether a handbook helps all categories
comparably or concentrates its benefit in a few:

|  |  |  |  |
|----|----|----|----|
|  |
``` math
\mathrm{CV}=\frac{1}{|\mathcal{C}|}\sum_{c\in\mathcal{C}}\bigl(\mathrm{MRG}_{c}-\mathrm{MRG}\bigr)^{2}.
``` |  | (5) |

MRG and SR are therefore effectiveness metrics, while DSR and CV
characterize risk and consistency; a method may raise MRG while also
raising DSR if its gains come from aggressive rewrites that occasionally
backfire.

### B.3 Implementation and Hyperparameters

All LLM components, Editor, Ranker, Reflector, and the
functional-deduplication stage of the Moderator use the gpt-5.4-global
Azure deployment (which corresponds to the standard, publicly available
GPT-5.4 model), with temperature set per role: $`0.5`$ for the Editor,
$`0.3`$ for the Ranker, $`0.7`$ for the Reflector so that it explores
diverse revisions, and $`0.0`$ for the Moderator so that redundancy
decisions are near-deterministic. Calls are capped at 5,000 completion
tokens, retried up to five times, and issued with at most 30 concurrent
requests. The editor receives the complete active behavior set as its
strategy pool rather than a retrieved subset, and the handbook is frozen
for the duration of a batch, so all 100 episodes of a batch run under
one handbook version.

A behavior stays active while its score is non-negative or while it is
still within a probation period of $`N_{\min}=5`$ applications.
Probation is needed because attribution is approximate: every behavior
reported as applied in an episode receives the same directional
feedback, so a useful behavior can absorb harmful counts from failures
it did not cause.

For embedding deduplication, we set the cosine-similarity threshold to
$`\tau=0.9`$. This value balances diversity and compactness: lower
values aggressively filter nuanced behaviors, while higher values allow
semantic redundancy to persist.
````
