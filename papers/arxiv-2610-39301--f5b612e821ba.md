###### Abstract

We present Youtu-Parsing-Omni, an omni-modal parser that converts
documents, images, audio, and video into structured records grounded in
space and time, providing a perception layer for agents that read,
locate, and cite evidence across modalities. Its design rests on one
encoder for every modality and one schema for every task.
Youtu-Omni-Encoder, initialized from a pre-trained language model to
strengthen text reading, encodes all modalities with shared weights in a
unified space-time coordinate system, and a few fusion layers let video
frames attend to concurrent audio, bringing cross-modal fusion and
temporal alignment into perception itself. OmniSchema unifies the
outputs of all ten parsing tasks, allowing a single self-evolving
post-training procedure, OmniSchema-Aware On-Policy Distillation (OSAD),
to provide a shared token-role-based objective across tasks. In each
round, the model is trained on its own rollouts against token-level
targets from a reference-conditioned copy of itself, which is then
refreshed with the trained weights, so that the parser and its
supervision co-evolve. With a single $`5`$ B-parameter checkpoint,
Youtu-Parsing-Omni achieves state-of-the-art performance on OmniDocBench
v1.6 ($`96.96`$ Overall) and leads all open-weight models on
OmniParsingBench ($`75.08`$ Avg.), with its advantage concentrated on
audio and video. It also achieves the best overall chart-parsing score
($`95.02`$) and the highest exact chemical-fingerprint agreement among
compared systems, and matches a dedicated optical-music model in
character-level transcription of typeset sheet music while staying far
ahead of general-purpose systems. Code and model weights are publicly
available.

## 1 Introduction

Large language model (LLM) agents increasingly act on information beyond
their own parameters: they retrieve evidence before
answering \[[1](#bib.bib1)\], call tools during
reasoning \[[2](#bib.bib2)\], and operate computers through the
screen \[[3](#bib.bib3)\]. Much of this information arrives not as plain
text but as documents, images, audio, and video. Having the model that
drives the agent consume such inputs directly is both _costly and hard
to audit_: each time the agent revisits the material, that model must
re-encode long sequences of visual and acoustic tokens, and an answer
drawn from raw pixels or waveforms does not by itself indicate which
region or interval supports it. _Omni-modal parsing_ addresses both
issues by converting each input once into a structured text record of
_what_ it contains and _where_ or _when_ each part occurs. Any LLM,
including a text-only one, can then read and act on this record and
trace a claim back to its source through the anchors it cites; parsing
thus provides a perception layer between non-text inputs and
language-model reasoning.

Current parsers, however, cover this range of inputs only partially.
Document parsers have become strong on standard pages \[[4](#bib.bib4),
[5](#bib.bib5), [6](#bib.bib6)\], but symbolic content such as chemical
structures and sheet music is still left largely to domain-specific
models \[[7](#bib.bib7), [8](#bib.bib8)\]. Beyond documents, parsing is
even less mature. Omni-modal models are built mainly for captioning and
question answering rather than for grounded, structured
output \[[9](#bib.bib9), [10](#bib.bib10)\], and parsing across images,
audio, and video has only recently been formulated as a task with a
dedicated benchmark \[[11](#bib.bib11)\]. As a result, different input
types are typically served by different models with different output
formats. Yet the target output is the same across input types, namely a
structured record whose units are anchored in space or time, which
suggests building a single parser with one output schema rather than one
specialist per input type.

Building such a parser raises two challenges. (C1) Joint perception
across modalities. Omni-modal models \[[10](#bib.bib10),
[12](#bib.bib12)\] and the omni-modal parser
Logics-Parsing-Omni \[[11](#bib.bib11)\] pair two separately pre-trained
encoders, one for vision and one for audio, an arrangement with three
consequences. First, each modality is encoded in isolation: no
cross-modal fusion takes place during perception, and the language model
must infer cross-modal relations from separate representations. Second,
the two encoders index time independently, so a frame and the sound of
the same instant do not share temporal positions within perception;
temporal alignment, where modeled, is deferred to the language
model \[[9](#bib.bib9)\]. Third, each encoder requires its own
architecture, training objective, and pre-training, so perception
parameters are not shared across modalities and each new modality
requires another tower. The first two consequences weigh more on parsing
than on captioning or question answering, because a structured parse
must state explicitly which content co-occurs across modalities and
when. Encoders shared across vision and audio have been
explored \[[13](#bib.bib13), [14](#bib.bib14), [15](#bib.bib15)\], but,
to our knowledge, not for grounded parsing. (C2) Joint optimization
across tasks. The same model must also be optimized jointly for content
accuracy, spatial and temporal grounding, and schema validity across ten
tasks whose output fields differ. Supervised fine-tuning (SFT) trains
only on reference prefixes, never on the prefixes the model itself
produces at inference \[[16](#bib.bib16), [17](#bib.bib17)\].
Reinforcement learning with verifiable rewards (RLVR), including Group
Relative Policy Optimization (GRPO) \[[18](#bib.bib18)\], is
increasingly used in document parsing \[[19](#bib.bib19),
[20](#bib.bib20), [6](#bib.bib6)\]; it trains on the model’s own outputs
but requires a scalar reward that is hard to define across such
heterogeneous criteria and provides only sequence-level feedback.
On-policy distillation supplies token-level targets on the model’s own
outputs using accessible teacher distributions \[[21](#bib.bib21)\].
Reference-conditioned self-distillation can instead obtain these targets
from the same model under an enriched context \[[22](#bib.bib22)\]; the
remaining question is how to adapt this supervision to heterogeneous
schema roles and refresh it as the parser learns.

To address both challenges, we present Youtu-Parsing-Omni, _an
omni-modal parser built on one encoder for every modality and one schema
for every task_
(Fig. [2](#S0.F2 "Figure 2 ‣ Youtu-Parsing-Omni: One Encoder, One Schema, All Modalities")).
For C1, a unified perception encoder, Youtu-Omni-Encoder, replaces the
two towers with one shared Transformer initialized from a pre-trained
text language model to strengthen text reading. Only lightweight input
stems and output projectors remain modality-specific, so almost all
perception parameters are shared across modalities. Visual and acoustic
tokens share one space-time positional encoding and interact in a few
fusion layers, so a frame and the sound of the same instant are aligned
and fused within short audio-visual windows inside perception, leaving
only dependencies across windows to the language model. For C2, the
shared schema allows a single self-evolving post-training procedure,
OmniSchema-Aware On-Policy Distillation (OSAD), to use the same
token-role-based objective across tasks after SFT and schema-routed
RLVR. Instead of a sequence-level reward, the model learns from
token-level targets on its own parses, provided by a frozen copy of
itself that additionally conditions on the reference
parse \[[22](#bib.bib22), [23](#bib.bib23)\]. Because every output
follows OmniSchema, each token can be identified as content or structure
and supervised with an objective suited to its role. After each round,
the trained student becomes the next teacher, so the supervision evolves
with the parser; OSAD itself thus requires neither a hand-designed
reward nor a separately trained teacher.

With this design, a single $`5`$ B-parameter Youtu-Parsing-Omni
checkpoint serves all ten parsing tasks and achieves _state-of-the-art
document parsing_, scoring $`96.96`$ on OmniDocBench v1.6
(Fig. [1](#S0.F1 "Figure 1 ‣ Youtu-Parsing-Omni: One Encoder, One Schema, All Modalities")a).
On OmniParsingBench, it leads open-weight models with a score of
$`75.08`$, surpassing Logics-Parsing-Omni ($`72.26`$), with its largest
gains on audio and video
(Fig. [1](#S0.F1 "Figure 1 ‣ Youtu-Parsing-Omni: One Encoder, One Schema, All Modalities")b).
The same checkpoint also excels at _symbolic transcription_
(Fig. [1](#S0.F1 "Figure 1 ‣ Youtu-Parsing-Omni: One Encoder, One Schema, All Modalities")c).
On chemical structures, it reaches an exact fingerprint-match rate
(Tani@1.0) of $`54.2`$, outperforming
DeepSeek-OCR 2 \[[24](#bib.bib24)\] ($`49.6`$). On typeset sheet music,
it achieves a character error rate (CER) of $`22.73`$, on par with the
specialist LEGATO \[[8](#bib.bib8)\] ($`23.30`$, as reported in its
original paper). Together, these results show that _one encoder and one
schema can support broad multimodal parsing while retaining the
precision of specialized models_.

## 2 Model

Youtu-Parsing-Omni is a decoder-only language model fed by one
perception encoder
(Fig. [3](#S1.F3 "Figure 3 ‣ 1 Introduction ‣ Youtu-Parsing-Omni: One Encoder, One Schema, All Modalities")).
It accepts text, images, audio, and video (with its audio track when
present) and emits text only. The decoder is a dense text language model
pre-trained following the recipe of Youtu-LLM-2B \[[25](#bib.bib25)\];
it keeps 1D rotary positions, since spatial and temporal structure is
already resolved inside the encoder
(App. [B.3](#A2.SS3 "B.3 Language Model ‣ Appendix B Architecture Details ‣ Youtu-Parsing-Omni: One Encoder, One Schema, All Modalities")).
Further architectural details, including the variants that the final
model does not use, are given in
App. [B](#A2 "Appendix B Architecture Details ‣ Youtu-Parsing-Omni: One Encoder, One Schema, All Modalities"),
and the complete configuration in
Tab. [17](#A2.T17 "Table 17 ‣ B.1 Model Specification ‣ Appendix B Architecture Details ‣ Youtu-Parsing-Omni: One Encoder, One Schema, All Modalities").
Two principles shape the encoder. First, every modality is read by the
same weights with the same space-time positional encoding
(Subsec. [2.1](#S2.SS1 "2.1 Youtu-Omni-Encoder ‣ 2 Model ‣ Youtu-Parsing-Omni: One Encoder, One Schema, All Modalities")–[2.2](#S2.SS2 "2.2 Unified Positional Encoding and Audio-Visual Fusion ‣ 2 Model ‣ Youtu-Parsing-Omni: One Encoder, One Schema, All Modalities")).
Second, these weights start from a model that already maps context to
symbols
(Subsec. [5.7](#S5.SS7.SSS0.Px2 "Effect of text-LM initialization. ‣ 5.7 Ablation Study ‣ 5 Evaluation ‣ Youtu-Parsing-Omni: One Encoder, One Schema, All Modalities")).
The first principle thus amortizes perception capacity across modalities
rather than duplicating it in one tower per modality.

### 2.1 Youtu-Omni-Encoder

Vision and audio inputs pass through a three-part pipeline whose middle
part is shared: a modality-specific stem turns raw input into
$`d`$-dimensional tokens, a shared Transformer contextualizes them, and
a modality-specific merger and projector down-sample the result and map
it to the decoder width. Only the stems and the merger–projector heads
depend on the modality; together they hold a small fraction of the
encoder’s parameters
(App. [B.2.1](#A2.SS2.SSS1 "B.2.1 Modality Stems ‣ B.2 Youtu-Omni-Encoder ‣ Appendix B Architecture Details ‣ Youtu-Parsing-Omni: One Encoder, One Schema, All Modalities")),
so most of the encoder is shared. Architecturally, adding a modality
therefore requires a new stem and projector rather than a second tower
with its own pre-training lineage, although the shared weights must
still be trained on the new input.

##### Stems.

The two stems convert raw signals into tokens with minimal machinery.
Images and video frames are cut into fixed-size patches at their native
resolution under a token budget \[[26](#bib.bib26)\], and a single
linear map turns each patch into one token; no further convolution,
absolute position table, or class token is used. Audio is converted to a
log-mel spectrogram, and a few strided convolutions down-sample it in
time before a linear map to width $`d`$, giving a fixed audio token rate
of $`r_{a}`$ tokens per second.

##### Shared Transformer blocks.

The shared Transformer is a stack of standard pre-norm blocks with
RMSNorm \[[27](#bib.bib27)\], SwiGLU \[[28](#bib.bib28)\], grouped-query
attention \[[29](#bib.bib29)\], and QK-Norm \[[30](#bib.bib30)\].
Attention is bidirectional. Rotary position embeddings
(RoPE) \[[31](#bib.bib31)\] are applied from a matrix of per-token
rotation angles rather than read from one position table shared by the
whole sequence; this is what makes the axis-factorized positional
encoding of
Subsec. [2.2](#S2.SS2 "2.2 Unified Positional Encoding and Audio-Visual Fusion ‣ 2 Model ‣ Youtu-Parsing-Omni: One Encoder, One Schema, All Modalities")
expressible. Any mix of images, audio chunks, and videos is packed into
one variable-length sequence whose attention windows are given by a
cumulative-length vector $`\mathbf{c}`$ \[[32](#bib.bib32)\], so one
encoder pass handles the whole mix without padding.

##### Token merger and projector.

After the shared Transformer, neighboring vision tokens within a frame
are concatenated along the feature axis into one token, and adjacent
audio tokens are merged in the same way along time. Each modality then
passes through an RMSNorm and a two-layer MLP that projects it to the
decoder width.

### 2.2 Unified Positional Encoding and Audio-Visual Fusion

##### One positional encoding for all modalities.

Sharing one Transformer across modalities makes positional encoding the
central design question: one rotary budget of frequency slots has to
express 2D layout, 1D time, and the correspondence between the two. We
partition the budget into contiguous segments of near-equal size, one
for each axis $`T`$, $`H`$, and $`W`$, each with its own
inverse-frequency table normalized by its own width, so every axis spans
the full frequency range regardless of how many slots it receives
(Equ. [7](#A2.E7 "In Chunked axis-factorized RoPE. ‣ B.2.3 Positional Encoding ‣ B.2 Youtu-Omni-Encoder ‣ Appendix B Architecture Details ‣ Youtu-Parsing-Omni: One Encoder, One Schema, All Modalities"),
App. [B.2.3](#A2.SS2.SSS3 "B.2.3 Positional Encoding ‣ B.2 Youtu-Omni-Encoder ‣ Appendix B Architecture Details ‣ Youtu-Parsing-Omni: One Encoder, One Schema, All Modalities")).
A vision token takes $`t`$ from its frame index and $`(h,w)`$ from its
patch position; an audio token takes $`t`$ from its time offset and sets
$`h=w=0`$. Both modalities therefore write into the same $`T`$ segment,
expressing their temporal positions on a common time scale. Modality
identity is left to the features: the two stems produce readily
separable feature distributions.

The shared timeline makes frame and audio positions comparable, but it
does not by itself let them interact. Fusion provides this interaction
by letting the two attend to each other, so that the correspondence a
video parse must output (for instance, which words are spoken while a
given slide is on screen) is computed in perception rather than
reconstructed by the decoder.

##### Fused and independent routes.

A video reaches the encoder by either of two routes that share all
weights and return outputs of identical shape. On the _independent_
route, each frame and each audio chunk forms its own attention window,
as if the input were a burst of images and an unrelated recording. On
the _fused_ route, the frames and audio chunks of one video are packed
in temporal order, and in the fusion layers audio-visual windows let a
frame attend to the sound of the same instant; the other layers keep one
window per frame or chunk. During training, a video takes the fused
route with probability $`p_{\mathrm{fus}}`$, set below $`1`$ from
Stage 2 on
(Sec. [4](#S4 "4 Training ‣ Youtu-Parsing-Omni: One Encoder, One Schema, All Modalities")),
which keeps both routes usable at inference.

##### Windows and time alignment.

On the fused route, the packed event list (e.g.,
$`[\mathrm{I}_{1},\mathrm{I}_{2},\mathrm{A}_{1},\mathrm{I}_{3},\dots]`$)
is cut into $`(\mathrm{I}^{+}\mathrm{A}^{*})`$ groups, i.e., one or more
frames followed by the audio chunks that precede the next frame, with a
new group starting at every audio-to-frame boundary; in the fusion
layers, each group becomes one attention window
(Fig. [4](#S2.F4 "Figure 4 ‣ Stems. ‣ 2.1 Youtu-Omni-Encoder ‣ 2 Model ‣ Youtu-Parsing-Omni: One Encoder, One Schema, All Modalities")a).
Inside a group, vision and audio advance on a common time scale tied to
the audio token rate,

````math
where $`\mathrm{fps}`$ is the sampled video frame rate and $`r_{a}`$ is

sampled frame to coincide with a discrete audio-token position
(Fig. [4](#S2.F4 "Figure 4 ‣ Stems. ‣ 2.1 Youtu-Omni-Encoder ‣ 2 Model ‣ Youtu-Parsing-Omni: One Encoder, One Schema, All Modalities")b).

##### Sparse fusion.

Because windows are specified only by $`\mathbf{c}`$, fusion is a
per-layer choice: the same packed features carry a per-group
segmentation $`\mathbf{c}^{\text{fus}}`$ and a per-event (non-fusion)
segmentation $`\mathbf{c}^{\text{nof}}`$, and each layer uses one of
them. The two segmentations assign different time origins to the same
token, which is harmless because a rotary attention score depends only
on the offset $`t_{q}-t_{k}`$ between query and key positions, and
queries never meet keys from another window.

schematic: \| separates alternative values, "..." stands for elided
content, and comments (//) are annotations rather than part of the

As discussed in
Sec. [1](#S1 "1 Introduction ‣ Youtu-Parsing-Omni: One Encoder, One Schema, All Modalities"),
parsing results of different modalities share a common form: a set of
units, each localized in space or time and paired with the content
extracted from the corresponding region or interval. Motivated by this
observation, we design a unified output schema, OmniSchema, which covers
ten parsing tasks across three modalities: images (document pages and
natural images), audio, and video. Because every element or segment is
localized by an explicit spatial or temporal anchor, each parsed result
is traceable to its source region or time interval.

##### Schema structure.

Lst. [1](#listing1 "List of listings 1 ‣ 3 Omni-Modal Parsing Schema ‣ Youtu-Parsing-Omni: One Encoder, One Schema, All Modalities")
gives an overview of the schema. Each output is serialized as a JSON
object with three common required fields: modality, a list of localized
units with their content (elements for images, segments for audio and
video), and a global description of the input (global_description).
Additional fields depend on the task: subtype and reading_order are
included where applicable, and video outputs contain structured_report,
populated for text-rich video and left empty for natural video. The unit
type depends on the modality. For images, the unit is an *element*, a
spatial region delimited by a bounding box
\<box\>\<x_1\>\<y_1\>\<x_2\>\<y_2\>\</box\> whose coordinates are
normalized to $`0`$–$`1{,}000`$ relative to the image width and height;
for audio and video, it is a *segment*, a time interval delimited by
start and end timestamps (HH:MM:SS, i.e., at one-second resolution,
relative to the input onset), and each speech segment additionally
includes one speaker identifier that is consistent across the input. The
content fields of each unit contain the information extracted from the
corresponding region or interval. For example, text contains the
recognized text of a text element, otsl encodes the structure and cell
content of a table, and asr_text contains the speech transcript of an
audio or video segment.

##### Multi-task parsing.

Youtu-Parsing-Omni supports ten parsing tasks: on images, document
parsing, chemical structure recognition, sheet music recognition, chart
parsing, flowchart parsing, geometric figure parsing, and natural image
parsing; on audio, audio parsing; and on video, natural video parsing
and text-rich video parsing. In the image tasks, each parsed region is
an element delimited by a bounding box. In *document parsing*, each
element on the page is labeled with a layout category, placed in the
reading order, and transcribed according to its category, e.g., as plain
text, a LaTEX formula, or a table serialized in Optimized Table
Structure Language (OTSL). In *chemical structure recognition*, a
molecule is parsed as a document element whose content is a
SMILES \[[33](#bib.bib33)\] string. In *sheet music recognition*, a
musical score is parsed as a document element whose content is
ABC \[[34](#bib.bib34)\] notation. In *chart parsing*, *flowchart
parsing*, and *geometric figure parsing*, the whole figure forms a
single element whose content is its underlying data as a Markdown table,
its nodes and edges as a Mermaid graph, or its geometric primitives and
their relations as a geometry string, respectively; the element also
contains a caption. In *natural image parsing*, each salient object
forms an element with a bounding box, a tag naming the object, the text
inside the box, and a region caption, and the global description adds an
image caption, a narrative, and a scene description. In the audio and
video tasks, the input is divided into a sequence of time segments. Each
audio segment is labeled as vocal or nonvocal: a vocal segment contains
a speaker identifier, a transcript, the language of the speech,
acoustic-event labels, and captions of timbre, delivery, and scene,
whereas a nonvocal segment contains acoustic-event labels and a caption
of the acoustic environment. Each video segment contains the objects and
on-screen text visible in its frames, where each text item is labeled
with an optical character recognition (OCR) type such as title. It also
contains atomic actions, actor-object interactions, camera motion at a
coarse and a fine level, an event description, and the speaker
identifier, transcript, and acoustic-event labels of the accompanying
audio. *Natural video parsing* and *text-rich video parsing* share this
segment structure; the output of text-rich video parsing additionally
contains a structured report in Markdown that summarizes the whole
video, a field left empty for natural video. Full example outputs for
each input type are given in
App. [F](#A6 "Appendix F Qualitative Examples ‣ Youtu-Parsing-Omni: One Encoder, One Schema, All Modalities").

##### Token roles.

Because every output follows OmniSchema, each token of a serialized
output can be assigned one of two roles, which OSAD supervises with
different objectives
(Subsec. [4.2.3](#S4.SS2.SSS3 "4.2.3 OmniSchema-Aware On-Policy Distillation ‣ 4.2 Post-Training ‣ 4 Training ‣ Youtu-Parsing-Omni: One Encoder, One Schema, All Modalities")).
Structure tokens belong to the JSON syntax, namely keys and punctuation
such as braces, brackets, colons, and commas, and follow a constrained
grammar; content tokens belong to field values, which can admit multiple
valid continuations.

## 4 Training

Training first develops unified perception through four pre-training
stages and then refines structured parsing through three post-training
stages
(Fig. [5](#S4.F5 "Figure 5 ‣ 4 Training ‣ Youtu-Parsing-Omni: One Encoder, One Schema, All Modalities")).
Supervised fine-tuning establishes the output format and instruction
following; two subsequent on-policy stages refine the model’s own parses
using verifiable rewards and then reference-conditioned token-level
supervision.

### 4.1 Pre-Training

Pre-training turns a text-only decoder and a text-initialized encoder
into an omni-modal perceiver, which raises three coupled problems.
First, the randomly initialized stems and projectors must learn to map
pixels and mel frames into a representation that the pre-trained
Transformer weights can read. Second, the model must acquire dense,
native-resolution perception of images, audio, and video without eroding
the decoder’s language ability. Third, it must handle long inputs such
as multi-page documents and long videos. Addressing all three at once is
both costly and unstable: gradients through randomly initialized
projectors would perturb the pre-trained decoder, and long
native-resolution sequences are expensive to train on before the
features are aligned. We therefore adopt a staged curriculum, and
progressively expand four axes across Stages 0–3
(Fig. [5](#S4.F5 "Figure 5 ‣ 4 Training ‣ Youtu-Parsing-Omni: One Encoder, One Schema, All Modalities")):
the trainable parameters (encoder only, then all parameters); the input
scale (from $`4`$ k-token sequences with at most $`256`$ tokens per
image to $`128`$ k-token sequences with up to $`512`$ video frames);
cross-modal interaction (from no fusion layers to four); and input
perturbation (from none to stochastic routing and augmentation).

We initialize the decoder from our text-only checkpoint and the shared
encoder block from Qwen3-0.6B-Base \[[35](#bib.bib35)\] without its
embedding layer and LM head; stems and projectors are randomly
initialized.

##### Stage 0: Perception Alignment.

The first stage bridges the randomly initialized stems and projectors to
the pre-trained weights on either side of them. Only the encoder (stems,
shared block, and projectors) is trained, while the decoder stays
frozen. Freezing the decoder serves two purposes: it shields the
language model from the noisy gradients of the new projectors, and it
forces the encoder to produce features in the input space that the fixed
language model already interprets. The supervision is dense: captions
and transcripts describe the whole input, so every region of an image
and every second of a recording contributes to the loss, whereas a short
answer about one region, as in visual question answering, would provide
little supervision for the remaining content. Inputs are kept small (at
most $`256`$ tokens per image, $`16`$ frames per video, and $`4`$ k
tokens per sequence) and no fusion layer is enabled, so that alignment
is learned cheaply over a large token budget before native-resolution
inputs make each step expensive.

##### Stage 1: Omni-Modal Pre-Training.

Once the encoder emits features that the decoder can read, the
bottleneck shifts from alignment to capacity: a frozen decoder cannot
learn to emit the long, dense symbol sequences required by parsing.
Stage 1 therefore unfreezes all parameters and is the largest stage,
consuming $`1.28`$ T tokens. The image budget grows from $`256`$ to
$`20`$ k tokens so that the model sees pages at native resolution,
videos grow to $`64`$ frames of up to $`512`$ tokens each, and sequence
lengths range from $`8`$ k to $`32`$ k tokens. Four fusion layers are
enabled at this point, so that frames attend to the co-occurring audio
(Subsec. [2.2](#S2.SS2 "2.2 Unified Positional Encoding and Audio-Visual Fusion ‣ 2 Model ‣ Youtu-Parsing-Omni: One Encoder, One Schema, All Modalities"))
only after each modality has been aligned on its own. Text-only data are
mixed in to limit catastrophic forgetting of the decoder’s language
ability. The learning rate is held constant so the total budget need not
be fixed in advance and any checkpoint can be handed to the decay stage.

##### Stage 2: Annealing.

Under a constant learning rate, the loss plateaus above the level that a
subsequent learning-rate decay reaches, and annealing is a standard
final phase of large-scale pre-training. Stage 2 decays the learning
rate from $`10^{-4}`$ to $`10^{-5}`$ with a cosine schedule over
$`512`$ B tokens, with sequences fixed at $`32`$ k tokens and slightly
larger image and per-frame budgets. Because annealing consolidates what
the model has learned, we also introduce two mechanisms here that
protect or broaden the learned perception. First, layer-wise
learning-rate decay scales the learning rate of encoder depth $`\ell`$
by $`\gamma^{L+1-\ell}`$ with $`\gamma=0.9`$, from the stems
($`\ell=0`$) to the projectors ($`\ell=L+1`$, no decay); the projectors,
the newest components, keep adapting, whereas the stems and lower
layers, which already encode generic low-level features, are protected
from being overwritten. Second, audio-visual videos are routed
stochastically with fused-route probability $`p_{\mathrm{fus}}=0.8`$, so
they take the independent route with probability $`0.2`$ and both routes
remain usable at inference.

##### Stage 3: Long-Context Extension.

Multi-page documents and long videos require far longer sequences than
Stages 0–2 provide. Stage 3 trains on sequences of up to $`128`$ k
tokens, with up to $`102{,}400`$ tokens per image or video and videos of
up to $`512`$ frames, for $`128`$ B tokens at a constant learning rate
of $`10^{-5}`$.

### 4.2 Post-Training

Pre-training yields a model that perceives all three modalities but does
not yet emit OmniSchema reliably. Post-training proceeds through
supervised fine-tuning (SFT) for OmniSchema serialization, schema-routed
reinforcement learning with verifiable rewards (RLVR) for sequence-level
optimization, and OmniSchema-Aware On-Policy Distillation (OSAD) for
token-adaptive supervision and iterative self-evolution.

#### 4.2.1 Supervised Fine-Tuning

Starting from the Stage 3 checkpoint, we train all parameters on
prompt–response pairs to establish reliable OmniSchema serialization and
instruction following. Although the pre-training mixture already
contains parsing data, the Stage 3 model does not yet consistently
respond to a task prompt with a complete, schema-conformant object; SFT
makes this output format the default response to each parsing
instruction.

The SFT mixture combines two sources. Parsing data cover all ten tasks
in
Sec. [3](#S3 "3 Omni-Modal Parsing Schema ‣ Youtu-Parsing-Omni: One Encoder, One Schema, All Modalities"):
each sample pairs a task prompt and its image, audio, or video input
with a reference parse serialized in OmniSchema, so a single model
learns to emit the fields each task requires. General-purpose data,
reused from Youtu-LLM \[[25](#bib.bib25)\],
Youtu-VL \[[36](#bib.bib36)\], Long-VITA \[[37](#bib.bib37)\],
VITA-1.5 \[[12](#bib.bib12)\], and VITA-Audio \[[38](#bib.bib38)\], span
text-only, visual, and audio instructions and preserve the
conversational and instruction-following abilities that a parsing-only
mixture would erode. SFT uses a budget of $`16`$ B tokens, sequences of
up to $`32`$ k tokens, and at most $`64`$ frames per video, and keeps
the four fusion layers of Stages 1–3
(Fig. [5](#S4.F5 "Figure 5 ‣ 4 Training ‣ Youtu-Parsing-Omni: One Encoder, One Schema, All Modalities")).

SFT also prepares the model for the two on-policy stages that follow,
both of which learn from the model’s own rollouts. RLVR assigns zero
reward to undecodable outputs, and with group-mean-centered advantages,
a group in which every rollout fails yields no gradient; OSAD likewise
distills only from rollouts that pass its admission checks. A policy
that rarely produces well-formed parses would therefore supply few
useful learning signals to either stage. SFT, however, supervises the
model only under reference prefixes, a limitation that the on-policy
stages address
(Subsec. [4.2.3](#S4.SS2.SSS3 "4.2.3 OmniSchema-Aware On-Policy Distillation ‣ 4.2 Post-Training ‣ 4 Training ‣ Youtu-Parsing-Omni: One Encoder, One Schema, All Modalities")).

#### 4.2.2 Schema-Routed RLVR

For an input query $`x`$, let $`y`$ denote the generated parse,
$`y^{\star}`$ its reference parse, and $`\nu`$ the task index. Here,
$`x`$ includes the task prompt and its multimodal input. We optimize the
policy on its own generated parses with Group Relative Policy
Optimization (GRPO) \[[18](#bib.bib18)\]. The reward is gated by
decodability and the presence of a primary payload, and combines shared
well-formedness with task-specific content accuracy:

|  |  |  |  |
|----|----|----|----|
|  |
``` math
\displaystyle R(y,y^{\star},\nu)=\mathds{1}[y\text{ decodes}]\,\mathds{1}[y\text{ has a payload}]\cdot\mathrm{clip}_{[0,1]}\big(\Omega(y,y^{\star})\cdot\mathrm{core}_{\nu}(y,y^{\star})\big),
``` |  | (2) |
|  |
``` math
\displaystyle\Omega(y,y^{\star})=\mathrm{Fmt}(y)\,\big(1-0.6\,P_{\mathrm{repeat}}\big)\,\big(1-0.7\,P_{\mathrm{under}}\big).
``` |  |  |

The indicator $`\mathds{1}[\cdot]`$ equals one when its condition holds
and zero otherwise; $`\mathrm{clip}_{[0,1]}`$ restricts its argument to
$`[0,1]`$. If either gate fails, the reward is zero; otherwise, it
equals the clipped product of the well-formedness and content factors.
Thus the final reward lies in $`[0,1]`$. The shared factor $`\Omega`$
combines schema validity, scored by $`\mathrm{Fmt}(y)`$, with penalties
for repetition ($`P_{\mathrm{repeat}}`$) and incomplete coverage
($`P_{\mathrm{under}}`$). Both penalties compare $`y`$ with
$`y^{\star}`$; their arguments are suppressed for brevity, and $`0.6`$
and $`0.7`$ are their respective coefficients. The task-specific factor
$`\mathrm{core}_{\nu}`$ averages grounded-field accuracy and
reference-description similarity when reference descriptions are
available; otherwise, it uses grounded-field accuracy alone.
App. [C.1](#A3.SS1 "C.1 Schema-Routed RLVR ‣ Appendix C Post-Training Details ‣ Youtu-Parsing-Omni: One Encoder, One Schema, All Modalities")
details the validity checks, penalties, and task-specific scorers.

##### Token-adaptive on-policy supervision.

SFT trains on reference prefixes, whereas inference uses model-generated
prefixes \[[16](#bib.bib16), [17](#bib.bib17)\]. RLVR trains on these
generated prefixes but assigns one reward to the entire parse. OSAD
complements this sequence-level optimization with reference-conditioned
targets at each token, building on on-policy
distillation \[[21](#bib.bib21), [39](#bib.bib39)\] and
reference-conditioned self-distillation \[[22](#bib.bib22)\], with the
reference serving as privileged information \[[23](#bib.bib23)\].

OSAD proceeds in rounds. Within round $`r`$, a frozen teacher with
parameters $`\bar{\theta}_{r}`$ and a student with effective parameters
$`\theta`$ start from the same checkpoint. The student trains low-rank
adapters (LoRA) \[[40](#bib.bib40)\] on frozen base weights and samples
a response $`y=(y_{1},\ldots,y_{T})`$ of length $`T`$ for each query
$`x`$. Only rollouts passing JSON-validity, schema-conformance,
box-syntax, and repetition checks enter distillation; rejected rollouts
are masked
(App. [C.2](#A3.SS2 "C.2 OmniSchema-Aware On-Policy Distillation ‣ Appendix C Post-Training Details ‣ Youtu-Parsing-Omni: One Encoder, One Schema, All Modalities")).
Both models score the same generated prefix
$`y_{<t}=(y_{1},\ldots,y_{t-1})`$, but only the teacher receives the
reference parse through $`\tilde{x}=[y^{\star};x]`$:

|  |  |  |  |
|----|----|----|----|
|  |
``` math
p_{t}^{(\tau)}=\mathrm{softmax}\big(f_{\theta}(x,y_{<t})/\tau\big),\qquad q_{t}^{(\tau)}=\mathrm{softmax}\big(f_{\bar{\theta}_{r}}(\tilde{x},y_{<t})/\tau\big).
``` |  | (3) |

Here, $`p_{t}^{(\tau)}`$ and $`q_{t}^{(\tau)}`$ are student and teacher
next-token distributions, $`f`$ returns vocabulary logits, and
$`\tau>0`$ denotes distillation temperature. Shared prefixes thus
provide aligned targets on the student’s own trajectories without
exposing the reference to the student.

Following the token roles in
Sec. [3](#S3 "3 Omni-Modal Parsing Schema ‣ Youtu-Parsing-Omni: One Encoder, One Schema, All Modalities"),
let $`\mathcal{C}(y)`$ and $`\mathcal{S}(y)`$ denote the content and
structure positions of a response, respectively. Content fields may
admit several valid continuations, whereas JSON keys and punctuation
follow a constrained grammar. We therefore use the symmetric, bounded
Jensen–Shannon (JS) divergence for content and the forward
Kullback–Leibler (KL) divergence for structure:

|  |  |  |  |
|----|----|----|----|
|  |
``` math
d_{t}^{\mathcal{C}}=\mathrm{JS}\big(q_{t}^{(\tau_{c})}\,\big\|\,p_{t}^{(\tau_{c})}\big),\qquad d_{t}^{\mathcal{S}}=\mathrm{KL}\big(q_{t}^{(\tau_{s})}\,\big\|\,p_{t}^{(\tau_{s})}\big),\qquad\tau_{s}>\tau_{c}.
``` |  | (4) |

The per-position divergences $`d_{t}^{\mathcal{C}}`$ and
$`d_{t}^{\mathcal{S}}`$ use content and structure temperatures
$`\tau_{c}`$ and $`\tau_{s}`$, respectively, and are computed over the
full vocabulary. Round indices on temperatures and role weights are
omitted here for brevity. JS bounds content disagreement, while forward
KL encourages coverage of the teacher’s structural predictions, softened
by the higher structure temperature.

The objective combines a shared all-token term with additional
role-specific terms. For each nonempty role
$`\mathcal{R}\in\{\mathcal{C},\mathcal{S}\}`$, define its mean
divergence as
$`\bar{d}^{\,\mathcal{R}}(y)=|\mathcal{R}(y)|^{-1}\sum_{t\in\mathcal{R}(y)}d_{t}^{\mathcal{R}}`$.
The all-token term applies JS uniformly at temperature $`\tau`$ and
averages over all $`T`$ response positions:

|  |  |  |
|----|----|----|
|  |
``` math
d_{t}^{\mathrm{all}}=\mathrm{JS}\big(q_{t}^{(\tau)}\,\big\|\,p_{t}^{(\tau)}\big),\qquad\bar{d}^{\,\mathrm{all}}(y)=\frac{1}{T}\sum_{t=1}^{T}d_{t}^{\mathrm{all}}.
``` |  |

With nonnegative content and structure weights $`\alpha_{c}`$ and
$`\alpha_{s}`$, the per-rollout loss and minibatch objective are

|  |  |  |  |
|----|----|----|----|
|  |
``` math
\mathcal{L}_{\mathrm{row}}(y)=\frac{\bar{d}^{\,\mathrm{all}}(y)+\alpha_{c}\,\bar{d}^{\,\mathcal{C}}(y)+\alpha_{s}\,\bar{d}^{\,\mathcal{S}}(y)}{1+\alpha_{c}+\alpha_{s}},\qquad\mathcal{L}=\frac{1}{|\mathcal{B}^{+}|}\sum_{y\in\mathcal{B}^{+}}\mathcal{L}_{\mathrm{row}}(y).
``` |  | (5) |

Here, $`\mathcal{B}^{+}`$ contains all admitted rollout instances in the
global minibatch across data-parallel ranks; updates are skipped when
this global collection is empty. For an absent role, its weighted loss
and coefficient are omitted from the numerator and denominator,
respectively. The all-token mean weights response positions equally,
while role averaging controls the additional supervision independently
of role length. Averaging over rollouts gives each admitted response
equal weight. The role-weight schedule is given in
App. [C.2](#A3.SS2 "C.2 OmniSchema-Aware On-Policy Distillation ‣ Appendix C Post-Training Details ‣ Youtu-Parsing-Omni: One Encoder, One Schema, All Modalities").

##### Self-evolution through teacher refresh.

Token-adaptive supervision remains tied to the starting checkpoint if
the teacher stays fixed throughout training. At each round boundary,
OSAD merges the learned adapters into the student’s base weights to
obtain $`\theta_{r}`$, which initializes the next teacher and student:

|  |  |  |  |
|----|----|----|----|
|  |
``` math
\bar{\theta}_{r+1}\leftarrow\operatorname{stopgrad}(\theta_{r}),\qquad\theta_{\mathrm{init}}^{(r+1)}\leftarrow\bar{\theta}_{r+1}.
``` |  | (6) |

Here, $`\operatorname{stopgrad}`$ blocks gradients, and
$`\theta_{\mathrm{init}}^{(r+1)}`$ denotes the next student’s initial
base weights, to which fresh low-rank adapters are added. Teacher
parameters are fixed within each round and refreshed between rounds,
while reference conditioning remains exclusive to the teacher. This
alternation updates both the parser and its supervision on a fixed
source pool. We run six rounds of OSAD.

provides the training settings and pseudocode

## 5 Evaluation

We evaluate a single checkpoint under a single inference configuration
and organize the evaluation around two questions: what this checkpoint
achieves across modalities, and how the two ideas behind the model, the
text-initialized unified encoder and self-evolving post-training,
contribute.
Subsec. [5.1](#S5.SS1 "5.1 Setup ‣ 5 Evaluation ‣ Youtu-Parsing-Omni: One Encoder, One Schema, All Modalities")
describes the benchmarks, baselines, and protocol, and

### 5.1 Setup

##### Benchmarks and baselines.

Tab. [1](#S4.T1 "Table 1 ‣ Self-evolution through teacher refresh. ‣ 4.2.3 OmniSchema-Aware On-Policy Distillation ‣ 4.2 Post-Training ‣ 4 Training ‣ Youtu-Parsing-Omni: One Encoder, One Schema, All Modalities")
lists every benchmark with its size, its metric, and the source of the
baseline numbers. OmniDocBench v1.6 \[[42](#bib.bib42)\] evaluates
page-level document parsing; its Overall score averages text accuracy
($`1-\text{edit distance}`$), formula CDM, and table TEDS.
PureDocBench \[[43](#bib.bib43)\] evaluates identical pages in clean,
digitally degraded, and physically recaptured tracks, which isolates the
cost of input degradation; it reports an Overall score per track and
their mean, Avg₃. OmniParsingBench \[[11](#bib.bib11)\] evaluates
parsing of natural images, charts, geometry, audio, natural video, and
text-rich video; each split is scored by a *Perception* component over
grounded fields, including localization, element extraction, OCR, and
automatic speech recognition (ASR), and by a *Cognition* component from
multiple-choice questions that an LLM judge answers by reading only the
parse. Overall is the per-split leaderboard score: the mean of
Perception and Cognition multiplied by the post-repair parse rate
(Tab. [5](#S5.T5 "Table 5 ‣ 5.4 OmniParsingBench ‣ 5 Evaluation ‣ Youtu-Parsing-Omni: One Encoder, One Schema, All Modalities")–[10](#S5.T10 "Table 10 ‣ Graphics chart and geometry. ‣ 5.4 OmniParsingBench ‣ 5 Evaluation ‣ Youtu-Parsing-Omni: One Encoder, One Schema, All Modalities")).
On OmniParsingBench, every system is run and scored by us: we compare
with the parsing-specialized Logics-Parsing-Omni, the open-weight
generalists Qwen3-Omni-30B-A3B \[[10](#bib.bib10)\] and
Qwen3.5-397B-A17B \[[66](#bib.bib66)\], and the API models
Gemini-3-Pro \[[62](#bib.bib62)\] and GPT-5.4 \[[67](#bib.bib67)\];
Qwen3.5 and GPT-5.4 are evaluated only on image splits because neither
model accepts audio input. Video-MME-v2 \[[44](#bib.bib44)\] evaluates
general video understanding with $`3{,}200`$ multiple-choice questions
arranged in groups of four; its group score rewards answering the
related questions of a group consistently, and it is also reported for
three capability levels (L1–L3). We use its setting without subtitles,
in which models receive visual frames only. ChemOCR \[[45](#bib.bib45)\]
evaluates chemical structure recognition from molecule images to SMILES,
scored by the mean Tanimoto similarity of molecular fingerprints (Avg.
Sim.) and the exact fingerprint-match rate (Tani@1.0).
PDMX-Synth \[[46](#bib.bib46), [8](#bib.bib8)\] evaluates optical music
recognition from rendered score images to ABC notation, scored by
character, symbol, and line error rates (CER, SER, and LER). For
OmniDocBench, PureDocBench, and Video-MME-v2, the baseline numbers are
taken from the official leaderboards; on ChemOCR and PDMX-Synth, we run
every baseline with the official evaluator, except
ChemDFM-X \[[7](#bib.bib7)\] and LEGATO \[[8](#bib.bib8)\], whose scores
come from TinyChemVL \[[41](#bib.bib41)\] and LEGATO\[[8](#bib.bib8)\],
respectively.

##### Protocol.

OmniDocBench, PureDocBench, Video-MME-v2, ChemOCR, and PDMX-Synth are
scored with their official evaluation code or protocol. OmniParsingBench
is released without a complete evaluation toolkit, so we implement one
from the metric definitions of the benchmark
(App. [D](#A4 "Appendix D Evaluation Details ‣ Youtu-Parsing-Omni: One Encoder, One Schema, All Modalities"))
and re-score every system with it on one internal leaderboard. These
numbers, for our model and for every baseline, are thus comparable with
each other, but not directly with those reported by the benchmark
authors. The toolkit repairs schema violations before scoring, so that
formatting errors are not charged as content errors, and it uses
corrected ground truth for a small number of verified annotation errors.
We set aside the camera-video subset because of annotation issues and
exclude $`136`$ samples with unavailable media, leaving $`3{,}738`$ of
$`3{,}874`$ samples.

performance on par with specialized document parsers. On OmniDocBench

the differences from TeleOCR on text, formulas, and tables are all

accurately and serialize it correctly. This pattern suggests that the
new model improves not only visual recognition, but also the
organization of recognized content into coherent, structured outputs.
Notably, this specialist-level document parsing performance is delivered
by the same model that processes natural images, audio, and video across
ten tasks
(Fig. [7](#S5.F7 "Figure 7 ‣ 5.2 OmniDocBench v1.6 ‣ 5 Evaluation ‣ Youtu-Parsing-Omni: One Encoder, One Schema, All Modalities")a).
Thus, the broader modality coverage is achieved without weakening
document understanding or fine-grained parsing capabilities.

##### Overall results.

We next ask whether a single encoder can serve images, audio, and video
at a competitive level, and where any advantage appears. Under our
evaluation toolkit, Youtu-Parsing-Omni is the strongest open-weight
model on OmniParsingBench, with an average of $`75.08`$ against
$`72.26`$ for Logics-Parsing-Omni; among the models evaluated on every
split, only the API model Gemini-3-Pro scores higher ($`77.44`$;
Tab. [4](#S5.T4 "Table 4 ‣ 5.3 PureDocBench ‣ 5 Evaluation ‣ Youtu-Parsing-Omni: One Encoder, One Schema, All Modalities"),
Fig. [1](#S0.F1 "Figure 1 ‣ Youtu-Parsing-Omni: One Encoder, One Schema, All Modalities")b).
It leads the other open-weight models on all three temporal splits
(audio, natural video, and text-rich video) and attains the highest
chart score of all systems ($`95.02`$). The advantage, however, is not
uniform across splits. Relative to Logics-Parsing-Omni,
Youtu-Parsing-Omni leads by $`2.5`$ points on audio, $`6.8`$ on natural
video, and $`10.3`$ on text-rich video ($`6.5`$ on average), whereas it
trails by $`2.8`$ points on average on the two static splits (natural
images and graphics), mainly on natural images ($`-4.7`$) and geometry
($`-2.0`$). These group means follow the leaderboard weighting,
combining chart and geometry into one graphics score before averaging.
Relative to Gemini-3-Pro, it is on par on the temporal splits ($`75.96`$
against $`76.12`$ on average) but trails on the static ones ($`73.76`$
against $`79.42`$). Logics-Parsing-Omni pairs a $`1.1`$ B two-tower
front end with a $`30`$ B mixture-of-experts (MoE) decoder that
activates about $`3`$ B parameters per token: fewer active parameters
than our dense $`5`$ B model, but about six times as many in total. The
contrast between static and temporal splits is consistent with encoding
all modalities on a shared timeline
(Sec. [2](#S2 "2 Model ‣ Youtu-Parsing-Omni: One Encoder, One Schema, All Modalities")),
whose benefit should be largest where a parse must align events in time
and across modalities. Overall, with a single encoder,
Youtu-Parsing-Omni is the strongest open-weight model on
OmniParsingBench, and its advantage is concentrated on the temporal
splits.

##### Natural images.

Youtu-Parsing-Omni leads in entity localization and plain-entity
recognition
(Tab. [5](#S5.T5 "Table 5 ‣ 5.4 OmniParsingBench ‣ 5 Evaluation ‣ Youtu-Parsing-Omni: One Encoder, One Schema, All Modalities")).
Knowledge recognition is weaker ($`13.90`$ versus $`21.39`$ for
Logics-Parsing-Omni), possibly reflecting our smaller total parameter
budget (e.g., Logics-Parsing-Omni uses a $`30`$ B-A$`3`$ B decoder).
Counting remains challenging across models, with all Count scores below
$`80`$ despite strong Theme and Scene scores.

##### Graphics chart and geometry.

Youtu-Parsing-Omni achieves the highest chart Perception ($`97.49`$) and
Overall ($`95.02`$) scores in the breakdown
(Tab. [6](#S5.T6 "Table 6 ‣ 5.4 OmniParsingBench ‣ 5 Evaluation ‣ Youtu-Parsing-Omni: One Encoder, One Schema, All Modalities")),
with its clearest advantage in statistical-chart extraction. In terms of
Cognition score, our method is lower than Logics-Parsing-Omni ($`92.93`$
versus $`94.79`$), with the gap concentrated in visual-element and
logical-reasoning questions. This is mainly because our captions tend to
provide globalized descriptions and weaken the semantic descriptions of
color and position, since such information contains limited effective
content and is prone to introducing semantic errors. For geometry
(Tab. [7](#S5.T7 "Table 7 ‣ 5.4 OmniParsingBench ‣ 5 Evaluation ‣ Youtu-Parsing-Omni: One Encoder, One Schema, All Modalities")),
Youtu-Parsing-Omni also exceeds Logics-Parsing-Omni in Perception
($`63.14`$ versus $`60.32`$), with gains in positioning, circle
detection, and membership. Geometric relations remain weaker in both
Perception ($`46.77`$ versus $`64.24`$) and Cognition ($`76.45`$ versus
$`86.35`$). Together, these results suggest that richer descriptions of
graphical elements and their relationships could improve how the parses
support downstream questions.

($`98.71`$) and object understanding ($`78.50`$), while matching the
best audio-visual causal reasoning score ($`100.00`$). Consistent
superior Cognition results across both video splits, evaluated purely
based on parsed outputs, verify that our unified temporal modeling
paradigm effectively preserves multimodal semantics for downstream
understanding, confirming its effectiveness in achieving both temporally
precise and semantically reliable video parsing.

##### L1 score.

The level-wise results indicate that this outcome stems mainly from L1,
i.e., information aggregation across frames. For the baselines, L1
varies little with either model size or inference mode: it lies within a
$`2.3`$-point range from InternVL3.5-4B-Instruct to
Qwen3-Omni-30B-A3B-Think, and enabling thinking in Qwen3-Omni raises it
by only $`0.8`$ points. Youtu-Parsing-Omni exceeds every non-thinking
baseline on L1 by at least $`5`$ points, a margin that neither
additional parameters nor thinking yields among the compared models. We
attribute this margin primarily to the parsing objective, which requires
the model to locate and transcribe the visual content of each frame
exhaustively and thus directly exercises cross-frame aggregation.

##### L2 and L3 scores.

On L2 and L3, which target temporal understanding and complex reasoning,
Youtu-Parsing-Omni performs comparably to the non-thinking baselines and
shows no comparable advantage. Its gap to Qwen3-Omni-30B-A3B-Think on
these levels ($`1.9`$ and $`1.8`$ points) is close to the improvement
that thinking brings to Qwen3-Omni itself ($`2.1`$ points on each),
whereas the same change contributes less than one point on L1. This
suggests that the remaining deficit arises from multi-step reasoning
over the extracted evidence rather than from perception, and that an
explicit reasoning mode, which yields a gain of similar size for
Qwen3-Omni, may help close it. It may also explain why the large lead on
L1 yields only a modest lead in group score, since the group-based
metric requires consistent answers across related questions, many of
which involve higher-level reasoning.

In short, parsing-centric training preserves general video understanding
and specifically improves cross-frame information aggregation, while
higher-level temporal reasoning remains limited in the absence of a
thinking mode.

### 5.6 ChemOCR and PDMX-Synth

ChemOCR and PDMX-Synth test whether a general parser can emit an exact
formal language (SMILES and ABC notation) rather than a plausible
description, and the two benchmarks separate the systems in different
ways
(Tab. [12](#S5.T12 "Table 12 ‣ 5.5 Video-MME-v2 ‣ 5 Evaluation ‣ Youtu-Parsing-Omni: One Encoder, One Schema, All Modalities")).

##### ChemOCR.

On chemical structures, Youtu-Parsing-Omni’s advantage is in exact
RDK-fingerprint agreement rather than average fingerprint similarity. On
ChemOCR, it attains the highest exact fingerprint-match rate (Tani@1.0)
among the compared models, $`54.2`$ against $`49.6`$ for DeepSeek-OCR 2,
while its average Tanimoto similarity (Avg. Sim.) is marginally lower
($`74.6`$ against $`74.9`$). A higher average fingerprint similarity
does not necessarily imply that a greater number of predictions share
the same fingerprint. In common scenarios, the latter is considered to
be more practically meaningful, so we regard Tani@1.0 as the main
metric.

##### PDMX-Synth.

On typeset sheet music, Youtu-Parsing-Omni attains the lowest character
error rate of all compared systems, $`22.73`$ CER, edging out the
specialized LEGATO \[[8](#bib.bib8)\] ($`23.30`$) and remaining second
to it at the symbol and line levels ($`26.73`$ against $`25.80`$ SER,
$`33.20`$ against $`31.70`$ LER). The margin over the other general
systems is of a different order: the strongest of them reach
$`45`$–$`54`$ CER (GPT-5.6 and Gemini-3-Pro), and the remaining parsers
lie at $`72`$–$`94`$ CER. Taken together, Youtu-Parsing-Omni leads every
compared model on ChemOCR’s Tani@1.0 metric and matches a dedicated
optical-music model in character-level transcription of typeset sheet
music, far ahead of the other general systems.

##### Unified encoder versus separate towers.

With two thirds of the perception parameters and no second tower, a

At the same budget, it trails on OCRBench by $`53.4`$ points

Text-LM initialization substantially reduces the vision gap: at the same

the towers on Avg-6 and surpasses them by $`77.2`$ points on OCRBench.

of the vision gap.

##### Effect of text-LM initialization.

At matched training budgets, initializing the shared block from
Qwen3-0.6B-Base rather than from scratch gives the encoder *a reading
advantage that persists throughout the plotted range*
(Fig. [8](#S5.F8 "Figure 8 ‣ 5.7 Ablation Study ‣ 5 Evaluation ‣ Youtu-Parsing-Omni: One Encoder, One Schema, All Modalities")b).
The two vision branches run identical Stage 0 and Stage 1 schedules and
differ only in this initialization. The initialized encoder leads on
OCRBench at every checkpoint evaluated in both branches; at $`300`$ B
tokens, its advantage is $`130.6`$ points ($`767.0`$ against $`636.4`$).
It reaches $`672`$ early in training, a score the scratch encoder never
attains within the plotted range. On Avg-6, the benefit is mainly one of
sample efficiency: the initialized encoder reaches $`64.1`$ with half
the Stage 1 tokens needed by the scratch encoder to reach a comparable
score, and it leads by $`0.9`$ points at $`300`$ B tokens ($`65.37`$
against $`64.48`$;
Fig. [8](#S5.F8 "Figure 8 ‣ 5.7 Ablation Study ‣ 5 Evaluation ‣ Youtu-Parsing-Omni: One Encoder, One Schema, All Modalities")a).
The advantage is concentrated on reading: at the same $`300`$ B budget,
the scratch encoder leads on $`8`$ of the $`16`$ vision benchmarks, most
clearly on BLINK ($`+9.5`$, $`52.89`$ against $`43.41`$;
Fig. [8](#S5.F8 "Figure 8 ‣ 5.7 Ablation Study ‣ 5 Evaluation ‣ Youtu-Parsing-Omni: One Encoder, One Schema, All Modalities")c),
which tests spatial and relational perception. This dissociation is
consistent with the second principle of the encoder
(Sec. [2](#S2 "2 Model ‣ Youtu-Parsing-Omni: One Encoder, One Schema, All Modalities")):
weights that already map context to symbols help perception output
symbols, not reason about space. Because parsing depends on reading more
than on any other capability, this is the encoder result most relevant
to our task.

OSAD provides *most of the improvement beyond SFT*, contributing
$`1.75`$ of the $`1.99`$ points gained on OmniDocBench v1.6 ($`88\%`$),
compared with $`0.24`$ from RLVR

outputs*: a schema-valid parse can still misread words, formula symbols,

indirectly.

## 6 Related Work

### 6.1 Parsing as a Perception Interface for Agents

Retrieval-augmented generation \[[1](#bib.bib1)\] and tool-using
agents \[[2](#bib.bib2)\] motivate reusable interfaces between external
evidence and language-model reasoning. For multimodal inputs, this
interface may consist of extracted content, visual embeddings, or
grounded structured records. ColPali \[[88](#bib.bib88)\] and visual
retrieval systems such as VisRAG and M3DocRAG \[[89](#bib.bib89),
[90](#bib.bib90)\] retrieve directly from document images, while
Pix2Struct \[[91](#bib.bib91)\] uses screenshot parsing to learn
representations for visual language understanding.
MMLongBench-Doc \[[92](#bib.bib92)\] evaluates understanding across long
multimodal documents, and OSWorld \[[3](#bib.bib3)\] and
TheAgentCompany \[[93](#bib.bib93)\] place perception within interactive
computer and workplace tasks. These settings motivate interfaces that
retain both semantic content and its source location. OmniSchema serves
this purpose through a common representation of entities, relations, and
spatial or temporal anchors across documents, images, audio, and video.

### 6.2 Omni-Modal Parsing and Perception Encoders

##### Document parsing.

Document understanding spans OCR-based pipelines and models that
generate structured outputs directly from images.
Donut \[[94](#bib.bib94)\] established an OCR-free encoder-decoder
approach, while systems such as MinerU and PaddleOCR \[[95](#bib.bib95),
[96](#bib.bib96)\] organize recognition and layout analysis into
specialized components. Recent parsers explore different allocations of
these computations: MinerU2.5 \[[5](#bib.bib5)\] separates
low-resolution layout analysis from high-resolution recognition;
dots.ocr and MonkeyOCR \[[58](#bib.bib58), [51](#bib.bib51)\] integrate
layout and content prediction; and Youtu-Parsing \[[4](#bib.bib4)\]
decodes regions in parallel from shared encoder features. MinerU2.5-Pro
and PaddleOCR-VL \[[20](#bib.bib20), [97](#bib.bib97), [6](#bib.bib6)\]
further improve document parsing through data and training refinements.
GOT-OCR2.0 and DeepSeek-OCR \[[79](#bib.bib79), [71](#bib.bib71)\] also
emphasize visual encoding tailored to text recognition and document
compression. Our work extends this encoder-centric approach to grounded
parsing across visual and auditory inputs.

##### Omni-modal models and structured parsing.

Omni-modal language models integrate vision and audio for multimodal
understanding and generation \[[9](#bib.bib9), [10](#bib.bib10),
[98](#bib.bib98), [99](#bib.bib99), [12](#bib.bib12),
[100](#bib.bib100), [101](#bib.bib101)\]. A common architecture uses
separate vision and audio encoders, followed by fusion in the language
model. Qwen2.5-Omni, for example, uses TMRoPE to align audio and video
tokens through temporal positional encoding \[[9](#bib.bib9)\].
Logics-Parsing-Omni \[[11](#bib.bib11)\] develops an explicit omni-modal
parsing framework that connects detection, recognition, and
interpretation through evidence grounding, and introduces
OmniParsingBench, which we adopt. Building on this task formulation,
Youtu-Parsing-Omni combines a shared output schema with a unified
perception encoder, Youtu-Omni-Encoder, placing audio-visual temporal
alignment and selective cross-modal interaction before the decoder.

##### Shared representations and unified encoders.

Multimodal alignment and encoder sharing address complementary aspects
of perception. ImageBind \[[102](#bib.bib102)\] aligns six modalities in
a common embedding space using image-paired data. Architectures such as
VATT \[[13](#bib.bib13)\], Omnivore \[[103](#bib.bib103)\], and
TVLT \[[14](#bib.bib14)\] instead explore shared Transformer computation
across different combinations of visual, auditory, textual, and depth
inputs. Meta-Transformer \[[104](#bib.bib104)\] and
OneLLM \[[105](#bib.bib105)\] extend parameter sharing across modalities
with modality-specific input processing. Youtu-Omni-Encoder targets
grounded parsing, including native-resolution pages, with a
text-initialized shared backbone and a common temporal positional
encoding for audio and video. Cross-modal attention is confined to
selected layers and local windows, combining shared computation with
explicit temporal interaction.

##### Language-model initialization for perception.

Pre-trained language-model weights provide a complementary starting
point to visual or contrastive pre-training. FPT \[[106](#bib.bib106)\]
studies transfer from text Transformers to non-text tasks, and frozen
language-model blocks can enrich visual
representations \[[107](#bib.bib107)\]. TrOCR \[[108](#bib.bib108)\]
uses pre-trained text components for recognition, while encoder-free
models such as Fuyu, EVE, and Mono-InternVL \[[109](#bib.bib109),
[110](#bib.bib110), [111](#bib.bib111)\] process image patches within
the language-model architecture. DeepSeek-OCR 2 \[[24](#bib.bib24)\] is
particularly relevant: its visual encoder incorporates a
Qwen2-initialized Transformer with bidirectional visual attention and
causal query tokens for learned reading order. We apply text
initialization to a separate perception backbone shared by vision and
audio, preserving a distinct decoder and evaluating the initialization
against an otherwise identical encoder trained from scratch
(Subsec. [5.7](#S5.SS7.SSS0.Px2 "Effect of text-LM initialization. ‣ 5.7 Ablation Study ‣ 5 Evaluation ‣ Youtu-Parsing-Omni: One Encoder, One Schema, All Modalities")).

### 6.3 Post-Training for Structured Parsing

##### Verifiable rewards.

Reinforcement learning extends parsing supervision from reference
sequences to model-generated outputs. GRPO \[[18](#bib.bib18)\] provides
a group-relative optimization framework, and OCR systems instantiate
task-specific rewards: olmOCR-2 \[[19](#bib.bib19)\] uses programmatic
unit tests, while MinerU2.5-Pro and PaddleOCR-VL-1.6 incorporate
reinforcement learning into their training pipelines \[[20](#bib.bib20),
[6](#bib.bib6)\]. Our schema-routed RLVR combines shared validity checks
with task-specific content scores under one policy. The subsequent
distillation stage supplies token-level feedback for structured outputs
whose heterogeneous fields are difficult to supervise with a single
scalar reward.

##### On-policy and reference-conditioned distillation.

Training on learner-generated trajectories addresses the mismatch
between reference prefixes and the states encountered at
inference \[[16](#bib.bib16), [17](#bib.bib17)\].
GKD \[[21](#bib.bib21)\] applies teacher feedback to student-generated
sequences and permits different distribution-matching objectives;
MiniLLM \[[39](#bib.bib39)\] develops on-policy optimization of a
reverse-KL distillation objective. A separate line of work transfers
information available only during training: learning with privileged
information and generalized distillation formalize this
setting \[[23](#bib.bib23), [112](#bib.bib112)\], while context
distillation internalizes the benefits of additional instructions or
reasoning context \[[113](#bib.bib113)\]. OPSD \[[22](#bib.bib22)\]
brings these ideas together by using the same model as teacher and
student under different contexts, with reference-conditioned token
targets evaluated on student rollouts. OSAD builds directly on this
construction and uses the output schema to adapt supervision to token
roles, assigning different divergences to content and structure within a
shared all-token objective.

##### Self-distillation and teacher evolution.

Born-again networks \[[114](#bib.bib114)\] and Noisy
Student \[[115](#bib.bib115)\] improve models through successive
teacher-student generations, while Mean Teacher and
DINO \[[116](#bib.bib116), [117](#bib.bib117)\] update a teacher through
an exponential moving average of student parameters. These approaches
establish teacher evolution as a general mechanism for refining
supervision. OSAD combines periodic teacher refresh with
reference-conditioned on-policy targets: the teacher remains frozen
within each round, then inherits the trained student’s checkpoint for
the next round. This design couples schema-aware token supervision with
a supervision source that incorporates the student’s accumulated
learning, as described in
Subsec. [4.2.3](#S4.SS2.SSS3 "4.2.3 OmniSchema-Aware On-Policy Distillation ‣ 4.2 Post-Training ‣ 4 Training ‣ Youtu-Parsing-Omni: One Encoder, One Schema, All Modalities").

## 7 Limitations and Conclusion

##### Limitations.

Compared with its predecessor Youtu-Parsing \[[4](#bib.bib4)\],
Youtu-Parsing-Omni does not yet implement inference acceleration.
Youtu-Parsing reuses shared encoder features across the regions of a
page and applies token- and query-level parallel decoding, whereas
Youtu-Parsing-Omni decodes end-to-end and autoregressively with a larger
decoder. We therefore expect its throughput on dense structured content
such as tables to be lower. We will bring parallel decoding and related
acceleration techniques to Youtu-Parsing-Omni in future work.

##### Conclusion.

We presented Youtu-Parsing-Omni, an omni-modal parser that converts
documents, images, audio, and video into structured records grounded in
space and time. Its design rests on *one encoder for every modality and
one schema for every task*. The encoder, Youtu-Omni-Encoder, replaces
separate vision and audio towers with one text-initialized Transformer,
in which visual and acoustic tokens share a space-time positional
encoding and interact within short audio-visual windows. The schema,
OmniSchema, casts the outputs of all ten tasks into one grounded format,
which allows a single self-evolving post-training procedure, OSAD, to
use the same token-role-based objective across tasks. Together, the two
components let a single $`5`$ B-parameter checkpoint serve all ten
parsing tasks with one inference configuration. Youtu-Parsing-Omni
achieves the highest OmniDocBench v1.6 score among all compared systems
($`96.96`$) and leads all open-weight models on OmniParsingBench
($`75.08`$).

### A.1 Document Parsing

| Field | Scope |  Semantics |
|----|----|----|
| id | element |  Unique element identifier. |
| category | element |  Element type: text, table, formula, code, caption, header, footer, title, chemical, score, chart, flowchart, figure, seal, or geometric. |
| bbox | element |  Bounding box of the element in page coordinates. |
| content.text | element |  Transcription for text-like elements, code, chemical structures, and ABC notation. |
| content.latex | formula |  Formula transcription in LaTEX. |
| content.otsl | table |  Table structure and content in OTSL. |
| content.markdown | chart |  Structured chart data in Markdown. |
| content.mermaid | flowchart |  Nodes and directed relations in Mermaid. |
| content.geometric | geometric |  Geometric primitives and relations. |
| content.caption | visual element |  Description of a chart, flowchart, figure, or geometric diagram. |
| attributes.language | element |  Language of the element content. |
| reading_order | page |  Ordered list of element identifiers. |
| global_description | page |  Page-level caption, narrative, language, and semantic tag. |

Table 13: Annotation fields of the document parsing dataset and their
semantics.

The document data consist of two parts: full pages for layout and
content parsing, and dedicated data for specialized elements. For full
pages, public document datasets are typically annotated for a single
sub-task and contain label noise, so we re-annotate them with expert
models and vision-language models (VLMs). Pages that pass consistency
checks and a vote among annotators with different architectures are
retained directly; of the pages on which the annotators disagree, about
$`10\%`$ are corrected by human experts and added back to the corpus.
Synthetic pages are rendered from layout templates of magazines, papers,
textbooks, manuals, and advertisements, so their labels are exact by
construction. For specialized elements, source tables of public chart
datasets \[[118](#bib.bib118), [119](#bib.bib119), [120](#bib.bib120)\]
are serialized to Markdown, and flowcharts, mind maps, and architecture
diagrams generated from sampled graphs are serialized to Mermaid.
Molecules from PubChem \[[121](#bib.bib121)\] and
ChEMBL \[[122](#bib.bib122)\] are rendered into $`1.0`$ M pairs of
images and SMILES \[[33](#bib.bib33)\] strings, geometric figures are
produced by a procedural generator with primitives and relations aligned
to pixels by construction, and music scores from
PDMX \[[46](#bib.bib46)\] are converted to ABC and rendered with varied
engines, fonts, and layouts.

### A.2 Natural Image Parsing

| Field | Scope |  Semantics |
|----|----|----|
| id | element |  Unique element identifier. |
| category | element |  Element type, fixed to entity. |
| bbox | element |  Bounding box of a salient object. |
| tag | element |  A word naming the object inside the bounding box. |
| content.text | element |  OCR result inside the bounding box; "" when the annotation pipeline returns no text. |
| content.caption | element |  Precise and concise caption of the region inside the bounding box. |
| global_description.caption | image |  Precise and concise caption of the image. |
| global_description.narrative | image |  Detailed description of the image, within $`100`$ characters. |
| global_description.scene | image |  Short phrase describing where the image takes place. |

Table 14: Annotation fields of the natural image parsing dataset and
their semantics.

Each image is annotated in three stages: captioning, entity
verification, and localization. We first prompt a VLM to write a short
caption restricted to the subject, the scene, and the action, followed
by a longer narrative conditioned on that caption and the image. Next, a
large language model (LLM) extracts the entities named in the caption
and the narrative, and a second VLM checks whether each entity is
visible in the image. If any caption entity is hallucinated, the sample
is discarded; hallucinated narrative entities are instead removed, the
narrative is rewritten from the remaining entities, and the entity lists
of the caption and the narrative are merged. Finally, each remaining
entity is localized independently by SAM-3 \[[123](#bib.bib123)\] and by
a VLM. When the IoU of the two boxes exceeds a threshold, their
intersection is kept; otherwise, an LLM selects the box whose region
caption matches the entity. The region captions, kept as
content.caption, and the scene phrase global_description.scene are also
generated by a VLM. The text inside each box is transcribed by
Youtu-Parsing \[[4](#bib.bib4)\] and by a general-purpose OCR engine;
when the two transcripts disagree, the element is discarded. An empty
text records that neither OCR system returned text, rather than
guaranteeing that the region contains none.

### A.3 Audio Parsing

| Field | Scope |  Semantics |
|----|----|----|
| id | segment |  Unique segment identifier. |
| kind | segment |  Segment type: vocal or nonvocal. |
| audio.asr_text | vocal segment |  Verbatim transcription of the speech in the segment. |
| audio.speaker_id | vocal segment |  Speaker identifier, consistent across the chunk. |
| audio.timbre_caption | vocal segment |  Voice timbre: gender, age, pitch, breathiness, etc. |
| audio.instruct_caption | vocal segment |  Speech delivery characteristics: emotion, pace, prosody, etc. |
| audio.scene_caption | vocal segment |  Mid-level scene context: time, location, activity, etc. |
| language | vocal segment |  Language of the segment (zh/en/unk). |
| audio.env_caption | nonvocal segment |  Description of the background acoustic environment. |
| audio.acoustic_events | segment |  Closed-set acoustic-event labels (e.g., Human Voice, Music). |
| start/end_timestamp | segment |  Segment boundaries relative to the chunk onset (HH:MM:SS). |
| global_description | entire chunk |  Holistic description aggregating information across segments. |

Table 15: Annotation fields of the audio parsing dataset and their
semantics.

The audio data consist of in-house audiobooks, podcasts, and
conversations. Each clip is first segmented: a
BEATs \[[124](#bib.bib124)\] tagger trained with
PretrainedSED \[[125](#bib.bib125)\] labels every frame with an
AudioSet \[[126](#bib.bib126)\] class, and the resulting vocal and
nonvocal regions are split into segments of at most $`30`$ s and packed
into chunks of about $`60`$ s, each of which forms one training sample.
Speech is then attributed and transcribed:
DiariZen \[[127](#bib.bib127)\] assigns clip-level speaker identities,
three ASR systems with different architectures transcribe each turn, and
the transcript with the smallest total pairwise WER is retained, while
the largest pairwise WER is recorded as a disagreement score. The
language of each segment is identified from the transcript by
fastText \[[128](#bib.bib128)\] and from the audio by
MMS-LID \[[129](#bib.bib129)\], and word timestamps are obtained by MMS
forced alignment. The timbre, delivery, and environment captions
(timbre_caption, instruct_caption, and env_caption) are generated by an
audio-language model, and the scene caption and the chunk-level
global_description by an LLM. For fine-tuning, a chunk is retained only
if the two language identifiers agree and its disagreement score does
not exceed $`0.1`$. For reinforcement learning, we further discard
chunks whose four offline rollouts receive uniformly high, uniformly
low, or identical scores from an audio-language judge; this judge is
used only for this offline filtering, and online training uses the
rule-based verifiable reward of
Equ. [2](#S4.E2 "In 4.2.2 Schema-Routed RLVR ‣ 4.2 Post-Training ‣ 4 Training ‣ Youtu-Parsing-Omni: One Encoder, One Schema, All Modalities").

| Field | Scope | Category |  Semantics |
|----|----|----|----|
| id | segment | shared |  Unique segment identifier. |
| subtype | video | shared |  Video type: natural_video or text_rich_video. |
| start/end_timestamp | segment | shared |  Temporal boundaries relative to video onset. |
| visual.elements | segment | shared |  Salient objects and on-screen text; each item has a category (object or text) and, for text, an ocr_type (e.g., title). |
| visual.atomic_actions | segment | shared |  Fine-grained actions within the segment. |
| visual.object_actor_interactions | segment | shared |  Interactions between actors and objects. |
| visual.camera_motion | segment | shared |  Camera motion at two granularities (l1: coarse, l2: fine). |
| visual.event_description | segment | shared |  Summary of the segment-level visual event. |
| audio.speaker_id | segment | shared |  Speaker identifier, consistent across the video. |
| audio.asr_text | segment | shared |  Transcription of speech in the segment. |
| audio.acoustic_events | segment | shared |  Acoustic-event labels of the segment audio. |
| global_description | video | shared |  Global scene, narrative, caption, and semantic tag. |
| structured_report | video | shared |  Markdown report of text-centric content for text-rich video; an empty string ("") for natural video. |

Table 16: Annotation fields of the video parsing dataset and their
semantics.

Each video is first segmented by a VLM, at event and scene changes for
natural video and at slide, page, and interface transitions for
text-rich video. The VLM then annotates the visual fields of each
segment; in parallel, an ASR system transcribes the corresponding audio,
a speaker diarization model assigns speaker IDs that remain consistent
across the entire video, and an acoustic event tagger labels its
acoustic events; the visual and audio annotations are aligned only
through the segment timestamps. Finally, an LLM summarizes the segments
into the global_description and, for text-rich video, into the
structured_report.

### B.2 Youtu-Omni-Encoder

#### B.2.1 Modality Stems

Both stems are thin: they only turn raw signals into tokens of the
shared-block width $`d`$ and together hold less than $`3\%`$ of the
encoder parameters. The *vision stem* is a single linear map from each
$`16\times 16`$ patch, taken at native resolution under a token
budget \[[26](#bib.bib26)\], to one token, with no convolution, absolute
position table or class token, so all spatial information enters through
RoPE
(Subsec. [2.2](#S2.SS2.SSS0.Px1 "One positional encoding for all modalities. ‣ 2.2 Unified Positional Encoding and Audio-Visual Fusion ‣ 2 Model ‣ Youtu-Parsing-Omni: One Encoder, One Schema, All Modalities")).
The *audio stem* applies three $`3\times 3`$, stride-2 convolutions with
GELU to the log-mel spectrogram, so each $`1`$ s window of $`100`$ mel
frames becomes $`\lceil 100/8\rceil=13`$ tokens, i.e., $`13`$ audio
tokens per second. It then folds the remaining frequency bins into the
channels and projects them to width $`d`$ with a bias-free linear map,
so that audio tokens have exactly the layout the shared block expects.

#### B.2.2 Shared Transformer Block

The shared block is a standard bias-free pre-norm Transformer
(RMSNorm \[[27](#bib.bib27)\], SwiGLU FFN \[[28](#bib.bib28)\],
grouped-query attention \[[29](#bib.bib29)\] with
QK-Norm \[[30](#bib.bib30)\]) without a final normalization layer, since
the merger supplies its own. It departs from a language-model decoder in
two ways: attention is bidirectional, and rotary embeddings are read
from a per-token angle matrix, which makes the axis-factorized scheme of
Subsec. [2.2](#S2.SS2.SSS0.Px1 "One positional encoding for all modalities. ‣ 2.2 Unified Positional Encoding and Audio-Visual Fusion ‣ 2 Model ‣ Youtu-Parsing-Omni: One Encoder, One Schema, All Modalities")
expressible and lets the same token be rotated differently in different
layers on the video path
(Subsec. [2.2](#S2.SS2 "2.2 Unified Positional Encoding and Audio-Visual Fusion ‣ 2 Model ‣ Youtu-Parsing-Omni: One Encoder, One Schema, All Modalities")).

#### B.2.3 Positional Encoding

Sharing one block across modalities makes positional encoding the
central design question: a single frequency budget of
$`d_{\mathrm{rot}}=d_{h}/2`$ rotary slots, with $`d_{h}`$ the per-head
dimension of the shared block, has to express 2D image geometry, 1D
audio time and, for fused video, the correspondence between the two.

A plain 2D-vision / 1D-audio RoPE \[[31](#bib.bib31)\] would place video
frames and their audio under incomparable positional encodings, with no
frame index and with audio time occupying the slots that vision uses for
height.

##### Chunked axis-factorized RoPE.

We instead partition the rotary budget across a set of semantic axes
$`\mathcal{A}`$: each axis $`A\in\mathcal{A}`$ receives a contiguous
segment of $`d_{A}`$ slots with its own inverse-frequency table, and the
angle row $`\boldsymbol{\Phi}[s]`$ of token $`s`$ concatenates the
per-axis contributions:

|  |  |  |  |
|----|----|----|----|
|  |
``` math
\boldsymbol{\Phi}[s]=\big\|_{A\in\mathcal{A}}\ x^{(A)}_{s}\,\boldsymbol{\phi}^{(A)},\qquad\phi^{(A)}_{k}=b_{A}^{-\,k/d_{A}},\ \ k=0,\dots,d_{A}-1,\qquad\sum_{A\in\mathcal{A}}d_{A}=d_{\mathrm{rot}},
``` |  | (7) |

where $`x^{(A)}_{s}`$ is the position index of token $`s`$ along axis
$`A`$ and $`b_{A}`$ its rotary base. Because each segment is normalized
by its own width $`d_{A}`$, every axis spans the full frequency range
regardless of how many slots it owns. Youtu-Parsing-Omni uses
$`\mathcal{A}=\{T,H,W\}`$ with a common base and
$`(d_{T},d_{H},d_{W})=(21,21,22)`$ at $`d_{\mathrm{rot}}=64`$
(Fig. [4](#S2.F4 "Figure 4 ‣ Stems. ‣ 2.1 Youtu-Omni-Encoder ‣ 2 Model ‣ Youtu-Parsing-Omni: One Encoder, One Schema, All Modalities"));
vision tokens take $`t`$ from the frame index and $`(h,w)`$ from the
patch grid, while audio tokens take $`t`$ from the time offset and set
$`h=w=0`$, so both modalities share one time axis
(Subsec. [2.2](#S2.SS2 "2.2 Unified Positional Encoding and Audio-Visual Fusion ‣ 2 Model ‣ Youtu-Parsing-Omni: One Encoder, One Schema, All Modalities")).

##### Unused variants.

The formulation admits two variants that the final model does not use.
First, an explicit *modality* axis $`M`$ with a categorical positional
encoding (image, audio, video frame, video audio) gave no gain with
$`d_{M}=4`$ in preliminary runs, since the two stems already produce
readily separable features. Second, an *interleaved* layout, in the
style of the interleaved M-RoPE of Qwen3-VL \[[63](#bib.bib63)\], lets
$`T`$, $`H`$, and $`W`$ share one full-length frequency table through a
stride-3 assignment, so that each axis covers the whole spectrum without
per-axis renormalization. Because the per-axis normalization of
Equ. [7](#A2.E7 "In Chunked axis-factorized RoPE. ‣ B.2.3 Positional Encoding ‣ B.2 Youtu-Omni-Encoder ‣ Appendix B Architecture Details ‣ Youtu-Parsing-Omni: One Encoder, One Schema, All Modalities")
already gives every axis the full frequency range, the two layouts
differ only in where each axis samples that range; the interleaved
variant is a drop-in replacement, but preliminary runs favored the
chunked layout for videos of up to $`64`$ frames. Stage 3 training uses
up to $`512`$ frames, while inference uses $`64`$ frames.

#### B.2.4 Token Merger and Projector

Down-sampling acts *after* the shared block, so attention runs at full
resolution while the decoder receives fewer tokens. Vision tokens are
merged by concatenating each $`2\times 2`$ block within a frame along
the feature axis ($`4\times`$ fewer tokens, e.g., $`196`$ decoder tokens
for a $`448\times 448`$ image), which is nearly free because adjacent
patches are highly redundant. Each modality then applies RMSNorm to the
merged features, followed by a bias-free two-layer GELU MLP that maps
them to the decoder width, so they enter the decoder as ordinary input
embeddings.

### B.3 Language Model

The encoder’s tokens are consumed by a decoder that we pre-train for
text. It is a dense $`40`$-layer Transformer of width $`2{,}560`$ with
multi-head latent attention (MLA) \[[130](#bib.bib130)\], which
compresses the key-value cache for long outputs, and with 1D rotary
positions of base $`1.6\times 10^{6}`$ and a $`128`$ k context. Its
pre-training follows the recipe of Youtu-LLM-2B \[[25](#bib.bib25)\],
scaled to $`4.5`$ B parameters. The decoder retains 1D positions because
the encoder already encodes spatial and temporal structure; this lets us
reuse the text checkpoint and its long-context recipe unchanged.

### C.1 Schema-Routed RLVR

The reward in
Equ. [2](#S4.E2 "In 4.2.2 Schema-Routed RLVR ‣ 4.2 Post-Training ‣ 4 Training ‣ Youtu-Parsing-Omni: One Encoder, One Schema, All Modalities")
combines two factors: shared well-formedness $`\Omega`$ and
schema-specific content accuracy $`\mathrm{core}_{\nu}`$. We describe
their components below and optimize the resulting reward with
GRPO \[[18](#bib.bib18)\], using group-mean-centered rewards as
advantages.

##### Well-formedness ($`\Omega`$).

$`\Omega`$ combines three components: *(i) format validity*
($`\mathrm{Fmt}`$), which averages checks for decoding after repair,
decoding without repair, correctly typed required fields, and absence of
undeclared fields; *(ii) repetition* ($`P_{\mathrm{repeat}}`$), which
penalizes excess top-level units, repeated field-scoped $`16`$-grams,
and looping relative to the reference; and *(iii) incomplete coverage*
($`P_{\mathrm{under}}`$), which penalizes shortfalls in unit counts,
semantic content, and available category or temporal fields. Each
penalty takes the largest violation across its checks, with
task-specific thresholds estimated from clean rollouts. Undecodable
outputs and outputs without a primary payload receive zero reward.

##### Content accuracy ($`\mathrm{core}_{\nu}`$).

The content factor combines a grounded-field score $`\Pi_{\nu}`$ with a
description score $`\Gamma_{\nu}`$. When the reference includes
descriptions, $`\mathrm{core}_{\nu}=(\Pi_{\nu}+\Gamma_{\nu})/2`$;
otherwise, $`\mathrm{core}_{\nu}=\Pi_{\nu}`$. For the document and image
tasks used in RLVR, the grounded-field scorer is selected as follows:
*(i) charts and flowcharts* use RMS-$`F_{1}`$ and Mermaid $`F_{1}`$,
respectively
(App. [D.1.3](#A4.SS1.SSS3 "D.1.3 OmniParsingBench ‣ D.1 Metric Definitions ‣ Appendix D Evaluation Details ‣ Youtu-Parsing-Omni: One Encoder, One Schema, All Modalities"));
*(ii) documents* average sequence similarity over reference-present
text, formula, table, and reading-order categories; *(iii) natural
images* combine entity text similarity and box IoU with weights $`0.7`$
and $`0.3`$, renormalized over available annotations; and *(iv) other
structured fields* use sequence similarity for geometric expressions and
normalized SMILES, and text similarity for OCR and music transcriptions.
The description score $`\Gamma_{\nu}`$ averages text similarity over
reference-present descriptive fields. For both entity and description
scoring, text similarity is the mean of token-set $`F_{1}`$ and
normalized character-sequence similarity after lowercasing and
whitespace normalization. This training reward is distinct from the
LLM-judged CaptionQA accuracy used to evaluate Cognition on
OmniParsingBench
(App. [D.1.3](#A4.SS1.SSS3 "D.1.3 OmniParsingBench ‣ D.1 Metric Definitions ‣ Appendix D Evaluation Details ‣ Youtu-Parsing-Omni: One Encoder, One Schema, All Modalities")).

Algorithm 1 OSAD with self-evolution.

Starting from the RLVR checkpoint, OSAD replaces sequence-level rewards
with the token-level supervision defined in
Subsec. [4.2.3](#S4.SS2.SSS3 "4.2.3 OmniSchema-Aware On-Policy Distillation ‣ 4.2 Post-Training ‣ 4 Training ‣ Youtu-Parsing-Omni: One Encoder, One Schema, All Modalities").
Alg. [1](#alg1 "Algorithm 1 ‣ C.2 OmniSchema-Aware On-Policy Distillation ‣ Appendix C Post-Training Details ‣ Youtu-Parsing-Omni: One Encoder, One Schema, All Modalities")
summarizes the training loop; below we specify its sampling, batch
reduction, and round schedule.

##### Sampling and loss reduction.

We sample one response per query with sampling temperature
$`T_{\mathrm{samp}}=0.35`$, nucleus cutoff $`0.9`$, and top-$`k=50`$.
This sampling temperature is distinct from the distillation temperatures
in
Equ. [3](#S4.E3 "In Token-adaptive on-policy supervision. ‣ 4.2.3 OmniSchema-Aware On-Policy Distillation ‣ 4.2 Post-Training ‣ 4 Training ‣ Youtu-Parsing-Omni: One Encoder, One Schema, All Modalities")
and
Equ. [4](#S4.E4 "In Token-adaptive on-policy supervision. ‣ 4.2.3 OmniSchema-Aware On-Policy Distillation ‣ 4.2 Post-Training ‣ 4 Training ‣ Youtu-Parsing-Omni: One Encoder, One Schema, All Modalities").
The admission gate then admits a response to the loss only if it passes
JSON-validity, schema-conformance, box-syntax, and repetition checks;
rejected rollouts are masked in place rather than repaired. To make the
global averaging in
Equ. [5](#S4.E5 "In Token-adaptive on-policy supervision. ‣ 4.2.3 OmniSchema-Aware On-Policy Distillation ‣ 4.2 Post-Training ‣ 4 Training ‣ Youtu-Parsing-Omni: One Encoder, One Schema, All Modalities")
explicit, let $`\mathcal{B}_{k}^{+}`$ be the admitted rollout instances
on data-parallel rank $`k`$, with count $`n_{k}=|\mathcal{B}_{k}^{+}|`$
and loss sum
$`s_{k}=\sum_{y\in\mathcal{B}_{k}^{+}}\mathcal{L}_{\mathrm{row}}(y)`$.
For a nonzero global count $`N=\sum_{k}n_{k}`$, the objective is

|     |                                      |     |
|-----|--------------------------------------|-----|
|     |
       ``` math
       \mathcal{L}=\frac{\sum_{k}s_{k}}{N}.
       ```                                   |     |

This is a mean over admitted instances, not an unweighted mean of
per-rank means when admission counts differ. A rank with no admitted
rollout contributes zero to both sums in this expression. An update is
skipped only when $`N=0`$.

##### Round schedule.

The first round starts from the RLVR checkpoint; subsequent rounds use
the preceding student’s checkpoint according to
Equ. [6](#S4.E6 "In Self-evolution through teacher refresh. ‣ 4.2.3 OmniSchema-Aware On-Policy Distillation ‣ 4.2 Post-Training ‣ 4 Training ‣ Youtu-Parsing-Omni: One Encoder, One Schema, All Modalities").
The content and structure weights $`(\alpha_{c},\alpha_{s})`$ are
$`(0.50,0.10)`$ in round 1, $`(0.60,0.10)`$ in round 2, and
$`(0.80,0.08)`$ in rounds 3–6, progressively emphasizing content
supervision. The learning rate is $`2\times 10^{-7}`$ for rounds 1–2 and
$`1.5\times 10^{-7}`$ for rounds 3–6.

### D.1 Metric Definitions

#### D.1.1 OmniDocBench

OmniDocBench v1.6 \[[42](#bib.bib42)\] evaluates document parsing on
pages annotated with text blocks, formulas, tables, and reading order.
We follow the official evaluation: each output is converted to Markdown,
and the official pipeline matches predicted and reference text blocks,
formulas, and tables one-to-one before computing the metrics below. Text
Edit is the normalized edit distance between matched predicted and
reference text. CDM \[[131](#bib.bib131)\] renders the predicted and
reference LaTEX formulas and reports the character-level $`F_{1}`$ of
the rendered images. TEDS \[[132](#bib.bib132)\] is a similarity based
on the tree edit distance between the predicted and reference HTML
tables, and TEDS-S ignores cell text. Reading Order Edit is the
normalized edit distance between the predicted component order and the
ground-truth reading order.

#### D.1.2 PureDocBench

PureDocBench \[[43](#bib.bib43)\] evaluates the robustness of document
parsing to image degradation. Every page is generated from an HTML/CSS
source, which also provides the structured ground truth, and is rendered
in three matched versions: a clean rendering, a digitally degraded
version, and a physically recaptured version (printed on paper and
photographed). Because the three tracks share identical content and
reference answers, score differences isolate the effect of the image
condition. All component metrics—Text Edit, Formula CDM, Table TEDS, and
Reading Order Edit—are computed exactly as on OmniDocBench
(App. [D.1.1](#A4.SS1.SSS1 "D.1.1 OmniDocBench ‣ D.1 Metric Definitions ‣ Appendix D Evaluation Details ‣ Youtu-Parsing-Omni: One Encoder, One Schema, All Modalities")),
with Overall defined per track as the mean of
$`(1-\text{Text Edit})\cdot 100`$, Formula CDM, and Table TEDS; Avg₃ is
the mean of the three track Overalls.

#### D.1.3 OmniParsingBench

OmniParsingBench \[[11](#bib.bib11)\] evaluates structured parsing on
five splits: natural images, graphics (charts and geometric figures),
audio, natural video, and text-rich video. Each split is scored by two
components. *Perception* measures the accuracy of the grounded fields of
a parse, such as localization, element extraction, OCR, and ASR, against
the ground truth. *Cognition* is measured by multiple-choice questions
(CaptionQA) that an LLM judge answers by reading only the parse.
Dimension accuracies are aggregated using the split-specific rules
below; text-rich video first averages dimensions within the parsing and
report groups, then averages the two group scores. We use
Qwen3-235B-A22B for all LLM judging in this benchmark, including
Cognition and model-based Perception grader components. *Overall* is the
mean of Perception and Cognition multiplied by the post-repair parse
rate. Because the benchmark is released without a complete evaluation
toolkit, we implement these metrics following the benchmark definitions.
Before scoring, every output is converted to a common representation and
schema repair is applied. Outputs that remain unparseable are excluded
from the component metrics and penalized through the parse rate;
successfully repaired outputs are included. For each task $`t`$, let the
parse rate $`r_{t}\in[0,1]`$ be the fraction of outputs that are
parseable after repair if necessary:

|  |  |  |  |
|----|----|----|----|
|  |
``` math
r_{t}=\frac{N_{\mathrm{parsed},t}}{N_{\mathrm{total},t}},\qquad O_{t}=r_{t}\,\frac{P_{t}+C_{t}}{2}.
``` |  | (8) |

##### Natural image.

Perception evaluates the localization and recognition of three kinds of
targets: plain entities, knowledge entities, and text regions. Predicted
and reference targets of each kind are matched separately by the
Hungarian algorithm at IoU $`\geq 0.5`$. The identity of each matched
entity is then verified by an LLM judge, and a matched text region is
counted as correct when its normalized similarity exceeds $`0.7`$ or
when the judge finds the reference text in the caption. Each Perception
component is the recall after these checks. Cognition covers the
dimensions $`\mathcal{D}_{\mathrm{img}}=`$ {theme, emotion, scene,
count, attributes, location, text, style, composition}:

|  |  |  |  |
|----|----|----|----|
|  |
``` math
P_{\mathrm{img}}=\operatorname{Avg}(p_{\mathrm{plain}},p_{\mathrm{knowledge}},p_{\mathrm{text}}),\quad C_{\mathrm{img}}=\operatorname{Avg}_{d\in\mathcal{D}_{\mathrm{img}}}c_{d},\quad O_{\mathrm{img}}=r_{\mathrm{img}}\operatorname{Avg}(P_{\mathrm{img}},C_{\mathrm{img}}).
``` |  | (9) |

##### Graphics.

Charts and geometric figures are scored separately and then averaged.
For charts, RMS-$`F_{1}`$ \[[133](#bib.bib133)\] scores statistical
charts by optimally matching table entries on header and value
similarity, and Mermaid $`F_{1}`$ scores structural diagrams by
averaging the $`F_{1}`$ of labeled nodes and labeled edges. Chart
Cognition covers OCR and data, visual elements, and logical reasoning:

|  |  |  |  |
|----|----|----|----|
|  |
``` math
P_{\mathrm{chart}}=\operatorname{Avg}(p_{\mathrm{rms}},p_{\mathrm{mermaid}}),\quad C_{\mathrm{chart}}=\operatorname{Avg}(c_{\mathrm{ocr/data}},c_{\mathrm{visual}},c_{\mathrm{logic}}),\quad O_{\mathrm{chart}}=r_{\mathrm{chart}}\frac{P_{\mathrm{chart}}+C_{\mathrm{chart}}}{2}.
``` |  | (10) |

For geometric figures, predictions are canonicalized and scored on
positioning, existence of primitives, and relations, and geometry
Cognition covers basic elements, geometric relations, and quantitative
relations:

|  |  |  |  |
|----|----|----|----|
|  |
``` math
P_{\mathrm{geo}}=0.3p_{\mathrm{pos}}+0.3p_{\mathrm{prim}}+0.4p_{\mathrm{rel}},\quad C_{\mathrm{geo}}=\operatorname{Avg}(c_{\mathrm{basic}},c_{\mathrm{relation}},c_{\mathrm{quant}}),\quad O_{\mathrm{geo}}=r_{\mathrm{geo}}\frac{P_{\mathrm{geo}}+C_{\mathrm{geo}}}{2}.
``` |  | (11) |

Graphics Perception and Cognition average the corresponding chart and
geometry components; Graphics Overall averages their separately
computed, parse-rate-adjusted Overall scores:

|  |  |  |  |
|----|----|----|----|
|  |
``` math
P_{\mathrm{graphics}}=\operatorname{Avg}(P_{\mathrm{chart}},P_{\mathrm{geo}}),\quad C_{\mathrm{graphics}}=\operatorname{Avg}(C_{\mathrm{chart}},C_{\mathrm{geo}}),\quad O_{\mathrm{graphics}}=\operatorname{Avg}(O_{\mathrm{chart}},O_{\mathrm{geo}}).
``` |  | (12) |

##### Audio.

Perception combines segmentation, event labeling, and transcription.
Predicted and reference segments are matched one-to-one by temporal IoU,
and Time $`F_{1}`$ is averaged over the IoU thresholds
$`\{0.3,0.5,0.7\}`$. Key $`F_{1}`$ compares the event labels of
overlapping segments. The concatenated transcript is scored by WER or
CER, which is converted to a score by
$`p_{\mathrm{asr}}=100\,\big(1-\min(1,e_{\mathrm{asr}})\big)`$.
Cognition covers information extraction and recognition:

|  |  |  |  |
|----|----|----|----|
|  |
``` math
P_{\mathrm{audio}}=\operatorname{Avg}(p_{\mathrm{time}},p_{\mathrm{key}},p_{\mathrm{asr}}),\quad C_{\mathrm{audio}}=\operatorname{Avg}(c_{\mathrm{info}},c_{\mathrm{recognition}}),\quad O_{\mathrm{audio}}=r_{\mathrm{audio}}\operatorname{Avg}(P_{\mathrm{audio}},C_{\mathrm{audio}}).
``` |  | (13) |

##### Natural video.

Time $`F_{1}`$ and the ASR score are computed as for audio. For Key
$`F_{1}`$, action and interaction phrases are matched semantically by an
LLM, which also rates the descriptions of segment pairs at temporal IoU
$`\geq 0.5`$ from $`0`$ to $`5`$ to obtain $`p_{\mathrm{visual}}`$.
Cognition covers the dimensions $`\mathcal{D}_{\mathrm{vid}}=`$
{object/attribute, event, emotion, audio-visual causality}:

|  |  |  |  |
|----|----|----|----|
|  |
``` math
P_{\mathrm{video}}=\operatorname{Avg}(p_{\mathrm{time}},p_{\mathrm{key}},p_{\mathrm{asr}},p_{\mathrm{visual}}),\quad C_{\mathrm{video}}=\operatorname{Avg}_{d\in\mathcal{D}_{\mathrm{vid}}}c_{d},\quad O_{\mathrm{video}}=r_{\mathrm{video}}\operatorname{Avg}(P_{\mathrm{video}},C_{\mathrm{video}}).
``` |  | (14) |

##### Text-rich video.

Time $`F_{1}`$ is computed as for natural video, and the ASR score as
for audio. For the OCR score, repeated adjacent screens are merged, and
the ordered on-screen text is scored by one minus the clipped CER:

|  |  |  |  |
|----|----|----|----|
|  |
``` math
P_{\mathrm{textvid}}=\operatorname{Avg}(p_{\mathrm{time}},p_{\mathrm{ocr}},p_{\mathrm{asr}}).
``` |  | (15) |

Cognition averages two groups of dimensions, named as in
Tab. [10](#S5.T10 "Table 10 ‣ Graphics chart and geometry. ‣ 5.4 OmniParsingBench ‣ 5 Evaluation ‣ Youtu-Parsing-Omni: One Encoder, One Schema, All Modalities"):
the parsing dimensions $`\mathcal{D}_{\mathrm{parse}}=`$ {audio
information extraction, objects, OCR, attributes and states, events,
audio-visual information synthesis, causal reasoning} and the report
dimensions $`\mathcal{D}_{\mathrm{report}}=`$ {core summary, outline,
deep content}:

|  |  |  |  |  |
|----|----|----|----|----|
|  | $`\displaystyle C_{\mathrm{parse}}`$ | $`\displaystyle=\operatorname{Avg}_{d\in\mathcal{D}_{\mathrm{parse}}}c_{d},\quad C_{\mathrm{report}}=\operatorname{Avg}_{d\in\mathcal{D}_{\mathrm{report}}}c_{d},`$ |  | (16) |
|  | $`\displaystyle C_{\mathrm{textvid}}`$ | $`\displaystyle=\operatorname{Avg}(C_{\mathrm{parse}},C_{\mathrm{report}}),\quad O_{\mathrm{textvid}}=r_{\mathrm{textvid}}\operatorname{Avg}(P_{\mathrm{textvid}},C_{\mathrm{textvid}}).`$ |  |  |

The leaderboard Avg. is the equal-weight mean of the five split Overall
scores:

|  |  |  |  |
|----|----|----|----|
|  |
``` math
\mathrm{Avg}_{\mathrm{leaderboard}}=\frac{O_{\mathrm{img}}+O_{\mathrm{graphics}}+O_{\mathrm{audio}}+O_{\mathrm{video}}+O_{\mathrm{textvid}}}{5}.
``` |  | (17) |

#### D.1.4 ChemOCR

ChemOCR \[[45](#bib.bib45)\] evaluates optical chemical structure
recognition on $`1{,}000`$ image–SMILES pairs before scoring exclusions.
A single predicted SMILES is extracted from each output. Following the
official evaluator of ChemVLM \[[45](#bib.bib45)\],
RDKit \[[134](#bib.bib134)\] parses the predicted and reference SMILES
with MolFromSmiles, creates their default RDKFingerprint bit vectors,
and computes Tanimoto similarity,
$`s_{i}=|A_{i}\cap B_{i}|/|A_{i}\cup B_{i}|`$, where $`A_{i}`$ and
$`B_{i}`$ are the sets of active fingerprint bits. In practice, the
official scorer excludes $`10`$ samples with unparseable reference
SMILES from the $`1{,}000`$-sample benchmark. On the remaining $`N=990`$
samples, we report $`\mathrm{Avg.\ Sim.}=100\sum_{i}s_{i}/N`$ and
$`\mathrm{Tani@1.0}=100\sum_{i}\mathbf{1}[s_{i}=1]/N`$, which measure
the overall similarity and the number of perfectly correct samples,
respectively.

#### D.1.5 PDMX-Synth

PDMX-Synth \[[8](#bib.bib8)\] evaluates full-page optical music
recognition on $`800`$ rendered score images paired with ABC
transcriptions. Following LEGATO \[[8](#bib.bib8)\], we report the
normalized ABC edit distance at the character, symbol, and line levels
(CER, SER, and LER).
````
