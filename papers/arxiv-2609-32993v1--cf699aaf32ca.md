###### Abstract

Multi-step agents are trained on flat action streams: SFT and RLVR
weight every token uniformly and ignore the sub-procedures that recur
across tasks, the hierarchy that lets humans plan top-down from reusable
routines. This structure sits unused, and flat training uses each scarce
trajectory less fully than its content allows. Recent agents do use that
structure, but only as LLM-written skills in context, never in the
weights, so their gains do not generalize beyond retrieval. We instead
recover this hierarchy from the data itself and train on it, with no LLM
calls. Following text tokenizers, which build a vocabulary by counting
alone, we score action spans by reusability and merge canonicalized
actions into a _reusable eXperience tree_ (X-Tree). Each X-Tree node
captures how a frequent and success-bearing skill is composed from
sub-skills, guiding efficient generalization. We integrate X-Tree into
three training settings: offline RL, with each node as a training
instance; online RLVR, with an adaptive skill bonus; and on-policy
self-distillation, with X-Tree as the self-teacher’s privileged context.
Across WebArena, ScienceWorld, and WebShop at three model scales, X-Tree
improves over standard recipes at matched data and budget by up to
$`4.5\%`$ SR on WebArena, $`5.8\%`$ SR on ScienceWorld and $`4.1\%`$
success on WebShop. Matched analyses attribute the gains to the X-Tree
structure and the three integrations.

## 1 Introduction

Human learners spontaneously discover hierarchies that compose recurring
action sequences, acting from goals through sub-goals to primitives
([Miller, 1956](#bib.bib33); [Botvinick et al., 2009](#bib.bib35)).
Language models trained to operate websites ([Zhou and others,
2023](#bib.bib25)), resolve repository issues ([Jimenez et al.,
2024](#bib.bib16)), and act over long-horizon interactive environments
([Xie et al., 2024](#bib.bib15); [Xi and others, 2024](#bib.bib41))
learn the opposite way. A trajectory enters training, whether SFT or
RLVR, as a flat stream of actions, and the objective weights every token
equally ([Ouyang et al., 2022](#bib.bib14); [Shao and others,
2024](#bib.bib27)). This equal weighting overlooks the sub-procedures
that recur across tasks, such as browse-and-select or pick-up-and-move.
The hierarchy is present in the data, but the training objective does
not use it. Uniform training therefore extracts less from each
trajectory than the data allows, requiring more data to learn.

This underutilization is especially costly because experience is scarce.
A trajectory is collected by a human ([Wang et al., 2025](#bib.bib13))
or synthesized and verified by a model ([Gandhi and Neubig,
2025](#bib.bib26)). An environment must be built, its tasks written, and
its verifier made trustworthy. None of this scales the way web text
does. We therefore ask how to extract the most from a finite set of
experience.

To extract more insight from a given pool of experience, recent agent
harnesses such as OpenClaw ask an LLM to summarize past experience as
natural-language workflows and replay them _in context_ ([Wang et al.,
2023](#bib.bib20); [Wang et al., 2024](#bib.bib1)). Nothing is
compressed into the weights, so the experience cannot generalize beyond
retrieval. On-policy self-distillation (OPSD) instead brings such skills
into training, where a self-teacher reads them as privileged context and
re-weights the learner’s own tokens ([Zhao et al., 2026](#bib.bib11);
[Lu et al., 2026](#bib.bib42)). Both depend on an LLM to write the
abstraction, which is costly, uncontrollable and leaves a library which
cannot be reproduced from the data alone.

[5](#A2.F5 "Figure 5 ‣ Appendix B A case study ‣ X-Tree: Tokenizing Reusable Experience for Efficient Agent Generalization")
demonstrates a concrete X-Tree example from a trajectory.

Language models already solve the analogous problem for text before
learning begins. A recurrence-based tokenizer merges co-occurring
characters into a structured vocabulary ([Sennrich et al.,
2016](#bib.bib30)). In this paper, we tokenize experience into reusable
structures
(Figure [1](#S1.F1 "Figure 1 ‣ 1 Introduction ‣ X-Tree: Tokenizing Reusable Experience for Efficient Agent Generalization")).
We canonicalize each action step in a trajectory into a typed token
(i.e., verb$`<`$role$`>`$). We introduce $`\mathcal{X}`$-Score, a
measure of reusability that scores a span by how often it recurs, how
long it is, and how often it appears in successful episodes. Guided by
$`\mathcal{X}`$-Score, we merge adjacent pairs into nodes, then merge
nodes into larger nodes hierarchically. This produces reusable
eXperience tree (X-Tree), a deterministic, auditable hierarchy over a
trajectory corpus built with zero LLM calls. Each X-Tree node captures
how a frequent and success-bearing skill is composed from sub-skills,
guiding efficient generalization.

Our preliminary result shows that X-Tree is already useful as in-context
advice
(Appendix [C](#A3 "Appendix C X-Tree as skills in the context ‣ X-Tree: Tokenizing Reusable Experience for Efficient Agent Generalization")).
We integrate X-Tree into three training settings
(Figure [2](#S3.F2 "Figure 2 ‣ 3.2 X-Tree for Offline RL: Each Node as one RL instance ‣ 3 X-Tree: Tokenizing Reusable EXperience ‣ X-Tree: Tokenizing Reusable Experience for Efficient Agent Generalization")). 1)
Offline RL, when only trajectories exist without an environment. Each
X-Tree node acts as one training instance. The policy partially rolls
out from the gold prefix that precedes the node. We optimize with GRPO
over a step-matching reward with a depth scaled completion bonus. 2)
Online RLVR, when an environment and a verifier exist. X-Tree adds a
bonus for each X-Tree skill a rollout executes with an adaptive weight
that supplies signal while verifier signal is scarce and down-weights it
as the signal becomes informative. 3) OPSD, where X-Tree replaces the
LLM-written skill bank that the self-teacher reads.

We experiment across three environments and three model scales at
matched data and budget. Our offline RL with X-Tree gains $`4.5\%`$
success rate (SR) over full-data SFT on WebArena ([Zhou and others,
2023](#bib.bib25)) with Qwen2.5-7B. Ablations, such as random tree,
attribute the gain to X-Tree and our RL method. Our online RLVR with
X-Tree stays ahead of outcome-based RL across all scales by up to
$`4.9\%`$ SR, leading the held-out tasks, on ScienceWorld ([Wang et al.,
2022](#bib.bib29)). It also consistently outperforms standard recipe by
up to $`3.6\%`$ success and $`4.6\%`$ graded score on WebShop ([Yao et
al., 2022](#bib.bib38)). For OPSD, X-Tree as the privileged context of
self-teacher matches LLM-written skills, with no LLM calls on both
ScienceWorld and WebShop at all scales. We summarize our contributions:

- •
  Three integrations of X-Tree with training, as data, reward, and
  context: offline RL for the trajectories-only setting; online RLVR
  with an adaptive, verifier-aligned skill bonus; and OPSD with X-Tree
  as the self-teacher’s privileged context
  (§[3.2](#S3.SS2 "3.2 X-Tree for Offline RL: Each Node as one RL instance ‣ 3 X-Tree: Tokenizing Reusable EXperience ‣ X-Tree: Tokenizing Reusable Experience for Efficient Agent Generalization")–[3.4](#S3.SS4 "3.4 X-Tree for On-policy Self-Distillation: a Privileged Context ‣ 3 X-Tree: Tokenizing Reusable EXperience ‣ X-Tree: Tokenizing Reusable Experience for Efficient Agent Generalization")).
- •
  Experiments across three environments and three scales showing that
  X-Tree improves over standard recipes at matched data and budget by a
  large margin, with ablations that attribute gains to X-Tree structure
  and to the three integrations
  (§[5](#S5 "5 Results and Analysis ‣ X-Tree: Tokenizing Reusable Experience for Efficient Agent Generalization")).

## 2 Related work

Hierarchy learning. Hierarchical organization of behavior is an
established finding in cognitive science: capacity limits force recoding
into reusable structures, and learners act from goals through sub-goals
to primitives ([Miller, 1956](#bib.bib33); [Gobet et al.,
2001](#bib.bib34); [Botvinick et al., 2009](#bib.bib35)), choosing
decompositions that trade utility against planning cost ([Solway et al.,
2014](#bib.bib36); [Correa et al., 2023](#bib.bib37)). A long line of
work recovers such structure from demonstrations by segmenting
trajectories into options or sub-policies ([Sutton et al.,
1999](#bib.bib24); [Konidaris et al., 2012](#bib.bib43); [Fox et al.,
2017](#bib.bib44); [Shiarlis et al., 2018](#bib.bib46); [Kipf et al.,
2019](#bib.bib45); [Jiang et al., 2022](#bib.bib47)). We take from it
the finding that bottom-up training on flat action streams overlooks
structure a learner should exploit. We recover the hierarchy as a tree
structure over actions handed to training rather than as a set of advice
in context.

LLM-induced skills and experience reuse. Recent agents ask a proprietary
model to summarize reusable experience as natural-language workflows
([Wang et al., 2023](#bib.bib20); [Wang et al., 2024](#bib.bib1); [Tang
et al., 2025](#bib.bib7)) or executable tools ([Zheng and others,
2025](#bib.bib17); [Prabhu and others, 2025](#bib.bib18)), or store raw
experience as verbal reflections, distilled insights and retrieved
trajectories ([Shinn et al., 2023](#bib.bib53); [Zhao et al.,
2024](#bib.bib54); [Zheng et al., 2024](#bib.bib55); [Su et al.,
2025](#bib.bib56)). Both families keep the skills in prompt or a tool
registry, costing LLM calls for abstraction. Skills are never compressed
into the model, not generalizing beyond retrieval. We replace the
abstraction step with a deterministic miner and train the skills into
the weights.

Compression as abstraction. Grammar induction over symbol sequences
([Nevill-Manning and Witten, 1997](#bib.bib23)) and dictionary
compression ([Larsson and Moffat, 2000](#bib.bib48)) are the classical
ancestors. Library learning compresses programs under a
description-length objective ([Ellis et al., 2021](#bib.bib50); [Bowers
et al., 2023](#bib.bib51); [Grand et al., 2024](#bib.bib52)). And robot
policies tokenize continuous actions by vector quantization ([Lee et
al., 2024](#bib.bib49)). Closest to us, PRISE ([Zheng and others,
2024](#bib.bib21)) and Subwords-as-Skills ([Yunis et al.,
2023](#bib.bib22)) apply Byte-Pair-Encoding (BPE) to quantized
continuous-control actions. We differ in alphabet (typed actions from a
canonicalizer), in merge criterion ($`\mathcal{X}`$-Score to measure
reusability, as behavior carries more information than text), and in the
use of vocabulary: not a fixed macro-action space but reusable
experience as a prior to guide training as data, as credit and as
context.

Multi-turn agent training. Many domains lack an online environment and a
task verifier ([Zhou and others, 2023](#bib.bib25); [Xie et al.,
2024](#bib.bib15)). Our offline RL integration with X-Tree provides a
solution to train from the trajectory data [Gandhi and Neubig
(2025)](#bib.bib26) alone. Recent studies train agents online with
multi-turn RL ([Qi and others, 2024](#bib.bib31); [Wei and others,
2025](#bib.bib32); [Zhang et al., 2025](#bib.bib28)) using
policy-gradient ([Feng and others, 2025](#bib.bib39)). Unlike a learned
process-reward model, our shaping signal is mined from the trajectory
pool itself. On the other hand, on-policy self-distillation trains a
model toward its own predictions under a privileged context ([Zhao et
al., 2026](#bib.bib11); [Shenfeld et al., 2026](#bib.bib12); [Lu et al.,
2026](#bib.bib42)). We keep that objective and replace the LLM-written
privileged context with the X-Tree.

### 3.1 X-Tree Mining

The text BPE tokenizer ([Sennrich et al., 2016](#bib.bib30)) turns a
character stream into a vocabulary by recursively merging the most
frequent adjacent pair, which is itself a hierarchy. We apply the idea
to experience with two changes: actions are first made comparable by
canonicalization to reduce noise, and merges are chosen by how
_reusable_ the resulting pair is.

Canonicalization. We map each raw action (excluding thought) to a typed
token verb$`\langle`$role$`\rangle`$, where the role is a class or
object the verb acts on, e.g.,
fill(bid,’2/2/26’)$`\mapsto`$type$`\langle`$date$`\rangle`$ (templates
are in
Appendix [A.2](#A1.SS2 "A.2 Canonicalization examples ‣ Appendix A Implementation details ‣ X-Tree: Tokenizing Reusable Experience for Efficient Agent Generalization")).
Other values in the action (e.g., element id, object name) are stripped.
Therefore, structurally identical actions share a symbol, which makes
recurrence visible.

$`\mathcal{X}`$-Score: measuring reusability of a merged skill.
Recurrence-based text tokenization treats each occurrence of a character
pair equally. Experience carries more signal: a pair of actions is
reusable when it _recurs_ across the corpus, when it is _long_ enough
that reusing it induces better compression, and when it frequently
appears in _successful_ episodes.

Let $`u`$ and $`v`$ be two symbols that occur adjacently in the corpus,
each either a canonicalized action or a node from an earlier merge, let
$`uv`$ be the candidate node by merging them. Let $`f_{uv}`$ be the
number of times the pair occurs adjacently, and $`\ell_{u}`$ be the
number of primitive actions symbol $`u`$ expands to, so
$`\ell_{u}{+}\ell_{v}`$ is the length of the candidate: a primitive
action has $`\ell{=}1`$, merging type$`\langle`$text*input$`\rangle`$
with type$`\langle`$text_input$`\rangle`$ gives $`\ell{=}2`$ as it
contains two primitive actions (Figure
[1](#S1.F1 "Figure 1 ‣ 1 Introduction ‣ X-Tree: Tokenizing Reusable Experience for Efficient Agent Generalization")b).
Let $`\mathrm{succ}(uv)`$ be the fraction of $`f*{uv}`$ that lie in
successful episodes. We define $`\mathcal{X}`$-Score of a candidate as

|     |     |     |     |
| --- | --- | --- | --- |
|     |

````math
\mathcal{X}(u,v)\;=\;\underbrace{f_{uv}}_{\textstyle\text{recurrence}}\;\cdot\;\underbrace{(\ell_{u}+\ell_{v})^{p_{\ell}}}_{\textstyle\text{length}}\;\cdot\;\underbrace{(\mathrm{succ}(uv)+\epsilon)^{p_{s}}}_{\textstyle\text{success}}\,,
``` |  | (1) |

and recursively merge the pair with the highest $`\mathcal{X}`$-Score.
$`p_{\ell}`$ and $`p_{s}`$ set how strongly length and success weigh
against recurrence (set to $`1`$), and $`\epsilon`$ is a smoothing
factor on the success rate. Therefore, a long, reliable, recurrent
structure outranks a frequent but short or failure-prone pair, a
distinction a text tokenizer cannot make.

A merge must also compress the corpus: it removes $`f_{uv}-1`$ symbols
and adds an entry of $`\ell_{u}{+}\ell_{v}`$ at a cost of $`\eta`$, a
hyper-parameter keeping the corpus from collapsing into a few giant
symbols. We merge only when $`f_{uv}-1>\eta(\ell_{u}+\ell_{v})`$.
Merging ends when no pair passes it or a cap is reached.

What X-Tree contains. The result of recursive merging yields a tree
where the leaves are canonicalized actions. Each internal node is a
composition of actions, a skill, whose depth $`d_{v}`$ is one more than
the deeper of its children. The whole procedure is deterministic and
auditable with zero LLM calls. Applying X-Tree to a trajectory yields
its *top-level tiling*, a segmentation into maximal mined skills with
uncovered positions left as primitives. X-Tree is therefore a *reuse
prior*: it marks which parts of a trajectory are recurring,
compositional, and success-bearing (examples in
Appendix [B](#A2 "Appendix B A case study ‣ X-Tree: Tokenizing Reusable Experience for Efficient Agent Generalization")).

### 3.2 X-Tree for Offline RL: Each Node as one RL instance

![Refer to caption](2609.32993v1/figure2.png)

Figure 2: Three training integrations with X-Tree. (a) Offline RL:
X-Tree nodes as RL instances, partially rolled out from gold prefix and
rewarded for node completion. (b) Online RLVR: an adaptive bonus for
X-Tree nodes a rollout executes plus outcome signal. (c) OPSD: the same
weights, given the retrieved X-Tree skills (examples in Appendix
[G](#A7 "Appendix G OPSD on WebShop ‣ X-Tree: Tokenizing Reusable Experience for Efficient Agent Generalization"))
as privileged context for the self-teacher.

We have $`\mathcal{D}`$ without an environment: no action can be
executed. The only available signal is agreement with the gold
trajectory, which is sparse over a long horizon. In X-Tree, each node is
a reusable sub-procedure which is used as one RL training instance
(Figure [2](#S3.F2 "Figure 2 ‣ 3.2 X-Tree for Offline RL: Each Node as one RL instance ‣ 3 X-Tree: Tokenizing Reusable EXperience ‣ X-Tree: Tokenizing Reusable Experience for Efficient Agent Generalization")a):
the input is observations and actions in the trajectory before the node,
the output is actions the policy writes next (as partial rollouts), and
the reward is how closely those actions match the node.

Formally, let $`v`$ be a node instantiated at position $`t`$ of an
annotated trajectory, $`\ell_{v}`$ its length and $`d_{v}`$ its depth
(§[3.1](#S3.SS1 "3.1 X-Tree Mining ‣ 3 X-Tree: Tokenizing Reusable EXperience ‣ X-Tree: Tokenizing Reusable Experience for Efficient Agent Generalization")).
Conditioned on the gold actions and observations before $`t`$ (prefix
$`s_{<t}`$), the policy generates at most $`\ell_{v}`$ steps. Let
$`\mathrm{match}_{j}\in\{0,1\}`$ be $`1`$ when step $`j`$ reproduces the
gold action: the same action and element. We concatenate the gold
observation at step $`j`$ from the gold trajectory if
$`\mathrm{match}_{j}{=}1`$. A rollout stops when
$`\mathrm{match}_{j}{=}0`$. Let $`c_{v}=\prod_{j}\mathrm{match}_{j}`$,
which is $`1`$ only when every step of the node is matched. More details
in Appendix
[E](#A5 "Appendix E Offline RL on WebArena ‣ X-Tree: Tokenizing Reusable Experience for Efficient Agent Generalization").
We adopt GRPO ([Shao and others, 2024](#bib.bib27)) with:

|  |  |  |  |
|----|----|----|----|
|  |
``` math
r\;=\;(1-\alpha)\,\underbrace{\tfrac{1}{\ell_{v}}\textstyle\sum_{j}\mathrm{match}_{j}}_{\text{step-matching reward}}\;+\;\alpha\,\underbrace{(1+\gamma\,d_{v})}_{\text{depth factor}}\,\underbrace{c_{v}}_{\text{node completion reward}},
``` |  | (2) |

with $`\alpha{=}0.3`$ and $`\gamma{=}0.5`$ as hyper-parameters. The
first term is a step-matching reward for how far the rollout stays on
the gold path. The second is a bonus for finishing the node. In
Figure [2](#S3.F2 "Figure 2 ‣ 3.2 X-Tree for Offline RL: Each Node as one RL instance ‣ 3 X-Tree: Tokenizing Reusable EXperience ‣ X-Tree: Tokenizing Reusable Experience for Efficient Agent Generalization")a,
the X-Tree node *date filter* fills two dates and clicks apply
($`\ell_{v}{=}3`$) with $`d_{v}{=}2`$. Rollout $`\tau_{0}`$ reproducing
every action obtains full matching reward with completion bonus scaled
by $`d_{v}`$. Rollout $`\tau_{1}`$ that clicks apply too early stops at
the second step and gets only $`1/3`$ matching reward, with no
completion bonus.

### 3.3 X-Tree for Online RLVR: an Adaptive Skill Bonus

With an environment and a verifier, RLVR is possible. Early in training,
groups with no successful rollout give GRPO zero advantage and hence no
gradient. X-Tree provides the missing contrast: a rollout that carries
out more mined skills is distinguished from one that does not
(Figure [2](#S3.F2 "Figure 2 ‣ 3.2 X-Tree for Offline RL: Each Node as one RL instance ‣ 3 X-Tree: Tokenizing Reusable EXperience ‣ X-Tree: Tokenizing Reusable Experience for Efficient Agent Generalization")b).
And the signal gets down-weighted as the verifier becomes informative on
its own.

Let $`\tau_{i}`$ be the $`i`$-th rollout of a group $`g`$,
$`R_{\mathrm{out}}(\tau_{i})`$ the verifier reward,
$`\mathrm{matched}(\tau_{i})`$ the nodes in X-Tree whose action sequence
appears in $`\tau_{i}`$ (each counted once per episode): the nodes
$`\tau_{i}`$ actually executes. Let $`b_{v}`$ be the reward an execution
of node $`v`$ earns, specific to an environment. Let $`\mathrm{w}_{g}`$
be the fraction of the group the verifier counts as successes,
$`w_{\mathrm{ref}}`$ a threshold, and $`\lambda_{g}`$ the weight which
the bonus carries in $`g`$: $`\lambda_{g}`$ equals $`\lambda_{0}`$ when
no rollout succeeds and falls to zero once
$`{w}_{g}{=}w_{\mathrm{ref}}`$, so the bonus is at full strength when
the verifier cannot separate and absent on those it can. We define
reward:

|  |  |  |  |
|----|----|----|----|
|  |
``` math
r_{i}\;=\;\underbrace{R_{\mathrm{out}}(\tau_{i})}_{\text{verifier}}\;+\;\lambda_{g}\!\!\sum_{v\in\mathrm{matched}(\tau_{i})}\!\!b_{v},\qquad\lambda_{g}\;=\;\lambda_{0}\,\mathrm{clip}\!\Big(1-\tfrac{{w}_{g}}{w_{\mathrm{ref}}},\,0,\,1\Big).
``` |  | (3) |

$`b_{v}`$ stands for the value of the X-Tree node $`v`$, e.g., depth
$`d_{v}`$, where a deeper node is a longer and harder composition. In
Figure [2](#S3.F2 "Figure 2 ‣ 3.2 X-Tree for Offline RL: Each Node as one RL instance ‣ 3 X-Tree: Tokenizing Reusable EXperience ‣ X-Tree: Tokenizing Reusable Experience for Efficient Agent Generalization")b,
fill_at_sink(obj) is a depth-2 node. A rollout $`\tau_{0}`$ that
executes it earns the bonus $`b_{\text{fill\_at\_sink}}`$.
§[4](#S4 "4 Experimental setup ‣ X-Tree: Tokenizing Reusable Experience for Efficient Agent Generalization")
specifies $`b_{v}`$ designs in each environment.
Appendix [F.2](#A6.SS2 "F.2 The dynamic of 𝜆_𝑔 over training steps ‣ Appendix F Online RLVR on ScienceWorld ‣ X-Tree: Tokenizing Reusable Experience for Efficient Agent Generalization")
traces $`\lambda_{g}`$ over training step: an adaptive device with an
operating window, not a universal add-on.

### 3.4 X-Tree for On-policy Self-Distillation: a Privileged Context

OPSD trains a model on its own rollouts toward a teacher that is the
*same* model conditioned on privileged information ([Zhao et al.,
2026](#bib.bib11); [Shenfeld et al., 2026](#bib.bib12)). A per-token
distillation term is added to the RL objective, so the student receives
dense token-level guidance. Hinted by Table
[15](#A3.T15 "Table 15 ‣ Appendix C X-Tree as skills in the context ‣ X-Tree: Tokenizing Reusable Experience for Efficient Agent Generalization"),
X-Tree as advice in context can enhance a model’s multi-step reasoning.
We therefore add X-Tree to the teacher as privileged context in OPSD.
Since teacher and student are the same policy differing only in context,
any gap between them is attributable to the context (LLM-written or
X-Tree skills).

Let $`y=(y_{1},\dots,y_{|y|})`$ be the response the student sampled for
a prompt $`s^{\mathrm{stu}}`$, and $`s^{\mathrm{tea}}`$ the same prompt
with retrieved X-Tree skills prepended: the response tokens are
identical under both, so log-probabilities align position for position.
Write $`\bar{\theta}`$ for the weights held fixed for the teacher’s
forward pass,
$`\delta_{t}=\log\pi_{\bar{\theta}}(y_{t}\mid s^{\mathrm{tea}})-\log\pi_{\theta}(y_{t}\mid s^{\mathrm{stu}})`$
for the per-token gap, positive exactly on the tokens the privileged
context makes more likely. The gap also decides how much of the teacher
each token copies: $`g_{t}=\sigma(\beta\,\delta_{t})`$, with $`\sigma`$
the logistic function and $`\beta`$ the sharpness, is a confidence gate.
It is near $`1`$ where the teacher leads and near $`0`$ where the
student is already the more confident, so the student is pulled toward
the teacher only on the tokens the skills inform. A coefficient $`c`$
sets the weight of this term against the RL loss (set to $`0.01`$). The
objective adds one term to the RL loss:

|  |  |  |  |
|----|----|----|----|
|  |
``` math
\mathcal{L}\;=\;\mathcal{L}_{\mathrm{GRPO}}(R_{\mathrm{out}})\;+\;c\,\underbrace{\tfrac{1}{|y|}\textstyle\sum_{t}g_{t}\,\big(\log\pi_{\bar{\theta}}(y_{t}\mid s^{\mathrm{tea}})-\log\pi_{\theta}(y_{t}\mid s^{\mathrm{stu}})\big)}_{\text{per-token distillation}}.
``` |  | (4) |

Minimising it raises the student probability that the privileged context
finds likely. The rendered X-Tree writes each node as one line of text
with its success rate and occurrence count
(Appendix [G.1](#A7.SS1 "G.1 The X-Tree rendered privileged context ‣ Appendix G OPSD on WebShop ‣ X-Tree: Tokenizing Reusable Experience for Efficient Agent Generalization")).

## 4 Experimental setup

Offline RL: WebArena ([Zhou and others, 2023](#bib.bib25)). We mine 256
X-Tree skills from 7.9k trajectories ([Gandhi and Neubig,
2025](#bib.bib26)). We use Qwen2.5-7B-Instruct with SFT on half the
pool, then one GRPO stage on X-Tree nodes from the other half by verl.
Appendix [A](#A1 "Appendix A Implementation details ‣ X-Tree: Tokenizing Reusable Experience for Efficient Agent Generalization")
lists training details. Evaluation runs the 694 deterministic
(non-fuzzy) tasks, 30-step cap with official reward. We evaluate success
rate (SR) with normalization, i.e., a task counts as success if the
official evaluator returns $`1`$, or, for the exact match tasks, if the
normalized gold string appears verbatim in the final output. All
baselines are based on the same harness.
Appendix [E](#A5 "Appendix E Offline RL on WebArena ‣ X-Tree: Tokenizing Reusable Experience for Efficient Agent Generalization")
shows more details.

Online RLVR: ScienceWorld ([Wang et al., 2022](#bib.bib29)) and WebShop
([Yao et al., 2022](#bib.bib38)), three scales. We use SFT warm starts
from 200 (ScienceWorld) and 500 (WebShop) trajectories at 1.5B/3B/7B,
then a GRPO stage. The bonus
(Eq. [3](#S3.E3 "In 3.3 X-Tree for Online RLVR: an Adaptive Skill Bonus ‣ 3 X-Tree: Tokenizing Reusable EXperience ‣ X-Tree: Tokenizing Reusable Experience for Efficient Agent Generalization"))
uses $`\lambda_{0}{=}0.75`$ and $`w_{\mathrm{ref}}{=}0.4`$ on
ScienceWorld, $`w_{\mathrm{ref}}{=}0.85`$ on WebShop (training details
in
Appendix [A](#A1 "Appendix A Implementation details ‣ X-Tree: Tokenizing Reusable Experience for Efficient Agent Generalization"),
hyperparameter sensitivity in Appendix
[F.3](#A6.SS3 "F.3 Sensitivity to 𝜆_0 and 𝑤_ref ‣ Appendix F Online RLVR on ScienceWorld ‣ X-Tree: Tokenizing Reusable Experience for Efficient Agent Generalization")).

i) ScienceWorld: we mine 80 X-Tree skills from 1,673 trajectories ([Xi
and others, 2024](#bib.bib41)). We evaluate success rate
(score$`{=}100`$) on three generalization folds ([Zhang et al.,
2025](#bib.bib28)): G0 (seen tasks, $`n{=}1.6k`$), G1 (unseen
variations, $`n{=}1.6k`$), G2 (unseen tasks, $`n{=}0.5k`$, trained on 19
types and evaluated on the remaining 10). A matched skill node earns
$`b_{v}=1+\gamma\,d_{v}`$, granted once per episode. When two matched
skills nest, the outer one is rewarded the difference between its
$`b_{v}`$ and the largest already rewarded inside it, so a nested family
contributes what its largest member is worth rather than the sum. ii)
WebShop: we mine 48 skills from 1,824 trajectories ([Song and others,
2024](#bib.bib40)). We evaluate two metrics on 512 held-out episodes:
*success*, the fraction of purchases that meet every requirement of the
task goal, and *graded score*, the partial reward in $`[0,1]`$ for the
requirements met. A matched X-Tree skill node earns
$`b_{v}=s_{v}k_{v}/T`$: its corpus success rate $`s_{v}`$ times the
number $`k_{v}`$ of steps in the X-Tree node that help the task goal,
over the episode length $`T`$.

OPSD: ScienceWorld and WebShop, three scales. OPSD shares the X-Tree,
the SFT warm start and evaluation with RLVR for both environments. It
changes only the skill bank the self-teacher reads: LLM-written or the
X-Tree rendering. i) ScienceWorld: we use our implementation of
Eq. [4](#S3.E4 "In 3.4 X-Tree for On-policy Self-Distillation: a Privileged Context ‣ 3 X-Tree: Tokenizing Reusable EXperience ‣ X-Tree: Tokenizing Reusable Experience for Efficient Agent Generalization").
The teacher reads one X-Tree rendering per task family, retrieved by the
task line: the most relevant skill node to the task family. The
LLM-written bank is by gpt-oss-120b from the same corpus with the same
retrieval keys. ii) WebShop: we use the released trainer ([Lu et al.,
2026](#bib.bib42)). The LLM-written bank is by GPT-o3. X-Tree rendered
examples are in Appendix
[G.1](#A7.SS1 "G.1 The X-Tree rendered privileged context ‣ Appendix G OPSD on WebShop ‣ X-Tree: Tokenizing Reusable Experience for Efficient Agent Generalization").

We use Qwen2.5-Instruct and report the mean over three seeds.
Appendix [H](#A8 "Appendix H Stability and scope: the spread behind each mean ‣ X-Tree: Tokenizing Reusable Experience for Efficient Agent Generalization")
shows stability analysis.

#### 5.1.1 Which part of the recipe carries the gain, the tree or the RL method?

Our recipe changes two things compared to Go-Browse SFT on the same
corpus: the *training instance* (X-Tree nodes instead of whole
trajectories) and a *novel RL method* (with a step-matching reward and a
completion bonus).

GRPO receives less reward signal. And the lead narrows at larger $`n`$,

Three mechanisms
(Eq. [3](#S3.E3 "In 3.3 X-Tree for Online RLVR: an Adaptive Skill Bonus ‣ 3 X-Tree: Tokenizing Reusable EXperience ‣ X-Tree: Tokenizing Reusable Experience for Efficient Agent Generalization"))

## 6 Conclusion

Limited experience is the current bottleneck in training multi-step
agents. Standard recipes consume the action sequence uniformly and
bottom-up, without the hierarchy that lets human learners generalize
more efficiently with the same data. We tokenize reusable experience to
recover that hierarchy from a trajectory pool as X-Tree, with zero LLM
calls. Each X-Tree node captures how a recurrent and success-bearing
skill is composed from sub-procedures, guiding efficient generalization.
X-Tree enters training in three settings: as the training instance in
offline RL, as an adaptive bonus that keeps online RLVR ahead while the
outcome signal is scarce, and as the privileged context in OPSD where it
matches the LLM-written skill bank. Analyses attribute the gain to the
X-Tree structure and our integration design. These results hold across
three environments and three model scales.

Limitations. We mine X-Tree once from a fixed pool, and integrate X-Tree
with training without improving it. Mining from the policy’s own
trajectories would potentially let the structure and the policy improve
together in a loop. We evaluate the three integrations one per setting
and never combine them. A possible future work is to train a single
model on X-Tree nodes, taking the X-Tree bonus, and distill from X-Tree
at once. X-Tree also only reorganizes experience that already exists.
Because it records which pairs recur and which succeed, it marks where a
corpus is thin, identifying the trajectories worth synthesizing to fill
the gap.

stripped before the match and preserved. This is what makes move
thermometer to metal pot and move thermometer to ceramic cup the same

## Appendix B A case study

Tables [12](#A2.T12 "Table 12 ‣ Appendix B A case study ‣ X-Tree: Tokenizing Reusable Experience for Efficient Agent Generalization")–[14](#A2.T14 "Table 14 ‣ Appendix B A case study ‣ X-Tree: Tokenizing Reusable Experience for Efficient Agent Generalization")
study X-Tree nodes from the three environments to illustrate the
semantics. First, the boundaries are meaningful: the most frequent
WebArena depth-2 node is a two-field form followed by its submit button,
and the same canonical node instantiates as a report filter on the shop
admin site and as a route query on the map, which are reusable
structures of real-world meanings. Second, depth composes: the
ScienceWorld chain S8 $`\to`$ S19 $`\to`$ S20 $`\to`$ S21 adds one
primitive per depth, from “go to the kitchen via the hallway” to “fetch
the thermometer,” so a depth-6 node is a sub-procedure while its
descendants remain reusable on their own. Tree-structured decomposition
also helps answer complex questions over knowledge bases ([Huang et al.,
2023b](#bib.bib8)). X-Tree mines such a tree from trajectories instead.
Third, the $`\mathcal{X}`$-Score separates structures that the verifier
rewards from those it does not: on WebShop, the node that engage an
option type named by the goal (color, size, flavor) succeed in 81–97% of
their occurrences, the universal macros (search, click item, buy) sit at
the corpus mean of 0.56, and the pagination chains and untyped option
clicks sit at 0.14–0.36. This is the separation the
$`\mathcal{X}`$-Score merge and the option-recall gate exploit
(§[5.2.2](#S5.SS2.SSS2 "5.2.2 Is the gain from the extra data used to mine X-Tree? ‣ 5.2 Online RLVR on ScienceWorld and WebShop ‣ 5 Results and Analysis ‣ X-Tree: Tokenizing Reusable Experience for Efficient Agent Generalization")).
The libraries also contain low-value macros (WebArena’s
menu-then-submenu click pair recurs 1,219 times), which is why the
offline reward scales with depth.

## Appendix D X-Tree integration with SFT

##### Segmentation.

Standard SFT trains one action per training row with a full context
(system prompt, goal, observation, history) for every row. We test
X-Tree integration with SFT by *one X-Tree node per row*: the target is
the node’s full action span (several actions generated one time) and the
context is encoded once per node. A length-matched sliding window
baseline is the random cut over action stream with matched length as
X-Tree node. The three formats supervise the identical action streams
(i.e., trained over the same trajectory corpus). On the ScienceWorld
300-random-episode corpus, the vanilla SFT costs 1,766 tokens per
supervised action against 446 for the X-Tree node SFT, a $`4.0\times`$
saving, with $`97.6\%`$ of raw’s tokens being repeated prompts under the
same training settings.

##### Test-time protocol.

A node-trained policy outputs one turn per node: a \<planning\> block
and one \<action\> tag per action. The evaluator executes the tags in
order, one environment step each, and returns no observation until the
turn ends (the last action is executed). The next prompt carries the
observation after the last executed action and the turn’s joined action
string, which is the same node-level history the SFT rows are built
with. An action that the environment rejects returns its error message
as that step’s observation. The remaining tags still execute. Then, the
policy sees the failure at its next turn. Every run has the same budget
of 30 environment actions per episode. The standard SFT row executes one
action per turn as in ([Zhang et al., 2025](#bib.bib28)).

##### SFT integration with X-Tree outperforms the standard one at all scales (Table [16](#A4.T16 "Table 16 ‣ SFT integration with X-Tree outperforms the standard one at all scales (Table ). ‣ Appendix D X-Tree integration with SFT ‣ X-Tree: Tokenizing Reusable Experience for Efficient Agent Generalization")).

| SFT row             | 1.5B | 3B   | 7B   |
|---------------------|------|------|------|
| one standard action | 11.7 | 16.7 | 20.8 |
| length-matched span | 12.0 | 17.4 | 19.3 |
| an X-Tree node      | 16.6 | 19.1 | 29.9 |

Table 16: SFT at 1.5B/3B/7B on ScienceWorld (SR pooled over G0 and G1).

While consuming $`4\times`$ fewer tokens for the identical supervised
actions, our X-Tree with SFT leads by $`+4.9`$, $`+2.4`$ and $`+9.1`$.
The length-matched baseline further validates the effectiveness of
X-Tree: a sliding window with the same span lengths is on par with the
vanilla SFT, under-performing X-Tree significantly. This indicates that
X-Tree truly merges meaningful reusable structures that guides training
to save compute budget and improve performance.

## Appendix E Offline RL on WebArena

### E.1 Rollout observations for offline RL

We have the trajectory pool providing the thought, action and
observation at each interaction turn. At an X-Tree node boundary the
policy is given the gold prefix (i.e., previous observation and action
steps) and output one action per turn. If the action reproduces the
exact recorded gold action (thought excluded) and the node has steps
left, the recorded next observation in the trajectory is appended and
the rollout continues. If it does not, the rollout ends there. So the
loop never has to invent an observation for a state the gold trajectory
does not contain. The step-matching reward of
Eq. [2](#S3.E2 "In 3.2 X-Tree for Offline RL: Each Node as one RL instance ‣ 3 X-Tree: Tokenizing Reusable EXperience ‣ X-Tree: Tokenizing Reusable Experience for Efficient Agent Generalization")
is the fraction of the node’s steps reached before that stop.
Observations are replayed in Go-Browse’s compact form and the whole
prefix is retained.

The self-teacher reads X-Tree as plain text by a fixed rendering
template with no LLM calls. The template produces one rendering per
goal-option type (color, size, flavor, etc) and one general rendering. A
rendering opens with a header naming the option type, then lists up to
six mined X-Tree-node-based chains selecting that option, ranked by
corpus success rate, one line each in a fixed format: the canonical
chain, success rate and occurrence count, a tag against the corpus base
rate (above, at, below), and a gloss that maps every token to a fixed
phrase (click$`\langle`$option-color$`\rangle`$ to “select the goal’s
color option”, and a click$`\langle`$option$`\rangle`$ the goal did not
ask for to “wasted step”). It closes with a one-sentence plan, which
states the task’s rules outright ([Zhou et al., 2025](#bib.bib59)).
Table [22](#A7.T22 "Table 22 ‣ G.1 The X-Tree rendered privileged context ‣ Appendix G OPSD on WebShop ‣ X-Tree: Tokenizing Reusable Experience for Efficient Agent Generalization")
shows the rendering for the color option.

The general rendering states the corpus and lists the option-free chains
in the same format. Retrieval is the released trainer’s keyword rule: an
instruction that contains “color:” receives the general rendering
followed by the color rendering, prepended to teacher’s prompt.
Organizing procedural knowledge into such logic units helps the models
understanding ([An et al., 2025](#bib.bib60)), and a better retriever is
worth future exploration ([Zhuang et al., 2024](#bib.bib58)).

with $`t=\Delta/(\mathrm{sd}(\Delta)/\sqrt{n})`$ over the $`n`$ paired
````
