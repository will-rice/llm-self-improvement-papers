# When AI Reviews Its Own Code: Recursive Self-Training Collapse in Code LLMs

Xinyuan Song Affiliation: Emory University, Atlanta, GA, USA    Zekun
Cai Affiliation: The University of Tokyo, Tokyo, Japan
Affiliation: LocationMind, Tokyo,

Liang Zhao Affiliation: Emory University, Atlanta, GA, USA

###### Abstract

Recursive self-training can degrade neural generative models when
generated data is reused without fresh human data or external quality
control. We study this risk in code LLMs, where AI-generated code can
enter real repositories, later become training data, and create a
repository-scale self-training loop. While software development
traditionally interrupts this loop through _pull-request review_, tests,
compilation, and human approval, AI coding tools now produce code faster
than humans can review it, and code review itself is increasingly
automated by AI systems. We therefore compare three recursive
fine-tuning regimes: no review, Human-gate review using
model-independent filters such as compilation and static quality checks,
and AI-self-gate review using the code LLM’s own signals such as
perplexity and binary self-scoring. Across multiple code LLMs and
benchmarks, _no review_ collapses fastest, _Human-gate_ filters slow but
do not stop collapse, and _AI-self-gate_ filters can look strong early
but later lose their filtering effect. In the clearest case, the binary
self-gate enters a rubber-stamp regime where acceptance scores rise
while benchmark correctness falls. We explain this behavior by
formulating review as gated distributional reweighting, proving that AI
self-gating degenerates to ungated self-training under a self-confirming
acceptance condition, and giving a spectral analysis of
representation-level covariance concentration under recursive
retraining. These results suggest that stable recursive code LLM
training requires exogenous verification rather than model-coupled
self-review. Codes are available at
[https://github.com/Hik289/code-retraining.git](https://github.com/Hik289/code-retraining.git).

## 1 Introduction

Recursive self-training has been repeatedly shown to be harmful for
neural generative models when the loop is not anchored by fresh human
data or an external quality signal. In image generation, self-consuming
training can reduce distributional variance and drive models toward
low-diversity outputs, a failure mode described as model amplification
disorder [Alemohammad et al. (2023)](#bib.bib47). In general generative
modeling, training on recursively generated data can cause model
collapse: distributional errors accumulate, low-probability modes are
lost, and the learned distribution drifts away from the original data
distribution [Shumailov et al. (2024)](#bib.bib15); [Dohmatob et al.
(2024)](#bib.bib50). Similar effects have been reported for language
models, where synthetic text can reduce diversity, amplify earlier
mistakes, and degrade long-horizon quality unless real data or strong
external filtering is preserved in the training loop [Briesch et al.
(2023)](#bib.bib48); [Seddik et al. (2024)](#bib.bib49); [Suresh et al.
(2025)](#bib.bib51). These results give a general warning: self-training
is not automatically self-improvement. When a model is trained on data
produced by earlier versions of the same kind of model, the loop can
become self-reinforcing rather than corrective.

Code large language models (LLMs) [Ben Allal et al. (2023)](#bib.bib29);
[Li et al. (2023)](#bib.bib30); [Rozière et al. (2023)](#bib.bib36);
[Hui et al. (2024)](#bib.bib32) are likely to face the same risk in a
concrete and testable form. A code model can generate programs, add them
back into the training corpus, and fine-tune the next model on this
synthetic code. If these programs were always correct, diverse, and well
reviewed, the loop could cheaply scale code data. In practice, generated
code often contains bugs, incomplete logic, repeated templates, missing
edge cases, and narrow stylistic patterns. Recursive training can
therefore copy these errors into later models, making them better at
imitating their own code style while worse at solving programming tasks.
This is the recursive self-training trap for code: more data is created,
but it can carry the model’s own functional errors into future training.

This issue is no longer only an offline training concern. AI-generated
code is rapidly entering real repositories through tools such as GitHub
Copilot [GitHub (2026b)](#bib.bib5), Cursor [Anysphere
(2026)](#bib.bib6), Amazon CodeWhisperer [Amazon Web Services
(2026)](#bib.bib7), and Devin [Cognition AI (2026)](#bib.bib8). Studies
report large productivity gains from Copilot [Peng et al.
(2023)](#bib.bib1), and enterprise reports show that Copilot-suggested
code is frequently accepted, committed, and merged into pull
requests [GitHub (2024)](#bib.bib2). Future code LLMs may therefore be
trained on repositories already containing AI-generated or AI-assisted
code. If such code is collected without review, the loop becomes
recursive self-training at repository scale: AI writes code, the code
enters GitHub, GitHub enters the next training corpus, and the next
model learns from earlier model outputs.

In real software development, code is usually filtered before entering a
repository. A developer opens a pull request (PR), and the change may
pass through compilation, tests, static analysis, and human review
before merging. Modern code review is a lightweight but consequential
quality-control process: it catches defects, transfers project
knowledge, and affects downstream software quality [Bacchelli and Bird
(2013)](#bib.bib11); [Bosu et al. (2015)](#bib.bib12); [McIntosh et al.
(2016)](#bib.bib13); [Sadowski et al. (2018)](#bib.bib14). This PR
process acts as an external quality gate: the author does not define the
acceptance rule, and the rule does not become weaker when the author
writes worse code. Failed builds, failing tests, or poor design can
still block the PR. We call this model-independent acceptance mechanism
a _Human gate_. The term does not require every decision to be manual;
it means that the verifier is exogenous to the generator and preserves a
fixed quality standard.

The AI coding era weakens this assumption. AI tools can generate PRs
faster than humans can review them, while AI code review is becoming a
practical engineering workflow. Recent studies examine LLM-assisted
review with AI co-reviewers and interactive review
assistants [Aðalsteinsson et al. (2025)](#bib.bib3); large-scale GitHub
Actions analyses show AI review tools automatically commenting on real
PRs [Sun et al. (2025)](#bib.bib4); and GitHub Copilot code review is
now integrated into the PR workflow [GitHub (2026a)](#bib.bib9). At the
same time, LLM-as-judge systems are known to be sensitive to evaluator
design and can favor model-like outputs [Zheng et al.
(2023)](#bib.bib24); [Panickssery et al. (2024)](#bib.bib28). Future
repositories may therefore contain both AI-generated and AI-reviewed
code. In this setting, the verifier may no longer be a human-quality
external process, but another AI model, possibly close to the generator.
If AI writes the code and AI reviews the code, the acceptance signal can
become coupled to the same distribution being retrained. The review
process may look like filtering, but a biased AI reviewer can gradually
accept the generator’s degraded outputs as normal.

This observation leads to the central question of this paper: In
recursive code LLM training, how do no review, human-style review, and
AI-based review differ? Review changes the training distribution:
without review, the model trains on all generated outputs; with review,
training is reweighted toward samples that satisfy an acceptance rule.
The key question is who defines this rule. A _Human gate_ is fixed and
model-independent, so it can reject degraded outputs as the generator
worsens. An _AI self-gate_ is coupled to the generator, so it can drift
with the model and accept degraded model style as high quality. This
concern is consistent with evidence that LLM reviewers still miss many
human-flagged PR issues, even when they are strong code
generators [Kumar (2026)](#bib.bib10); [Tong and Zhang
(2024)](#bib.bib26); [Zhao et al. (2025)](#bib.bib27).

We study this question through recursive fine-tuning experiments that
directly compare no review, Human-gate review, and AI-self-gate review.
The Human-gate setting uses external, model-independent checks to decide
which generated code enters future training. The AI-self-gate setting
uses the code LLM itself to evaluate its own generated code, so the same
model both produces and filters the training data.

We validate this comparison across multiple code LLM families and
benchmarks. Our primary experiments use SantaCoder [Ben Allal et al.
(2023)](#bib.bib29), a 1.1B-parameter code model trained on permissively
licensed code from The Stack [Kocetkov et al. (2022)](#bib.bib41), and
evaluate recursive fine-tuning on HumanEval [Chen et al.
(2021)](#bib.bib33); [OpenAI (2021)](#bib.bib16), MBPP [Austin et al.
(2021)](#bib.bib23), and LiveCodeBench [Jain et al. (2024)](#bib.bib34),
with additional results on HumanEval+ and MBPP+ [Liu et al.
(2024)](#bib.bib67). We further test StarCoder2 [Lozhkov et al.
(2024)](#bib.bib37), Qwen2.5-Coder [Hui et al. (2024)](#bib.bib32), and
Code Llama [Rozière et al. (2023)](#bib.bib36), with extended vanilla
trajectories for StarCoder [Li et al. (2023)](#bib.bib30) in the
appendix, to examine whether the same pattern holds across model
families.

The results show a clear ordering across review regimes: no review
collapses fastest, Human-gate filters slow but do not stop collapse, and
AI-self-gate filters can look strong early but later lose their
filtering effect. In particular, unfiltered recursive fine-tuning
degrades all tested model families; Human-gate filters such as compile
checks and quality rules reduce the collapse rate but cannot prevent
long-horizon semantic drift; and AI-self-gate filters such as perplexity
and binary self-scoring become less discriminative as the generator
degrades. The binary classifier is the clearest AI-self-gate failure
case: acceptance scores rise while benchmark correctness falls,
indicating a self-confirming rubber-stamp regime.

## 2 Problem Formulation and Theoretical Analysis

### 2.1 Iterative Self-Training Without vs. With Gating

Figure [1](#S2.F1 "Figure 1 ‣ 2.1 Iterative Self-Training Without vs. With Gating ‣ 2 Problem Formulation and Theoretical Analysis ‣ When AI Reviews Its Own Code:Recursive Self-Training Collapse in Code LLMs")
illustrates the two recursive training pipelines considered in this
paper: ungated self-training, which reuses all generated code, and gated
self-training, which filters generated code before retraining. Let
$`x\in\mathcal{X}`$ denote a prompt or programming task, and let
$`c\in\mathcal{C}`$ denote a candidate code solution.

No verification (ungated recursion). In ungated recursive self-training,
every generated sample is directly reused as training data. The
synthetic data distribution at iteration $`t`$ is

|     |     |     |     |
| --- | --- | --- | --- |
|     |

````math
m_{t}^{\mathrm{ungated}}(x,c):=p_{X}(x)p_{\theta_{t}}(c\mid x).
``` |  | (2.1) |

The next model is obtained by maximum-likelihood estimation (MLE)
training on this distribution:

|  |  |  |  |
|----|----|----|----|
|  |
``` math
\theta_{t+1}^{\mathrm{ungated}}\in\arg\max_{\theta}\mathbb{E}_{(x,c)\sim m_{t}^{\mathrm{ungated}}}\big[\log p_{\theta}(c\mid x)\big].
``` |  | (2.2) |

Equivalently, this minimizes
$`\mathrm{KL}(m_{t}^{\mathrm{ungated}}\|p_{X}p_{\theta})`$. Thus,
ungated recursion only enforces self-consistency: the next model is
trained to imitate the current model’s samples. It does not impose any
external constraint on correctness, compilability, or execution success.

Verification (gated recursion). In gated recursive self-training,
generated code is accepted only after passing a review or verification
signal. Let $`\mathcal{E}(x,c)\in\{0,1\}`$ denote the acceptance event,
and define

|     |                                                         |     |       |
|-----|---------------------------------------------------------|-----|-------|
|     |
       ``` math
       r(x,c):=\mathbb{P}(\mathcal{E}(x,c)=1\mid x,c)\in[0,1].
       ```                                                      |     | (2.3) |

Here, $`r(x,c)`$ can represent a compile check, execution test, static
quality filter, human review score, or AI-based review score.
Conditioning the generator on acceptance gives the accepted distribution

|  |  |  |  |
|----|----|----|----|
|  |
``` math
q_{\theta_{t}}(c\mid x):=\mathbb{P}(c\mid x,\mathcal{E}=1)=\frac{p_{\theta_{t}}(c\mid x)r(x,c)}{Z_{\theta_{t}}(x)},\quad Z_{\theta_{t}}(x):=\sum_{c^{\prime}\in\mathcal{C}}p_{\theta_{t}}(c^{\prime}\mid x)r(x,c^{\prime}).
``` |  | (2.4) |

The gated synthetic data distribution is therefore

|     |                                                               |     |       |
|-----|---------------------------------------------------------------|-----|-------|
|     |
       ``` math
       m_{t}^{\mathrm{gated}}(x,c):=p_{X}(x)q_{\theta_{t}}(c\mid x).
       ```                                                            |     | (2.5) |

Training on accepted samples yields

|  |  |  |  |
|----|----|----|----|
|  |
``` math
\theta_{t+1}^{\mathrm{gated}}\in\arg\max_{\theta}\mathbb{E}_{(x,c)\sim m_{t}^{\mathrm{gated}}}\big[\log p_{\theta}(c\mid x)\big].
``` |  | (2.6) |

Thus, gated recursion differs from ungated recursion only through the
sampling measure: before training the next model, generated samples are
reweighted by the acceptance signal $`r(x,c)`$.

Difference (see
Figures [1](#S2.F1 "Figure 1 ‣ 2.1 Iterative Self-Training Without vs. With Gating ‣ 2 Problem Formulation and Theoretical Analysis ‣ When AI Reviews Its Own Code:Recursive Self-Training Collapse in Code LLMs")).
The two recursions differ only in the sampling measure:

|  |  |  |  |
|----|----|----|----|
|  |
``` math
m_{t}^{\mathrm{gated}}(x,c)\propto m_{t}^{\mathrm{ungated}}(x,c)\cdot r(x,c).
``` |  | (2.7) |

Thus, gated recursion trains on the same generated distribution as
ungated recursion, but reweights samples by acceptance: high-$`r(x,c)`$
code receives more training mass, while low-$`r(x,c)`$ code is
suppressed. At a fixed point of the gated recursion (pure
self-training), one must satisfy

|  |  |  |  |
|----|----|----|----|
|  |
``` math
p_{\theta^{*}}(c\mid x)=q_{\theta^{*}}(c\mid x)\Longleftrightarrow p_{\theta^{*}}(c\mid x)\propto p_{\theta^{*}}(c\mid x)r(x,c),
``` |  | (2.8) |

which implies that (for each $`x`$) probability mass concentrates on the
support where $`r(x,c)`$ is maximal (e.g., $`r(x,c)=1`$ if such code
exists). In contrast, the ungated recursion enforces only
self-reproduction of its own samples and does not bias toward
executability. This is why a useful exogenous gate can slow collapse,
while a gate that becomes constant on the generator’s support loses its
filtering effect and approaches ungated self-training.

### 2.2 Representation-Subspace Drift Under Recursive Self-Training

We next describe a representation-level view of recursive self-training
collapse. Let $`\mathcal{D}_{t}`$ denote the training distribution at
iteration $`t`$ over prompt–code pairs
$`(x,c)\in\mathcal{X}\times\mathcal{C}`$, where $`\mathcal{D}_{t}`$ may
be ungated or gated. Fix a representation map

|  |  |  |  |
|----|----|----|----|
|  |
``` math
\phi:\mathcal{X}\times\mathcal{C}\to\mathbb{R}^{d},\qquad z:=\phi(x,c).
``` |  | (2.9) |

The distribution $`\mathcal{D}_{t}`$ induces a mean vector and
covariance matrix in representation space:

|  |  |  |  |
|----|----|----|----|
|  |
``` math
\mu_{t}:=\mathbb{E}_{(x,c)\sim\mathcal{D}_{t}}[z],\qquad\Sigma_{t}:=\mathbb{E}_{(x,c)\sim\mathcal{D}_{t}}\big[(z-\mu_{t})(z-\mu_{t})^{\top}\big]\in\mathbb{R}^{d\times d}.
``` |  | (2.10) |

The covariance $`\Sigma_{t}`$ captures which representation directions
remain diverse under the current training distribution. If recursive
self-training narrows the generated code distribution, then
$`\Sigma_{t}`$ should concentrate on fewer dominant directions.

Let $`U_{t}\in\mathbb{R}^{d\times k}`$ contain the top-$`k`$
eigenvectors of $`\Sigma_{t}`$, and let $`P_{t}:=U_{t}U_{t}^{\top}`$ be
the corresponding rank-$`k`$ projector. We measure consecutive subspace
drift by

|  |  |  |  |
|----|----|----|----|
|  |
``` math
\mathrm{Sim}(t,t+1):=\frac{1}{k}\mathrm{Tr}(P_{t}P_{t+1})\in[0,1],\hskip 9.24994pt\mathrm{Dist}(t,t+1):=\|P_{t}-P_{t+1}\|_{2}=\sin\theta_{\max}(U_{t},U_{t+1}).
``` |  | (2.11) |

Here, high similarity means the dominant representation subspace is
stable, while large distance indicates that recursive training has
shifted the main directions of variation.

To analyze the mechanism, we use a linearized covariance recursion:

|     |                                                             |     |        |
|-----|-------------------------------------------------------------|-----|--------|
|     |
       ``` math
       \Sigma_{t+1}=A\Sigma_{t}A^{\top},\qquad\Sigma_{0}\succeq 0.
       ```                                                          |     | (2.12) |

This recursion should be read as a local approximation of how one round
of retraining transforms representation covariance. Let
$`A=U\mathrm{diag}(s_{1},\ldots,s_{d})V^{\top}`$ be an SVD with
$`s_{1}\geq s_{2}\geq\cdots\geq s_{d}\geq 0`$. Then
$`\Sigma_{t}=A^{t}\Sigma_{0}(A^{\top})^{t}`$ and therefore

|  |  |  |  |
|----|----|----|----|
|  |
``` math
\|\Sigma_{t}\|_{2}\leq\|A^{t}\|_{2}^{2}\|\Sigma_{0}\|_{2}=s_{1}^{2t}\|\Sigma_{0}\|_{2}.
``` |  | (2.13) |

More importantly, different singular directions are amplified at
different rates. For any unit vector $`v`$,

|  |  |  |  |
|----|----|----|----|
|  |
``` math
v^{\top}\Sigma_{t}v=\|(A^{\top})^{t}v\|_{\Sigma_{0}}^{2},\qquad\|(A^{\top})^{t}v\|\ \text{scales as}\ s_{i}^{t}\ \text{when }v=v_{i}.
``` |  | (2.14) |

Thus, if $`s_{1}\gg s_{2}`$, the component aligned with the leading
singular direction dominates after repeated retraining. Whenever
$`\Sigma_{0}`$ has nonzero energy in this direction, the ratio
$`\lambda_{1}(\Sigma_{t})/\lambda_{2}(\Sigma_{t})`$ is expected to
increase with $`t`$ because the leading component is amplified roughly
by $`s_{1}^{2t}`$ while the next component is amplified roughly by
$`s_{2}^{2t}`$. This gives a representation-space explanation for
collapse: recursive self-training can progressively concentrate variance
into a low-dimensional subspace, reducing diversity in the generated
code distribution.

We now formalize the concentration effect by the linearized covariance
recursion in
Equation ([2.12](#S2.E12 "In 2.2 Representation-Subspace Drift Under Recursive Self-Training ‣ 2 Problem Formulation and Theoretical Analysis ‣ When AI Reviews Its Own Code:Recursive Self-Training Collapse in Code LLMs")).

###### Proposition 2.1 (Spectral concentration).

Under the covariance recursion in
Equation ([2.12](#S2.E12 "In 2.2 Representation-Subspace Drift Under Recursive Self-Training ‣ 2 Problem Formulation and Theoretical Analysis ‣ When AI Reviews Its Own Code:Recursive Self-Training Collapse in Code LLMs")),
recall that $`\Sigma_{t}=A^{t}\Sigma_{0}(A^{\top})^{t}`$. Let
$`A=U\mathrm{diag}(s_{1},\ldots,s_{d})V^{\top}`$ be the SVD of $`A`$,
with $`s_{1}>s_{2}\geq\cdots\geq s_{d}\geq 0`$, and define
$`\widetilde{\Sigma}_{0}:=V^{\top}\Sigma_{0}V\succeq 0`$. Then
$`\Sigma_{t}=U\mathrm{diag}(s_{1}^{t},\ldots,s_{d}^{t})\widetilde{\Sigma}_{0}\mathrm{diag}(s_{1}^{t},\ldots,s_{d}^{t})U^{\top}`$.
If
$`(\widetilde{\Sigma}_{0})_{11}=v_{1}^{\top}\Sigma_{0}v_{1}\geq\alpha>0`$
and $`\rho_{2}:=s_{2}/s_{1}<1`$, then

|  |  |  |  |
|----|----|----|----|
|  |
``` math
\frac{\lambda_{1}(\Sigma_{t})}{\lambda_{2}(\Sigma_{t})}\geq\frac{\alpha}{\lambda_{2}(\widetilde{\Sigma}_{0})+\|\Sigma_{0}\|_{2}\rho_{2}^{2t}}.
``` |  | (2.15) |

Consequently, if $`\lambda_{2}(\widetilde{\Sigma}_{0})>0`$, then
$`\lambda_{1}(\Sigma_{t})/\lambda_{2}(\Sigma_{t})\to\alpha/\lambda_{2}(\widetilde{\Sigma}_{0})`$
as $`t\to\infty`$; if $`\lambda_{2}(\widetilde{\Sigma}_{0})=0`$, the
ratio grows without bound.

The proof is given in
Appendix [C](#A3 "Appendix C Complete Proofs ‣ When AI Reviews Its Own Code:Recursive Self-Training Collapse in Code LLMs").
Proposition [2.1](#S2.Thmtheorem1 "Proposition 2.1 (Spectral concentration). ‣ 2.2 Representation-Subspace Drift Under Recursive Self-Training ‣ 2 Problem Formulation and Theoretical Analysis ‣ When AI Reviews Its Own Code:Recursive Self-Training Collapse in Code LLMs")
shows that recursive retraining can amplify the dominant representation
direction faster than all others, at a relative rate controlled by
$`\rho_{2}^{2t}`$. This gives a representation-level mechanism for mode
concentration: the model distribution can become increasingly low-rank
even while training continues to optimize self-generated samples.

### 2.3 Human Gate vs. AI Self-Gate

#### 2.3.1 Verifier parameterization: exogenous Human gate vs. endogenous AI self-gate

We now specialize the generic acceptance function $`r(x,c)`$ from
Equation ([2.3](#S2.E3 "In 2.1 Iterative Self-Training Without vs. With Gating ‣ 2 Problem Formulation and Theoretical Analysis ‣ When AI Reviews Its Own Code:Recursive Self-Training Collapse in Code LLMs")).
The key is whether the acceptance rule is fixed outside the generator or
coupled to the generator during recursive training.

##### Human gate: exogenous acceptance.

A Human gate uses a fixed acceptance function $`r_{H}(x,c)\in[0,1]`$,
$`r_{H}`$ is independent of $`t`$ and $`\theta_{t}`$. It induces the
accepted conditional distribution

|  |  |  |  |
|----|----|----|----|
|  |
``` math
q^{H}_{\theta_{t}}(c\mid x):=\frac{p_{\theta_{t}}(c\mid x)r_{H}(x,c)}{Z^{H}_{\theta_{t}}(x)},\quad Z^{H}_{\theta_{t}}(x):=\sum_{c^{\prime}\in\mathcal{C}}p_{\theta_{t}}(c^{\prime}\mid x)r_{H}(x,c^{\prime}).
``` |  | (2.16) |

The corresponding training distribution is
$`m_{t}^{H}(x,c)=p_{X}(x)q^{H}_{\theta_{t}}(c\mid x)`$. This covers
model-independent review signals such as compilation, execution, quality
checks, or human PR review.

##### AI self-gate: endogenous acceptance.

An AI self-gate uses a learned reviewer with parameters $`\phi_{t}`$,
producing $`r_{\phi_{t}}(x,c)\in[0,1]`$. It induces

|  |  |  |  |
|----|----|----|----|
|  |
``` math
q^{A}_{\theta_{t},\phi_{t}}(c\mid x):=\frac{p_{\theta_{t}}(c\mid x)r_{\phi_{t}}(x,c)}{Z^{A}_{\theta_{t},\phi_{t}}(x)},\quad Z^{A}_{\theta_{t},\phi_{t}}(x):=\sum_{c^{\prime}\in\mathcal{C}}p_{\theta_{t}}(c^{\prime}\mid x)r_{\phi_{t}}(x,c^{\prime}).
``` |  | (2.17) |

The corresponding training distribution is
$`m_{t}^{A}(x,c)=p_{X}(x)q^{A}_{\theta_{t},\phi_{t}}(c\mid x)`$. In our
experiments, this case corresponds to perplexity filtering and binary
self-scoring, where the code LLM evaluates its own generated samples.
Unlike $`r_{H}`$, the score $`r_{\phi_{t}}`$ can drift as the generator
changes.

##### Taxonomy summary.

Table [1](#S2.T1 "Table 1 ‣ Taxonomy summary. ‣ 2.3.1 Verifier parameterization: exogenous Human gate vs. endogenous AI self-gate ‣ 2.3 Human Gate vs. AI Self-Gate ‣ 2 Problem Formulation and Theoretical Analysis ‣ When AI Reviews Its Own Code:Recursive Self-Training Collapse in Code LLMs")
classifies the six filtering strategies by whether the acceptance rule
is exogenous or endogenous. Vanilla has no gate and accepts all
generated code. Compile is a Human gate because it directly runs Python
compilation and accepts code only when compilation succeeds. Quality is
also a Human gate because it uses fixed code-quality rules, described in
Section [D](#A4 "Appendix D Quality Gate Set: Full Definition ‣ When AI Reviews Its Own Code:Recursive Self-Training Collapse in Code LLMs"),
such as repetition rate and length. Compile+Quality combines these two
model-independent rules, so it is also exogenous. Perplexity and Binary
Classifier are AI self-gates: both use the code LLM itself to score its
own generated code. Perplexity filters by the model’s own likelihood,
while Binary Classifier uses the model’s own logit-difference score,
defined in
Section [E](#A5 "Appendix E AI Self-Verification Protocol ‣ When AI Reviews Its Own Code:Recursive Self-Training Collapse in Code LLMs").
Since the generator also provides the filtering signal, these two gates
are coupled to $`\theta_{t}`$.

| Method | Gate type | Acceptance signal | Coupled to $`\theta_{t}`$? |
|----|----|----|----|
| Vanilla | – (no gate) | Accept all | No |
| Compile | Human gate | Compilability ($`\texttt{compile}()`$) | No |
| Quality | Human gate | Repetition rate + length (no compile) | No |
| Compile+Quality | Human gate | Compile + repetition/length filters | No |
| Perplexity | AI self-gate | Model perplexity (lowest 25%) | Yes |
| Binary Classifier | AI self-gate | Logit-difference score (top 25%) | Yes |

Table 1: Human gate vs. AI self-gate taxonomy of all filtering
strategies studied.

##### Coupled dynamics under AI self-gating.

We now formalize the failure mode where the verifier is coupled to the
generator. This captures the AI self-gate setting: the code LLM
generates candidate code, scores its own outputs, and then trains on the
samples it accepted. For a clean statement, we analyze the extreme case
where the generator and verifier share the same parameters:

|  |  |  |  |
|----|----|----|----|
|  |
``` math
\phi_{t}=\theta_{t},\qquad r_{\phi_{t}}(x,c)=r_{\theta_{t}}(x,c).
``` |  | (2.18) |

###### Assumption 2.2 (Self-confirming acceptance).

There exists a measurable function $`\kappa:\mathcal{X}\to(0,1]`$ such
that for $`p_{X}`$-almost every $`x`$, $`r_{\theta_{t}}(x,c)=\kappa(x)`$
for $`p_{\theta_{t}}(\cdot\mid x)`$-almost every $`c`$.

Assumption [2.2](#S2.Thmtheorem2 "Assumption 2.2 (Self-confirming acceptance). ‣ Coupled dynamics under AI self-gating. ‣ 2.3.1 Verifier parameterization: exogenous Human gate vs. endogenous AI self-gate ‣ 2.3 Human Gate vs. AI Self-Gate ‣ 2 Problem Formulation and Theoretical Analysis ‣ When AI Reviews Its Own Code:Recursive Self-Training Collapse in Code LLMs")
describes the rubber-stamp regime: on the code that the current model is
likely to generate, the AI reviewer assigns essentially the same
acceptance score. Once this happens, the gate no longer changes the
training distribution.

###### Theorem 2.3 (Degeneracy to ungated recursion).

Assume the shared-parameter self-gate in
Equation ([2.18](#S2.E18 "In Coupled dynamics under AI self-gating. ‣ 2.3.1 Verifier parameterization: exogenous Human gate vs. endogenous AI self-gate ‣ 2.3 Human Gate vs. AI Self-Gate ‣ 2 Problem Formulation and Theoretical Analysis ‣ When AI Reviews Its Own Code:Recursive Self-Training Collapse in Code LLMs"))
and
Assumption [2.2](#S2.Thmtheorem2 "Assumption 2.2 (Self-confirming acceptance). ‣ Coupled dynamics under AI self-gating. ‣ 2.3.1 Verifier parameterization: exogenous Human gate vs. endogenous AI self-gate ‣ 2.3 Human Gate vs. AI Self-Gate ‣ 2 Problem Formulation and Theoretical Analysis ‣ When AI Reviews Its Own Code:Recursive Self-Training Collapse in Code LLMs").
Then for $`p_{X}`$-almost every $`x`$,

|  |  |  |  |
|----|----|----|----|
|  |
``` math
Z^{A}_{\theta_{t},\theta_{t}}(x):=\sum_{c^{\prime}\in\mathcal{C}}p_{\theta_{t}}(c^{\prime}\mid x)r_{\theta_{t}}(x,c^{\prime})=\kappa(x),
``` |  | (2.19) |

and for $`p_{\theta_{t}}(\cdot\mid x)`$-almost every $`c`$,

|  |  |  |  |
|----|----|----|----|
|  |
``` math
q^{A}_{\theta_{t},\theta_{t}}(c\mid x):=\frac{p_{\theta_{t}}(c\mid x)r_{\theta_{t}}(x,c)}{Z^{A}_{\theta_{t},\theta_{t}}(x)}=p_{\theta_{t}}(c\mid x).
``` |  | (2.20) |

Consequently,

|  |  |  |  |
|----|----|----|----|
|  |
``` math
m_{t}^{A}(x,c):=p_{X}(x)q^{A}_{\theta_{t},\theta_{t}}(c\mid x)=p_{X}(x)p_{\theta_{t}}(c\mid x)=m_{t}^{\mathrm{ungated}}(x,c)\qquad\text{a.e.},
``` |  | (2.21) |

and the gated MLE update coincides with the ungated self-training
update:

|  |  |  |  |
|----|----|----|----|
|  |
``` math
\arg\max_{\theta}\mathbb{E}_{(x,c)\sim m_{t}^{A}}[\log p_{\theta}(c\mid x)]=\arg\max_{\theta}\mathbb{E}_{(x,c)\sim m_{t}^{\mathrm{ungated}}}[\log p_{\theta}(c\mid x)].
``` |  | (2.22) |

The proof is given in
Appendix [C](#A3 "Appendix C Complete Proofs ‣ When AI Reviews Its Own Code:Recursive Self-Training Collapse in Code LLMs").
Theorem [2.3](#S2.Thmtheorem3 "Theorem 2.3 (Degeneracy to ungated recursion). ‣ Coupled dynamics under AI self-gating. ‣ 2.3.1 Verifier parameterization: exogenous Human gate vs. endogenous AI self-gate ‣ 2.3 Human Gate vs. AI Self-Gate ‣ 2 Problem Formulation and Theoretical Analysis ‣ When AI Reviews Its Own Code:Recursive Self-Training Collapse in Code LLMs")
states that once an AI self-gate becomes constant on the generator’s own
support, filtering becomes mathematically identical to no filtering.
This is exactly the recursive self-training failure case where the model
writes code, approves its own code, and then trains on that approved
code.

###### Corollary 2.4 (Collapsed fixed point).

If there exists $`(\theta^{\star},\phi^{\star})`$ such that
$`r_{\phi^{\star}}(x,c)\equiv 1`$ for all $`(x,c)`$, then for all $`x`$,

|  |  |  |  |
|----|----|----|----|
|  |
``` math
q^{A}_{\theta^{\star},\phi^{\star}}(c\mid x)=p_{\theta^{\star}}(c\mid x),\qquad m^{A}(x,c)=p_{X}(x)p_{\theta^{\star}}(c\mid x).
``` |  | (2.23) |

Thus, the gating operator is the identity on
$`p_{\theta^{\star}}(\cdot\mid x)`$.

The proof is given in
Appendix [C](#A3 "Appendix C Complete Proofs ‣ When AI Reviews Its Own Code:Recursive Self-Training Collapse in Code LLMs").

#### 2.3.2 When AI review matches human review: equivalence and a non-collapse condition

The previous theorem gives the failure case: self-confirming AI review
degenerates to no review. We now give the non-collapse case: if AI
review stays close to exogenous human review and the human gate accepts
nonzero good-code mass, then AI-gated training remains close to
human-gated training.

##### Uniform calibration error.

Recall the Human-gate conditional $`q^{H}_{\theta_{t}}`$ in
Equation ([2.16](#S2.E16 "In Human gate: exogenous acceptance. ‣ 2.3.1 Verifier parameterization: exogenous Human gate vs. endogenous AI self-gate ‣ 2.3 Human Gate vs. AI Self-Gate ‣ 2 Problem Formulation and Theoretical Analysis ‣ When AI Reviews Its Own Code:Recursive Self-Training Collapse in Code LLMs"))
and the AI-self-gate conditional $`q^{A}_{\theta_{t},\phi_{t}}`$ in
Equation ([2.17](#S2.E17 "In AI self-gate: endogenous acceptance. ‣ 2.3.1 Verifier parameterization: exogenous Human gate vs. endogenous AI self-gate ‣ 2.3 Human Gate vs. AI Self-Gate ‣ 2 Problem Formulation and Theoretical Analysis ‣ When AI Reviews Its Own Code:Recursive Self-Training Collapse in Code LLMs")).
Here, $`r_{H}(x,c)`$ denotes the human-style external review rule, while
$`r_{\phi_{t}}(x,c)`$ denotes AI review: the learned reviewer scores
whether generated code should be accepted for future training. We
measure how well the AI reviewer matches the human reviewer by the
worst-case calibration error

|  |  |  |  |
|----|----|----|----|
|  |
``` math
\varepsilon_{t}:=\sup_{x\in\mathcal{X},c\in\mathcal{C}}\big|r_{\phi_{t}}(x,c)-r_{H}(x,c)\big|.
``` |  | (2.24) |

##### Non-collapse human acceptance mass.

To avoid a degenerate case where almost no generated code is accepted by
the human reviewer, we require the Human gate to accept a non-vanishing
fraction of the generator’s probability mass.

###### Assumption 2.5 (Non-collapse human acceptance mass).

There exists $`z_{0}\in(0,1]`$ such that

|  |  |  |  |
|----|----|----|----|
|  |
``` math
Z^{H}_{\theta_{t}}(x)=\sum_{c^{\prime}}p_{\theta_{t}}(c^{\prime}\mid x)r_{H}(x,c^{\prime})\geq z_{0}\qquad\text{for }p_{X}\text{-almost every }x\text{ and all }t.
``` |  | (2.25) |

Assumption [2.5](#S2.Thmtheorem5 "Assumption 2.5 (Non-collapse human acceptance mass). ‣ Non-collapse human acceptance mass. ‣ 2.3.2 When AI review matches human review: equivalence and a non-collapse condition ‣ 2.3 Human Gate vs. AI Self-Gate ‣ 2 Problem Formulation and Theoretical Analysis ‣ When AI Reviews Its Own Code:Recursive Self-Training Collapse in Code LLMs")
says that the external reviewer still finds enough acceptable code in
the generator distribution. Without this lower bound, the accepted
distribution can become unstable because it is normalized by a vanishing
acceptance mass.

##### Quality gate sufficient condition.

A simple sufficient condition for
Assumption [2.5](#S2.Thmtheorem5 "Assumption 2.5 (Non-collapse human acceptance mass). ‣ Non-collapse human acceptance mass. ‣ 2.3.2 When AI review matches human review: equivalence and a non-collapse condition ‣ 2.3 Human Gate vs. AI Self-Gate ‣ 2 Problem Formulation and Theoretical Analysis ‣ When AI Reviews Its Own Code:Recursive Self-Training Collapse in Code LLMs")
follows from the quality gate set $`\mathcal{F}_{\mathrm{qual}}(x)`$.
Suppose the human reviewer gives nontrivial acceptance probability to
quality gate code:
$`c\in\mathcal{F}_{\mathrm{qual}}(x)\Longrightarrow r_{H}(x,c)\geq\delta_{H}`$
for some $`\delta_{H}\in(0,1]`$. If the generator also assigns
nontrivial mass to quality gate code,
$`p_{\theta_{t}}\big(\mathcal{F}_{\mathrm{qual}}(x)\mid x\big)\geq\beta_{H}`$
for some $`\beta_{H}>0`$, then
Assumption [2.5](#S2.Thmtheorem5 "Assumption 2.5 (Non-collapse human acceptance mass). ‣ Non-collapse human acceptance mass. ‣ 2.3.2 When AI review matches human review: equivalence and a non-collapse condition ‣ 2.3 Human Gate vs. AI Self-Gate ‣ 2 Problem Formulation and Theoretical Analysis ‣ When AI Reviews Its Own Code:Recursive Self-Training Collapse in Code LLMs")
holds with $`z_{0}=\delta_{H}\beta_{H}`$, since

|  |  |  |  |
|----|----|----|----|
|  |
``` math
Z^{H}_{\theta_{t}}(x)=\sum_{c^{\prime}}p_{\theta_{t}}(c^{\prime}\mid x)r_{H}(x,c^{\prime})\geq\sum_{c^{\prime}\in\mathcal{F}_{\mathrm{qual}}(x)}p_{\theta_{t}}(c^{\prime}\mid x)r_{H}(x,c^{\prime})\geq\delta_{H}p_{\theta_{t}}\big(\mathcal{F}_{\mathrm{qual}}(x)\mid x\big)\geq\delta_{H}\beta_{H}.
``` |  | (2.26) |

Thus, the Human gate remains stable when it accepts quality gate code
and the generator has not lost all probability mass on such code.

###### Theorem 2.6 (Uniform approximation of human-gated review).

Suppose the AI reviewer satisfies
Equation ([2.24](#S2.E24 "In Uniform calibration error. ‣ 2.3.2 When AI review matches human review: equivalence and a non-collapse condition ‣ 2.3 Human Gate vs. AI Self-Gate ‣ 2 Problem Formulation and Theoretical Analysis ‣ When AI Reviews Its Own Code:Recursive Self-Training Collapse in Code LLMs"))
with $`\varepsilon_{t}<z_{0}`$, and suppose
Assumption [2.5](#S2.Thmtheorem5 "Assumption 2.5 (Non-collapse human acceptance mass). ‣ Non-collapse human acceptance mass. ‣ 2.3.2 When AI review matches human review: equivalence and a non-collapse condition ‣ 2.3 Human Gate vs. AI Self-Gate ‣ 2 Problem Formulation and Theoretical Analysis ‣ When AI Reviews Its Own Code:Recursive Self-Training Collapse in Code LLMs")
holds. Then for $`p_{X}`$-almost every $`x`$,

|  |  |  |  |
|----|----|----|----|
|  |
``` math
\big\|q^{A}_{\theta_{t},\phi_{t}}(\cdot\mid x)-q^{H}_{\theta_{t}}(\cdot\mid x)\big\|_{1}\leq\frac{2\varepsilon_{t}}{z_{0}}.
``` |  | (2.27) |

Consequently,

|  |  |  |  |
|----|----|----|----|
|  |
``` math
\big\|m_{t}^{A}-m_{t}^{H}\big\|_{1}=\int_{\mathcal{X}}p_{X}(x)\big\|q^{A}_{\theta_{t},\phi_{t}}(\cdot\mid x)-q^{H}_{\theta_{t}}(\cdot\mid x)\big\|_{1}dx\leq\frac{2\varepsilon_{t}}{z_{0}}.
``` |  | (2.28) |

The proof is in
Appendix [C](#A3 "Appendix C Complete Proofs ‣ When AI Reviews Its Own Code:Recursive Self-Training Collapse in Code LLMs").
Theorem [2.6](#S2.Thmtheorem6 "Theorem 2.6 (Uniform approximation of human-gated review). ‣ Quality gate sufficient condition. ‣ 2.3.2 When AI review matches human review: equivalence and a non-collapse condition ‣ 2.3 Human Gate vs. AI Self-Gate ‣ 2 Problem Formulation and Theoretical Analysis ‣ When AI Reviews Its Own Code:Recursive Self-Training Collapse in Code LLMs")
shows when AI review remains safe: the AI reviewer must stay close to
human review, and the Human gate must accept nonzero generator mass. If
$`\varepsilon_{t}`$ grows or $`z_{0}`$ shrinks, the bound weakens and AI
review can approach ungated self-training.

Equivalently, AI-gated recursion avoids collapse only when
$`\varepsilon_{t}\ll z_{0}`$ and $`r_{H}(x,\cdot)`$ is not approximately
constant on $`\mathrm{supp}(p_{\theta_{t}}(\cdot\mid x))`$. These
conditions mean that AI review remains calibrated to human review, and
human review still separates good from bad generated code.

### 2.4 Quality Gate

The ideal gate for recursive code training would accept exactly the
programs in the *quality gate set* $`\mathcal{F}_{\mathrm{qual}}(q)`$:
programs satisfying semantic correctness, runtime safety, efficiency,
security/compliance, and readability requirements. We define this set
and its quality dimensions (A)–(G) formally in
Appendix [D](#A4 "Appendix D Quality Gate Set: Full Definition ‣ When AI Reviews Its Own Code:Recursive Self-Training Collapse in Code LLMs").
In our experiments, Human-gate methods are concrete approximations to
this ideal: the compile filter checks basic runtime validity, while the
quality filter implements fixed code-quality rules such as repetition
and length constraints. These model-independent checks remain stable as
the generator degrades. In contrast, AI self-gates use model-derived
scores that can drift with the generator, causing the gate to lose its
connection to $`\mathcal{F}_{\mathrm{qual}}(q)`$ as in
Theorem [2.3](#S2.Thmtheorem3 "Theorem 2.3 (Degeneracy to ungated recursion). ‣ Coupled dynamics under AI self-gating. ‣ 2.3.1 Verifier parameterization: exogenous Human gate vs. endogenous AI self-gate ‣ 2.3 Human Gate vs. AI Self-Gate ‣ 2 Problem Formulation and Theoretical Analysis ‣ When AI Reviews Its Own Code:Recursive Self-Training Collapse in Code LLMs").

## 3 Experiments

### 3.1 Evaluation Setup

##### Evaluation benchmarks.

We use three standard code generation benchmarks. HumanEval [Chen et al.
(2021)](#bib.bib33); [OpenAI (2021)](#bib.bib16): 164 hand-written
Python problems with 7–9 unit tests each; primary benchmark, metric =
pass@1. MBPP [Austin et al. (2021)](#bib.bib23): 374 crowd-sourced
introductory Python problems with 3 unit tests each (sanitized split);
second primary benchmark. LiveCodeBench [Jain et al.
(2024)](#bib.bib34): continuously updated competition problems that
prevent data contamination; used as a robustness probe. We additionally
report HumanEval+ and MBPP+ [Liu et al. (2024)](#bib.bib67) (augmented
edge-case test suites) in per-round tables
(Appendix [H](#A8 "Appendix H Per-Round Degradation Trajectories (SantaCoder, All Strategies) ‣ When AI Reviews Its Own Code:Recursive Self-Training Collapse in Code LLMs")).
All evaluations use bigcode-evaluation-harness [Ben Allal et al.
(2022)](#bib.bib17) with temperature 0.8, top-$`p`$ 0.95; HumanEval+ and
MBPP+ use the EvalPlus framework.

##### Base models.

We evaluate four code LLMs: SantaCoder (1.1B) [Ben Allal et al.
(2023)](#bib.bib29) (HumanEval+ baseline: 0.171, MBPP+ baseline: 0.294),
StarCoder2-3B [Lozhkov et al. (2024)](#bib.bib37) (HumanEval+ baseline:
0.274, MBPP+ baseline: 0.492), Qwen2.5-Coder-1.5B [Hui et al.
(2024)](#bib.bib32) (HumanEval+ baseline: 0.372, MBPP+ baseline: 0.582),
and Code Llama-7B [Rozière et al. (2023)](#bib.bib36) (HumanEval+
baseline: 0.287, MBPP+ baseline: 0.388). All five primary recursive
regimes are evaluated on all four models for 5 recursive rounds.

##### Recursive pipeline.

At each round $`t`$, model $`M_{t}`$ generates synthetic code from a
fixed prompt pool; the filtering gate (Human or AI self-gate;
Table [1](#S2.T1 "Table 1 ‣ Taxonomy summary. ‣ 2.3.1 Verifier parameterization: exogenous Human gate vs. endogenous AI self-gate ‣ 2.3 Human Gate vs. AI Self-Gate ‣ 2 Problem Formulation and Theoretical Analysis ‣ When AI Reviews Its Own Code:Recursive Self-Training Collapse in Code LLMs"))
selects $`5{,}000`$ accepted samples; $`M_{t+1}`$ is fine-tuned on the
accepted set for 3,000 steps (so 5 rounds = 15k steps). Human gate
methods generate in batches until 5,000 accepted; AI self-gate methods
generate 20k once per round and retain the top/bottom 25%. All methods
share the same optimizer, learning rate cosine schedule, and batch
size—only the filtering policy differs. Hardware: NVIDIA RTX 6000 Ada
Generation GPUs. Full implementation details are in
Appendix [J](#A10 "Appendix J Implementation Details ‣ When AI Reviews Its Own Code:Recursive Self-Training Collapse in Code LLMs").

##### Filtering strategies.

We evaluate five primary regimes under the Human gate / AI self-gate
taxonomy
(Table [1](#S2.T1 "Table 1 ‣ Taxonomy summary. ‣ 2.3.1 Verifier parameterization: exogenous Human gate vs. endogenous AI self-gate ‣ 2.3 Human Gate vs. AI Self-Gate ‣ 2 Problem Formulation and Theoretical Analysis ‣ When AI Reviews Its Own Code:Recursive Self-Training Collapse in Code LLMs")).
No gate: (1) Vanilla reuses all generated samples. Human gates:
(2) Compile applies a syntax gate via compile(); (3) Quality applies
fixed static metrics (repetition rate $`\leq 0.3`$, length $`\geq 50`$
tokens). AI self-gates: (4) Perplexity generates 20k samples and retains
the lowest 25% by masked-completion perplexity; (5) Binary Classifier
generates 20k samples and retains the top 25% by logit-difference score.
Execution-validated training pipelines have been effective in code
generation [Le et al. (2022)](#bib.bib63); [Wei et al.
(2024a)](#bib.bib62); [Gehring et al. (2025)](#bib.bib65); [Zheng et al.
(2024)](#bib.bib64); our experiments isolate the narrower question of
whether such exogenous signals remain different from model-coupled
self-review under recursive retraining. Extended Compile+Quality and
Quality-20R trajectories are reported in
Appendix [H](#A8 "Appendix H Per-Round Degradation Trajectories (SantaCoder, All Strategies) ‣ When AI Reviews Its Own Code:Recursive Self-Training Collapse in Code LLMs").

shows that both StarCoder2-3B and Qwen2.5-Coder-1.5B exhibit recursive
self-training collapse regardless of filtering strategy, providing
direct empirical corroboration that the collapse mechanism is not
specific to SantaCoder.

##### Collapse magnitude.

Under vanilla self-retraining (no filter), StarCoder2-3B declines from a
HumanEval+ baseline of $`0.274`$ to $`0.104`$ by round 5 ($`-62.0\%`$)
and from an MBPP+ baseline of $`0.492`$ to $`0.172`$ ($`-65.0\%`$).
Qwen2.5-Coder-1.5B collapses even more severely: HumanEval+ from
$`0.372`$ to $`0.043`$ ($`-88.4\%`$) and MBPP+ from $`0.582`$ to
$`0.082`$ ($`-85.9\%`$) by Round 5. Code Llama-7B shows the smallest
collapse on HumanEval+ under Vanilla: from $`0.287`$ to $`0.134`$
($`-53.3\%`$), and on MBPP+ from $`0.388`$ to $`0.214`$ ($`-44.8\%`$).
The steeper decline in Qwen2.5-Coder is consistent with the stronger
initial distribution hypothesis: a model pretrained on a richer code
corpus exhibits a sharper distributional shift when contaminated with
self-generated outputs.

##### Effect of filtering strategies.

The benefit of a gate depends on which failure mode the benchmark
rewards. Compile filtering improves Qwen2.5-Coder at R5 relative to
Vanilla on both HumanEval+ ($`0.098`$ vs. $`0.043`$) and MBPP+
($`0.127`$ vs. $`0.082`$), and it is the strongest Code Llama-7B
strategy on HumanEval+ ($`0.171`$). For StarCoder2-3B, however, compile
and quality filters lag behind Vanilla at R5 on HumanEval+ and MBPP+,
showing that syntactic validity alone cannot guarantee semantic
preservation. Binary filtering achieves the highest R5 HumanEval+ for
three of four models, which means self-scoring can still rank some
useful samples in early and medium horizons. Its MBPP+ behavior is
weaker and less stable, matching our central story: AI self-gates may
improve one visible metric while losing broader semantic coverage.
Perplexity (PPL) filtering shows a slow increase in pass rate from
approximately $`0.17`$ to $`0.24`$ (averaged across models;
Figure [7](#S3.F7 "Figure 7 ‣ Perplexity self-gating loses calibration. ‣ 3.3 SantaCoder: All Strategies Across Rounds ‣ 3 Experiments ‣ When AI Reviews Its Own Code:Recursive Self-Training Collapse in Code LLMs")),
consistent with the endogenous degeneracy result of
Theorem [2.3](#S2.Thmtheorem3 "Theorem 2.3 (Degeneracy to ungated recursion). ‣ Coupled dynamics under AI self-gating. ‣ 2.3.1 Verifier parameterization: exogenous Human gate vs. endogenous AI self-gate ‣ 2.3 Human Gate vs. AI Self-Gate ‣ 2 Problem Formulation and Theoretical Analysis ‣ When AI Reviews Its Own Code:Recursive Self-Training Collapse in Code LLMs").

##### Collapse attractor.

Despite large differences in architecture size, pretraining data, and
starting pass@1, all four models show qualitatively similar long-horizon
degradation patterns. SantaCoder ($`0.171`$ HumanEval+ baseline) and
Qwen2.5-Coder ($`0.372`$ baseline) both reach approximately
$`0.04`$–$`0.10`$ HumanEval+ pass@1 under Vanilla by Round 5.
StarCoder2-3B and Code Llama-7B maintain somewhat higher residual
performance ($`0.10`$–$`0.14`$), likely due to stronger capacity and
pretraining data quality. This convergence to a common degradation floor
is consistent with the theoretical prediction of a collapse attractor.

##### Key takeaway.

No filtering strategy evaluated here—Compile, Perplexity, Quality, or
Binary—prevents collapse across all model families. Binary filtering
achieves the best R5 HumanEval+ for three models, but this comes with
erratic MBPP+ behavior. Human gates are more interpretable and preserve
executable validity, yet simple compile/static filters are still too
weak to guarantee semantic robustness. LiveCodeBench approaches
near-zero for all models by Round 5 regardless of strategy, confirming
that recursive self-training systematically degrades harder,
out-of-distribution tasks.

## 4 Conclusion

We studied recursive self-training collapse in code LLMs under no
review, Human-gate review, and AI-self-gate review. Across models and
benchmarks, no review produces the sharpest degradation, Human gates
preserve useful validity signals but cannot stop long-horizon semantic
drift, and AI self-gates can look strong on early HumanEval-style
metrics while their acceptance signal drifts with the generator. Our
theory explains this through gated distributional reweighting: exogenous
gates preserve an external quality signal, while endogenous gates can
become self-confirming. Stable recursive code LLM training therefore
needs verification that remains outside the model’s own preference
distribution.

## 5 Limitations

Our experiments focus on Python benchmarks and models up to 7B
parameters in the full five-strategy sweep, with additional StarCoder
trajectories in the appendix. Human-gate filters are simplified proxies
for full PR review and do not fully check semantics, security, or design
quality. Longer horizons, larger models, multilingual code, stronger
execution-based gates, and periodic human-verified data remain important
future directions.

## Appendix A Related Work

### A.1 Model Collapse

The systematic study of model collapse begins with Shumailov et
al. [Shumailov et al. \[2024\]](#bib.bib15), who demonstrate that
training on recursively generated data causes (1) early collapse:
distributional errors accumulate and the model drifts from the true
distribution; and (2) late collapse: low-frequency events permanently
disappear. Their experiments on VAE, GMM, and OPT confirm that fresh
human data must be periodically injected to prevent collapse.
Alemohammad et al. [Alemohammad et al. \[2023\]](#bib.bib47) study
self-consuming image generation models, proving that pure synthetic
training loops monotonically shrink distribution variance (MAD: Model
Amplification Disorder). They identify three loop types: fully
synthetic, augmented (partial human mixing), and accumulating (fixed
replay); only augmented and accumulating loops with sufficient human
fraction avoid collapse.

Briesch et al. [Briesch et al. \[2023\]](#bib.bib48) provide the first
LLM-specific self-consuming study using logically verifiable outputs
(logical expressions), finding that synthetic data fraction is the
primary collapse predictor. Seddik et al. [Seddik et al.
\[2024\]](#bib.bib49) apply random matrix theory: token variance decays
exponentially per generation, and mixing $`\geq 5\%`$ real data prevents
long-term collapse; $`100\%`$ synthetic data collapses linearly with
generation count. Dohmatob et al. [Dohmatob et al. \[2024\]](#bib.bib50)
reframe collapse as a change in scaling laws—synthetic training
truncates the power-law tail of the data distribution, eliminating rare
events. Suresh et al. [Suresh et al. \[2025\]](#bib.bib51) prove that
preserving a fraction $`\epsilon>0`$ of real data per generation keeps
the KL divergence from the true distribution bounded, while
$`\epsilon\to 0`$ (pure synthetic) leads to unbounded
divergence—formalizing the role of exogenous quality signal.

On the constructive side, Ferbach et al. [Ferbach et al.
\[2024\]](#bib.bib53) prove a characterization theorem: self-consuming
loops converge to the preference-maximizing distribution if and only if
the curation function aligns with a ground-truth reward. This directly
justifies our Human gate framework: a compile gate or execution gate
aligns with ground-truth correctness; AI self-gate does not. Gillman et
al. [Gillman et al. \[2024\]](#bib.bib52) propose a correction function
that maps synthetic samples toward higher-probability regions of the
true distribution, stabilizing loops; code execution is the natural
correction function in the code domain. Zhu et al. [Zhu et al.
\[2025\]](#bib.bib54) demonstrate token-level diversity perturbations as
a mitigation strategy. Fu et al. [Fu et al. \[2025\]](#bib.bib55)
introduce recursive stability conditions for Transformer in-context
learning.

### A.2 Modern Code Review and Exogenous Verification

Modern code review provides the software-engineering analogue of the
Human gate in our framework. Bacchelli and Bird [Bacchelli and Bird
\[2013\]](#bib.bib11) show that defect finding is only one part of
review: reviewers also enforce design norms, share knowledge, and
improve maintainability. Bosu et al. [Bosu et al. \[2015\]](#bib.bib12)
study which review comments developers find useful, while McIntosh et
al. [McIntosh et al. \[2016\]](#bib.bib13) link code-review coverage,
participation, and reviewer expertise to post-release software quality.
At industrial scale, Sadowski et al. [Sadowski et al.
\[2018\]](#bib.bib14) describe Google’s tool-based review process over
millions of changes. These studies motivate our abstraction of review as
an exogenous acceptance rule: the important property is not that every
decision is manual, but that acceptance is not produced by the same
model distribution being retrained.

### A.3 Code LLM Development

Representation era (2020–2021). CodeBERT [Feng et al.
\[2020\]](#bib.bib56) established the bimodal NL-PL representation
paradigm (encoder-only, 6 languages, MLM + RTD). Codex [Chen et al.
\[2021\]](#bib.bib33) introduced generative code LLMs (12B, fine-tuned
GPT on GitHub) and the pass@$`k`$ evaluation standard. AlphaCode [Li et
al. \[2022\]](#bib.bib57) scaled to competition-level difficulty at 41B
parameters, using massive sampling ($`10^{3}`$ candidates) plus
execution-based filtering—an early Human gate.

Fill-in-the-middle and open-source (2022–2023). InCoder [Fried et al.
\[2022\]](#bib.bib42) unified generation and infilling via causal
masking. CodeGen [Nijkamp et al. \[2022\]](#bib.bib43) demonstrated
multi-turn multi-lingual generation at 16B. The Stack [Kocetkov et al.
\[2022\]](#bib.bib41) established 3TB permissive-license code as the
community standard. SantaCoder [Ben Allal et al. \[2023\]](#bib.bib29)
showed that 1.1B models with high-quality filtering can match much
larger counterparts; this is our primary base model. StarCoder [Li et
al. \[2023\]](#bib.bib30) (15.5B) set the open-source SOTA on HumanEval
(67.2%). CodeT5+ [Wang et al. \[2023\]](#bib.bib58) demonstrated
flexible encoder-decoder pretraining objectives.

Data-quality and instruction-tuning era (2023–2024). WizardCoder [Luo et
al. \[2024\]](#bib.bib59) applied Evol-Instruct (AI-generated
instruction evolution) to code, reaching HumanEval 57.3%; this is an
early AI-assisted data augmentation pipeline. Gunasekar et
al. [Gunasekar et al. \[2023\]](#bib.bib60) showed that 6B tokens of
GPT-4-quality synthetic data can train a 1.3B model to HumanEval 50.6%
(phi-1)—one-shot synthetic, not recursive. Magicoder [Wei et al.
\[2024b\]](#bib.bib61) introduced OSS-Instruct: seed real code snippets
$`\to`$ GPT-generated problems $`\to`$ 7B model at HumanEval 70.7%.
StarCoder2 [Lozhkov et al. \[2024\]](#bib.bib37) and The Stack v2
extended to 900+ languages with improved governance. CodeRL [Le et al.
\[2022\]](#bib.bib63) uses unit-test feedback and a learned critic for
program synthesis, showing the value of grounding code generation in
functional signals. SelfCodeAlign [Wei et al. \[2024a\]](#bib.bib62)
introduced the first execution-validated self-alignment pipeline; its
execution gate corresponds to our Human gate archetype. Code
Llama [Rozière et al. \[2023\]](#bib.bib36) (7B, 13B, 34B) fine-tuned
Llama 2 on code with a mixed code-language pretraining data mixture.

State-of-the-art (2024–2025). DeepSeek-Coder [Guo et al.
\[2024\]](#bib.bib38) (1B–33B) achieves HumanEval 79.3% with
repository-level training. DeepSeek-Coder-V2 [Zhu et al.
\[2024\]](#bib.bib31) (MoE 236B/21B active) matches GPT-4-Turbo code
ability. Qwen2.5-Coder [Hui et al. \[2024\]](#bib.bib32) (0.5B–72B)
surpasses GPT-4o on LiveCodeBench at 72B. OpenCoder [Huang et al.
\[2024\]](#bib.bib35) provides fully open recipe.
OpenCodeInterpreter [Zheng et al. \[2024\]](#bib.bib64) integrates code
generation with execution and refinement, further emphasizing executable
feedback as an external training signal. RLEF [Gehring et al.
\[2025\]](#bib.bib65) grounds code LLMs in execution feedback with RL,
confirming execution-based reward is more stable than LLM-as-judge
reward. DeepSeek-R1 [DeepSeek-AI et al. \[2025\]](#bib.bib66)
demonstrates GRPO-based reasoning scaling with execution verification,
reaching top-96th-percentile on Codeforces.

## Appendix B Evaluation Benchmarks: Full Description

##### HumanEval.

Chen et al. [Chen et al. \[2021\]](#bib.bib33) introduce 164
hand-written Python programming problems with unit test suites. Each
problem consists of a function signature, docstring, and 7–9 unit tests.
The evaluation metric is pass@1 (using the unbiased estimator with
$`n=200`$ samples). HumanEval is the primary benchmark in this paper.

##### MBPP.

The Mostly Basic Programming Problems dataset [Austin et al.
\[2021\]](#bib.bib23) contains 374 crowd-sourced Python problems
focusing on introductory-level tasks (string manipulation, arithmetic,
sorting). Each problem has 3 unit tests. We use the sanitized split.
MBPP is our second primary benchmark.

##### LiveCodeBench.

LiveCodeBench [Jain et al. \[2024\]](#bib.bib34) continuously collects
new programming problems from LeetCode, AtCoder, and Codeforces,
preventing contamination from models that have been trained on earlier
problems. In our experiments, SantaCoder achieves near-zero pass@1 on
LiveCodeBench throughout retraining, reflecting the gap between
introductory-level proficiency and competition-level reasoning. We
retain it as a robustness probe.

##### HumanEval+ and MBPP+.

We additionally report HumanEval+ [Liu et al. \[2024\]](#bib.bib67) and
MBPP+, which augment the original test suites with additional edge
cases. Results are reported in all per-round tables.

##### Code generation metrics.

Table [5](#A2.T5 "Table 5 ‣ Code generation metrics. ‣ Appendix B Evaluation Benchmarks: Full Description ‣ When AI Reviews Its Own Code:Recursive Self-Training Collapse in Code LLMs")
summarizes common metrics for evaluating code generation quality.

|  Metric |  Measured on |  Typical definition |
|----|----|----|
|  pass@k (functional correctness) [Chen et al. \[2021\]](#bib.bib33) |  $`k`$ sampled candidates per problem |  A problem is counted as solved if *at least one* of the $`k`$ sampled programs passes the full unit-test suite; reported as pass@1, pass@10, pass@100. [Chen et al. \[2021\]](#bib.bib33) |
|  pass@1 (single-sample correctness) [Chen et al. \[2021\]](#bib.bib33) |  One candidate per problem |  Special case of pass@k with $`k{=}1`$: fraction of problems whose single generated program passes all tests. [Chen et al. \[2021\]](#bib.bib33) |
|  CodeBLEU [Ren et al. \[2020\]](#bib.bib18) |  Generated code vs. reference code |  A weighted combination of (i) BLEU $`n`$-gram match, (ii) weighted $`n`$-gram match, (iii) AST match, and (iv) data-flow match. [Ren et al. \[2020\]](#bib.bib18) |
|  Text overlap [Papineni et al. \[2002\]](#bib.bib19), [Lin \[2004\]](#bib.bib20), [Popović \[2015\]](#bib.bib21) |  Generated text/code vs. references |  Text overlap metrics: BLEU (precision-weighted $`n`$-gram overlap) [Papineni et al. \[2002\]](#bib.bib19), ROUGE (recall-oriented overlap family) [Lin \[2004\]](#bib.bib20), and chrF (character $`n`$-gram F-score) [Popović \[2015\]](#bib.bib21). |

use pass@1 because recursive retraining changes single-sample
correctness, while the table lists complementary metrics that capture
functional correctness, lexical overlap, structural similarity, and
sample diversity.

##### SantaCoder: Open code LMs with governance and infilling-capable training.

The BigCode technical report on SantaCoder describes the development of
1.1B-parameter code LMs trained on permissively licensed data from The
Stack with an emphasis on transparency and responsible release [Ben
Allal et al. \[2023\]](#bib.bib29), [Kocetkov et al.
\[2022\]](#bib.bib41). The report studies deployment-relevant modeling
choices, notably Multi-Query Attention (MQA) for faster decoder
inference [Shazeer \[2019\]](#bib.bib22) and Fill-in-the-Middle (FIM)
objectives that enable arbitrary-position code infilling [Bavarian et
al. \[2022\]](#bib.bib39), [Fried et al. \[2022\]](#bib.bib42).
Evaluation is conducted using MultiPL-E, which extends unit-test-driven
code generation benchmarks to many languages [Cassano et al.
\[2022\]](#bib.bib40).

##### StarCoder: Open-access code LMs with long context, infilling, and responsible release.

StarCoder and StarCoderBase are 15.5B-parameter open-access code LMs
trained primarily on permissively licensed data from The Stack [Li et
al. \[2023\]](#bib.bib30), [Kocetkov et al. \[2022\]](#bib.bib41). The
models combine an 8K context window, Fill-in-the-Middle (FIM) training
for infilling, and Multi-Query Attention (MQA) for faster large-batch
decoding [Li et al. \[2023\]](#bib.bib30), [Bavarian et al.
\[2022\]](#bib.bib39), [Shazeer \[2019\]](#bib.bib22).

##### StarCoder2: scaling open code LMs with The Stack v2.

StarCoder2 provides 3B/7B/15B parameter checkpoints trained on 3.3–4.3T
tokens, incorporating Fill-in-the-Middle (FIM) training and fast decoder
inference via multi-query style attention [Lozhkov et al.
\[2024\]](#bib.bib37), [Bavarian et al. \[2022\]](#bib.bib39), [Shazeer
\[2019\]](#bib.bib22).

holds and $`\kappa(x)>0`$ (this is $`p_{X}`$-a.e. $`x`$). By
Assumption [2.2](#S2.Thmtheorem2 "Assumption 2.2 (Self-confirming acceptance). ‣ Coupled dynamics under AI self-gating. ‣ 2.3.1 Verifier parameterization: exogenous Human gate vs. endogenous AI self-gate ‣ 2.3 Human Gate vs. AI Self-Gate ‣ 2 Problem Formulation and Theoretical Analysis ‣ When AI Reviews Its Own Code:Recursive Self-Training Collapse in Code LLMs"),
$`r_{\theta_{t}}(x,c)=\kappa(x)`$ for
$`p_{\theta_{t}}(\cdot\mid x)`$-a.e. $`c`$. Therefore,

|  |  |  |  |  |
|----|----|----|----|----|
|  | $`\displaystyle Z^{A}_{\theta_{t},\theta_{t}}(x)`$ | $`\displaystyle=\sum_{c^{\prime}\in\mathcal{C}}p_{\theta_{t}}(c^{\prime}\mid x)r_{\theta_{t}}(x,c^{\prime})`$ |  | (C.1) |
|  |  | $`\displaystyle=\sum_{c^{\prime}\in\mathcal{C}}p_{\theta_{t}}(c^{\prime}\mid x)\kappa(x)`$ |  |  |
|  |  | $`\displaystyle=\kappa(x)\sum_{c^{\prime}\in\mathcal{C}}p_{\theta_{t}}(c^{\prime}\mid x)`$ |  |  |
|  |  | $`\displaystyle=\kappa(x).`$ |  |  |

For any $`c`$ in the $`p_{\theta_{t}}(\cdot\mid x)`$-support where
$`r_{\theta_{t}}(x,c)=\kappa(x)`$,

|  |  |  |  |  |
|----|----|----|----|----|
|  | $`\displaystyle q^{A}_{\theta_{t},\theta_{t}}(c\mid x)`$ | $`\displaystyle=\frac{p_{\theta_{t}}(c\mid x)r_{\theta_{t}}(x,c)}{Z^{A}_{\theta_{t},\theta_{t}}(x)}`$ |  | (C.2) |
|  |  | $`\displaystyle=\frac{p_{\theta_{t}}(c\mid x)\kappa(x)}{\kappa(x)}`$ |  |  |
|  |  | $`\displaystyle=p_{\theta_{t}}(c\mid x),`$ |  |  |

which proves
$`q^{A}_{\theta_{t},\theta_{t}}(\cdot\mid x)=p_{\theta_{t}}(\cdot\mid x)`$
as measures (for $`p_{X}`$-a.e. $`x`$). Multiplying by $`p_{X}(x)`$
yields
$`m_{t}^{A}(x,c)=p_{X}(x)p_{\theta_{t}}(c\mid x)=m_{t}^{\mathrm{ungated}}(x,c)`$
almost everywhere. Substituting $`m_{t}^{A}=m_{t}^{\mathrm{ungated}}`$
into the respective MLE objectives shows the two argmax sets coincide. ∎

``` |  | (C.4) |

so by adding and subtracting
$`r_{H}(x,c)/Z^{A}_{\theta_{t},\phi_{t}}(x)`$ and using triangle
inequality,

|  |  |  |  |  |
|----|----|----|----|----|

### C.3 Proof of Proposition [2.1](#S2.Thmtheorem1 "Proposition 2.1 (Spectral concentration). ‣ 2.2 Representation-Subspace Drift Under Recursive Self-Training ‣ 2 Problem Formulation and Theoretical Analysis ‣ When AI Reviews Its Own Code:Recursive Self-Training Collapse in Code LLMs") (Spectral Concentration)

###### Proof of Proposition [2.1](#S2.Thmtheorem1 "Proposition 2.1 (Spectral concentration). ‣ 2.2 Representation-Subspace Drift Under Recursive Self-Training ‣ 2 Problem Formulation and Theoretical Analysis ‣ When AI Reviews Its Own Code:Recursive Self-Training Collapse in Code LLMs").

Assume the noiseless recursion
$`\Sigma_{t}=A^{t}\Sigma_{0}(A^{\top})^{t}`$ and let
$`A=U\mathrm{diag}(s_{1},\ldots,s_{d})V^{\top}`$ with
$`s_{1}>s_{2}\geq\cdots\geq s_{d}\geq 0`$. Write
$`\widetilde{\Sigma}_{0}:=V^{\top}\Sigma_{0}V\succeq 0`$, so

|  |  |  |  |
|----|----|----|----|
|  |
``` math
\Sigma_{t}=U\mathrm{diag}(s_{1}^{t},\ldots,s_{d}^{t})\widetilde{\Sigma}_{0}\mathrm{diag}(s_{1}^{t},\ldots,s_{d}^{t})U^{\top}.
``` |  | (C.6) |

For any unit vector $`y\in\mathbb{R}^{d}`$, by the Rayleigh quotient and
the change of variables $`y=Ux`$ (so $`\|x\|=1`$),

|  |  |  |  |
|----|----|----|----|
|  |
``` math
y^{\top}\Sigma_{t}y=x^{\top}\Big(\mathrm{diag}(s_{1}^{t},\ldots,s_{d}^{t})\widetilde{\Sigma}_{0}\mathrm{diag}(s_{1}^{t},\ldots,s_{d}^{t})\Big)x.
``` |  | (C.7) |

Let
$`D_{t}:=\mathrm{diag}(s_{1}^{t},\ldots,s_{d}^{t})=s_{1}^{t}\mathrm{diag}\big(1,\rho_{2}^{t},\ldots,\rho_{d}^{t}\big)`$
with $`\rho_{i}:=s_{i}/s_{1}\in[0,1)`$ for $`i\geq 2`$. Then

|  |  |  |  |  |
|----|----|----|----|----|
|  | $`\displaystyle\Sigma_{t}`$ | $`\displaystyle=s_{1}^{2t}U\Big(\widetilde{\Sigma}_{0}+E_{t}\Big)U^{\top},`$ |  | (C.8) |
|  | $`\displaystyle E_{t}`$ | $`\displaystyle:=\Big(\mathrm{diag}(1,\rho_{2}^{t},\ldots,\rho_{d}^{t})\widetilde{\Sigma}_{0}\mathrm{diag}(1,\rho_{2}^{t},\ldots,\rho_{d}^{t})-\widetilde{\Sigma}_{0}\Big).`$ |  |  |

Since
$`\|\mathrm{diag}(1,\rho_{2}^{t},\ldots,\rho_{d}^{t})\|_{2}\leq 1`$ and
$`\|\widetilde{\Sigma}_{0}\|_{2}=\|\Sigma_{0}\|_{2}`$, we have the
operator-norm bound

|  |  |  |  |  |
|----|----|----|----|----|
|  | $`\displaystyle\|E_{t}\|_{2}`$ | $`\displaystyle\leq\|\widetilde{\Sigma}_{0}\|_{2}\cdot\Big\|\mathrm{diag}(1,\rho_{2}^{t},\ldots,\rho_{d}^{t})^{2}-I\Big\|_{2}`$ |  | (C.9) |
|  |  | $`\displaystyle\leq\|\Sigma_{0}\|_{2}\cdot\rho_{2}^{2t}.`$ |  |  |

Moreover, if $`\widetilde{\Sigma}_{0}`$ has nontrivial energy on the
first coordinate, i.e.,

|  |  |  |  |
|----|----|----|----|
|  |
``` math
(\widetilde{\Sigma}_{0})_{11}=v_{1}^{\top}\Sigma_{0}v_{1}\geq\alpha>0,
``` |  | (C.10) |

then taking the Rayleigh quotient [Horn and Johnson
\[2012\]](#bib.bib45) at $`x=e_{1}`$ gives the lower bound

|  |  |  |  |
|----|----|----|----|
|  |
``` math
\lambda_{1}(\Sigma_{t})\geq e_{1}^{\top}D_{t}\widetilde{\Sigma}_{0}D_{t}e_{1}=s_{1}^{2t}(\widetilde{\Sigma}_{0})_{11}\geq\alpha s_{1}^{2t}.
``` |  | (C.11) |

For the second eigenvalue, Weyl’s inequality [Bhatia
\[1997\]](#bib.bib46) applied to
([C.8](#A3.E8 "In Proof of Proposition . ‣ C.3 Proof of Proposition (Spectral Concentration) ‣ Appendix C Complete Proofs ‣ When AI Reviews Its Own Code:Recursive Self-Training Collapse in Code LLMs"))
yields

|  |  |  |  |  |
|----|----|----|----|----|
|  | $`\displaystyle\lambda_{2}(\Sigma_{t})`$ | $`\displaystyle=s_{1}^{2t}\lambda_{2}(\widetilde{\Sigma}_{0}+E_{t})`$ |  | (C.12) |
|  |  | $`\displaystyle\leq s_{1}^{2t}\big(\lambda_{2}(\widetilde{\Sigma}_{0})+\|E_{t}\|_{2}\big)`$ |  |  |
|  |  | $`\displaystyle\leq s_{1}^{2t}\Big(\lambda_{2}(\widetilde{\Sigma}_{0})+\|\Sigma_{0}\|_{2}\rho_{2}^{2t}\Big).`$ |  |  |

Combining
([C.11](#A3.E11 "In Proof of Proposition . ‣ C.3 Proof of Proposition (Spectral Concentration) ‣ Appendix C Complete Proofs ‣ When AI Reviews Its Own Code:Recursive Self-Training Collapse in Code LLMs"))–([C.12](#A3.E12 "In Proof of Proposition . ‣ C.3 Proof of Proposition (Spectral Concentration) ‣ Appendix C Complete Proofs ‣ When AI Reviews Its Own Code:Recursive Self-Training Collapse in Code LLMs"))
gives the explicit ratio bound

|  |  |  |  |
|----|----|----|----|
|  |
``` math
\frac{\lambda_{1}(\Sigma_{t})}{\lambda_{2}(\Sigma_{t})}\geq\frac{\alpha}{\lambda_{2}(\widetilde{\Sigma}_{0})+\|\Sigma_{0}\|_{2}\rho_{2}^{2t}}.
``` |  | (C.13) |

In particular, when $`s_{1}\gg s_{2}`$ (so
$`\rho_{2}=s_{2}/s_{1}\ll 1`$), the term $`\rho_{2}^{2t}`$ decays
exponentially, and the top-eigen direction becomes increasingly
dominated by the $`v_{1}`$-aligned energy injected by
([C.10](#A3.E10 "In Proof of Proposition . ‣ C.3 Proof of Proposition (Spectral Concentration) ‣ Appendix C Complete Proofs ‣ When AI Reviews Its Own Code:Recursive Self-Training Collapse in Code LLMs"))
while contributions from other singular directions are exponentially
suppressed. This yields spectral concentration in the sense that
$`\Sigma_{t}`$ approaches a scaled rank-one form along $`u_{1}`$ when
$`\lambda_{2}(\widetilde{\Sigma}_{0})`$ is small, and more generally the
leading variance component grows at rate $`s_{1}^{2t}`$ whereas any
component tied to $`s_{2}`$ is upper bounded by a factor $`s_{2}^{2t}`$.
∎

## Appendix D Quality Gate Set: Full Definition

### D.1 Quality Dimensions for Code Solutions

Let $`q`$ denote a task/query and let $`\mathcal{D}_{q}`$ be the induced
input distribution (test-time instances) for $`q`$. For a candidate
program $`x\in\mathcal{X}`$, let $`R(x,i)`$ denote the execution output
on input $`i\sim\mathcal{D}_{q}`$, and let $`y(q,i)`$ denote the
task-specific semantic ground truth. We define the following measurable
quality dimensions, each of which can be used either as an evaluation
metric or as a constraint in a quality gate set.

##### (A) Semantic correctness.

We quantify semantic success by the probability of producing the correct
semantic output under $`\mathcal{D}_{q}`$:

|  |  |  |  |
|----|----|----|----|
|  |
``` math
m_{\mathrm{corr}}(x;q):=\Pr_{i\sim\mathcal{D}_{q}}\bigl[R(x,i)=y(q,i)\bigr].
``` |  | (D.1) |

When only a reference answer is available (instead of $`y(q,i)`$), the
event $`R(x,i)=y(q,i)`$ can be replaced by “execution matches the
reference after normalization.”

##### (B) Runtime safety (no crashes/undefined behavior).

Let $`\mathsf{Crash}(x,i)`$ be an indicator of runtime failure on input
$`i`$ (e.g., uncaught exceptions, out-of-bounds access, non-termination
detected by a timeout, or undefined behavior in low-level languages). We
define

|  |  |  |  |
|----|----|----|----|
|  |
``` math
m_{\mathrm{safe}}(x;q):=1-\Pr_{i\sim\mathcal{D}_{q}}\bigl[\mathsf{Crash}(x,i)\bigr].
``` |  | (D.2) |

Equivalently, one may impose a hard safety constraint:

|  |  |  |  |
|----|----|----|----|
|  |
``` math
\Pr_{i\sim\mathcal{D}_{q}}\bigl[\mathsf{Crash}(x,i)\bigr]\leq\delta_{\mathrm{safe}},
``` |  | (D.3) |

for a user-specified tolerance $`\delta_{\mathrm{safe}}\in(0,1)`$.

##### (C) Robustness to perturbations and distribution shift.

Let $`\mathcal{T}(i)`$ denote a set of admissible perturbations of an
input $`i`$ (e.g., format variations, paraphrases, boundary-value
modifications). We define robust correctness as

|  |  |  |  |
|----|----|----|----|
|  |
``` math
m_{\mathrm{rob}}(x;q):=\Pr_{i\sim\mathcal{D}_{q}}\Bigl[\forall i^{\prime}\in\mathcal{T}(i),\ R(x,i^{\prime})=y(q,i^{\prime})\Bigr].
``` |  | (D.4) |

Alternatively, using a loss $`\ell(\cdot,\cdot)`$, we define a
worst-case risk:

|  |  |  |  |
|----|----|----|----|
|  |
``` math
\mathcal{R}_{\mathrm{rob}}(x;q):=\mathbb{E}_{i\sim\mathcal{D}_{q}}\Bigl[\sup_{i^{\prime}\in\mathcal{T}(i)}\ell\bigl(R(x,i^{\prime}),y(q,i^{\prime})\bigr)\Bigr].
``` |  | (D.5) |

##### (D) Resource usage and efficiency.

Let $`T(x,i)`$ be the runtime cost (e.g., wall-clock time) and
optionally $`M(x,i)`$ the memory footprint or $`C(x,i)`$ the number of
external API calls. A simple efficiency score is the negative expected
runtime:

|  |  |  |  |
|----|----|----|----|
|  |
``` math
m_{\mathrm{res}}(x;q):=-\mathbb{E}_{i\sim\mathcal{D}_{q}}\bigl[T(x,i)\bigr].
``` |  | (D.6) |

One may also enforce probabilistic latency constraints:

|  |  |  |  |
|----|----|----|----|
|  |
``` math
\Pr_{i\sim\mathcal{D}_{q}}\bigl[T(x,i)\leq\tau\bigr]\geq 1-\delta_{\mathrm{time}},
``` |  | (D.7) |

or tail-latency bounds (e.g., the $`0.99`$-quantile):

|     |                                                            |     |       |
|-----|------------------------------------------------------------|-----|-------|
|     |
       ``` math
       \mathrm{Quantile}_{0.99}\bigl(T(x,i)\bigr)\leq\tau_{0.99}.
       ```                                                         |     | (D.8) |

##### (E) Security and compliance.

Let $`\mathsf{Bad}(x,i)`$ indicate unsafe or policy-violating behavior
(e.g., invoking dangerous system calls, writing to sensitive paths,
unintended network access, or insecure deserialization). We define

|  |  |  |  |
|----|----|----|----|
|  |
``` math
m_{\mathrm{sec}}(x;q):=1-\Pr_{i\sim\mathcal{D}_{q}}\bigl[\mathsf{Bad}(x,i)\bigr],
``` |  | (D.9) |

or impose a hard constraint
$`\Pr[\mathsf{Bad}]\leq\delta_{\mathrm{sec}}`$ for
$`\delta_{\mathrm{sec}}\in(0,1)`$.

##### (F) Maintainability and testability.

Maintainability can be captured by static code metrics such as
cyclomatic complexity, code duplication, and dependency burden:

|  |  |  |  |
|----|----|----|----|
|  |
``` math
m_{\mathrm{maint}}(x):=-\Bigl(\lambda_{1}\mathrm{Cyclomatic}(x)+\lambda_{2}\mathrm{Dup}(x)+\lambda_{3}\mathrm{Deps}(x)\Bigr),
``` |  | (D.10) |

with weights $`\lambda_{1},\lambda_{2},\lambda_{3}\geq 0`$. If a
unit-test distribution $`\mathcal{T}_{\mathrm{unit}}`$ is available,
test pass rate provides an executable proxy:

|  |  |  |  |
|----|----|----|----|
|  |
``` math
m_{\mathrm{test}}(x):=\Pr_{t\sim\mathcal{T}_{\mathrm{unit}}}\bigl[x\ \text{passes test}\ t\bigr].
``` |  | (D.11) |

##### (G) Readability and style (including documentation consistency).

Let $`S_{\mathrm{read}}(x)\in[0,1]`$ be a readability/style score from
either rule-based or learned evaluators. We set

|     |                                             |     |        |
|-----|---------------------------------------------|-----|--------|
|     |
       ``` math
       m_{\mathrm{read}}(x):=S_{\mathrm{read}}(x).
       ```                                          |     | (D.12) |

When inline documentation $`\mathrm{doc}(x)`$ is present, one may
additionally measure documentation–implementation consistency via an
alignment score $`\mathrm{Align}\bigl(x,\mathrm{doc}(x)\bigr)`$, where
larger values indicate better semantic agreement.

### D.2 Quality-Feasible Code Set

Let $`q`$ denote a task/query, $`\mathcal{X}`$ the program space, and
$`\mathcal{D}_{q}`$ the input distribution induced by $`q`$. Let
$`V:\mathcal{X}\to\{0,1\}`$ be a feasibility verifier, $`R(x,i)`$ the
execution result of program $`x`$ on input $`i`$, and $`y(q,i)`$ the
task-specific semantic ground truth. We further define runtime event
predicates $`\mathsf{Crash}(x,i)`$ (crash/exception/undefined behavior)
and $`\mathsf{Bad}(x,i)`$ (unsafe or policy-violating behavior), a
runtime cost $`T(x,i)`$ (e.g., wall-clock time), and a readability/style
scorer $`S_{\mathrm{read}}(x)\in[0,1]`$. For user-specified thresholds
$`\delta_{\mathrm{safe}},\delta_{\mathrm{sec}}\in(0,1)`$ and
$`\tau,r_{0}>0`$, we define the *quality-feasible* solution set as

|  |  |  |  |  |
|----|----|----|----|----|
|  | $`\displaystyle\mathcal{F}_{\mathrm{qual}}(q):=\Bigl\{x\in\mathcal{X}`$ | $`\displaystyle:\underbrace{V(x)=1}_{\text{feasibility}},`$ |  | (D.13) |
|  |  | $`\displaystyle\underbrace{\Pr_{i\sim\mathcal{D}_{q}}\bigl[R(x,i)=y(q,i)\bigr]\geq\delta_{\mathrm{corr}}}_{\text{semantic correctness}},`$ |  |  |
|  |  | $`\displaystyle\underbrace{\Pr_{i\sim\mathcal{D}_{q}}\bigl[\mathsf{Crash}(x,i)\bigr]\leq\delta_{\mathrm{safe}}}_{\text{runtime safety}},`$ |  |  |
|  |  | $`\displaystyle\underbrace{\mathbb{E}_{i\sim\mathcal{D}_{q}}\bigl[T(x,i)\bigr]\leq\tau}_{\text{resource/efficiency}},`$ |  |  |
|  |  | $`\displaystyle\underbrace{\Pr_{i\sim\mathcal{D}_{q}}\bigl[\mathsf{Bad}(x,i)\bigr]\leq\delta_{\mathrm{sec}}}_{\text{security/compliance}},`$ |  |  |
|  |  | $`\displaystyle\underbrace{S_{\mathrm{read}}(x)\geq r_{0}}_{\text{readability/style}}\Bigr\},`$ |  |  |

where $`\delta_{\mathrm{corr}}\in(0,1]`$ specifies the minimum
acceptable semantic success rate. If only a reference answer is
available (rather than $`y(q,i)`$), the event $`R(x,i)=y(q,i)`$ can be
replaced by “execution matches the reference after normalization.”

### D.3 Supporting Assumptions

###### Assumption D.1 (Non-trivial quality-feasible completeness / coverage).

Let $`\mathcal{D}`$ denote the target distribution over queries $`q`$,
and for each $`q`$ let $`\mathcal{D}_{q}`$ be the induced input
distribution. Let $`V:\mathcal{X}\to\{0,1\}`$ be a feasibility verifier
and define the quality gate set
$`\mathcal{F}_{\mathrm{qual}}(q)\subseteq\mathcal{X}`$ as in the main
text (incorporating feasibility, semantic correctness, runtime safety,
efficiency, security/compliance, and readability/style). Then for
$`\mathcal{D}`$-almost every query $`q`$, there exists a non-empty
subset $`\mathcal{F}_{\mathrm{qual}}(q)`$ and constants
$`\alpha,\beta\in(0,1]`$ such that

|  |  |  |  |
|----|----|----|----|
|  |
``` math
\mu\bigl(\mathcal{F}_{\mathrm{qual}}(q)\bigr)\geq\alpha,\qquad P_{\theta_{0}}\bigl(\mathcal{F}_{\mathrm{qual}}(q)\mid q\bigr)\geq\beta,
``` |  | (D.14) |

where $`\mu`$ is a reference measure on $`\mathcal{X}`$ (or on the
relevant solution equivalence class for $`q`$), and
$`P_{\theta_{0}}(\cdot\mid q)`$ is the initial generator’s conditional
distribution.

###### Assumption D.2 (Quality-feasible margin).

Let $`d:\mathcal{X}\times\mathcal{X}\to\mathbb{R}_{\geq 0}`$ be a metric
(or pseudometric) on $`\mathcal{X}`$, and define

|  |  |  |  |
|----|----|----|----|
|  |
``` math
d(x,\mathcal{F}_{\mathrm{qual}}(q)):=\inf_{y\in\mathcal{F}_{\mathrm{qual}}(q)}d(x,y).
``` |  | (D.15) |

There exists $`\gamma>0`$ such that for $`\mathcal{D}`$-almost every
$`q`$, for all $`x\in\mathcal{F}_{\mathrm{qual}}(q)`$ and all
$`x^{\prime}\in\mathcal{X}`$,

|  |  |  |  |
|----|----|----|----|
|  |
``` math
d(x,x^{\prime})\leq\gamma\Longrightarrow x^{\prime}\in\mathcal{F}_{\mathrm{qual}}(q).
``` |  | (D.16) |

Equivalently, the $`\gamma`$-ball around any
$`x\in\mathcal{F}_{\mathrm{qual}}(q)`$ is contained in
$`\mathcal{F}_{\mathrm{qual}}(q)`$.

###### Assumption D.3 (Local contraction toward the quality gate set).

Let $`C:\mathcal{X}\to\mathcal{X}`$ denote a correction (or calibration)
operator applied to candidate programs. There exist constants
$`\rho\in(0,1)`$ and $`\eta\geq 0`$ such that for $`\mathcal{D}`$-almost
every $`q`$ and all $`x`$ in the region of interest,

|  |  |  |  |
|----|----|----|----|
|  |
``` math
d\bigl(C(x),\mathcal{F}_{\mathrm{qual}}(q)\bigr)\ \leq\ \rho\,d\bigl(x,\mathcal{F}_{\mathrm{qual}}(q)\bigr)\ +\ \eta.
``` |  | (D.17) |

When $`\eta=0`$, $`C`$ is a strict contraction toward
$`\mathcal{F}_{\mathrm{qual}}(q)`$; when $`\eta>0`$, the term $`\eta`$
captures an irreducible residual error (noise floor).

## Appendix E AI Self-Verification Protocol

### E.1 Implemented AI Self-Gates

This appendix details the two AI self-gate methods used in our
experiments: Perplexity and Binary Classifier. We use these methods as
representative AI self-verification protocols because both derive
acceptance scores from the code LLM itself, rather than from human
labels, execution tests, or external static analyzers. Thus, the same
model family that generates candidate code also evaluates which samples
enter future training.

##### Basic formulation.

Let $`q`$ denote the programming problem and let $`x`$ denote a code
sample generated by the current code LLM. We construct an evaluation
prompt $`\Pi_{\mathrm{eval}}(q,x)`$ that contains the problem statement,
the candidate code, and an explicit request for assessment. The model
then produces an evaluation response

|     |                                                  |     |       |
|-----|--------------------------------------------------|-----|-------|
|     |
       ``` math
       r\sim p_{\theta}(r\mid\Pi_{\mathrm{eval}}(q,x)).
       ```                                               |     | (E.1) |

This is a self-evaluation procedure because the same parameterized model
$`p_{\theta}`$ first generates $`x`$ and then, under a different prompt
or scoring rule, evaluates $`x`$.

##### Binary-classifier self-gate.

The binary self-gate forces the model into a two-label judgment. The
evaluation prompt asks the model to classify a candidate as good or bad.
In our implementation, the prompt appends “\n# quality: ” to the last
2000 tokens of the generated completion. The acceptance score is

|  |  |  |  |
|----|----|----|----|
|  |
``` math
S_{\mathrm{bin}}(x\mid q)=\log P_{\theta}(\texttt{good}\mid q,x)-\log P_{\theta}(\texttt{bad}\mid q,x).
``` |  | (E.2) |

Samples are ranked by $`S_{\mathrm{bin}}(x\mid q)`$, and the top 25% are
retained for the next round of recursive fine-tuning. This uses only the
model parameters: no human label, execution result, or external quality
metric is used.

##### Perplexity self-gate.

Code LLMs are generative models trained to predict code tokens and are
commonly used for code completion or masked/fill-in-the-middle
generation. We therefore use the model’s own conditional likelihood as
an AI self-gate. For each generated sample $`x`$ under problem context
$`q`$, we compute

|  |  |  |  |
|----|----|----|----|
|  |
``` math
S_{\mathrm{ppl}}(x\mid q)=-\frac{1}{|x|}\sum_{i=1}^{|x|}\log P_{\theta}(x_{i}\mid q,x_{<i}).
``` |  | (E.3) |

Equivalently, the perplexity is

|  |  |  |  |
|----|----|----|----|
|  |
``` math
\mathrm{PPL}_{\theta}(x\mid q)=\exp\big(S_{\mathrm{ppl}}(x\mid q)\big).
``` |  | (E.4) |

Generated samples with lower $`S_{\mathrm{ppl}}(x\mid q)`$, or lower
$`\mathrm{PPL}_{\theta}(x\mid q)`$, are treated as more acceptable. In
our implementation, samples are ranked by perplexity and the lowest 25%
are retained for future training. This is an AI self-gate because the
same code LLM family generates $`x`$ through completion/filling and then
scores $`x`$ by its own token likelihood.

### E.2 Other Candidate AI Self-Verifier Protocols

The following protocols are natural extensions of AI self-verification,
but are not used as main filtering methods in our experiments.

##### Chain-of-thought judge followed by forced verdict.

A stronger AI verifier can first generate an assessment trace and then
output a forced final verdict. The evaluation prompt may request the
model to summarize the intended algorithm, identify possible bugs or
edge-case failures, and then output a final label from a fixed set. The
model generates a reasoning trace $`z`$ and a verdict $`y`$:

|  |  |  |  |
|----|----|----|----|
|  |
``` math
p_{\theta}(y,z\mid q,x)=p_{\theta}(z\mid q,x)p_{\theta}(y\mid q,x,z).
``` |  | (E.5) |

##### Self-consistency over judge samples.

Since one judge response can be noisy, the model can sample multiple
evaluations:

|  |  |  |  |
|----|----|----|----|
|  |
``` math
r^{(1)},r^{(2)},\dots,r^{(M)}\sim p_{\theta}(\cdot\mid\Pi_{\mathrm{eval}}(q,x)).
``` |  | (E.6) |

The final self-judgment can be obtained by majority vote,

|  |  |  |  |
|----|----|----|----|
|  |
``` math
\hat{y}_{\mathrm{vote}}(x\mid q)=\operatorname{mode}\{y^{(1)},\dots,y^{(M)}\},
``` |  | (E.7) |

or by averaged label probabilities:

|  |  |  |  |
|----|----|----|----|
|  |
``` math
\hat{y}_{\mathrm{avg}}(x\mid q)=\arg\max_{y\in\mathcal{Y}}\frac{1}{M}\sum_{m=1}^{M}P_{\theta}^{(m)}(y\mid q,x).
``` |  | (E.8) |

##### Constrained multi-label judge.

For code LLMs, the evaluation prompt should be constrained. A weak
prompt such as “Is this code good?” is underspecified. A more controlled
prompt asks the model to check whether the implementation matches the
specification, handles corner cases, and avoids likely bugs, then end
with exactly one label from a fixed set such as CORRECT, LIKELY_CORRECT,
UNCERTAIN, LIKELY_BUGGY, or BUGGY. This still remains an AI self-gate if
the score is produced by the same model family that generated the code.

##### Why AI self-evaluation degrades.

LLM evaluators exhibit significant self-preference bias [Panickssery et
al. \[2024\]](#bib.bib28): they assign higher scores to outputs in their
own generation style, regardless of actual quality. As the model
collapses and its style converges to a narrow distribution, the
evaluator’s preferences converge with it, causing the gate to accept
progressively worse outputs with progressively higher confidence. This
is the self-confirming regime formalized in
Assumption [2.2](#S2.Thmtheorem2 "Assumption 2.2 (Self-confirming acceptance). ‣ Coupled dynamics under AI self-gating. ‣ 2.3.1 Verifier parameterization: exogenous Human gate vs. endogenous AI self-gate ‣ 2.3 Human Gate vs. AI Self-Gate ‣ 2 Problem Formulation and Theoretical Analysis ‣ When AI Reviews Its Own Code:Recursive Self-Training Collapse in Code LLMs")
and
Theorem [2.3](#S2.Thmtheorem3 "Theorem 2.3 (Degeneracy to ungated recursion). ‣ Coupled dynamics under AI self-gating. ‣ 2.3.1 Verifier parameterization: exogenous Human gate vs. endogenous AI self-gate ‣ 2.3 Human Gate vs. AI Self-Gate ‣ 2 Problem Formulation and Theoretical Analysis ‣ When AI Reviews Its Own Code:Recursive Self-Training Collapse in Code LLMs").
For production-quality judging protocols that mitigate this bias,
see [Panickssery et al. \[2024\]](#bib.bib28), [Hashemi et al.
\[2024\]](#bib.bib25), [Zheng et al. \[2023\]](#bib.bib24).

## Appendix F Mixed Training

Code LLMs differ in their pretraining data mixtures, and we adapt the
recursive fine-tuning format accordingly. The key distinction is whether
a model was trained mainly on raw source code or on a broader mixture of
code and code-related natural language.

##### SantaCoder.

SantaCoder [Ben Allal et al. \[2023\]](#bib.bib29) is pretrained on
Python, Java, and JavaScript from The Stack [Kocetkov et al.
\[2022\]](#bib.bib41). Its data consists primarily of source-code files,
with natural language appearing only inside comments, docstrings, and
identifiers. We therefore fine-tune SantaCoder using pure code samples
in the recursive loop.

##### StarCoder and StarCoder2.

StarCoder [Li et al. \[2023\]](#bib.bib30) and StarCoder2 [Lozhkov et
al. \[2024\]](#bib.bib37) are trained on broader code corpora that
include source code together with code-related natural language, such as
issues, commits, pull-request text, and notebook content. For these
models, recursive fine-tuning uses a mixed code–natural-language format
to better match the original training distribution.

##### Qwen2.5-Coder.

Qwen2.5-Coder [Hui et al. \[2024\]](#bib.bib32) follows a multi-stage
code-model training pipeline, including large-scale code pretraining,
code-related natural-language data, and instruction tuning. We therefore
also use a mixed code–natural-language fine-tuning format for
Qwen2.5-Coder rather than pure code-only retraining.

##### Training mixture used in our experiments.

Following the model-specific formats above, we use pure-code recursive
fine-tuning for SantaCoder and mixed code–natural-language fine-tuning
for StarCoder, StarCoder2, and Qwen2.5-Coder. For the mixed setting,
each round uses approximately 70–80% code and 20–30% code-related
natural language, including problem statements, comments, commits,
issues, notebooks, and instruction-style descriptions. After recursive
data construction, the accepted samples are used for SFT-style
fine-tuning, and we preserve a small human-verified or
execution-verified anchor set when available. When recursive retraining
is applied, Human-gate runs use model-independent checks such as
compilation and quality rules at every round, while AI-self-gate runs
use model-assigned scores such as PPL. This design follows prior
analyses of recursive training collapse [Suresh et al.
\[2025\]](#bib.bib51), [Seddik et al. \[2024\]](#bib.bib49) and
code-model training practice [Gunasekar et al. \[2023\]](#bib.bib60),
while keeping the controlled variable fixed: within each model family,
only the review policy changes.

## Appendix J Implementation Details

##### Data generation and filtering.

At each recursive round, the current model first performs one inference
pass to generate candidate code from the fixed prompt pool. The accepted
set size is fixed to 5000 samples per round. For Human-gate methods, we
generate samples in batches of 2000 until 5000 samples pass the filter.
For AI-self-gate methods, we generate 20,000 samples once, score all
candidates, and retain the top or bottom 25% depending on the score
definition. After the accepted set is built, the model is fine-tuned on
these self-generated samples for 3000 training steps. Thus, 10 recursive
rounds correspond to 30k training steps. Across methods, the recursive
loop is the same: one generation stage followed by one fine-tuning stage
per round; only the filtering policy differs.

##### Evaluation and hardware.

After each round, all methods are evaluated on HumanEval [Chen et al.
\[2021\]](#bib.bib33), [OpenAI \[2021\]](#bib.bib16), MBPP [Austin et
al. \[2021\]](#bib.bib23), and LiveCodeBench [Jain et al.
\[2024\]](#bib.bib34). We use bigcode-evaluation-harness [Ben Allal et
al. \[2022\]](#bib.bib17) with temperature 0.8 and top-$`p`$ 0.95 for
generation, and greedy decoding for final pass@1 computation. HumanEval+
and MBPP+ are evaluated with EvalPlus [Liu et al. \[2024\]](#bib.bib67).
For execution-pass analysis, we evaluate 500 generated samples with a 5s
timeout. All experiments are conducted on NVIDIA RTX 6000 Ada Generation
GPUs.
````
