###### Abstract

Large language models have made substantial progress in mathematical
reasoning, yet in complex multi-step reasoning, an error at any step may
propagate along an incorrect path, and the resulting solution may omit
necessary branches. Existing natural-language reflection methods often
struggle to locate critical errors precisely, while outcome verification
typically checks only whether the available candidate answers satisfy
the problem conditions and can therefore overlook necessary branches. To
address these limitations, we propose Agent-Guided Process Verification
(AGPV) for mathematical self-correction. AGPV decomposes the current
solution into an ordered sequence of key claims, verifies them
individually while invoking a shared mathematical toolbox when needed,
and stops upon detecting the first error. A summarization agent converts
the failure evidence into a diagnosis that guides a correction agent to
re-derive the subsequent solution from that point; AGPV then adapts the
next verification iteration to the revised solution. AGPV also verifies
solution completeness. We further prove that AGPV guarantees solution
correctness and completeness when key claims provide sufficient coverage
and local verification is reliable, provided that all key claims pass
verification. The implementation compresses long working contexts and
reuses successful tool results within each problem. We evaluate AGPV on
five challenging mathematical reasoning datasets with four models from
DeepSeek, Qwen, and GPT. AGPV achieves an average accuracy of 63.8%,
outperforming the strongest among the representative baselines evaluated
(50.3%) by 13.5 percentage points, with higher repair coverage than the
programmatic-verification baselines.

## 1 Introduction

Large language models have made substantial progress in mathematical
reasoning (Wei et al., 2022; Lewkowycz et al., 2022; Guo et al., 2025).
However, in complex multi-step mathematical problems, an error at one
step may cause the subsequent reasoning to proceed along an incorrect
path and ultimately produce a wrong answer (Uesato et al., 2022;
Lightman et al., 2024). Effective error checking and self-correction are
therefore essential to improving the reliability of mathematical
reasoning in large language models. Existing approaches primarily
include natural-language reflection, iterative refinement, structured
checking, and program- or tool-augmented verification (Pan et al., 2024;
Gou et al., 2024a). For example, Self-Refine (Madaan et al., 2023) and
Reflexion (Shinn et al., 2023) use natural-language feedback to support
reflection and iterative refinement, while CheckList (Cook et al., 2024)
organizes evaluation and correction through generated checklists.
ProgCo (Song et al., 2025), by contrast, employs a programmatic
verification mechanism to perform outcome verification from candidate
answers.

These approaches nevertheless have two limitations. First, holistic
natural-language reflection has difficulty locating errors precisely.
Even when it identifies several suspicious points, it may fail to find
the first critical error that actually invalidates the subsequent
reasoning, leading to unfocused, wholesale rewriting (Huang et al.,
2024; Tyen et al., 2024). Second, outcome verification starting from
candidate answers typically focuses on whether the available results
satisfy the problem conditions (Uesato et al., 2022; Lightman et al.,
2024). However, it does not explicitly represent whether all valid
solutions and necessary branches have been covered. It may therefore
miss incompleteness errors such as incomplete solution sets or omitted
branches. As shown in Fig. 1, the problem asks for all real roots of an
equation. Substituting the available results $`\{2,-1\}`$ into the
original equation verifies both roots, yet the solution set remains
incomplete. In contrast, checking the key claim “whether all solutions
to $`x^{2}=4`$ have been found” along the solution process reveals the
omission and precisely localizes the error.

The first critical error in mathematical reasoning resembles the first
falling domino: subsequent errors often emerge through a cascading
effect. It is therefore important to localize the first critical error
in the solution process promptly and begin correction from that point.
Tyen et al. show that providing an error location can facilitate
correction (Tyen et al., 2024). Motivated by this, AGPV constructs and
sequentially verifies key claims along the solution process to localize
the first claim that compromises the correctness or completeness of
subsequent reasoning. Step-level process verification provides
fine-grained signals over intermediate reasoning (Lightman et al., 2024;
Wang et al., 2024). AGPV uses this granularity to check whether
necessary branches are complete as the reasoning unfolds, thereby
verifying completeness within the same process.

Accordingly, we propose AGPV. Here, process verification means
converting the current solution into an ordered sequence of locally
verifiable key claims and checking them in their original reasoning
order. We call the method agent-guided because specialized agents
dynamically construct and verify solution-specific key claims, summarize
the first failed claim together with supporting evidence, and use this
diagnosis to guide localized correction of the subsequent reasoning.
Within the AGPV framework, a generation agent first parses the current
solution and constructs an ordered sequence of key claims. A
verification agent then checks these claims sequentially and, when
necessary, invokes a shared mathematical toolbox to obtain mathematical
evidence such as equation-solving and constraint-checking results. Upon
encountering the first key claim that fails verification, the framework
stops searching and initiates correction. A summarization agent then
generates feedback from the failure evidence, guiding a correction agent
to re-derive the subsequent solution from that point. Based on whether
the answers before and after correction are equivalent, the framework
regenerates or adapts the key claims for the revised solution and
repeats this process until all key claims pass verification or the
iteration limit is reached. We further prove that, under ideal
conditions in which the key claims provide sufficient coverage and local
verification is reliable, AGPV guarantees the correctness and
completeness of the final solution, provided that all key claims pass
verification.

We evaluate AGPV on five challenging mathematical reasoning datasets
with four models from DeepSeek, Qwen, and GPT. AGPV achieves an average
accuracy of $`63.8\%`$, outperforming the strongest evaluated baseline
($`50.3\%`$) by $`13.5`$ percentage points. Correction analysis shows
that it repairs more initially incorrect answers, with particularly
pronounced gains on problems that the initial models solve less
reliably.

Our contributions are as follows: (1) We propose AGPV, which uses
process verification to localize the first key claim that fails
verification and guides the model to re-derive the subsequent solution
from that point; (2) AGPV naturally incorporates solution-completeness
checking into process verification without requiring a separate
completeness-checking stage, enabling it to identify incompleteness
errors. We further provide a corresponding conditional reliability
proof; and (3) We develop a multi-agent implementation of AGPV with a
shared mathematical toolbox, iterative key-claim adaptation,
working-context compression, and within-problem reuse of successful tool
results, and validate its effectiveness across multiple mathematical
datasets and model settings.

## 2 Related Work

This work relates to three research areas: self-correction in large
language models, process verification, and tool-augmented mathematical
reasoning.

Self-Correction in Large Language Models. Prior work improves test-time
outputs through natural-language feedback, reflection, structured
checking, and multi-path sampling. Self-Refine (Madaan et al., 2023)
iteratively generates feedback and revises its responses;
Reflexion (Shinn et al., 2023) uses linguistic feedback to summarize
prior failures; TICK (Cook et al., 2024) organizes evaluation and
correction with automatically generated checklists; and
Self-Consistency (Wang et al., 2023) selects a consistent answer across
multiple reasoning paths. Recent studies further improve
self-verification and self-correction through training. S²R (Ma et al., 2025) uses reinforcement learning to train models for self-verification
and correction, while SPOC (Zhao et al., 2025) interleaves solution
generation and verification in a single inference pass to trigger
spontaneous correction. Collectively, these studies show that feedback
and test-time iteration can improve large language models’ reasoning
outcomes.

Process Verification. Verifiers commonly evaluate, rank, or filter
candidate solutions. Early mathematical reasoning work used outcome
verifiers (Cobbe et al., 2021) to select more reliable outputs from
multiple candidates. Uesato et al. (Uesato et al., 2022) compared
outcome-based and process-based feedback for mathematical reasoning.
Lightman et al. (Lightman et al., 2024) introduced PRM800K with
step-level annotations and used process supervision to train process
reward models. Math-Shepherd (Wang et al., 2024) automated
process-supervision data construction, assigned rewards to intermediate
reasoning steps, and applied them to candidate ranking and reinforcement
learning. For test-time self-correction, ProgCo (Song et al., 2025)
applies program-guided verification to candidate solutions and generates
corrective feedback from execution results. Together, these studies
extend verification from final outcomes to intermediate reasoning and
provide a foundation for identifying process errors.

Figure 2: The AGPV workflow: sequential key-claim verification,
first-error localization, failure-evidence summarization, solution
correction, and verification-plan regeneration or updating.

Tool-Augmented Mathematical Reasoning. Tool-augmented reasoning combines
programs, code interpreters, and specialized mathematical tools to
improve the reliability of language models’ symbolic derivations and
exact computation. PAL (Gao et al., 2023) translates problems into
programs executed by a Python interpreter; Program-of-Thoughts (Chen
et al., 2023) separates computation from natural-language reasoning; and
ToRA (Gou et al., 2024b) alternates between natural-language reasoning
and external tool calls to solve complex mathematical problems.
ReAct (Yao et al., 2023) coordinates reasoning with external actions,
while Toolformer (Schick et al., 2023) enables language models to select
and invoke tools autonomously. Recent work such as AgentMath (Luo
et al., 2026) and R1-Code-Interpreter (Chen et al., 2026) further
integrates code interpreters and mathematical tools with agent training
for complex mathematical reasoning.

Overall, prior work improves mathematical reasoning through test-time
self-correction, process supervision, and tool augmentation. AGPV builds
on these directions by constructing ordered key claims from the current
solution and problem objective, locating the first failed claim,
checking completeness claim by claim, and using tool evidence to focus
correction on the subsequent solution.

## 3 Method

Figure 2 presents the overall AGPV framework. Given a problem $`q`$, the
current solution $`y_{t}`$ at iteration $`t`$, and its extracted answer
$`a_{t}`$, AGPV generates an ordered sequence of locally verifiable key
claims and checks them in an order aligned with the original reasoning
process. If all claims pass, the system accepts the current answer.
Otherwise, it identifies the first failed claim as the first critical
error, summarizes the failure evidence, and corrects the subsequent
solution from that point. After correction, the answer-equivalence
controller compares the answers before and after correction to decide
whether the next iteration should regenerate or update the key-claim
sequence and verification plan. Key-claim verification, solution
correction, and updates to the key claims and verification plan may
invoke the shared mathematical toolbox for exact computation. The
following subsections describe key-claim generation and verification,
solution correction, and verification-plan updates. Algorithm 1 in
Appendix A provides the complete AGPV control procedure.

Table A in Appendix A lists the prompts for the six agents in Figure 2.

### 3.1 Generating Key Claims

AGPV verifies a sequence of key claims jointly determined by the current
solution and the problem objective. Given problem $`q`$, current
solution $`y_{t}`$, and extracted answer $`a_{t}`$ at iteration $`t`$,
$`\mathcal{A}_{\mathrm{gen}}`$ generates the key-claim sequence and its
verification plan:

```math
(C_{t},V_{t})=\mathcal{A}_{\mathrm{gen}}(q,y_{t},a_{t}),\qquad C_{t}=(c_{t,1},c_{t,2},\ldots,c_{t,n_{\scriptstyle t}}). \tag{1}
```

Here, the ordered key-claim sequence $`C_{t}`$ specifies what to verify,
and $`V_{t}`$ specifies how to verify it along the current solution. The
term $`c_{t,i}`$ is the $`i`$-th verifiable mathematical claim at
iteration $`t`$, and $`n_{t}`$ is the number of key claims in that
iteration. These claims may come from explicit reasoning steps or be
induced by the problem objective, including algebraic simplification,
equation transformation, numerical computation, constraint derivation,
and completeness requirements.

Key claims are distinct from solution steps. Solution steps are the
original reasoning units that appear in their written order in the
current solution $`y_{t}`$, whereas a key claim $`c_{t,i}`$ is an
independently verifiable mathematical proposition extracted or
constructed from one or more solution steps and the problem objective.
Their mapping need not be one-to-one: one step may yield multiple
claims, several steps may support one claim, and the problem objective
may induce completeness claims that are not stated explicitly in the
current solution. AGPV orders key claims by the original solution
process, while $`V_{t}`$ specifies their verification. The verification
plan $`V_{t}`$ specifies the order in which the key claims are verified,
their local verification objectives, the tool types that may be
required, and the evidence to retain during verification. AGPV
decomposes the current solution into key claims ordered by the original
reasoning process, enabling subsequent verification to localize errors
to specific reasoning stages rather than issuing a single judgment on
the final answer.

AGPV naturally incorporates solution-completeness checks into process
verification. For problems requiring all solutions, complete counting,
exhaustive enumeration, a complete set, or a global optimum, it converts
each requirement into a key claim in $`C_{t}`$. These requirements thus
enter the same process-verification chain as local computations,
constraint derivations, and intermediate conclusions.

### 3.2 Verifying Key Claims

AGPV verifies the current solution claim by claim and invokes the shared
mathematical toolbox agent when exact computation is required, producing
traceable tool evidence. Given the key-claim sequence $`C_{t}`$ and
verification plan $`V_{t}`$ from the preceding subsection,
$`\mathcal{A}_{\mathrm{ver}}`$ returns

```math
(r_{t},R_{t},k_{t})=\mathcal{A}_{\mathrm{ver}}(q,y_{t},a_{t},C_{t},V_{t}). \tag{2}
```

Here, $`r_{t}\in\{0,1\}`$ indicates whether verification succeeds at
iteration $`t`$; $`R_{t}`$ stores the examined key claims, corresponding
tool evidence, and pass/fail decisions; and $`k_{t}`$ is the position of
the first failed claim, with $`k_{t}=\varnothing`$ when all claims pass.
Under the ideal conditions that the key claims sufficiently cover the
current solution process, preserve the original reasoning order, and are
verified reliably, the first failed claim corresponds to the first
critical error. We use this term below. Specifically,
$`\mathcal{A}_{\mathrm{ver}}`$ checks the claims in $`C_{t}`$ in the
order specified by $`V_{t}`$. For each claim,
$`\mathcal{A}_{\mathrm{ver}}`$ determines whether the problem conditions
and previously verified steps support it. $`\mathcal{A}_{\mathrm{ver}}`$
directly returns pass or fail for simple logical or
expression-consistency checks. For algebraic simplification, equation
solving, enumeration, counting, constraint checking, or exact numerical
computation, $`\mathcal{A}_{\mathrm{ver}}`$ sends a structured request
to the shared mathematical toolbox agent and uses the result as
verification evidence.

##### Shared Mathematical Toolbox Agent.

Let $`\mathbb{T}`$ denote the available tools for symbolic
simplification, equation solving, enumeration and counting, constraint
checking, and exact computation. When reliable computation is needed
during key-claim verification, solution correction, or updates to the
key claims and verification plan, the corresponding agent generates a
structured request $`\tau_{t}^{s}`$, where
$`s\in\{\mathrm{ver},\mathrm{fix},\mathrm{upd}\}`$.
$`\mathcal{A}_{\mathrm{tool}}`$ selects a tool and generates an
executable call:

```math
\kappa_{t}^{s}=\mathcal{A}_{\mathrm{tool}}(\tau_{t}^{s};\mathbb{T}),\qquad z_{t}^{s}=\operatorname{Run}(\kappa_{t}^{s}). \tag{3}
```

Here, $`\kappa_{t}^{s}`$ is the generated tool call,
$`\operatorname{Run}`$ executes it on the tool backend, and
$`z_{t}^{s}`$ is the returned result. Equation (3) may be repeated as
needed within a stage. Verification results enter $`R_{t}`$; correction
results support new computations or derivations; and update results help
inspect the updated verification targets. $`\mathcal{A}_{\mathrm{sum}}`$
does not call the toolbox directly but summarizes the tool evidence
already stored in $`R_{t}`$. Our implementation supports SymPy (Meurer
et al., 2017), Z3 (de Moura & Bjørner, 2008), and Python tools for exact
numerical computation and enumeration.

If all key claims pass verification, $`r_{t}=1`$ and
$`k_{t}=\varnothing`$, and the system accepts the current solution and
extracted answer. Otherwise, AGPV identifies the first failed claim as
the first critical error:

```math
k_{t}=\min\{i\mid c_{t,i}\ \text{fails verification}\},\qquad r_{t}=0. \tag{4}
```

Verification stops immediately, and $`R_{t}`$ retains the verification
trace from the first claim through the first failed claim. Stopping at
the first critical error is necessary because later reasoning may
already depend on an erroneous premise, and continuing to inspect
subsequent claims can obscure the actual source of the error.

### 3.3 Correcting the Solution and Updating the Verification Plan

When $`r_{t}=0`$, AGPV enters feedback-based correction, involving
$`\mathcal{A}_{\mathrm{sum}}`$, $`\mathcal{A}_{\mathrm{fix}}`$,
$`\mathcal{A}_{\mathrm{upd}}`$, and an answer-equivalence controller.
The agents respectively summarize failure evidence into feedback,
correct the solution, and update the key-claim sequence and verification
plan when the answers are equivalent. Based on answer equivalence, the
controller directs $`\mathcal{A}_{\mathrm{gen}}`$ to regenerate the key
claims and verification plan for the next iteration or
$`\mathcal{A}_{\mathrm{upd}}`$ to update them.

First, $`\mathcal{A}_{\mathrm{sum}}`$ uses the current verification plan
$`V_{t}`$, the verification trace $`R_{t}`$, and the position $`k_{t}`$
of the first failed claim to summarize the failure evidence;
$`\mathcal{A}_{\mathrm{fix}}`$ then corrects $`y_{t}`$ using $`F_{t}`$:

```math
\displaystyle F_{t} \displaystyle=\mathcal{A}_{\mathrm{sum}}(q,y_{t},a_{t},V_{t},R_{t},k_{t}), \tag{5}
```

```math
\displaystyle y^{\prime}_{t} \displaystyle=\mathcal{A}_{\mathrm{fix}}(q,y_{t},a_{t},F_{t}). \tag{6}
```

Here, $`F_{t}`$ is natural-language feedback identifying the first
critical error, the relevant tool evidence in $`R_{t}`$, why the key
claim fails, and where correction should begin. Because the evidence is
read directly from $`R_{t}`$, no separate execution-record variable is
required. Here, $`y^{\prime}_{t}`$ is the corrected candidate solution,
and $`a^{\prime}_{t}`$ is its extracted answer. Guided by the error
location in $`F_{t}`$, $`\mathcal{A}_{\mathrm{fix}}`$ re-derives the
subsequent solution from the first critical error rather than
regenerating the entire solution. When recomputation, constraint
checking, or verification of a new derivation is required, it may invoke
$`\mathcal{A}_{\mathrm{tool}}`$ and use the returned result.

After correction, the answer-equivalence controller compares
$`a^{\prime}_{t}`$ and $`a_{t}`$, where $`I_{\mathrm{ans}}(x,y)=1`$
denotes equivalence and $`I_{\mathrm{ans}}(x,y)=0`$ non-equivalence. If
$`I_{\mathrm{ans}}(a^{\prime}_{t},a_{t})=0`$, the changed answer may
make $`C_{t}`$ and $`V_{t}`$ inapplicable. The system sets
$`y_{t+1}=y^{\prime}_{t}`$ and $`a_{t+1}=a^{\prime}_{t}`$, clears
$`C_{t},V_{t}`$, and invokes $`\mathcal{A}_{\mathrm{gen}}`$ in the next
iteration to regenerate $`C_{t+1},V_{t+1}`$ from $`q,y_{t+1},a_{t+1}`$.

If $`I_{\mathrm{ans}}(a^{\prime}_{t},a_{t})=1`$, the answers are
equivalent, but the revised solution may no longer align with
$`C_{t},V_{t}`$. Direct reuse risks inconsistency, whereas full
regeneration may discard the previous failure diagnosis. Therefore,
$`\mathcal{A}_{\mathrm{upd}}`$ updates the key-claim sequence and
verification plan using
$`y^{\prime}_{t},a^{\prime}_{t},C_{t},V_{t},R_{t},F_{t}`$. If $`V_{t}`$
contains missing or invalid tool tasks or conflicts with the corrected
solution, $`\mathcal{A}_{\mathrm{upd}}`$ may invoke
$`\mathcal{A}_{\mathrm{tool}}`$ before producing:

```math
\displaystyle(C_{t+1},V_{t+1}) \displaystyle=\mathcal{A}_{\mathrm{upd}}(q,y^{\prime}_{t},a^{\prime}_{t},C_{t},V_{t},R_{t},F_{t}). \tag{7}
```

The implementation compares extracted answer strings; differently
formatted but mathematically equivalent answers may therefore trigger
regeneration rather than adaptation. In both branches,
$`y_{t+1}=y^{\prime}_{t}`$ and $`a_{t+1}=a^{\prime}_{t}`$, so, if
another iteration remains, it verifies the corrected solution. When the
iteration limit is reached, AGPV returns the latest corrected candidate
without further verification. In the equivalent-answer branch,
$`\mathcal{A}_{\mathrm{upd}}`$ uses the evidence in $`R_{t}`$ and the
diagnosis in $`F_{t}`$ to update $`C_{t+1}`$ and $`V_{t+1}`$, keeping
them consistent with $`y^{\prime}_{t}`$.

##### Working-Context Compression and Tool-Result Reuse.

The implementation maintains a working context for continued
verification and correction. When it reaches the configured token
threshold, a compression agent summarizes older working content while
retaining the fixed instructions and recent interaction context. The
compression prompt requests preservation of key computations, tool
evidence, failed approaches, and unfinished checks; the full execution
records remain available separately. Before feedback summarization and
verification-plan updates, long execution traces can likewise be
replaced by compact working summaries. For repeated mathematical-tool
requests within the same problem, the executor reuses an earlier
successful, nonempty result for the same request text (after trimming
surrounding whitespace), avoiding repeated code generation and Python
execution. Failed or empty results are not cached, and the cache is not
shared across problems. These mechanisms support the verification
workflow; their individual effects are not isolated by the experiments
reported here.

##### Conditional Reliability.

The result assumes sufficient coverage of the correctness and
completeness requirements and reliable verification of each claim
against the problem conditions and previously accepted claims.
Intuitively, the argument follows mathematical induction over the
ordered claims. The first claim follows from the problem conditions. If
the first $`i-1`$ claims have been established, reliable local
verification shows that the $`i`$-th claim also follows from the problem
conditions and those preceding claims. Repeating this step establishes
all claims, and sufficient coverage then implies final-answer
correctness and completeness. Let $`P_{q}`$ denote the problem
conditions and $`C_{t}=(c_{t,1},\ldots,c_{t,n_{\scriptstyle t}})`$ the
ordered key-claim sequence. Suppose all key claims pass reliable local
verification; that is, for every $`i\in\{1,\ldots,n_{t}\}`$,

```math
P_{q}\land\bigwedge_{j=1}^{i-1}c_{t,j}\models c_{t,i}, \tag{8}
```

where $`\models`$ denotes semantic entailment. For $`i=1`$, Eq. (8)
yields $`P_{q}\models c_{t,1}`$; induction over the ordered claims then
gives

```math
P_{q}\models\bigwedge_{i=1}^{n_{\scriptstyle t}}c_{t,i}. \tag{9}
```

Further suppose the problem objective contains completeness requirements
$`h_{1},\ldots,h_{m}`$, and every $`h_{\ell}`$ is semantically entailed
by some key claim $`c_{t,j(\ell)}`$. Equation (9) and transitivity then
yield

```math
P_{q}\models\bigwedge_{\ell=1}^{m}h_{\ell}. \tag{10}
```

Thus, if the key claims sufficiently cover final-answer correctness and
completeness and local verification is reliable, a single
process-verification chain supports all these requirements. Complete
definitions and proofs are provided in Appendix B.1.

## 4 Experiments

Our experiments address three questions: (1) whether AGPV improves
final-answer accuracy; (2) whether its gains primarily arise from
correcting initially incorrect answers rather than from indiscriminate
rewriting; and (3) whether its performance remains stable across
backbone models and settings with different initial capabilities.

### 4.1 Experimental Setup

##### Datasets

We evaluate the methods on five hard-test mathematical reasoning
datasets comprising 170 problems: AIME 2024, AIME 2025, BRUMO 2025, and
HMMT February 2025 from MathArena (Balunovic et al., 2025), together
with AMO Bench (Liu et al., 2026). These datasets cover algebra,
combinatorics, number theory, geometry, and integrated reasoning in
competition mathematics. Dataset sizes and basic characteristics are
provided in Table 6. Backbone Models. The experiments use
DeepSeek-V4.1-Flash and DeepSeek-V4-Pro (0813) (DeepSeek, 2026),
Qwen3.6-35B-A3B-FP8 (Qwen Team, 2026), and GPT-5.6-Luna (OpenAI, 2026).
Short model names follow the retained experiment records; the complete
mapping is given in Table 4.

##### Baselines

We compare AGPV with three representative classes of baselines. Initial
Score denotes the backbone model’s initial response without additional
correction. The first class comprises natural-language correction
methods: Reflex, which uses natural-language reflection;
Self-Refine (Madaan et al., 2023), which uses iterative self-feedback;
Self-Reflection, which uses reflective feedback; and CheckList (Cook
et al., 2024), which performs checklist-guided correction. The second
class is the reasoning-enhanced method CoT-Tool (Abedi Firouzjaei,
2025), which samples multiple chain-of-thought paths (Wei et al., 2022)
and selects an answer using Self-Consistency (Wang et al., 2023). The
third class comprises the verification-enhanced methods ProgCo (Song
et al., 2025) and ProgCo-Py. ProgCo uses program-driven verification and
correction, whereas ProgCo-Py enables Python-tool feedback based on the
public ProgCo implementation. AGPV instead performs process verification
along the key-claim sequence of the current solution and uses the first
critical error and tool evidence to guide subsequent correction.

##### Experimental Protocol

All self-correction methods use $`\texttt{max\_turn}=3`$ and follow
their respective stopping rules. This setting does not imply matched
model-call or token budgets. All self-correction methods start from the
same pregenerated responses. We analyze intermediate answers
retrospectively from these runs rather than from independent
$`\texttt{max\_turn}=1`$ experiments. Empty outputs or outputs without a
valid extractable answer are incorrect; when execution falls back to a
saved answer, that returned answer is evaluated. Accuracy always uses
the original fixed benchmark denominator. Implementation Parameters. The
generation temperature is set to $`0.0`$ for all methods. Following its
own mechanism, CoT-Tool independently generates three chain-of-thought
paths and determines its output by the majority among the extracted
answers; its budget is therefore not interpreted as correction turns.
Complete model identifiers, reasoning modes, method-level budgets,
tool-execution limits, and answer-judgment rules are provided in
Appendix C.1. Evaluation Metrics. Final-answer accuracy is our primary
metric. Each model’s overall score is computed over all 170 problems,
weighting datasets by their sample counts. Mean averages these four
model scores, equivalently pooling 680 model–problem instances, not 680
distinct questions. For correction analysis, $`C`$ and $`W`$ denote
correct and incorrect answers. Thus, $`W\rightarrow C`$ denotes an
initially incorrect answer becoming correct and $`C\rightarrow W`$
denotes an initially correct answer becoming incorrect. We additionally
report the average number of recorded states as a description of the
saved processes, not a measure of total inference cost.

### 4.2 Main Results

AGPV leads all evaluated baselines under each of the four models
(Table 1). Mean accuracy reaches $`63.8\%`$, exceeding Self-Refine, the
strongest evaluated baseline, by $`13.5`$ percentage points. Gains span
models with different initial capabilities, indicating that the benefit
is not restricted to one backbone. Additional robustness analyses are
provided in Appendix C.3.

Per-Dataset Results. Tables 7 and 8 retain the complete breakdown over
the five datasets. Overall improvements are consistent across the four
models, although AGPV does not lead every individual dataset. We next
examine the sources and distribution of these gains.

To examine whether AGPV’s gains concentrate in particular difficulty
ranges, we estimate empirical difficulty from initial-answer correctness
across multiple backbone-model settings. Specifically, a problem is
considered empirically more difficult when fewer of the four models
answer it correctly at initialization. We label problems solved
initially by all four models as Easy, by three models as Medium, by two
models as Hard, and by zero or one model as Very hard. These groups
contain 30, 26, 32, and 82 distinct problems, respectively.

Fig. 4 compares Self-Refine, ProgCo-Py, and AGPV across these groups.
Relative gain is defined as
$`(\mathrm{Acc}_{\mathrm{Final}}-\mathrm{Acc}_{\mathrm{Initial}})/\mathrm{Acc}_{\mathrm{Initial}}`$.
Because low initial accuracy magnifies this ratio, the figure also shows
Initial Acc.

AGPV exceeds both baselines on Medium, Hard, and Very hard problems,
with an absolute gain of $`28.0`$ percentage points over Initial in the
Very hard group. Its advantage therefore concentrates in problems that
the initial models solve less reliably. Easy problems exhibit a small
regression under AGPV, while both baselines preserve their initial
accuracy.

### 4.5 Effect of Iteration Turns

AGPV verifies and corrects the current solution through feedback. To
examine how accuracy changes during this process, Fig. 5 compares AGPV
with ProgCo, ProgCo-Py, and Self-Refine across all four models. We
reconstruct stopping-point answers for limits of one and three turns
using each method’s stopping rule, retaining an earlier terminal answer
after stopping. Missing intermediate scores are completed with the same
answer-evaluation procedure, without regenerating responses; unavailable
intermediate answers use the recorded fallback. Reconstructed
stopping-point accuracies are provided in Table 17.

Across all four models, AGPV exceeds the best of the three baselines at
both reported post-initial checkpoints, not only their mean. Most gains
are already present at the first reported stopping point, with further
improvements by the final point. Table 10 describes recorded-state
counts; neither these counts nor saved checkpoints imply equal
computation budgets. Appendix C.5 reports the observed reduction in
request-context length when compression is triggered, rather than an
overall token-efficiency comparison.

## 5 Conclusion

AGPV verifies ordered key claims, locates the first failed claim, and
uses failure evidence to revise subsequent reasoning and update the
verification plan. Embedding completeness requirements in these claims
unifies correctness and completeness checks; both are conditionally
guaranteed with sufficient claim coverage, reliable local verification,
and all claims passing. Experiments demonstrate improved
mathematical-reasoning accuracy, error correction, and repair coverage.
Future work will extend process verification to other domains with
traceable intermediate processes, including code generation, scientific
reasoning, and data analysis, using domain knowledge and specialized
tools to construct well-scoped claims verifiable with reliable evidence.

## Appendix B Theoretical Supplement

### B.1 Conditional Reliability Proof for Process Verification

To formalize how completeness is embedded in process verification, we
denote the completeness requirements in the problem objective by

```math
\mathcal{H}(q,y_{t})=\{h_{1},h_{2},\ldots,h_{m}\}, \tag{11}
```

Here, $`\mathcal{H}(q,y_{t})`$ is the set of completeness requirements
induced by the problem objective and instantiated under the current
solution $`y_{t}`$; $`\ell\in\{1,\ldots,m\}`$ indexes these
requirements, and $`m`$ is their total number. Each $`h_{\ell}`$ denotes
a completeness property or proposition required by the problem objective
rather than the target object itself. For example, $`h_{\ell}`$ may
state that “the target object given by the current solution equals the
complete target object implied by the problem conditions.” The key-claim
sequence $`C_{t}`$ covers these completeness requirements if, for every
$`h_{\ell}\in\mathcal{H}(q,y_{t})`$, there exists a key claim
$`c_{t,j(\ell)}`$, where $`j(\ell)\in\{1,\ldots,n_{t}\}`$ is the
position of the key claim covering the $`\ell`$-th completeness
requirement, such that the claim semantically entails the corresponding
requirement:

```math
c_{t,j(\ell)}\models h_{\ell}. \tag{12}
```

Here, $`\models`$ denotes semantic entailment, and
$`c_{t,j(\ell)}\models h_{\ell}`$ states that the $`j(\ell)`$-th key
claim semantically entails the corresponding completeness requirement.
This definition embeds completeness into the process-verification chain
when the key-claim sequence is constructed.

![](arxiv-2611-19122v1--ab172117d467.figures/inline-1.svg)

##### Conditional-Reliability Intuition

AGPV’s process verification admits an idealized conditional-reliability
interpretation. To simplify notation, we omit the turn subscript $`t`$
below and denote the current solution by $`y`$. Let $`P_{q}`$ be the
problem conditions and let the key-claim sequence be

```math
C=(c_{1},c_{2},\ldots,c_{n}). \tag{17}
```

where $`n`$ is the total number of key claims after omitting the turn
subscript. For $`i\in\{1,\ldots,n\}`$, define the verified context
preceding the $`i`$-th claim as

```math
\Gamma_{i-1}=P_{q}\land c_{1}\land c_{2}\land\cdots\land c_{i-1}, \tag{18}
```

where $`\Gamma_{0}=P_{q}`$. Ideally, if the verifier is reliable, then
whenever the $`i`$-th key claim passes verification,

```math
\Gamma_{i-1}\models c_{i}. \tag{19}
```

Here, $`\models`$ denotes semantic entailment. The relation
$`\Gamma_{i-1}\models c_{i}`$ means that the current key claim $`c_{i}`$
holds in every interpretation satisfying the problem conditions and the
preceding verified claims. Thus, the $`i`$-th key claim follows from the
problem conditions and the preceding verified claims.

##### Proposition 1: Conditional Reliability of Process Verification

Let $`P_{q}`$ be the problem conditions and let
$`C=(c_{1},\ldots,c_{n})`$ be the ordered key-claim sequence constructed
by AGPV from the current solution and the problem objective. Suppose
that all key claims pass verification and that the verifier is reliable;
that is, for every $`i`$,

```math
P_{q}\land c_{1}\land\cdots\land c_{i-1}\models c_{i}, \tag{20}
```

where the set of preceding claims is empty when $`i=1`$. Then

```math
P_{q}\models c_{1}\land c_{2}\land\cdots\land c_{n}. \tag{21}
```

##### Proof

We proceed by induction on $`i`$.

Base case: when $`i=1`$, verifier reliability gives

```math
P_{q}\models c_{1}. \tag{22}
```

Therefore, the proposition holds for $`i=1`$.

Induction hypothesis: suppose that, for some $`i-1\geq 1`$,

```math
P_{q}\models c_{1}\land c_{2}\land\cdots\land c_{i-1}. \tag{23}
```

That is, the first $`i-1`$ key claims are all supported by the problem
conditions $`P_{q}`$.

Inductive step: because the $`i`$-th key claim passes verification and
the verifier is reliable,

```math
P_{q}\land c_{1}\land\cdots\land c_{i-1}\models c_{i}. \tag{24}
```

From the induction hypothesis and $`P_{q}\models P_{q}`$, conjunction
introduction gives $`P_{q}\models\Gamma_{i-1}`$. Because
$`\Gamma_{i-1}\models c_{i}`$, transitivity of semantic entailment
yields $`P_{q}\models c_{i}`$. Applying conjunction introduction again
to this conclusion and the induction hypothesis gives

```math
P_{q}\models c_{1}\land\cdots\land c_{i}. \tag{25}
```

Mathematical induction therefore establishes Eq. (21). This completes
the proof.

##### Corollary 1: Completeness Is Covered by the Same Process-Verification Chain

Suppose the construction of the key-claim sequence $`C`$ covers the
completeness requirements $`\mathcal{H}(q,y)=\{h_{1},\ldots,h_{m}\}`$
associated with the current solution; that is, for every
$`h_{\ell}\in\mathcal{H}(q,y)`$, there exists a key claim
$`c_{j(\ell)}`$ such that

```math
c_{j(\ell)}\models h_{\ell}, \tag{26}
```

Then, under the conditions of Proposition 1,

```math
P_{q}\models h_{1}\land h_{2}\land\cdots\land h_{m}. \tag{27}
```

##### Proof

Proposition 1 gives $`P_{q}\models c_{1}\land\cdots\land c_{n}`$, and
hence $`P_{q}\models c_{j(\ell)}`$ for every $`j(\ell)`$. Combining this
result with Eq. (26), transitivity of semantic entailment yields
$`P_{q}\models h_{\ell}`$. This conclusion holds for every
$`h_{\ell}\in\mathcal{H}(q,y)`$; conjunction introduction then gives
Eq. (27). This completes the proof.

The proposition and corollary clarify the meaning of embedded
completeness in AGPV. When a problem requires all solutions, complete
counting, exhaustive enumeration, or a global optimum, these
completeness requirements enter the same process-verification chain
through the construction of the key-claim sequence. If the key claims
provide complete coverage and the corresponding verification is
reliable, the completeness conclusions are also supported by the problem
conditions.

This conditional-reliability intuition is consistent with soundness
theorems in formal logic: if a conclusion follows from a set of premises
through sound inference rules, then the conclusion is a semantic
consequence of those premises. Soundness proofs for natural deduction
commonly proceed by induction over derivations (Open Logic Project,
n.d.). The same idea is also related to Floyd–Hoare-style program
verification, in which intermediate assertions organize local checks and
composition rules support global properties (Floyd, 1967; Hoare, 1969;
Pierce et al., n.d.).

AGPV is not a formal proof checker. The proposition and corollary
characterize how process verification can embed completeness
requirements under the ideal conditions that the key claims provide
complete coverage, their order matches the original reasoning process,
and local verification is reliable. Under these conditions, the first
key claim that fails verification corresponds to the first critical
error in the current solution. In practice, performance may still be
affected by incomplete key-claim extraction, completeness requirements
omitted from the key-claim sequence, incorrectly constructed
verification targets, or tool-execution failures.

##### AGPV Tool Execution and Runtime Stability

AGPV’s verification, correction, and verification-plan update agents can
invoke the shared mathematical toolbox dynamically. The backends support
symbolic simplification, equation solving, enumeration, constraint
checking, and exact or numerical computation. The four retained AGPV
runs set a language-model-call timeout of 960 seconds and a Python
execution timeout of 120 seconds; ordinary and stopping-decision calls
have retry limits of 10 and 20, respectively. A soft warning and hard
stop are configured at 100 and 120 generated Python snippets per sample.
The working-context compression trigger is 131,072 tokens, subject to
the runtime’s model-capacity checks. Successful nonempty results are
cached by problem identifier and trimmed tool-request text; cache hits
return the previous evidence instead of generating and executing Python
again. These are implementation settings, not an ablation or a measured
token-saving result. Failed executions and their returned fallback
answers remain in the fixed-denominator evaluation.

##### Unified Answer Evaluation

All methods use the same three-stage answer-evaluation pipeline:
normalized exact matching, directly decidable numerical comparison, and
a model-based equivalence judgment when needed. Parsed numerical answers
are considered equivalent when their absolute error is below
$`10^{-3}`$. Expressions, sets, and other unresolved answer forms are
judged with the shared DeepSeek-Flash fallback at temperature $`0.0`$.
Set-valued answers must contain all required elements, and order is
checked when the problem requires an ordered answer. Empty or
unextractable answers are incorrect. If execution returns an earlier
saved answer after a failure, we score that actual returned answer; no
sample is removed. The fixed denominators are 30 each for AIME 2024,
AIME 2025, BRUMO 2025, and HMMT February 2025, and 50 for AMO Bench,
totaling 170 distinct problems per model.

residues. AGPV found the 10 missing ones, and its final list of 16
matched the reference answer. Qwen 35B’s original answer listed 7
residues. In the first round, AGPV enumerated $`n=1`$ to $`50`$ in
Python and added the missing residues 14, 20, 24, and 30. In the second
round, the verifier enumerated the same range. The 11 residues it found
matched the revised answer, which passed verification. Yet $`n=51`$
already gives 28, which was missing from the answer. Verification
correctly computed the residues within the chosen range but did not
establish that the range covered every possible residue. Compared with
the reference answer, AGPV still missed 8, 10, 18, 22, and 28.

Using a counterexample to locate an error in an upper bound

Another AMO Bench problem gives $`2025`$ real numbers
$`x_{1},\ldots,x_{2025}`$ in $`[0,1]`$ and asks for a function $`f`$
such that $`\sum_{k}f(x_{k})`$ estimates $`(\sum_{k}x_{k})^{2}`$ with
the smallest possible worst-case absolute error. After the first
correction, DeepSeek Flash’s solution still claimed that its function
had an error of at most 1,025,156. On rechecking, AGPV found that
setting every $`x_{k}`$ to 1 gives an error of 2,049,300, exceeding the
claimed bound. The corrector redid the derivation and obtained the
correct answer, 512,578, which passed the final check.

Rechecking affected branches when the final answer stays the same

An AIME 2024 problem asks for the smallest positive integer $`m`$ for
which $`17^{2}=289`$ divides $`m^{4}+1`$, once the prime has been
identified as 17. The original solution considered the four possible
residues of $`m`$ modulo 17 separately and obtained $`110,138,151,179`$.
AGPV found that 138 and 151 failed the divisibility condition and
replaced them with 155 and 134, respectively. The minimum remained 110.
In the next round, the verifier rechecked each of the four branches
under the updated plan. It enumerated one full period modulo 289 in
Python and confirmed all four values.
