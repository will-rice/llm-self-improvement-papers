###### Abstract

The memory of production agents is increasingly becoming a bottleneck
and is built almost exclusively from text: key points are extracted from
out-of-limit context and retrieved into context at query time.
Therefore, every new query incurs an additional cost that grows with the
accumulated history. Weight memory is a complementary alternative that
internalizes knowledge into model parameters and answers with no context
at all, and has recently proven effective in self-evolving agents for
internalizing skills and behaviors. However, its application in episodic
and semantic memory, such as user-specific facts, remains comparatively
unexplored, and a gap remains between earlier attempts at weight memory
and text-based systems regarding recall performance. We study how to
make weight memory competitive as a long-term factual store by applying
on-policy self-distillation (OPSD). It trains a context-free student
from a teacher, which is the same model conditioned on the user’s
memory, together with a verify-then-regenerate router that lets weight
and text memory each cover the queries they handle best. On the HaluMem
benchmark, OPSD matches or surpasses strong text-memory baselines,
including full-context prompting and retrieval systems, while reading
fewer tokens per query. We further conduct an extensive study that
characterizes the behavior of weight memory and analyzes how different
training recipes affect its performance. As agent harnesses move toward
persistent, multi-session deployments, these results position weight
memory as a practical, low-cost component of agent memory and provide
insights into feasible training and evaluation protocols for combining
it with retrieval.

## 1 Introduction

Persistent agents need to recall project conventions, user preferences,
and earlier interactions across sessions. Many memory systems store this
information as text, then retrieve relevant entries into the prompt
([Packer et al., 2023](#bib.bib8); [Gutiérrez et al., 2025](#bib.bib10);
[Xu et al., 2026b](#bib.bib9); [Li et al., 2025](#bib.bib11)). This
design makes stored evidence inspectable but introduces retrieval and
context-processing costs and depends on retrieving the relevant facts.

Storing memory in weights provides an alternative. If user history is
internalized into parameters, the following queries can be answered
without retrieval or context, so the marginal cost of a query stops
depending on how long the dialogue is, and the cost is a training pass
whenever memory is written. Early attempts to use weights as memory,
however, underperform once the model is deprived of context at inference
and are studied mostly for verbatim recall ([Back et al.,
2026](#bib.bib23); [Xu et al., 2026c](#bib.bib1)). Recent self-evolving
agents revive the idea more successfully, showing that on-policy
distillation can internalize procedural skill into weights ([Zhang et
al., 2026a](#bib.bib6); [Feng et al., 2026c](#bib.bib7)). But none of
this work isolates the memory itself from the harness, and the case that
matters most for personalization is left open: the episodic and semantic
memories built from timestamped sessions can arrive incrementally,
update, or even sometimes contradict each other. The nearest evidence is
a diagnostic of substrate asymmetry ([Deng, 2026](#bib.bib5)), which
compares a per-user adapter against retrieval and concludes that neither
dominates and the two are complementary — leaving unanswered how far a
parametric memory can actually be pushed on episodic and semantic recall
and what it would take.

We address that question directly and apply on-policy self-distillation
(OPSD): a per-user Low-Rank Adaptation (LoRA), referred to as the
student, which is trained to reproduce, with no context at inference,
the answers that the same model provides with context in the prompt,
referred to as the teacher. The distillation takes place on the
student’s own distribution, so the objective matches the deployment
condition. OPSD makes weight memory outperform every text baseline we
test, but it requires extra training costs and inherits two limits
intrinsic to its parameters: it forgets older facts along with new
updates, and it cannot tell whether a fact was never recorded, so it
confabulates instead of abstaining. Because weight and text memory fail
on different questions, we then ask whether they can combine. We adopt
verify-then-regenerate (VtR): the parametric memory answers first; those
answers are audited against the text store, and only conflicted answers
are regenerated with the retrieved evidence, auditing the produced
answer rather than judging from the query.

These claims rest on a broad experimental study on benchmarks for
long-term memory such as HaluMem [Chen et al. (2025)](#bib.bib3) and
LoCoMo [Maharana et al. (2024)](#bib.bib2), and four findings stand out.
First, OPSD reaches an overall QA accuracy of $`59.9\%`$, while ordinary
Supervised Fine-Tuning (SFT) on identical data reaches $`36.9\%`$, which
is below every text baseline; the accuracy holds across model variant
scales. Second, the three memory paradigms differ less in accuracy than
in how they degrade with question age: context truncates, weights forget
gradually, retrieval barely notices, and within weight memory, the
learned habit of declining survives while the content it protected
decays. Third, the one deficit training does not fix is inspecting
absence, which can be traced to a single training-side lever. The
model’s willingness to decline is attributable entirely to the ratio of
refusal samples included in the training set. Fourth, VtR adds $`6.2`$
points over OPSD and improves five of six question categories, whereas
every other query-side routing signal we tried, including similarity,
learned query features, model consistency, and answer confidence, can
hardly predict whether the answer of weight-based memory is correct.
Extensive analysis is conducted on these observations.

We summarize our contributions as follows.

- •
  An evaluation of OPSD for recent user-memory recall. On the question
  set for eight HaluMem-Long users, OPSD reaches $`59.9\%`$, compared
  with $`47.8\%`$ for MemOS-style retrieval, $`51.9\%`$ for extracted
  context, and $`51.3\%`$ for raw dialogue. The advantage over retrieval
  is positive for all eight users, and the comparison with extracted
  context and retrieval holds at 4B, 9B, and 27B.
- •
  A characterization of retention and training effects. Repeated
  questions distinguish context truncation, gradual forgetting in
  weights, and more stable retrieval. Our ablations identify
  training-objective and refusal-supervision effects within the tested
  recipes, while cost accounting separates query token usage from
  unmeasured deployment costs.
- •
  A routing study and VtR integration. Query-side and confidence signals
  provide limited correctness information in our probes. Answer
  verification with text-based regeneration adds $`6.2`$ points over
  OPSD on native HaluMem questions, improving five of six categories
  while reducing memory-conflict accuracy.

## 2 Related Work

#### Text memory systems.

Text memory in deployed agents follows a typical loop: key points are
extracted from the dialogue as natural-language statements, written to
external storage, then retrieved by relevance when a new query arrives
and injected into the prompt. Within that shared skeleton, systems
differ mainly in how they organize and consolidate. [Xu et al.
(2026b)](#bib.bib9) maintain atomic notes with evolving cross-links,
[Gutiérrez et al. (2025)](#bib.bib10) build a knowledge graph, and [Feng
et al. (2026b)](#bib.bib15) store distilled reasoning rather than raw
text. A further line evolves the memory online from feedback ([Zhang et
al., 2026c](#bib.bib12); [Zhang et al., 2026b](#bib.bib13); [Rhodes and
Kang, 2026](#bib.bib14)). [Li et al. (2025)](#bib.bib11) generalize the
picture into an operating-system abstraction spanning plaintext,
activation, and parameter memory. However, these text-based systems
inherit the same costs. Every query incurs retrieval latency and context
tokens, and because the store grows while the window does not, retrieval
quality eventually becomes the binding constraint on accuracy. Surveys
of the area reach the same conclusion from the opposite direction,
finding that consolidation, updating , and forgetting remain far less
developed than retrieval ([Du et al., 2025](#bib.bib25); [Hu et al.,
2026](#bib.bib26)), and that a longer context window is not a substitute
for a memory system ([Du, 2026](#bib.bib24)). We take [Li et al.
(2025)](#bib.bib11) as our primary text-based system baseline.

#### Weight memory systems.

The alternative writes new information directly into the model
parameters. Editing methods localize a fact and overwrite the
responsible feed-forward weights ([Meng et al., 2022](#bib.bib16)),
which is precise but degrades after thousands of edits. Others attach
side feed-forward modules to a frozen backbone ([Lu et al.,
2026](#bib.bib18)) or update fast weights during inference ([Feng et
al., 2026a](#bib.bib19)), while [Behrouz et al. (2026)](#bib.bib20)
learns a memory module updated by surprise-gated descent with an
explicit forgetting gate. Empirical analyzes of LoRA as a memory store
([Back et al., 2026](#bib.bib23); [Xu et al., 2026c](#bib.bib1)) report
that adapter capacity scales with rank while efficiency peaks at low
rank, and that question-answer formatted synthetic data substantially
improves memorization, which is consistent with our own findings.
Closest to our setting are methods using distillation: [Hübotter et al.
(2026)](#bib.bib21) compress in-context feedback into parameters through
KL minimization, and the same idea appears in recent self-evolving agent
work. [Zhang et al. (2026a)](#bib.bib6) distills a hindsight-conditioned
teacher into a context-free student to internalize skills, and [Feng et
al. (2026c)](#bib.bib7) uses self-distillation to calibrate search
behavior. Our training method belongs to this family, and what
distinguishes it is the object rather than the optimizer: the teacher’s
privilege is a recency-bounded window of the user’s accumulated memory,
the student is context-free at evaluation, and the target is a specific
user’s episodic and semantic memory rather than a skill or a search
policy.

#### Routing between memory systems.

Routing is the natural response to the observation that not a single
memory system can win all behavioral consistency, fact recall, and
absence calibration at the same time([Deng, 2026](#bib.bib5)). Existing
routers on memories are mostly built within the same type, either
text-based or parametric: [Wang et al. (2024)](#bib.bib17) route a query
between frozen and edited parametric memory by activation distance;
[Back et al. (2026)](#bib.bib23) routes among multiple learned adapters
through similarity; [Xu et al. (2026a)](#bib.bib4) arbitrates the
model’s closed-book answer against a retrieved one by likelihood margin.
We tested various signals for routing and finally designed a
verify-then-regenerate mechanism for routing between two memory systems,
making the memory reader closer in spirit to the write-time verification
gate of [Rhodes and Kang (2026)](#bib.bib14).

## 3 Method

To make weight memory competitive, we train it using OPSD ([Zhao et al.,
2026](#bib.bib22)): when a memory write is triggered, we convert the new
dialogue contents into a question-answer training set and distill a
context-free student from a teacher that uses the same model but can see
the context window. To combine the two memory systems where each is
strong, we then add a VtR reader that acts as a router: it fact-checks
the weight memory’s answer against the text store, judges whether the
store supports it, and regenerates from retrieved context only when it
does not.

### 3.1 Data preparation

We call one assistant response a _turn_, and a _session_ a sequence of
turns spanning one period of interaction. A user’s history is then a
sequence of sessions $`S_{1},\dots,S_{T}`$, and the evaluation is
conducted after each complete session through question answering, so
memory is written once per session and read after every session.

Both memory systems we study consume the same intermediate
representation for adding a session into memory: a base language model
reads each session’s dialog and extracts its key memory points, each
written as one narrative sentence carrying its timestamp. A text memory
system stores and retrieves those sentences directly; we instead convert
them into training supervision, using the same base model for the
augmentation that produced the extraction. How that supervision is
shaped matters more than how much of it there is. Continued pretraining
on memory points or dialogue as raw text transfers poorly to question
answering; what works is generating question-answer pairs in the same
prompt template used at evaluation, and training with the loss masked to
the answer. For each memory point we then generate three kinds of pair.
_Paraphrases_ ask for the same fact several ways, which is what later
lets the student generalize across phrasings rather than memorize one
surface form. _Counterfactuals_ state the fact wrongly and require a
correction, which teaches the corrective form that questions carrying a
false premise demand. _Unknowns_ ask about attributes the session never
recorded and require an explicit refusal; these turn out to be the
entire source of the model’s willingness to decline, and removing them
is catastrophic in a way
§[4.3](#S4.SS3 "4.3 Characterizing weight memory as long-term memory ‣ 4 Experiments ‣ Route to Remember: Adaptive Memory Selection for LLM Agents")
quantifies.

### 3.2 On-policy self-distillation of memory

We train a per-user LoRA adapter to answer without context, using the
same base model conditioned on the context window as the teacher.
Denoting $`\pi_{\theta}`$ for the student and $`\pi_{\mathrm{base}}`$
for the base model, the teacher is
$`\pi_{\mathrm{base}}(\cdot\mid q,M_{t})`$ and the student is
$`\pi_{\theta}(\cdot\mid q)`$ with no memory in the prompt. Here
$`M_{t}`$ is not the entire accumulated memory, which eventually exceeds
any context budget, but a recency-bounded window over it: the current
session’s memory points, always kept, plus as many of the most recent
prior sessions as fit a fixed budget, usually the context limit of the
model. The student, being a persistent adapter, keeps evolving across
sessions, so it can retain facts that no individual teacher context
still contained, a point we return to when we ask why the student can
outperform its teacher
(§[4.2](#S4.SS2 "4.2 OPSD-based weight memory outperforms text memory ‣ 4 Experiments ‣ Route to Remember: Adaptive Memory Selection for LLM Agents")).
Training proceeds on-policy: for a question $`q`$ drawn from the pool,
the student samples its own answer $`y\sim\pi_{\theta}(\cdot\mid q)`$,
the teacher scores exactly those tokens, and we minimize the divergence
between them on the sampled trajectory,

| --- | --- | --- | --- |
|     |

````math
\mathcal{L}(\theta)\;=\;\mathbb{E}_{q}\,\mathbb{E}_{y\sim\pi_{\theta}(\cdot\mid q)}\sum_{i}\mathrm{KL}\!\left(\pi_{\mathrm{base}}(\cdot\mid q,M_{t},y_{<i})\,\middle\|\,\pi_{\theta}(\cdot\mid q,y_{<i})\right).
``` |  | (1) |

Sampling from the student rather than the teacher is what keeps the
objective on-policy, and it matters for both a mundane reason and a
theoretical one: an off-policy variant, like supervised learning over
the teacher’s answers, suffers from exposure bias and degenerates into
repetition loops, scoring well below the on-policy version.

Two design choices proved decisive for training robustness. The first is
that the teacher should not be replaced by the student: Using the
accumulating student snapshot from the previous session as a teacher,
the natural self-distillation choice lets errors compound across
sessions, and the forgetting curve collapses late in the horizon. The
second is that the question pool should stay fixed or grow only within a
reasonable range. Expanding it with an adversarially trained questioner
helps in a single-session probe but hurts across many sessions, where
the generated questions can drift onto unrelated topics and dilute the
native facts the model needs to retain. Since memory is written once per
session and read many times, we keep the adapter persistent across
sessions, so each session’s training accumulates on top of all previous
ones. Adding a regularization term may be a solution for both problems,
however it can introduce extra costs to tune the hyperparameter.

### 3.3 Verify-then-regenerate as the router

Weight memory answers fluently whether or not it knows, and its one
systematic blind spot, absence, is exactly what a text store makes
visible. That asymmetry suggests auditing the weight memory’s answer
rather than choosing between the two systems in advance based on the
query, and
§[4.4](#S4.SS4 "4.4 Route design ‣ 4 Experiments ‣ Route to Remember: Adaptive Memory Selection for LLM Agents")
shows why the alternative fails. Given the student’s answer $`\hat{y}`$
to question $`q`$ at session $`t`$, we retrieve from the text store
twice, once with $`q`$ as the query and once with $`\hat{y}`$, taking
the top $`k`$ of each. A verifier then judges $`\hat{y}`$ against the
answer-anchored evidence as supported, conflicting, or unsupported.
Because it only has to emit one of three labels, the verifier is a cheap
classifier rather than a second LLM agent. If the verdict is supported,
the weight memory’s answer stands. Otherwise, the base model, with no
adapter, re-answers from the union of both retrieved evidence sets, each
memory point annotated with a timestamp, under an instruction to reply
properly with the retrieved evidence.

Three details carry the result: (1) Where the evidence comes from
matters. We retrieve from the store managed by the text memory system,
not from the weight memory’s raw training data. This is what allows the
text-based memory system to handle updates, which a case weight memory
handles poorly on its own, because a later session’s training set can
overwrite an earlier fact, for example, a user’s changing physical
address. More specifically, in this experiment, we retrieve against a
*merged* store, in which superseded values have been integrated into the
previous related statements or totally replaced them; without merging, a
third of all verdicts come back as conflicts, while merging reduces that
to about one percent. (2) Retrieving with a generated answer is not the
same operation as retrieving with the question because it inserts a step
of semantic reasoning. Weight memory produces a plausible answer, which
maps the question into a region of the space where memory points
themselves live; matching against that region is a better-posed
retrieval problem than matching a question against statements that are
not phrased as questions, and it cuts retrieval noise accordingly. The
two keys are also deliberately kept distinct since verification and
regeneration need different evidence: the audit should see what was
actually claimed, while the regenerator should see what the question
makes answerable. The two sets overlap only partially, and the
answer-anchored half contributes evidence that the question alone does
not surface. (3) Only the base model is used for regeneration;
therefore, it is adapter-free by design. The fallback path is purely
text-based and thus cannot inherit the confabulations that the audit
aims to catch.

## 4 Experiments

### 4.1 Setup

#### Benchmarks.

HaluMem [Chen et al. (2025)](#bib.bib3) is our primary benchmark. It has
in total dialogue data of $`20`$ distinct users, each with
$`109`$–$`136`$ sessions and roughly a million tokens per use. We choose
it because it evaluates after every session rather than once after the
whole dialogue, and because its question taxonomy separates the
phenomena we care about: basic fact recall, memory conflict, dynamic
update, multi-hop inference, generalization and application, and memory
boundary. That last category is where the question is asking for
out-of-distribution facts, and the agent should refuse to answer. We
additionally tested our method over LoCoMo [Maharana et al.
(2024)](#bib.bib2), a multi-session dialogue benchmark, to check that
the result is not an artifact of HaluMem’s generation process; it has no
native notion of question age, so the retention protocol remains
HaluMem-only.

HaluMem originally asks each question only in the session that first
makes it answerable, and that native distribution is what all our
headline numbers report. To study retention, we add a supplementary
protocol that re-asks every question $`20,40,\dots,80`$ sessions later,
which we report the results per each age to trace each memory system’s
forgetting curve
(§[4.3](#S4.SS3 "4.3 Characterizing weight memory as long-term memory ‣ 4 Experiments ‣ Route to Remember: Adaptive Memory Selection for LLM Agents")).
We do not average the two, because the re-asks outnumber the native
questions roughly two to one and the memory systems decay at different
rates, so a pooled mean reflects the mixing ratio as much as the
systems.

#### Baselines.

Three text memory systems span the cost spectrum: MemOS-style retrieval
over a database with top-$`k`$ fetch, the full extracted memory in
context, and the raw dialogue truncated to the context limit. We use
MemOS because it is the strongest text memory system in HaluMem’s own
evaluation. Ground-truth memory points in context, provided by the
benchmark, serve as an oracle and is denoted as GT points. On the weight
side we compare against SFT on identical augmented data in the style of
[Back et al. (2026)](#bib.bib23), which isolates the contribution of the
distillation objective.

#### Protocol.

One language model performs every text operation in the pipeline,
including memory-point extraction, text-store management, training-data
preparation, and question answering, so differences between systems are
attributable to the memory rather than to the reader. We use Qwen3.5-9B
for the main comparison and repeat it at a smaller scale to check that
the effect is not scale-specific
(Appendix [A.2](#A1.SS2 "A.2 Model scale: the effect is not specific to Qwen3.5-9B ‣ Appendix A Additional results ‣ Route to Remember: Adaptive Memory Selection for LLM Agents")).
Claude Sonnet 4.6 serves as the judge, labelling each response correct,
hallucinated, or omitted, with no partial credit; we report Correct%
throughout, and the absence of partial credit is worth keeping in mind
for questions whose ground-truth answer is a terse label. We report
paired McNemar tests over matched questions, $`95\%`$ confidence
intervals from a bootstrap clustered on users, and per-user differences,
so that no claim rests on a single user’s behaviour. Full training and
retrieval hyperparameters are given in
Appendix [A.1](#A1.SS1 "A.1 Implementation details ‣ Appendix A Additional results ‣ Route to Remember: Adaptive Memory Selection for LLM Agents").

#### Weight memory is more accurate, and the recipe is what makes it so.

OPSD reaches $`59.9\%`$, above every text baseline, including the two
full-context systems that hold the entire history in the prompt
($`51.3\%`$ and $`51.9\%`$) and the MemOS retriever ($`47.8\%`$). The
margin over retrieval is $`12.1`$ points, with a user-clustered
confidence interval of $`[9.4,14.8]`$, positive for all eight users
individually, from $`7.1`$ to $`18.1`$ points; on matched questions,
OPSD is uniquely correct on $`309`$ questions against retrieval’s
$`136`$. We take the comparison against the full-context base model to
be the more informative one: even though the context is not shown, the
OPSD method still does better relying purely on its weights. The
advantage is broadly distributed — OPSD leads on five of six question
categories — and it holds across model size, leading every baseline at
4B and 27B
(Appendix [A.2](#A1.SS2 "A.2 Model scale: the effect is not specific to Qwen3.5-9B ‣ Appendix A Additional results ‣ Route to Remember: Adaptive Memory Selection for LLM Agents")).
It is, nonetheless, an accuracy that is concentrated on recent material
and blind to what was never recorded: weight memory forgets as facts age
and confabulates when asked for an attribute the user never gave, the
two failure modes we characterize in
§[4.3](#S4.SS3 "4.3 Characterizing weight memory as long-term memory ‣ 4 Experiments ‣ Route to Remember: Adaptive Memory Selection for LLM Agents").
The latter is exactly the memory boundary, the one category OPSD loses,
where the answer is an abstention, and a text system can simply observe
that its retrieved list contains nothing relevant
(§[4.3](#S4.SS3.SSS0.Px3 "Absence is not inspectable in weights. ‣ 4.3 Characterizing weight memory as long-term memory ‣ 4 Experiments ‣ Route to Remember: Adaptive Memory Selection for LLM Agents"));
this is also the only category propping up the otherwise weak text
baselines, and removing it widens OPSD’s overall margin over retrieval
from $`12.1`$ to $`18.0`$ points.

That this accuracy is a property of the training recipe rather than of
parametric storage is shown by the weakest row in
Table [1](#S4.T1 "Table 1 ‣ 4.2 OPSD-based weight memory outperforms text memory ‣ 4 Experiments ‣ Route to Remember: Adaptive Memory Selection for LLM Agents"):
supervised fine-tuning on the identical augmented data reaches only
$`36.9\%`$, below every text baseline, even though its stored
representation and training data match OPSD’s and only the objective
differs. Early results discouraging about weight memory were obtained
almost entirely with supervised fine-tuning ([Deng, 2026](#bib.bib5);
[Back et al., 2026](#bib.bib23)); our comparison indicates that
on-policy self-distillation, not SFT, is the appropriate objective for
internalizing episodic/semantic memory, and that the medium was never
the constraint those results attributed it to.
Appendix [A.5](#A1.SS5 "A.5 Training objective and anti-forgetting ‣ Appendix A Additional results ‣ Route to Remember: Adaptive Memory Selection for LLM Agents")
traces how the OPSD configuration was reached.

#### Weight memory is costly to write but cheap to query.

Table [2](#S4.T2 "Table 2 ‣ 4.2 OPSD-based weight memory outperforms text memory ‣ 4 Experiments ‣ Route to Remember: Adaptive Memory Selection for LLM Agents")
shows that the two families invert where their cost falls. A text system
writes for free but reads an entire context on every query, spending
$`1.7`$M to over a billion input tokens across the evaluation; weight
memory front-loads the cost into writing — extraction, QA augmentation,
and a distillation pass not billed in tokens — and then reads only the
query tokens, four orders of magnitude fewer than full context and a
factor of five below retrieval. Because writing is paid once per stored
memory while reading recurs, weight memory pays off precisely when the
same memory is queried many times: its natural use case is internalizing
a common fact or skill that thousands of users will each query, rather
than a single user’s transient history. The crossover is quantifiable
from
Table [2](#S4.T2 "Table 2 ‣ 4.2 OPSD-based weight memory outperforms text memory ‣ 4 Experiments ‣ Route to Remember: Adaptive Memory Selection for LLM Agents").
Against full context, OPSD’s roughly $`150`$M extra write tokens are
repaid after about $`600`$ queries per stored memory, since each query
saves about $`2.4\times 10^{5}`$ input tokens. Against retrieval the
break-even is far higher, on the order of $`10^{5}`$ queries, because
retrieval is already cheap to read (about $`310`$ input tokens saved per
query against a $`57`$M-token extra write): weight memory dominates full
context almost immediately but only overtakes retrieval on cost under
very heavy, highly shared query load. VtR keeps weight memory’s read
cost on the $`38\%`$ of queries the gate accepts and pays a
retrieval-plus-regeneration read on the rest, so its per-query cost sits
between OPSD and MemOS
(Table [2](#S4.T2 "Table 2 ‣ 4.2 OPSD-based weight memory outperforms text memory ‣ 4 Experiments ‣ Route to Remember: Adaptive Memory Selection for LLM Agents")).

#### Why the student can beat its teacher.

OPSD ($`59.9\%`$) also exceeds the teacher configuration it distils from
— the base model reading extracted memory in context ($`51.9\%`$). We
offer three possible explanations and leave further analysis for future
work: (i) *Consolidation:* training over many paraphrases of a fact
averages over the extraction noise that any single retrieved statement
carries, in the psychological sense of consolidation. (ii) *No
in-context search:* the student never has to locate its answer among
hundreds of distractor statements, which is where the full-context
memory systems visibly fail, their hallucination rate sitting at
$`33`$–$`34\%`$. (iii) *Persistence past the teacher’s window:* because
the teacher sees only a recency-bounded context while the adapter
persists, the student can retain facts that have since dropped out of
any single teacher window rather than re-finding them at query time.

Figure [2](#S4.F2 "Figure 2 ‣ Retention: content decays, habits do not. ‣ 4.3 Characterizing weight memory as long-term memory ‣ 4 Experiments ‣ Route to Remember: Adaptive Memory Selection for LLM Agents")
separates the three paradigms by failure modes. Context methods fall off
a cliff when the relevant session leaves the window, and the more
compressed the representation the later the cliff arrives: raw dialogue
collapses by age $`40`$, extracted memory holds until $`60`$. Weight
memory decays smoothly instead, from $`59.9`$ to $`32.4`$ by age $`80`$.
Retrieval is nearly flat, from $`47.8`$ to $`40.1`$, because a top-$`5`$
fetch is indifferent to how old a fact is. This is the precise scope
condition on
§[4.2](#S4.SS2 "4.2 OPSD-based weight memory outperforms text memory ‣ 4 Experiments ‣ Route to Remember: Adaptive Memory Selection for LLM Agents"):
weight memory’s advantage is concentrated on recent material, and
retrieval overtakes it beyond roughly twenty sessions. It also suggests
the write policy a deployed system should adopt, distilling recent
sessions into weights while leaving the tail to retrieval.

Within weight memory, forgetting is strikingly non-uniform. Between age
$`0`$ and age $`100`$ the memory-boundary category is flat, drifting
from $`81.7`$ to $`88.1`$, while every content category collapses. The
model does not forget that it should be careful; it forgets what it
knew, and keeps answering anyway.

#### Second benchmark: LoCoMo.

To check that the ranking is not an artifact of HaluMem’s generation
process, we port LoCoMo, a multi-session dialogue benchmark
independently constructed. LoCoMo asks all questions once after the full
conversation, so there is no notion of question age; we therefore pool
every session into a single memory and report end-of-conversation
accuracy per LoCoMo category (single-hop, temporal, multi-hop,
open-domain, and adversarial, the last being unanswerable-from-context
questions that should be refused).
Figure [2](#S4.F2 "Figure 2 ‣ Retention: content decays, habits do not. ‣ 4.3 Characterizing weight memory as long-term memory ‣ 4 Experiments ‣ Route to Remember: Adaptive Memory Selection for LLM Agents")
(right) shows overall accuracy; the full per-category breakdown is in
Table [15](#A1.T15 "Table 15 ‣ A.15 LoCoMo second benchmark: full per-category breakdown ‣ Appendix A Additional results ‣ Route to Remember: Adaptive Memory Selection for LLM Agents")
(appendix).

The HaluMem ranking reproduces. OPSD matches extracted text memory on
the content categories (single-hop $`70.2`$ vs $`69.3`$, temporal
$`61.3`$ vs $`61.7`$, multi-hop $`33.5`$ vs $`33.3`$) and edges it
overall ($`46.9`$ vs $`46.4`$), while both crush SFT ($`16.9`$); raw
full-context again loses on temporal questions ($`7.2`$), where a whole
conversation in the window obscures when each fact was held. The one
category where every paradigm fails is adversarial: pure weight and pure
text memory both sit near the floor ($`2.5`$–$`10.6`$), because neither
reliably refuses an unanswerable question. This is the same
absence-inspection failure as HaluMem’s memory-boundary category
(§[4.3](#S4.SS3.SSS0.Px3 "Absence is not inspectable in weights. ‣ 4.3 Characterizing weight memory as long-term memory ‣ 4 Experiments ‣ Route to Remember: Adaptive Memory Selection for LLM Agents")),
and it is exactly what the router repairs: verify-then-regenerate lifts
adversarial accuracy to $`73.1`$ and, without hurting the categories
weight memory already answers, takes the overall best at $`60.4`$, the
same $`+13`$–$`15`$pt hybrid gain we see on HaluMem, now on an
independent benchmark.

#### Absence is not inspectable in weights.

The one category where text memory beats weight memory is the one where
the correct answer is that nothing was recorded. The mechanism is not
knowledge but inspectability: a text system reads a retrieved list,
finds no such field, and reports its absence, whereas parameters offer
nothing to inspect and instead supply a plausible value. The inventions
are specific enough to be diagnostic, with concrete salaries and body
weights produced for attributes the dataset never contained,
inconsistently across ages for the same question. This is precisely the
confabulation [Deng (2026)](#bib.bib5) identify for single-turn
personalization, reproduced here in a multi-session setting. About a
fifth of the boundary “hallucination” verdicts are in fact valid
abstentions scored wrong while a near-identical text refusal was scored
correct, so the true fabrication rate is roughly $`80\%`$ of the stated
one; this is one instance of the rubric artifacts catalogued in
Appendix [A.11](#A1.SS11 "A.11 Weak categories are partly measuring the rubric ‣ Appendix A Additional results ‣ Route to Remember: Adaptive Memory Selection for LLM Agents").

#### What the training recipe contributes.

The recipe rather than the medium is what makes weight memory work, and
we ablate it along every axis we could vary; the full sweeps are in
Appendix [A](#A1 "Appendix A Additional results ‣ Route to Remember: Adaptive Memory Selection for LLM Agents")
and we summarize it here. (1) *Objective* is the dominant lever:
on-policy self-distillation ($`59.9\%`$) beats both supervised
fine-tuning on identical data
(Table [1](#S4.T1 "Table 1 ‣ 4.2 OPSD-based weight memory outperforms text memory ‣ 4 Experiments ‣ Route to Remember: Adaptive Memory Selection for LLM Agents"),
$`36.9\%`$) and an off-policy variant that teacher-forces the teacher’s
raw text rather than the student’s own samples, and full-parameter
fine-tuning does not improve on the LoRA adapter
(Appendix [A.5](#A1.SS5 "A.5 Training objective and anti-forgetting ‣ Appendix A Additional results ‣ Route to Remember: Adaptive Memory Selection for LLM Agents")).
(2) *Teacher construction* is next: decoupling the teacher from the
accumulating student to a frozen base model on capped cumulative memory
removes a late-session collapse and is worth roughly $`+14`$ points over
the horizon, while curriculum expansion of the training-QA pool, helpful
in a single session, reverses online and is dropped
(Appendix [A.5](#A1.SS5 "A.5 Training objective and anti-forgetting ‣ Appendix A Additional results ‣ Route to Remember: Adaptive Memory Selection for LLM Agents")).
(3) *Training data* matters more than capacity: unknown-answer
augmentation is solely responsible for the abstention ability. Removing
it collapses the memory boundary from $`88\%`$ to $`1\%`$ and costs
$`14`$–$`16`$ points overall, with hallucination rising to
$`60\%`$—while doubling the unknown/counterfactual budget or adding
composite-QA augmentation is at best neutral
(Appendix [A.4](#A1.SS4 "A.4 Augmentation ablations ‣ Appendix A Additional results ‣ Route to Remember: Adaptive Memory Selection for LLM Agents")).
(4) *Anti-forgetting* replay of cached answers helps the tail but
craters dynamic update, because re-supervising a stale answer re-teaches
a superseded value
(Appendix [A.5](#A1.SS5 "A.5 Training objective and anti-forgetting ‣ Appendix A Additional results ‣ Route to Remember: Adaptive Memory Selection for LLM Agents")).
(5) By contrast *capacity* is nearly inert: adapter rank is flat from
$`16`$ to $`128`$ (best at $`64`$, $`128`$ mildly overfitting) and
training length is non-monotonic
(Appendix [A.3](#A1.SS3 "A.3 LoRA rank sweep ‣ Appendix A Additional results ‣ Route to Remember: Adaptive Memory Selection for LLM Agents")).
Across all of these it is the objective and the training-QA set, not the
size of the store, that determine what weight memory can do.

### 4.4 Route design

Since the two memory systems fail on different questions, disagreeing on
$`445`$ of $`1438`$, an oracle choosing the better one per question
would reach $`69.3\%`$ against OPSD’s $`59.9\%`$. The natural way to
claim that prize is to inspect the query and decide which store to
trust, and we report four attempts, all negative, because together they
explain the design of
§[3.3](#S3.SS3 "3.3 Verify-then-regenerate as the router ‣ 3 Method ‣ Route to Remember: Adaptive Memory Selection for LLM Agents").

Query-memory similarity carries no signal at all: correct and incorrect
answers have indistinguishable top-$`1`$ similarity distributions
($`0.735`$ against $`0.741`$ for weight memory, $`0.737`$ against
$`0.737`$ for retrieval), so every threshold degenerates into always
choosing the better system. A classifier over query embeddings,
similarity features and cue tokens gains at most $`0.9`$ points, and raw
query embeddings actively hurt: whether the weights happen to have
memorized a fact is not legible in the question. Confidence in the
generated answer looks promising until it is deconfounded: per-token
confidence correlates at $`0.65`$ with answer length, and length
correlates with correctness with opposite signs across categories,
positively where the right answer is a verbose refusal and negatively
where a rambling answer signals a miss, so a single global probe hides
two opposing effects. Controlling for that with a length-constant probe,
which teacher-forces a fixed refusal string of identical token length
for every question, gives a genuinely clean detector, with an area under
the curve of $`0.918`$ for answerability and negligible correlation with
answer length. But it detects answerability rather than correctness:
against the event that the model is wrong, the same probe is at chance
($`0.516`$). Routing on it yields a single point, and under the
retention protocol it collapses entirely, sending essentially every
question to retrieval once the threshold drifts.

Figure 3: Left: $`p_{\mathrm{abs}}`$ has near-identical distributions
for correct vs. wrong age-$`0`$ OPSD answers (means
$`0.305`$/$`0.306`$), so no threshold separates them. Right: query-side
signals predict *correctness* at chance (red, AUC$`{\approx}0.5`$) but
$`p_{\mathrm{abs}}`$ predicts *answerability* at $`0.918`$ (blue):

The common thread
(Figure [3](#S4.F3 "Figure 3 ‣ 4.4 Route design ‣ 4 Experiments ‣ Route to Remember: Adaptive Memory Selection for LLM Agents"))
is that all four signals are functions of the question and the model’s
internal state, and none of them observes the answer that was actually
produced. Verification does, which is why VtR takes the form it does.

VtR reaches $`66.1\%`$, an improvement of $`6.2`$ points over OPSD
($`p=2\times 10^{-6}`$, user-clustered interval $`[3.6,8.6]`$) and
$`18.2`$ over the best text baseline, and unlike any of the selection
mechanisms above it improves at every question age
(Figure [2](#S4.F2 "Figure 2 ‣ Retention: content decays, habits do not. ‣ 4.3 Characterizing weight memory as long-term memory ‣ 4 Experiments ‣ Route to Remember: Adaptive Memory Selection for LLM Agents")).
The gate keeps $`37.9\%`$ of answers and regenerates the rest. Its
behaviour is category-dependent in a way that matches the per-category
picture
(Table [8](#A1.T8 "Table 8 ‣ A.7 Verify-then-regenerate: full breakdown ‣ Appendix A Additional results ‣ Route to Remember: Adaptive Memory Selection for LLM Agents"),
Appendix [A.7](#A1.SS7 "A.7 Verify-then-regenerate: full breakdown ‣ Appendix A Additional results ‣ Route to Remember: Adaptive Memory Selection for LLM Agents")):
it improves five of six categories, and every memory-boundary question
is flagged, correctly, since nothing in the store supports an
unanswerable question, and the regenerated answer is a refusal, which
lifts that category to $`99.4\%`$.

## 5 Conclusion

Today’s agents keep a user’s memory in text and pay for it on every
turn. We showed that this memory can instead live in a model’s weights
by training with OPSD. Parametric memory should be held back not by the
model or data but by the training protocol, since SFT on the same data
has distinct performances. The characteristic study conducted on
weighted-based memory demonstrates that it excels with recent material
but forgets as facts age and cannot tell when a fact was never recorded;
the regimes where a text store still wins. Our verify-then-regenerate
router lets the weight memory answer and then checks that answer against
the text store. For an agent , this suggests a concrete design:
consolidate a user’s recurring or widely shared knowledge into weights
while keeping a text store for the recent and the absent, and compose
the two by verifying answers.

The broader opportunity is that weight memory changes what an agent can
afford to remember. Because the write cost is paid once and the read
cost is negligible, the natural unit to internalize is not a single
user’s history but a pattern mined across many of them: a workflow that
thousands of users repeat, a tool-calling convention, a recurring
preference, or an interaction style. Distilling such shared
regularities, with per-user memory layered on top, would let a harness
carry common competence in its weights and reserve retrieval for what is
genuinely individual and current. This also points beyond text. The same
objective should apply to procedural and skill memory, to tool use, and,
with a multimodal teacher, to knowledge that never had a clean textual
form, so that an agent accumulates capability rather than merely facts,
which marks the future direction of this research.

## Appendix A Additional results

### A.1 Implementation details

All conditions use Qwen3.5-9B as the reader; the memory-point
extraction, text-store management, training-data augmentation, and
question answering are performed by this same model. OPSD trains a
per-user LoRA adapter of rank $`64`$ ($`\alpha{=}128`$) for $`30`$
rounds per session, sampling $`60`$ on-policy questions per round; the
adapter is persistent across sessions. The teacher is the same base
model conditioned on a recency-bounded window of the user’s memory,
capped at $`12{,}000`$ characters (current session always kept, whole
older sessions dropped to fit). Retrieval, for both the MemOS baseline
and the verify-then-regenerate router, uses Qwen3-Embedding-0.6B with
cosine top-$`5`$ fetch. The judge is Claude Sonnet 4.6 with a
correct/hallucinated/omitted rubric and no partial credit. These
settings are fixed across the experiments below unless a subsection
states otherwise.

### A.5 Training objective and anti-forgetting

The following recipe results are directional—they explain how the OPSD
configuration in the main text was arrived at. *Objective.* On the
session-$`0`$ probe the objective ladder is monotone: an off-policy
variant that teacher-forces the teacher’s raw answer text reaches
$`47\%`$ and suffers repetition/degeneration from exposure bias, whereas
the on-policy formulation (the student samples its own answer and the
teacher scores those tokens) reaches $`61\%`$ with clean generations;
supervised fine-tuning on the same data is the weakest and is the row
reported in the main comparison
(Table [1](#S4.T1 "Table 1 ‣ 4.2 OPSD-based weight memory outperforms text memory ‣ 4 Experiments ‣ Route to Remember: Adaptive Memory Selection for LLM Agents")).
Full-parameter fine-tuning of the base model, on the value-only
pipeline, does not beat the rank-$`64`$ LoRA adapter and is far more
expensive, so we keep the adapter. *Teacher construction.* The dominant
fix over the multi-session horizon is *teacher decoupling*: replacing
the accumulating-student teacher (which itself degrades over sessions)
with a frozen base model reading capped cumulative memory lifts the full
run from about $`51\%`$ to about $`65\%`$ on the first-$`10`$-session
probe ($`+14`$ points), with the largest gains on Generalization
($`20\rightarrow 50`$) and Basic Fact ($`56\rightarrow 78`$), and
removes the late-session collapse. Curriculum expansion of the
training-QA pool, which helped on the single-session probe (reaching the
$`\sim`$80% teacher ceiling), *reverses* online: growing the pool to
$`1000+`$ generated questions dilutes the native facts, so the best
multi-session configuration is base teacher with a fixed cache pool and
no expansion. A more aggressive questioner is worse still: a learned
questioner trained with a GRPO objective to maximize the student–teacher
KL divergence, that is, to ask whatever the student is currently worst
at, reaches only $`26\%`$ on the session-$`0`$ probe against on-policy
OPSD’s $`61\%`$, because the difficulty-chasing reward collapses the
generated pool onto a single question type and starves it of diversity.
The lesson across both variants is that the questioner should broaden
coverage of the recorded facts, not maximize hardness. On the full long
horizon, an SFT-replay anti-forgetting term (rehearsing cached answers
to old questions) helps the far tail (age-$`100`$
$`27\rightarrow 32\%`$) but craters Dynamic Update, because
re-supervising a cached answer re-teaches a value that has since been
superseded, a concrete instance of weight memory and volatile facts
interacting badly. Round count is non-monotonic with $`30`$ rounds the
sweet spot. This is the mechanism behind the retention-versus-freshness
tension in
§[4.3](#S4.SS3 "4.3 Characterizing weight memory as long-term memory ‣ 4 Experiments ‣ Route to Remember: Adaptive Memory Selection for LLM Agents").

### A.8 Routed hybrids and oracle ceilings

Because the two memory systems fail on different questions, a
per-question oracle that always chooses the better arm reaches
$`69.3\%`$ against OPSD’s $`59.9\%`$ at age $`0`$; this is the prize the
negative routing signals of
§[4.4](#S4.SS4 "4.4 Route design ‣ 4 Experiments ‣ Route to Remember: Adaptive Memory Selection for LLM Agents")
could not claim.

stable facts to a LoRA and volatile facts to a text arm never beats the
best single non-oracle text method (MemOS at $`46.1\%`$ pooled), because

ground-truth stability oracle for the route does not rescue it. The LLM
router is a high-recall, low-precision volatile detector (agreement with
the ground-truth route $`71.6\%`$, volatile recall $`99.6\%`$), so it
over-routes to the text arm. This is why the main text pursues

### A.9 Retrieval recency is a binary cliff, not a gradient

A natural hypothesis is that retrieval accuracy degrades gracefully with
how stale the fetched fact is. It does not. Once question age and
category are controlled and Memory Boundary is excluded, the graded
session-distance correlation is negligible for all three paradigms
($`|r|\leq 0.10`$; the pooled correlation has an inverted sign purely
from age and boundary confounds, so we do not report it). The real
effect is binary: whether *any* retrieved fact comes from the current
session.
Table [12](#A1.T12 "Table 12 ‣ A.9 Retrieval recency is a binary cliff, not a gradient ‣ Appendix A Additional results ‣ Route to Remember: Adaptive Memory Selection for LLM Agents")
shows this separates the paradigms cleanly: extracted memory collapses
to $`3\%`$ without a current-session fact (near-definitional, since it
only sees the current session), OPSD gains $`+21`$ points, and MemOS is
nearly flat at $`+3`$ points. That flatness is exactly why MemOS
overtakes weight memory at high age. The only graded signal that
survives is recency *variance* (a wider spread of retrieved-fact ages

topic-drift/interference signature too weak to route on. These are
working-note numbers (recency builder over the retrieval logs) and

### A.10 Confidence signals for routing

§[4.4](#S4.SS4 "4.4 Route design ‣ 4 Experiments ‣ Route to Remember: Adaptive Memory Selection for LLM Agents")
reports that confidence in the generated answer is not a usable global
routing signal. This subsection gives the detail. Self-consistency
(agreement across $`K{=}5`$ samples) is a weak, category-dependent
correctness signal that *inverts* on Memory Boundary: boundary accuracy
rises with consistency up to the $`95`$–$`99\%`$ bin ($`0.971`$) then
collapses to $`0.404`$ at perfect consistency, because a deterministic
wrong value (a middle name grabbed from the surname) repeats perfectly
while genuine abstentions vary in phrasing. Per-token confidence is
orthogonal to self-consistency ($`r{=}-0.02`$) and slightly stronger,
but on boundary it is largely an answer-length proxy
($`\mathrm{corr}(\text{length},\text{ptc\_mean}){=}0.65`$): a scoring
penalty on the first token is diluted across a long abstention but
dominates a one-word value. A single global correctness probe therefore
averages two opposite confidence-to-correctness mappings and lands near
chance (AUC $`0.63`$). The signal only works once the boundary regime is
separated.

The clean detector is a length-constant one. Teacher-forcing a fixed
six-token abstain string (constant for every question, so
length-confound-free by construction) and reading its probability gives
an answerability detector with AUC $`0.944`$ on the extraction baseline
and, critically, AUC $`0.918`$ when scored under the OPSD weight
adapter, confirming the gate reads the model’s *parametric* knowledge
state, not merely context visibility. But this detector predicts
answerability, not correctness: against the event that the model is
wrong it is at chance ($`0.516`$), and margin_lp/minp confidence
features are actively anti-predictive. Routing on it yields a single
operating point that gains only $`+1.0`$ point over OPSD at age $`0`$
and turns net-negative pooled over ages, because once OPSD forgets the
threshold degenerates to "always route to text."

lowest-scoring categories, and much of that score reflects the
evaluation rubric rather than the memory systems. On the $`173`$

*all five* methods including full context, which sees the entire
dialogue, so retrieval cannot be the dominant cause.

### A.12 Representation dominates age on HaluMem-Medium

On HaluMem-Medium, where each user’s full history ($`\sim`$160k tokens)
still fits the context window, the representation of memory matters far
more than question age. Answering the same cumulative questions from
ground-truth points, extracted memory, and raw dialogue gives
$`63.7\%>57.6\%>54.2\%`$ overall, with accuracy nearly flat across age
in every condition (no long-context decay at this scale). The
extraction-over-dialogue win is entirely a Memory Boundary effect
(dialogue $`46.6\%`$ vs extraction $`72.6\%`$): a clean extracted list
lets the reader say "unknown," whereas a raw transcript invites a
hallucinated answer, and on every other category extraction slightly
loses to raw dialogue because extraction drops or fragments detail. This
localizes where compression helps (abstention) and where it hurts (fine
detail), and it is why the main results use the longer HaluMem-Long,
where the context wall actually bites. from a cumulative-representation

### A.13 RouterMem-Mini: volatile facts are the hard axis

To probe volatile-versus-stable memory more directly than HaluMem
allows, we built RouterMem-Mini, a small generator ($`8`$ users
$`\times`$ $`20`$ sessions) with an enriched volatile-fact axis ($`173`$
of $`520`$ questions typed volatile through explicit update chains) and
genuinely unanswerable Memory Boundary questions. The round-2 evaluation
confirms the split that motivates routing: text methods drop from
$`66`$–$`69\%`$ on stable facts to $`31\%`$ on volatile facts, and the
weight memory drops from $`29`$–$`31\%`$ to $`8\%`$. Improved
third-person minimal-span augmentation did not lift the weight memory
($`22`$–$`23\%`$ overall, $`r{=}100\approx r{=}200`$), which holds only
on Memory Boundary abstention ($`92`$–$`94\%`$), confirming that the
roughly $`20\%`$ weight-memory ceiling on this data is a weight-memory
limit and not an augmentation-quality artifact. This corroborates the
volatile-facts finding of
§[4.3](#S4.SS3 "4.3 Characterizing weight memory as long-term memory ‣ 4 Experiments ‣ Route to Remember: Adaptive Memory Selection for LLM Agents")
on an independently generated benchmark.

### A.14 Where each memory system wins, qualitatively

The one robust place text memory beats weight memory is absence.
Analyzing the disjoint wins at age $`0`$, the only category where either
MemOS or extracted memory beats OPSD net is Memory Boundary: of $`120`$
MemOS-only wins, $`47`$ are boundary questions where OPSD confabulates a
value (its boundary omission rate is $`0.000`$, so it never abstains, it
invents), and the clearest sub-pattern is the "precise unrecorded
attribute" question (a salary, an exact weight, a film title the dataset
never recorded) where a text system reads its list, finds no such field,
and reports the absence, while OPSD produces a concrete number,
inconsistently across ages for the same question. The remaining
non-boundary "wins" are mostly not a text-memory capability: about
$`18\%`$ are OPSD over-answering artifacts (it contained the gold but
added extra true detail and was scored wrong) and a majority are lenient
passes where the text answer contained under half the gold content. We
include this because it is the honest mechanism behind the one category
OPSD loses in
§[4.2](#S4.SS2 "4.2 OPSD-based weight memory outperforms text memory ‣ 4 Experiments ‣ Route to Remember: Adaptive Memory Selection for LLM Agents")
and
§[4.3](#S4.SS3.SSS0.Px3 "Absence is not inspectable in weights. ‣ 4.3 Characterizing weight memory as long-term memory ‣ 4 Experiments ‣ Route to Remember: Adaptive Memory Selection for LLM Agents"):
inspectability, not knowledge. We also flag a judge inconsistency found
here, where roughly $`20\%`$ of OPSD’s "hallucination" verdicts on
boundary questions were correct abstentions scored wrong while a
near-identical text abstention was scored correct, so the stated OPSD
fabrication rate is inflated by about a fifth.
````
