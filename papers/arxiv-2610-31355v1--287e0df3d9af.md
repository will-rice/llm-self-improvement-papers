# Muffin - A Shared Memory Buffer for Asynchronous AI Agents

###### Abstract

The rise of Agentic AI systems has changed the landscape of artificial
intelligence by enabling strong reasoning capabilities through
specialized multi-agent interaction with structured self-reflection.
However, in target-driven reasoning tasks, single- and multi-agent
systems are often on par in terms of performance gains. A major
challenge is that failures often arise from an ineffective exchange of
critical information during inter-agent interaction and coordination.
Different from existing multi-agent debate paradigms that rely on
synchronous turn-taking and sharing information across different agents,
we propose an inter-agent protocol based on shared memory buffer
inference - referred to as Muffin - in an asynchronous agentic
framework. In the first step, an orchestrator routes queries based on
their reasoning demands and delegates demanding ones to a multi-agent
setting, where a shared memory buffer provides asynchronous exchange of
intermediate findings while an agent’s private reasoning remains local.
Our experiments show that our framework Muffin outperforms established
competitors, achieving the best accuracy in 17 out of 20 of our
benchmark settings, and provides a better quality-cost trade-off than
multi-agent debate: Muffin improves accuracy by 19.2 accuracy points
while using 77.4% fewer tokens, without requiring full-trace sharing.

## 1 Introduction

Frontier models like Opus ([Anthropic, 2026](#bib.bib1)), Gemini
([Google DeepMind, 2026](#bib.bib2)), ChatGPT ([OpenAI,
2026](#bib.bib3)) have made a substantial leap in artificial
intelligence by demonstrating reasoning capabilities that approach human
performance in a variety of domains ([Luo et al., 2024](#bib.bib4);
[Bermejo et al., 2025](#bib.bib5); [Alohali et al., 2025](#bib.bib6);
[Street et al., 2026](#bib.bib7)). In the current era of Agentic AI, we
see a shift towards systems that are able to plan, act, use tools, and
apply feedback loops for enhanced performance ([Abou Ali et al.,
2025](#bib.bib8); [Pati, 2025](#bib.bib9); [Xi et al.,
2025](#bib.bib20)). However, strong single-agent reasoning does not
remove the need for collaboration. More complex tasks often require
decomposing the problem, checking partial information, and integrating
the conclusions generated by different reasoning parts. This motivates
goal-oriented multi-agent behavior that goes beyond single-agent
responses toward agent collaboration supported by memory ([Zhang et al.,
2025](#bib.bib13)), reasoning ([Subramaniam et al., 2025](#bib.bib14)),
or environmental interaction ([Lan et al., 2024](#bib.bib15)).

Recent multi-agent research has been applied to scientific
experimentation ([Ghareeb et al., 2026](#bib.bib10)), embodied agents
([Huang et al., 2023](#bib.bib12)), or societal simulation ([Gao et al.,
2023](#bib.bib11)). Nevertheless, recent studies suggest that
multi-agent systems do not automatically outperform strong single-agent
or repeated-sampling baselines ([Xia et al., 2024](#bib.bib16); [Kapoor
et al., 2025](#bib.bib17)), because critical information is lost during
inter-agent coordination and verification processes fail ([Cemri et al.,
2025](#bib.bib18)). In particular, a key limitation is that many
multi-agent systems communicate after an agent has produced a complete
output, leaving partial critical findings unavailable to peer agents
while simultaneously overwhelming them with verbose, task-irrelevant
reasoning traces that increase context overhead ([Liu et al.,
2024](#bib.bib19); [Ning et al., 2024](#bib.bib35); [Du et al.,
2024](#bib.bib30)). This motivates our core question, whether agents can
collaborate more effectively by asynchronously sharing the intermediate
findings, and allowing other agents to retrieve and reuse information
during inference without exposing full reasoning traces.

We propose an asynchronous system based on shared memory buffer
inference, referred to as Muffin, that enables exchange of agents’ novel
insights. The general workflow is visualized in
[Figure 1](#S1.F1 "In 1 Introduction ‣ Muffin - A Shared Memory Buffer for Asynchronous AI Agents").
In the first step, an Orchestrator routes a user query based on the
expected reasoning demands, i.e., whether a query can be solved directly
or a multi-step reasoning is required. For more demanding queries,
multiple agents are instantiated by assigning each of them a specialized
role, and a subtask, both provided by the orchestrator. For an efficient
exchange of relevant insights, a shared memory provides a controlled and
selective exchange of intermediate findings. An agent only pushes
relevant information into the buffer which is expected to help in making
progress in a collaborative problem solving manner. We keep an agent’s
own reasoning local. After a finite reasoning horizon, a Summarizer is
fed the final messages from each agent along the agents’ meta
information and the initial user query, to produce the final response.

![Refer to caption](2610.31355v1/workflow-2.png)

Figure 1: General workflow of Muffin - a shared memory buffering system.

In our empirical study, we show how Muffin provides reasoning
capabilities that are on the Pareto front w.r.t. the downstream accuracy
and the token consumption. We evaluate on four reasoning benchmarks and
report performance gains across four open-weight language models. By
applying Muffin, we improve the strongest baseline by 4.4 accuracy
points on average across all benchmarks, with larger gains on OlymMATH-E
of 11.8 accuracy points. Moreover, we show that it reaches a better
quality-cost trade-off compared to multi-agent debate architectures,
improving accuracy by 19.2 accuracy points while using 77.4% fewer
tokens in the step-wise analysis, as in our pipeline we exchange only
selected findings instead of full reasoning traces.

The key contributions of our work:

- •
  Shared Memory Buffer: We propose Muffin, an LLM-based multi-agent
  workflow in which agents asynchronously exchange selected intermediate
  findings through a shared buffer.
- •
  Asynchronously Selective Information Sharing: Muffin keeps each
  agent’s local reasoning information private and shares partial
  intermediate findings through the buffer asynchronously, enabling
  agent collaboration without exposing full reasoning traces.
- •
  Accuracy-Cost Trade-off: Muffin outperforms single-agent and
  majority-vote baselines across four reasoning benchmarks, while lying
  on the accuracy-token Pareto frontier.

## 2 Related work

##### Multi-agent collaboration.

Recent research has shown that agentic systems can improve reasoning and
performance by organizing multiple specialized agents rather than
relying on a single language model inference ([Hong et al.,
2024](#bib.bib21); [Chen et al., 2024a](#bib.bib25); [Xi et al.,
2025](#bib.bib20); [Abou Ali et al., 2025](#bib.bib8)). Several systems
instantiate this idea through task decomposition ([Chen et al.,
2024b](#bib.bib28); [Qian et al., 2024](#bib.bib33)), where agents will
have specialized roles while working on different parts of a task,
including general reasoning workflows and software development
pipelines. General-purpose agent frameworks make this coordination more
flexible by allowing LLM-backed agents, tools, and humans to be composed
into different interaction patterns ([Wu et al., 2024](#bib.bib34);
[Moura and CrewAI Inc., 2023](#bib.bib26); [LangChain AI,
2024](#bib.bib27)). Despite these differences, a common denominator of
most multi-agent systems is that they still integrate outputs only after
full messages, subtasks, or rounds have completed, limiting how agents
can adapt to one another’s reasoning while inference is still
unfinished.

Aggregation and shared intermediate information. Some studies on
aggregation show how outputs from other inference processes can be used
as additional context for improving final answers ([Jiang et al.,
2023](#bib.bib36); [Wang et al., 2024b](#bib.bib24)). Layered
aggregation uses responses from earlier model calls to condition later
ones, enhancing the complement of strengths across models ([Wang et al.,
2025](#bib.bib29)). Debate-based systems instead expose agents to peer
answers and critiques over multiple rounds before selecting a final
answer ([Du et al., 2024](#bib.bib30); [Liang et al., 2024](#bib.bib22);
[Xiong et al., 2023](#bib.bib23)). These results support the value of
shared intermediate information, but the shared object is usually a
complete response, critique, or round output, rather than having the LLM
judge which information is useful enough to share. This leaves open how
agents should share and use partial information before a full answer has
been completed.

Fine-grained and streaming interaction. More recent work studies
collaboration below the level of complete turns through token-level
collaboration ([Hsu et al., 2025](#bib.bib31)), which lets other agents
observe generation progress and adjust their reasoning before a complete
answer is produced. Similarly, streaming communication sends reasoning
steps to downstream agents during generation, reducing the delay caused
by waiting for complete turns ([Ning et al., 2024](#bib.bib35); [Yang et
al., 2026](#bib.bib32)). This direction suggests that sharing partial
reasoning during inference can reduce coordination latency and enable
earlier reactions, while leaving room to study how partial information
can be selected, maintained, and jointly reused. A key challenge is to
support asynchronous sharing, where agents can make useful findings
available to others without exposing their full reasoning traces. This
frames a middle ground between isolated final-answer aggregation and
full-trace exchange.

## 3 Methodology

### 3.1 General Multi-Agent Problem Setting

In a multi-agent system, a team of $`N`$ agents
$`\mathcal{A}=\{a_{i}\}_{i=1}^{N}`$ tries to solve a given query $`x`$.
We initialize each agent $`a_{i}`$ with a language model
$`p_{\theta_{i}}`$ having an agent-specific role $`r_{i}`$ and a subtask
$`\tau_{i}`$, executing $`T`$ reasoning steps. An agent holds a local
history $`h_{i}^{(t)}`$ for each step $`t`$, and conditions on a prompt
$`c_{i}^{(t)}`$ constructed by the shared context formatting function
$`C_{agent}`$, i.e.:

|     |     |     |
| --- | --- | --- |
|     |

       ``` math
       c_{i}^{(t)}=C_{agent}(x,r_{i},\tau_{i},h_{i}^{(t)})
       ```                                                  |     |

The message generated by the agent is denoted as $`m_{i}^{(t)}`$:

|     |     |     |
| --- | --- | --- |
|     |

       ``` math
       m_{i}^{(t)}\sim p_{\theta_{i}}(\cdot\mid c_{i}^{(t)}).
       ```                                                     |     |

In standard multi-agent inference, agents usually communicate using
completed messages. The agents can work sequentially and respond one
after another ([Hong et al., 2024](#bib.bib21)), or in parallel, where
multiple agents generate their outputs independently before a final
aggregation or selection step ([Wang et al., 2025](#bib.bib29)).

After one or more inference rounds, a final answer is produced by an
aggregation function $`G`$, which may select one agent’s output, combine
multiple outputs, apply a majority vote, or synthesize a new response:

|     |     |     |
| --- | --- | --- |
|     |

````math
y=G(c_{\mathrm{sum}}),\qquad\text{with~}c_{\mathrm{sum}}=C_{\mathrm{sum}}(x,m_{1}^{(1:T)},\ldots,m_{N}^{(1:T)})
``` |  |

where $`c_{\mathrm{sum}}`$ is the aggregation context constructed from
the query and completed agent messages by the formatting function
$`C_{\mathrm{sum}}`$. Therefore, the standard setting treats
communication mainly as completed messages rather than explicitly
modeling how information from each round is organized and reused in
later inference steps.

### 3.2 Muffin - Shared memory buffer Inference

To support asynchronous sharing of intermediate findings, we introduce a
shared memory buffer. First, an orchestrator routes the input query
according to the expected demands to a single-agent or multi-agent
setting. In the latter case, it configures a team of agents. The agents
reason concurrently and exchange insights through a shared memory
buffer. Finally, a summarizer produces the final answer. Our general
workflow is illustrated in
[Figure 1](#S1.F1 "In 1 Introduction ‣ Muffin - A Shared Memory Buffer for Asynchronous AI Agents").

Orchestrator. The orchestrator is a language model $`p_{\theta_{O}}`$
that maps a query $`x`$ to an inference plan:

|  |  |  |
|----|----|----|
|  |
``` math
\pi=(z,\{\alpha_{i}\}_{i=1}^{N},\rho)\sim p_{\theta_{O}}(\cdot\mid x),\qquad\text{with~}\alpha_{i}=(a_{i},r_{i},\tau_{i}),
``` |  |

where $`z\in\{\mathrm{direct},\mathrm{multi}\}`$ is the routing
decision, $`\alpha_{i}`$ assigns each agent $`a_{i}`$ a role $`r_{i}`$
and a non-overlapping subtask $`\tau_{i}`$, and $`\rho`$ denotes the
collaboration protocol. The protocol specifies what kind of information
is shared (e.g., critique, warnings, etc.), defines what to keep only in
an agent’s local reasoning sphere, and sets whether new findings may
trigger reactive steps of other peers. In case of $`z=\mathrm{direct}`$,
a single call $`y\sim p_{\theta}(\cdot|x)`$ terminates the pipeline
without memory buffer or summarizer. For cases where more demanding
reasoning is expected, the pipeline triggers the multi-agent route.

Asynchronous Multi-Agent Reasoning via a Shared Memory Buffer. In the
multi-agent route, the set of agents can share insights via a shared
memory buffer.

• Shared Memory Buffer. Due to an asynchronous sharing of information
over a shared memory buffer, we refer to the memory’s state at time step
$`d`$ with $`\ell`$-many entries as:

|  |  |  |
|----|----|----|
|  |
``` math
B^{(d)}=(e_{1},\ldots,e_{\ell}),\qquad\text{with~}e_{j}=(a_{i},s_{i}^{(t)},t)\qquad\text{and~}B^{(0)}=\emptyset.
``` |  |

Each entry $`e_{j}`$ stores the information about the source agent
$`a_{i}\in\mathcal{A}`$, the agent’s finding in the $`t`$-th reasoning
step $`s_{i}^{(t)}`$, and an identifier of the source step $`t`$. We
define the memory buffer as an append-only data structure, i.e., any
existing data is immutable, and the only permitted mutation is adding
new information. Hence, $`B^{(d)}{\preceq}B^{(d^{\prime})}`$ for two
time stamps $`d\leq d^{\prime}`$. Since agents can only append
information, there are no write conflicts and no locking beyond
atomicity of the append operation. When retrieving information from the
buffer, agents access the stored data through a bounded window denoted
as $`R_{k}(B^{(d)},i)`$ to retrieve the $`k`$ most recent findings of
$`B`$ at time $`d`$ contributed by other agents. In particular, it scans
backward and skips the agent’s $`a_{i}`$ own shared findings, which are
available in the agent’s private history.

![Refer to caption](2610.31355v1/internal_workflow-3.png)

Figure 2: An agent’s internal workflow.

• Agent step. The agent’s internal workflow is summarized in
[Figure 2](#S3.F2 "In 3.2 Muffin - Shared memory buffer Inference ‣ 3 Methodology ‣ Muffin - A Shared Memory Buffer for Asynchronous AI Agents").
At reasoning step $`t`$, we denote the agent’s dispatch time as
$`\beta_{i,start}^{(t)}`$. Given a generation latency of
$`\delta_{i}^{(t)}`$, the agent ends the $`t`$-th inference step at
$`\beta_{i,end}^{(t)}=\beta_{i,start}^{(t)}+\delta_{i}^{(t)}`$. At
dispatch, the agent reads the $`k`$ most recent findings of other peers
from the memory buffer and constructs its context information:

|  |  |  |
|----|----|----|
|  |
``` math
c_{i}^{(t)}=C_{agent}(x,r_{i},\tau_{i},h_{i}^{(t)},R_{k}(B^{\beta_{i,start}^{(t)}},i),\rho),
``` |  |

where $`h_{i}^{(t)}`$ denotes the agent’s local history. An agent
generates a structured output according to:

|  |  |  |
|----|----|----|
|  |
``` math
(m_{i}^{(t)},s_{i}^{(t)},n_{i}^{(t)})\sim p_{\theta_{i}}(\cdot|c_{i}^{(t)}),
``` |  |

where $`m_{i}^{(t)}`$ denotes an agent’s step summary, $`s_{i}^{(t)}`$
refers to the optional shared finding, and $`n_{i}^{(t)}`$ are local
notes only visible for the respective agent. In case of a finding is
shared, the buffer is updated:

|  |  |  |
|----|----|----|
|  |
``` math
B^{\beta_{i,end}^{(t)}}=B^{\beta_{i,end}^{(t)-}}\circ(a_{i},s_{i}^{(t)},t),
``` |  |

where $`\circ`$ appends a new entry to the memory buffer,
$`B^{\beta_{i,end}^{(t)-}}`$ denotes the buffer state immediately before
agent $`a_{i}`$ commits its new finding. The private history is updated
independently,

|     |                                                          |     |
|-----|----------------------------------------------------------|-----|
|     |
       ``` math
       h_{i}^{(t+1)}=H_{i}(h_{i}^{(t)},m_{i}^{(t)},n_{i}^{(t)})
       ```                                                       |     |

The history update $`H_{i}`$ retains only a compact summary rather than
a full trajectory to keep the agents’ local states small.

• Asynchronous execution. In contrast to prior research, our work does
not rely on a global round index. Specifically, an agent $`a_{i}`$ is
dispatched $`\beta_{i,start}^{(t)}`$ as soon as it completes the last
committing $`\beta_{i,end}^{(t-1)}`$, independently of the progress of
any other agent. Therefore, agents run as concurrent requests and the
generation $`\delta_{i}^{(t)}`$ dominates latency during which other
agents continue to read and write from the buffer. W.l.o.g., assuming
two agents $`a_{i},a_{j}\in\mathcal{A}`$ and two reasoning time steps
$`t,t^{\prime}`$, a finding that is committed at $`\beta_{i,end}^{(t)}`$
by the $`i`$-th agent is visible for other agent $`a_{j}`$ iff
$`\beta_{i,end}^{(t)}\leq\beta_{j,start}^{(t^{\prime})}`$, and lies
within the $`k`$ most recent findings. Hence, any two overlapping
intervals $`[\beta_{i,start}^{(t)},\beta_{i,end}^{(t)}]`$ and
$`[\beta_{j,start}^{(t^{\prime})},\beta_{j,end}^{(t^{\prime})}]`$ with
$`(\beta_{j,start}^{(t^{\prime})}>\beta_{i,start}^{(t)})\land(\beta_{j,start}^{(t^{\prime})}<\beta_{i,end}^{(t)})`$
cannot share new findings that are not yet committed. If the
collaboration protocol $`\rho`$ enables re-activation, an agent executes
exactly one additional reasoning step and we define the agent’s own
reasoning horizon as $`T_{i}=T{+}1`$ dispatched at
$`\beta_{i,start}^{(T+1)}=\max_{j}(\beta_{j,end}^{(T)})`$, i.e., when
all agents finished at least T reasoning steps.

Summarizer. After each agent finishes its reasoning up to $`T_{i}`$
steps, our system builds a structured input for the summarizer rather
than giving the full interaction trace from each agent. We feed the
summarizer the query $`x`$, the agents’ assignments $`\alpha_{i}`$, and
the last step summary $`m_{i}^{(T_{i})}`$ of each agent. Since each
$`m_{i}^{(T_{i})}`$ was produced after reading the buffer, findings from
the buffer $`B`$ reach the Summarizer module through the agents’
summaries. The answer is produced by a separate language model
$`p_{\theta_{\mathrm{sum}}}`$ (in our experiments the same served
model):

|  |  |  |
|----|----|----|
|  |
``` math
y\sim p_{\theta_{\mathrm{sum}}}\!\left(\cdot\mid c_{\mathrm{sum}}\right),\qquad\text{with }c_{\mathrm{sum}}=C_{\mathrm{sum}}\!\left(x,\left\{(\alpha_{i},m_{i}^{(T_{i})})\right\}_{i=1}^{N}\right)
``` |  |

The summarizer is focusing on the task of choosing and summarizing the
best-supported answer from the agents’ last message summaries, using the
candidate summary as evidence rather than trusting it completely. It is
also instructed not to solve the task again, introduce new assumptions,
or choose an answer which is not supported by the agent outputs unless
no candidate can be extracted. We analyze the summary’s design choice in
Section [4.3](#S4.SS3 "4.3 Ablation Studies ‣ 4 Experiments ‣ Muffin - A Shared Memory Buffer for Asynchronous AI Agents")
by comparing the summarizer output with the agents’ last individual
outputs.

## 4 Experiments

Our experiments are organized around three questions. First, we evaluate
whether our method improves reasoning accuracy. Second, we study the
inference-cost trade-off introduced by multi-agent collaboration. Third,
we analyze whether the shared buffer helps agents use intermediate
findings from other agents before final summarization.

### 4.1 Setup

We first describe the overall experimental setting, including the
benchmarks, baselines, and implementation details.

Benchmarks. We evaluate on four benchmarks that cover complementary
reasoning tasks. The first two follow the evaluation protocol of prior
work ([Du et al., 2024](#bib.bib30)):

- •
  Chess Move Validity, derived from the BIG-Bench Chess State Tracking
  benchmark ([authors, 2023](#bib.bib40)), measures a system’s
  predictive performance of a valid move in a chess setting.
- •
  MMLU-Pro ([Wang et al., 2024a](#bib.bib38)) for broad multi-domain
  multiple-choice reasoning.
- •
  GPQA-Diamond ([Rein et al., 2024](#bib.bib39)) tests difficult,
  knowledge-intensive scientific reasoning.
- •
  OlymMATH ([Sun et al., 2025](#bib.bib37)), which evaluates
  mathematical problem solving that often requires multi-step
  derivation, proof-like reasoning, and verification.

For Chess Move Validity and MMLU-Pro, we use the 100 examples from each
dataset, following the 100-example evaluation setting of prior work ([Du
et al., 2024](#bib.bib30)). For GPQA-Diamond, we evaluate on the full
Diamond split of 198 examples. For OlymMATH, we use 100 examples from
the English easy (-E) subset and 100 examples from the English hard (-H)
subset, and report the results for the two subsets separately.

Baselines. We compare Muffin with single-agent, majority-voting based
multi-agent, and multi-agent debate:

- •
  Single-Agent uses only one language model agent to solve the task. We
  explicitly allow for multiple reasoning steps and not just one-shot
  inference.
- •
  Majority Vote leverages multiple independent single-agent, and gathers
  their final results and choose the majority answer from them.
- •
  Multi-Agent Debate follows the setting of the Multi-agent Debate ([Du
  et al., 2024](#bib.bib30)), where the agents will revise their
  responses after observing other agents’ output.

Implementation Details. We evaluate all methods with four LLMs:
gemma-4-E4B-it, gemma-4-31B-it, Qwen3.8-27B, and Qwen3.5-4B ([Team,
2026](#bib.bib41); [Qwen Team, 2026b](#bib.bib42); [Qwen Team,
2026a](#bib.bib43)). All models are served on a compute cluster through
a vLLM ([Kwon et al., 2023](#bib.bib44)) OpenAI-compatible endpoint. All
baselines and our method call the same served model in each comparison.
We serve the models using tensor parallelism from vLLM, utilizing two
H100 GPUs for the smaller models and four H100 GPUs for the larger
models. As LLM inference might introduce small run-to-run difference, we
repeat each experiment three times and report averaged results. For
method execution and agent parameters, unless explicitly stated
otherwise, we set the number of steps to five for all methods and fix
the number of agents to three for Majority Vote, Multi-Agent Debate, and
Muffin. Our code is publicly available:
[https://anonymous.4open.science/r/Muffin](https://anonymous.4open.science/r/Muffin)

Hypothesis 2: Asynchronous problem solving provides a better
quality-cost trade-off.
We evaluate this hypothesis through three complementary comparisons on
the OlymMATH-Easy, a representative benchmark that requires multi-step
mathematical reasoning and allows us to compare how accuracy and token
usage evolve across inference steps. First we compare different
inference methods over ten reasoning steps. Second, we vary the number
of agents in Muffin to check whether adding more agents improves
accuracy enough to cover the additional token cost. Third, we compare
Muffin with full-trace sharing to evaluate the benefit of selective
sharing. In terms of token usage, we measure both input and output
tokens. Regarding accuracy, baseline results can be obtained directly
after each step, whereas in our method, we extract the outputs at each
step and take a majority vote across them. For both accuracy and token
usage, we report the average over three independent runs.

• Method comparison over inference rounds. As shown in
Figure [4](#S4.F4 "Figure 4 ‣ 4.2 Effectiveness and Efficiency ‣ 4 Experiments ‣ Muffin - A Shared Memory Buffer for Asynchronous AI Agents"),
sharing the intermediate findings provides a better quality-cost
trade-off on the selected benchmark. Each symbol represents a different
method and reasoning steps are colorized, respectively. All methods
improve in accuracy as the number of reasoning steps increases, with our
approach achieving the highest performance by the $`6`$-th step and
gaining a boost in the final round after incorporating the summarizer,
increasing from 44.9% to 59.2%. Overall, Muffin reaches the highest
final accuracy and dominates the multi-agent baselines, outperforming
the strongest baseline by 19.2 accuracy points while using 77.4% fewer
tokens than multi-agent debate. The remaining benchmarks follow the same
trend, with detailed results reported in
Appendix [B.1](#A2.SS1 "B.1 Step-wise Accuracy and Token Usage ‣ Appendix B Additional Experimental Results ‣ Muffin - A Shared Memory Buffer for Asynchronous AI Agents").

• Effect of the number of agents. We next study the effect of the number
of agents on the performance of Muffin. We vary the number of agents
from two to five while fixing the reasoning to five steps. The results
shown in
Figure [4](#S4.F4 "Figure 4 ‣ 4.2 Effectiveness and Efficiency ‣ 4 Experiments ‣ Muffin - A Shared Memory Buffer for Asynchronous AI Agents")
demonstrate that moving from two to three agents improves accuracy from
50.6% to 59.3%, showing a clear benefit from additional collaboration.
However, increasing to four or five agents gives only slight performance
changes, reaching 59.7% and 58.7%, but token usage continues to
increase. This indicates that the benefit of the collaboration does not
scale linearly with the number of agents and shows a convergence
behavior where additional token usage does not pay off.

• Full-trace sharing versus our method. Lastly, we compare our method

useful information, but much of this benefit can be recovered by sharing

### 4.3 Ablation Studies

We conduct ablation studies to inspect which parts of our method
contribute to the final performance. These experiments focus on two
design choices: whether the final summarizer improves over the agents’
last inference outputs, and how the number of shared findings affects
the performance.

• Agents’ final outputs versus summarizer output. We compare the final
answer produced by the summarizer with the last individual outputs
generated by the agents, which include the last findings from the shared
buffer in their input. This evaluates whether the summarizer is giving
additional benefit by combining agents’ final evidence. We compute this
comparison across all benchmarks and two model sizes from the Gemma-4
family. As shown in
Table [2](#S4.T2 "Table 2 ‣ 4.3 Ablation Studies ‣ 4 Experiments ‣ Muffin - A Shared Memory Buffer for Asynchronous AI Agents"),
the summarizer changes the last agent answer in 11.14% of cases. Among
those changed cases, wrong-to-correct changes account for 32.05%, while
correct-to-wrong changes account for 21.20%. This means beneficial
corrections are 10.85 percentage points more than harmful changes. This
suggests that the summarizer does more than copy or choose the majority
from the final agent outputs, and can recover correct answers from the
agents’ final evidence while introducing less harmful noise.

• Number of shared findings. Next, we control how much information an
agent can retrieve from the buffer, and test whether more shared context
always improves collaboration. We use OlymMATH-Easy with the Gemma-4
models.
Figure [6](#S4.F6 "Figure 6 ‣ 4.2 Effectiveness and Efficiency ‣ 4 Experiments ‣ Muffin - A Shared Memory Buffer for Asynchronous AI Agents")
shows that increasing the number of shared findings does not always
improve accuracy. For gemma-4-E4B-it, the best result appears at

findings reduces performance. By contrast, gemma-4-31B-it is less
sensitive to this budget, with accuracy changing by only 2.0 points.
This suggests that a moderate number of shared findings is sufficient,
while adding more findings can introduce noise by including redundant or
outdated findings.

### 4.4 Limitations and Discussion

Our results show that shared intermediate findings in an asynchronous
manner can improve multi-agent reasoning without agents exchanging or
using the full reasoning traces. Our evaluation is focused on
question-answering and reasoning benchmarks. Future work should evaluate
shared buffer collaboration on tasks that require tool use, planning,
environment interaction, or long-horizon execution. Our experiments are
also limited by compute cost. Although we test multiple models,
benchmarks, and agent configurations, we cannot cover all closed- and
open-weight models with different experimental settings. Broader
evaluation would help to clarify how the shared buffer can adapt across
different agentic usages.

## 5 Conclusion

Existing multi-agent debate methods rely on synchronous turn-taking and
sharing information across different agents. We introduce Muffin, an
agentic memory buffer inference framework in which an orchestrator first
routes queries by expected reasoning demand. For more demanding queries,
the collaborating agents exchange intermediate findings asynchronously
through a shared memory buffer while keeping private reasoning local.
Finally, a summarizer produces the final answer from compact agent
summaries. Across four reasoning benchmarks and four language models,
Muffin achieves the best accuracy in 17 out of 20 benchmark settings and
reaches a better accuracy-token trade-off than multi-agent debate.
Muffin improves final accuracy by 19.2 accuracy points while using 77.4%
fewer tokens than multi-agent debate, showing that selective sharing of
findings is a lightweight alternative to full-trace exchange. Future
work includes a dynamic scaling of the number of agents, and extending
the buffer to tool-using and long-horizon tasks.

Routing:

\- Default to multi_agent mode.

\- Use direct mode only when the answer is truthfully 100% certain from
explicit prompt evidence or a deterministic trivial fact.

\- Use multi_agent for uncertainty, ambiguity, missing context,
calculation risk, domain reasoning, verification, critique, or multiple
viewpoints.

\- The reason must explain why direct or multi_agent was selected.

\- For direct, name the exact evidence or deterministic property and
explain why multi-agent verification would not help.

If multi_agent, create {min_dynamic_subagents} to
{max_dynamic_subagents} subagents.

\- Do not create overlapping roles or duplicate subtasks.

\- Each role must own a distinct evidence source, check, or perspective.

\- At least one subagent must challenge assumptions and contradictions.

\- Rules should be short, specific operating or communication rules.

}
